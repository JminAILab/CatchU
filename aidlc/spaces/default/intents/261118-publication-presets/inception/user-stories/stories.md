# User Stories — 발행 프리셋

근거: 승인된 요구사항 `inception/requirements-analysis/requirements.md`(FR1~FR7, NFR1~NFR6), `personas.md`(P1 지원자, P2 면접관), 코드 지식 기록 `aidlc/spaces/default/codekb/CatchU/business-overview.md`·`component-inventory.md`, 팀 관행 `inception/practices-discovery/team-practices.md`, 이 단계 질문 Q1~Q4.

나누는 기준은 사용 흐름 순서이고(Q2), 이야기 하나는 사용자 동작 하나다(Q3). 모두 Must다(scope-document). 수락 기준은 요구사항의 Given/When/Then을 옮겨 쓰고, 팀 관행에 따라 이것이 구현 전에 정하는 시험 시나리오다.

## US1. 프리셋 관리 (P1 지원자)

### US1.1 프리셋 목록 보기

지원자로서 내가 만든 프리셋을 한눈에 보고 싶다. 그래서 무엇이 준비돼 있는지 알고 고칠 프리셋을 고를 수 있다.

- 우선순위: Must · 요구사항: FR1.1, FR1.2, NFR5, NFR6
- **AC1.1.1** Given 로그인한 지원자 When 상단 메뉴를 보면 Then 「내 자산 · 텍스트 자료 · 프리셋 · 발행본 · JD 관리」 순서로 보이고, 「프리셋」을 누르면 프리셋 목록으로 간다.
- **AC1.1.2** Given 프리셋 목록 화면 When 상단 메뉴를 보면 Then 「프리셋」만 현재 자리로 표시된다.
- **AC1.1.3** Given 프리셋 3개 When 목록을 열면 Then 3개가 한 번에 이름·항목 수·글자 수와 함께 보인다. 프리셋이 50개일 때도 쪽 나눔 없이 한 번에 모두 보인다.
- **AC1.1.4** Given 프리셋 0개 When 목록을 열면 Then 「아직 만든 프리셋이 없습니다」와 [새 프리셋]이 보인다.
- **AC1.1.5** Given 목록 불러오기 실패 When 화면을 보면 Then 실패 안내와 [다시 불러오기]가 보이고 0개 안내는 보이지 않는다.

### US1.2 프리셋 만들기

지원자로서 이름을 붙인 묶음에 Catch·텍스트 자료·PDF를 담아 두고 싶다. 그래서 발행할 때마다 하나씩 고르지 않는다.

- 우선순위: Must · 요구사항: FR1.3, FR1.4, FR1.5, FR1.6, FR1.7, FR1.12, NFR2, NFR3
- **AC1.2.1** Given [새 프리셋] When 1~50자 이름을 쓰고 공개·확인된 Catch, 텍스트 자료, 글 추출이 끝난 PDF를 담아 저장하면 Then 프리셋이 저장되어 목록에 보인다. 이름 칸에는 이 이름이 받은 사람 화면의 탭 이름으로 보인다는 안내가 있다.
- **AC1.2.2** Given 담을 Catch 목록 When 보면 Then 비공개 Catch와 확인이 필요한 Catch는 목록에 없고, 목록 위의 「작성자 설명을 쓴 Catch만 보기」는 지금 발행 화면처럼 동작한다.
- **AC1.2.3** Given 이름이 비었거나 51자 When 저장하면 Then 저장되지 않고 이름 칸에 이유가 보이며 담은 자료는 남는다.
- **AC1.2.4** Given 이미 담긴 자료, 또는 담으면 항목 20개·전체 글 60,000자를 넘는 자료 When 담으려 하면 Then 담기지 않고 이유가 보인다. 서버도 거부한다.
- **AC1.2.5** Given 프리셋 50개 When 새 프리셋을 저장하면 Then 저장되지 않고 50개까지라는 안내가 보인다.
- **AC1.2.6** Given `<b>`가 든 이름 When 저장하고 어느 화면에서 보든 Then 이름이 글자 그대로 보인다.
- **AC1.2.7** Given 저장 요청이 실패함(연결 끊김, 서버 오류) When 저장하면 Then 실패 안내가 보이고 입력한 이름과 담은 자료가 그대로 남는다.
- **AC1.2.8** Given 다른 회원의 Catch·텍스트 자료·PDF ID When 프리셋에 담아 저장을 요청하면 Then 서버가 거부한다.

### US1.3 프리셋 안 자료의 순서 정하기

지원자로서 프리셋 안 자료의 순서를 정하고 필요 없는 자료를 빼고 싶다. 그래서 면접관이 중요한 자료부터 본다.

- 우선순위: Must · 요구사항: FR1.8
- **AC1.3.1** Given 자료 3개가 담김 When 셋째 자료의 [위로]를 누르면 Then 둘째 자리로 올라간다.
- **AC1.3.2** Given 첫째 자료 When 보면 Then [위로]를 쓸 수 없고, 마지막 자료는 [아래로]를 쓸 수 없다.
- **AC1.3.3** Given 담긴 자료 When [빼기]를 누르면 Then 목록에서 빠지고 항목 수·글자 수가 줄어든다.

### US1.4 프리셋 고쳐 저장하기

지원자로서 만든 프리셋의 이름과 자료를 고치고 싶다. 그래서 지원하는 곳이 바뀌어도 묶음을 다시 만들지 않는다.

- 우선순위: Must · 요구사항: FR1.10, FR1.13, NFR2
- **AC1.4.1** Given 프리셋 P When 이름을 바꾸고 자료 하나를 더하고 순서를 바꿔 저장하면 Then 목록과 편집 화면에 바뀐 이름·항목 수·순서가 보인다.
- **AC1.4.2** Given 프리셋 P를 고치는 화면 When 보면 Then 「프리셋을 고쳐도 이미 보낸 링크는 바뀌지 않습니다」가 보인다.
- **AC1.4.3** Given 프리셋 P When 만들 때 막히는 내용(빈 이름, 겹친 자료, 상한 넘음)으로 저장하면 Then 저장되지 않고 바꾼 내용은 남는다. 서버도 거부한다.
- **AC1.4.4** Given 다른 회원의 프리셋 ID When 읽기·고치기·지우기를 요청하면 Then 서버가 거부한다.
- **AC1.4.5** Given 고쳐 저장하는 요청이 실패함 When 저장하면 Then US1.2의 AC1.2.7과 같이 실패 안내가 보이고 바꾼 이름과 자료가 그대로 남는다.

### US1.5 프리셋 지우기

지원자로서 더 쓰지 않는 프리셋을 지우고 싶다. 그래서 목록이 정리된다.

- 우선순위: Must · 요구사항: FR1.9
- **AC1.5.1** Given 프리셋 P When [프리셋 지우기]를 누르면 Then P의 이름을 밝힌 확인이 나오고, 확인하면 지워져 목록으로 간다.
- **AC1.5.2** Given 지우기 확인 When 취소하면 Then P는 그대로다.
- **AC1.5.3** Given P로 만든 발행본 When P를 지운 뒤 받은 사람 화면을 열면 Then 발행 당시 자료가 그대로 보인다.

### US1.6 발행할 수 없게 된 프리셋 알아보기

지원자로서 담아 둔 자료 때문에 프리셋을 발행할 수 없게 되면 미리 알고 싶다. 그래서 발행 직전에 놀라지 않는다.

- 우선순위: Must · 요구사항: FR1.11, FR1.14, NFR1
- **AC1.6.1** Given 담긴 Catch를 내 자산 화면에서 숨김 When 프리셋을 열면 Then 그 Catch가 담긴 목록에 남고 「비공개」 이유가 보인다.
- **AC1.6.2** Given 담긴 Catch의 원본 저장소가 보호로 바뀜 When 프리셋을 열면 Then 그 Catch에 보호 이유가 보인다.
- **AC1.6.3** Given 담긴 텍스트 자료를 고쳐 프리셋이 60,000자를 넘음 When 목록이나 편집 화면을 열면 Then 상한을 넘었다는 표시가 보인다.
- **AC1.6.4** Given 위 표시들 When 화면 낭독기로 읽으면 Then 이유가 글자로 읽힌다(색만으로 나타내지 않는다).

## US2. 프리셋으로 발행 (P1 지원자)

### US2.1 프리셋을 골라 발행하기

지원자로서 발행할 때 프리셋을 골라 순서를 정하고 싶다. 그래서 자료를 하나씩 고르지 않고 빠르게 발행한다.

- 우선순위: Must · 요구사항: FR2.1, FR2.2, FR2.3, FR2.10, FR6.1
- **AC2.1.1** Given 프리셋 2개 When 발행 화면에서 둘을 고르고 순서를 바꾼 뒤 제목·비밀번호를 쓰고 발행하면 Then 발행되고, 흐름(고르기 → 순서 → 제목과 비밀번호 → 발행 내용 확인 → 발행됨)은 지금과 같다.
- **AC2.1.2** Given 「발행 내용 확인」 When 보면 Then 제목·비밀번호·만료와 고른 프리셋·순서가 보인다.
- **AC2.1.3** Given 프리셋 5개를 고름 When 더 고르려 하면 Then 나머지 칸이 막히고 「최대 5개」가 보인다.
- **AC2.1.4** Given 프리셋 P1(자료 2개)·P2(자료 3개)를 순서대로 골라 발행 When 사본을 보면 Then 자료 순서 번호가 P1의 1·2, P2의 3·4·5로 이어진다.

### US2.2 고를 수 없는 프리셋의 이유 보기

지원자로서 고를 수 없는 프리셋이 왜 막혔는지 알고 싶다. 그래서 무엇을 고쳐야 할지 안다.

- 우선순위: Must · 요구사항: FR2.4, FR2.5, FR2.6, NFR1, NFR5
- **AC2.2.1** Given 항목이 0개인 프리셋 When 발행 화면을 보면 Then 고를 수 없고 이유가 칸 옆에 보인다.
- **AC2.2.2** Given 이미 고른 프리셋에 더하면 항목 20개 또는 60,000자를 넘는 프리셋 When 보면 Then 고를 수 없고 상한 이유가 보인다. 같은 자료가 두 프리셋에 있으면 두 번 센다.
- **AC2.2.3** Given 발행할 수 없는 자료가 담긴 프리셋 When 보면 Then 고를 수 없고 어느 자료 때문인지 보인다.
- **AC2.2.4** Given 프리셋 0개 When 발행 화면을 열면 Then 「프리셋 고르기」 자리에 프리셋 목록을 가리키는 링크만 보인다.
- **AC2.2.5** Given 프리셋 목록 불러오기 실패 When 발행 화면을 보면 Then 실패 안내와 [다시 불러오기]가 보이고 「프리셋 없음」으로 보이지 않는다.

### US2.3 같은 자료가 담긴 프리셋 함께 발행하기

지원자로서 같은 Catch가 들어간 프리셋 여럿을 한 번에 보내고 싶다. 그래서 프리셋마다 자료를 따로 정리하지 않아도 된다.

- 우선순위: Must · 요구사항: FR2.7
- **AC2.3.1** Given Catch A가 P1·P2에 담김 When P1·P2를 골라 발행하면 Then 발행되고 받은 사람 화면의 P1 탭과 P2 탭에 Catch A가 각각 보인다.
- **AC2.3.2** Given 위 발행 When 상한을 세면 Then Catch A가 두 번 세어진다.

### US2.4 발행이 막혔을 때 이유 보기

지원자로서 발행 직전에 무언가 바뀌어 막히면 어느 프리셋의 어느 자료 때문인지 알고 싶다. 그래서 그 자료만 고치고 다시 발행한다.

- 우선순위: Must · 요구사항: FR2.8, FR2.9, NFR2
- **AC2.4.1** Given 프리셋을 고른 뒤 다른 창에서 담긴 Catch를 숨김 When 발행하면 Then 발행되지 않고 그 프리셋과 Catch가 보인다.
- **AC2.4.2** Given 다른 회원의 프리셋 ID When 발행에 넣으면 Then 서버가 거부한다.
- **AC2.4.3** Given 발행 When 끝나면 Then 비공개 Catch를 공개로 바꾸는 일은 일어나지 않는다.

### US2.5 프리셋을 고쳐도 보낸 발행본 지키기

지원자로서 프리셋을 고쳐도 이미 보낸 링크의 내용이 바뀌지 않기를 바란다. 그래서 면접관이 본 내용과 내가 보낸 내용이 같다.

- 우선순위: Must · 요구사항: FR2.11
- **AC2.5.1** Given 발행본을 만든 뒤 프리셋 이름과 담긴 자료를 바꿈 When 받은 사람 화면을 열면 Then 발행 당시의 탭 이름과 자료가 보인다.
- **AC2.5.2** Given 발행본을 만든 뒤 프리셋을 지움 When 받은 사람 화면을 열면 Then 발행 당시 내용이 그대로 보인다.

## US3. 발행본 읽기 (P2 면접관, US3.5는 P1 지원자)

### US3.1 요약을 먼저 읽고 프리셋별 탭으로 자료 보기

면접관으로서 AI 요약을 먼저 읽고 자료를 프리셋별 탭으로 나눠 보고 싶다. 그래서 무엇이 어떤 자리인지 헷갈리지 않는다.

- 우선순위: Must · 요구사항: FR3.1, FR3.2, FR5.1
- **AC3.1.1** Given 받은 사람 화면 When 위에서부터 읽으면 Then 제목 → 이 링크에서 할 수 있는 것 안내 → Claude 연결 → 발행 시각 → 「AI 요약」 → 「발행본 자료」(탭) → 「발행본에 질문하기」 → JD 요약 순서다.
- **AC3.1.2** Given 프리셋 하나로 만든 발행본 When 열면 Then 탭 줄이 보이고 탭 하나가 있다.
- **AC3.1.3** Given 이름이 긴 프리셋 When 탭을 보면 Then 탭 이름 뒤가 줄어 있고, 탭을 누르면 그 아래에 이름 전체가 보인다. 탭 옆에 자료 개수는 없다.
- **AC3.1.4** Given 이 변경 전에 만든 발행본의 링크 When 변경 뒤에 열면 Then 지금의 접근 불가 화면(제목 「이 링크는 열람할 수 없습니다.」)이 보인다. 요구사항 FR5.1의 「쓸 수 없는 링크」 화면은 이 화면을 가리킨다.

### US3.2 키보드로 탭 옮기기

면접관으로서 키보드만으로 탭을 옮기고 자료를 읽고 싶다. 그래서 마우스 없이도 발행본을 다 본다.

- 우선순위: Must · 요구사항: FR3.3, NFR1
- **AC3.2.1** Given 탭 줄에 초점 When 오른쪽·왼쪽 화살표를 누르면 Then 옆 탭으로 옮겨 가며 그 탭이 바로 열린다.
- **AC3.2.2** Given 탭 줄 밖에서 Tab으로 들어옴 When 초점을 보면 Then 열려 있는 탭에 놓이고, 다시 Tab을 누르면 그 탭의 자료로 들어간다.
- **AC3.2.3** Given 화면 낭독기 When 탭을 읽으면 Then 탭 역할과 선택 상태가 읽힌다.

### US3.3 탭을 바꿔도 질문 대화 이어 가기

면접관으로서 다른 탭의 자료를 보다가도 질문 대화를 이어 가고 싶다. 그래서 질문을 다시 쓰지 않는다.

- 우선순위: Must · 요구사항: FR3.4, FR6.3
- **AC3.3.1** Given 질문과 답이 하나 있음 When 다른 탭을 열면 Then 그 질문과 답이 그대로 보인다.
- **AC3.3.2** Given 여러 프리셋으로 만든 발행본 When 질문하면 Then 고른 프리셋 전체를 근거로 답한다. 같은 자료가 두 프리셋에 있을 때의 근거 처리는 설계 단계 결정을 따른다.
- **AC3.3.3** Given 여러 프리셋으로 만든 발행본 When AI 요약을 보면 Then 고른 프리셋 전체를 다룬 요약이 탭 밖에 보인다.

### US3.4 출처로 다른 탭의 글에 가고 돌아오기

면접관으로서 답이나 요약의 출처를 눌러 그 글을 확인하고, 다시 답으로 돌아오고 싶다. 그래서 근거를 확인하면서도 읽던 자리를 잃지 않는다.

- 우선순위: Must · 요구사항: FR3.5, FR3.6, NFR1
- **AC3.4.1** Given 첫 탭이 열려 있고 답의 출처가 둘째 탭의 PDF를 가리킴 When 출처 단추를 누르면 Then 둘째 탭이 열리고 그 PDF 글이 강조된다.
- **AC3.4.2** Given 출처로 옮겨 간 글 When 보면 Then 그 글 바로 위에 [답으로 돌아가기]가 있다. 가리킨 글이 열린 탭에 있어도 있다.
- **AC3.4.3** Given 답에서 출처를 눌러 옮겨 감 When [답으로 돌아가기]를 누르면 Then 그 답으로 돌아가고 초점이 눌렀던 출처 단추에 놓인다. 탭은 옮겨 간 탭 그대로다.
- **AC3.4.4** Given AI 요약에서 출처를 눌러 옮겨 감 When [답으로 돌아가기]를 누르면 Then 요약으로 돌아가고 초점이 그 출처 단추에 놓인다.

### US3.5 작성자 발행본 화면에서 같은 모양으로 보기

지원자로서 내 발행본을 면접관과 같은 탭 모양으로 보고 싶다. 그래서 면접관이 무엇을 보는지 안다.

- 우선순위: Must · 요구사항: FR3.7
- **AC3.5.1** Given 작성자 발행본 상세 화면 When 「발행본 자료」를 보면 Then 받은 사람 화면과 같은 탭 줄·탭 이름·키보드 동작이다.
- **AC3.5.2** Given 작성자 발행본 상세 화면의 AI 요약 When 출처 단추를 누르면 Then 받은 사람 화면과 같이 그 탭의 글로 옮겨 가고 [답으로 돌아가기]가 보인다.

### US3.6 Claude로 받은 링크 읽기

면접관으로서 Claude 연결로 받은 링크를 읽을 때 지금처럼 자료를 순서대로 받고 싶다. 그래서 쓰던 방식이 바뀌지 않는다.

- 우선순위: Must · 요구사항: FR6.2, FR6.1
- **AC3.6.1** Given 프리셋 둘로 만든 발행본 When Claude 연결로 받은 링크를 읽으면 Then 항목이 이어 매긴 순서 번호대로 나오고 프리셋 구분은 없다.
- **AC3.6.2** Given 같은 자료가 두 프리셋에 있는 발행본 When 읽으면 Then 그 자료가 두 번(사본마다) 나온다.

## US4. 정리 (P1 지원자)

### US4.1 자료를 지우면 프리셋에서도 빠지기

지원자로서 텍스트 자료나 PDF를 지우면 프리셋에서도 사라지기를 바란다. 그래서 지운 자료가 프리셋에 남아 헷갈리지 않는다.

- 우선순위: Must · 요구사항: FR4.1
- **AC4.1.1** Given 텍스트 자료 T가 프리셋 P에 담김 When T를 지우는 확인을 보면 Then 「프리셋에 담겨 있으면 거기서도 빠진다」는 말이 있다.
- **AC4.1.2** Given 위 상태 When T를 지우면 Then P의 항목 수가 하나 줄고 T는 자리표시 없이 사라진다.
- **AC4.1.3** Given T의 사본이 든 발행본 When T를 지운 뒤 받은 사람 화면을 열면 Then T 사본이 그대로 보인다.
- **AC4.1.4** Given PDF가 프리셋에 담김 When 그 PDF를 지우면 Then 텍스트 자료와 같이 프리셋에서 빠진다.

### US4.2 탈퇴하면 프리셋도 지워지기

지원자로서 탈퇴하면 프리셋도 함께 지워지기를 바란다. 그래서 내 자료가 남지 않는다.

- 우선순위: Must · 요구사항: FR4.2
- **AC4.2.1** Given 프리셋이 있는 지원자 When 탈퇴하면 Then 프리셋이 모두 지워진다.
- **AC4.2.2** Given 탈퇴 화면 When 보면 Then 지금 화면 그대로다.

### US4.3 개인정보처리방침에서 프리셋 저장 알기

지원자로서 개인정보처리방침에서 프리셋도 저장되고 하나씩 지울 수 있다는 것을 알고 싶다. 그래서 내 정보가 어디에 남는지 안다.

- 우선순위: Must · 요구사항: FR4.3
- **AC4.3.1** Given 개인정보처리방침 화면 When 저장 항목 표를 보면 Then 프리셋이 들어 있다.
- **AC4.3.2** Given 같은 화면 When 「하나씩 지우기」 문장을 보면 Then 프리셋을 지울 수 있다고 적혀 있다. 문구는 팀장 확정 문구다.

### US4.4 자료 화면 탭을 키보드로 옮기기

지원자로서 텍스트 자료 화면의 탭도 화살표 키로 옮기고 싶다. 그래서 탭 동작이 화면마다 같다.

- 우선순위: Must · 요구사항: FR7.1, NFR1
- **AC4.4.1** Given 텍스트 자료 화면의 탭 줄에 초점 When 화살표를 누르면 Then 「텍스트 자료」「PDF 자료」 탭이 옮겨 가며 바로 열린다.
- **AC4.4.2** Given 같은 화면 When 탭 이름과 자리를 보면 Then 지금과 같다.

## INVEST 메모

- **Independent**: 이야기마다 시험할 수 있는 동작이 하나다. US2·US3은 US1.2의 저장이 있어야 하므로 시험에서는 미리 만든 프리셋을 쓴다.
- **Negotiable**: 문구와 모양은 다듬은 화면 단계와 팀원 3의 다듬기에서 정한다.
- **Valuable**: 모두 지원자나 면접관이 직접 겪는 동작이다. 사용자에게 보이지 않는 요구사항은 관련 이야기의 수락 기준에 넣었다(FR5.1 → AC3.1.4, FR6.1 → AC2.1.4·AC3.6.1)(Q4).
- **Estimable·Small**: 동작 하나에 수락 기준 2~8개다(Q3를 기준으로 하되, US1.2는 승인 검토에서 저장 실패와 남의 자료 거부 기준을 더해 8개다). US1.2가 가장 크다(담을 자료 종류와 검증이 모여 있다).
- **Testable**: 모든 수락 기준이 Given/When/Then이다.
