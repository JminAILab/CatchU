# Personas — 발행 프리셋

근거: `ideation/intent-capture/intent-statement.md`(대상과 불편), `inception/requirements-analysis/requirements.md`, `aidlc/spaces/default/codekb/CatchU/business-overview.md`, 이 단계 질문 Q1.

## P1. 지원자

| 항목 | 내용 |
|---|---|
| 역할 | CatchU에 Catch·텍스트 자료·PDF를 모아 두고, 그것을 묶어 발행본으로 만들어 면접관에게 링크를 보내는 사람. 자기 발행본을 작성자 발행본 화면에서 다시 본다 |
| 목표 | 지원하는 곳에 맞는 자료 묶음을 빠르게 골라 보낸다. 면접관이 자료의 자리를 헷갈리지 않게 한다 |
| 지금 불편 | 발행할 때마다 Catch와 자료를 하나씩 골라야 한다. 원하는 Catch를 찾을 때까지 「더 보기」를 반복한다. 순서 단추가 눈에 잘 들어오지 않는다 |
| 기술 친숙도 | 중간~높음(개발 직군 지원자) |
| 쓰는 빈도 | 지원할 때마다 발행한다. 프리셋은 한 번 만들어 두면 자주 바꾸지 않는다 |

## P2. 면접관

| 항목 | 내용 |
|---|---|
| 역할 | 지원자가 보낸 링크로 받은 사람 화면을 열어 발행본을 읽는 사람. Claude 연결로 받은 링크를 읽기도 한다 |
| 목표 | 지원자의 자료가 어떤 자리(예: 자기소개서, 포트폴리오)인지 구분해 읽고, AI 요약과 질의응답으로 빨리 핵심을 잡고, 출처를 확인한다 |
| 지금 불편 | 자료가 한 줄로 길게 나열되고 요약이 맨 아래에 있다. 박스 크기가 제각각이고 안내가 펼쳐져 있어 복잡하다 |
| 기술 친숙도 | 높음(개발 실무자) |
| 쓰는 빈도 | 받은 링크마다 한 번, 몇 분 |

## 관계와 우선순위

- 지원자가 만든 발행본을 면접관이 읽는다. 지원자의 작업(프리셋·발행)이 면접관 화면의 모양을 정한다.
- 두 페르소나 모두 이 작업의 1순위다. 지원자 쪽 이야기가 먼저 만들어져야 면접관 쪽 화면을 볼 수 있다.
