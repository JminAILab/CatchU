이 문서는 화면별 구역·글자·상태를 정한다. 색·간격·크기 같은 모양은 정하지 않고 지금 부품을 그대로 쓴다(`design-system-mapping.md`). 모양 다듬기와 드래그는 이 작업 뒤 팀원 3이 한다(team-practices, constraint-register C-O4).

표기: `[단추]`, `<링크>`, `(눌림)` 고르기 단추가 눌린 상태, `(막힘)` 고를 수 없는 단추. 「지금」은 이 브랜치 코드 그대로, 「바뀜」·「새로」는 이 작업에서 바꾸는 곳이다.

## 화면 초안과 달라진 곳

| 곳 | 화면 초안 | 다듬은 화면 | 근거 |
|---|---|---|---|

| 저장 뒤 | 정하지 않음 | 편집 화면에 남고 「저장했습니다」 | Q5 |

[답으로 돌아가기]를 만들지 않는 이유: 넓은 화면 좌우 배치(#615, 팀원 담당)가 들어오면 답이 옆에 남아 이 단추는 좁은 화면에서만 쓰인다. 좁은 화면에서 답으로 돌아오는 방법은 #615가 정한다(2026-11-19 팀장 결정). Q2의 답 가운데 초점을 옮겨 간 항목에 두는 부분은 그대로 따르고, 단추 자리 부분은 이 결정으로 쓰지 않는다.

- 요구사항 FR3.6(옮겨 간 글 바로 위의 [답으로 돌아가기]와 그 동작).
- 요구사항 FR3.7의 FR3.6 참조 부분(작성자 상세도 FR3.6과 같이 움직인다는 부분).

- 요구사항 열린 질문의 「출처로 옮겨 간 직후 초점이 놓이는 자리와 [답으로 돌아가기]에 키보드로 닿는 방법」. 초점 자리는 Q2대로 옮겨 간 항목이고, 돌아가기 부분은 이 결정으로 닫는다.
- 이야기 AC3.4.2·AC3.4.3·AC3.4.4, AC3.5.2의 돌아가기 부분.
- `ideation/rough-mockups/user-flow.md` F4의 5단계와 4단계의 [답으로 돌아가기] 부분, `wireframes.md` W5·W6의 [답으로 돌아가기].

## M1. 상단 메뉴 (W1, US1.1)

```
[CatchU]  내 자산 · 텍스트 자료 · 프리셋 · 발행본 · JD 관리          [프로필]
                              ^ 새로
```

- 「프리셋」은 프리셋 목록(M2)으로 간다. 프리셋 화면에 있을 때 「프리셋」만 현재 자리로 표시된다(AC1.1.2).
- 헤더는 지금처럼 한 줄이다. 320px 폭에서 [프로필]이 화면 밖으로 밀리지 않는지 이 작업에서 한 번 확인하고, 밀리면 그때 배치를 정한다(Q4).

## M2. 프리셋 목록 (W2, US1.1·US1.6)

```
h1 프리셋
                                              [새 프리셋]
h2 내 프리셋
  자기소개서
    항목 4개 · 12,300자 · 발행할 수 없는 자료 1개
    <고치기>
  포트폴리오
    항목 3개 · 8,100자
    <고치기>
  긴 이름의 프리셋 이름이 여기서 줄어…
    항목 20개 · 61,200자 · 상한을 넘었습니다
    <고치기>
```

- <고치기>의 읽히는 이름은 「(프리셋 이름) 고치기」다(화면 낭독기가 링크 목록에서 어느 프리셋인지 알게).

| 상태 | 글자 |
|---|---|
| 불러오는 중 | 「프리셋 목록을 불러오고 있습니다.」 |
| 비었음 | 「아직 만든 프리셋이 없습니다. [새 프리셋]으로 만들어 보세요.」 |
| 불러오기 실패 | 「프리셋 목록을 불러오지 못했습니다.」와 [다시 불러오기] |
| 50개 | [새 프리셋]이 막히고 「프리셋은 50개까지 만들 수 있습니다.」 |

- 50개까지 쪽 나눔 없이 한 번에 보인다(AC1.1.3).
- 「발행할 수 없는 자료 N개」「상한을 넘었습니다」는 글자로 보인다(AC1.6.4).

## M3. 프리셋 편집 (W3, US1.2~US1.6)

```
h1 프리셋 고치기            (새로 만들 때 h1 새 프리셋)
<프리셋 목록으로>
h2 이름
  [ 자기소개서                                   ]
  이 이름이 받은 사람 화면의 탭 이름으로 보입니다. (1~50자)
h2 담을 자료 고르기
  h3 내 Catch
    [ ] 작성자 설명을 쓴 Catch만 보기              <- 지금 발행 화면 그대로(체크박스)
    불러온 20개의 Catch
    [Catch A  저장소 이름 · 설명 안 씀] (눌림)
    [Catch B  저장소 이름]
    ...                                          [더 보기]
  h3 내 텍스트 자료
    [자기소개서 본문]                   (눌림)
  h3 내 PDF 자료
    글 추출이 완료된 PDF만 고를 수 있습니다.
    [포트폴리오.pdf]
h2 담긴 자료와 순서 (항목 4개 · 12,300자)
  1 자기소개서 본문                     [위로][아래로][빼기]
  2 Catch A                             [위로][아래로][빼기]
  3 Catch C  비공개로 바뀌어 발행할 수 없습니다   [위로][아래로][빼기]
  ...
  프리셋을 고쳐도 이미 보낸 링크는 바뀌지 않습니다.
[저장]  [프리셋 지우기]
```

- Catch 고르기 목록에는 공개했고 확인됐고 원본 저장소가 보호되지 않은 Catch만 나온다. 비공개·확인 필요 Catch는 목록에 없다(AC1.2.2). 「작성자 설명을 쓴 Catch만 보기」 체크박스와 「불러온 N개의 Catch」, [더 보기]는 지금 발행 화면 그대로다.
- 고르기는 누르는 단추다. 누르면 눌림 상태가 되고 「담긴 자료와 순서」에 더해진다. 다시 누르면 빠진다(Q1).
- Catch 단추의 작은 줄은 지금 발행 화면이 그리는 글(저장소 이름 · 설명 안 씀 · 불일치 표시됨)을 그대로 쓴다. 이 목록에는 공개한 Catch만 나와 공개 상태가 늘 같으므로 공개 상태 글은 뺀다(바뀜).
- 이미 20개를 담았거나 담으면 60,000자를 넘는 자료는 단추가 막히고 단추 안에 「항목은 20개까지 담을 수 있습니다」 또는 「전체 글이 60,000자를 넘습니다」가 보인다(AC1.2.4).
- 담긴 Catch가 나중에 숨겨지거나 원본 저장소가 보호되면 담긴 목록에 남고 이유 글자가 붙는다(AC1.6.1·AC1.6.2).
- 첫 자료의 [위로], 마지막 자료의 [아래로]는 막힌다(AC1.3.2).

| 상태 | 글자 |
|---|---|
| 담긴 자료 없음 | 「아직 담은 자료가 없습니다.」 |
| 이름 오류 | 이름 칸 아래 「이름을 1~50자로 써 주세요.」, 담은 자료는 남는다 |
| 저장 중 | [저장]이 막히고 「저장하고 있습니다.」 |
| 저장됨 | 편집 화면에 남고 「저장했습니다.」. 새 프리셋이면 그 프리셋의 편집 화면으로 바뀐다(Q5) |
| 저장 실패 | 「저장하지 못했습니다. 다시 시도해 주세요.」, 이름과 담은 자료는 남는다(AC1.2.7·AC1.4.5) |
| 50개 가득 참 | 새 프리셋을 저장하면 「프리셋은 50개까지 만들 수 있습니다.」, 이름과 담은 자료는 남는다(AC1.2.5) |
| 상한 넘음(저장 뒤 원본이 길어짐) | 「담긴 자료와 순서」 머리에 「전체 글이 60,000자를 넘어 발행할 수 없습니다.」(AC1.6.3) |
| 지우기 | 「‘자기소개서’ 프리셋을 지울까요? 이미 보낸 발행본은 그대로 남습니다.」 확인 → 지우면 목록(M2)으로 |
| 저장 없이 떠남 | 「저장하지 않은 입력이 있습니다. 이동하시겠습니까?」(텍스트 자료 화면과 같은 경고, Q3) |

## M4. 발행 (W4, US2.1~US2.4)

```
h1 발행
h2 프리셋 고르기                                       <- 바뀜
  [자기소개서   항목 4개 · 12,300자]            (눌림)
  [포트폴리오   항목 3개 · 8,100자]             (눌림)
  [빈 프리셋   항목 0개 · 담긴 자료가 없어 고를 수 없습니다]       (막힘)
  [긴 프리셋   항목 15개 · 고르면 항목이 20개를 넘습니다]          (막힘)
  [옛 프리셋   발행할 수 없는 자료가 있습니다: Catch C]            (막힘)
h2 고른 프리셋과 순서 (2/5)                             <- 바뀜
  1 자기소개서                          [위로][아래로][빼기]
  2 포트폴리오                          [위로][아래로][빼기]
h2 제목과 비밀번호                                     <- 지금 그대로
  ...
  [다음: 발행 내용 확인]
```

- 고르기는 누르는 단추다(Q1). 다섯 개를 고르면 나머지 단추가 막히고 「프리셋은 5개까지 고를 수 있습니다.」가 보인다(AC2.1.3).
- 막힌 단추 안의 이유는 「담긴 자료가 없어 고를 수 없습니다」「고르면 항목이 20개를 넘습니다」「고르면 전체 글이 60,000자를 넘습니다」「발행할 수 없는 자료가 있습니다: (자료 이름)」이다(AC2.2.1~AC2.2.3). 같은 자료가 두 프리셋에 있으면 두 번 센다.
- 다섯 개가 차면 안 고른 단추가 모두 막히고, 5개 안내는 목록 위에 한 번만 보인다. 이때 단추 안에는 그 프리셋 자체의 이유(항목 0개, 발행할 수 없는 자료)가 있을 때만 그것을 보이고, 상한 이유는 보이지 않는다.
- 같은 이름의 프리셋은 그대로 보이고 따로 구분하지 않는다(가정, FR1.4가 같은 이름을 허용).
- 「발행 내용 확인」은 지금처럼 제목·비밀번호·만료를 보이고, 고른 자료 대신 「고른 프리셋과 순서」를 보인다(AC2.1.2).

| 상태 | 글자 |
|---|---|
| 불러오는 중 | 「프리셋 목록을 불러오고 있습니다.」 |
| 프리셋 없음 | 「아직 만든 프리셋이 없습니다.」와 <프리셋 만들러 가기>(M2로) |
| 불러오기 실패 | 「프리셋 목록을 불러오지 못했습니다.」와 [다시 불러오기] |
| 발행이 막힘(서버) | 「발행되지 않았습니다」와 「‘자기소개서’ 프리셋의 ‘Catch C’ 때문에 발행할 수 없습니다.」(AC2.4.1). 지금 막힘 안내 자리를 쓴다 |

## M5. 받은 사람 화면 (W5, US3.1~US3.4)

```
h1 (발행본 제목)                                        <- 지금
이 링크에서 할 수 있는 것 안내                          <- dev의 모습(기본 접힘)
Claude 연결                                             <- 지금
발행 시각                                               <- 지금
h2 AI 요약                                              <- 자리 바뀜(자료 위로)
  ... 요약 ... [출처]
h2 발행본 자료                                          <- 지금 이름
  [자기소개서] [포트폴리오] [긴 프리셋 이름이 여…]        <- 새로, 탭 줄
  자기소개서                                            <- 열린 탭의 프리셋 이름 전체
  h3 (종류) 자기소개서 본문 ...                          <- 지금 항목 그리기
  h3 (종류) Catch A ...
h2 발행본에 질문하기                                    <- 지금, 탭 밖
JD 요약                                                 <- 지금
```

출처로 옮겨 간 뒤:

```
h2 발행본 자료
  [자기소개서] [포트폴리오(열림)]
  포트폴리오
  h3 (PDF) 포트폴리오.pdf          <- 초점이 이 항목에 놓임(Q2)
    ... 가리킨 글이 강조됨 ...
```

- 「이 링크에서 할 수 있는 것」 안내는 #606(PR #611)으로 dev에서 기본 접힘이 됐다. 이 작업은 안내를 건드리지 않고 dev의 모습을 따른다.

- 처음 열면 첫 프리셋 탭이 열려 있다(requirements Assumptions).
- 탭 이름이 길면 뒤를 「…」로 줄인다. 탭을 누르면 탭 줄 아래에 프리셋 이름 전체가 보인다. 탭 옆에 자료 개수는 없다(AC3.1.3).
- 탭을 바꿔도 「발행본에 질문하기」 대화가 남는다(AC3.3.1).
- 출처 단추를 누르면, 가리킨 글이 다른 탭에 있으면 그 탭으로 바꾸고 그 글로 옮겨 강조하며, 초점을 그 항목에 둔다(FR3.5, AC3.4.1, Q2). [답으로 돌아가기]는 만들지 않는다(위 「화면 초안과 달라진 곳」). 답으로 돌아오는 방법은 #615가 정한다.
- 이 변경 전 발행본 링크는 지금의 접근 불가 화면(제목 「이 링크는 열람할 수 없습니다.」)이 보인다(AC3.1.4).

## M6. 작성자 발행본 상세 (W6, US3.5)

- 「발행본 자료」 자리가 M5와 같은 탭 줄·열린 탭의 프리셋 이름·항목으로 바뀐다. 그 밖의 상세 화면 구성은 지금 그대로다.
- AI 요약의 출처 단추는 M5와 같이 탭을 바꿔 그 글로 옮기고 초점을 그 항목에 둔다(AC3.5.2의 옮겨 가기 부분). 돌아가기 단추는 없다.

## M7. 텍스트 자료 화면의 탭과 지우기 확인 (US4.1·US4.4)

- 「텍스트 자료」「PDF 자료」 탭은 M5와 같은 탭 부품을 써서 화살표 키로 옮겨지고 바로 열린다. 탭 이름과 자리는 지금 그대로다(AC4.4.1·AC4.4.2).
- 텍스트 자료 지우기 확인 문장: 지금 문장 「이 자료를 삭제할까요? 이미 발행한 사본은 그대로 남고…」에 「프리셋에 담겨 있으면 거기서도 빠집니다.」를 더한다(AC4.1.1). PDF 지우기 확인 문장도 같은 말을 더한다(AC4.1.4).

## M8. 개인정보처리방침 (US4.3)

- 저장 항목 표와 「하나씩 지우기」 문장에 프리셋을 더한다. 문구는 팀장 확정 문구로 바꾼다(AC4.3.1·AC4.3.2). 화면 틀은 바뀌지 않는다.

## 화면 크기

지금 화면들과 같은 기준이다. 탭 줄이 넘치면 다음 줄로 넘어간다(rough-mockups Q7). 좁은 화면 배치를 따로 설계하지 않는다.
