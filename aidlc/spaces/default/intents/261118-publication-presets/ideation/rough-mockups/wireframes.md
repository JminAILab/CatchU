# Wireframes — 발행 프리셋 (거친 화면 초안)

근거: 승인된 의도 진술 `ideation/intent-capture/intent-statement.md`(intent-statement), 범위 문서 `ideation/scope-definition/scope-document.md`(scope-document, S1~S9), 백로그 `ideation/scope-definition/intent-backlog.md`(intent-backlog, IB-1~IB-8), 이 단계 질문 `rough-mockups-questions.md`의 답(Q1~Q7), 입력 문서 `docs/ai-dlc-input-preset/CatchU_발행_프리셋_입력.md` §3.

이 문서는 화면의 자리와 순서만 정한다. 문구·모양은 다듬은 화면 단계와 그 뒤 팀원 3의 다듬기에서 정한다(intent-statement 「하지 않는 것」). 「지금」이라고 적은 표시는 이 브랜치의 `web/src` 코드에서 확인한 그대로이고, 바뀌는 곳은 「바뀜」·「새로」로 적었다.

## W1. 상단 메뉴와 발행본 목록

상단 메뉴의 「텍스트 자료」와 「발행본」 사이에 「프리셋」을 더한다(Q1).

```
지금:  내 자산 · 텍스트 자료 · 발행본 · JD 관리
바뀜:  내 자산 · 텍스트 자료 · 프리셋 · 발행본 · JD 관리
                              ^ 새로, 프리셋 목록(W2)으로 간다
```

발행본 목록은 지금 그대로다.

```
h1 발행본
  h2 내 발행본                          [새로 발행]
  - 발행본 1 ...
  - 발행본 2 ...
```

- 접근성: 상단 메뉴는 지금 메뉴와 같은 방식으로 「프리셋」을 하나 더한다. 발행본 목록은 지금 그대로 h1 「발행본」, h2 「내 발행본」, `main` 안.

## W2. 프리셋 목록 (새로)

목록 화면과 편집 화면을 따로 둔다(Q2).

```
h1 프리셋
                                        [새 프리셋]
  h2 내 프리셋
  - 자기소개서
      항목 4개 · 12,300자 · 확인 필요 1개
      <고치기>
  - 포트폴리오
      항목 3개 · 8,100자
      <고치기>
```

| 상태 | 보이는 것 |
|---|---|
| 불러오는 중 | 「프리셋 목록을 불러오고 있습니다」 |
| 비었음 | 「아직 만든 프리셋이 없습니다」와 [새 프리셋] |
| 불러오기 실패 | 실패 안내와 [다시 불러오기]. 0개로 보이지 않는다 |
| 이름이 긺 | 목록에서는 줄여 보이고 편집 화면에서 전체가 보인다 |

- 프리셋마다 항목 수·글자 수를 보인다. 확인이 필요한 Catch·비공개 Catch가 있으면 그 수를 함께 보인다(S6).
- 접근성: h1 「프리셋」, h2 「내 프리셋」. `main` 안. 본문의 첫 Tab은 [새 프리셋].

## W3. 프리셋 편집 (새로)

```
h1 프리셋 고치기 (새로 만들 때는 「새 프리셋」)
  <프리셋 목록으로>
  h2 이름
    [ 자기소개서                     ]
  h2 담을 자료 고르기                   <- 지금 발행 화면의 「발행할 자료 고르기」를 옮김
    h3 내 Catch
      [ ] 작성자 설명을 쓴 Catch만 보기   <- 지금 발행 화면에서 옮김
      [ ] Catch A        비공개
      [ ] Catch B        확인 필요
      ...                               [더 보기]
    h3 내 텍스트 자료
      [ ] 자기소개서 본문
    h3 내 PDF 자료
      [ ] 포트폴리오.pdf
  h2 담긴 자료와 순서 (항목 4개 · 12,300자)
    1 자기소개서 본문        [위로][아래로][빼기]
    2 Catch A  비공개        [위로][아래로][빼기]
    3 Catch B  확인 필요     [위로][아래로][빼기]
    ...
  안내: 프리셋을 고쳐도 이미 보낸 링크는 바뀌지 않습니다.
  [저장]  [프리셋 지우기]
```

| 상태 | 보이는 것 |
|---|---|
| 담긴 자료 없음 | 「아직 담은 자료가 없습니다」 |
| 확인 필요·비공개 | 담을 때와 담긴 목록에서 Catch 옆에 표시한다(S6) |
| 저장 실패 | 실패 안내. 입력한 이름과 담긴 자료는 그대로 둔다 |
| 지우기 | 무엇을 지우는지 이름을 밝힌 확인을 거친다 |
| 담긴 자료의 원본이 지워짐 | 텍스트 자료나 PDF를 지우면 그 자료는 담긴 목록에서도 사라지고 자리표시를 남기지 않는다(S7) |

- 고르기 목록의 동작(내 Catch의 「더 보기」, 작성자 설명 걸러 보기)은 지금 발행 화면 그대로 옮긴다(intent-statement 「불편마다 이번에 풀리는지」).
- 순서는 「위로」「아래로」 단추로 정한다. 드래그는 없다(scope-document 범위 밖).
- 항목 수·글자 수가 발행 상한에 닿는지 판단하는 방식은 요구사항 단계에서 정한다.
- 접근성: h1 화면 이름, h2 구역마다. `main` 안. 첫 Tab은 <프리셋 목록으로>, 그다음 이름 칸.

## W4. 발행 (지금 흐름, 고르기 자리만 바뀜)

흐름은 지금 그대로다: 고르기 → 순서 → 제목과 비밀번호 → 발행 내용 확인 → 발행됨(Q3). 바뀌는 것은 앞의 두 구역이다.

```
h1 발행
  h2 프리셋 고르기                      <- 바뀜 (지금: 「발행할 자료 고르기」)
    [ ] 자기소개서      항목 4개 · 12,300자 · 확인 필요 1개
    [ ] 포트폴리오      항목 3개 · 8,100자
  h2 고른 프리셋과 순서 (2/5)           <- 바뀜 (지금: 「고른 항목과 순서 (n/20)」)
    1 자기소개서        [위로][아래로][빼기]
    2 포트폴리오        [위로][아래로][빼기]
  h2 제목과 비밀번호                    <- 지금 그대로
    ...
    [다음: 발행 내용 확인]
```

| 상태 | 보이는 것 |
|---|---|
| 불러오는 중 | 「프리셋 목록을 불러오고 있습니다」 |
| 불러오기 실패 | 실패 안내와 [다시 불러오기]. 「프리셋 없음」으로 보이지 않는다 |
| 프리셋 없음 | 「프리셋 고르기」 자리에 프리셋 화면(W2)을 가리키는 링크만 보인다. 발행 화면 안에서 프리셋을 만들지 않는다 |
| 6개째를 고르려 함 | 최대 5개라는 것을 알린다. 세부는 요구사항 단계에서 정한다 |
| 발행이 막힘 | 「발행 내용 확인」 또는 발행 뒤 안내에 어느 프리셋의 어느 자료 때문인지 보인다(S6) |

「발행 내용 확인」은 지금 그대로 제목·비밀번호·만료를 보이고, 고른 자료 대신 고른 프리셋과 그 순서를 보인다.

- 접근성: h1 「발행」, h2 구역마다(지금 그대로). `main` 안. 첫 Tab은 첫 프리셋 고르기 칸, 프리셋이 없으면 프리셋 화면을 가리키는 링크.

## W5. 받은 사람 화면 (배치가 바뀌고 탭이 생김)

순서가 바뀐다(Q4). 지금은 「발행본 자료」 다음에 「AI 요약」이 온다.

```
h1 (발행본 제목)                        <- 지금 그대로
  이 링크에서 할 수 있는 것 안내         <- 지금 그대로
  Claude 연결                           <- 지금 그대로
  발행 시각                             <- 지금 그대로
  h2 AI 요약                            <- 자리가 바뀜 (자료 위로)
    ... 요약 ... [출처]
  h2 발행본 자료                        <- 지금 이름 그대로, 아래가 탭으로 바뀜
    [자기소개서] [포트폴리오] [긴 프리셋 이름...]   <- 탭 줄, 프리셋이 하나여도 보임
    자기소개서                          <- 누른 탭의 프리셋 이름 전체
    h3 자기소개서 본문 ...
    h3 Catch A ...
  h2 발행본에 질문하기                   <- 지금 그대로, 탭 밖
    질문 ... 답 ... [출처]
  JD 요약                               <- 지금 그대로
```

출처 단추를 눌러 다른 탭의 글로 옮겨 갔을 때:

```
  h2 발행본 자료
    [자기소개서] [포트폴리오*]           <- 가리킨 글이 있는 탭으로 바뀜
    포트폴리오
    [답으로 돌아가기]                    <- 옮겨 간 글 바로 위 (Q6)
    h3 포트폴리오.pdf  (가리킨 글을 강조)
```

- [답으로 돌아가기]를 누르면 출처 단추를 누른 자리로 돌아간다. 답에서 눌렀으면 그 답으로, AI 요약에서 눌렀으면 요약으로 돌아간다. 탭은 옮겨 간 탭 그대로 둔다(Q6).
- 가리킨 글이 지금 보이는 탭에 있어도 [답으로 돌아가기]가 같은 자리에 보인다.
- 돌아간 뒤 초점은 눌렀던 출처 단추에 둔다.
- 탭을 바꿔도 「발행본에 질문하기」의 대화는 남는다. 질의응답과 AI 요약이 탭 밖에 있기 때문이다(scope-document S4).
- 탭 이름은 프리셋 이름이고, 길면 뒤를 줄인다. 탭 옆에 자료 개수는 붙이지 않는다(scope-document 범위 밖).
- 탭 줄이 넘치면 다음 줄로 넘어간다. 좁은 화면 배치를 따로 설계하지 않는다(Q7).
- 이 변경 전 발행본은 버리므로(scope-document S8) 탭이 없는 발행본 화면은 그리지 않는다.
- 접근성: h1 발행본 제목, h2 「AI 요약」·「발행본 자료」·「발행본에 질문하기」. `main` 안. 탭은 지금 자료 화면의 탭 부품에 화살표 키로 탭 사이를 옮기는 동작을 더해 쓴다(Q5). 화살표 키로 옮기면 그 탭이 바로 열린다. 탭 줄에 Tab으로 들어오면 열려 있는 탭에 초점이 놓이고, 다시 Tab을 누르면 그 탭의 자료로 들어간다.

## W6. 작성자 발행본 상세 (자료 자리가 탭으로 바뀜)

받은 사람 화면과 같은 사본 표시를 쓰므로(입력 문서 §4-3) 「발행본 자료」 자리가 W5와 같은 탭 줄과 탭의 자료로 바뀐다. 그 밖의 상세 화면 구성(링크·상태·중지 등)은 지금 그대로다.

이 화면에도 지금 AI 요약과 출처 단추가 있으므로, 출처 단추로 다른 탭의 글로 옮겨 가기와 [답으로 돌아가기]는 W5와 같다.

- 접근성: 지금 상세 화면의 제목 구조 그대로, 「발행본 자료」 아래 탭은 W5와 같은 동작.

## 자료 화면의 탭 (함께 바뀜)

「텍스트 자료」 화면의 탭(「텍스트 자료」「PDF 자료」)도 같은 탭 부품을 쓰므로 화살표 키로 탭 사이를 옮기는 동작이 함께 생긴다(Q5). 탭 이름과 자리는 지금 그대로다.

## 자료 지우기·탈퇴·개인정보처리방침 (S7)

- 텍스트 자료나 PDF를 지우는 확인 문장에, 그 자료가 프리셋에 담겨 있으면 거기서도 빠진다는 말을 더한다. 지우면 그 자료는 담긴 프리셋에서 자동으로 빠진다(W3 상태표).
- 탈퇴는 화면 변경이 없다. 탈퇴할 때 프리셋도 지운다.
- 개인정보처리방침은 문구만 바뀐다(저장 항목 표와 「하나씩 지우기」 문장에 프리셋을 더한다).

## Assumptions & Open Questions

- 프리셋 6개째·0개일 때의 세부, 상한(항목 20개·60,000자)을 세는 방식: 요구사항 단계(scope-document).
- 기존 발행본을 지울지 열리지 않게 둘지: 요구사항 단계(scope-document S8).
- 확인이 필요한 Catch를 담은 프리셋을 발행 화면에서 고를 수 있게 할지(고르면 발행 때 막히는지): 요구사항 단계.
- 프리셋 이름의 길이 상한: 요구사항 단계(입력 문서 §7).
- 항목이 0개인 프리셋을 발행 화면에서 고를 수 있는지: 요구사항 단계.
- 출처로 옮겨 간 직후 초점이 놓이는 자리와 [답으로 돌아가기]에 키보드로 닿는 방법: 다듬은 화면 단계.
- 저장하지 않은 변경을 두고 프리셋 편집 화면을 떠날 때의 처리: 다듬은 화면 단계.
