# Feasibility Assessment — 발행 프리셋

근거: 승인된 의도 진술 `ideation/intent-capture/intent-statement.md`(intent-statement), 이 단계 질문 `feasibility-questions.md`의 답(Q1~Q7), 입력 문서 `docs/ai-dlc-input-preset/CatchU_발행_프리셋_입력.md` §4(기준 커밋 `61b03716`의 지금 코드).

## 결론

**할 수 있다.** 새 기술·새 AWS 자원·새 규제 요구 없이 지금 스택으로 팀장 혼자 만들 수 있다. 다만 손이 가는 곳이 넓고(아래 「영향 범위」 9곳), 같은 화면을 팀원 3이 동시에 고치고 있으며, 계약 변경에 담당 리뷰가 필요해 11월 안 dev 반영(의도 진술의 성공 기준)이 빠듯하다. 기존 발행본을 버리기로 해(Q2·Q7) 이전 처리 부담은 없다.

## 기술 타당성

| 항목 | 판단 | 근거 |
|---|---|---|
| 기술 스택 | 지금 스택 그대로 된다. 새 라이브러리 없음. 탭 부품은 자료 화면에 이미 있는 것을 다시 쓴다 | Q3 |
| 인력 | 팀장 혼자 구현한다 | Q3 |
| 인프라 | 새 AWS 자원 없음. 개발 서버 자동 배포와 `dev-ci`를 그대로 쓰고, DB 변경은 배포 때 도는 migration으로 넣는다 | Q5 |
| 규제·개인정보 | 새 규제 요구 없음. 개인정보처리방침 문구 수정과 탈퇴 때 프리셋 삭제는 필요하다 | Q4 |
| 기존 자료 | 이 변경 전 발행본은 버린다. 지우거나 열리지 않아도 된다 | Q2, Q7 |

## 영향 범위

지금 발행본은 항목마다 순서 번호 하나로만 저장되고 묶음 개념이 없다(입력 문서 §4-1). 프리셋 구분을 더하면 아래가 함께 바뀌거나 영향을 받는다(Q1). 어디까지 고칠지는 설계에서 정하는 곳도 있다.

| # | 영역 | 무엇이 바뀌나 |
|---|---|---|
| 1 | 발행 요청과 사본 저장 | 요청에 프리셋 구분이 생기고, 저장된 항목에 프리셋 구분을 더하는 DB 변경이 든다 |
| 2 | AI 요약 근거·질의응답 머리글·검색 조각 | 지금 순서 번호만 쓴다. 순서 번호를 발행본 전체에 하나로 이어 매기면(프리셋 1의 자료, 그다음 프리셋 2의 자료) 지금 그대로 통한다. 이 세 곳에 프리셋 구분을 알릴지는 설계에서 정하고, 가장 단순한 안은 알리지 않는 것이다 |
| 3 | 받은 사람 화면·작성자 발행본 화면·출처 단추 | 같은 사본 표시를 탭으로 나누고, 출처 단추가 다른 탭으로 옮겨 가야 한다 |
| 4 | 받은 링크 읽기·JD 요약 | 사본 구조가 바뀌면 영향을 받는다. 프리셋 구분을 실을지는 요구사항 단계에서 정한다 |
| 5 | 프리셋 저장·프리셋 화면·발행 화면 | 새로 만든다. 발행 화면은 프리셋 고르기로 바뀐다 |
| 6 | 텍스트 자료·PDF 지우기 | 프리셋에 담긴 자료를 지울 때의 처리가 필요하다 |
| 7 | 탈퇴 | 프리셋도 지운다 |
| 8 | 개인정보처리방침 문구 | 저장 항목 표와 「하나씩 지우기」 문장에 프리셋을 더한다 |
| 9 | 외부 AI로 보내는 내용 | 프리셋 이름을 외부 AI에 보낼지는 설계에서 정한다. 보내면 고지 문구도 고친다(Q4) |

## 위험 분석

| 위험 | 가능성 | 영향 | 대응 |
|---|---|---|---|
| 11월 안 dev 반영을 못 맞춘다 | 중간 | 높음. 팀원 3의 화면 다듬기가 이 작업을 기다린다(intent-statement) | 범위를 의도 진술에 고정하고, 계약 변경을 먼저 올려 리뷰를 일찍 받는다 |
| 팀원 3과 같은 화면 파일이 충돌한다 | 높음 | 중간 | 팀원 3의 정리(안내 접기·박스 크기)가 먼저 dev에 들어가면 그 위에서 시작하거나, 겹치는 파일을 미리 맞춘다(Q6) |
| 계약 변경 PR의 리뷰가 늦다 | 중간 | 중간 | 받은 링크 읽기·JD 요약 담당에게 바뀌는 사본 모양을 일찍 알린다(Q6) |
| 순서 번호를 발행본 전체에 하나로 이어 매기지 않아, 요약·질의응답의 출처가 틀린 자료나 탭을 가리킨다 | 낮음 | 중간 | 설계에서 순서 번호를 발행본 전체에 하나로 이어 매기는지 확인하고, 출처 단추가 그 번호로 맞는 탭의 글을 찾는지 시험으로 묶는다 |
| 프리셋 이름이 외부 AI로 나가는데 고지가 빠진다 | 낮음 | 중간 | 설계에서 보낼지 정하고, 보내면 고지 문구 수정을 같은 작업에 넣는다(Q4) |

## Assumptions & Open Questions

- 프리셋 이름을 외부 AI에 보낼지: 설계 단계에서 정한다(Q4).
- AI 요약 근거·질의응답 머리글·검색 조각에 프리셋 구분을 알릴지: 설계 단계에서 정한다. 가장 단순한 안은 알리지 않는 것이다(영향 범위 2번).
- 받은 링크 읽기에 프리셋 구분을 실을지: 요구사항 단계에서 정한다(Q1, 입력 문서 §7).
- 기존 발행본을 「지운다」와 「열리지 않게 둔다」 중 무엇으로 할지: 요구사항 단계에서 정한다(Q2, Q7).
