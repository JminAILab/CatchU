# Unit Test Instructions — u4-privacy-policy

근거: `code-generation-plan.md`(Testing Contract, Step 3·Step 7·Step 8), 기능 설계 `functional-design/functional-spec.md` 「확정 문구」·「원문 출처와 대조」·「실패와 경계」, `functional-design/rules.md` BR1.1~BR1.5.

## 실행기와 준비

- 실행기: 지금 web 실행기, Node 내장 시험 실행기(`node --test`). 새 도구·설정을 들이지 않는다.
- 시험은 `web/test/u2-render.mjs`로 `privacy-policy.tsx`·`page.tsx`·첫 화면을 서버 렌더링해 사본(`web/src/features/privacy/privacy-policy.md`)과 대조한다. DB·네트워크·환경변수가 필요 없다.
- 미리 `web`의 의존성이 설치되어 있어야 한다(`npm --prefix web ci`, 지금 web 시험과 같음).

## 이 단위 명령

```bash
(cd web && node --test test/privacy-policy.test.mjs)
```

이 단위가 바꾸는 시험 파일은 이것 하나다. 새 시험 파일은 없다.

## 사본과 확정 문구의 차이 확인(Step 7)

```bash
git diff -- web/src/features/privacy/privacy-policy.md
```

차이가 C1~C5 다섯 곳뿐이고, 각 줄이 functional-spec 「확정 문구」 표의 새 글(C5는 `- 2026년 11월 30일: 처리하는 정보, 보관 기간, 하나씩 지우기에 프리셋(이름과 담은 자료 목록)을 더했습니다.`)과 글자 그대로 같은지 눈으로 대조한다. SHA-256 시험은 사본이 시험에 적은 값과 같은지만 보므로, 사본이 확정 문구와 같은지는 이 확인이 맡는다.

## 기대 커버리지

- 범위(mvp)의 80% 줄 커버리지는 Build and Test가 전체 시험(`npm --prefix web run test:coverage`)으로 잰다. 위 단위 명령은 커버리지 문턱을 판정하지 않는다. 문턱 설정을 바꾸지 않는다.
- 이 단위는 `privacy-policy.tsx`의 글만 바꾸고 분기를 더하지 않아, 지금 시험이 그 파일을 그리는 범위는 그대로다.
