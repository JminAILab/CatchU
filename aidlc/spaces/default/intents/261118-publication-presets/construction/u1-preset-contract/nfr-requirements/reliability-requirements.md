# Reliability Requirements — u1-preset-contract

근거: 기능 설계 `construction/u1-preset-contract/functional-design/functional-spec.md`(W1·W4·W5·W6·W7)와 `rules.md`, 기능 설계 검토 `construction/u1-preset-contract/functional-design/reviews/review-01.md`(R-01~R-08), 요구사항 `inception/requirements-analysis/requirements.md`(NFR2), 계약 `inception/contract-design/contract-summary.md`(공통 전제 「에러 대응 최소선」), 이 단계 질문 `nfr-requirements-questions.md`(Q1).

가용성 목표 수치(SLO)는 두지 않는다. 지금 api와 같은 배포·재시작 방식을 따르고, 12월 계약의 에러 대응 최소선(실패를 숨기지 않음, 다시 시도는 사람이 함, 자동 재시도 없음, 함께 바뀌어야 하는 것만 한 트랜잭션)을 지킨다.

## 쓰기의 원자성

| ID | 요구 | 확인 방법 |
|---|---|---|
| NFR2.7 | 프리셋 만들기·고치기는 한 트랜잭션이다. 검사에 걸리거나 쓰기가 실패하면 이름과 항목 모두 바뀌지 않는다(BR1.7) | 고치기 중 항목 검사에 걸리면 이름도 그대로인 시험 |
| NFR2.8 | 발행은 지금처럼 PDF 사본 복사 → 트랜잭션 → 실패면 사본 접두어 정리 순서다. 트랜잭션이 실패하면 발행본·항목·조각이 하나도 남지 않는다(C-17) | 지금 발행 실패 시험이 그대로 통과 |
| NFR2.9 | 같은 프리셋을 동시에 두 번 저장하거나, 소유 확인 뒤 자료가 지워져 저장이 DB 제약에 걸리면 500이다. 이 경우를 따로 막지 않는다(검토 R-08 결정). 둘 중 하나의 저장은 온전히 남거나, 아무것도 바뀌지 않는다 | 설계 결정. 시험하지 않음 |

## 기록 문제와 오류

| ID | 요구 | 확인 방법 |
|---|---|---|
| NFR2.10 | 원 분석 요청이 회원과 맞지 않거나 저장소 보호 관측이 없거나 불완전한 Catch는 프리셋 목록·상세·세기에서도 서버 오류(500)다. 발행과 같은 판정 함수를 쓰고, 새 이유 값·경고 로그·따로 짠 판정은 두지 않는다(Q1). 그런 Catch는 지금도 본인 Catch 목록을 500으로 만들어 고르기 목록에 나올 수 없고, 보호 관측 행은 탈퇴 때만 지워진다 | 보호 관측 행이 없는 Catch를 담은 프리셋의 목록이 500인 시험 |
| NFR2.11 | 모든 실패는 응답 코드로 드러낸다. 막힘(400·409)은 이유 하나와 blockedSources, 없음·남의 것은 404, 상한은 400·409, 그 밖은 500이다. 실패를 성공으로 바꾸거나 이유를 비우지 않는다 | 경로별 실패 시험 |

## 사본과 앞선 사본

| ID | 요구 | 확인 방법 |
|---|---|---|
| NFR2.12 | 「앞선 사본인가」 칸은 사본 항목의 필수 칸이다. 값이 없는 사본을 받는 경우를 두지 않는다. 지금 시험이 만드는 사본 객체(요약·질의응답·받은 링크 읽기·JD 요약 시험)는 이 칸을 넣도록 함께 고친다(검토 R-04) | 기존 시험이 칸을 넣은 채 통과 |
| NFR2.13 | 같은 PDF가 두 프리셋에 있으면 PDF 쪽 글 합계도 편 항목마다 더한다(두 번 셈). 잠금 결과(원본마다 한 번)를 그대로 합하지 않는다(검토 R-05) | 같은 PDF를 두 프리셋에 담아 60,000자 경계를 넘는 발행이 거부되는 시험 |

## 변경 전 발행본

| ID | 요구 | 확인 방법 |
|---|---|---|
| NFR2.14 | 마이그레이션은 변경 전 발행본 행을 모두 지운 뒤 칸 둘을 필수로 더한다. 되돌리기(down)는 칸 둘과 프리셋 표를 지우되, 지운 발행본은 되살리지 않는다 | 마이그레이션을 빈 DB와 발행본이 있는 DB에 올리고 내리는 시험 |
| NFR2.15 | 배포 전 파일 지우기는 사람이 한다(BR5.2). 지울 곳은 `members/*/publications/`만이고, S3는 `--dryrun`으로 목록을 먼저 확인한다. 원본 `members/*/materials/`와 `members/` 전체는 지우지 않는다. 이 안내를 배포 안내와 첫 PR 본문에 적는다 | PR 본문 확인 |

## 검토 R-02~R-08 반영(코드 생성에서)

기능 설계 검토의 Minor는 문서에 반영하지 않은 채 커밋됐고, 코드 생성에서 검토 권장대로 반영한다(이 단계 Q1 답).

| 검토 | 코드 생성에서 |
|---|---|
| R-02 | 프리셋 항목 position은 저장할 때 1부터 빈틈없이 매기고, 원본 삭제의 연쇄로 빈자리가 생길 수 있다. 읽을 때 position 순으로 본다 |
| R-03 | 작성자 상세 응답에서도 「앞선 사본인가」 값을 뺀다(NFR4.3) |
| R-04 | 「앞선 사본인가」 칸을 필수로 하고 시험 사본을 고친다(NFR2.12) |
| R-05 | PDF 쪽 글도 편 항목마다 두 번 센다(NFR2.13) |
| R-06 | violations의 `field`: 프리셋 저장은 `name`·`items`, 세기는 `items`, 발행은 `presetIds`(항목 수·전체 글은 `presetIds`, 빈 프리셋은 `presetIds[i]`) |
| R-07 | 제목이 없는 Catch는 세기·프리셋 응답에서도 발행과 같은 `UNTITLED_CATCH_TITLE`을 쓴다 |
| R-08 | 같은 프리셋 동시 저장의 500을 받아들인다(NFR2.9) |
