# Security Requirements — u1-preset-contract

근거: 기능 설계 `construction/u1-preset-contract/functional-design/functional-spec.md`와 `rules.md`(BR1.1·BR1.5·BR3.2·BR4.5·BR7.1), 요구사항 `inception/requirements-analysis/requirements.md`(NFR2·NFR3·NFR4), 계약 `inception/contract-design/contract-summary.md`(공통 전제 「자료 보호」, P-2·P-3), 팀 관행 Code Style(비밀값·사용자 자료를 로그·공유 로그에 남기지 않음), 보안 점검 `docs/CatchU_security_checks.md`, 이 단계 질문 `nfr-requirements-questions.md`.

## 인증과 권한

| ID | 요구 | 확인 방법 |
|---|---|---|
| NFR2.1 | 프리셋 경로 다섯과 세기 경로는 로그인 회원만 부른다. 지금 회원 경로와 같은 인증(Bearer Access 토큰)과 CSRF 검사를 쓴다 | 토큰 없는 요청이 401인 시험 |
| NFR2.2 | 프리셋 읽기·고치기·지우기는 그 회원의 프리셋만 한다. 없는 프리셋과 남의 프리셋은 구분하지 않고 404다(BR1.1) | 다른 회원의 프리셋 ID로 GET·PUT·DELETE가 404이고 그 프리셋이 바뀌지 않는 시험 |
| NFR2.3 | 프리셋에 담는 자료와 세기 경로로 묻는 자료는 요청 회원의 것만 받는다. 남의 자료 ID는 404다(BR1.5) | 다른 회원의 Catch·텍스트 자료·PDF ID로 저장·세기가 404인 시험 |
| NFR2.4 | 발행에 고른 프리셋은 요청 회원의 것만 받는다. 남의 프리셋 ID는 404이고 아무것도 쓰지 않는다(BR3.2) | 다른 회원의 프리셋 ID로 발행이 404이고 발행본·PDF 사본이 생기지 않는 시험 |
| NFR2.5 | 프리셋 항목이 가리키는 자료의 주인은 외래 키가 아니라 저장 때의 소유 확인으로 지킨다(ADR-004). 발행 트랜잭션은 지금처럼 잠근 행을 요청 회원 조건으로 다시 읽는다 | NFR2.3·NFR2.4 시험 |

## 입력 검사

| ID | 요구 | 확인 방법 |
|---|---|---|
| NFR2.6 | 본문은 정해진 칸만 받는다. 프리셋은 `name`·`items`, 세기는 `items`, 발행은 `title`·`password`·`presetIds`. 정의 밖 칸과 잘못된 모양(UUID 아님, 정해진 kind 밖)은 400이다 | 각 경로에 정의 밖 칸(발행의 옛 `items` 포함)을 넣은 시험 |
| NFR3.1 | 프리셋 이름은 앞뒤 공백만 빼고 그대로 저장한다. 서버는 이름을 HTML로 바꾸거나 해석하지 않는다. 화면에서 글자로만 그리는 것은 U2·U3이 맡는다 | `<b>`가 든 이름을 저장하고 읽어 같은 글자가 오는 시험 |

## 자료 보호

| ID | 요구 | 확인 방법 |
|---|---|---|
| NFR4.1 | 로그에는 회원 ID·프리셋 ID·발행본 ID와 오류 코드만 쓴다. 프리셋 이름과 담긴 자료 내용(제목·본문·Catch 글)은 로그에 남기지 않는다(BR7.1) | 로그 함수가 받는 인자를 ID와 코드로 제한하고, 로그 시험에서 이름 글자가 없음을 확인 |
| NFR4.2 | 오류 응답의 `details`에는 프리셋 ID와 자료 종류·ID만 싣는다(blockedSources). 이름·내용은 싣지 않는다. 오류 필터는 UUID와 정해진 kind 값만 옮긴다 | 막힘 응답 시험에서 details 모양을 확인 |
| NFR4.3 | 원본 ID(source_id)는 어떤 사본 응답에도 싣지 않고, 「앞선 사본인가」 값은 받은 링크 열람 응답과 작성자 상세 응답 모두에서 뺀다(BR4.5, 검토 R-03) | 받은 링크 열람·작성자 상세 응답에 두 칸이 없는 시험 |
| NFR4.4 | 프리셋 이름은 외부 AI로 보내지 않는다. 요약 근거·질의응답 머리글·검색 조각은 지금 모양 그대로다(ADR-007) | 요약 근거·머리글 시험에서 프리셋 이름이 없음을 확인 |

## 위협 메모

- 남의 프리셋·자료 ID 맞히기: NFR2.2~NFR2.4로 막는다. 404로 구분 없이 답해 있는지 여부도 알리지 않는다.
- 세기 경로로 남의 자료 글자 수 알아내기: NFR2.3으로 막는다.
- 발행 중 프리셋 바꾸기(같은 회원): 읽은 때의 내용으로 발행된다(BR3.2). 남의 자료 노출이 아니라 막지 않는다(코딩 절차 「기술」 행).
- 동시에 51번째 프리셋 만들기, 같은 프리셋 동시 저장: 막지 않는다(BR1.3, 검토 R-08 결정). 자기 자료 안의 일이고 남의 자료 노출·삭제 실패가 아니다.
