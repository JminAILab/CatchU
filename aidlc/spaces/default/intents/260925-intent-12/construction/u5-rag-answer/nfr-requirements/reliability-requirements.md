## 범위

가동률·복구 수치는 새로 만들지 않는다(NFR4). 이 문서는 실패를 숨기지 않고 접수와 완료를 구분하는 방식(에러 대응 최소선), 삭제된 자료를 늦은 결과가 되살리지 않는 것(NFR5), RAG 품질 평가(NFR3), 화면에서의 구분(NFR7)을 정한다.

## 요구사항

### 실패 처리와 수명

| ID | 요구사항 | 확인 | 근거 |
|---|---|---|---|
| NFR5.1 | `base_summary`는 발행본 외래 키 `ON DELETE CASCADE`로 발행본 삭제·작성자 탈퇴 때 함께 지워지고, 이 표를 만드는 PR에서 `api/docs/member-withdrawal-deletion.md` 표에 "base_summary \| 발행본" 행을 더한다. 회원 연쇄 삭제 시험(`test/db/member-cascade-delete.test.cjs`)이 통과한다 | 연쇄 삭제 시험 | NFR5, C-06, 기능 설계 BR9.1 |
| NFR5.2 | 늦게 도착한 기본 요약 결과는 행이 없거나 `FAILED`이거나 마감이 지났으면 저장하지 않고 버린다. 다시 시도하지 않는다 | 처리 중 발행본 삭제·마감 지남 시험 | NFR5, FR14.10, C-02 late-result, 기능 설계 BR5.4 |
| NFR5.3 | 기본 요약은 처리 시한 10분 하나로 실패가 확정된다. 작업 등록 실패·작업 유실이어도 읽을 때 `FAILED`가 되어 "만드는 중"에 영원히 남지 않는다. 다시 시도는 작성자의 [다시 만들기]뿐이다 | 처리기가 돌지 않은 채 10분 지남 시험 | FR6.8, C-02, 기능 설계 BR6.2 |
| NFR5.4 | 비동기 접수와 완료를 구분한다. [다시 만들기]의 `202`는 접수이며 화면은 "만드는 중"을 보인다. 작업 등록이 실패해도 `202`를 주되 경고 로그를 남긴다 | 등록 실패 합성 시험 | team.md Code Style, 기능 설계 BR7.3 |
| NFR5.5 | 예외를 삼키지 않는다. 기본 요약 처리기의 실패는 `FAILED` 저장과 실패 종류 로그로 드러내고, 질의응답 스트림의 실패는 `error` 이벤트와 로그로 드러낸다. 이미 보낸 항목은 그대로 둔다 | 실패 경로 시험 | team.md Code Style, phases/construction.md Error Handling, 기능 설계 BR4.6·BR5.5 |
| NFR5.6 | 외부 의존이 느리거나 없을 때: 다시 쓰기·질문 임베딩·답 생성 실패는 그 질문만 실패로 끝낸다. Redis 장애는 질문을 통과시킨다(기록만). 색인 준비 전·실패면 질의응답만 막고 기본 요약·열람은 그대로 둔다 | 각 의존 실패 합성 시험 | components QnA·BaseSummary, 기능 설계 BR2.2·BR3.2·BR4.6 |
| NFR5.7 | 한계로 받아들이는 것(에러 대응 최소선 6): 겹친 기본 요약 생성은 두 번 생성되고 하루 횟수를 두 번 쓴다. [다시 만들기]는 `DONE` 요약도 지우고 만들며, 실패하면 기존 요약이 사라진다. Redis 주소가 없거나 장애인 동안은 질문을 세지 않아 질문 횟수 상한이 없다. 질문당 비용이 작아(10/24 사전 시험 Haiku 약 $0.001) 받아들인다. 받은 사람 연결이 끊겨도 이미 시작한 다시 쓰기 호출(10초·200토큰)은 끝까지 돌고 결과만 버린다 | 해당 없음(기능 설계 가정 절에 기록) | C-02, 기능 설계 「Assumptions & Open Questions」, 비기능 수정 요청(R-02·R-03) |

### RAG 품질 평가

| ID | 요구사항 | 확인 | 근거 |
|---|---|---|---|
| NFR3.1 | RAG 품질은 CI 밖에서 손으로 한 번 돌리는 평가 스크립트로 잰다. U4가 통합 브랜치에 합쳐진 뒤 실제 발행 경로로 만든 시연 발행본 1개와 실제 Voyage·Claude로 측정하고, 그 전 합성 확인은 측정으로 보지 않는다 | 평가 기록의 모드 칸 | NFR3, AC19.3.1, 기능 설계 BR10.1 |
| NFR3.2 | 검색 적중률(앞 5·8·12개)과 근거 통과율을 스크립트로 계산하고, 사람이 오귀속·근거 비뒷받침·다른 곳의 맞는 근거를 판정한다. 통과 기준은 오귀속 0건, 근거 비뒷받침 1건 이하다. 넘으면 지시문 한 번 수정 또는 질의응답만 Sonnet 전환 중 하나로 조정하고 한 번만 다시 잰다 | 평가 기록 | NFR3, AC19.3.1~AC19.3.5, 기능 설계 BR10.3·BR10.4·BR10.6 |
| NFR3.3 | 평가 입력과 답·인용 원문은 저장소에 넣지 않는 로컬 파일에만 두고, `docs/` 기록에는 건수·위치·판정만 남긴다. JD 두 방식 비교도 같다 | 저장소 diff에 원문이 없는지 확인 | team.md Code Style, AC19.3.6, 기능 설계 BR10.5·BR10.7 |
