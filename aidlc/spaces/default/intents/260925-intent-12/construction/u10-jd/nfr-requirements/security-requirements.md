# U10 보안 요구사항

본인 JD와 실행 결과의 비공개, 발행본 링크 조건, 외부 AI 전송 경계를 승인된 기능 설계 안에서 정리한다. 보안 요구사항 충족이나 실제 통합 시험 완료를 주장하는 문서가 아니다.

## 인증·권한과 자료 격리

| ID | 요구사항 | 확인할 결과 | 근거 |
|---|---|---|---|
| NFR1.1 | JD CRUD·목록·실행은 회원 인증을 요구하고 소유자 식별자는 인증 정보에서 얻는다. 요청으로 받은 소유자 값을 신뢰하지 않는다. | 본인 조건이 목록·상세·변경 쿼리에 적용된다. 타인과 없는 JD·실행은 같은 404 RESOURCE_UNAVAILABLE이며 타인 제목·개수·원문이 반환되지 않는다. | 기능 명세 §3·§4·§8·§9, BR1.1·BR2.2 |
| NFR1.2 | 접수·실행 목록·상세 재열람마다 C-10 resolveForRecipient로 링크를 판정하고 실행자·publicationId를 일치시킨다. | 링크 중지·만료·삭제·비밀번호 조건을 본인·작성자도 우회하지 않는다. 로그인 오류는 AUTH_REQUIRED/AUTH_INVALID, 링크 오류는 LINK_PASSWORD_REQUIRED/LINK_UNAVAILABLE로 구분한다. | C-10~C-12, 기능 명세 §4·§8 |
| NFR1.3 | 브라우저는 C-11 getGrant·onAccessLost를 사용하고 U10이 토큰·grant·결과의 별도 영구 저장을 추가하지 않는다. | 인증·접근 상실 때 결과·선택 상태를 비우고 이전 요청의 늦은 응답이 화면을 복원하지 않는다. 회원 토큰은 기존 메모리 정책, 링크 grant는 U4의 기존 링크별 sessionStorage 정책을 따른다. | C-11, 화면 설계, 보안 점검 |
| NFR1.4 | 입력은 허용 필드·ID 형식·길이를 검사하고 SQL 매개변수 및 기존 인증 Guard를 사용한다. 합성 제공자는 시험에 명시적으로 주입한다. | 정의하지 않은 필드·잘못된 식별자를 거부한다. 시험 전용 권한 우회나 운영 실패의 합성 성공 대체가 없다. | 보안 점검, BR5.1 |

## 외부 AI·검색과 자료 보호

| ID | 요구사항 | 확인할 결과 | 근거 |
|---|---|---|---|
| NFR2.1 | 외부 AI 실행 전 C-04의 현재 판본 동의를 확인하고 공용 안내를 사용한다. JD 저장 자체에는 AI 동의·호출·횟수 차감을 요구하지 않는다. | 동의 없음은 AI_CONSENT_REQUIRED이며 동의 후 재요청도 접수 검사를 다시 거친다. 하루 한도는 C-03에서 실행자 기준으로 적용한다. 직접 올린 자기 자료는 동의 아래 전송하고 민감정보 삭제 안내를 적용한다. | FR20, C-03·C-04, 기능 명세 §3·§4, 보안 점검 |
| NFR2.2 | C-09가 반환한 같은 발행본의 조각만 C-01에 전달한다. JD 요구사항과 근거는 신뢰하지 않는 자료로 취급하고 숨긴 지시를 실행하지 않는다. | 다른 회원 자료·원본 저장소를 임의로 모으지 않는다. sourceKind·text·location·catchEvidenceUrls를 보존한다. 모델에는 현재 줄과 검색 근거를 보내며 publicationText는 공용 검사에만 사용한다. | C-01·C-09, 기능 명세 §5·§6 |
| NFR2.3 | JD는 C-01 HAIKU와 공용 인용·표기 검사를 소비한다. U10이 별도 판정 AI·영어 추출·평가 점수·도구 실행을 추가하지 않는다. | 인용·근거·AI 해석·서버 안내의 역할을 유지한다. NO_ITEMS·REFUSED·NOT_CONFIGURED·연결 오류를 정상 빈 결과로 바꾸지 않는다. 기계 대조만으로 의미적 품질을 충족했다고 보고하지 않는다. | NFR2·NFR3, 기능 명세 §6·§7, BR3.2·BR3.5 |
| NFR2.4 | 외부 호출의 주소·응답 크기·시간·횟수 제한은 기존 공용 제공자 경계에서 적용한다. 사용자 값으로 외부 호스트나 redirect 대상을 선택하는 U10 경로를 추가하지 않는다. | U10이 공용 제한을 완화하거나 비밀값을 요청·응답·큐 payload에 싣지 않는다. 큐에는 runId만 넣는다. Voyage 모델·자료 보존·학습 조건 확인은 공용 제공자 책임의 증거로 구분한다. | 보안 점검, C-01·C-02·C-09, 기능 명세 §6 |

## 안전한 화면과 위협 대응

| ID | 요구사항 | 확인할 결과 | 근거 |
|---|---|---|---|
| NFR7.1 | JD 원문·생성 내용·서버 안내는 React 텍스트로 표시한다. 근거·AI 해석·AI 초안·고정 발행본 원문을 혼동시키지 않는다. | HTML 삽입이나 HTML을 만드는 마크다운을 사용하지 않는다. 외부 링크는 보안 점검의 http(s)·허용 호스트·rel 기준을 따르고 원문 강조는 C-11 showEvidence에 검증된 위치를 전달한다. | NFR7, 보안 점검, C-01·C-11, 화면 설계 |

| 위협 | 대응 요구사항 | 기존 확인 범위 |
|---|---|---|
| 타인 JD·runId 추측, 다른 링크로 결과 열기 | NFR1.1·NFR1.2 | 두 회원의 접근 거부와 발행본 불일치 |
| 중지된 링크·만료 로그인 뒤 결과 노출 | NFR1.2·NFR1.3 | 보호 흐름·화면 상태 정리 |
| 자료 속 명령·HTML·오류 원문 노출 | NFR2.2·NFR2.3·NFR7.1·NFR6.1 | 기존 공용 검사와 U10 안전 출력·로그 검토 |
| 삭제 후 결과 부활 | NFR5.1~NFR5.3 | 삭제 관계·조건부 저장 확인 |
| 무제한 입력·호출 | NFR4.1·NFR4.2·NFR2.1 | 접수 한도·공용 차감·순차 처리 |

자료 삭제는 [신뢰성 요구사항](reliability-requirements.md), 안전한 로그는 [관측성 요구사항](observability-requirements.md)이 정본이다. 별도 규제 인증·컴플라이언스 달성이나 새로운 자료 보관 기간을 요구하지 않는다.
