# U10 관측성·검증 요구사항

현재 로거와 기존 확인 결과 표로 접수·실제 완료·실패를 구별한다. 별도 관제 화면·로그 플랫폼·분산 추적 시스템·알림 체계·자동 배포를 추가하지 않는다.

## 로그와 확인 결과

| ID | 요구사항 | 확인할 결과 | 근거 |
|---|---|---|---|
| NFR6.1 | 요청 접수, 큐 등록, 처리 단계, 실제 완료·실패를 구분한다. 시각·수준·서비스·단계와 기존 계약의 runId 등 안전한 식별자, 상태·고정 오류 분류·필요한 소요 시간만 기록한다. | 접수만으로 완료 로그를 남기지 않는다. JD·발행본·검색 조각·AI 응답 원문, 토큰·grant, 전체 URL·오류 객체·SQL·stack을 로그·오류 응답에 싣지 않는다. 필드 허용 방식으로 기록하고 함수 인자·반환값을 통째로 기록하지 않는다. | 코딩 절차 「자료와 실행 로그」, 보안 점검, C-02·공통 에러 대응 최소선 |
| NFR6.2 | 실제 실행 결과·실패·미실행을 기존 FR19 확인 결과 표에 구분한다. 합성 제공자 시험, 실제 DB 연결, 실제 C-10/C-11 연결, 실제 외부 AI 실행을 구별한다. | 명령·대상·결과·한계와 필요한 산출물 근거를 남기고 합성 통과를 실제 AI 품질·연결·배포 완료로 보고하지 않는다. 승인된 기능 설계 §11의 확인 범위를 사용한다. | NFR6·FR19, 기능 명세 §10·§11, BR5.1 |
| NFR6.3 | 실제 통합의 선행 조건과 책임을 결과에 명시한다. C-10 실제 접근 제공자·C-11 공유 화면과 근거 강조는 #416 연결 조건이다. | 미연결·미실행은 성공으로 집계하지 않는다. 완료된 U7 검사를 반복하거나 #450 실측을 U10 통과로 대체하지 않는다. 기능 사이 실패 확인은 상류 핵심 보호 흐름 범위를 유지한다. | 기능 명세 §10·§11, NFR1·NFR6 |

R-01의 사용자·저장 코드는 생성 실패로 통일하지만 로그의 처리 단계는 검색·생성을 구분한다. 공용 제공자가 안전하게 분류한 사유가 있을 때만 그 고정 분류를 사용하며 원문 예외를 기록하지 않는다. 공용 계약에 없는 새로운 오류 반환값을 요구하지 않는다. C-01 droppedCount는 기존 로그용 값이며 화면에 표시하지 않는다.

## 근거 품질 확인의 경계

| ID | 요구사항 | 확인할 결과 | 근거 |
|---|---|---|---|
| NFR3.1 | JD는 같은 JD 하나에 대한 전체 입력 방식·검색 기반 방식 결과를 나란히 기록하는 기존 비교 범위를 유지한다. | 새 서비스 실행 모드·판정 AI·반복 튜닝·CI 품질 게이트를 만들지 않는다. 질의응답 10개의 합격 수치·Sonnet 조정 절차를 JD에 적용하지 않는다. 실제 자료·외부 호출은 허용된 대상·비용·자료 취급 조건이 있을 때만 수행하고 아니면 미실행으로 남긴다. | 상류 NFR3, 기능 명세 §11, 작성 전 확인 |
| NFR3.2 | 공용 인용·표기 검사와 실제 의미적 근거 품질을 구분한다. | 기계 검사를 통과했어도 남의 기여 혼동·뜻 뒤집기·역할 부풀림을 막았다는 증거로 쓰지 않는다. 상류 질의응답 사람 평가와 #450 실측의 결과는 각각의 담당 근거로 연결하고 U10 자체 품질 완료로 대체하지 않는다. | 상류 NFR2·NFR3, 기능 명세 §10·§11 |

NFR3의 질의응답 전용 평가 조건은 U10에 비적용이지만 JD 비교 기록은 적용되므로 추적표에서 NFR3 전체를 N/A로 처리하지 않는다. 비교 기록과 실측은 후속 실제 자료 작업의 범위이며 이번 문서 작성은 그 실행이 아니다.

## 지표·알림과 한계

처리 상태·안전한 실패 분류·필요한 소요 시간은 원인 확인용이다. 새로운 SLI/SLO, 경보 임계값, 상시 모니터링 대시보드, 보존 기간, 분산 trace ID 전파 계약은 만들지 않는다. 자료 보호 기준은 로컬 로그뿐 아니라 AI·이슈·PR 공유에도 동일하게 적용한다.
