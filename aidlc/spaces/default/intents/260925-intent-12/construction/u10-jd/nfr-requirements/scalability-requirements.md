# U10 확장성 요구사항

소수 외부 사용자가 사용하는 시연 규모를 전제로 한다. 기존 입력·호출·목록 한도를 소비하며 새로운 부하 목표나 확장 장치를 만들지 않는다.

## 처리량과 데이터 증가의 경계

| ID | 요구사항 | 확인할 결과 | 근거 |
|---|---|---|---|
| NFR4.5 | 한 실행 안에서는 원문 순서대로 최대 20개 요구사항을 처리하고 각 줄의 검색·생성 호출은 최대 한 번이다. 자동 재시도·병렬 생성을 추가하지 않는다. | C-02 기존 큐를 사용하며 U10 전용 큐 서비스·worker·자동 확장 정책을 만들지 않는다. 실행 사이 전역 동시성은 공용 실행 정책을 소비하고 새 숫자를 정하지 않는다. | BR3.1·BR4.1, C-02, 기능 명세 §6 |
| NFR4.6 | C-03 공용 하루 한도를 접수 시 실행자 기준 1회 차감하고 새 실행마다 새 사본·결과 행을 만든다. | JD 저장에는 차감하지 않는다. 실행 도중 실패·큐 등록 실패를 환급하거나 자동 재접수하지 않는다. 하루 횟수 값·한국 시간 날짜 경계는 공용 정책을 따른다. | C-03, BR2.3·BR2.4 |
| NFR4.7 | 목록의 20개 cursor 페이지와 상세 분리를 유지하며 사본·결과는 승인된 삭제 관계에 따라 보관한다. | 목록 요청이 전체 원문·전체 실행 결과를 한 번에 싣지 않는다. 자료 증가를 막기 위한 자동 만료·임의 삭제·새 저장 총량 상한을 추가하지 않는다. | 기능 명세 §8·§9, NFR5, NFR4.4 |

## 용량 판단과 비적용 항목

동시 사용자 수·초당 실행 수·DB 용량·자동 확장 임계값은 승인된 목표가 없으므로 수치를 새로 만들지 않는다. NFR4.1·NFR4.2는 개별 입력·호출 크기의 경계이며 전체 시스템 용량 보장으로 해석하지 않는다.

요구사항 수와 호출 수의 한도는 정상 흐름의 비용 경계다. 큐 중복 전달 등 드문 겹침을 완전히 제거하는 새 멱등·재개 장치를 요구하지 않는다. 남의 자료 노출·삭제 실패를 막는 조건과 외래 키는 유지한다. 다른 기능의 부하·실측은 U10 시험으로 대체하지 않는다.

공용 인프라·CI 변경은 요구사항 C07의 공용 기반 책임이다. 필요성이 실제로 드러나면 기존 계약 변경 절차로 조율하며 이 문서가 확장 또는 신규 인프라의 구현 승인이 되지 않는다.
