## 상류 확정 내용

기존 승인 내용을 다시 묻지 않는다. JD는 개인 회원 소유이며 별도 관리 페이지에서 저장·수정·삭제한다. 로그인 회원이 유효한 공유 링크에 자기 JD로 실행하며 실행한 회원만 결과를 본다. 링크 작성자에게 다른 회원의 JD·결과를 공개하지 않는다. 같은 JD로 다시 실행하면 새 실행이다.

요약은 요구사항별로 순차 생성하고 원문 줄·근거·확인되지 않는 점·면접 질문의 대응을 유지한다. 근거 원문에 GitHub 기록·작성자 자료 출처를 구분해 붙인다. 공용 생성 검사를 사용하고, 근거 없는 역량 단정·점수·비율을 만들지 않는다. JD에는 Haiku를 쓰며 별도 판정 모델·Sonnet 전환을 도입하지 않는다.

접수한 작업은 브라우저를 닫아도 계속한다. 처리 시한 이후 실패하며 자동 재시도·중간 재개는 없다. 입력 초과는 접수 전에 거부하고 JD 일부를 잘라 실행하지 않는다. 링크 중지·만료는 결과 열람을 막되 그것만으로 결과를 삭제하지 않는다.

## 개발 담당 결정안

아래 값과 방법은 요구사항의 개발 담당 결정 범위에서 제안한다. 기존 승인값이나 실측된 성능 보장이 아니다. 길이는 공용 입력 검사와 같은 UTF-16 코드 단위로 센다.

| 항목 | 결정안과 이유 |
|---|---|
| JD 저장 | 제목 필수·최대 200자, 본문 필수·최대 20,000자. 공백만 있는 값 거부. AI 실행·동의 없이 저장 가능. |
| 요구사항 분리 | 비어 있지 않은 각 원문 줄을 요구사항 하나로 삼고 원문 줄 번호·내용·순서를 보존. CRLF/LF 경계를 일관되게 처리. AI로 항목을 선별하거나 임의로 합치지 않음. |
| 요약 접수 상한 | 비어 있지 않은 줄 최대 20개, 한 줄 최대 2,000자. 초과하면 실행 전체를 거부하고 수정 조건 안내. 저장된 긴 JD를 자르거나 삭제하지 않음. |
| 검색 | 요구사항마다 C-09 의미 검색 최대 6개 조각. 현재 조각 1,000자 상한과 요구사항 2,000자로 공용 입력 80,000자 안에 둠. 실제 반환 입력도 검사하고 초과하면 자르지 않음. 발행본 전체 글은 공용 검사 용도. |
| 처리 시한 | 접수 후 20분. 큐 대기 포함, 완료 시간 보장은 아님. 현재 검색 호출 10초·생성 호출 45초와 최대 20개 순차 처리에 맞춘 초기값. 시한을 넘긴 결과는 저장하지 않음. |
| 진행 확인 | 공유 링크 요약 영역의 상태 새로고침 버튼과 본인 실행 목록으로 재열람. 브라우저 저장소에 결과·접근 비밀값을 영구 저장하지 않음. |
| 일부 실패 | 요구사항별 성공·실패 대응 유지. 전체 실패·시한 초과는 실행 실패로 표시. 시한 전 저장한 일부 결과는 실패 안내와 구분해 표시. 재실행은 새 실행. |
| 빈 결과 | 정상 반환 후 검사에 남은 내용이 없으면 결과 없음으로 안내하고 호출 오류·시간 초과에 따른 실패와 구분. 자료 부재를 역량 부재로 해석하지 않으며 표기 미발견 안내는 공용 서버 안내 사용. |
| 수정·삭제 | 실행 시점 JD 입력 사본을 보존해 JD 수정이 과거 결과를 바꾸지 않도록 함. JD 삭제 때 관련 실행·결과·입력 사본 삭제. 저장·삭제 실패를 성공으로 표시하지 않고 편집 입력 보존. |

## 구성할 흐름

1. **JD 관리:** 로그인 → 내 JD 목록 → 새 작성 또는 수정 → 유효성 확인 → 저장. 타인 JD 접근 거부. 삭제 안내에 관련 요약 삭제 포함.
2. **접수:** 로그인·링크 조건·본인 JD·입력 상한·첫 AI 이용 동의·검색 준비 확인 → 공용 하루 횟수 차감과 실행·입력 사본 저장 → 저장 성공 후 백그라운드 등록 → 접수 응답. C-02·C-03의 접수·실패 규칙 적용.
3. **처리:** 저장된 요구사항마다 순차 검색 → 공용 생성·출력 검사 → 해당 요구사항 결과 기록. 삭제된 부모·종료된 실행·시한 초과를 확인해 늦은 결과 버림.
4. **재열람:** 같은 유효한 링크에서 실행자 본인의 목록·상태·결과만 조회. C-10을 요청마다 재확인. 인증 만료는 로그인 안내, 비밀번호·중지·만료는 공유 화면 접근 처리로 연결.
5. **연쇄 삭제:** 실행 회원 탈퇴·JD 삭제·발행본 삭제·발행본 작성자 탈퇴 시 실행·결과·입력 사본 삭제. 발행본 작성자 탈퇴로 다른 회원의 JD 원본까지 삭제하지 않음.
