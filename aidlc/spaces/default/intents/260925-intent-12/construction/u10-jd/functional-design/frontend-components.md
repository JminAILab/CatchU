# U10 화면 구성과 상호작용

## 화면 구성

- JdManagementPage: 별도 JD 관리 페이지. JdList, JdEditor, DeleteJdConfirm을 포함한다.
- JdList: 본인 JD 제목·수정 시각과 선택·다음 페이지 동작.
- JdEditor: 제목·본문·저장. 저장 중 중복 버튼을 막고 실패 시 입력을 유지한다.
- DeleteJdConfirm: 원본 및 관련 요약 기록 삭제 안내와 확인·취소.
- JdSummaryPanel: C-11 공유 페이지의 지정 영역. 사이드 패널이 아니다.
- JdPicker: 저장한 본인 JD 선택, JD 관리 페이지 연결. 요약 실행은 저장된 JD만 사용한다.
- JdRunList: 해당 링크에서 본인이 실행한 목록. 새로고침과 다음 페이지.
- JdRunResult: 실행 상태·요구사항별 원문·결과 없음·오류·세 칸을 표시.
- JdRequirementResult: 근거 / 자료로 확인되지 않는 점 / 면접 질문. 서버 안내·AI 해석·근거 원문 라벨을 구분.

## 부모로부터 받는 값과 소유 경계

C-11의 token, getGrant, onAccessLost, isLoggedIn, showEvidence를 그대로 받는다. grant 보관·비밀번호 확인·공유 페이지 전체 접근 흐름은 U4가 소유한다. U10은 grant를 요청 때 받아 사용하며 원문·토큰·grant를 자체 영구 저장하지 않는다. 공용 동의 창은 U2의 것을 사용한다.

근거를 누르면 showEvidence(citation.location)를 호출한다. U10이 글자 검색으로 위치를 다시 찾거나 U4의 강조 기능을 복제하지 않는다. PDF 쪽은 제공된 경우에만 전달하며 PDF 개발 전체를 기다리는 조건으로 만들지 않는다.

## 상태

| 화면 | 상태 | 동작 |
|---|---|---|
| JD 관리 | 미로그인 | 로그인 안내 |
| JD 목록 | 로딩·빈 목록·목록·오류 | 작성 또는 다시 불러오기 |
| 편집 | 편집·저장 중·입력 오류·저장 실패 | 입력 보존, 성공 후 목록 반영 |
| 요약 영역 | 미로그인 | JD·실행 목록 조회 안 함, 로그인 안내 |
| 실행 전 | JD 없음·선택됨·접수 중 | 관리 페이지 연결 또는 실행 |
| 접수 거부 | 동의 필요·검색 미준비·입력 초과·한도 도달 | 원인별 안내, 자동 실행 반복 없음 |
| 실행 결과 | PENDING | 처리 중, 상태 새로고침 |
| 실행 결과 | DONE | CONTENT·EMPTY·일부 실패를 함께 구분 |
| 실행 결과 | FAILED | 실패 이유와 저장된 일부 결과를 구분 |
| 접근 상실 | 로그인 만료 또는 링크 오류 | 현재 JD·결과 화면 상태를 비우고 각 소유자의 처리로 연결 |

로그인 변경 시 다른 회원의 목록·선택·결과가 남지 않도록 상태를 초기화한다. 권한 실패 응답은 기존 결과 위에 오류만 덧붙이지 않고 민감한 화면 내용을 제거한다. 요청 응답이 늦게 도착하면 현재 token·선택 실행·로그인 상태와 일치할 때만 반영한다.

## 입력·흐름

JD 편집에는 제목 200자·본문 20,000자 상한을 안내한다. 실행 영역은 최대 20개의 비어 있지 않은 줄·줄당 2,000자, 한 줄이 요구사항 하나라는 규칙을 안내한다. 화면 검사는 편의를 위한 것이며 서버 검사가 최종이다. 붙여넣은 JD를 조용히 잘라 저장하거나 실행하지 않는다.

JD 저장에는 외부 AI 동의 창을 띄우지 않는다. 요약 실행에는 외부 AI 전송 고지를 두며 첫 동의가 필요하면 공용 창을 연다. 동의 완료 후 한 번 재요청하며 또 거부되면 오류를 표시하고 무한 재요청하지 않는다.

현재 실행은 선택한 runId와 함께 확인한다. 재방문은 서버의 본인 실행 목록에서 복원한다. 수동 새로고침만 사용하며 자동 폴링·브라우저 알림은 도입하지 않는다. 같은 JD로 새로 실행할 때 새 실행임을 표시한다.

## 결과 문구

- EMPTY: “이번 자료에서 표시할 요약 내용이 없습니다.”
- 검색 조각 없음: 원문 줄 옆에 “이번에 찾은 자료가 없어 이 요구사항의 표기를 찾지 못했습니다.”
- SERVER_NOTICE: 공용 관문 문구를 그대로 표시하고 AI 해석으로 표시하지 않는다.
- 요구사항 처리 실패: “이 요구사항을 처리하지 못했습니다.” 개별 생성 호출 시간 초과도 GENERATION_FAILED로 받아 최초 조회·재열람 모두 이 문구로 안내한다.
- 전체 시한 초과(DEADLINE_EXCEEDED): “전체 처리 시한이 지나 완료하지 못했습니다.”
- 일부 실패: “일부 요구사항을 처리하지 못했습니다.”와 해당 행 표시.
- 근거 없는 해석은 “AI 해석”, 근거 원문은 C-01 sourceLabel 그대로 표시한다. AI 문장을 확인된 사실로 표시하지 않는다.

## API 연결과 검증

경로·오류 의미는 [기능 명세 §9](functional-spec.md#9-외부-동작과-내부-경로)를 따른다. 입력·접수 실패, 결과 없음, 일부 실패, 링크 접근 상실을 서로 다른 상태로 검증한다. C-10 실제 제공자·U4 공유 화면 연결 전에는 합성 props·제공자로 확인한 범위만 보고한다.
