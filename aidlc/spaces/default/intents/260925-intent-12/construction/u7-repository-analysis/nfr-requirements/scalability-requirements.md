# U7 저장소·분석 — 규모와 자원 요구사항
## 근거와 적용 범위

작성일: 2026-10-29. [사용자가 확인한 작성안](nfr-requirements-questions.md)을 상세화한다. 코드 구현·실측·실제 분석 완료 기록이 아니다.

직접 근거: [기능 명세](../functional-design/functional-spec.md)(functional-spec), [업무 규칙](../functional-design/rules.md)(rules), [재승인 요구사항](../../../inception/requirements-analysis/requirements.md)(requirements), [계약 요약](../../../inception/contract-design/contract-summary.md)(contract-summary). 세부 NFR ID는 이 Unit 안에서 해당 상위 NFR을 구체화하며, 전체 대응은 [traceability.json](traceability.json)에 둔다.

NFR4의 시연 규모와 FR6.6의 계정당 하루 제한을 적용한다. 새 동시 사용자 수, 초당 요청 수, 성장률 목표는 정하지 않는다.

## 규모 요구사항

| ID | 요구사항 | 판정·검증 방법 |
|---|---|---|
| NFR4.4 | 현재 worker 프로세스당 동시 분석 1을 유지한다. 커밋 반영량을 늘리기 위해 병렬 생성이나 소비자 자동 증설을 도입하지 않는다. | 실행 설정에서 동시 수를 확인하고 실제 소비자 수를 측정 기록에 남긴다. 소비자가 여러 개면 전체 동시 수는 합이므로 프로세스당 1을 서비스 전체 1로 오인하지 않는다. |
| NFR4.5 | 새 분석의 비용·자원 사용은 U2 C-03의 하루 소비와 U7 요청당 수집·생성 상한으로 제어한다. 등록·조회·같은 요청의 재응답은 새 실행으로 세지 않는다. | 신규 접수 트랜잭션에서 ANALYSIS 소비가 연결되고 한도 초과 시 새 요청·동의·시도가 저장되지 않는지 확인한다. 요청 저장 실패면 같은 트랜잭션의 소비도 되돌아간다. 실행 실패는 환급하지 않는다. |

## 용량을 판단할 근거

| 대상 | 기록할 값 | 적용 방법 |
|---|---|---|
| 요청 하나 | 커밋·상세·관계 호출·수집 바이트, 후보·생성 횟수, 실행 시간 | [성능 요구사항](performance-requirements.md)의 측정으로 상한 간 충돌을 확인 |
| 실행 환경 | worker 소비자 수, 현재 동시 수, 큐 대기 시간, 실행/반영 소요 | 새 등록 경로 실측이 이 환경에서 나온 결과임을 명시. 수치만 다른 환경에 일반화하지 않음 |
| 회원의 실행 접수 | C-03 ALLOWED/LIMIT_REACHED, KST 날짜 경계 | U2의 계약 값을 사용. U7만의 별도 하루 계수기나 잔여 횟수 UI를 만들지 않음 |
| 저장 자료 | 회원별 등록, 요청·동의·시도·결과와 실제 부모 관계 | 자료 수명은 [신뢰성 요구사항](reliability-requirements.md)의 삭제 규칙을 따름. 자동 보관 만료·청소 장치는 추가하지 않음 |

현재 동시 수의 근거는 [worker 설정·배포 제약](../../../../../../../../worker/docs/queue-consumer.md)이다. 상한 값과 하루 횟수는 서로 다른 목적이다. 하루 횟수에 여유가 있어도 요청 한 건의 크기·호출·시간 상한은 유지한다.

## 한도와 대기 처리

분석은 기존 Redis/BullMQ 비동기 경로로 처리한다. 큐 대기가 길어져 접수 처리 시한 안에 끝나지 않은 요청은 기존 시한 판정 대상이며, 접수 응답을 완료로 표시하지 않는다. 접수 이후 큐 전달이 실패해도 이미 센 실행 횟수는 환급하지 않는다.

같은 키·같은 본문 재응답과 진행 중 요청 확인의 기존 보호는 유지한다. 드물게 겹치는 호출을 막기 위한 새 분산 잠금·추가 중복 제거 장치는 만들지 않는다. C-03의 원자적 소비와 기존 접수 보호를 그대로 쓰며, 남의 자료 노출·삭제 실패 방지는 줄이지 않는다.

## 기술과 인프라 경계

시연을 위해 캐시, 별도 큐, 샤딩, 읽기 복제본, 자동 확장 정책을 추가하지 않는다. 현재 실행 수에서 약 500개 반영을 확인할 수 없는 경우 실패 지점·상한·영향을 기록하고 담당 결정으로 조정한다. 동시 수를 늘려야 한다는 판단이 나면 기존 단일 소비자 제약과 종료 처리를 바꾸는 별도 설계 검토가 필요하며, 이 문서가 그 변경을 승인하지 않는다.

배포·공유 인프라는 기존 AWS 작업을 따른다. 라이브러리·설정·마이그레이션의 U7 변경은 U7 코드 PR에 포함하고 공용 기반 변경은 계약과 팀 운영 경계를 따른다.
