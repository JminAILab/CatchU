# U7 저장소·분석 — 보안 요구사항
## 근거와 적용 범위

작성일: 2026-10-29. [사용자가 확인한 작성안](nfr-requirements-questions.md)을 상세화한다. 코드 구현·실측·실제 분석 완료 기록이 아니다.

직접 근거: [기능 명세](../functional-design/functional-spec.md)(functional-spec), [업무 규칙](../functional-design/rules.md)(rules), [재승인 요구사항](../../../inception/requirements-analysis/requirements.md)(requirements), [계약 요약](../../../inception/contract-design/contract-summary.md)(contract-summary). 세부 NFR ID는 이 Unit 안에서 해당 상위 NFR을 구체화하며, 전체 대응은 [traceability.json](traceability.json)에 둔다.

NFR1·NFR2, FR1.2·FR1.7, C-04의 분석 동의 예외, C-06을 적용한다. [보안 점검](../../../../../../../../docs/CatchU_security_checks.md)과 [자료와 실행 로그](../../../../../../../../docs/CatchU_coding_procedures.md#자료와-실행-로그)의 해당 항목을 구체화하며 새 법적 적합성·인증 획득을 주장하지 않는다.

## 인증·권한·입력 요구사항

| ID | 요구사항 | 판정·검증 방법 |
|---|---|---|
| NFR1.1 | 회원 API의 기존 인증을 유지한다. 등록·요청·동의·결과는 인증 회원과 같은 소유자 범위에서 읽고 쓴다. 내부 worker 조회는 회원 인증과 분리된 기존 서비스 인증을 쓴다. | 두 회원의 등록·요청 식별자를 서로 바꾼 거부 사례를 확인한다. 다른 회원 자원과 없는 자원은 같은 접근 불가 응답을 쓰며 내부 참조 불일치는 기존 계약대로 처리한다. 시험용 우회 권한을 만들지 않는다. |
| NFR1.2 | 저장소 주소와 메시지의 형식·허용 필드를 검증한다. 외부 호출은 고정 GitHub/생성 제공자 호스트, 검증한 좌표와 기존 시간·응답 크기 제한만 사용하며 redirect를 따르지 않는다. | GitHub 외 호스트, 사용자정보·포트·쿼리·fragment·추가 경로와 정의하지 않은 필드를 거부한다. 응답 속 URL이나 사용자 입력으로 요청 호스트를 바꾸지 못하는지 확인한다. |
| NFR1.3 | 토큰·키·민감 원문을 화면·오류·일반 로그에 노출하지 않는다. 기존 운영 설정 검증과 개발/시험 환경 한정 MOCK 보호를 유지한다. | 누락·잘못된 운영 필수 비밀값은 기존 기동 실패 동작을 유지한다. 개발·시험의 LIVE 설정 없음은 기존 비활성 규칙을 따른다. API 응답·예외·SDK 로그에 비밀값과 원문이 없는지 합성 값으로 확인한다. |

등록 허가 조건에 저장소 소유·기여 관계를 추가하지 않는다. 본인 GitHub 연결 신원, 공개 여부, 지원 범위는 등록·접수·worker의 각 확인 지점에서 대조한다. 404나 외부 조회 실패를 비공개로 추정하지 않는다. 다른 회원의 등록과 동의 참조로 실행 범위를 바꾸지 못하게 한다.

주소 정규화는 기능 명세의 앞뒤 공백·끝 슬래시·선택적 .git 처리 범위다. 입력 URL을 그대로 HTTP 클라이언트에 넘기지 않고 서버가 확인한 저장소 ID와 좌표를 사용한다. SQL은 매개변수 바인딩을 사용하며 셸 실행·eval로 해석하지 않는다.

## 외부 AI·동의·출력 요구사항

| ID | 요구사항 | 판정·검증 방법 |
|---|---|---|
| NFR2.1 | 신규 분석과 허용된 실패 재요청마다 현재 고지·범위 판본에 동의받고 그 요청에 고정한다. 등록만으로 분석이나 동의를 만들지 않는다. | accepted 누락·거짓·이전 판본·다른 등록의 참조는 접수되지 않아야 한다. 동일 키 재응답은 기존 요청이며 새 동의나 새 소비를 만들지 않는다. |
| NFR2.2 | 저장소 글은 신뢰할 수 없는 자료로 분리하고 기존 비밀값·개인정보 가리기를 거쳐 외부 AI에 보낸다. 다른 회원 자료·자격정보·허용 범위 밖 자료를 넣지 않는다. | 기존 가리기와 자료/지시문 분리 검사를 유지하고 새 등록 경로에도 동일하게 적용되는지 확인한다. 텍스트·PDF 업로드의 미가리기 예외를 저장소 수집에 적용하지 않는다. |
| NFR2.3 | 기존 후보·본인 기여·근거 대조를 유지한다. 생성 문구를 확인된 작업 사실로 승격하지 않고, 화면은 React 텍스트와 허용한 GitHub 근거 링크를 사용한다. | 기존 생성 출력 검증과 본인 커밋 판정을 재사용한다. 근거 없는 기여·가린 자료를 결과로 만들지 않는다. HTML 삽입을 쓰지 않고 외부 링크에는 기존 호스트 제한과 noopener noreferrer를 적용한다. |
| NFR2.4 | 기존 ClaudeProvider와 생성/제목 교정의 Haiku 5.5 설정을 재사용한다. SDK 자동 재시도·다른 모델로의 실패 재호출을 추가하지 않는다. | 기존 고정 제공자 주소·SDK 재시도 0·응답 크기·입출력 제한을 보존한다. 실제 실행 때 모델·시간·토큰·실패 원인 등 안전한 제공자 관측값을 기록한다. |

분석은 C-04의 첫 이용 AI 동의와 함께 존재하는 요청별 동의 경로다. U2 공용 동의 창으로 분석 동의를 대체하지 않는다. Voyage 임베딩과 발행본 AI 공통 게이트는 U7의 새 경로가 아니다. NFR3의 질의응답 10개 품질 평가는 U7에 새로 적용하지 않으며, 기존 저장소 분석의 가리기·기여·생성 검증은 유지한다.

현재 제공자 설정의 근거는 [생성 제공자](../../../../../../../../worker/docs/generation-provider.md)다. 제공자 문서에 있는 과거 실측과 처리 위치 관측은 당시 기록이며, 새 실행 환경·자료 전송 조건이 확인됐다는 증거로 대체하지 않는다.

## 검증과 한계

변경한 입력·권한·동의·가리기·출력 경계의 정상·거부 검사를 기존 시험 체계에서 확인한다. 새 보안 플랫폼·관제·인증 절차를 만들지 않는다. 외부 AI 자체의 내용 정확성을 기계 검사만으로 보장하지 않으며 기존 분석 판정의 한계를 보존한다.

실제 자료 검사는 허용된 대상·범위·비용·자료 취급 조건 안에서만 수행하고 합성 검사와 구분한다. 실제 거부 1~2종은 [관측 요구사항](observability-requirements.md)의 실제 확인 표에 남긴다. 이 문서 작성으로 실제 호출·저장소 공개·보호 검증을 완료했다고 보지 않는다.
