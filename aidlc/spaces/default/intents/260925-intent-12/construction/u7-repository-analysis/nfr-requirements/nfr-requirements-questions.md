## 성능·처리량 작성안

약 500개 커밋을 목록에서 읽는 것만으로 성공으로 보지 않는다. 목록 → 필요한 상세·관계 조회 → 본인 기여와 후보 판정 → 실제 생성 → 결과 반영의 개수와 제외·중단 이유를 함께 대조한다. 기존 후보 묶음 규칙을 유지하므로 커밋 500개가 Catch 500개를 뜻하지 않는다.

현재 체크아웃 `5551cf8c43a468d71293932979c856e9a18132ab`의 다음 값은 실측 출발점이다. 이번 단계에서 새 수치로 확정하지 않는다.

상한 조정은 NFR 설계에서 측정 방법과 변경 지점을 구체화하고 구현·실제 측정 결과로 값을 정한다. 수집·생성·worker 전체·접수 처리 시한의 관계와 큐 대기·반영 시간을 함께 기록한다. 기존 10월 실측은 참고이며 새 직접 등록 경로의 성능 증거가 아니다. 새 응답 지연 목표, 처리량 보장, 동시 사용자 수 목표, 가동률·복구 수치, 부하 시험 플랫폼은 추가하지 않는다.

## 보안·자료 수명 작성안

- 회원용 경로는 기존 인증을 유지하고 등록·분석 요청·결과를 소유자 조건으로 조회한다. 다른 회원의 자원과 없는 자원은 같은 접근 불가 응답으로 처리한다. worker 내부 조회는 기존 서비스 인증을 쓴다.
- 사용자 주소는 승인된 GitHub 저장소 루트 형식만 해석하고, 실제 호출 호스트는 코드에 고정한다. 사용자 값이나 응답 속 URL로 호스트를 바꾸지 않고 redirect를 따르지 않는다. 외부 호출의 시간·응답 크기 보호를 유지한다.
- 요청별 고지·동의 판본과 수집 범위를 고정한다. 주소 등록이나 다른 AI 기능의 첫 이용 동의를 분석 동의로 대신하지 않는다. 등록 때 저장소 소유·기여 관계를 허가 조건으로 추가하지 않는다.
- 저장소 글을 신뢰할 수 없는 자료로 다루고, 기존 비밀값·개인정보 가리기와 근거·기여 판정을 유지한다. 텍스트·PDF 자료의 개인정보 미가리기 예외는 저장소 분석에 적용하지 않는다.
- 새 등록과 관련 자료는 회원·요청 등 실제 부모를 참조하고 C-06의 연쇄 삭제 및 필요한 동일 소유자 복합 외래 키를 따른다. 부모가 삭제돼 결과 저장이 거부되면 버리고 다시 실행하지 않는다. 회원 탈퇴와 분석 결과가 겹칠 때의 기존 보호를 유지한다.
- 토큰·키·원문·프롬프트·모델 응답·오류 객체를 통째로 로그나 이슈에 붙이지 않는다. 화면은 텍스트 출력과 허용한 근거 링크를 사용한다.

## 신뢰성·사용자 안내 작성안

- 접수, 처리, 결과 반영을 구분한다. 큐에 넣음·결과 수신 성공만으로 화면 완료를 표시하지 않는다.
- 본인 커밋 관측은 UNKNOWN/NONE/FOUND로 유지한다. 조회 장애나 상한으로 확인하지 못한 것을 본인 기록 없음으로 바꾸지 않는다. 본인 커밋은 있지만 후보가 없는 경우도 따로 안내한다.
- 기존 시한 닫기와 서버의 제한된 실패 재요청 판정을 재사용한다. 조회 실패는 상태 새로고침으로 확인하며 새 분석을 자동 실행하지 않는다. 정상 완료·정상 0건·유효 부분 결과의 재분석은 추가하지 않는다.
- U2 C-03은 새 분석 접수 트랜잭션 안에서 소비한다. 같은 요청의 재응답·주소 등록·상태 조회는 소비하지 않는다. 실패한 실행은 환급하지 않으며 하루 한도 도달은 일반 요청 빈도 제한과 구분한다.
- 새 자동 복구, 분석 재시도, 모델 자동 대체, 별도 관제 화면, 백업·재해 복구 체계는 이 Unit에 추가하지 않는다.

## 관측·검증 작성안

기존 요청 ID·시도 ID로 수집·후보·생성·수신·반영과 본인 화면 결과를 연결한다. 시각·환경·코드 버전·대상 리비전·최종 상태, 단계별 개수·소요 시간·안전한 실패 사유와 한계를 필요한 범위로 남긴다. 기존 단계·제공자 로그를 우선 쓰며 새 로그 플랫폼·대시보드는 만들지 않는다.

U7 완료 조건은 [기존 Unit 이슈 #424](https://github.com/JminAILab/CatchU/issues/424)의 실제 분석과 거부 사례 1~2종, 통합 브랜치 병합이다. 실제 GitHub 수집 → 실제 생성 → 결과 반영 → 본인 화면의 Catch·근거 확인을 새 등록 경로로 잇는다. 전체 통합 확인은 U2가 취합하고, U7은 같은 확인 표에 자신의 실제·실패·미실행 증거를 제공한다. 합성 검사·기존 선정 경로·로컬 성공을 새 흐름의 AWS 실제 확인으로 바꾸어 적지 않는다.

새 임의 품질 점수나 기능별 동시 요청·재전송·늦은 결과 시험 체계를 추가하지 않는다. 기존 보호 검사는 유지하며 변경한 입력·회원 권한·가리기·상한/상태 판정을 확인한다. NFR3의 질의응답 10개 평가는 U7 소유가 아니므로 U7 추적표에는 적용 대상 아님과 이유를 남긴다.

## 기술 선택 작성안

기존 Next.js/React·NestJS/TypeORM·PostgreSQL·FastAPI worker·Redis/BullMQ와 실제 생성 제공자 `ClaudeProvider`를 재사용한다. [web 의존성](../../../../../../../../web/package.json), [api 의존성](../../../../../../../../api/package.json), [worker 의존성](../../../../../../../../worker/pyproject.toml)과 각 잠금 파일을 기준으로 하며 이 단계에서 업그레이드하지 않는다. 생성과 제목 교정은 기존 `claude-haiku-5-5` 설정을 유지하고 SDK 자동 재시도도 꺼 둔다([현재 제공자](../../../../../../../../worker/docs/generation-provider.md)).

새 분석 경로 전체를 U2 AiRun·AiGenerationGate로 옮기지 않는다. U2에서는 C-03 한도 계약을 연결하고 C-06 삭제 규칙을 따른다. Voyage 임베딩·발행 색인·JD 기능은 U7 기술 선택에 넣지 않는다. 배포는 기존 AWS 기반을 사용하며 인프라·CI 신설은 범위 밖이다.
