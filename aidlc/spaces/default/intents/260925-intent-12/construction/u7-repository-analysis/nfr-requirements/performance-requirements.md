# U7 저장소·분석 — 성능 요구사항
## 근거와 적용 범위

작성일: 2026-10-29. [사용자가 확인한 작성안](nfr-requirements-questions.md)을 상세화한다. 코드 구현·실측·실제 분석 완료 기록이 아니다.

직접 근거: [기능 명세](../functional-design/functional-spec.md)(functional-spec), [업무 규칙](../functional-design/rules.md)(rules), [재승인 요구사항](../../../inception/requirements-analysis/requirements.md)(requirements), [계약 요약](../../../inception/contract-design/contract-summary.md)(contract-summary). 세부 NFR ID는 이 Unit 안에서 해당 상위 NFR을 구체화하며, 전체 대응은 [traceability.json](traceability.json)에 둔다.

NFR4와 FR1.6을 따른다. 대상은 소수 외부 사용자가 쓰는 시연 규모다. 약 500개 커밋의 실제 반영을 확인하며 별도 응답 지연·처리량·가동률 목표를 만들지 않는다.

## 성능 요구사항

| ID | 요구사항 | 판정·검증 방법 |
|---|---|---|
| NFR4.1 | 팀장 계정의 CatchU 저장소 약 500개 커밋이 수집·판정에 반영되는지 확인한다. 목록 개수만 채우고 상세·관계 조회가 부족한 상태를 충족으로 보지 않는다. | 동일 실행에서 목록·본인 커밋 관측·필요 상세·관계 확인·후보·생성·수신·반영 건수와 제외 이유를 대조한다. OQ2에 따른 대체 대상이면 팀장이 정한 분석 대상과 기준을 함께 적는다. |
| NFR4.2 | 수집, 생성, worker 전체 실행, 접수 처리 시한을 함께 조정한다. 각 시간의 시작점과 큐 대기·결과 반영 시간을 구분한다. | 측정 환경·상한 설정·단계별 시작/종료·대기 시간을 기록하고, 먼저 끝난 상한 때문에 뒤 단계가 잘렸는지 확인한다. 새 수치는 실측 결과로 정하며 현재 값을 새 보장으로 쓰지 않는다. |
| NFR4.3 | 개수·호출·시간·응답 크기·전체 수집량·생성 입력/출력 상한을 유지한다. 상한 증가가 무제한 외부 호출이나 자료 확대로 이어지지 않아야 한다. | 개수 범위 초과는 기존 수집 한계로, 필요한 조회의 호출·시간·총량 초과는 기존 수집 실패로 기록한다. 생성 상한 때문에 생성하지 못한 후보도 기존 부분 실패 의미를 유지한다. |

## 현재 구현 기준값

아래는 기준 커밋 `5551cf8c43a468d71293932979c856e9a18132ab`의 값이다. 기존 결정과 제안값이 섞여 있으므로 모두 새 확정값으로 인용하지 않는다.

| 구간 | 현재 값 | 지위·확인할 관계 |
|---|---|---|
| 커밋·관계 수집 | 목록 500, 본인 커밋 상세 200, GitHub HTTP 호출 300 | 수집 모듈의 실측 전 제안값. 필요한 관계 조회 호출도 같은 예산을 사용하므로 목록 500만으로 상세 반영을 보장하지 않음 |
| 수집 자원 | 10분, 전체 50 MiB, 단일 응답 10 MiB | 수집 모듈의 제안값. 응답 크기 한계와 요청 전체 예산 초과를 구분 |
| 생성 횟수 | 생성 200회, 제목 교정 요청당 20회·제목당 최대 3회 | 생성 200회와 제목당 3회는 기존 팀장 결정. FR1.6에 따라 생성 상한은 재측정하며 제목 교정 규칙은 확대하지 않음 |
| 생성 호출 | 생성 45초·교정 20초, 자료 24,000 B·지시문 포함 32,000 B, 출력 4,000 B | 생성 모듈의 제안값. 남은 실행 시간이 호출 시간보다 짧으면 새 호출을 시작하지 않음 |
| worker 전체 | 작업을 꺼낸 시각부터 20분, 생성 마감은 그 시각 + 20분 − 60초 | 현재 실행 장치의 값. 수집 10분도 작업을 꺼낸 시각부터 계산 |
| api 처리 시한 | 접수 시각부터 60분, 닫기 판정 완료 후 1분 뒤 다음 판정 | 현재 계약·구현. 60분은 화면 완료 보장 시간이 아니며 큐 대기·반영 시간과 판정 주기가 별도로 영향을 줌 |

## 측정과 판정

- 대상 저장소·분석 대상 리비전, 연결 계정의 역할, 코드 버전과 환경을 고정해 기록한다. 공개 여부 또는 대체 대상은 요구사항 OQ2를 따른다.
- 커밋 목록 수, 확인한 본인 커밋 수, 필요한 상세와 관계 조회의 수행/제외 수, GitHub 호출 수·받은 바이트·수집 시간을 기록한다.
- 후보 수와 생성 대상 수, 실제 생성·제목 교정 호출 수, 생성하지 못한 이유, 검증된 결과·새로 반영된 Catch·기존 작업 참조 수를 구분한다. 기존 묶음·작업 동일성 규칙 때문에 각 수가 같을 필요는 없다.
- 큐 대기, worker 실행, 생성 종료, 결과 수신, DB 반영과 본인 화면 확인을 잇는다. 후보별 내부 원문을 통째로 출력하지 않고 기존 안전한 건수·상태 기록을 우선 사용한다.
- 실제 생성 제공자의 토큰·시간과 허용된 비용 범위를 대조한다. 이 문서에는 현재 가격이나 실행 비용을 추정해 보장하지 않는다.
- 상한에 걸린 자료를 말없이 빼고 전체 성공으로 보고하지 않는다. 본인 기록이 없음을 확정하지 못했으면 UNKNOWN이며, 해당 실행의 한계와 미확인 범위를 기록한다.

## 값 확정과 완료 경계

NFR 설계에서 변경 지점·측정 방법을 구체화하고 구현·실측에서 값을 확정한다. 기존 10월 실측은 참고 자료이며 새 직접 등록 경로의 성공 증거가 아니다. 약 500개 목록을 조회해도 필요한 판정·생성·반영이 상한 때문에 누락되면 충족으로 표시하지 않는다. 기능상 정상적으로 제외한 자료와 자원 상한에 막힌 자료는 구분한다.

실제 실행 전 대상 공개 결정·실행 환경·자격정보·허용 자료 범위와 비용 조건을 확인한다. 준비되지 않았으면 미실행으로 남긴다. 최종 증거와 U7 완료 기준은 [관측 요구사항](observability-requirements.md)을 따른다.
