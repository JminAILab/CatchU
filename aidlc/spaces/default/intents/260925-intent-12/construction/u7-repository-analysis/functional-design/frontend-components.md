## 기존 모달의 유지와 대체

URL 입력 방식은 FR1.2의 직접 등록 요구를 구현하기 위해 사용자에게 확인받은 설계 선택이다. 기존 화면 구성은 `web/src/features/repository-management`와 `web/src/features/analysis-request`를 근거로 한다.

| 영역 | 처리 | 사용자 행동 |
|---|---|---|
| 내 자산의 GitHub 연결 관리 진입 | 유지 | 기존 버튼으로 모달 열기 |
| 모달 제목·닫기·키보드/초점 처리 | 유지 | 기존 모달 사용 |
| 상단 연결된 저장소 | 유지 | 분석 이력·상태 확인, 상태 새로고침, Catch 보기 |
| 실패 요청 아코디언 | 유지 | 서버가 허용한 요청만 현재 고지로 다시 동의하고 재요청 |
| 하단 연결할 수 있는 저장소 | 대체 | 사전 선정 목록 선택 대신 공개 저장소 주소 입력·등록 |
| 등록 결과와 고지·분석 요청 | 기존 요청 영역 확장 | 확인한 저장소 이름·주소를 보고 고지에 동의하여 분석 요청 |
| 요청 중·응답 불명·거부 안내 | 유지·원인 구분 추가 | 기존 요청 확인, 하루 한도·공개 여부 등 안내 |

새 페이지나 별도 저장소 탐색 모달은 만들지 않는다. 상단은 분석 접수 이력이 있는 저장소를 보여 주므로 등록만 끝난 저장소를 분석 완료나 이력으로 표시하지 않는다. 하단에서 본인 등록 목록을 다시 읽어 아직 분석하지 않은 등록을 선택할 수 있다. 이 목록은 팀 선정 목록이 아니며 신규 주소 입력을 대체하지 않는다.

## 논리 컴포넌트와 상태 소유

| 구성 | 입력 | 소유 상태/출력 |
|---|---|---|
| RepositoryManagement | 본인 연결·등록·분석 이력 공급, Catch 보기 이동 | 열림, 펼친 이력, 조회 상태, 공유 요청 상태 객체의 수명 |
| RepositoryRegistrationInput | 연결 가능 여부, 등록 동작 | 주소 초안, 입력 오류, 등록 중/실패/확인된 저장소 |
| AnalysisRequestSection | 확인된 등록, 현재 고지, 공유 요청 상태 | 고지 조회, 요청 중/응답 불명/거부/접수 안내 |
| ConnectedList | 본인 최신 분석 상태 목록 | 진행/완료/부분/실패/조회 실패 표시 |
| RetryRequest | 서버 retry.allowed와 최신 요청, 현재 범위·고지 | 새 동의·새 키 요청을 같은 공유 요청 상태에 전달 |

등록 정보는 서버가 정본이다. 화면은 주소에서 저장소 ID나 범위 판본을 만들어 보내지 않는다. 관측 정보·상태·재요청 허용 여부 역시 서버 응답을 사용하며 후보 수 0만으로 본인 기록 없음을 추정하지 않는다.

기존 공유 상태 객체를 모달 바깥에서 보유하여 같은 회원·화면에서 모달을 닫았다 열어도 보낸 요청의 키·본문을 유지한다. 주소 초안도 그 수명에서 보유하되 화면 이동·회원 변경 때 버린다. 새 영속 저장·자동 분석 실행은 없다. 요청 중 또는 응답 불명인 동안 다른 주소의 분석으로 바꾸지 못하게 한다.

## 화면 흐름

1. 연결 상태를 확인한다. 미연결/재인증 필요는 기존 연결 안내, 확인 실패는 조회 실패로 보여 준다.
2. 주소 입력 → [저장소 등록] → 서버가 확인한 이름·주소·등록 상태를 표시한다. 실패하면 입력을 남겨 고칠 수 있게 한다.
3. 등록 완료와 현재 고지 조회 완료 후 [동의하고 분석 요청]을 활성화한다. 등록 버튼은 외부 AI 동의 버튼이 아니다.
4. 접수 202 또는 기존 요청 200을 안내하고 상단 이력을 다시 읽는다. 이력 조회만 실패하면 접수 안내는 유지한다.
5. [상태 새로고침]으로 확인한다. 완료된 본인 결과만 [Catch 보기]로 이동한다.
6. 서버가 최신 실패의 재요청을 허용한 경우에만 아코디언에서 현재 고지·새 동의로 요청한다. 같은 요청 재전송과 실패 재요청은 서로 다른 버튼·의미다.

## 표시·오류·접근성

| 상태 | 표시와 동작 |
|---|---|
| 아직 등록 없음 | 주소 입력 안내, 분석 완료나 실패로 표시하지 않음 |
| 잘못된 주소 | 주소 필드와 연결된 오류 문구, 입력 보존 |
| 비공개 확인/지원 불가 | 서버가 확인한 이유와 수정할 행동 |
| 조회 실패 | 재조회 안내, 본인 기록 없음/분석 실패로 단정하지 않음 |
| ownCommitObservation=NONE + 정상 반영된 EMPTY | 본인 기록이 없어 Catch가 만들어지지 않았다는 안내 |
| FOUND + 정상 반영된 EMPTY | 본인 기록은 확인했으나 생성할 Catch가 없다는 안내 |
| UNKNOWN | 실패·수집 범위 한계를 있는 그대로 표시 |
| PARTIAL_FAILED | 확인된 결과와 실패 부분 구분, 추가 생성 버튼 없음 |
| DAILY_LIMIT_REACHED | 오늘 한도 도달 안내, 남은 횟수 없음, 짧은 자동 재시도 안내 없음 |
| 기존 일반 429 | 기존 Retry-After 대기와 사용자가 누르는 동일 요청 재전송 |
| 응답 불명 | 기존 키·본문 보존, 동일 요청 확인만 제공, 자동 새 키 요청 없음 |

주소 필드에 보이는 레이블과 오류 연결을 두고 진행 상태는 글자로 알린다. 키보드 열기·닫기·초점 복귀를 기존 모달에서 유지한다. 고지와 서버 메시지는 일반 텍스트로 표시하고 HTML로 실행하지 않는다. 기존 사용자 입력을 조회 오류로 지우지 않는다.

## 기능 명세 연결과 확인

[functional-spec.md](functional-spec.md)의 F1~F4와 오류 표를 따른다. 모달 유지/하단 대체, 등록 성공과 분석 접수의 구분, 닫기/재열기의 보낸 요청 보존, 본인 기록 없음/후보 없음/조회 실패 구분, 하루 한도와 일반 429 구분을 구현 검사 대상으로 삼는다. 실제 분석 완료 검증은 모달의 접수 안내가 아니라 본인 화면의 최종 Catch·근거 확인까지 이어 간다.
