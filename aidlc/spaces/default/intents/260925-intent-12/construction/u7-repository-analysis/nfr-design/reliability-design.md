# U7 저장소·분석 — 신뢰성 설계

작성일: 2026-10-29. [확인한 작성안](nfr-design-questions.md), [신뢰성 요구사항](../nfr-requirements/reliability-requirements.md), [기능 명세 F2~F4](../functional-design/functional-spec.md)을 따른다. 구현·장애 시험·실제 분석 완료 기록이 아니다.

## RD1 상태와 시한

대응: NFR4.6, NFR7.1. 기존 처리(processing)·반영(application)·수명(lifecycle) 세 축을 유지한다. api의 상태 응답에 관측값을 더하되 단일 success 플래그로 접수·수신·반영을 합치지 않는다.

| 상황 | 기존 상태 기준 | 화면·후속 |
|---|---|---|
| 새 접수 | ACTIVE / QUEUED / NOT_READY | 접수됨. 완료가 아님 |
| worker 시작/진행 | ACTIVE / RUNNING 또는 UNCERTAIN / NOT_READY | 진행 또는 실행 확인 중 |
| 결과 수신·반영 | ACTIVE / 수신한 처리 결과 / PENDING→APPLYING | 반영 중. receipt ACCEPTED는 본인 결과 준비가 아님 |
| 반영 완료 | CLOSED / 수신한 처리 결과 / APPLIED | 처리 결과와 ownerResultsReady에 따라 완료·0건·부분 결과·실패 |
| 반영 실패/복구 | 기존 APPLY_FAILED 또는 RECOVERING | 실패/복구 상태와 종료 여부. 새 분석 금지 조건을 보존 |
| 상태 조회 실패 | 저장 상태 변경 없음 | 조회 실패·새로고침. 분석 실패나 재요청 허용으로 추정하지 않음 |

[시한 서비스](../../../../../../../../api/src/analysis-deadline/analysis-deadline.service.ts)의 요청 → 시도 잠금 순서, SKIP LOCKED, 배치와 판정 주기를 보존한다. ACTIVE 중 다음 기존 조건만 닫는다.

- QUEUED/RUNNING/UNCERTAIN + NOT_READY가 시한에 도달하면 FAILED/APPLIED/CLOSED와 서버 시한 실패 근거를 남긴다.
- 반영 PENDING이 시한에 도달하면 처리 결과를 유지하고 APPLY_FAILED/CLOSED로 닫는다.
- APPLY_FAILED는 기존 종료 판정으로 CLOSED가 된다.
- 다른 상태 조합을 임의로 강제 종료하거나 상태 조회 요청에서 수정하지 않는다.

현재 api 시한은 접수부터 60분, worker 전체는 꺼낸 시각부터 20분이다. 값 조정은 [PD2](performance-design.md#pd2-시계와-예산의-관계) 실측으로 정하고 기존 전이 조건은 유지한다. 이 값은 가동률·복구 시간 보장이 아니다. DB·큐 장애 동안의 정리가 즉시 이뤄진다고 약속하지 않는다.

## RD2 본인 관측과 실패 의미

대응: NFR7.2. 기존 수집 결과에서 숫자 계정 ID로 본인 커밋을 확인한다. 후보 판정 전에 관측을 만들고 후보 없음·생성 실패 등 조기 반환에도 전달한다.

| 관측 | count | 성립 조건·표시 |
|---|---|---|
| UNKNOWN | null | 관측 전·조회 중단·관측 불충분. 본인 기록 없음으로 표시하지 않음 |
| NONE | 0 | 필요한 조회 완료, 부재 판정을 막는 한계 없음, 확인된 본인 커밋 0. 본인 기록 없음 |
| FOUND | 양의 정수 | 본인 커밋을 실제 확인함. 전체 수집이 끝났다는 의미는 아니며 한계/실패를 함께 보존 |

FOUND의 개수는 관측한 수이지 저장소 전체 본인 커밋의 총수 보장이 아니다. NONE은 후보 수 0이나 CollectionOutcome.completed만 보고 만들지 않는다. 현재 completed는 수집 실패 유무만 보므로 coverage_limits와 필요한 본인 관측의 완료 여부를 별도로 대조해야 한다. FOUND이면서 후보 0이면 생성 가능한 Catch 없음으로 안내한다.

관측은 CollectionOutcome → 후보/GenerationOutput → compose_result → api 메시지 검사 → 수신 저장/AnalysisAttempt → 본인 상태 응답으로 이어진다. [현행 스키마](logical-components.md#lc4-현행-메시지와-패키징)에서는 enum·정수 범위·상태/count 조합과 허용 필드를 검사한다. collectionLimitNotes에는 기존 수집 한계의 안전한 설명만 싣고 원문/예외 객체는 넣지 않는다.

수집 전 컨텍스트 실패·worker 종료에는 UNKNOWN/null이 남는다. 송신자는 관측하지 않은 경우에도 이 값을 명시한다. 필수 관측 필드가 빠진 잘못된 새 Result는 스키마 거부이며 기존 시도의 기본 관측은 UNKNOWN이다. 누락을 NONE/0으로 보정하지 않는다. 관측 때문에 기존 outcome·failures·미제공·반영 결과를 덮어쓰지 않는다.

비공개 확인, 404 확인 불가, 연결/동의 문제, DAILY_LIMIT_REACHED, 수집 한계, 외부 오류를 각각 기존 상태/오류 모양에 연결한다. 하루 한도 429는 일반 Retry-After 안내로 바꾸지 않는다.

## RD3 부모 삭제와 자료 수명

대응: NFR5.1, NFR5.2. 신규 등록의 회원 FK와 요청의 동일 회원/등록/저장소 복합 FK는 CASCADE다. [LC2](logical-components.md#lc2-등록과-요청-사본)의 부모 UNIQUE를 함께 둔다. 새 등록이 과거 전역 repository_selection의 NO ACTION 예외를 상속하지 않게 한다. 요청·동의·시도의 기존 순환 예외는 C-06이 허용한 기존 범위만 보존한다.

마이그레이션·엔티티·[탈퇴 삭제 표](../../../../../../../../api/docs/member-withdrawal-deletion.md)를 같은 U7 코드 PR에서 갱신한다. 새 자료가 두 부모를 따라 삭제될 때 두 부모의 회원이 같은지 복합 FK로 확인한다. 동의의 좌표 사본은 요청 수명을 따르며 독립적으로 살아 있는 등록/분석 자료로 사용하지 않는다.

수신/반영은 기존 부모·현재 시도·회원 상태 검사와 요청→시도 잠금을 유지한다. 삭제됐거나 삭제 때문에 저장할 부모가 없으면 결과를 버리고 회원·요청·Catch를 재생성하지 않는다. FK 거부를 재시도 큐나 새 분석으로 보정하지 않는다. 반영 도중의 DB 실패는 기존 실패 처리로 남긴다.

회원 탈퇴의 세션/링크/MCP 차단·파일/자격정보 삭제·회원 행 삭제 순서는 U2 소유다. U7은 자기 새 표의 부모와 결과 반영 보호를 맞추며 탈퇴 전체 절차를 복제하지 않는다. 사용자용 등록 삭제·Catch 삭제·자동 보관 만료·백업/복원 장치를 추가하지 않는다.

## RD4 제한된 실패 재요청

기능 명세 F4와 기존 서버 retry.allowed가 정본이다. UI는 그 값을 사용하고 HTTP 시간 초과나 문구로 판정하지 않는다.

| 순서 | 판정 |
|---|---|
| 소유자·대상 | 타인/없는 요청은 동일 접근 불가 |
| 결과 존재 | 등록된 Catch 또는 유효 본인 결과가 있으면 재분석 금지 |
| 현재 요청 | 같은 회원·저장소의 최신 종료 요청이어야 하고 다른 ACTIVE가 없어야 함 |
| 닫힌 반영 실패 | CLOSED + APPLY_FAILED, 결과/Catch 없음이면 기존 허용 후보. 후보 수나 처리 outcome으로 이 분기를 좁히지 않음 |
| 확인된 처리 실패 | CLOSED + FAILED + APPLIED, 후보 0·실패 목록·서버 실패 확정 참조 또는 검증된 결과 반영 기록이 모두 필요 |
| 그 외 | 진행·불명·대기·복구·정상 완료·EMPTY·유효 부분 결과는 새 분석 금지 |

허용 후보에만 새 공개/연결/등록/지원/고지 확인, 새 동의·키·요청, C-03 소비를 적용한다. 기존 요청·동의·Catch는 수정하지 않는다. 응답 불명 때 같은 키로 기존 접수를 확인하는 행위는 이 새 실패 재요청과 구분한다.

기존 큐 전달·receipt 확인·반영 복구 장치는 유지하되 새로운 분석 재시도·모델 대체·정상 완료 재분석·부분 결과 추가 생성을 넣지 않는다. 생성 내부의 기존 제한된 제목 교정도 확대하지 않는다.

## RD5 실패 처리와 검증

| 실패 지점 | 적용과 검증 |
|---|---|
| 주소·외부 확인 | 등록/접수 전 거부, 빈 성공·비공개 추정 없음 |
| 접수 저장 | 새 요청과 하루 소비를 함께 롤백 |
| 접수 뒤 큐/실행 | 기존 시한·상태 처리, 횟수 환급/자동 새 분석 없음 |
| 수집/생성 | 관측·한계·부분 실패 보존, 없는 기록 생성 금지 |
| 반영 | receipt와 반영 완료 구분, 기존 APPLY_FAILED/종료 판단 |
| 삭제된 부모 | 저장 거부·버림, 재생성/재시도 없음 |
| 상태 조회 | 안전한 오류·새로고침, DB 상태 변경 없음 |

새 등록 참조와 관측값을 기존 정상/거부·상태·삭제 검사에 연결한다. 회원 간 참조와 삭제 보호는 필수다. 새로운 기능별 동시/재전송/늦은 결과 시험 체계를 신설하지 않고, 기존 검사의 회귀와 U2가 취합하는 공통 보호 흐름 3개에 연결한다. 기존 장애 복구를 재설계하거나 새로운 복구 목표를 약속하지 않는다.
