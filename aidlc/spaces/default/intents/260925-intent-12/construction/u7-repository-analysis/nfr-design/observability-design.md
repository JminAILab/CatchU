# U7 저장소·분석 — 관측과 검증 설계

작성일: 2026-10-29. [확인한 작성안](nfr-design-questions.md)과 [관측 요구사항](../nfr-requirements/observability-requirements.md)을 따른다. 아래 표는 실행 기록 양식과 판정 방법이며 실제 성공 기록이 아니다.

## OD1 실제 완료 증거

대응: NFR6.1. [#424](https://github.com/JminAILab/CatchU/issues/424)의 완료 조건에 맞춰 새 주소 등록부터 본인 화면까지 하나의 요청/시도로 잇는다.

| 단계 | 확인 행위 | 남길 최소 증거 |
|---|---|---|
| 준비 | OQ2 대상·공개 상태·본인 기여·분석 리비전·허용 자료/비용/환경 확인 | 날짜, 환경, 코드/대상 리비전, 계정 역할, 대상 결정 근거 |
| 등록·동의 | 기존 모달 하단에서 실제 공개 주소 등록, 현재 고지에 요청별 동의 | 새 경로 여부, 등록 식별자, 요청/시도 ID, 고지/범위 판본 |
| 수집·생성 | 실제 GitHub 조회와 실제 생성 제공자 사용 | LIVE 경로·실제 모델, PD1의 개수·제외 이유·한계, 호출·시간·바이트·토큰 |
| 수신·반영 | Result 수신과 Catch 반영을 각각 확인 | receipt, 처리/반영/수명 최종 상태, 새 Catch·기존 참조·거부 수, ownerResultsReady |
| 본인 화면 | 완료/부분/실패 안내와 준비된 Catch·근거를 실제 확인 | 확인한 화면 동작, 최소 식별 정보·근거 확인 결과, 증거 위치 |
| 거부 1~2종 | 준비 가능한 실제 미동의/비공개 확인/한도 등에서 실행 전 거부와 안내 확인 | 실제 사용한 조건, 오류 코드, 분석 실행 여부, 화면 안내 |
| 마무리 | 약 500개 반영 판정과 병합 증거 대조 | 성공/실패/미실행, 미확인 범위, 통합 브랜치 병합 PR |

거부 사례는 준비 가능한 범위에서 1~2종을 선택한다. 비공개를 확인할 수 없어 404만 받았다면 “저장소 확인 불가”로 기록한다. 해당 사례를 비공개 판정 검증으로 바꾸지 않는다. 합성 권한/범위 검사는 따로 기록하며 실제 거부 증거를 대체하지 않는다.

요구사항 OQ2는 “누구 계정인지 임의 선택”이 아니라 CatchU를 공개할지 또는 팀장이 대체 공개 저장소를 정할지의 결정이다. 공개 전환 전 이력·문서·AI-DLC 기록을 점검하고, 대체한다면 FR1.6·FR19.1·NFR3의 분석·평가 대상을 팀장이 다시 정한다. U7은 공개 저장소만 분석하며 권한을 넓혀 비공개 CatchU를 우회 분석하지 않는다. 이 설계가 공개 전환이나 외부 자료 전송 실행을 승인·수행한 기록은 아니다.

정상 사례에는 본인 커밋과 생성 가능한 후보가 있어야 한다. EMPTY·부분 결과·실패는 그 상태대로 기록하고 별도로 약 500개 반영 충족 여부를 판단한다. 실제 성공을 확인하지 못하면 완료 조건을 낮추거나 이슈를 닫지 않는다.

## OD2 로그와 상관관계

대응: NFR6.2. 기존 로그에 requestId·attemptId를 연결한다. 생성 제공자 로그는 현재 자식 프로세스의 attemptId 접두어로 잇는 방식이므로 새 추적 플랫폼을 도입하지 않는다.

| 지점 | 기존 연결/보완할 허용 값 | 제외할 값 |
|---|---|---|
| 등록 | 안전한 등록 식별자·성공/거부 코드·소요 | 입력 URL 원문·토큰·외부 오류 전체 |
| 접수/큐 | requestId, attemptId, 기존 메시지 ID, 접수/전달 시각·결과 | 자격정보·동의 자료 원문 |
| 수집 | 목록/본인/상세·관계 집계, 호출·바이트·소요·한계/실패 코드 | 커밋 글·diff·PR/이슈 원문·응답 전체 |
| 생성 | 후보·실제 호출·교정·미생성·실패 수, 모델·토큰·시간·안전한 제공자 요청 ID | SHA·파일 경로·이름·제목·본문·프롬프트·응답 원문 |
| 수신/반영 | receipt와 사유 코드, 상태 세 축, 반영/참조/거부 수 | SQL·stack·오류 객체·원본 Result 전체 |
| 시한/조회 | 요청/시도·전이/조회 실패 코드·판정 시각 | 타인 자료 존재 정보·세션/키 |

집계는 [CollectionOutcome](../../../../../../../../worker/app/collection/collect.py)의 calls·received_bytes·관계 관측, 기존 생성 집계·제공자 로그, api 수신/반영 결과에서 얻는다. 누락된 값만 해당 경계에서 최소 보완한다. 세부 원문을 모아 별도 측정 저장소를 만들지 않는다.

로그 사건은 접수, 큐 전달, worker 시작, 수집 종료, 생성 종료, 결과 수신, 반영 종료로 구분한다. 한 사건의 성공이 다음 사건의 성공을 뜻하지 않는다. 비밀값/원문이 섞일 수 있는 자유 형식 오류는 허용된 코드로 바꾸고 알려지지 않은 예외는 기존 일반 오류로 처리한다.

여러 호스트의 시각은 환경 기록에 포함하고 경과 측정은 [PD2](performance-design.md#pd2-시계와-예산의-관계)를 따른다. 등록 단계에는 아직 requestId가 없으므로 등록 식별자를 사용하고 접수 뒤 등록/요청을 연결한다. 회원 식별자는 필요한 기록에서만 최소 사용한다.

## OD3 확인 표와 실행 구분

대응: NFR6.3. FR19.2 공통 확인 표의 U7 행을 만들거나 증거에 연결한다. 새 관제 페이지·경보·분산 추적·대시보드·별도 시험 플랫폼을 만들지 않는다.

| 칸 | 기록 원칙 |
|---|---|
| 실제/합성 | GitHub·생성 제공자·U2 C-03별로 실제 연결인지 표시 |
| 환경 | 로컬 또는 해당 AWS 환경을 명시. 로컬 성공으로 FR19.1 외부 확인을 대신하지 않음 |
| 코드·대상 | 실행 당시 커밋과 분석 리비전, 범위 판본·상한 설정을 고정 |
| 결과 | 실제 성공/실패/미실행, 상태 세 축과 본인 화면 확인을 각각 기록 |
| 규모 | 약 500개 대상/반영 판정, 정상 제외와 자원 상한의 중단을 분리 |
| 미확인 | 준비되지 않은 대상·환경·자료/비용 조건·U2 연결을 구체적으로 기록 |
| 근거·완료 | 안전한 로그/검사 결과 위치, 실제 확인 행, 병합 PR |

현재 단계의 실행 상태는 다음과 같다.

| 검증 | 현재 상태 |
|---|---|
| 새 경로 실제 GitHub → 실제 생성 → DB → 본인 화면 | 미실행 — 설계 단계 |
| 약 500개 커밋의 새 경로 실측·상한 확정 | 미실행 — 구현·대상/환경 준비 후 |
| 실제 거부 1~2종 | 미실행 — 구현·실제 실행 조건 준비 후 |
| U2 실제 C-03 연결 | 미실행 — 통합 때 별도 확인 |
| U7 통합 브랜치 병합 | 미실행 — 코드·검증·PR 단계 후 |

이 표는 설계 작성 시점의 상태다. 실제 실행 결과는 후속 코드/검증 기록과 이슈에 남기고 과거 승인 문서를 성공으로 소급 수정하지 않는다.

## OD4 검사 범위와 담당 인계

| 범위 | 검사 방식·담당 경계 |
|---|---|
| 회원별 등록·주소/권한/동의 | U7 기존 api/web 정상·거부 검사에 새 경계 연결 |
| 관측·스키마 | U7 worker/api 양쪽에서 UNKNOWN/NONE/FOUND·조합·허용 필드·동일 판본 검사 |
| 상한 | U7 기존 합성 검사로 개수/호출/시간/크기 경계 확인 후 허용된 실제 측정 |
| 상태·재요청·삭제 | U7 기존 회귀 검사와 새 등록 FK 연결 확인 |
| C-03 | U7 소비 지점 검사, 원자적 계수·KST 구현은 U2, 실제 연결 결과 별도 |
| 공통 보호 흐름 3개 | U2가 전체 취합. U7 증거를 제공하고 기능별 세부 시험 체계를 복제하지 않음 |

NFR3 질의응답 10개 품질 평가는 U7 소유가 아니다. U7은 기존 저장소 기여·근거·생성 검증과 실제 분석 증거를 제공한다. 테스트나 로그가 있다는 것만으로 실제 내용 품질·성능·완료를 보장하지 않는다.

## 운영·자료 취급 경계

기존 안전한 로그로 실패 구간을 확인한다. 새 SLI/SLO·오류 예산·자동 경보·당직/에스컬레이션 체계를 정하지 않는다. 시간과 건수는 요구사항 판정에 쓰는 관측값이다.

실제 자료의 열람·첨부·전송은 [자료와 실행 로그](../../../../../../../../docs/CatchU_coding_procedures.md#자료와-실행-로그)를 따른다. 이슈/PR에 전체 화면·원문·프롬프트·키를 일괄 첨부하지 않는다. 필요한 최소 증거를 가리고 남기며 실행 환경이나 비용 조건이 준비되지 않으면 미실행으로 보존한다.
