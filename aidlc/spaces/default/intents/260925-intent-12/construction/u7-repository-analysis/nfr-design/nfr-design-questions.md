사용자는 비기능 요구사항을 승인하고 비기능 설계 진행을 요청했다. 앞 단계의 제품 결정을 다시 묻지 않는다. 아래는 그 결정을 구현 가능한 구조로 연결할 제안이다. 승인된 세부 NFR 20개 모두를 상세 설계의 구체 적용 지점에 대응시킨다.

## 등록·접수·실행·결과를 연결하는 구조

1. 기존 web 저장소 관리 모달과 api/worker 배포 단위를 유지한다. 모달 하단은 주소 등록을 담당하고, 등록 뒤 기존 요청별 고지·동의·분석 요청 흐름으로 잇는다.
2. api의 전역 선정 공급을 회원별 등록 공급으로 바꾼다. 저장소 ID·서버 확인 좌표·범위 판본을 저장하고 같은 회원·같은 저장소 ID의 등록은 재사용한다. 회원 조회 조건과 동일 소유자 복합 외래 키를 함께 적용한다.
3. 요청 당시의 좌표·허용 자료 종류·범위 판본·등록 참조를 동의에 묶인 불변 사본으로 보존한다. 이후 등록 좌표가 바뀌어도 이전 동의 범위를 덮어쓰지 않는다. worker 컨텍스트와 결과 반영은 그 요청의 사본을 대조한다.
4. 기존 멱등 접수·회원 잠금·진행 요청/재분석 판정을 유지한다. 외부 연결·공개 여부 확인은 DB 접수 트랜잭션 밖에서 수행하고, 안에서는 회원·연결·등록·판본이 여전히 같은지 확인한다. 같은 키의 기존 응답을 새 외부 조회 실패 때문에 거부하지 않는 현재 보호도 유지한다.
5. 새 요청을 저장하는 분기에서만 U2 `DailyRunLimit.consume(memberId, ANALYSIS, now, manager)`를 호출한다. 횟수·동의·요청·시도·멱등 기록은 같은 접수 트랜잭션으로 묶고 큐 전달은 커밋 뒤 기존 경로를 쓴다. 등록·조회·기존 요청 재응답에는 소비하지 않는다.

확인한 현재 구현: [선정 공급](../../../../../../../../api/src/member-repositories/repository-selection.source.ts), [고정 카탈로그](../../../../../../../../api/src/member-repositories/selected-repository-catalog.ts), [접수](../../../../../../../../api/src/analysis-intake/analysis-intake.service.ts), [결과 반영용 좌표 조회](../../../../../../../../api/src/analysis-receiver/selected-repository-registration.source.ts). 이 네 지점에 같은 등록·동의 근거가 이어져야 하며 UI만 변경해서는 충족하지 않는다.

## 메시지·관측값의 연결

- 수집 결과에서 본인 커밋 관측을 계산해 후보 판정·생성·결과 조립을 거쳐 api 검증·저장·상태 응답까지 전달한다. `ownCommitObservation`, nullable `observedOwnCommitCount`, `collectionLimitNotes`의 의미는 승인된 기능 설계를 따른다.
- 후보가 없거나 생성 전에 실패한 조기 종료도 관측값을 잃지 않게 한다. 필요한 조회가 완료되고 부재 판정을 막는 한계가 없을 때만 NONE이며, 후보 0·실패·관측 누락을 본인 커밋 0으로 보정하지 않는다.
- 현재 api와 worker는 10월 승인 계약 파일을 직접 읽는다. 과거 원본은 보존하고 U7의 현행 메시지 스키마를 별도 정본으로 두어 송신·수신·검사·패키징이 같은 파일과 판본을 쓰도록 함께 변경한다. 새 필드 허용을 위해 임의 필드 검증 전체를 풀지 않는다.
- 새 내부 필드와 검증은 U7 안 변경으로 처리한다. U2의 공용 인터페이스·표를 바꿔야 하는 경우에는 제공 Unit의 계약 변경 절차를 따른다.

## 보안·자료 수명 적용 방식

- 주소 파서와 메타데이터 조회를 분리한다. 입력은 승인된 GitHub 루트 주소만 받고, 검증한 owner/name을 고정 `api.github.com` 경로에 넣는다. 응답의 URL을 다음 호출 주소로 쓰지 않고 redirect·과대 응답·시간 초과를 거부한다. 등록·접수에서 공개 여부를 확인하고 worker도 실행 직전에 다시 대조한다.
- 현재 GitHub 연결의 자격정보 보호·회원 신원 검사를 재사용한다. 메타데이터 조회 결과는 공개/확인된 비공개/찾을 수 없음·확인 불가를 구분한다. 기존 OAuth의 무권한 범위를 넓히지 않으며, 권한상 비공개를 확인할 수 없는 404를 비공개로 단정하지 않는다.
- 회원 API와 내부 worker 인증을 구분하고 모든 등록·동의·요청·결과 조회에 소유자를 대조한다. 새 등록과 요청 관계는 C-06에 따라 회원 삭제를 따르고 같은 PR에서 삭제 표를 갱신한다. 삭제된 부모에 도착한 결과는 기존 수신·반영 경계와 외래 키로 차단한다.
- 기존 저장소 자료 가리기·프롬프트 자료 구분·본인 기여와 생성 출력 검증을 유지한다. 모델은 Haiku 5.5, SDK 재시도 0을 유지한다. 화면은 텍스트와 허용한 GitHub 근거 링크로 출력한다.

현재 [GitHub 연결 클라이언트](../../../../../../../../api/src/github-connection/github.client.ts)는 고정 호스트·redirect 차단·시간 및 응답 크기 제한을 갖추지만 저장소 메타데이터 조회 기능은 없다. 상세 설계는 이 보호를 따른 U7 조회 경계를 명시하며, 현재 구현돼 있다고 기록하지 않는다.

## 약 500개 커밋 측정과 상한 결정

측정은 기존 시험 체계의 합성 경계 확인과 허용된 실제 대상의 새 경로 실행을 구분한다. 합성 결과로 실측을 대신하지 않는다.

| 구간 | 대조할 값과 변경 지점 |
|---|---|
| 목록·상세·관계 수집 | 목록 수·본인 관측·필요 상세와 관계 조회의 수행/제외 수, 호출·시간·총 바이트·응답 상한. `CollectionLimits`와 기존 수집 관측을 함께 확인 |
| 후보·생성 | 후보·실제 생성·교정·미생성·실패 수, 모델·토큰·시간·입출력 크기. 기존 묶음 판정을 유지하고 `GenerationLimits`를 함께 확인 |
| worker 실행 | 큐에서 꺼낸 시각부터 수집·전체 실행·생성 종료·결과 전송까지 측정. 결과 조립 후 자식 프로세스 전달 크기도 확인 |
| 접수·반영·화면 | 접수 시각부터 큐 대기·worker 처리·수신·DB 반영·본인 화면 준비 시점을 구분. api 처리 시한과 닫기 판정 간격을 함께 확인 |

현재 상한은 [성능 요구사항의 기준값](../nfr-requirements/performance-requirements.md)을 출발점으로 사용한다. 결과 전달에도 [worker 자식 프로세스 프레임 상한](../../../../../../../../worker/app/consumer/settings.py)이 있으므로 수집·생성만 늘려 결과가 전달되지 않는 상태를 놓치지 않는다. 기존 상한을 무제한으로 바꾸거나 새 성능·가동률 약속을 만들지 않는다.

구체 조정값은 실제 측정 결과와 허용 비용 안에서 정한다. 필요한 조회·생성이 자원 상한 때문에 누락됐는지와 기능 규칙상 정상 제외됐는지를 구분한다. worker 프로세스당 동시 분석 1을 유지하고 실제 소비자 수를 기록한다. 새 자동 증설·병렬 생성·캐시·분산 잠금·관제 플랫폼을 추가하지 않는다.

측정을 이유로 정상 완료 요청의 재분석 금지를 풀지 않는다. 반복이 필요하면 개발·시험 자료와 실행 조건을 먼저 정하고, 사용자에게 새 재분석 기능이나 권한 우회를 제공하지 않는다.

## 실패·안내·검증 증거

기존 처리·반영·수명 상태와 `ownerResultsReady`, 서버의 `retry.allowed`를 함께 사용한다. 접수·수신·DB 반영·본인 화면 완료를 구분하고, 본인 기록 없음/후보 없음/수집 한계/확인된 실패/조회 실패를 각각 안내한다. 기존 시한 닫기와 실패 재요청 조건을 유지하며 자동 분석 재시도나 정상·부분 결과의 추가 생성을 넣지 않는다.

로그는 기존 requestId·attemptId 연결에 필요한 건수·시간·상한·이유 코드만 보완한다. 토큰·원문·프롬프트·모델 응답 전체는 남기지 않는다. 실제 확인 표에는 날짜·환경·코드/대상 리비전·요청·최종 상태·Catch/근거 확인·거부 1~2종·한계·증거 위치·병합 PR을 연결한다. 로컬과 AWS, 합성과 실제 U2 C-03 제공자를 구분한다.

## 아직 실측으로 확정하지 않은 사항

- 요구사항 OQ2의 CatchU 공개 여부 또는 팀장이 정한 대체 대상.
- 실제 환경·자격정보·허용 자료 범위·비용 조건과, 그 환경에서 측정한 최종 상한.
- U2 C-03 실제 제공자의 통합 결과. 합성 제공자는 독립 개발용이다.

이 사항은 설계 작성의 선행 결정을 반복 요청할 사유가 아니라 실제 실행 전 확인할 조건이다. 준비되지 않아 실행하지 못하면 미실행으로 남기고 U7 완료로 표시하지 않는다.
