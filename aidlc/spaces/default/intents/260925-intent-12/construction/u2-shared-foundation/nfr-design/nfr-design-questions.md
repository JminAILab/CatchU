비기능 요구사항에서 정한 것(동시 1, 2시간 보관, 재시도 없음, 새 수치·관제 화면 없음, 새 라이브러리 없음)은 묻지 않는다. 남은 것은 비기능 요구사항 검토 지적 R-01(받아들인 위험)을 설계에서 어떻게 다룰지 하나다. 선택지는 가장 단순한 안을 A로 둔다.

## Q1. [운영] 파일 저장 설정(`FILE_STORAGE_DRIVER`·`FILE_STORAGE_LOCAL_ROOT`)이 없을 때 api 기동

NFR1.4는 저장 설정이 없거나 틀리면 api 기동을 멈춘다고 정했다. 그런데 새 환경변수를 개발 서버·`dev-ci`·예시 파일에 넣는 일은 팀장 공용 기반 작업이고, U8 전에는 실제로 저장하는 파일이 없다. 순서를 정하지 않으면 U2 코드가 먼저 합쳐질 때 개발 서버·CI·다른 Unit의 api 시험이 기동 실패로 막힐 수 있다.

A. 기동 실패는 그대로 두고, 두 환경변수를 개발 서버 SSM·`dev-ci`·예시 파일·시험 설정에 먼저 넣는 일을 U2 머지의 선행 조건으로 적는다(팀장이 U2 담당과 같으므로 U2 PR 직전에 함께 한다). 설정이 빠진 환경은 바로 드러난다
B. 설정이 없으면 기동은 하되 FileStorage를 쓰는 순간(탈퇴 2단계 등) `StorageUnavailable`로 실패한다. 더 막는 것: 설정 순서와 상관없이 다른 Unit 시험이 막히지 않는다. 대신: 설정이 빠진 배포 환경에서는 탈퇴가 그때 가서 실패하고, NFR1.4(기동 때 멈춤)를 바꾸게 된다
X. Other (please specify)

[Answer]: B

## Q2. [운영] 설정이 있는데 값이 틀릴 때 (Q1 후속)

Q1 답으로 설정이 없으면 기동은 하고 쓰는 순간 실패한다. 설정이 있지만 값이 틀린 경우(모르는 드라이버 이름, 상대 경로, 없는 폴더)는 아직 정하지 않았다.

A. 값이 있으면 기동 때 검사해 틀리면 기동을 멈춘다. 없을 때만 쓰는 순간 실패한다. 잘못 넣은 설정은 배포 때 바로 드러난다
B. 없을 때와 같이 기동은 하고 쓰는 순간 실패한다. 규칙이 하나라 단순하지만, 잘못 넣은 설정은 탈퇴를 해 볼 때까지 드러나지 않는다
X. Other (please specify)

[Answer]: A

## Consolidated Summary Confirmation

- 파일 저장 설정이 아예 없으면 api는 기동하고, FileStorage를 쓰는 순간(탈퇴 2단계 등) `StorageUnavailable`로 실패한다. 탈퇴는 500 `WITHDRAWAL_FAILED`로 끝난다
- 설정 값이 있으면 기동 때 검사해 틀리면(모르는 드라이버, 상대 경로, 없는 폴더) 기동을 멈춘다
- 이 결정은 승인된 NFR1.4("없거나 틀리면 기동 실패")의 "없을 때" 부분을 바꾼다. 비기능 요구사항 문서는 다시 승인하지 않고, 비기능 설계 security-design.md에 바뀐 내용과 이유(설정 순서와 상관없이 다른 Unit 시험이 막히지 않게)를 적는다
- 받아들인 지적 R-02~R-05는 설계에 이렇게 반영한다: 탈퇴 2·3단계는 대상이 이미 없어도 성공(기능 설계 BR6.3·BR7.3 그대로), NFR3·NFR6 번호 의미는 설계 추적에 비고로 적음, 2시간 보관은 상수 하나로 두고 처리 시한이 그보다 긴 Unit이 생기면 같이 올림, 80,000자는 상수 하나로 두고 JD 요약 "전체 넣기"에서 걸리면 팀장이 조정해 통합 확인 표에 기록
