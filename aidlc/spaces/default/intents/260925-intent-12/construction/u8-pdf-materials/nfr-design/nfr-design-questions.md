# U8 PDF 자료 — NFR 설계 질문

작성일: 2026-11-06. Unit: `u8-pdf-materials`(#420). 입력: [NFR 요구사항](../nfr-requirements/) 6개 문서, [기능 명세](../functional-design/functional-spec.md), [계약 요약](../../../inception/contract-design/contract-summary.md) C-10·C-11.

NFR 요구사항은 새 수치를 만들지 않고 기능 설계가 정한 값과 계약 규칙을 묶었다. 설계 단계도 같은 원칙으로 패턴만 정하며, 회로 차단기·캐시 계층·자동 확장·경보 같은 새 장치는 근거가 없어 두지 않는다(NFR4·NFR6, C06). 묻는 것은 기능 설계가 정하지 않았고 보안 요구사항 NFR1.2("호출마다 판정")와 사용성이 맞서는 한 가지다.

## Q1. [개발 담당(U8)] 받은 사람 화면에서 같은 PDF를 다시 열 때 다시 받을지

기능 설계 Q3대로 web은 PDF를 fetch로 받아 Blob URL로 연다. 쪽 목록의 [원본 n쪽 열기]를 여러 번 누르거나 [새 탭에서 열기]를 또 누를 때, 매번 서버에 다시 요청하면 요청마다 링크 판정(C-10)이 다시 실행되지만 20 MB까지의 파일을 다시 받는다. 탭 안에서 Blob을 재사용하면 한 번만 받지만, 그 사이 링크가 중지·만료되어도 새로고침 전까지는 이미 받은 파일을 계속 볼 수 있다.

A. 매번 다시 요청한다. 클릭마다 판정이 다시 실행되고 Blob URL은 쓰고 바로 해제한다 (가장 단순, NFR1.2 "호출마다 판정"과 같은 강도; 같은 PDF를 여러 번 열면 그만큼 다시 받음)
B. 탭 안에서 같은 항목의 Blob을 재사용한다. 받은 파일은 화면을 떠나거나 onAccessLost(401·404)가 올 때 해제한다 (다시 받지 않아 빠름; 중지·만료 뒤에도 그 탭에서는 이미 받은 PDF를 새로고침 전까지 볼 수 있음. 다른 자료(쪽 글·요약)도 이미 화면에 있는 내용은 같은 성질이라 새 노출은 아님)
X. Other (please specify)

[Answer]: X. PDF를 처음 열거나, 닫았다가 다시 열거나, [새 탭에서 열기]를 누르면 서버에 다시 요청해 C-10 판정을 받습니다. 같은 PDF가 화면에 이미 열려 있고 [원본 n쪽 열기]가 그 뷰어의 쪽만 바꾸는 경우에는 기존 Blob을 재사용합니다.재요청이 401·404면 기존 U4 onAccessLost 흐름으로 전환합니다. Blob URL은 클릭 직후 해제하지 말고 해당 뷰어가 더 이상 사용하지 않을 때 해제해 주세요. 링크 중지·만료는 다음 열람 요청부터 적용되며, 이미 열린 탭에 전달된 PDF까지 회수하는 것으로 보장하지 않습니다.
