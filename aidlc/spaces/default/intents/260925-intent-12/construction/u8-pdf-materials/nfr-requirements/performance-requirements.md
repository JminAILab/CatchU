# U8 PDF 자료 — 성능 요구사항

작성일: 2026-11-06. Unit: `u8-pdf-materials`. 입력: [기능 명세](../functional-design/functional-spec.md), [규칙](../functional-design/rules.md), [재승인 요구사항](../../../inception/requirements-analysis/requirements.md) NFR4, [계약 요약](../../../inception/contract-design/contract-summary.md) C-02·C-05·C-17, [NFR 질문·답변](nfr-requirements-questions.md) Q1·Q2.

재승인 요구사항 NFR4는 "질의응답 외의 처리 시간·가동률·복구 수치는 새로 만들지 않는다"고 했다. 그래서 이 문서는 응답 시간 목표를 새로 두지 않고, 기능 설계가 이미 정한 경계 값과 처리 구조를 성능 요구사항으로 묶는다. 값은 모두 기능 설계 Q1·Q2의 결정이다.

| ID | 요구사항 | 값·근거 | 확인 방법 |
|---|---|---|---|
| NFR4.1 | 업로드 요청의 크기 경계. 파일 20 MB, 회원당 20벌, 제목 1~100자를 api가 받기 전에 거부한다. 쪽 수 50은 worker가 판정한다. | 기능 설계 BR1.2(Q1). 이 값이 열람(파일 전체 수신)·추출·저장 부담의 상한이다 | 상한 초과 업로드가 400으로 거부되는 시험 |
| NFR4.2 | 추출 처리 시한은 업로드 커밋 뒤 10분이며 큐 대기를 포함한다. 시한이 지난 PENDING은 상태를 읽을 때 FAILED로 확정되어 "대기"에 영원히 남지 않는다. | 기능 설계 BR2.2·BR3.7(Q2), C-02 readStatus | 시한 지난 PENDING을 목록에서 읽으면 FAILED가 되는 시험 |
| NFR4.3 | 추출 작업은 자식 프로세스에서 돌고 자체 시간·메모리 제한을 가진다. 제한값은 이번 단계의 수치 목표가 아니라 구현 단계에서 기존 분석 소비자의 값과 대표 PDF 측정으로 정한다. 제한에 걸리면 FAILED(UNREADABLE_FILE)로 10분보다 일찍 확정된다. | NFR 질문 Q1(담당 결정), 10월 분석 소비자 구조 | 제한을 넘는 입력에서 작업이 종료되고 FAILED 결과가 오는 시험(값은 구현에서) |
| NFR4.4 | 추출 Worker는 분석 Worker와 독립이며 기본 동시성 1이다. 큐 대기를 포함한 전체 시한은 승인된 10분을 유지한다. 연속 업로드에서 뒤쪽 자료가 시한을 넘길 수 있다는 점은 알려진 한계이며, 구현 단계에서 대표 PDF의 연속 업로드를 한 번 재서 동시성 기본값(설정값)을 검토할 수 있다. 10분 시한 자체의 변경은 구현 중에 하지 않고, 측정 근거를 보고 담당자가 별도로 결정한다(새 처리 시간 수치를 구현 중에 만들지 않음, NFR4). | 기능 설계 BR2.2·BR3.7(Q2), 검토 R-07, 검토 R-03 | 대표 PDF 연속 업로드 측정 기록 1회 |
| NFR4.5 | PDF 열람은 파일 전체를 한 번에 내려주며 Range 요청을 지원하지 않는다. web은 받은 전체를 Blob URL로 연다. 응답 시간 목표는 두지 않고 20 MB 상한으로 부담을 억제한다. | 기능 설계 W4·BR6.3(Q3), NFR4 | 20 MB 파일 열람이 끝까지 동작하는 수동 확인 |
| NFR4.6 | 발행 때 PDF 복사는 트랜잭션 밖에서 하고(C-17 2단계) 복사 횟수는 PDF 항목 수(항목 상한 20) 이하다. 트랜잭션 안에서는 `published_pdf_page` 복사(한 PDF당 최대 50행)와 재확인만 한다. | 기능 설계 BR5.2·BR4.3, C-17 | PDF 항목 수만큼 copy가 불리는 시험 |
| NFR4.7 | 추출 결과 저장은 한 트랜잭션에서 최대 50행을 쓰며 부분 저장이 없다. 수신 메시지의 글 길이 상한은 두지 않는다(쪽 50·20 MB로 억제, OQ-U4-4에 딸림). | 기능 설계 BR3.3·BR3.4·BR4.5 | 50쪽 저장 중 한 행 실패 시 전무 시험 |
| NFR4.8 | S3 호출은 AWS SDK 기본 재시도(한 호출 안 최대 3회)를 유지한다. 호출 1회가 몇 초 더 걸릴 수 있음을 받아들이고, 최종 실패는 StorageUnavailable 한 번으로 끝낸다. | NFR 질문 Q2, C-05 errors | 가짜 S3 클라이언트로 일시 오류 뒤 성공·최종 실패 시험 |

새로 만들지 않은 것(NFR4·C06): 업로드·열람·발행의 응답 시간 목표, 처리량 목표, 자원 사용률 목표, 벤치마크. 시연 규모(소수 외부 사용자)에서 필요하지 않고 재승인 입력에 근거가 없다.
