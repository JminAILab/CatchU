# U8 PDF 자료 — 확장성 요구사항

작성일: 2026-11-06. Unit: `u8-pdf-materials`. 입력: [기능 명세](../functional-design/functional-spec.md), [규칙](../functional-design/rules.md), [재승인 요구사항](../../../inception/requirements-analysis/requirements.md) NFR4·C03, [계약 요약](../../../inception/contract-design/contract-summary.md) C-05·C-16, [NFR 질문·답변](nfr-requirements-questions.md).

재승인 요구사항은 12월 이용자를 "소수의 외부 사용자가 자기 자료로 써 보는 수준"으로 두었고(의도 분석, NFR4), 성장 전망·확장 기준을 새로 만들지 않는다. 이 문서는 시연 규모 가정과, 그 안에서 양을 묶는 경계만 적는다.

| ID | 요구사항 | 근거 | 확인 방법 |
|---|---|---|---|
| NFR4.9 | 규모 가정: 소수 외부 사용자(수 명~수십 명), 회원당 PDF 20벌 이하, PDF 1개 50쪽·20 MB 이하. 데이터 상한은 회원당 `pdf_material` 20행·`pdf_page_text` 1,000행이며, 발행 사본은 발행본마다 그 PDF 항목 수만큼 더해진다. | 기능 설계 BR1.2(Q1), 요구사항 의도 분석 | 상한 시험(NFR4.1) |
| NFR4.10 | 추출 처리 용량은 추출 Worker 동시성(기본 1)으로 정해지며, 늘릴 때는 설정값만 바꾼다(코드 변경 없음). 분석 Worker의 동시성과 독립이다. | 기능 설계 BR3.7 | 설정값으로 동시성이 바뀌는 시험 |
| NFR4.11 | 파일 저장은 환경별 S3 버킷 1개에 `members/{memberId}/...` 접두어 구조로 둔다. 회원·발행본 단위 삭제는 접두어 삭제로 하므로 자료 수가 늘어도 삭제 경로가 같다. 로컬·시험은 같은 키 구조의 로컬 드라이버다. | C-05 keys, ADR-003, 기능 설계 BR7.3 | 로컬·S3 드라이버가 같은 계약 시험 통과 |
| NFR4.12 | api는 PDF를 메모리에 받아 저장소에 쓰고(20 MB 상한), 열람은 저장소 스트림을 그대로 내려준다. 수평 확장이 필요하면 api 인스턴스를 늘리는 것으로 충분하며 인스턴스 사이 공유 상태가 없다(파일은 S3, 상태는 DB). | 기능 설계 W1·W4, ADR-003 | 코드 검토: 로컬 디스크 임시 파일·인메모리 공유 상태 없음 |
| NFR4.13 | 확장 기준(언제 늘릴지)·용량 계획·부하 시험은 두지 않는다. 시연 규모에서 필요하지 않고 재승인 입력에 근거가 없다(NFR4, C06). | NFR4, C06 | 해당 없음 |
