# U8 PDF 자료 — 관측 요구사항

작성일: 2026-11-06. Unit: `u8-pdf-materials`. 입력: [기능 명세](../functional-design/functional-spec.md), [규칙](../functional-design/rules.md), [재승인 요구사항](../../../inception/requirements-analysis/requirements.md) NFR6·NFR7·FR19.2, [계약 요약](../../../inception/contract-design/contract-summary.md) C-16 receipt·「에러 대응 최소선」1, [NFR 질문·답변](nfr-requirements-questions.md).

NFR6은 "자동 배포·별도 관제 화면은 이 intent에서 만들지 않는다"고 했고, 검증은 FR19의 확인 표 한 장으로 한다. 그래서 지표·대시보드·경보·분산 추적은 두지 않고, 기존 로그와 10월 수신 확인 기록, FR19 확인 표로 관측한다. SLI/SLO 수치는 NFR4에 따라 새로 만들지 않는다.

## 로그 (NFR6, 에러 대응 최소선 1)

| ID | 요구사항 | 근거 | 확인 방법 |
|---|---|---|---|
| NFR6.1 | 다음 사건을 기존 서비스 로그 형식으로 남긴다: 업로드 저장 실패와 보상 삭제 실패, 추출 요청 발송 실패, 추출 결과 수신 판정(코드와 pdfMaterialId), 자식 프로세스 제한 초과 종료, 발행 PDF 복사 실패(`PDF_COPY_FAILED`)와 접두어 정리 실패(`PREFIX_CLEANUP_FAILED`), 저장소 삭제 실패, 열람 실패 코드(401·404·500), 사본 파일 없음 불일치. | 기능 설계 BR1.6·BR2.4·BR3.3·BR5.3·BR5.5·BR6.5·BR7.1, 에러 대응 최소선 1 | 각 실패 경로 시험에서 로그 한 줄 확인 |
| NFR6.2 | 로그에 넣지 않는 것: 링크 토큰·grant·파일 키·접두어 값·뽑은 글·제목·회원 식별 외 개인정보. 쪽 글은 쪽 번호와 길이만 적는다. | 기능 설계 BR3.5·BR6.7, team.md Code Style | 로그 출력 검토 |
| NFR6.3 | worker는 추출 결과의 수신 확인(ACCEPTED/DUPLICATE/REJECTED와 코드)과 미관측(수신 확인 없음)을 10월 `receipts.py` 방식으로 기록한다. 거부된 결과는 다시 보내지 않는다. | C-16 receipt, 기능 설계 W2 | 각 수신 판정 시험에서 worker 기록 확인 |

## 상태 표시 (NFR7)

| ID | 요구사항 | 근거 | 확인 방법 |
|---|---|---|---|
| NFR7.1 | 작성자는 PDF마다 "글 추출 중 / 완료 n쪽 / 실패(사유)"를 구분해 보고, 실패 사유에 따라 다른 안내(암호화 PDF·쪽 수 초과·뽑지 못함/시한)를 받는다. 상태는 새로고침 때 갱신한다(폴링 없음). | 기능 설계 BR2.3, frontend-components.md, NFR7 | 사유별 화면 문구 시험 |
| NFR7.2 | 받은 사람과 작성자는 PDF 쪽마다 쪽 번호를 보고, 읽을 수 없는 쪽은 "읽을 수 없음"으로 구분한다. AI 근거가 가리키는 쪽 글은 강조되고 "원본 n쪽 열기"가 함께 보인다. | 기능 설계 BR6.4, FR3.4·FR6.5, AC3.2.3·AC6.3.5 | readable=false 쪽 표지 시험, 근거 강조 수동 확인 |
| NFR7.3 | 발행에 넣을 수 없는 PDF(추출 중·실패)는 발행 화면에서 고를 수 없게 표시하고 이유를 보인다. 접근이 끊긴 PDF 열람(401·404)은 다른 패널과 같은 화면 전환으로 알린다. | 기능 설계 BR4.1·BR6.3 | 화면 시험 |
