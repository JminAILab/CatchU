# U8 PDF 자료 — 신뢰성 요구사항

작성일: 2026-11-06. Unit: `u8-pdf-materials`. 입력: [기능 명세](../functional-design/functional-spec.md), [규칙](../functional-design/rules.md), [재승인 요구사항](../../../inception/requirements-analysis/requirements.md) NFR4·NFR5·FR14.9·FR14.10, [계약 요약](../../../inception/contract-design/contract-summary.md) 「에러 대응 최소선」·C-02·C-05·C-16·C-17, [NFR 질문·답변](nfr-requirements-questions.md) Q1·Q2.

가동률·복구 시간 수치는 새로 만들지 않는다(NFR4). 신뢰성 요구사항은 "실패를 숨기지 않고, 끝나지 않은 작업은 시한으로 실패가 되고, 지운 자료는 되살아나지 않는다"는 에러 대응 최소선을 U8의 경로에 적용한 것이다.

## 자료 수명·삭제 (NFR5)

| ID | 요구사항 | 근거 | 확인 방법 |
|---|---|---|---|
| NFR5.1 | 자료 삭제는 원본 파일(materialKey)을 먼저 지우고 성공했을 때만 행을 지운다. 발행본 삭제는 발행본 접두어를 먼저 지우고(U4 순서), 탈퇴는 회원 접두어 전체를 지운다(U2 순서). 저장소 삭제가 실패하면 성공으로 응답하지 않고 DB를 남긴다. | 기능 설계 BR1.7·BR7.1·BR7.2, FR14.9, ADR-003, C-06 withdrawal-order | 저장소 삭제 실패 시 500·DB 유지 시험; 로컬 드라이버로 원본·사본이 모두 사라지는 시험 |
| NFR5.2 | 발행 사본(파일·`published_pdf_page`)은 원본과 수명이 다르다. 원본을 지우거나 다시 올려도 사본은 바뀌지 않고, 발행본 삭제·작성자 탈퇴 때만 함께 지워진다. | 기능 설계 BR4.4, FR3.2, C-06 사본 칸 규칙 | 원본 삭제 뒤 사본 열람·쪽 글 불변 시험 |
| NFR5.3 | 늦게 도착한 추출 결과는 자료가 지워졌거나(탈퇴·삭제) 시한이 지났으면 저장하지 않고 거부 코드로 끝낸다. 재전송은 없다. | 기능 설계 BR3.3, FR14.10, C-16 receipt | CONTEXT_MISMATCH·STALE_ATTEMPT 시험 |
| NFR5.4 | S3 실제 삭제 확인(탈퇴·발행본 삭제)은 버킷(#389)이 준비된 뒤 한 번 수행하고 FR19 확인 표에 적는다. 준비 전 완료 보고에는 "S3 실제 확인 미완"을 남긴다. | 기능 설계 미결 OQ-U8-2, Unit 정의 U8 책임 | FR19 확인 표의 U8 행 |

## 실패 처리·복구 (NFR4, 에러 대응 최소선)

| ID | 요구사항 | 근거 | 확인 방법 |
|---|---|---|---|
| NFR4.14 | 추출 상태는 PENDING→DONE 또는 FAILED로 한 번만 바뀌고, 시한(10분, 큐 대기 포함)이 지난 PENDING은 상태를 읽는 자리에서 FAILED(DEADLINE_EXCEEDED)로 확정된다. 작업 등록 실패·큐 유실·worker 꺼짐 어느 경우에도 "대기"에 영원히 남지 않는다. | 기능 설계 BR2.1·BR2.2·BR2.4·BR3.7, C-02 | 시한 경과 뒤 읽기에서 FAILED 시험, 등록 실패 시 201 유지·로그 시험 |
| NFR4.15 | 자동 재시도는 없다. 추출 실패의 재시도는 작성자의 다시 올리기, 발행 실패의 재시도는 작성자의 새 발행이다. 전송 수준에서는 AWS SDK 기본 재시도(한 호출 안 최대 3회)만 두고, 최종 실패는 StorageUnavailable 한 번으로 호출자가 실패 처리한다. | 기능 설계 BR2.3, 에러 대응 최소선 2, NFR 질문 Q2 | worker 재발송 경로가 없음을 코드 검토; SDK 재시도 설정 기본값 확인 |
| NFR4.16 | 결과 저장은 전부 아니면 전무다. 쪽 행 일부만 남는 상태가 없고, ACCEPTED/OK는 커밋 뒤에만 돌려주며 커밋 실패는 수신 확인 없이 작업 실패로 둔다. | 기능 설계 BR3.4, 에러 대응 최소선 1·4·5 | 50쪽 저장 중 제약 위반 → 0행·PENDING 유지 시험 |
| NFR4.17 | 발행의 PDF 복사·트랜잭션이 실패하면 발행본 접두어를 한 번 지우고 원래 오류를 그대로 응답한다. 정리가 실패하면 로그만 남기고, 남은 파일은 탈퇴 때 회원 접두어로 지워진다. 청소 장치는 두지 않는다. PDF 항목이 없는 발행은 저장소를 부르지 않아 저장소 장애에 영향받지 않는다. | 기능 설계 BR5.3~BR5.6, C-17 | 복사 실패·한도 롤백·chunk 예외·정리 실패 각 시험, 저장소 미설정에서 PDF 없는 발행 201 시험 |
| NFR4.18 | 추출은 자식 프로세스에서 돌고 시간·메모리 제한을 가진다. 한 작업의 멈춤·메모리 고갈이 worker 프로세스와 분석 소비자를 멈추지 않으며, 제한에 걸린 작업은 FAILED(UNREADABLE_FILE)로 확정된다. 제한값은 구현 단계에서 정한다. | NFR 질문 Q1 | 제한 초과 뒤 Worker가 다음 작업을 받는 시험 |
| NFR4.19 | 저장소를 쓸 수 없으면(설정 없음·장애) 업로드·복사·열람은 500으로 실패하고 상태를 바꾸지 않는다. 사본 행은 있는데 파일이 없는 불일치는 500과 로그(키 값 없음)로 드러낸다. 가동률 목표와 장애 복구 절차는 새로 두지 않는다. | 기능 설계 BR1.6·BR5.3·BR6.5, NFR4 | StorageUnavailable 주입 시험 |
| NFR4.20 | 백업·복구: PDF 원본·사본 파일의 별도 백업은 두지 않는다. 버킷은 버전 관리를 끈다(ADR-003). 데이터 보존은 작성자 삭제·탈퇴 때까지이며 자동 파기는 없다(NFR5). | ADR-003, NFR5 | 해당 없음(설계 기록) |
