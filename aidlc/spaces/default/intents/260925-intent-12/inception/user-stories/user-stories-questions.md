## 스토리 형식과 분해 접근

사용자 목표와 확인 가능한 결과를 기준으로 나눈다. 예: ‘공유본 발행’, ‘허용 자료로 질문’, ‘제안 수락 취소’, ‘해당 제안의 연락처 조회 중단’처럼 결과가 다른 행동은 구분한다. API·web·worker별로 같은 사용자 결과를 세 스토리로 복제하지 않는다. 실제 담당·이슈·PR 분할은 이번 문서에서 확정하지 않는다.

- 각 스토리는 행위자·행동·얻는 가치, 안정적인 `USx.y` 식별자, 승인 지위, 요구사항 출처, 필요한 선행 조건을 갖춘다.
- 수용 기준은 `ACx.y.z` 식별자와 Given/When/Then으로 쓴다. 정상 동작뿐 아니라 관련 거부·실패·경합·재시도 구분을 승인된 범위 안에서 다룬다.
- 독립 검사에 필요한 초기 상태를 명시한다. 의존성을 숨겨 완전 독립이라고 주장하거나, 다른 스토리 순서를 실행해야만 뜻이 통하게 만들지 않는다.
- INVEST 관점에서 크기·가치·검증 가능성을 점검한다. 팀의 추정 없이 작업 일수·스프린트 완료·담당 합의를 기록하지 않는다.
- 화면 배치·API·DB·검색 구현·세부 한도값은 확정하지 않는다. 미결이 걸린 수용 기준에는 관련 OQ와 확인 시점을 함께 표시한다.

## 우선순위와 미결 처리

- 승인된 ‘필수 / 포함·마감 비필수 / 후순위 포함’ 지위를 그대로 표시한다. 대표 구성 1순위와 기존 후순위를 보존하고 나머지 필수 기능의 구현 순서를 새로 확정하지 않는다.
- MoSCoW는 보조 표기다. 필수는 Must Have, 일반 포함·마감 비필수는 Should Have, 후순위 포함은 Could Have로 대응하되 원래 지위·마감 조건을 함께 쓴다. 이 표기로 새 마감 약속·영구 이연·기능 제외를 만들지 않는다.
- 미채택 후보·보류·범위 밖은 포함된 스토리와 구분한 경계 목록으로 추적한다. 비필수는 미채택 후보가 아니다.
- OQ1~15는 이미 승인된 후속 확정 책임·시점을 유지한다. 이번 문서 작성에 꼭 필요한 새 공백이나 실제 충돌만 1~2개씩 질문한다.
- FR과 NFR 전부를 `traceability.json`으로 연결한다. 후속 단계에서 다룰 NFR 세부는 단계와 이유를 표시하며, 자료 권한·수명 등 현재 스토리에 적용할 품질 조건을 통째로 뒤로 미루지 않는다.

## 답변 분석과 작성 계획 요약

Q1은 문서 상세 수준만 정한다. 기존 포함 지위·마감·후속 확정 조건과 충돌하지 않는다. 새 제품 정책이나 구현 담당·일정은 추가되지 않는다.

- 사용자군은 작성 회원/구직자, 공유 링크 수신자, 기업 회원, 서비스 운영팀의 4개다. 기업 회원 안의 관리자·채용 담당자·검토자 권한과 비로그인 수신자의 경로는 구분한다.
- 앞의 10개 흐름 안에서 사용자 목표·확인 가능한 결과로 스토리를 분해한다. 초안은 약 60~70개를 예상하되 실제 수는 독립성·중복·수용 기준 검토 후 집계한다. 이 예상 수는 기능 범위·담당·개발 기간의 확정값이 아니다.
- 필수 기능은 정상·거부·실패 및 관련 경계·경합 조건까지 상세한 Given/When/Then을 쓴다. 마감 비필수·후순위도 사용자 스토리, 이미 확정된 핵심 수용 기준, 출처와 미결을 남기고 아직 결정하지 않은 세부 예외는 관련 개발 전 확인에 연결한다.
- 각 스토리는 승인된 지위·FR/NFR 출처·관련 OQ·선행 조건을 연결한다. 103개 세부 기능과 NFR7개의 추적을 빠짐없이 확인한다. 그룹 FR1~19도 연결 정보를 유지한다.
- 고정 공유본의 독립 권한, 주장당 사용 가능한 Catch 최소 1장, 공개 대표/기업 허용 추가 주장의 구분, 링크 단위 JD/AI와 회원 단위 MCP 한도, 연락처 전달 당시 값·조회 중단·재동의, 소셜·신고의 마감 비필수 정정을 유지한다.
- 승인된 후속 미결 15개의 값·책임·확정 시점을 임의 변경하지 않는다. 실제 구현·일정 가능성·외부 처리 조건의 검증 완료를 주장하지 않는다.
- 로컬에서 personas.md, stories.md, user-stories-assessment.md, traceability.json을 작성하고 디자인·개발·품질 관점의 기여와 독립 제품 검토를 받는다. 이번 단계의 산출물 검토와 최종 승인은 작성 전 요약 확인과 별개다.
