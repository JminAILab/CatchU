# CatchU 12월 사용자군과 역할 (2026-10-24 재승인판)

## Sources

[재승인 요구사항](../requirements-analysis/requirements.md)(requirements)과 [작성 계획](user-stories-questions.md)의 2026-10-24 재승인 계획을 근거로 한다. 요구사항 의도 분석대로 12월 이용자는 소수의 외부 사용자다. 실제 이용자 조사를 대신하는 가상 인물 설정(나이·숙련도·사용 빈도)은 하지 않는다. 번호는 9월과 맞추며, 9월 P3 기업 회원은 기업 기능이 프로젝트 목표에서 제외돼 없앴다.

## P1. Catch에 설명을 붙여 발행하는 작성 회원

- 역할: 자기 저장소에서 Catch를 만들고, Catch마다 설명을 쓰고, 텍스트·PDF 자료와 함께 발행하는 회원(구직자)이다.
- 목표: 확인 가능한 기록에 맡은 역할·판단 이유·결과를 붙여, 면접관이 짧은 시간에 근거와 함께 읽을 수 있는 고정 발행본을 보낸다. Claude에서 자기 Catch·설명·텍스트 자료를 읽으며 자기소개·면접을 준비한다.
- 어려움: 기록만으로는 선택 이유·역할이 드러나지 않는다. 비공개 Catch가 발행 때 공개로 바뀌는 것, 원본 수정이 발행본에 반영되지 않는 것을 이해해야 한다.
- 맥락: Google 로그인 → GitHub 연결·분석 동의 → 공개 저장소 등록·분석 → Catch 설명 → 자료 → 발행. AI 실행은 계정당 하루 제한이 있다.
- 권한 경계: 본인 자료만 다룬다. 발행본은 원본과 독립된 고정 사본이며 링크 조건으로 제공을 끝낸다. 다른 회원이 자기 링크에 실행한 JD 요약 결과는 볼 수 없다.
- 근거: FR1~5·FR13.1·13.2·FR14·FR16.3·FR20.

## P2. 링크를 받아 근거를 확인하는 사람

- 역할: 작성자에게서 링크를 받은 면접관·채용담당자다. 기업 계정은 없고 일반 개인 계정을 쓴다. 두 상태를 구분한다.
  - P2-A 비로그인 수신자: 링크 조건을 충족하면 로그인 없이 발행본 자료·AI 기본 요약을 보고 질의응답을 쓴다.
  - P2-B 로그인한 면접관 회원: Google로 가입해 JD를 저장하고 그 링크에 JD 요구사항별 요약을 실행하며, Claude 연결로 비밀번호 없는 받은 링크를 읽는다(받은 사람의 Claude 연결은 후순위).
- 목표: GitHub 기록 전체를 읽지 않고도 AI 요약·질의응답·JD 요약에서 근거 원문을 눌러 확인하고, 확인되지 않은 점과 면접에서 물을 것을 구분한다.
- 어려움: AI 문장과 확인된 사실, AI 초안과 작성자 설명을 혼동할 수 있다. 자료에서 찾지 못한 것을 경험·역량이 없는 것으로 오해할 수 있다.
- 권한 경계: 받은 링크의 발행 사본만 쓴다. 비밀번호 링크는 Claude로 읽지 않는다. 본인 JD 요약 결과는 본인만 본다.
- 근거: FR2.7·FR4·FR5.1·FR6·FR13.3·FR16.3·FR20.1.

## P4. 검증·시연을 맡는 팀

- 역할: 외부 접속 가능한 AWS 서비스에서 통합 확인·보호 흐름·실제 Claude 연결·실제 분석·RAG 평가를 하고 12월 10일 제출 자료를 정리하는 팀(팀장 포함)이다.
- 목표: 실제 결과·실패·미실행을 그대로 기록하고, 필수 기능이 실패하면 조용히 빼지 않고 팀장에게 조정안을 낸다.
- 어려움: 로컬·모의 성공이나 10월 분석 경로로 대신 돌린 성공을 새 흐름 완료로 착각하기 쉽다.
- 맥락: 배포 작업 자체는 이 intent 밖 EKS 작업이다. 9월 P4의 운영 조치(이용 제한·기업 권한 중단)와 문의 접수·회신 약속은 제외됐다.
- 근거: FR19·NFR3·NFR6.

## 관계와 우선순위

P1이 발행하면 P2가 읽는다. P2-B가 자기 JD로 실행한 요약은 P2-B만 보고 P1은 보지 못한다. P4는 P1·P2 흐름을 실제 서비스에서 확인한다. 같은 사람이 P1과 P2-B를 함께 가질 수 있다. 핵심 가치 흐름은 P1의 발행본을 P2가 근거와 함께 읽는 것이다.
