# CatchU 12월 사용자 스토리

## Sources

[승인 요구사항](../requirements-analysis/requirements.md)(requirements), [최종 답변·정정](../requirements-analysis/requirements-analysis-questions.md), [작성 계획 확인](user-stories-questions.md), [사용자군 정의](personas.md)를 따른다. FR·NFR·OQ는 모두 이번 intent의 요구사항 식별자다. 원본의 확정 행동을 수용 기준으로 풀어 썼으며 실제 구현·검사 결과를 뜻하지 않는다.

## 읽는 방법과 공통 기준

`USx.y`는 사용자 결과, `ACx.y.z`는 Given/When/Then 수용 기준이다. 각 스토리의 선행은 준비할 상태/연결 계약이며 실행 순서를 강제하는 스프린트 계획이 아니다. 테스트는 해당 초기 상태를 독립적으로 준비할 수 있어야 한다. 정상·거부·실패가 여러 경로에 걸치면 해당 경로를 각각 확인한다.

상태 변경 요청의 접수만으로 발행·삭제·연락처 전달/중단 성공을 표시하지 않는다. 처리 실패 또는 완료 여부 미확정이면 그 상태와 실제 확인된 결과를 구분한다. 이는 FR19.2와 팀의 실제 완료·실패 구분 기준을 적용한 것이며 자동 재시도·새 알림·추가 복구 정책을 정하지 않는다.

| 표기 | 승인된 지위·적용 |
|---|---|
| Must Have | 필수. 2026-11-30 개발·NCP 외부 검증 목표. 공식 제출 결과는 12-10 기준 |
| Should Have | 포함·마감 비필수. 확정 핵심 기준을 유지하고 미정 상세는 해당 개발 전에 결정 |
| Could Have | 후순위 포함. 실제 필요·조건 확인 후 수행하며 필수로 자동 전환하지 않음 |

문서의 순번은 우선순위 순서가 아니다. 대표 구성의 기존 1순위를 보존한다. 비필수 기능 없이 필수 흐름이 성립해야 하며, 비필수 의존성이 드러나면 필요한 일부와 영향만 별도 판단한다. 공통 품질 조건 NFR1~7은 관련 스토리의 기준·출처와 후속 미결표에 연결한다.

## FR1 — 자기 기록 준비

### US1.1 Google 계정으로 자료 준비를 시작한다

작성 회원(P1)인 나는 내 기록을 준비하기 위해 로그인 후 GitHub 연결과 분석 동의를 하고 싶다.

- 지위: Must Have. 출처: FR1.1, NFR1. 선행: 없음. 후속 확인: OQ8.

| ID | Given | When | Then |
|---|---|---|---|
| AC1.1.1 | Google 로그인 전 회원 | 로그인에 성공함 | 자기 회원 계정으로 자료 준비를 시작하며 기업 업무도 이 계정의 소속 역할로 이용한다 |
| AC1.1.2 | 로그인했으나 GitHub 연결 또는 분석 동의가 없음 | 분석을 시작하려 함 | 빠진 준비 조건을 안내하고 해당 조건 없이 분석하지 않는다 |
| AC1.1.3 | 기업 등록·소속 승인이 있는 회원 | 자격을 확인함 | 기업 기능 권한과 실제 기업/소속 인증을 구분하며 Google 외 로그인 기능을 제공하지 않는다 |

### US1.2 지원 공개 저장소를 직접 분석 요청한다

작성 회원(P1)인 나는 팀에 저장소 선정을 부탁하지 않고 내 지원 공개 저장소에서 Catch를 얻고 싶다.

- 지위: Must Have. 출처: FR1.2, NFR7. 선행: US1.1의 연결·동의. 후속 확인: OQ2, OQ4, OQ8.

| ID | Given | When | Then |
|---|---|---|---|
| AC1.2.1 | 연결 계정이 소유하거나 커밋한 지원 공개 저장소와 동의·한도 충족 | 신규 회원이 직접 요청함 | 사전 연락·선정 없이 요청할 수 있다 |
| AC1.2.2 | 비공개·계정 관계 미충족·지원 범위 밖·한도 초과 중 하나 | 요청을 시도함 | 실행 전에 해당 이유를 알리고 조건을 충족하지 않은 분석을 실행하지 않는다 |
| AC1.2.3 | 지원 여부를 확인할 근거가 부족한 상태 | 지원 범위를 안내함 | 모든 저장소나 무제한 분석을 보장하지 않고 확인된 지원 조건을 제시한다 |

### US1.3 분석 상태와 허용된 재요청을 확인한다

작성 회원(P1)인 나는 실제 처리 상태에 맞게 다음 행동을 선택하기 위해 내 분석 결과와 실패를 구분하고 싶다.

- 지위: Must Have. 출처: FR1.3. 선행: US1.2의 요청. 후속 확인: OQ8의 기존 정책·구현 대조, OQ4의 한도.

| ID | Given | When | Then |
|---|---|---|---|
| AC1.3.1 | 본인 분석 요청이 있음 | 처리 상태를 확인함 | 진행·완료·확인된 실패를 구분하고 완료 시 본인 결과를 확인한다 |
| AC1.3.2 | 상태 조회만 시간 초과됨 | 결과를 다시 확인함 | 조회 실패를 분석 실패로 단정하지 않으며 새 분석을 자동 실행하지 않는다 |
| AC1.3.3 | 서버 실패가 확인됨 | 본인이 제한된 재요청을 선택함 | 유효 결과/등록 카드, 진행/복구, 새 동의 등 OQ8에서 대조한 기존 조건을 충족할 때만 재요청한다 |
| AC1.3.4 | 정상 완료 또는 부분 결과가 있는 상태 | 재처리를 검토함 | 정상 완료 재분석·부분 결과 추가 생성·자동 분석 재시도를 이번 흐름에 추가하지 않는다 |

### US1.4 Catch의 근거와 현재 숨김 상태를 관리한다

작성 회원(P1)인 나는 내 기여를 오해 없이 보여 주기 위해 Catch의 출처를 확인하고 현재 사용 여부를 바꾸고 싶다.

- 지위: Must Have. 출처: FR1.4, FR1.5, NFR1, NFR3. 선행: 본인 Catch. 관련: US2.2, US4.3.

| ID | Given | When | Then |
|---|---|---|---|
| AC1.4.1 | 본인 Catch에 기록·설명·AI 해석이 있음 | 내용을 확인함 | 세 출처를 구분하고 근거를 열 수 있으며 타인 기여를 본인 것으로 표시하지 않는다 |
| AC1.4.2 | 현재 사용 중인 Catch | 본인이 숨김으로 바꿈 | 현재 프로필·기업 검색·현재 자료 RAG/MCP·새 공유본에서 사용하지 않으며 본인 관리 정보는 보존한다 |
| AC1.4.3 | 숨긴 Catch | 숨김을 해제함 | 현재 자료의 허용 조건을 다시 적용하고 다른 자료를 자동 공개하지 않는다 |
| AC1.4.4 | 이미 공유본에 포함된 Catch | 원본을 숨김 | 기존 발행본의 독립 접근은 유지하며 사용자 Catch 원본 삭제 기능이나 보류된 서비스 내 3층 탐색을 추가하지 않는다 |

## FR2 — 강점 주장 구성

### US2.1 강점 주장을 초안부터 작성한다

작성 회원(P1)인 나는 기록만으로 설명하기 어려운 맥락을 전달하기 위해 제목·본문·Catch 구성으로 여러 주장을 작성하고 싶다.

- 지위: Must Have. 출처: FR2.1, FR2.3, FR2.5, NFR7. 선행: 본인 계정. 관련: US2.2, US4.1.

| ID | Given | When | Then |
|---|---|---|---|
| AC2.1.1 | 자기 주장 초안 또는 새 작성 상태 | 제목·본문·Catch 구성을 저장·수정함 | 한 작성 단위로 관리하며 경험을 별도 독립 자료로 만들지 않는다 |
| AC2.1.2 | 제목·본문 또는 Catch가 미완성 | 초안을 저장함 | 비공개 관리용 저장·수정을 허용하고 대표/검색/RAG/발행의 사용 조건과 구분한다 |
| AC2.1.3 | 여러 Catch·주장이 있음 | 새 주장을 작성함 | 여러 주장을 직접 관리할 수 있지만 모든 Catch의 주장 작성이나 복수 작성을 의무화하지 않는다 |
| AC2.1.4 | 짧거나 빈 본문 | 입력·저장함 | 최소 글자 수·품질 점수·배경/판단/역할/결과별 필수 입력을 추가하지 않고 빈 본문을 임의 생성하지 않는다 |

### US2.2 주장에 연결한 Catch를 관리한다

작성 회원(P1)인 나는 설명과 근거의 관계를 관리하기 위해 Catch 연결과 숨김 상태를 확인하고 바꾸고 싶다.

- 지위: Must Have. 출처: FR2.2, FR2.3, FR2.6, NFR1. 선행: 본인 주장·Catch. 관련: US1.4.

| ID | Given | When | Then |
|---|---|---|---|
| AC2.2.1 | 본인 주장과 Catch | 한 장 또는 여러 장을 연결·제외함 | 연결 구성만 바뀌며 제외한 Catch 원본은 삭제되지 않고 미선택 자료가 자동 포함되지 않는다 |
| AC2.2.2 | 주장에 연결이 없거나 모든 연결 Catch가 숨김 | 대표·검색·현재 RAG·새 발행에 사용하려 함 | 제목·본문을 포함한 주장 전체를 사용하지 않되 관리용 문구·연결은 보존한다 |
| AC2.2.3 | 일부 연결 Catch만 숨김 | 허용 경로에서 주장을 조회함 | 문구는 유지하고 나머지 허용 Catch만 제공하며 다시 한 장 이상 사용 가능해지면 사용 조건을 충족한다 |
| AC2.2.4 | 같은 Catch를 여러 현재 주장이 참고함 | 원본 Catch가 수정됨 | 참고 내용은 반영되지만 각 제목·본문·선택 구성은 자동 수정되지 않고 관리·미리보기에서 함께 확인한다 |

### US2.3 공유할 대표와 추가 주장을 고른다

작성 회원(P1)인 나는 전달 목적에 맞는 근거를 보여 주기 위해 대표 하나와 필요한 추가 주장을 골라 확인하고 싶다.

- 지위: Must Have. 출처: FR2.4, FR2.5. 선행: 본인 주장. 관련: US4.1.

| ID | Given | When | Then |
|---|---|---|---|
| AC2.3.1 | 사용 가능한 여러 주장 | 대표 하나와 선택적인 추가 주장을 지정함 | 실제 포함될 제목·본문·Catch를 발행 전에 확인한다 |
| AC2.3.2 | 선택한 주장에 빈 제목/본문 또는 열람 가능한 Catch가 없음 | 발행을 시도함 | 보완하거나 해당 주장을 제외하도록 안내하며 대표가 부족하면 초안으로 남긴다 |
| AC2.3.3 | 각 선택 주장에 제목·본문과 열람 가능한 Catch 한 장 이상 | 발행 조건을 확인함 | 최소 두 장·새 최대 장수를 요구하지 않고 이 조건 충족을 주장 입증·역량 검증으로 표시하지 않는다 |

## FR3 — 서류 등록과 참고 가능성

### US3.1 여러 서류 중 공유할 자료를 선택한다

작성 회원(P1)인 나는 지원 목적에 맞는 자료를 전달하기 위해 여러 벌 서류를 등록하고 공유본별로 선택하고 싶다.

- 지위: Must Have. 출처: FR3.1, FR3.2, FR3.3. 선행: 본인 계정. 관련: US4.1. 후속 확인: OQ2.

| ID | Given | When | Then |
|---|---|---|---|
| AC3.1.1 | 서류 등록 상태 | 자기소개서 텍스트, 포트폴리오 PDF/URL, 이력서 PDF를 등록함 | 종류별 여러 벌을 관리하고 주장 프리셋 밖에서 공유본별로 선택한다 |
| AC3.1.2 | 선택한 텍스트/PDF와 외부 URL | 공유본을 발행함 | 텍스트/PDF 내용과 URL 주소를 각각 보존하며 URL은 외부 원문 이동임을 구분하고 본문을 자동 수집하지 않는다 |
| AC3.1.3 | 수신자에게 허용된 텍스트/PDF | 읽기를 요청함 | 서비스 내 열람과 허용 AI 참고를 제공하며 별도 다운로드/허용 설정이나 완전 복사 방지 보장을 추가하지 않는다 |
| AC3.1.4 | OQ2에서 지원 규격·용량·수량을 확정함 | 해당 경계 사례를 검사함 | 확정 지원 범위를 기준으로 판정하며 값 확정 전 무제한 등록 가능으로 처리하지 않는다 |

### US3.2 AI가 못 읽는 PDF도 구분해서 공유한다

작성 회원·수신자(P1·P2)인 나는 자료를 직접 읽되 AI 검토 범위를 오해하지 않기 위해 읽기 가능성을 구분하고 싶다.

- 지위: Must Have. 출처: FR3.4, FR3.5, NFR3, NFR7. 선행: 정상 열람 가능한 PDF. 관련: US6.2, US4.3. 후속 확인: OQ2.

| ID | Given | When | Then |
|---|---|---|---|
| AC3.2.1 | 서비스 열람은 가능하지만 AI 읽기가 실패한 PDF | 등록·열람·공유함 | 동작을 허용하고 작성자와 수신자에게 AI 참고 불가를 구분한다 |
| AC3.2.2 | 그 PDF와 다른 읽기 가능한 자료가 있음 | AI 답변을 요청함 | 실패 PDF를 읽거나 인용한 척하지 않고 미검토 범위를 밝히며 근거 부족을 역량 부재로 단정하지 않는다 |
| AC3.2.3 | 기존 발행본과 교체된 원본 PDF | 작성자가 수정본을 전달하려 함 | 기존 발행본은 유지하고 새 링크로 전달한다. AI 참고 선택만으로 미공유 자료 권한을 얻지 않는다 |

## FR4 — 고정 공유본 발행과 읽기

### US4.1 발행 당시 자료를 고정해 전달한다

작성 회원(P1)인 나는 수신자가 같은 자료를 검토하도록 미리 본 구성을 고정 공유본으로 발행하고 싶다.

- 지위: Must Have. 출처: FR4.1, FR4.3, FR5.4, NFR7. 선행: US2.3·US3.1의 선택 구성. 후속 확인: OQ3.

| ID | Given | When | Then |
|---|---|---|---|
| AC4.1.1 | 각 선택 주장에 제목·본문·열람 가능한 Catch가 있고 서류를 선택함 | 발행함 | 제목·본문·연결 구성·실제 Catch·선택 텍스트/PDF·URL 주소를 발행 당시대로 보존한다 |
| AC4.1.2 | 숨김 Catch 또는 미완성 대표가 선택됨 | 발행을 시도함 | 숨김 해제·구성 보완이 필요함을 알리고 그 상태로 새 발행하지 않는다 |
| AC4.1.3 | 발행 전 기본 접근 조건을 확인하는 작성자 | 발행 내용을 확인함 | 실제 만료 시점과 원본 수정 비반영·수정본 새 발행·기존 제공 중단 방법을 알 수 있다 |
| AC4.1.4 | 공유 링크가 발행됨 | 결과를 안내함 | 고정 공유본임을 알리며 ATS 접수 완료나 철회 불가능한 공식 제출로 표시하지 않는다 |

### US4.2 짧은 요약에서 공유 근거를 읽는다

링크 수신자(P2)인 나는 검토 시간을 줄이기 위해 요약으로 파악한 뒤 필요한 대표·추가 자료를 직접 읽고 싶다.

- 지위: Must Have. 출처: FR2.7, FR4.2, FR4.4, NFR1, NFR7. 선행: 유효한 고정 공유본. 후속 확인: OQ1.

| ID | Given | When | Then |
|---|---|---|---|
| AC4.2.1 | 링크의 비밀번호·만료·중단 조건을 충족함 | 비로그인 수신자가 읽음 | 짧은 요약에서 설명·주장·Catch로 들어가며 포함된 추가 자료도 직접 읽을 수 있다 |
| AC4.2.2 | 접근 조건 미충족 또는 미포함 자료 | 웹·JD/RAG·자격 있는 MCP 경로로 새 조회함 | 해당 자료를 제공하지 않으며 사본 존재가 접근 조건을 우회하지 않는다 |
| AC4.2.3 | 별도 프로필 대표 소개가 없음 | 필수 읽기 흐름을 시작함 | 요약→설명·근거 읽기가 성립하며 초기 2~3장을 전체 자료 상한·발행 최소로 쓰지 않는다 |
| AC4.2.4 | 요약·자료 조회가 실패함 | 읽기 결과를 표시함 | 읽지 못한 내용을 확인한 근거로 제시하지 않는다. 실제 개수·길이·배치·생성 방식은 OQ1 확정 후 검사한다 |

### US4.3 원본 변경과 기존 발행본을 구분한다

작성 회원·수신자(P1·P2)인 나는 전달 시점의 내용을 유지하면서 제공 종료를 통제하기 위해 원본과 공유본의 차이를 알고 싶다.

- 지위: Must Have. 출처: FR4.1, FR4.3, FR4.5, NFR1. 선행: 발행본과 원본. 관련: US5.1·US5.2. 후속 확인: OQ8.

| ID | Given | When | Then |
|---|---|---|---|
| AC4.3.1 | 발행 후 원본·초안·프리셋·서류가 있음 | 수정·숨김·교체·원본 서류 삭제를 함 | 기존 발행본 내용은 바뀌지 않고 수신자에게 이후 원본 변경 사실을 안내하지 않는다 |
| AC4.3.2 | 발행 후 GitHub 원본이 비공개 전환됨 | 고정 공유본과 해당 JD/RAG/MCP를 조회함 | 링크 조건 안에서 발행 당시 자료를 유지한다. 원본 기반 현재 자료에는 보호 규칙을 적용한다 |
| AC4.3.3 | GitHub 조회에 실패함 | 원본 상태를 해석함 | 비공개 전환으로 단정하지 않고 보존 Catch를 현재 GitHub 원문 확인으로 표시하지 않는다 |
| AC4.3.4 | 작성자가 이전 자료 제공을 끝내려 함 | 관리 안내를 확인함 | 원본 변경이 아닌 링크 중단 또는 공유본 삭제를 선택할 수 있다 |

## FR5 — 공유본 접근과 보관 종료

### US5.1 수신자 접근을 끝내고 보관본을 확인한다

작성 회원(P1)인 나는 과거 전달 자료를 확인하면서 외부 제공을 끝내기 위해 만료·중단된 공유본을 관리하고 싶다.

- 지위: Must Have. 출처: FR5.1, FR5.3, NFR1, NFR5. 선행: 본인 발행본. 후속 확인: OQ3.

| ID | Given | When | Then |
|---|---|---|---|
| AC5.1.1 | 유효한 링크 | 만료되거나 작성자가 중단함 | 수신자의 열람·JD/RAG/MCP 접근을 중단한다 |
| AC5.1.2 | 만료·중단 후 보관 기간 안 | 작성자가 내용을 확인함 | 발행 당시 내용을 볼 수 있지만 수신자 접근은 계속 차단한다 |
| AC5.1.3 | 만료·중단된 링크 | 다시 이용하려 함 | 같은 링크를 부활시키지 않으며 원본 보유를 접근 복원으로 취급하지 않는다 |

### US5.2 본인 공유본을 직접 삭제한다

작성 회원(P1)인 나는 더 보관할 필요가 없는 발행 자료를 없애기 위해 특정 공유본을 삭제하고 싶다.

- 지위: Must Have. 출처: FR5.2, NFR1, NFR5. 선행: 본인 공유본. 후속 확인: OQ11.

| ID | Given | When | Then |
|---|---|---|---|
| AC5.2.1 | 본인 공유본 | 직접 삭제가 완료됨 | 링크가 무효가 되고 작성자도 발행 내용을 다시 읽지 못한다 |
| AC5.2.2 | 원본 자료와 다른 공유본도 있음 | 특정 공유본만 삭제함 | 원본과 다른 공유본은 유지한다 |
| AC5.2.3 | 삭제 전 요약·RAG/MCP 조회 흔적이 있음 | 삭제된 내용을 새로 조회함 | 이전 결과를 통해 삭제 내용을 다시 제공하지 않는다 |
| AC5.2.4 | 본인 공유본 삭제를 요청함 | 처리에 실패하거나 완료 여부를 아직 확인하지 못함 | 삭제·파기 완료로 표시하지 않고 실패·미확정과 실제 확인된 상태를 구분한다 |

### US5.3 보관 종료를 알고 자동 파기를 적용한다

작성 회원(P1)인 나는 과거 공유본의 이용 가능 기간을 알기 위해 보관 종료 시점을 확인하고 싶다.

- 지위: Must Have. 출처: FR5.3, FR5.4, NFR5. 선행: 만료·중단 공유본. 후속 확인: OQ3, OQ11.

| ID | Given | When | Then |
|---|---|---|---|
| AC5.3.1 | 근거를 검토해 보관 기간을 확정함 | 링크가 만료·중단됨 | 그 시점부터 보관 종료를 계산·안내하고 그 안에서는 본인 확인·직접 삭제를 허용한다 |
| AC5.3.2 | 확정된 보관 종료에 도달함 | 자동 파기 처리를 함 | 해당 보관 내용을 더 이상 제공하지 않는다. 실제 파기 대상·근거는 OQ11로 검증한다 |
| AC5.3.3 | 기본 링크 기간이나 보관값이 아직 미정 | 구현·시험을 준비함 | 과거 수치·무기한을 채우지 않고 OQ3 확정을 선행 조건으로 남긴다. 탈퇴에는 일반 보관 기간을 적용하지 않는다 |

## FR6 — JD와 근거 질문

### US6.1 JD를 현재 자료와 함께 검토한다

링크 수신자(P2)인 나는 직무 요구와 근거를 함께 보기 위해 직접 입력한 JD의 요약과 관련 대목을 확인하고 싶다.

- 지위: Must Have. 출처: FR6.1, NFR3. 선행: 접근 가능한 공유본. 관련: US6.4.

| ID | Given | When | Then |
|---|---|---|---|
| AC6.1.1 | 직접 입력한 JD와 현재 자료 | 검토함 | 한 장 요약·현재 자료 사이드 패널·질문에 JD를 반영한다 |
| AC6.1.2 | 현재 자료에 관련 근거가 없음 | 패널을 확인함 | 같은 JD 요약의 해당 항목을 안내하고 다른 서류 근거를 현재 자료의 근거로 섞지 않는다 |
| AC6.1.3 | 관련 대목이 제시됨 | 적합성 정보를 확인함 | JD 매칭 비율이나 패널 개수·비율·색상의 종합 역량 평가를 제공하지 않는다 |

### US6.2 참고 가능한 자료를 구분해 질문한다

링크 수신자(P2)인 나는 실제 근거의 범위를 이해하기 위해 허용 자료에서 질문하고 출처·미확인 사항을 알고 싶다.

- 지위: Must Have. 출처: FR6.2, FR6.3, FR6.4, NFR1, NFR3, NFR7. 선행: 접근 가능한 공유본. 후속 확인: OQ6.

| ID | Given | When | Then |
|---|---|---|---|
| AC6.2.1 | 공유된 허용 자료 | 프리셋을 따로 고르지 않고 질문함 | 관련 근거를 찾고 필요시 여러 주장 자료를 함께 쓰며 실제 확인 범위를 넘겨 전체 검토로 표시하지 않는다 |
| AC6.2.2 | 포함·접근 허용·AI 읽기 가능한 서류 | 기본 참고 대상을 확인하거나 특정 서류를 제외함 | 해당 서류가 기본 대상이며 제외를 반영하고 내용·열람 권한은 바꾸지 않는다 |
| AC6.2.3 | 외부 URL·AI 읽기 실패 PDF·미공유 자료 | 질문함 | 본문을 AI 참고하지 않고 현재 참고 대상·참고 불가·미검토 범위를 구분한다 |
| AC6.2.4 | 기록과 작성자의 역할·이유·성과 설명 | 경험·선택 이유·문제 해결·면접 질문을 물음 | 사실·자기 설명·AI 해석과 출처를 나누고 모르는 의도·책임·성과 수치를 만들지 않는다 |
| AC6.2.5 | 근거가 부족하거나 일부만 참고함 | 전체 요약·확인 공백을 요청함 | 실제 범위와 추가 질문 이유를 밝히며 근거 부재를 역량 부재로 판정하지 않는다 |

### US6.3 서류 주장과 관련된 근거 후보를 찾는다

링크 수신자(P2)인 나는 서류의 설명을 더 확인하기 위해 명시 연결 밖의 관련 근거 후보도 알고 싶다.

- 지위: Must Have. 출처: FR6.5, NFR3. 선행: 읽기 가능·접근 허용 서류와 자료. 후속 확인: OQ6.

| ID | Given | When | Then |
|---|---|---|---|
| AC6.3.1 | 작성자가 연결하지 않은 관련 Catch가 허용 자료에 있음 | 서류 주장의 근거를 질문함 | AI가 제안한 연결 후보로 표시하고 해당 주장 부분·구체 내용·출처·확인 한계를 설명한다 |
| AC6.3.2 | 후보를 제시함 | 저장된 주장 연결을 확인함 | 작성자 명시 연결과 구분되고 자동 변경되거나 입증 완료로 표시되지 않는다 |
| AC6.3.3 | 구체 관련 근거 없이 단어만 비슷함 | 후보를 찾음 | 억지 후보를 만들지 않고 현재 자료에서 찾지 못했음을 알리며 후속 질문을 제안한다 |

### US6.4 현재 조건에서 요약을 재사용하고 호출 한도를 이해한다

링크 수신자(P2)인 나는 불필요한 호출을 줄이면서 자료를 읽기 위해 유효한 요약과 새 AI 호출의 차이를 알고 싶다.

- 지위: Must Have. 출처: FR6.6, NFR1. 선행: 기존 JD 요약·유효 링크. 후속 확인: OQ4, OQ9.

| ID | Given | When | Then |
|---|---|---|---|
| AC6.4.1 | 현재 권한·참고 선택·고정본 조건과 확정 재사용 조건 충족 | 동일 JD 요약을 재사용함 | 유효한 요약을 이용하며 다른 수신자의 JD·질의 내용을 공유하지 않는다 |
| AC6.4.2 | 같은 링크를 여러 제공 경로에서 이용함 | CatchU JD/AI 호출을 집계함 | 기존 링크 단위로 합산하고 경로·MCP 연결 변경으로 새 한도를 얻거나 초기화하지 않는다 |
| AC6.4.3 | 새 AI 호출 한도를 소진함 | 새 호출 또는 기존 요약/원문 읽기를 요청함 | 새 호출은 제한하되 현재 조건에 맞는 기존 요약·원문 열람은 유지한다 |
| AC6.4.4 | 링크 접근이나 참고 조건을 잃음 | 저장된 요약을 새로 조회함 | 과거 요약 존재로 조건을 우회하지 않는다. 재방문 이력·기업 질의 공유·새 MCP AI 실행을 추가하지 않는다 |

## FR7 — 기업 소속과 역할

### US7.1 기업을 등록해 업무를 시작한다

기업을 등록하려는 로그인 회원(등록 성공 후 P3-A)인 나는 우리 기업의 업무 권한을 관리하기 위해 기업을 직접 등록하고 싶다.

- 지위: Must Have. 출처: FR7.1, NFR1. 선행: 회원 로그인.

| ID | Given | When | Then |
|---|---|---|---|
| AC7.1.1 | 로그인한 회원 | 기업명과 선택적 웹사이트로 등록함 | 최초 기업 관리자가 된다 |
| AC7.1.2 | 기업명 없이 등록하려 함 | 등록 조건을 확인함 | 필수 기업명이 필요하며 웹사이트·상세 회사 프로필을 필수로 요구하지 않는다 |
| AC7.1.3 | 기업이 등록됨 | 자격을 안내함 | 실제 기업·소속 인증 또는 CatchU 운영자 권한을 얻었다고 표시하지 않는다 |

### US7.2 신청한 소속과 업무 역할을 승인한다

기업 관리자(P3-A)인 나는 필요한 사람에게 업무를 맡기기 위해 소속 신청과 역할을 확인·승인하고 싶다.

- 지위: Must Have. 출처: FR7.2, FR7.3, NFR1. 선행: 기업·신청 회원.

| ID | Given | When | Then |
|---|---|---|---|
| AC7.2.1 | 다른 회원이 소속을 신청함 | 관리자가 승인함 | 기본 제시한 검토자 역할을 확인·변경할 수 있고 승인한 역할로 소속 권한을 얻는다 |
| AC7.2.2 | 미승인 신청자 | 소속 자료·업무를 요청하거나 역할을 확정하려 함 | 소속 권한과 역할 확정을 허용하지 않는다. 초대·수락 경로는 추가하지 않는다 |
| AC7.2.3 | 관리자·채용 담당자·검토자 각각 | 업무를 실행함 | 관리자는 소속 관리/검토/검색/제안, 채용 담당자는 검토/검색/제안, 검토자는 허용 자료 검토만 수행한다 |
| AC7.2.4 | 역할은 있으나 자료 허용·검색 참여 조건이 없음 | 후보 자료에 접근함 | 역할만으로 접근하지 못하며 직급·직함이나 임의 권한 조합으로 규칙을 바꾸지 않는다 |

### US7.3 소속·역할 변경의 영향을 반영한다

기업 회원(P3)인 나는 업무 자격이 바뀔 때 남은 권한을 명확히 하기 위해 소속 해제와 역할 변경 결과를 확인하고 싶다.

- 지위: Must Have. 출처: FR7.4, FR7.5, NFR1. 선행: 승인 소속. 관련: US12.2, US14.2, US15.3.

| ID | Given | When | Then |
|---|---|---|---|
| AC7.3.1 | 일반 소속 회원 | 본인 또는 관리자가 해당 소속을 해제함 | 해당 기업 소속 권한을 중단한다 |
| AC7.3.2 | 마지막 관리자 | 일반 해제·강등을 시도함 | 다른 관리자 확보 후 허용하며 마지막 관리자 탈퇴의 기업 종료 경로와 구분한다 |
| AC7.3.3 | 미응답 제안 발송자가 소속·제안 역할을 잃음 | 구직자가 기존 제안에 응답함 | 읽기·거절은 가능하나 수락은 불가하다. 같은 기업 자격 회복 후에는 현재 조건으로 수락 가능하다 |
| AC7.3.4 | 관리자와 채용 담당자 사이 역할 변경 | 제안 자격을 확인함 | 제안 역할 상실로 보지 않는다. 검토자로 변경한 뒤 회복한 경우 연락처 권한은 자동 복원하지 않는다 |

## FR8 — 공개 대표와 기업 열람 동의

### US8.1 개인 프로필의 대표 주장을 공개한다

작성 회원(P1)인 나는 내 강점을 처음 방문한 사람에게 보여 주기 위해 대표 주장 하나를 지정하고 싶다.

- 지위: Must Have. 출처: FR8.1, NFR1. 선행: 본인 주장. 관련: US2.2.

| ID | Given | When | Then |
|---|---|---|---|
| AC8.1.1 | 사용 조건을 갖춘 본인 주장 | 프로필 대표로 지정함 | 한 개의 제목·본문·연결된 허용 Catch를 전체 공개한다 |
| AC8.1.2 | 다른 주장·연결되지 않은 Catch가 있음 | 대표를 공개함 | 다른 자료를 자동 공개하지 않고 대표 전체/맞팔 선택을 두지 않는다 |
| AC8.1.3 | 대표 Catch 일부 또는 전체가 숨김 | 프로필을 조회함 | 일부면 나머지 허용 Catch만, 전부면 주장 전체 사용 중단이라는 기존 조건을 적용한다 |

### US8.2 기업 검색 참여를 직접 정한다

구직자(P1)인 나는 기업에 새로 발견될지를 통제하기 위해 기업 검색 참여를 따로 설정하고 싶다.

- 지위: Must Have. 출처: FR8.2, FR10.1, NFR1. 선행: 본인 계정·대표 주장.

| ID | Given | When | Then |
|---|---|---|---|
| AC8.2.1 | 신규 회원 | 기업 검색 참여 설정을 확인함 | 기본 OFF이며 명시 동의한 경우에만 새 발견 대상이 된다 |
| AC8.2.2 | 검색 동의가 있으나 대표 제목·본문 또는 사용 가능한 Catch가 없음 | 기업이 검색함 | 검색에서 제외하되 동의·초안을 유지하고 조건 회복 후 기존 동의에 따라 노출한다 |
| AC8.2.3 | 검색 참여를 켜려는 구직자 | 설정을 확인함 | 현재 제안 수신 상태를 안내하고 별도로 허용할 수 있으며 자동으로 수신 ON을 만들지 않는다 |

### US8.3 기업에 추가 주장을 허용하고 철회한다

구직자(P1)인 나는 공통 대표 밖의 강점 공개를 통제하기 위해 추가 주장별로 기업 열람을 허용하거나 철회하고 싶다.

- 지위: Must Have. 출처: FR8.3, FR8.4, NFR1. 선행: 본인 계정·관리할 추가 주장. 기업의 실제 검색·열람에는 검색 참여·주장 사용 조건·기업 권한을 별도 적용한다. 관련: US9.3, US13.4.

| ID | Given | When | Then |
|---|---|---|---|
| AC8.3.1 | 본인의 추가 주장 | 기업 열람 설정을 확인·변경함 | 새 주장은 기본 미허용이며 작성자가 주장별로 허용·철회한다. 허용만으로 검색 참여를 ON으로 만들거나 검색 대표 조건을 생략하지 않는다 |
| AC8.3.2 | 기업 자격·검색 동의·자료 조건 충족 | 허용 추가 자료를 열람함 | 열람 전 제목·무료 안내, 열람 후 본문·연결된 허용 Catch를 제공하고 검색 판정에도 사용한다 |
| AC8.3.3 | 과거에 기업이 열람한 추가 주장 | 작성자가 허용을 철회함 | 이전 열람과 무관하게 웹/MCP의 해당 경로 새 조회를 막는다 |
| AC8.3.4 | 테스트 무료 정책 적용 중 | 추가 자료를 이용함 | 마일리지 차감 없이 권한·허용을 검사한다. 철회가 공개 대표·독립 고정 공유본 정책을 바꾸지 않는다 |

## FR9 — 근거가 구분되는 구직자 검색

### US9.1 필요한 기술 조건을 모두 충족하는 후보자를 찾는다

기업 관리자·채용 담당자(P3-A·P3-H)인 나는 근거를 확인하며 후보를 찾기 위해 기술 조건을 조합하고 싶다.

- 지위: Must Have. 출처: FR9.1, FR9.4, NFR3. 선행: 검색 권한·참여/자료 동의. 후속 확인: OQ5.

| ID | Given | When | Then |
|---|---|---|---|
| AC9.1.1 | 허용 프로필 자가 입력과 Catch 확인 기술 | 여러 조건과 복수 기술로 검색함 | 서로 다른 조건과 선택 기술 모두 충족해야 하며 자가 입력과 기록 확인 출처를 구분한다 |
| AC9.1.2 | 같은 구직자의 여러 허용 Catch에 기술 근거가 나뉨 | 모두 충족하는지 확인함 | 근거를 합쳐 조건을 충족할 수 있지만 동일 프로젝트 동시 사용으로 표시하지 않는다 |
| AC9.1.3 | 동일 기술로 확인된 표기 차이 | 기술 필터를 적용함 | 근거 있는 최소 대응표를 적용하고 미확인 표기를 임의 병합하거나 숙련도 평가로 바꾸지 않는다 |
| AC9.1.4 | 비허용 자료에만 기술 근거가 있음 | 검색함 | 그 자료를 판정에 사용하지 않는다. 상세 프로필 전체·의미 검색·관리 화면을 자동 필수화하지 않는다 |

### US9.2 허용 항목에서 모든 검색어가 있는 후보자를 찾는다

기업 관리자·채용 담당자(P3-A·P3-H)인 나는 필요한 표현이 담긴 자료를 찾기 위해 자유 문자열로 검색하고 싶다.

- 지위: Must Have. 출처: FR9.2, NFR1, NFR4. 선행: 검색 권한·허용 자료. 후속 확인: OQ5, OQ6.

| ID | Given | When | Then |
|---|---|---|---|
| AC9.2.1 | 검색어가 공백으로 나뉘고 여러 허용 항목에 존재함 | 문자열로 검색함 | 같은 구직자의 허용 항목 안에 모든 단어가 있으면 일치하며 항목이 달라도 된다 |
| AC9.2.2 | 앞뒤 공백이나 영문 대소문자만 다름 | 같은 검색을 함 | 그 차이로 결과를 다르게 판정하지 않는다 |
| AC9.2.3 | 일부 단어가 없거나 비공개 자료·서류 전체에만 있음 | 검색함 | 일치로 처리하지 않으며 주장 제목·본문과 Catch 기존 검색 항목의 출처를 구분한다 |

### US9.3 검색 일치의 근거와 한계를 읽는다

기업 관리자·채용 담당자(P3-A·P3-H)인 나는 과도한 역량 추정을 피하기 위해 어떤 자료가 검색에 일치했는지 확인하고 싶다.

- 지위: Must Have. 출처: FR9.3, FR8.4, NFR3, NFR7. 선행: 검색 결과. 관련: US8.3.

| ID | Given | When | Then |
|---|---|---|---|
| AC9.3.1 | 일치 후보자가 있음 | 결과와 상세를 확인함 | 일치 항목·출처, 대표 본문·허용 Catch를 읽으며 추가 주장 본문은 추가 자료 열람 조건을 따른다 |
| AC9.3.2 | 문자열 일치·기술 사용 기록이 있음 | 근거를 해석함 | 문자열을 사실 근거로, 기술 사용을 숙련도로 바꾸지 않고 근거 없는 기술을 못 쓴다고 판정하지 않는다 |
| AC9.3.3 | 결과가 없거나 조회에 실패함 | 검색 상태를 확인함 | 두 경우를 구분하고 자동 조건 완화·추천·유사도/일치 개수 순위를 추가하지 않는다 |

## FR10 — 제안과 응답

### US10.1 새 제안 수신을 따로 설정한다

구직자(P1)인 나는 기존 제안을 정리하면서 새 연락을 통제하기 위해 수신 허용을 독립적으로 바꾸고 싶다.

- 지위: Must Have. 출처: FR10.1, FR10.4. 선행: 본인 계정. 관련: US8.2, US11.1.

| ID | Given | When | Then |
|---|---|---|---|
| AC10.1.1 | 신규 회원 | 새 제안 수신 상태를 확인함 | 기본 OFF이며 명시 허용 후 수신할 수 있다 |
| AC10.1.2 | 검색 참여와 수신 허용 설정이 있음 | 하나를 바꿈 | 다른 설정을 자동 변경하지 않고 수신 허용만으로 자료 접근·새 발견 경로를 주지 않는다 |
| AC10.1.3 | 기존 미응답 제안이 있음 | 전체 새 수신을 OFF로 함 | 기존 읽기·수락·거절은 유지하되 차단·발송자 자격·운영 제한을 별도로 적용한다 |

### US10.2 현재 조건에 맞는 채용 제안을 전달한다

기업 관리자·채용 담당자(P3-A·P3-H)인 나는 관심 후보자에게 기회를 설명하기 위해 포지션·JD·사유를 담은 제안을 보내고 싶다.

- 지위: Must Have. 출처: FR10.2, FR10.3, NFR1. 선행: 기업 검색·제안 역할. 후속 확인: OQ4.

| ID | Given | When | Then |
|---|---|---|---|
| AC10.2.1 | 기업 검색의 후보이며 기업/계정·역할·수신·차단·반복 조건 충족 | 제안을 보냄 | 포지션·JD·사유를 전달한다. 공유 링크에서 새 제안을 시작하지 않는다 |
| AC10.2.2 | 같은 발송 계정–구직자 쌍에 미응답 제안이 있음 | 제한 안에서 추가 발송함 | 추가 전달 가능하며 같은 기업 다른 발송자 건수는 합산하지 않는다 |
| AC10.2.3 | 직전 기간의 실제 전달 기록 | 반복 한도를 계산함 | JD/포지션·응답·취소와 무관하게 합산하고 날짜 경계·차단 해제로 초기화하지 않는다 |
| AC10.2.4 | 실패·미전달 또는 동일 요청의 중복 처리 | 건수를 계산함 | 새 전달 건수로 더하지 않는다 |
| AC10.2.5 | 한도 또는 현재 발송 조건을 충족하지 못함 | 발송을 시도함 | 이유를 안내하고 전달하지 않으며 거부한 발송을 대기·자동 전달하지 않는다. 기존 읽기·응답까지 한도로 막지 않는다 |

### US10.3 받은 제안을 읽고 수락하거나 거절한다

구직자(P1)인 나는 채용 기회에 의사를 전달하기 위해 미응답 제안을 읽고 응답하고 싶다.

- 지위: Must Have. 출처: FR10.4, FR10.7, FR7.5. 선행: 본인에게 전달된 미응답 제안. 관련: US11.1, US15.2·US15.3. 후속 확인: OQ11.

| ID | Given | When | Then |
|---|---|---|---|
| AC10.3.1 | 응답 자격·상태를 충족하는 미응답 제안 | 수락 또는 거절함 | 선택한 의사를 반영하고 수락만으로 연락처를 공개하거나 DM을 요구하지 않는다 |
| AC10.3.2 | 발송자가 해당 기업 소속/제안 역할을 잃었거나 기업 활동이 제한됨 | 수락하려 함 | 현재 조건으로 수락을 막되 허용되는 기존 읽기·거절 정리를 유지한다 |
| AC10.3.3 | 시간이 지난 미응답 제안 | 응답하려 함 | 자동 만료시키지 않고 현재 조건을 확인한다. 무기한 보관·채용 의사 지속으로 표시하지 않는다 |

### US10.4 수락을 취소한다

구직자(P1)인 나는 진행 의사를 철회하기 위해 수락한 제안을 취소하고 싶다.

- 지위: Must Have. 출처: FR10.5, NFR1. 선행: 본인이 수락한 제안. 관련: US12.2.

| ID | Given | When | Then |
|---|---|---|---|
| AC10.4.1 | 수락한 제안 | 취소를 결정하기 전 안내를 확인함 | 같은 제안 재수락 불가와 재진행 시 새 제안 필요를 알 수 있다 |
| AC10.4.2 | 취소를 실행함 | 결과를 확인함 | 해당 제안 기반 연락처 공유·조회를 중단하고 자동 재제안·재수락·연락처 복원을 하지 않는다 |
| AC10.4.3 | 취소한 제안 | 이후 관계를 확인함 | 계정 차단이나 외부 ATS 전형 취소로 취급하지 않으며 새 제안은 현재 발송 조건부터 확인한다 |

### US10.5 보낸 미응답 제안을 철회한다

원래 발송자(P3-A·P3-H)인 나는 잘못되거나 더 진행하지 않을 제안을 정리하기 위해 내 미응답 제안을 철회하고 싶다.

- 지위: Must Have. 출처: FR10.6, FR15.4. 선행: 자기 미응답 제안·해당 소속/역할. 관련: US15.2·US15.3.

| ID | Given | When | Then |
|---|---|---|---|
| AC10.5.1 | 현재 소속·역할 조건을 갖춘 원래 발송자 | 자기 미응답 제안을 철회함 | 구직자의 거절과 다른 철회 상태로 처리하고 복원·별도 철회 알림을 추가하지 않는다 |

| AC10.5.3 | 같은 미응답 제안에 수락·철회가 경합함 | 둘 다 처리 요청됨 | 먼저 성립한 결과를 유지하고 중복 상태 변경 없이 실제 결과를 안내한다 |

## FR11 — 계정 단위 연락 차단

### US11.1 특정 상대의 연락을 차단하고 해제한다

회원(P1·P3)인 나는 원치 않는 연락을 통제하기 위해 특정 계정을 차단하고 필요할 때 명시적으로 해제하고 싶다.

- 지위: Must Have. 출처: FR11.1~FR11.5, NFR1. 선행: 상대 회원 계정. 관련: US10.3, US12.2. DM 적용은 DM 제공 시점의 비필수 기준이다.

| ID | Given | When | Then |
|---|---|---|---|
| AC11.1.1 | 특정 상대 계정 | 차단함 | 양쪽 사이 새 제안·제공 중인 DM을 막고 같은 기업 다른 계정·일반 자료 열람으로 확대하지 않는다 |
| AC11.1.2 | 본인이 상대를 차단함 | 새 연락 또는 받은 미응답 제안 수락을 시도함 | 본인 차단의 명시 해제가 먼저 필요하며 행동만으로 해제하지 않는다. 기존 읽기·거절은 가능하다 |
| AC11.1.3 | 차단으로 전달 못 한 연락이 있음 | 차단을 해제함 | 자동 전달하지 않고 새 시도에 상대 차단·현재 권한·수신·반복 제한을 적용한다 |
| AC11.1.4 | 차단 상대가 소속·역할을 변경함 | 관계를 확인함 | 계정 차단은 유지하며 기존 전달 기록은 차단만으로 삭제되지 않는다 |
| AC11.1.5 | 차단 관계와 기존 자료 권한이 있음 | 검색·프로필·포스팅·피드·팔로우·고정 링크·허용 JD/RAG/MCP를 이용함 | 연락 차단만으로 제한하거나 관계를 해제하지 않는다. 연락처 조회 중단은 별도로 적용한다 |

## FR12 — 선택한 연락처 전달과 중단

### US12.1 수락 후 선택한 연락처를 특정 회원에게 전달한다

구직자(P1)인 나는 동의한 상대와 후속 연락을 하기 위해 수락 후 제공할 연락처 항목·값을 확인하고 싶다.

- 지위: Must Have. 출처: FR12.1, FR12.2, NFR1, NFR5. 선행: 수락한 제안·현재 공유 자격. 후속 확인: OQ11.

|---|---|---|---|
| AC12.1.1 | 제안 수락 후 공유 가능한 상태 | 이메일·전화번호 중 항목과 실제 값을 선택해 별도 동의함 | 동의한 특정 기업 회원에게만 전달 당시 값을 고정해 제공한다 |
| AC12.1.2 | 수락만 했거나 한 항목만 선택함 | 연락처를 확인함 | 로그인 정보·미선택 항목을 자동 공개하지 않고 두 항목 모두의 등록·공유를 강제하지 않는다 |
| AC12.1.3 | 동의한 수신자와 같은 기업 다른 회원/관리자 | 기존 제안 상세에서 연락처를 요청함 | 동의한 수신자만 확인하며 ‘전달 당시 연락처’임을 알 수 있다 |
| AC12.1.4 | 전달 후 원본 연락처가 수정됨 | 과거 제안 상세를 확인함 | 전달값·권한이 자동 변경되지 않는다. DM이나 별도 이메일/SMS 전송 없이 이용한다 |

### US12.2 연락처 조회를 중단하고 새 동의로 다시 공유한다

구직자(P1)인 나는 연락처 이용을 제안별로 통제하기 위해 조회를 중단하고 필요할 때 새 항목·값에 동의하고 싶다.

| ID | Given | When | Then |
|---|---|---|---|
| AC12.2.1 | 연락처 공유 중 | 어느 쪽 차단·수락 취소·수신자 해당 소속/제안 역할 상실·기업 종료·해당 탈퇴·운영 제한 발생 | 관련 새 공유와 기존 연락처 조회를 중단한다. 관리자↔채용 담당자 변경만으로 중단하지 않는다 |

| AC12.2.3 | 차단·역할·운영 제한이 풀리거나 새 제안을 수락함 | 이전 연락처를 조회함 | 자동 복원하지 않는다. 현재 자격과 실제 제공할 항목·값을 다시 확인·선택해 재동의해야 한다 |
| AC12.2.4 | 새 동의를 완료함 | 연락처를 공유함 | 새 전달 당시 값만 제공하며 과거 값·현재 원본을 자동 공개하지 않는다 |
| AC12.2.5 | 조회를 중단했으나 상대가 이미 복사했거나 서류에 연락처가 있음 | 중단 결과를 안내함 | 외부 복사값 회수·서류 자동 가림을 보장하지 않는다. 기존 제안/대화·고정본은 수정·삭제하지 않고 내부 보관은 OQ11을 따른다 |

## FR13 — 제품 MCP의 세 읽기 흐름

### US13.1 외부 도구 연결과 이용 범위를 통제한다

회원(P1·P3)인 나는 외부 도구로 자료를 안전하게 활용하기 위해 연결할 도구·범위를 확인하고 연결을 해제하고 싶다.

| AC13.1.4 | MCP 또는 CatchU AI 한도 소진 | 자료 이용을 시도함 | 해당 기능만 제한하며 허용 웹 열람은 유지한다. CatchU AI 소진만으로 허용 MCP 자료 조회까지 막지 않는다 |
| AC13.1.5 | 테스트 계정이 저장·제안 발송 등 쓰기 또는 DM/연락처/운영 기록 포괄 조회를 요청함 | MCP로 실행함 | 제공하지 않으며 시험 목적의 권한 우회도 없다. 쓰기 검사는 별도 수단을 사용한다 |

### US13.3 받은 공유본을 기업 회원의 도구에서 검토한다

기업 회원(P3)인 나는 전달받은 자료를 내 검토 도구에서 활용하기 위해 공유본을 MCP로 읽고 싶다.

## FR14 — 탈퇴와 기업 종료

회원(P1·P3)인 나는 서비스 이용을 끝내기 위해 계정 탈퇴와 관련 자료 처리를 요청하고 싶다.

| AC14.2.3 | 다른 소속 회원·개인 자료·기존 제안이 있음 | 기업이 종료됨 | 다른 개인 계정·자료는 유지하고 허용되는 제안 읽기·거절 등 정리를 제공한다. 구직자 수락 취소나 권한 이전으로 처리하지 않는다 |

| AC14.2.5 | 기업 이용 종료가 성립한 마지막 관리자 | 본인 탈퇴도 완료됨 | 그 계정의 로그인·MCP 연결·현재 자료 외부 제공·소속 권한·연락처 이용·모든 발행 링크 접근을 중단한다. 불필요해진 자료의 파기는 US14.1과 같은 FR14.1·OQ11 기준을 적용한다 |
| AC14.2.6 | 마지막 관리자의 기업 종료가 실패함 | 종료 결과를 확인함 | 종료 성공으로 표시하거나 마지막 관리자만 먼저 제거하지 않고 실패와 재시도 경로를 안내한다 |

### US14.3 정상 탈퇴 후 새 계정으로 다시 시작한다

회원(P1·P3)인 나는 다시 서비스를 이용하기 위해 같은 Google 계정으로 새롭게 가입하고 싶다.

- 지위: Must Have. 출처: FR14.6, NFR1, NFR5. 선행: 정상 탈퇴한 Google 계정. 후속 확인: OQ13.

| ID | Given | When | Then |
|---|---|---|---|
| AC14.3.1 | 정상 탈퇴 후 같은 Google 계정 | 재가입함 | 신규 기본값으로 시작하며 과거 자료·기업 소속·권한·링크를 복원하지 않는다 |
| AC14.3.2 | 기업 업무·MCP 이용을 원함 | 이용을 시작함 | 새 소속 승인·도구 연결 승인을 받아야 한다 |
| AC14.3.3 | 과거 계정에 차단·제재·한도가 있었음 | 새 계정에 통제를 적용함 | 과거 제한을 자동 연결하거나 그 목적의 식별정보를 추가 보관하지 않는다. 현재 계정 통제와 수동 운영의 한계를 구분한다 |

## FR15 — 최소 운영 조치와 정리

### US15.1 기존 연락 경로로 문제를 접수하고 회신한다

서비스 운영자(P4)인 나는 테스트 중 문제를 처리하기 위해 이용자가 접근할 수 있는 기존 연락 경로에서 접수·회신하고 싶다.

- 지위: Must Have. 출처: FR15.1, FR15.6, NFR6. 선행: 테스트 개방 준비. 후속 확인: OQ11, OQ13.

| ID | Given | When | Then |
|---|---|---|---|
| AC15.1.1 | 테스트 개방 전 | 접수 수단과 확인 담당을 확정함 | 이용자에게 실제 이용할 연락 경로를 안내하고 수동 접수·회신할 수 있다 |
| AC15.1.2 | 조치가 필요한 접수 | 처리함 | 권한 있는 담당자가 목적에 필요한 최소 자료로 확인하며 포괄 비공개 조회·자료 전체 복사를 전제하지 않는다 |
| AC15.1.3 | 접수·조치·조회에 실패함 | 결과를 안내함 | 성공으로 표시하지 않고 실제 상태와 연락 경로를 안내한다. 별도 고객센터·신고함·관리자 화면을 필수로 요구하지 않는다 |

### US15.2 확인된 계정의 제안·연락처 이용을 제한한다

서비스 운영자(P4)인 나는 문제가 확인된 발송자의 연락을 제한하기 위해 현재 계정에 최소 이용 조치를 적용하고 싶다.

- 지위: Must Have. 출처: FR15.2, FR15.4, FR15.5, FR15.6, NFR1, NFR6. 선행: 운영 권한·확인된 대상 계정. 후속 확인: OQ11, OQ13.

| ID | Given | When | Then |
|---|---|---|---|
| AC15.2.1 | 권한 있는 운영자와 확인된 발송 계정 | 채용 제안·연락처 이용 제한을 적용함 | 새 발송, 그 계정이 보낸 기존 제안의 새 수락·관련 연락처 새 공유/조회를 제한한다 |
| AC15.2.2 | 제한 계정이 소속·역할을 바꿈 | 제한 상태를 확인함 | 계정 조치는 유지하고 기존 수락을 자동 취소하거나 개인 자료·공유 링크·일반 검색 노출을 포괄 차단하지 않는다 |
| AC15.2.3 | 제한 중 기존 기록을 정리하려 함 | 읽기·거절·수락 취소·연락처 중단·본인 미응답 철회·소속 정리·탈퇴를 함 | 기존 조건에서 허용한다. 철회 예외는 운영 제한으로 정리가 막힌 경우만이며 소속/역할 상실을 우회하지 않는다 |
| AC15.2.4 | 운영자가 명시 해제함 | 다시 이용함 | 현재 자격·다른 제한을 확인하고 연락처는 재동의해야 한다. 취소·철회·탈퇴 상태를 되살리지 않는다 |
| AC15.2.5 | 권한 없는 요청 또는 조치 실패 | 처리 결과를 기록함 | 권한 없는 조치를 허용하지 않고 실패를 성공으로 기록하지 않는다. 권한 확인과 사유·대상·결과의 최소 기록을 남긴다 |

서비스 운영자(P4)인 나는 기업 단위의 문제에 대응하기 위해 기업 권한을 중단하고 해제하고 싶다.

- 지위: Must Have. 출처: FR15.3~FR15.6, NFR1, NFR6. 선행: 운영 권한·대상 기업. 관련: US14.2. 후속 확인: OQ11, OQ13.

| ID | Given | When | Then |
|---|---|---|---|
| AC15.3.1 | 활동 중인 기업 | 운영자가 일시 중단함 | 새 소속 신청/승인·권한 변경·기업 검색/제안·소속 기반 JD/RAG/MCP·기존 제안 새 수락·연락처 이용을 제한한다 |
| AC15.3.2 | 기업이 일시 중단됨 | 기록·개인 자료·독립 링크를 확인함 | 소속 기록·개인 계정을 삭제하거나 독립 공개 링크를 중단하지 않는다 |

| AC15.3.4 | 운영자가 제한을 명시 해제함 | 이용을 재개함 | 현재 조건을 다시 검사하고 연락처 자동 복원·종료 기업 재개를 하지 않는다. 자동 기한 해제도 추가하지 않는다 |
| AC15.3.5 | 운영 권한이 없거나 조치에 실패함 | 중단·해제를 요청함 | 무권한 조치·거짓 성공을 막고 사유·대상·결과를 최소 기록한다. 구체 보관·조회 범위는 OQ11을 따른다 |

## FR16 — 알림과 필수 시작 안내

작성 회원(P1)인 나는 분석이 끝난 뒤 결과를 놓치지 않기 위해 완료·실패 알림에서 해당 결과로 이동하고 싶다.

## FR17 — 포함·마감 비필수의 핵심 이야기

이 절은 모두 Should Have다. 실제 제공 시점에 권한·실패·안내·운영·검사를 함께 준비한다. 세부 예외·보관·수치는 OQ10~12 등 지정된 조건으로 확인하며 아래 핵심 기준을 지우거나 미채택 후보와 합치지 않는다.

### US17.1 개인 계정을 팔로우한다

회원(P1·P3)인 나는 관심 있는 사람의 활동을 보기 위해 팔로우하고 해제하고 싶다.

- 지위: Should Have. 출처: FR17.1. 선행: 개인 계정. 관련: US11.1. 후속 확인: OQ10.

| ID | Given | When | Then |
|---|---|---|---|
| AC17.1.1 | 상대 회원 | 팔로우·해제함 | 상대 승인 없이 가능하고 서로 팔로우한 동안만 맞팔이다 |
| AC17.1.2 | 기업 소속 또는 차단 관계 | 관계를 확인함 | 개인 계정으로 이용하며 연락 차단만으로 팔로우/맞팔을 해제하지 않는다 |

### US17.2 글의 공개 범위를 정해 게시한다

회원(P1·P3)인 나는 내 소식을 원하는 대상에게 알리기 위해 텍스트 글을 작성하고 공개 범위를 바꾸고 싶다.

- 지위: Should Have. 출처: FR17.2. 선행: 개인 계정·현재 팔로우 관계. 후속 확인: OQ10.

| ID | Given | When | Then |
|---|---|---|---|
| AC17.2.1 | 본인 글 | 작성·수정·삭제 또는 공개 범위를 변경함 | 글별 전체/맞팔을 선택하며 전체 기본값을 게시 전에 확인·변경할 수 있다 |
| AC17.2.2 | 공개 범위나 관계가 바뀜 | 글을 열람함 | 현재 관계·공개 조건을 적용하고 기업 명의 공동 운영·미채택 첨부/반응 기능을 추가하지 않는다 |

### US17.3 팔로우 관계에 맞는 피드를 읽는다

회원(P1·P3)인 나는 관심 있는 사람의 글을 보기 위해 홈 피드를 읽고 싶다.

- 지위: Should Have. 출처: FR17.3, NFR7. 선행: US17.1·US17.2의 관계·글. 후속 확인: OQ10.

| ID | Given | When | Then |
|---|---|---|---|
| AC17.3.1 | 팔로우한 사람이 있음 | 홈을 읽음 | 현재 읽기 가능한 팔로우 기반 글을 제공한다 |
| AC17.3.2 | 팔로우가 없음 | 홈을 읽음 | 팔로우가 많은 사람의 공개 글을 제시한다 |
| AC17.3.3 | 팔로우는 있지만 읽을 글이 없거나 조회에 실패함 | 상태를 확인함 | 빈 상태와 실패를 구분하고 빈 상태에 미팔로우 글을 자동 혼합하지 않는다 |

### US17.4 제공 중인 대상의 문제를 신고한다

회원(P1·P3)인 나는 서비스 안의 문제를 알리기 위해 대상과 이유를 신고하고 제출 성공/실패를 확인하고 싶다.

- 지위: Should Have. 출처: FR17.4, NFR5. 선행: 로그인 회원이 현재 열람할 수 있는 실제 제공 대상. 접수·검토 자료 조회는 운영자 권한으로 구분한다. 후속 확인: OQ10, OQ11.

| ID | Given | When | Then |
|---|---|---|---|
| AC17.4.1 | 로그인 회원과 현재 열람 가능한 신고 대상 | 대상·이유를 제출함 | 신고자에게 제출 성공/실패를 구분해 알린다. 개발팀 운영자가 접수하며 운영자만 목적상 필요한 신고 당시 내용/상태·관련 이력을 확인한다. 신고자용 처리 결과 조회를 추가하지 않는다 |
| AC17.4.2 | 신고가 접수됨 | 처리 자료를 준비함 | 신고자 자동 공개·자동 제재·비회원/첨부 신고·연결 자료 전체 복사/포괄 조회·AI 판정을 추가하지 않는다 |
| AC17.4.3 | Catch 내용 불일치 또는 아직 제공하지 않는 대상 기능 | 처리 경로를 정함 | Catch 품질 경로와 구분하고 신고를 위해 비필수 대상 기능부터 구현해야 한다고 판단하지 않는다 |

### US17.5 기존 주장을 독립 복제한다

작성 회원(P1)인 나는 다른 목적의 자료를 빠르게 준비하기 위해 기존 주장 구성을 복제하고 싶다.

- 지위: Should Have. 출처: FR17.5. 선행: 본인 주장. 관련: US2.2, US4.3. 후속 확인: OQ10.

| ID | Given | When | Then |
|---|---|---|---|
| AC17.5.1 | 본인 주장 | 복제함 | 제목·본문·Catch 선택을 독립 복사하고 Catch 원본은 공동 이용하며 프로필 대표 소개는 복제하지 않는다 |

| AC19.1.6 | 헬스체크·모의/로컬 성공 또는 MCP 한 흐름만 성공함 | 완료 범위를 보고함 | 전체 통합·MCP 세 흐름·사용자 효과 검증으로 대체하지 않는다. 직접 사용/시연 참관·미체험 흐름과 미검증 효과를 나눠 보고한다 |

## INVEST 점검과 추정의 한계

- Independent: 각 스토리의 초기 상태를 준비해 독립 판정할 수 있다. 자료 생산·소속·권한처럼 공통 선행 상태는 명시했고 실제 연결은 팀의 계약 작업으로 조율한다.
- Negotiable: 화면·API·DB·기술 구조는 후속 설계 대상이다. 승인된 정책을 협의 가능하다는 이유로 임의 변경하지 않는다.
- Valuable: 제목과 본문에 행위자·사용자 결과·가치를 명시했다. 운영·제출 이야기는 승인된 FR15·19의 이해관계자 결과를 다룬다.
- Estimable: 역할·범위·기대 결과를 제공하지만 팀 추정은 아직 없다. OQ가 붙은 스토리는 필요한 값·근거 확보 후 추정하며 ‘착수 준비 완료’로 표시하지 않는다.
- Small: 독립 결과로 분해했지만 US13.1의 연결/한도, US14.2의 종료/탈퇴, US16.2의 역할별 안내, US19.1의 통합 검증은 연결 범위가 넓다. 팀 작업량 확인 때 같은 스토리의 검사 사례/작업으로 나누거나 결과가 달라지면 하위 스토리로 분해한다. 현재 스프린트 내 완료를 보장하지 않는다.
- Testable: 고유 AC와 초기 상태·행동·관찰 결과를 쓴다. 비필수는 합의한 핵심 수준이고 미정 상세까지 검사 가능하다고 주장하지 않는다. 숫자·지원 목록·보관/외부 처리 조건이 미정이면 그 관련 검사는 값 확정 전 미준비다.

## 범위 밖·후보·보류 경계

범위 밖/이번 미제공 항목을 스토리로 만들지 않는다. Google 외 로그인·MCP 쓰기·서류 다운로드 설정·OCR/외부 URL 자동 수집·공유 링크 제안·Catch 사용자 원본 삭제·기업/구직자 인증·내부 지원 접수/전형 관리는 승인된 경계를 유지한다.

수신자 프리셋별 수동 참고 조절, 소셜 반응/첨부, 본인 카드 복합 필터/정렬/일괄 처리 등은 후보다. 후보 메모/질의 기업 공유·공고-JD 연결·diff 전량 복구·반복 표현 튜닝·CD·구독/가격·기타 알림은 미결이다. 링크 열람 기록과 그 기록의 알림/MCP 연계, 서비스 내 3층 탐색은 보류다. MCP 권한/요청 한도 검사에 필요한 기록 전체가 보류된 것은 아니다. 내부 선택 공유의 재도입 미정·조건별 운영 경고의 기존 계획/재검토 지위도 유지한다. 세부 목록은 requirements.md의 범위 밖 표를 따른다.
