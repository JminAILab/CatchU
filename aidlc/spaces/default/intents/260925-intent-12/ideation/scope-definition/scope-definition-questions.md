# 12월 범위 요구사항 — 범위 정의 질문

## 근거와 진행 방식

- 상류 산출물: [승인된 의도 설명](../intent-capture/intent-statement.md). 2026-09-25 사용자의 `Approve`로 의도 정리가 승인됐다.
- 제품 범위 입력: `docs/ai-dlc-input-december/CatchU_12월_범위_보완.md` 하나. 공식 문서 입력 읽기로 확인했으며 원본을 수정하지 않는다. 문서 안의 과거 자료 링크는 지위·출처 설명으로 보존하며 별도 입력으로 확장하지 않는다.
- 답변 방식: 기존에 선택한 **Guide me**를 이어간다. 한국어로 한 번에 1~2개씩 안내하며, 기존 결정의 요약 확인과 새로운 미결 판단을 구분한다.
- 질문은 범위 경계와 일정 해석에 집중한다. 역할별 상세 동작·수용 기준·미정 기능의 포함 여부와 순서는 요구사항 분석에서 질문한다. 범위 정의만으로 구현 계획·담당·납기 실현 가능성을 확정하지 않는다.

## 이미 정해진 진행 조건

- 활성 intent는 `260925-intent-12`, 작업 브랜치는 `docs/december-requirements`이며 새 intent를 만들지 않는다.
- 의도 정리 → 범위 정의 → 승인·인계 → 요구사항 분석 승인까지 진행한다. 마지막 승인 직후 공식 `park`로 일시정지하며 전체 intent를 완료 처리하지 않는다. 도메인 설계·API 계약·ERD·구현은 이번 수행 범위가 아니다.
- 이번 문서 작업은 입력의 모든 항목에 요구사항 또는 처리 결정을 연결하고, 포함 요구사항에 수용 기준을 두며, 남는 미결에 이유와 후속 확인 조건을 기록해 승인받는 것을 완료 기준으로 삼는다(의도 정리 Q3).
- 기존 품질 목표의 기록상 지위를 유지한다. 새 목표값은 근거·측정 가능성을 확인해 제안하고 사용자 확인을 받는다. 개발·측정이 필요한 수치는 이유·후속 조건을 미결로 남긴다(의도 정리 Q4).
- 팀장인 사용자가 범위·우선순위를 최종 결정하고 단계 산출물을 승인한다. 팀원 검토는 이후 공유 시 진행하며, 이번 로컬 단계 승인 전 필수 조건이 아니다. 미실시 검토·합의는 완료로 기록하지 않는다(의도 정리 Q5).
- 별도 보고 주기 없이 기존 팀의 회의·공유·PR 검토 규칙을 유지한다(의도 정리 Q6).
- 입력과 기존 두 intent의 완료·승인 기록을 보존한다. 관련 변경만 최종 검증 후 로컬 커밋하고 푸시·PR·원격 이슈 등록·Claude 설치는 하지 않는다.

## 제품 MCP의 마감 필수 선행 연결

Q10의 세 필수 이용 흐름과 선행 기능을 기능 수준에서 연결한다. 인증 방식·구체 제공 항목·쓰기 범위·채널별 세부 동작은 요구사항 분석에서 확정한다. 아래는 구현 구조나 검증 완료 기록이 아니며, 요구사항 분석에서 기능별 요구사항·수용 기준에 대응시켜 누락 여부를 점검한다.

| 필수 이용 흐름 | 연결할 선행 기능·조건 | 누적 목록 연결 | 남은 확인 |
|---|---|---|---|
| 구직자가 자기 LLM·도구에서 허용된 CatchU 데이터를 이용 | 접근 주체 식별과 본인 자료의 허용 범위 판정, 해당 범위의 CatchU 데이터 제공 | D-M08·D-M09 | 인증 방식과 상세 제공 항목을 확정한다. 구직자 LLM의 정보를 CatchU로 가져오는 흐름으로 바꾸지 않는다. |
| 기업이 받은 링크의 허용 자료를 이용 | 기업 로그인, 기업 등록·소속·직책 권한, 받은 링크의 접근 조건에 따른 자료 범위 판정 | D-M06·D-M08·D-M09 | 화면·링크·MCP의 일관된 권한 판정과 비밀번호·만료·중단·공개 상태 변화의 반영을 구체화한다. |
| 기업이 검색 참여에 동의한 구직자를 탐색 | 기업 로그인·검색 권한, 구직자의 검색 참여 동의, 동의한 구직자를 대상으로 하는 검색과 결과 열람 권한 판정 | D-M06·D-M08·D-M09 | 검색 조건·제공 항목·동의 해제 반영을 구체화한다. 입력의 기업 로그인·검색 참여 동의·순위 없음 조건을 유지한다. |

**범위 유지:** 위 선행 기능과 세 이용 흐름을 마감 필수 목표로 함께 관리한다. 세부 미결을 기능 제외로 해석하지 않으며, 일정 충돌이 확인되면 조정안을 제시하고 사용자 결정을 받는다. MCP 기록의 보류는 링크 열람 기록과 연계된 부분에 한정한다(Q1·Q10).
