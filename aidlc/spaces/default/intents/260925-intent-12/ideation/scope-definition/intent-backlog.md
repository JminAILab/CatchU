# 12월 범위 요구사항 — 우선순위 백로그

작성일: 2026-09-25. 활성 intent: 260925-intent-12.
[범위 문서](scope-document.md)와 [Q1~Q20·통합 요약 확인](scope-definition-questions.md)을 근거로 한다. 상류 목적·완료 기준은 [intent-statement](../intent-capture/intent-statement.md)에서 유지한다.

## 백로그의 용도와 우선순위 해석

아래 BG 식별자는 요구사항 분석으로 넘길 후보 작업 묶음(proto-Units)이다. 최종 Unit, 도메인 경계, 서비스/API/ERD 설계, 담당 배정이나 개발 일정이 아니다. D-M/D-N/D-C는 범위 문서의 목표 식별자이고, O-S는 미결 식별자다. 신규 FR/NFR 번호는 여기서 만들지 않는다.

확인된 마감 경계를 MoSCoW로 표시하되 사용자 답변보다 우선순위를 더 강하게 해석하지 않는다.

| 표시 | 이번 백로그에서의 의미 | 근거 |
|---|---|---|
| Must | 11월 30일까지 완성할 필수 목표 또는 12월 10일 공식 제출 결과 | Q3~Q19의 해당 필수 결정 |
| S/C 미정 | 포함하되 마감 필수 아님. Should와 Could의 세부 구분·순서는 아직 정하지 않음 | Q1과 각 마감 비필수 답변 |
| Could | 운영 기능에만 적용하는 기존 “후순위이지만 가능하면 포함” | 입력 §2, Q1·Q12 |
| Won't | 명시된 범위 밖 항목. 아래 보류·재검토·미결과 구분 | 입력 §3, Q1·Q13·Q14 |
| 보류·미결 | 기존 지위를 보존하며 요구사항 분석에서 확인. MoSCoW 범주로 자동 전환하지 않음 | Q1 |

대표 구성(BG01)은 1순위다. 운영 기능(BG12)은 후순위다. 그 밖의 묶음 사이의 구체 순서는 요구사항 분석에서 정한다. 표의 행 번호는 개발 순서가 아니다. 마감 비필수 항목을 모두 Could로 내리거나 범위 밖으로 해석하지 않는다.

12월 가용 인력·개발량이 미확정이므로 WSJF/RICE 점수, 인월·소요일·작업량 비율을 계산하지 않는다. 일반적인 우선순위 방법의 수치를 새 품질 목표나 일정 수용량으로 사용하지 않는다. 일정 충돌이 확인되면 근거와 조정안을 제시하고 사용자 결정을 받는다.

## 범위 밖·보류 항목의 처리

- Won't: MFA 등 계정 설정·구직자 신원 인증, 기업 인증의 기존 범위 밖 지위, 서비스 안 지원 접수·전형 관리, 마일리지 현금 구매·현금/재화 교환. 중단·만료 링크 복구는 별도 기능 없이 새 발행으로 처리한다.
- 보류: 링크 열람 기록과 연계 알림·MCP 기록, 카드 탐색 3층. 일반 GitHub 근거 링크와 다른 MCP 기록 전체를 보류하지 않는다.
- 재검토·시점 미정: 다운로드 허용 여부와 탈퇴 시점은 별도로 남긴다.
- 내부 선택 공유·조건별 운영 경고, 여러 대표 프리셋 등 기존 후보/계획은 “범위 밖”으로 합치지 않고 O-S 확인 목록에 유지한다.

## 일정 검토와 조정 절차

- 11월 30일 완료는 코드 작성뿐 아니라 NCP 통합 배포·핵심 흐름의 외부 접속/동작 확인을 포함한다. 12월 1~9일의 검증 기간으로 이 기준을 자동 미루지 않는다.
- 현재 전체 Must 목표의 일정 내 구현 가능성은 미검증이다. 10월 담당표의 4명을 12월 가용량으로 사용하지 않는다. 12월 인원·기간·시간·개발량은 미정이며 사용자 제공 참고 정보를 팀원 합의로 바꾸지 않는다.
- 10월 결과·선행 기능과 실제 가용량을 확보한 뒤, 충돌하는 목표·의존 조건·부족 근거를 정리한다. 필수 목표 간 우선순위와 범위 조정 대안을 사용자에게 제시하고 결정 후 질문·답변과 누적 목록에 반영한다.
- 마일리지 없이 필수 기능을 제공할 조건, 검색에 필요한 프로필 항목, 연락처 공개 조건은 요구사항 분석에서 사용자 확인이 필요한 관계다. 이를 숨긴 채 무료·무제한·모든 연락처 공개나 전체 프로필 필수를 확정하지 않는다.
- 새 품질 목표값·한도는 근거와 측정 가능성을 확인하고 사용자 승인을 받는다. 실제 측정이 필요한 수치는 미결 이유와 후속 조건을 남긴다.

범위 문서의 가치 흐름과 이 백로그를 바탕으로 승인·인계 후 요구사항 분석을 진행한다. 요구사항 분석에서 입력 전체 추적, 기능별 수용 기준, 상세 결정·미결 사유와 후속 조건을 검토받는다. 지금은 실제 개발 작업을 배정하거나 도메인·API·ERD를 작성하지 않는다.

단계별 승인 주체는 팀장인 사용자다. 요구사항 분석 승인 직후 공식 park로 중단하고, 최종 변경 검증 후 관련 기록만 로컬 커밋한다. 현재 문서 작성이나 요약 확인은 제품 구현·배포·팀원 검토·전체 intent 완료 기록을 대체하지 않는다.
