# 12월 범위 요구사항 — 범위 문서

작성일: 2026-09-25. 활성 intent: 260925-intent-12. 범위 분류: feature.
Q1~Q20의 통합 요약을 사용자가 Looks correct로 확인한 뒤 작성했다. 이는 산출물의 단계 승인과 구분하며, 단계 승인 여부는 엔진 상태·감사 기록을 따른다.

## 목적과 근거

12월(MVP 이후) 기능을 포함·마감 필수·후순위·보류·제외·미결로 구분하고, 누락 없이 요구사항 분석에 넘긴다. 이번 작업은 문서 정리와 승인까지이며 제품 개발 완료를 선언하지 않는다.

|---|---|
| [승인된 의도 설명](../intent-capture/intent-statement.md) | intent-statement: 목적, 역할, 입력 전체 추적·수용 기준·미결 관리, 품질 목표와 승인 주체 |
| [범위 정의 질문·답변](scope-definition-questions.md) | Q1~Q20과 통합 요약 확인. 새 범위·마감 결정의 근거 |

입력의 과거 요구사항 번호는 출처 설명이며 이번 intent의 신규 요구사항 ID가 아니다. 아래 D-M/D-N/D-C와 O-S는 범위 추적용 식별자다. 제품 요구사항·수용 기준과의 연결은 요구사항 분석에서 작성한다. 과거 두 intent의 승인 원본을 소급 수정하지 않는다.

## 이번 문서 작업의 경계

- 의도 정리 → 범위 정의 → 승인·인계 → 요구사항 분석 승인까지 수행한다. 요구사항 분석 승인을 기록한 직후 다음 단계 본문을 시작하지 않고 공식 park로 일시정지한다. intent 전체를 complete로 처리하지 않는다.
- 입력의 모든 항목에 요구사항 또는 처리 결정을 연결하고, 포함 요구사항에 확인 가능한 수용 기준을 두며, 남는 미결에는 이유·후속 확인 조건을 남겨 승인받는 것이 이번 문서 작업의 완료 기준이다.
- 도메인 설계·API 계약·ERD·구현은 수행하지 않는다. 아래 기능 흐름과 후보 작업 묶음은 구현 구조·담당 배정·개발 착수 승인이 아니다.
- 팀장인 사용자가 범위·우선순위를 최종 결정하고 각 단계 산출물을 승인한다. 팀원 검토는 이후 공유 시 진행하며 이번 로컬 단계 승인의 선행 조건이 아니다. 받지 않은 검토·합의를 완료로 기록하지 않는다.
- 별도 보고 주기를 추가하지 않고 기존 회의·공유·PR 검토 규칙을 유지한다. docs/december-requirements에서 한국어로 기록하며, 마지막에 검증 후 관련 변경만 로컬 커밋한다. 푸시·PR·원격 이슈 등록·Claude 설치·버전 변경은 하지 않는다.

## 포함 범위 — 기존 후순위 운영 기능

D-C01은 입력 §2와 Q1·Q12의 “후순위이지만 가능하면 포함” 지위를 유지한다.

- 품질 신호, 오류·권한 위반 징후·AI 호출량·추정 비용 등 운영 기록 조회, 신규 분석·AI 호출 전체 중단·재개.
- 지표는 확인 후 행동할 수 있는 항목으로 제한한다. 분석 요청 수·성공/부분 실패/실패 비율·실패 사유·처리 시간·대기 작업 수, LLM 호출 수·토큰·추정 비용과 예산 상한·한도 도달, 불일치 건수/유형·근거 링크 자동 검사 실패를 입력의 세 묶음으로 유지한다.
- 가입부터 열람까지의 사용 흐름 지표는 선택이다. 10월 분석 상태·실행 기록을 활용하며 별도 수집 플랫폼을 필수 조건으로 추가하지 않는다.
- 인젝션·시스템 이상에 대응하는 별도 수동 화면은 두지 않는 입력의 경계를 유지한다. 내부 선택 공유·조건별 운영 경고는 O-S17의 별도 미결이다.

신고 처리·제재와 기업 등록 관리(D-M11·D-M12)는 위 후순위 운영 조회 기능과 다른 필수 목표다.

## 10월 결과와 기존 품질 목표를 유지하는 원칙

- 입력 §4의 권한 판정 재사용은 화면·링크·MCP의 규칙 일관성이지 API 한 곳이라는 물리 배치 결정이 아니다.
- 10월 공개/숨김과 기업·직접 링크 규칙을 유지하고 구직자 간 전체/맞팔의 적용 대상을 구분한다. 필드 수나 저장 구조를 확정하지 않는다.
- 10월 분석 식별자·상태·완료/실패 기록을 후속 알림에 연결하되, 입력만으로 10월 알림 발송·이벤트 시스템이 구현됐다고 쓰지 않는다.
- 회사 프로필 재사용 방향과 같은 데이터 구조 강제를 구분한다. 계정 관계·편집 권한의 상세와 설계는 이후 절차의 대상이다.
- 10월 링크 무료 조건을 12월 전체의 무료·무제한 조건으로 확대하지 않는다. 로그인 홈의 피드와 헤더 분석 알림 방향을 유지한다.
- 기존 품질 목표는 목표·미결·검증 결과라는 기록상 지위를 유지한다. 새 수치는 근거와 측정 가능성을 확인해 사용자 승인을 받고, 개발·측정이 선행되어야 하면 이유·후속 조건을 남긴다.

## 인계와 확인 상태

[우선순위 백로그](intent-backlog.md)는 이 범위를 기능별 후보 작업 묶음으로 연결한다. 요구사항 분석에서는 모든 입력 항목에 요구사항 또는 처리 결정을 연결하고, 포함 요구사항별 수용 기준과 미결 이유·후속 확인 조건을 제시한다.

Q1~Q20과 통합 요약의 사용자 확인은 완료됐다. 가용 인력·개발량 검증, 팀원 검토, 구현·배포·성능 측정은 수행 완료로 기록하지 않는다. 범위 정의의 최종 단계 승인과 요구사항 분석 승인은 별도 기록을 따른다.
