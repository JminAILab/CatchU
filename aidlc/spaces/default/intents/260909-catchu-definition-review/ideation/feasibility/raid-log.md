# CatchU 위험·가정·문제·의존성 기록

## 사용 기준

현재 답변으로 식별한 위험과 미확인 사실을 기록한다. 아래 대응은 범위·요구사항 검토에서 채택 여부를 논의할 **평가상 권고**이며, 구현 작업의 승인·배정·완료 기록이 아니다. 개인별 담당자는 아직 미정이다. 범위·우선순위 결정은 4인 팀의 합의 방식에 따르되 구체적 실행 책임은 별도로 정한다. [ST] [Q1]

위험의 발생 확률·일수·비용 손실을 산정할 근거는 없다. 따라서 수치 점수나 사람별 개발량을 만들지 않고, 발생 조건과 영향 및 필요한 판단 시점을 기록한다. 현재 존재하는 정보 공백은 문제(I), 향후 불리한 결과의 가능성은 위험(R), 순서상 필요한 입력은 의존성(D)으로 구분한다.

## Assumptions — 가정·기대의 경계

아래 항목은 팀이 밝힌 구상·기대 또는 아직 검증되지 않은 가능성이다. 새로운 가정을 확정하거나 미확인 사항에 기본값을 넣은 목록이 아니다.

| ID | 구상·기대 또는 가능성 | 근거 수준과 사용 한계 | 후속 확인 |
|---|---|---|---|
| A01 | 대한민국을 초기 제공 지역으로 우선 고려한다. | 팀의 현재 구상이다. 확정 제약·국내 서버 의무·보관/전송 정책이 아니며 전부 미정으로 지우지도 않는다. [Q6] [지역 수정] | FE-OQ6 |
| A02 | 중간 발표에서 핵심 링크 전달 흐름을 직접 사용할 수 있는 MVP 수준을 기대한다. | 팀의 잠정 기대다. 공식 발표 기준·세부 기능량·그 시점의 완성 가능성은 확정되지 않았다. [Q7] [Q8] | FE-OQ1·2 |
| A03 | 외부 PoC의 일부 코드·규칙·자료를 재사용할 수 있을 가능성이 있다. | 자산 존재와 과거 결과가 근거다. 실제 재사용 적합성·절감량은 미검증이며 LLM·RAG 성능 검증을 뜻하지 않는다. [Q3] [P] | FE-OQ3 |
| A04 | 기술·배포·비동기 처리 후보를 비교할 수 있다. | Q4의 선호·검토안이다. 필수 조건·조합 선택이나 계정 확보로 해석하지 않는다. [Q4] | FE-OQ4 |

## Issues — 현재 확인된 정보 공백

아래는 관찰된 제품 장애가 아니라 아직 결정·확인되지 않은 상태다. 위험의 현실화나 팀의 의무 불이행으로 해석하지 않는다.

| ID | 현재 상태 | 다음에 필요한 확인 | 연결·근거 |
|---|---|---|---|
| I01 | 팀원 경험은 알려졌으나 역할·실제 가용량·학습과 협업 지원 시간은 미확인이다. | 개발량 산정·책임 배정 전에 팀과 확인한다. | FE-OQ2; [Q1] |
| I02 | 공개 범위와 10월·12월 세부 기능 수준·검색/소싱 최소 완성도가 미결이다. | 범위 정의에서 공개 정책과 최소 흐름을 우선 논의한다. | FE-OQ1; [IC] [Q8] |
| I03 | PoC의 최신 전체 실행·원격 변경 반영·현 기획 적합성과 서비스 재사용성은 미검증이다. | 확인할 재사용 후보와 검증 범위를 정한다. 과거 기록과 사용자 보고의 범위 차이는 평가 문서에 유지한다. | FE-OQ3; [Q3] [P] |
| I04 | 초기 이용량, 서비스용 API, AWS 계정·지원·크레딧·제한·필수 조건이 미확인이다. | 비용·수용량 및 기술 선택에 필요한 입력을 확보한다. | FE-OQ4·5; [Q4] [Q5] |
| I05 | 대한민국 우선 구상은 있으나 확정 제약은 아니다. 외부 AI 처리·보관 조건과 실제 데이터 흐름은 미확인이다. | 관련 정책 확정 전에 실제 처리 관계·계약 조건과 적용 요건을 확인한다. | FE-OQ6; [Q6] [지역 수정] |
| I06 | 조사 참여자·문항·판정 기준 및 내부 기능·자료 품질의 구체적 확인 기준이 미정이다. | 요구사항 검토에서 구체화하고 참여 가능 대상에 맞춰 검증 주장의 범위를 유지한다. | FE-OQ7; [IC IC-OQ3] |

## Dependencies — 의존성

| ID | 필요한 선행 입력 | 이를 기다려야 하는 후속 판단 | 결정·실행 주체 |
|---|---|---|---|
| D01 | 전역 숨김과 링크별 자산 선택의 관계 | 열람 권한·요약·질의응답·검색 노출의 세부 기준 | 공개 정책은 팀 합의, 후속 담당 미정 |
| D02 | 10월 최소 흐름·12월 기능 수준 및 팀 역할·가용량 | 일정·준비량의 비교와 후속 설계 범위 | 팀 합의, 실행 책임 미정 |
| D03 | PoC 재사용 후보의 현 기획 적합성·현재 동작·근거 범위 | 재사용으로 줄일 수 있는 개발·검증량 판단 | 확인 담당 미정, 결과는 팀 검토 |
| D04 | 초기 이용량·분석량·API·계정·지원 조건 | 운영 수용량·월 합산 비용·기술 구성 선택 | 확인 담당 미정, 예산·선택은 팀 검토 |
| D05 | 데이터 항목·목적·공개 정책·외부 처리 관계·계약·보관 조건 | 서버 위치·외부 처리·보관·전송 정책 및 적용 요건 판단 | 담당 미정, 팀이 후속 검토 책임 결정 |
| D06 | 조사 참여 가능성·직접 사용/시연 구분 및 내부 품질 기준 | 요구사항 확인 기준과 서비스 효과에 관한 주장 | 팀 합의, 조사·검증 담당 미정 |

D01~D06은 관련 판단 전에 필요한 입력을 표시하며, 모두 지금 답해야 하거나 이후 모든 작업을 일괄 중단한다는 뜻은 아니다. 공개 정책과 최소 기능 수준을 우선 논의하면서 독립적인 자원·재사용·검증 정보 확인은 진행할 수 있다. 구현·배포는 이번 작업 범위에 들어 있지 않다. [IC] [평가]
