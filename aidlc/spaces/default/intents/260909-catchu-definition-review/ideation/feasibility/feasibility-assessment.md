# CatchU 실현 가능성 평가

## 평가 의견

**범위 정의를 진행할 근거는 확보됐으며, 서비스 완성 가능성의 정량 판단은 유보한다.** GitHub 분석 PoC와 팀원 1·2의 웹 개발 경험은 검토의 출발점이다. 다만 현재 PoC의 서비스 재사용성, 팀원별 역할·실제 가용량, 운영 규모·서비스용 API·계정 조건이 확인되지 않아 10월 초 기대 수준이나 12월 중순 제품 범위를 일정·예산 안에서 달성한다고 단정할 수 없다. 이는 확인된 답변에 따른 평가 의견이며, 단계 승인이나 구현 착수 결정은 아니다. [IC] [Q1] [Q3] [Q4] [Q5]

이 단계의 권고는 **다음 범위 정의에서 링크 전달의 최소 흐름과 공개 범위를 먼저 구체화하고, 이를 기준으로 준비량과 후속 설계 과제를 판단하는 것**이다. 검색·소싱은 제품 범위에 유지하며, 10월 발표 기대와 12월 서비스 범위를 구분해 완성도를 논의한다. 상세 기술 구성은 이 평가에서 선택하지 않는다. [IC] [Q7] [Q8]

PoC 위치는 `/Users/ljm/Desktop/project/teampj_poc`이다. 본인 소유 공개 저장소 3개의 수집·가명화·마스킹·사건 묶기·후보 선정·근거 정리를 실험했다는 팀 답변을 기록했다. 팀 답변에 따르면 LLM 추론을 사용하지 않았고 사람이 서사형·스냅샷형 카드 각 1장을 작성했다. 이번 제한된 문서 확인에서 후자의 작성 방식·카드 수를 별도로 검증하지 않았다. [Q3]

이 확인은 파일·과거 실험 기록의 존재 확인에 한정한다. 현재 저장소의 제품 코드 부재 확인과 외부 PoC의 존재는 양립하며, 공식 Reverse Engineering 단계 완료나 서비스 재사용 승인으로 취급하지 않는다. [WS] [Q3] [P]

## 외부 연계와 운영 환경 검토

- GitHub 데이터 활용은 유지한다. 공식 문서에는 인증 방식에 따른 기본 호출 제한과 추가 제한이 설명돼 있다. 따라서 PoC의 세 저장소 결과만으로 사용자 증가·재분석을 수용할 수 있다고 판단할 수 없다. 필요한 분석량과 허용 가능한 대기·실패 처리를 후속 요구사항에서 확인해야 한다. 이번 평가에서 인증 방식이나 작업 처리 구성을 선택하지 않는다. [Q3] [Q5] [GitHub 호출 제한](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)
- API 사용 지침은 제한 초과 시 호출을 멈추고 대기하며 반복 실패를 무시하지 않도록 안내한다. 후속 검토에서는 분석 중단·지연 시 사용자에게 무엇을 제공할지와 정상 복구 여부를 확인할 기준이 필요하다. 구체적인 큐·재시도 설정은 아직 설계하지 않는다. [GitHub API 사용 지침](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)
- 현재 사용 중인 개발 보조 도구와 별개로, 서비스용 API와 AWS 계정·지원·크레딧·제한의 확보 상태는 추가 확인 대상이다. 질문 Q4의 기술·배포·보관·비동기 처리 후보는 선호·검토안이며 필수 기술이 아니다. 관리해야 할 도구·서비스의 수가 늘어날 때 학습·운영 부담이 어떻게 달라지는지도 선택 전에 비교할 항목이다. [Q4]
- 기존 ATS와 역할을 나눈다. 직접 연동은 확정된 기능이 아니므로 이미 확보된 외부 연계나 당연한 선행조건으로 계산하지 않는다. [IC] [D2]

## 데이터와 제공 지역

**대한민국을 우선 고려하는 서비스 구상이 있으나 확정 제약은 아니다.** 초기 이용량과 외부 AI 처리·보관 조건은 미확인이다. 이 구상만으로 국내 서버 사용, 특정 리전, 보관 기간 또는 데이터 전송 허용·금지 정책을 정하지 않는다. [Q5] [Q6]

기존 데이터 기준은 본인이 분석에 동의한 공개 저장소다. 프로필·자기소개서·포트폴리오·JD와 공동 기여자 정보가 어떤 범위로 처리되는지는 별도 확인이 필요하다. PoC의 가명화·마스킹 기록을 모든 서비스 데이터의 적절한 처리나 법적 익명화가 검증됐다는 근거로 사용하지 않는다. [IC] [D1] [Q3] [Q6]

개인정보 보호법의 수집·이용 근거(제15조), 처리업무 위탁 시 문서화할 사항(제26조), 국외 제공·조회·처리위탁·보관의 허용 요건(제28조의8)을 후속 확인 대상으로 식별했다. 실제 데이터 항목·목적·흐름과 계약·보관 조건이 정해진 뒤 각각의 해당 여부와 요건을 검토해야 한다는 평가상 추론이며, 외부 AI 제공자를 위탁 또는 제3자 제공으로 미리 분류하거나 준수 완료를 판정한 결과는 아니다. [개인정보 보호법 — 2025-10-02 시행본](https://www.law.go.kr/LSW//lsInfoP.do?ancYnChk=0&chrClsCd=010202&efYd=20251002&lsiSeq=270351&urlMode=lsInfoP)
