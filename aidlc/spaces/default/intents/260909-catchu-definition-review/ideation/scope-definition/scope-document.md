## 목적·대상과 이번 작업의 경계

CatchU는 GitHub 기록을 분석·정리한 자산으로 구직자의 자기 PR을 돕고, HR/HM이 자신의 JD에 따라 지원자의 프로필·자기소개서·포트폴리오·GitHub 자산을 확인하도록 한다. HM의 GitHub 확인 어려움과 HR의 인재 탐색·기술 스택 이해 어려움은 팀이 전달한 인터뷰 근거이며, 서비스의 개선 효과를 이미 입증한 결과가 아니다. [IC]

초기 대상은 신입·취업준비생, 초기 사용자 구상은 인공지능사관학교 수료생이다. 개발팀이 운영도 맡는 방향을 유지한다. 이 대상 구상이 이번 조사 참여자 확보나 실제 이용량을 뜻하지 않는다. [D1 §2~§3] [IC]

이번 catchu-definition 작업은 방향·초기 범위·요구사항 검토까지다. 요구사항 검토를 마친 뒤 다음 설계 작업을 정한다. 구현·배포, 상세 설계·기술 선택은 이번 작업의 산출물이 아니다. 제품 범위에 포함한 기능과 이번 세션에서 실제 구현하는 작업을 구분한다. [IC] [Q12] [CONF]

SC07~SC09의 12월 채택을 10월 기능 추가로 해석하지 않는다. SC05~SC06의 제품 포함은 유지하지만, 개별 요구사항 수준과 우선순위를 이번 표만으로 모두 확정하지 않는다. [Q4] [Q6] [Q11]

10월 분석 대상은 기존 PoC에 한정하지 않는다. 분석에 동의한 팀원·검증 참여자가 자신의 기여·근거를 확인할 수 있는 공개 저장소 중 팀이 사전 점검한 목록을 선정한다. 목록·개수는 미정이며, 이 결정은 사전 점검이나 서비스 분석 검증의 완료 기록이 아니다. 사전 분석 결과만 조회하는 방식으로 대체하기로 선택한 것도 아니다. [Q5] [Q10]

| 직접 링크와 구독 | 직접 전달 링크의 GitHub 근거 열람은 기업 구독으로 제한하지 않음 | 요약·질의응답 등 모든 기능의 무료 제공을 확정한 것은 아님 | [Q8] |

공개된 모든 자산을 매번 요약 결과에 빠짐없이 담아야 한다는 결정은 아니다. 공개 경계는 사용할 수 있는 자료의 범위를 정한다. 또한 구직자가 직접 전달한 링크와 기업 검색 경로의 열람 정책을 동일한 구독 정책으로 합치지 않는다. [Q2] [Q8] [Q9]

## 가치 흐름과 기능 의존성

가치 흐름은 이용자의 행위와 필요한 기능의 관계를 나타낸다. 기술 구조·구현 순서나 소요시간을 확정한 도식이 아니다. [CONF]

| 흐름 | 주체·행위 | 얻으려는 가치 | 범위 연결 |
|---|---|---|---|
| 링크 전달 1 | 동의한 공개 저장소를 선정·분석하고 경험 후보·근거를 확인 | 자기 PR에 사용할 기록을 찾음 | SC01 → SC02 |
| 링크 전달 2 | 프로필·GitHub 자산을 구성하고 전역 공개 범위를 정함 | 전달할 자기 PR 자료를 준비 | SC03 + SC04 |
| 링크 전달 3 | 링크 발행 → 수신자가 허용된 자료·근거를 직접 열람 | 기존 지원 과정에서 근거를 확인 | SC04; 10월 최소 흐름 |
| 링크 전달 보강 | 자기소개서·포트폴리오와 JD 요약·질의응답으로 자료 확인 지원 | JD에 따른 자료 이해 지원 | SC05 + SC06; 12월 방향 유지 |
| 검색·접촉 1 | HR이 조건을 입력해 후보와 허용된 자료를 확인 | 관심 후보 발견 | SC07; 검색 노출·열람 상세는 미결 |
| 검색·접촉 2 | 포지션/JD·관심 이유를 담은 제안 → 구직자 확인·수락·거절 | 관심의 맥락 전달과 구직자의 선택 | SC08; 수신 설정·반복 제한 포함 |
| 검색·접촉 3 | 수락 후 텍스트 DM, 동의한 외부 연락 수단 연결 | 후속 대화·연락 | SC09; 자산 공개는 자동 확대하지 않음 |

링크 발행은 준비한 자료와 공개 경계에, JD 요약·질의응답은 근거 자료와 사용 허용 범위에 의존한다. 채용 제안은 후보 발견·허용된 자료 확인에, 수락 후 DM은 제안의 수락 상태에 의존한다. 검색 공개 구성·구독 정책의 미결이 필요한 지점은 확정 요구사항과 설계의 선행 확인 항목으로 둔다. [Q1] [Q2] [Q3] [Q7] [Q9] [Q11]

우선순위는 링크 전달 주 경로의 실제 완주를 먼저 둔다. 이후 자료·JD 확인 보강과 검색·제안·DM의 세부 순서·병행 가능성은 요구사항과 역할·가용량 검토 후 정한다. 새 스택·구조·인력 배분을 기본값으로 채택하지 않는다. [IC] [Q4~Q6] [Q12]
