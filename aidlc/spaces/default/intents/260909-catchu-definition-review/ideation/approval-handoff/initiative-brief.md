# CatchU 이니셔티브 브리프

작성일: 2026-09-10  
상태: 확인된 요약에 따른 인계 검토본 — Approval & Handoff 단계 승인 전

## 목적과 판단

**권고: 승인된 방향·범위와 미결을 보존해 요구사항 검토를 이어간다.** 이번 작업은 방향·초기 범위·요구사항 검토까지다. 요구사항 검토 후 팀과 다음 설계 작업을 정하며, 구현·배포·완성 일정 확약은 포함하지 않는다. [CONF] [IC] [SC]

CatchU는 GitHub 기록을 자기 PR 자산으로 정리해 구직자를 돕고, HR/HM이 자신의 JD에 따라 지원 자료와 근거를 확인하도록 한다. HM의 GitHub 확인 어려움, HR의 인재 탐색·기술 스택 이해 어려움은 팀이 전달한 인터뷰 근거다. 초기 대상은 신입·취업준비생이며 인공지능사관학교 수료생을 초기 사용자로 고려한다. [IC] [SC]

## 범위와 이용 흐름

| 구분 | 전달할 범위 |
|---|---|
| 10월 1~2일 최소 흐름 | 동의한 사전 선정 공개 저장소의 서비스 분석 → 경험 후보·근거 확인 → 프로필·GitHub 자산 구성 → 링크 발행 → 수신자 직접 열람. 저장소 목록·개수는 미정이며 기존 PoC에 한정하지 않는다. |
| 12월 제품 방향 | 자기소개서·포트폴리오와 JD 한 장 요약·질의응답을 유지한다. 이들은 10월 최소 흐름의 필수가 아니다. 가이드의 첫 범위는 경험 후보·근거·생각해볼 질문이다. |
| 12월 검색·접촉 최소 | 직접 조건 검색 → 포지션/JD·관심 이유를 담은 제안 → 확인·수락·거절 → 수락 후 텍스트 DM·동의한 외부 연락. 제안 수신 설정·반복 발송 제한을 포함한다. |

근거: [SC SC01~SC10] [BL B01~B10]. 위 흐름은 개념을 보여주는 텍스트이며 목업·기술 구조·작업 배정이 아니다.

- **공개 경계:** 전역에서 숨기지 않은 GitHub 자산을 링크에 표시하며 첫 범위에 링크별 자산 선택은 없다. 숨김은 기존 링크와 요약·질의응답의 자료 사용에도 적용한다. 직접 링크의 GitHub 근거 열람은 기업 구독으로 제한하지 않으며, 구독·제안 수락으로 공개 범위를 확대하지 않는다. [SC]
- **후보의 경계:** 대표 주장·Catch의 검색 재사용과 비구독 기본 정보 열람 안은 우선 검토·비교 방향이다. 정확한 구독 차등·결제 범위, 제안 이유의 Catch 연결·구독별 발송 한도, 자동 문장 작성·첨삭은 미결·미채택 상태다. ATS 역할 분담을 유지하고 매칭 %·전체 소셜 기능을 추가하지 않는다. [SC] [BL]

## 근거·팀·자원과 위험

| 확인된 근거·계획 기준 | 판단의 한계 |
|---|---|
| 4인 합의, 팀 회의 검토 후 합의·미결 전달. 팀원 1·2의 웹 경험, 3·4의 개발 경험 부재 | 담당·실제 작업 가능량은 미정. 요구사항 검토 후 다음 설계 작업을 정하기 전에 팀과 확인한다. |
| 평일 09:00~18:00 참여, 서버·LLM/API 월 합산 약 160만 원, 2026년 12월 중순 목표 | 참여 시간을 순수 개발량·추가 근무로 환산하지 않는다. 계정·서비스 API·이용량과 일정·예산 충족은 미확인이다. |
| 규칙 기반 GitHub PoC 코드와 과거 결과, 사람이 작성한 카드 | 현재 재사용성·최신 동작·LLM/RAG·자동 서술 성능의 검증 근거가 아니다. |
| 대한민국 우선 제공 구상 | 확정 제약은 아니다. 외부 AI 처리·보관·전송 조건이나 서버 위치는 미확인이다. |

근거: [ST] [FE] [CR] [SC]. **채용 제안·수락 후 DM은 실현 가능성 평가 이후 구체화됐다.** 이 두 범위의 상세 요구사항·가용량·대화 및 연락 데이터·운영량에 따른 일정·비용·동작 검증은 수행되지 않았다. 다른 범위도 실제 완성 가능성을 검증한 것은 아니다. 기존 RAID의 대응 권고를 수행·완료된 대응으로 바꾸지 않는다. [RAID] [CHECK]

## 검증과 다음 검토

사용자 검증은 참여 가능한 응답자의 만족도·체감 유용성·개선 의견 조사다. 직접 사용과 시연을 구분하고, HM 미참여 시 업무 효과는 미검증으로 남긴다. 5분 내 파악은 후속 가설이다. 기능·자료 품질은 내부에서 별도로 확인한다. 시장조사·경쟁분석·목업·팀 편성 결과는 이번 진행안에 없으며 시장성·투자 타당성 검증 완료를 주장하지 않는다. [IC] [FE] [CONF]

## Assumptions & Open Questions

미결의 기준은 [범위 문서의 SD-OQ1~SD-OQ10](../scope-definition/scope-document.md#assumptions--open-questions)이다. 공개·검색·구독, 저장소·PoC, 가이드·자료, 검색 조건, 제안·연락·DM, 조사·내부 품질은 요구사항 검토에 연결한다. 담당·가용량은 다음 설계 작업 결정 전에, 자원·이용량·데이터 조건은 이에 의존하는 정책·설계·비용 판단 전에 확인한다. 새 수치·기술·권한 기본값은 채택하지 않았다. [SC] [BL]
