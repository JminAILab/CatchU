# CR3 AI 쪽 — 성능 요구사항

입력: 기능 설계(BR2.1·BR2.6·BR6.1), 요구사항 NFR2, 지금 생성 상한(`worker/app/generation/limits.py`: 생성 호출 300번, 생성 시간 제한 45초, 분석 마감 3,600초에서 60초 여유).

## 인셉션 NFR2(호출 횟수)에서 물려받는 요구사항

| ID | 요구사항 | 확인 방법 | 근거 |
|---|---|---|---|
| NFR2.1 | AI 쪽이 켜지면 판정 호출은 Catch당 한 번, 큰 후보는 생성 전 재료 판정 한 번이 더해진다. Catch N개(큰 후보 M개)면 판정 호출은 N+M 이하다. 꺼지면 0번이다. | 호출 수 시험: 합성 판정으로 Catch 3개(큰 후보 1개)일 때 4번 이하(S7), 꺼지면 0번(S1). | NFR2, BR2.1·BR6.1 |
| NFR2.2 | 판정 호출의 시간 제한은 Catch 판정·재료 판정 모두 20초다. 판정 호출도 지금 마감 확인을 따르고, 남은 시간이 20초보다 짧으면 판정을 보내지 않는다(BR2.6). | 시험: 마감 직전 시계로 돌리면 판정 요청이 없고 GENERATION_BUDGET_EXHAUSTED가 1건이다(S28). | NFR2, BR2.6 |
| NFR2.3 | 판정 호출 상한은 요청당 Catch 판정 300번·재료 판정 300번이다. 상한에 닿은 Catch는 판정하지 않는다(BR2.6). | 상한을 작게 둔 시험에서 상한 뒤 Catch는 판정 요청이 없다. | NFR2, BR2.6 |

## 확인 사항

- **분석 전체 시간:** 생성 호출 뒤 판정 호출이 더해지므로 AI 쪽이 켜지면 분석이 길어진다. 마감은 지금 값(3,600초) 그대로이고, 늘리지 않는다. 마감에 걸린 Catch는 BR2.6대로 다룬다. FR10 확인 때 TheMe 분석의 전체 시간을 한 번 재서 확인 기록에 남긴다(판정 기준이 아니다).
- **재료 판정 크기:** 질문 400개 상한과 파일당 앞 5줄로 요청 크기가 묶인다(BR6.2). 따로 바이트 상한을 두지 않는다.
