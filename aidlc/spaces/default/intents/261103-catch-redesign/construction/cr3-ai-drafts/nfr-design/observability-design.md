# CR3 AI 쪽 — 관측 설계

입력: 비기능 요구사항 NFR2.6·NFR3.2·NFR5.2, 지금 `GenerationReport`와 `_log`(`worker/app/generation/flow.py`).

- **같은 한 줄:** 판정 건수는 지금 생성 운영 로그(요청마다 한 줄)에 칸을 더해 남긴다. 새 로그 줄·경보·대시보드는 만들지 않는다.
- **더하는 건수:**
  - 판정: Catch 판정 요청·실패(코드별), 재료 판정 요청·실패(코드별), 시간 부족·상한으로 판정하지 않은 Catch
  - 결과: 기계 대조로 버린 후보·문장, 문턱 미만으로 버린 후보·문장, 둘째 줄을 지운 Catch, 제목 출처별 Catch 수(기록의 글·AI 후보·전체 미달 기록의 글·조각 제목·없음)
  - AI 쪽: 켜짐 여부와 공급자 이름(키 값 아님)
- **원문 없음:** 기록의 글·후보·문장·판정 답·키는 로그에 쓰지 않는다(NFR5.2). 시험이 로그에 원문이 없는지 단언한다(CR1 로그 시험과 같은 방식).
- **FR10 확인표:** 운영 관측이 아니다. 개발 명령의 로컬 파일로만 둔다(보안 설계 「FR10 확인 명령」).
