# CR3 AI 쪽 — 성능 설계

입력: 비기능 요구사항 NFR2.1~NFR2.3, 기능 설계 `construction/cr3-ai-drafts/functional-design/functional-spec.md`(W2~W4)와 BR2.1·BR2.6·BR6.1, 이 단계의 답 Q1 A, 지금 상한(`worker/app/generation/limits.py`).

## 호출 순서 (Q1 A)

후보마다 다음을 차례로 하고 다음 후보로 간다. 후보 사이 순서는 지금 우선순위(`material.priority`) 그대로다.

1. 큰 후보면 재료 판정(1번)
2. 생성(1번)
3. Catch 판정(1번)

마감에 걸리면 그 뒤 후보만 빠진다. 끝난 Catch는 판정까지 마친다. AI 쪽이 꺼진 경로의 제목 고쳐 쓰기는 지금처럼 모든 생성 뒤에 몰아서 한다.

## 상한 (NFR2.2·NFR2.3)

| 값 | 크기 | 자리 |
|---|---|---|
| 판정 시간 제한 | 20초(Catch 판정·재료 판정) | `limits.py`에 생성 시간 제한 옆에 둔다 |
| Catch 판정 호출 상한 | 요청당 300번 | 같은 곳 |
| 재료 판정 호출 상한 | 요청당 300번 | 같은 곳 |
| 판정 질문 상한 | 요청당 400개 | 판정 구성 요소 |
| 재료 판정 파일당 줄 | 5줄 | 판정 구성 요소 |
| 판정 출력 상한 | Catch 판정 2,000토큰(질문은 많아야 기록의 글 2 + 고르기 1 + 문장 3 = 6개라 답은 수백 토큰), 재료 판정 8,000토큰 | 판정 구성 요소. Claude 어댑터는 `max_tokens`로, OpenAI 어댑터는 SDK의 출력 토큰 상한 인자로 넘긴다(인자 이름은 코드 생성 때 공식 문서로 확인). 생성 기본 4,000과 따로 둔다 |

- **답 모양을 작게:** 판정 답은 질문마다 `[id, 값]` 꼴의 짧은 배열로 받는다. 재료 판정 질문 400개의 답은 약 10 KB(약 3,000~4,000토큰)라 8,000토큰 상한 안에 든다. 상한에 걸려 잘린 답은 읽을 수 없는 응답이다(JUDGEMENT_RESPONSE_UNREADABLE). 재료 판정이면 규칙 순서로 담는다(BR6.4).
- **20초 안에 드는지:** 재료 판정 400개 답이 20초 안에 오는지는 공급자 속도에 달렸다. 시간 제한을 늘리지 않고(기능 설계 BR2.6), FR10 확인 때 가장 큰 후보의 재료 판정 시간을 재서 확인 기록에 남긴다. 넘으면 실패 처리(규칙 순서)로 돌아가고, 질문 상한을 줄일지는 그때 팀장이 정한다.
- **마감 확인:** 판정 호출도 지금 `CallBudget`으로 마감을 확인한다. 생성 호출과 판정 호출은 각자의 시간 제한으로 「남은 시간 ≥ 시간 제한」을 본다. AI 쪽이 켜졌으면 생성을 시작할 때 「남은 시간 ≥ 생성 시간 제한 45초 + Catch 판정 20초」를 본다. 큰 후보는 재료 판정을 시작하기 전에 「남은 시간 ≥ 재료 판정 20초 + 45초 + 20초」를 보고, 모자라면 재료 판정 없이 규칙 순서로 담은 뒤 생성 확인으로 넘어간다. 판정 몫이 없으면 그 후보의 생성을 시작하지 않고 지금 생성 건너뜀(budget_skipped)과 같이 다룬다. 생성만 하고 판정 시간이 모자라 생성 결과를 버리는 일을 줄인다.
- **호출 세기:** `CallBudget`에 판정 호출 수를 생성 호출 수와 따로 센다(Catch 판정·재료 판정 각각). 상한에 닿은 판정 종류만 막는다.
- 시간을 단언하는 시험은 두지 않는다. 호출 수와 「마감 직전이면 판정 없음」만 단언한다(CR1과 같은 방식).
