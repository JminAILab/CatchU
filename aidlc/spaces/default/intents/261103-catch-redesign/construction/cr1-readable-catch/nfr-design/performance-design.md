## 설계

| 요구 | 설계 |
|---|---|
| NFR2.1 생성 쪽 호출 수는 지금 이하 | 생성 흐름(`worker/app/generation/flow.py`)은 제목을 고를 때 후보의 기록의 글 칸을 먼저 본다. 쓸 만하면 제목을 정하고, 조각 제목 고쳐 쓰기 단계를 부르지 않는다. 생성 호출 자체(설명 초안·질문·조각 제목 대상)는 지금처럼 한 번 한다. |
| NFR2.2 판정 호출 0번 | CR1에는 판정 공급자 자리가 없다. 판정 호출을 만드는 코드가 없으므로 호출 수는 0이다. |

## 확인 사항의 설계

- **재료 계산:**
  - 파일 종류는 파일마다 한 번만 판정한다. 결과는 재료 고르기 동안 다시 쓴다.
  - 묶음 나누기는 파일 경로를 한 번 정렬한 뒤 깊이를 늘려 가며 갈라지는 곳을 찾는다. 경로 수에 거의 비례한다.
  - 줄 담기는 지금처럼 한 줄씩 크기를 더해 상한을 넘는 줄을 건너뛴다.
- **시간 확인(Q1 A):**
  - 일반 시험은 커밋 3,000 합성 후보에서 결과만 단언한다. 결과가 상한 안에 있고, 같은 입력이면 같은지 본다. 시간 단언은 넣지 않는다.
  - 코드 생성 때 같은 합성 후보로 재료 고르기 시간을 한 번 재서 코드 생성 요약에 적는다. 5초를 넘으면 그 사실을 알리고 원인을 적는다.
- **요청 크기:** 직렬화한 자료가 24,000 B(지시문 포함 32,000 B)를 넘지 않는 것은 지금 `select`의 크기 계산을 그대로 쓴다. 큰 후보의 한 파일 6,000 B 상한도 같은 계산(머리글 포함)으로 센다.
