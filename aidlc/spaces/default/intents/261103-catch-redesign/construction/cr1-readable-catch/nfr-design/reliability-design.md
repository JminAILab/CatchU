# CR1 규칙 쪽 Catch — 신뢰성 설계

입력:
- 비기능 요구사항 `construction/cr1-readable-catch/nfr-requirements/reliability-requirements.md`
- 기능 설계 `construction/cr1-readable-catch/functional-design/`(functional-spec.md W1·W2, rules.md BR1.3·BR5.7)
- 계약 `inception/contract-design/contract-summary.md`(C5)

## 설계

| 요구 | 설계 |
|---|---|
| NFR4.1 같은 입력이면 같은 결과 | 기록의 글 고르기, 작업 사실, 재료 고르기는 모두 정렬 순서를 정해 둔 순수 계산이다. 기준은 다음과 같다. 커밋은 작성 시각과 SHA, 파일은 근거 순서·GitHub 순서와 경로, 묶음은 바뀐 줄 수와 이름이다. 집합이나 사전의 순회 순서에 기대지 않는다. 시험은 같은 입력으로 두 번 돌려 결과 전체를 비교한다. |
| NFR4.2 나뉘지 않던 단위의 열쇠 유지 | 나누기 코드를 지울 때 열쇠 계산에서 조각 값만 뺀다. 조각이 없는 단위의 열쇠 입력은 지금과 같게 둔다. 시험은 지금 작업 동일성 시험의 기대 열쇠 값을 그대로 쓴다. |

## 확인 사항의 설계

- **배포:** CR1은 계약 파일과 판본 문자열을 고치지 않는다. 그래서 worker·web을 각각 배포해도 된다. CR1 PR에 계약 파일 변경이 없는지 PR 검토에서 확인한다.
- **옛 Catch와 섞임:** 화면은 작업 사실을 글 목록으로만 다루고 줄의 꼴을 해석하지 않는다(지금과 같음). 그래서 옛 꼴과 새 꼴이 섞여도 그려진다. 화면 시험에 옛 꼴 작업 사실 표본을 하나 둔다.
- **생성 실패:** 제목 결정은 생성 결과보다 기록의 글 칸을 먼저 본다(W2). 생성이 실패하거나 건너뛰어져도 이 순서는 그대로다. 생성 실패 처리(설명 초안 실패, 다시 부르지 않음)는 바꾸지 않는다.
- **재시도·회로 차단:** 새로 두지 않는다. CR1에는 새 외부 호출이 없다.
