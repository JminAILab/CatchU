# CR1 규칙 쪽 Catch — 확장성 설계

입력:
- 비기능 요구사항 `construction/cr1-readable-catch/nfr-requirements/scalability-requirements.md`
- 기능 설계 `construction/cr1-readable-catch/functional-design/functional-spec.md`

CR1에는 인셉션 NFR에서 물려받은 확장성 요구사항이 없다. 확장 구조(수평 확장, 분할, 큐)를 바꾸지 않는다. 아래는 확인 사항의 설계다.

- **글 길이:**
  - 기록의 글은 한 글 검사의 2,000자 규칙 때문에 2,000자 이하로만 들어온다.
  - 저장·계약·화면 어디에도 새 길이 상한을 두지 않는다.
  - 경계 시험은 2,000자 첫 줄(기록의 글이 됨)과 2,001자 첫 줄(기록의 글 없음)을 둔다.
- **근거 조각:** 작업 사실 한 줄이 1,000자를 넘으면 api의 지금 조각 나누기(`MAX_CHUNK_LENGTH`)가 나눈다. CR1은 이 처리를 바꾸지 않는다.
- **발행본 글자 합계:** 지금 상한(60,000자) 처리를 그대로 쓴다. 기록의 글 줄은 Catch 하나에 최대 2,000자를 더한다.
- **변경 묶음 수:** 상한은 없다. 묶음 몫이 머리글보다 작으면 첫 채우기를 건너뛰고 두 번째 채우기가 받는다(BR5.6). 그래서 묶음이 많아도 재료 크기는 전체 상한 안이다.
