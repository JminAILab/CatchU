## 질문의 범위

- 입력: 승인된 의도 설명·범위 문서·우선순위 목록·화면 초안(`ideation/`), 코드 지식(`aidlc/spaces/default/codekb/CatchU/`, 기준 커밋 9923226c), 입력 문서 `docs/ai-dlc-input-catch/CatchU_Catch_개편_입력.md`(§3·§4·§5·§8은 팀장 결정).
- 화면 초안 승인 때 정한 것: 받은 사람 화면 안내 문장 고치기(IB-9)는 AI 쪽이 아니라 제목·작업 사실 변경과 함께 넣으며, 이 결정이 승인된 범위 문서·우선순위 목록보다 앞선다.
- 입력 문서에서 이미 정한 규칙(제목 순서, 작업 사실 첫 줄, 설명 초안, 판정 문턱, 재료 순서, 소속 저장의 막는 것·막지 못하는 것)은 다시 묻지 않고 요구사항으로 옮긴다. 아래는 입력에 답이 없거나 코드 분석에서 새로 드러난 것만 묻는다.

## Q1. [제품] 받은 사람 화면의 자동 생성 안내 문장을 어떻게 고칠까요?

**배경:** 지금 문장은 「제목과 설명은 CatchU가 GitHub 기록에서 자동으로 만들었습니다」이고, 상세에서는 제목·설명 가운데 있는 것만 가리킨다(`recipient-format.ts`의 `generatedNotice`). 개편 뒤 제목은 작성자의 PR 제목·커밋 첫 줄일 수도, AI가 쓴 글일 수도 있다. 화면 초안에서 문구는 여기서 정하기로 했다.

A. 「제목은 GitHub 기록의 글이거나 CatchU가 만든 글이고, 설명은 CatchU가 GitHub 기록에서 자동으로 만들었습니다」. 있는 것만 가리키는 지금 동작은 그대로 둔다(제목만 있으면 앞 절만).

C. 요구사항에는 "제목이 기록의 글이거나 AI 글일 수 있다는 뜻을 알린다"만 적고, 문구는 기능 설계에서 정한다.
