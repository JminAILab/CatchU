# Catch 개편 — 페르소나

입력: 요구사항 `aidlc/spaces/default/intents/261103-catch-redesign/inception/requirements-analysis/requirements.md` 「의도 분석」, 의도 설명 「Target Customer」, 코드 지식 `aidlc/spaces/default/codekb/CatchU/business-overview.md`. 페르소나는 둘이다(질문 Q1).

## P1 구직자(Catch 주인)

| 항목 | 내용 |
|---|---|
| 역할 | 자기 GitHub 공개 저장소를 분석해 Catch를 만들고, 확인·작성자 설명·공개를 거쳐 발행본으로 보낸다 |
| 목표 | 자기 작업이 무엇이었는지 Catch만 보고 알아본다. 재분석해도 같은 작업이 한 Catch로 남고 자기가 쓴 설명이 지켜진다 |
| 불편 | 「CreateArticlePage.vue 코드 수정」 같은 조각 제목과 SHA가 든 작업 사실로는 무슨 작업인지 감이 안 잡힌다. 재분석하면 같은 작업이 새 Catch로 생기고, 거기에는 설명이 비어 있다 |
| 기술 익숙도 | 높음(개발자 구직자) |
| 쓰는 빈도 | 저장소를 연결하고 분석할 때, 그리고 발행 전에 Catch를 정리할 때 |
| 이번에 닿는 화면 | 구직자 Catch 목록·상세, 분석 고지·첫 이용 고지 |

## P2 받은 사람(기업·면접관)

| 항목 | 내용 |
|---|---|
| 역할 | 구직자가 보낸 링크로 공개 Catch를 읽고, 12월 AI 요약·질의응답으로 묻는다 |
| 목표 | 제목과 작업 사실만 보고 무슨 작업인지 안다. AI가 쓴 글과 사람이 쓴 기록의 글을 구분한다 |
| 불편 | 제목·작업 사실로는 무슨 작업인지 모른다. 12월 AI도 작성자 설명이 없는 Catch에서는 "무엇을 했나"를 쓸 재료가 없다. 시연에서 사람의 말로 쓴 글이 없다 |
| 기술 익숙도 | 중간~높음 |
| 쓰는 빈도 | 링크를 받았을 때 한 번씩 |
| 이번에 닿는 화면 | 받은 사람 목록·상세(로그인 없음) |

## 관계와 우선순위

- P1이 만든 Catch를 P2가 읽는다. 기록의 글과 작업 사실의 변화는 둘 모두에게 닿는다.
- 우선순위는 같다. 의도 설명의 문제 둘 가운데 중복 Catch는 주로 P1, 읽히지 않는 Catch는 P1·P2 모두의 문제다.
- 12월 받은 사람 AI는 페르소나가 아니라 P2가 쓰는 도구다. 작업 사실의 기록의 글이 그 AI의 근거가 된다.
