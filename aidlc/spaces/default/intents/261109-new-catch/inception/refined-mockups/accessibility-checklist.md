## 본인 Catch 목록

- [ ] 「작성자 설명」 선택 칸에 보이는 이름이 있고(`label`이 감쌈), 키보드 순서는 공개 상태 다음이다. (WCAG 1.3.1, 2.4.3, 3.3.2 / AC4.1.4)
- [ ] 걸러 본 개수는 지금처럼 `aria-live="polite"`로 알린다. (4.1.3 / AC4.1.4)
- [ ] 빈 결과 안내는 지금 빈 결과와 같은 제목·글 꼴이다. (1.3.1 / AC4.1.3)

## 지원자 Catch 상세

- [ ] 칸 제목 8개가 각 글칸의 보이는 `label`이다. 칸 제목은 글칸 위에 있다. 지금 숨은 이름표 「작성자 설명」은 이 이름표들로 바뀐다. (1.3.1, 2.4.6, 3.3.2 / AC1.1.4, Q1 A)
- [ ] 새 안내 한 줄은 첫 글칸의 설명, 합계 글자 줄은 저장 단추의 설명(`aria-describedby`)으로 잇는다. 짚어 볼 곳 안내는 그 글칸의 설명이다. (1.3.1, 3.3.2)
- [ ] 키보드 순서: 8칸 → [설명 저장]. 숨긴 것 없이 위에서 아래로. (2.1.1, 2.4.3)
- [ ] 「발행하면 면접관에게 열릴 링크」는 h4 제목으로 찾을 수 있다. 알림 영역이 아니라 글자를 칠 때마다 읽히지 않는다. (2.4.6, 4.1.3 / AC2.3.6)
- [ ] 「다시 볼 곳」 커밋 링크는 화면 낭독기에 「(새 탭)」이 읽힌다. 화면에는 보이지 않는다(지금 `snapshot-view.tsx`와 같다). (3.2.5 / AC9.1.4)
- [ ] 저장 중·실패·상한 안내는 지금 상태 영역(`role` status·alert)을 그대로 쓴다. (4.1.3)

## 발행 화면

- [ ] 「작성자 설명을 쓴 Catch만 보기」는 보이는 이름이 감싼 체크 칸이고, 키보드 순서는 「내 Catch」 항목들 앞이다. (1.3.1, 2.4.3, 3.3.2 / AC5.3.4)
- [ ] 걸러 본 개수는 `aria-live="polite"`로 알린다(새 개수 줄, 가정). (4.1.3 / AC5.3.4)
- [ ] 항목은 지금처럼 `aria-pressed` 단추다. 작은 줄의 저장소 이름·「설명 안 씀」은 단추 안 글자라 단추 이름과 함께 읽힌다. (4.1.2, Q2 A)
- [ ] 확인 단계의 새 안내는 지금 비공개 안내와 같은 글자 꼴이다. 발행 단추를 막지 않는다. (1.3.1 / AC5.4.1)

## 면접관 발행본 Catch

- [ ] 칸 제목은 h4 「작성자 설명」 아래의 h5다. 제목 순서가 건너뛰지 않는다. (1.3.1, 2.4.6 / Q3 A)
- [ ] 그리지 않은 빈 칸은 화면 낭독기에도 나오지 않는다(숨긴 요소로 남기지 않고 그리지 않음). (1.3.1 / AC1.4.4)
- [ ] 링크 이름이 링크의 접근 이름이다. 화면 낭독기에 「(새 탭)」이 이어 읽힌다(지금 그대로). (2.4.4, 3.2.5 / AC2.2.7)
- [ ] 이름에서 푼 글자의 제어 문자는 지운다(방식은 기능 설계). (NFR5 / AC2.2.8)
- [ ] 한계: 주소 전체는 마우스를 올려야 보이므로, 키보드·터치 사용자는 이름만으로는 주소 전체를 볼 수 없고 링크를 열면 확인된다. 보이는 방식은 기능 설계에서 정한다. (1.3.1, FR3.4) [assumption]
- [ ] 표지는 「이 작업의 본인 커밋」 글자로 읽힌다. 색만으로 나타내지 않는다. (1.4.1 / AC7.1.3)
- [ ] 작성자가 글로 쓴 표지 흉내와 진짜 표지가 화면에서 구별된다(모양은 기능 설계). (NFR5 / AC7.2.6)
- [ ] 저장소 줄·작성 시점·한계 목록은 글자다. 「이 기록으로 알 수 없는 것」은 펼친 채라 접힘 안에 숨지 않는다. (1.3.1 / AC6.3.4)
- [ ] 긴 링크 이름은 잘리지 않고 줄을 바꾼다. 400% 확대에서도 가로로 넘치지 않는다. (1.4.10 / AC2.2.11)

## 색 대비

- [ ] 새 색이 없다. 새 h5와 작은 글자는 지금 색(`--color-muted` 등)으로 AA 대비를 지킨다. (1.4.3)
