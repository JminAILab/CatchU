# 새 Catch — 다듬은 화면

## 읽는 법

- 근거:
  - 승인된 대략 화면 `ideation/rough-mockups/wireframes.md`와 사용자 흐름 `ideation/rough-mockups/user-flow.md`
  - 사용자 이야기 `inception/user-stories/stories.md`(US1~US11)
  - 요구사항 `inception/requirements-analysis/requirements.md`(FR1~FR14, NFR2·NFR5~NFR7)
  - 이 단계의 답 `refined-mockups-questions.md`(Q1~Q4 모두 A)
- 새 화면은 없다. 기존 화면 네 곳에서 바뀌는 곳만 다듬는다. 대략 화면에서 정한 배치·문구·순서는 다시 정하지 않는다.
- 지금 코드가 그리는 모양을 확인해 그대로 적었다. 이번에 바뀌는 곳은 그림 오른쪽에 `<- 바뀜`, `<- 새것`으로 표시했다. 표시가 없는 줄은 지금 그대로다.
- 〔 〕는 화면에 나오지 않는 설명이다. 그림 속 글과 예시는 모양을 보이려는 것이다. 실제 문구가 기능 설계로 넘어간 곳(FR1.6, FR4.1, FR5.2, NFR5)은 그렇게 적었다.
- 반응형·접근성은 기존 화면 기준을 따른다(대략 화면 Q6). 좁은 화면용 배치를 따로 만들지 않는다. 화면 낭독기·키보드 항목은 `accessibility-checklist.md`, 상태와 동작은 `interaction-spec.md`, 쓰는 모양 이름은 `design-system-mapping.md`에 있다.

## 대략 화면과 달라진 곳

대략 화면을 지금 코드와 맞춰 보니, 대략 화면이 지금 모양과 다르게 그린 곳이 있었다. 아래처럼 지금 모양으로 고쳐 다듬었다.

| 곳 | 대략 화면 | 지금 코드 | 다듬은 화면 |
|---|---|---|---|
| 상세의 작성자 설명 칸 제목 | 칸 제목을 글칸 왼쪽에 그림 | 글칸 하나, 이름표 「작성자 설명」은 화면에 보이지 않음(`author-description-panel.tsx`) | 칸 제목을 글칸 위에 보이고 글칸은 한 줄 전체를 쓴다(Q1 A) |
| 발행 화면 「내 Catch」 항목 | `[ ]` 체크 칸으로 그림 | 누르면 골라지는 단추(`aria-pressed`), 안에 제목과 작은 줄 「공개/비공개 · 불일치 표시됨」(`publish-view.tsx`) | 단추 그대로 두고 작은 줄에 저장소 이름과 「설명 안 씀」을 이어 붙인다(Q2 A) |
| 다시 볼 곳 커밋 링크의 「(새 탭)」 | 「지금 근거 링크처럼」 붙인다고 적음 | 지원자 상세의 근거 링크 「원본 근거 열기」에는 「(새 탭)」이 없다. 발행본 화면의 링크에만 화면 낭독기용 숨은 글자로 있다(`snapshot-view.tsx`) | 발행본 화면과 같은 숨은 「(새 탭)」을 붙인다. 지원자 상세의 근거 링크는 바꾸지 않는다(가정 A4) |
| 면접관 화면의 칸 제목 | h5로 가정 | Catch 안 구역은 h4, h5 모양은 없음 | h5로 확정하고 글자 모양을 하나 더한다(Q3 A) |

- 「작성자 설명」 칸은 저장소 칸처럼 목록 요청 조건으로 서버에서 거른다. 지금 공개 상태 칸은 불러온 목록 안에서 거르지만(「불러온 Catch 중에는 없습니다」 안내), 새 칸은 그렇게 하지 않는다. (FR7.2, 대략 화면 1절)
- 카드에는 설명 여부도 작업 시각도 보이지 않는다. 정렬 선택 칸은 없다. (FR7.4, FR14.3)

## Assumptions & Open Questions

- 발행 화면에서 걸러 본 개수 줄 「불러온 N개의 Catch」를 새로 둔다는 것은 가정이다. 지금 발행 화면에는 개수 줄이 없지만, 요구사항 NFR6이 걸러 본 개수를 `aria-live="polite"`로 알리라고 한다. 본인 목록의 개수 줄과 같은 모양을 골랐다. [assumption]
- 「안 씀」 빈 결과 문구 「작성자 설명을 쓰지 않은 Catch가 없습니다」는 FR7.3의 「씀」 문구를 따라 만든 것이다. 문구는 기능 설계에서 정한다. [assumption]
- 작성 시점을 h4 「작성자 설명」 안의 작은 글자로 둔다(지금 지원자 상세 h3 「작성자 설명 내가 직접 쓴 설명」과 같은 꼴). 그래서 화면 낭독기는 제목과 함께 읽는다. [assumption]
- 링크 이름의 주소 전체는 마우스를 올려야 보인다(FR3.4). 키보드·터치 사용자는 이름만으로는 주소 전체를 볼 수 없고, 링크를 열면 확인된다. 이것을 한계로 둔다. 보이는 방식은 기능 설계에서 정한다. [assumption]
- 표지 모양, 작성자가 글로 쓴 표지 흉내와 구별하는 법, 제어 문자 처리는 기능 설계에서 정한다(NFR5).
- 칸 제목 줄의 저장 모양은 기능 설계에서 정한다(FR1.6).
