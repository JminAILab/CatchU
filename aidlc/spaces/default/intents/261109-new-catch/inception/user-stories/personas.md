# 새 Catch — 사람(페르소나)

사람은 의도 설명 「Target Customer」의 둘 그대로이고 새로 만들지 않는다(질문 계획). 이 문서에서 「팀장」은 이 intent를 정하는 우리 팀장만 뜻한다.

## P1. 지원자 (Catch 주인)

| 항목 | 내용 |
|---|---|
| 누구 | GitHub 활동을 분석해 Catch를 받은 개발자 구직자. Google로 로그인하고 자기 저장소를 등록해 분석한다(코드 지식 `aidlc/spaces/default/codekb/CatchU/business-overview.md` 「주요 흐름」 1~5). |
| 바라는 것 | 작업에서 내린 판단을 자기 말로 남겨, 면접관이 그 말을 실제 코드 앞에서 물어보게 한다. 많은 Catch 가운데 보낼 것을 빨리 고른다. 오래된 작업에서 무엇을 다시 고쳤는지 기억을 되살린다. |
| 지금 겪는 불편 | 판단이 기록보다 머릿속에 있는데 쓸 자리가 자유 칸 하나뿐이다. 같은 무게로 늘어선 카드 가운데 무엇을 보낼지 고를 도움이 없다(의도 설명 「Target Customer」). |
| 쓰는 화면 | 내 Catch 목록, Catch 상세(작성자 설명 편집, 다시 볼 곳), 발행 화면 |
| 하지 않는 것 | 질문별 답을 저장하지 않는다. CatchU가 순위·추천을 내지 않으므로 고르는 일은 지원자가 한다(요구사항 「Catch 정의」 원칙 넷). |

## P2. 면접관 (Catch를 받아 보는 사람)

| 항목 | 내용 |
|---|---|
| 누구 | 지원자가 보낸 발행본 링크를 로그인 없이 여는 사람. 사본, AI 기본 요약, 질의응답을 쓴다(코드 지식 `business-overview.md` 「주요 흐름」 7). |
| 바라는 것 | 지원자가 무엇을 맡았고 무엇을 고르고 버렸는지를 물을 재료를 얻는다. 요약이라도 원본으로 바로 갈 수 있어야 믿는다. |
| 지금 겪는 불편 | GitHub를 봐야 한다고 생각하지만 시간이 없어 거의 못 본다. 점수화·등급화·추천은 원하지 않는다(의도 설명 「Target Customer」, 2026-08-27 인터뷰 한 번). |
| 쓰는 화면 | 발행본 Catch(받은 사람 화면). 작성자 발행본 상세도 같은 표시를 쓴다. |
| 보지 않는 것 | 지원자만 보는 「다시 볼 곳」과 작업 시각(요구사항 FR12.2, FR14.3). |

## 두 사람의 관계와 우선순위

- 지원자가 쓰고 고르고 보내고, 면접관이 받아 읽고 묻는다. 지원자가 쓴 글(작성자 설명)이 면접관 화면의 재료가 되므로 1단계(지원자 화면)가 2단계(면접관 화면)보다 먼저다(할 일 목록 「만드는 순서」).
- 우선순위는 두 사람 모두 같다. 할 일 11개가 모두 Must이고, 한 사람의 이야기만 먼저 끝내는 순서는 두지 않는다. 순서는 선행 PR과 항목 의존이 정한다.
- 면접관 쪽 근거는 인터뷰 한 번이고, 새 모양을 면접관에게 먼저 보이지 않고 만든다(요구사항 「한계」).
