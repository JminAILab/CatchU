## 항목별 내용

### 1단계 지원자 화면

- **(1) 칸 제목이 붙은 작성자 설명 쓰기·보기.** 칸 제목은 이 작업에서 정한 것 / 맡은 부분 / 무엇이 문제였나 / 고른 것과 버린 것 / 어떻게 확인했나·결과 / AI가 낸 것 가운데 받아들이지 않았거나 고친 것 / 짚어 볼 곳 / 더 쓰기다. 편집 화면은 칸마다 입력 칸을 따로 보이고, 저장할 때 지금의 한 칸(4,000자, 칸 제목 글자 포함)에 칸 제목과 함께 넣는다. 받은 사람 화면은 같은 글을 칸 제목별로 나눠 보이고 빈 칸은 칸 제목째 숨긴다. 칸 제목을 읽지 못하는 옛 글은 전체를 '더 쓰기'로 보인다. (Q1·Q4)
- **(2) 짚어 볼 곳 링크와 관련 커밋 넣기.** 지원자가 GitHub에서 커밋 판본의 줄 링크를 복사해 붙이고 메모 한 줄을 단다. 한글 파일 이름은 퍼센트 인코딩한 주소로 넣게 안내한다. 관련 커밋은 이 Catch 근거에 든 본인 커밋 주소만 넣는다. (Q1)
- **(3) 쓰기 도움 문구.** 생각해 볼 질문(#487)을 칸 옆에 둔다. 질문 옆 "질문에 대한 답변을 저장하는 기능은 제공하지 않습니다"는 "질문을 보고 아래 칸에 자기 말로 적어 보세요" 같은 말로 바꾼다. "이 글은 링크를 가진 누구나 보고 외부 AI로도 보냅니다. 다른 사람의 이름·평가와 비밀값은 쓰지 마세요." 안내 한 줄을 둔다. (Q1)
- **(4) 본인 목록 '설명 씀/안 씀' 걸러 보기.** 목록 응답에 칸 하나를 더한다. (Q1)
- **(5) 발행 화면 '저장소마다 3~5개 권장' 안내.** 추천·순위는 내지 않는다. (Q1)

### 2단계 면접관 화면

- **(6) 발행 사본의 세 칸.** 저장소 이름, 작성 시점(작성자 설명을 마지막으로 고친 달), 이 작업만의 조회 한계를 발행 사본에 담는다. 셋 다 화면에만 보이고 받은 사람 AI 재료에는 넣지 않는다. (Q1)
- **(7) 링크 표지.** 작성자 글 속 커밋 링크가 발행 사본의 근거와 맞을 때만 '이 작업의 본인 커밋' 표지를 붙인다. 사본 근거는 본인 커밋 최근 20건까지다. 부정 표지는 두지 않는다. (Q1·Q3)
- **(8) 요약·질의응답 지시와 재측정.** 기본 요약·질의응답은 작성자 자료를 "작성자는 …라고 적었다"로 옮긴다. 질의응답 10개를 12월 NFR3 방식으로 다시 잰다. (Q1)

### 3단계 분석 쪽

- **(9) 기억 되살리기 사실.** 같은 작업 안에서 뒤 본인 커밋이 앞 본인 커밋의 줄을 다시 고친 곳, 새 파일로 옮긴 곳, 확장자 바꿈, 되돌림 표시. 지원자 화면에만 보인다. (Q1)
- **(10) 좁은 시험 파일과 산출물 목록.** 시험 폴더와 시험 이름 꼴만 '있음'으로 인정한다. 좁은 산출물 목록(잠금 파일, build·dist·out 폴더, 압축된 js, AI 하네스 기록·폴더, 도구가 관리하는 지시 파일 블록, 비밀 파일 경로)은 (9)·(10)에서만 뺀다. (Q1)
- **(11) 작업 시각과 정렬.** 첫·마지막 본인 커밋 시각을 남겨 지원자 목록을 작업 시각순으로 정렬한다. 면접관에게는 보이지 않는다. (Q1·Q3)
- **3단계 공통.** 결과 메시지 계약 판본을 올리고 api와 worker를 함께 배포한다. 결과 문장을 Catch에 남기면 고지 v3 4절에 한 줄을 더하고 팀장이 그 PR에서 승인한다. 규칙이 만든 줄 30~50개를 원문과 맞춘다. (Q1)

의존 우선(Q4). 선행 PR이 풀리는 순서대로, 같이 풀리면 1단계 → 2단계 → 3단계. (7)은 (2) 뒤에 한다. (1) 안에서 받은 사람 화면의 칸 제목별 보기는 칸 제목 저장 모양이 정해진 뒤에 한다. 3단계 (9)~(11)은 1·2단계와 서로 기대지 않는다(Q3).
