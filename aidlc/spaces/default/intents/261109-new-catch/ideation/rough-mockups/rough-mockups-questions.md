## Q1. [기획] 본인 Catch 목록의 작업 시각 정렬

## Q2. [기획] 짚어 볼 곳 링크와 관련 커밋 넣기

할 일 (2)는 지원자가 GitHub 커밋 판본 줄 링크를 붙이고 메모 한 줄을 달며, 관련 커밋은 이 Catch 근거에 든 본인 커밋 주소만 넣는다고 적었다. 저장은 지금의 한 칸에 칸 제목과 함께 들어간다(입력 문서 §8-1의 7).

A. 짚어 볼 곳도 다른 칸처럼 여러 줄 글칸 하나다. 칸 위 안내에 "한 줄에 GitHub 줄 링크 하나와 메모 한 줄", "한글 파일 이름은 퍼센트 인코딩한 주소로"를 적는다. 관련 커밋은 따로 넣는 장치 없이 "이 Catch 근거의 본인 커밋 주소만 표지가 붙는다"고 안내하고, 위 근거 칸에서 주소를 복사해 붙이게 한다. (가장 단순)
B. A와 같되, 칸 아래에 이 Catch 근거의 본인 커밋 목록과 [넣기] 단추를 두어 누르면 그 주소가 칸 끝에 「관련 커밋: 주소」 줄로 붙는다. 근거 밖 커밋을 넣는 실수를 더 막는다. 목록·단추와 커서 위치 처리가 는다.
C. 링크 칸과 메모 칸을 한 쌍으로 두고 [한 줄 더] 단추로 늘린다. 형식이 틀린 줄을 더 막는다. 줄 모양 검사와 저장 형식 정리가 는다.
X. Other (please specify)

[Answer]: X — A로 하되 하나를 더한다. 짚어 볼 곳 칸 아래에 「면접관에게 열리는 링크」 목록을 면접관 화면과 같은 링크 판별 규칙으로 보여 준다. 한글 앞에서 잘린 링크를 지원자가 저장 전에 보게 하려는 것이다. API는 바꾸지 않는다.

## Q3. [디자인] 지원자 Catch 상세에서 쓰는 칸과 보며 쓸 재료의 순서

지금 상세는 위에서부터 작업 사실·나의 기여 → 근거 → 작성자 설명(편집) → Catch 설명 초안 → 생각해 볼 질문 → 현재 확인 상태다. 입력 문서 §4-4는 지원자가 기억 되살리기(AI 초안, 기록의 글, 근거, 3단계 사실)와 생각해 볼 질문을 보며 칸 제목이 붙은 칸에 쓴다고 적었고, 할 일 (3)은 생각해 볼 질문을 칸 옆에 둔다고 적었다. 3단계 사실(다시 고친 곳·옮긴 곳·확장자 바꿈·되돌림·시험 파일 있음)이 들어갈 자리도 정해야 한다.

A. 지금 순서를 그대로 두고 생각해 볼 질문만 작성자 설명 바로 위로 옮긴다. 3단계 사실은 근거 아래에 새 칸 「다시 볼 곳(본인만 확인)」으로 둔다. (가장 단순)
B. 보며 쓸 재료를 모두 작성자 설명 위로 모은다: 작업 사실·나의 기여 → 근거 → 다시 볼 곳 → Catch 설명 초안 → 생각해 볼 질문 → 작성자 설명(편집) → 현재 확인 상태. 쓰다가 아래위로 오가는 일을 더 막는다. 칸 하나(AI 초안)를 더 옮긴다.
C. 넓은 화면에서 작성자 설명 옆에 생각해 볼 질문을 나란히 둔다. 질문을 보며 쓰기가 가장 쉽다. 상세 창 폭과 좁은 화면 배치를 새로 정해야 한다.
X. Other (please specify)

[Answer]: B

## Q4. [디자인] 작성자 설명 편집 칸의 모양

칸 제목은 8개다(이 작업에서 정한 것 / 맡은 부분 / 무엇이 문제였나 / 고른 것과 버린 것 / 어떻게 확인했나·결과 / AI가 낸 것 가운데 받아들이지 않았거나 고친 것 / 짚어 볼 곳 / 더 쓰기). 모두 건너뛸 수 있고, 저장은 한 번에 한 칸(4,000자, 칸 제목 글자 포함)으로 들어간다. 칸마다 따로 저장하는 안은 채택하지 않았다.

A. 8칸을 모두 펼친 채 칸마다 낮은 글칸을 보인다. 글자 수는 칸 제목 글자를 포함한 합계 하나(예: 1,240 / 4,000자)를 맨 아래에 보이고, 저장 단추도 하나다. (가장 단순)
B. 「이 작업에서 정한 것」만 펼치고 나머지 7칸은 칸 제목을 눌러 펼친다. 처음 보는 화면이 길어지는 것을 더 막는다. 펼침 상태와 쓴 칸 표시가 는다.
X. Other (please specify)

[Answer]: X — A로 하되 합계 글자 수 옆에 「칸 제목 포함」을 적는다.

## Q5. [디자인] 면접관 화면에서 이 작업만의 조회 한계 자리

입력 문서 §8-1의 6은 조회 한계를 면접관에게 주는 물어볼 재료로 적었고, 화면에만 보이며 받은 사람 AI 재료에는 넣지 않는다. 자리는 §4-2 예시에 없다. 여기서 조회 한계는 근거마다 이미 저장된 「이 근거로 알 수 없는 것」을 이 작업 몫으로 모은 것으로 본다(가정). §3-4의 칸 순서는 그대로 두고 새 칸만 끼운다.

A. 「기록에서 확인한 내용」 안 작업 사실 바로 아래에 펼친 채 「이 기록으로 알 수 없는 것」 목록으로 보인다. 면접관이 물어볼 재료를 접힌 칸에서 찾지 않게 한다. (가장 단순)
B. 「근거 자세히 보기」 접힌 칸 안에 둔다. 처음 보는 Catch가 길어지는 것을 더 막는다. 면접관이 펼쳐야 보인다.
X. Other (please specify)

[Answer]: X — 자리는 A(「기록에서 확인한 내용」 안 작업 사실 바로 아래, 펼침)로 한다. 다만 근거마다의 「이 근거로 알 수 없는 것」을 모두 모으지 않는다. 작업 전체에 걸린 한계(같은 작업을 다시 냈거나 cherry-pick으로 옮긴 변경일 수 있다는 경고, 커밋 목록을 다 받지 못한 PR이 있다는 한계)만 겹치지 않게 보이고, 없으면 칸을 그리지 않는다. 근거마다의 조회 상태 문장(「병합 커밋이라 변경 내용을 조회하지 않았다」 등)은 면접관 화면에 넣지 않는다.
