# 새 Catch — 사용자 흐름

입력: 승인된 의도 설명 `aidlc/spaces/default/intents/261109-new-catch/ideation/intent-capture/intent-statement.md`, 범위 문서 `ideation/scope-definition/scope-document.md`(「가치 흐름」), 할 일 목록 `ideation/scope-definition/intent-backlog.md`, 이 단계의 화면 초안 `wireframes.md`와 답 `rough-mockups-questions.md`(Q1~Q6), 화면 초안 검토 뒤 변경 요청 세 번(2026-11-09).

분석, 작업 사실·기여 확인 두 칸, 발행, 발행 후 확인은 지금 그대로다(입력 문서 §4-4의 6). 아래는 바뀌는 흐름만 적는다.

## 정보 구조

```
지원자
  내 자산
    내 Catch 목록 ---- [걸러 보기: 저장소 / 공개 상태 / 작성자 설명]
      Catch 상세 ----- 근거 -> 다시 볼 곳 -> AI 초안 -> 생각해 볼 질문 -> 작성자 설명(편집)
  발행 ------------- 자료 고르기(3~5개 권장) -> 순서 -> 제목·비밀번호 -> 확인 -> 발행됨

면접관
  발행본 링크
    발행본 자료 ---- Catch 항목: 제목 + 저장소 이름
                     -> AI 초안 -> 작성자 설명(칸 제목별, 작성 시점, 링크 표지)
                     -> 기록에서 확인한 내용(작업 사실, 작업 전체 한계, 근거 자세히 보기)
```

## 흐름 1. 고르고 쓰기 (지원자)

```
Flow: 고르고 쓰기
Persona: 지원자(Catch 주인)
Trigger: 분석이 끝나 내 Catch 목록에 Catch가 생겼다
Steps:
  1. 내 Catch 목록 -> [작성자 설명: 안 씀] 고름 -> 서버에서 걸러 아직 안 쓴 Catch만 불러온다(3단계 뒤에는 최근 작업이 위)
  2. 카드 -> 상세 보기 -> Catch 상세 창이 열린다
  3. 상세 -> 근거·다시 볼 곳·AI 초안·생각해 볼 질문을 읽으며 내려온다 -> 작성자 설명 8칸이 보인다
     (3단계 뒤에만) 「다시 볼 곳」의 커밋 링크를 열어 다시 고친 곳을 보고, 짚어 볼 곳으로 옮길 줄을 고른다
  4. 작성자 설명 -> 쓰고 싶은 칸만 쓴다 -> 합계 글자 수(칸 제목 포함)가 바뀐다
  5. 짚어 볼 곳 -> 면접관이 설명을 청할 만한 줄을 GitHub에서 고르고 Copy permalink로 복사해 붙인 뒤 메모 한 줄 -> 「발행하면 면접관에게 열릴 링크」 목록에 「파일 이름 · 줄 · 판본」 이름으로 나타난다
  6. [설명 저장] -> 저장됨 안내
  7. 내 Catch 목록 -> [작성자 설명: 씀] -> 쓴 Catch만 남는다
Success outcome: 고를 Catch마다 칸 제목이 붙은 작성자 설명이 저장되어 있다
Error paths:
  - 링크가 한글 앞에서 끊겼다 -> 「발행하면 면접관에게 열릴 링크」 목록에 끊긴 이름(파일 이름 없이 폴더까지 등)이 보인다 -> 안내대로 주소를 바꿔 붙인다
  - 판본 대신 브랜치 주소를 붙였다 -> 목록 이름에 「브랜치 main」이 보인다 -> Copy permalink로 다시 복사해 붙인다
  - 발행 뒤에 설명을 고쳤다 -> 이미 보낸 링크에는 반영되지 않는다(목록 아래 안내) -> 새로 발행해 새 링크를 보낸다
  - 8칸을 모두 비우고 저장했다 -> 지금처럼 설명이 지워진다
  - 4,000자(칸 제목 포함)를 넘었다 -> 지금처럼 저장하지 못한다고 알린다 -> 칸을 줄이고 다시 저장한다
  - 저장 실패(로그인 만료 등) -> 지금 작성자 설명 영역의 실패 안내 -> 다시 저장한다
  - 근거에 없는 커밋을 관련 커밋으로 붙였다 -> 저장은 된다 -> 면접관 화면에서 표지가 붙지 않는다(흐름 3)
  - 옛 자유 글이 있는 Catch -> 글 전체가 「더 쓰기」 칸에 들어가 있다 -> 그대로 저장해도 칸 제목 글자가 붙지 않아 4,000자를 넘지 않는다. 필요하면 칸 제목별로 옮겨 쓴다
```
<!-- Text fallback: 지원자는 목록에서 안 쓴 Catch를 걸러 상세를 열고, 재료를 읽은 뒤 작성자 설명 8칸 가운데 쓰고 싶은 칸을 쓰며, 짚어 볼 곳에 줄 링크와 메모를 붙이고 면접관에게 열릴 링크를 확인한 뒤 저장한다. 링크 끊김, 글자 수 초과, 저장 실패, 근거 밖 커밋, 옛 글을 오류·예외 경로로 둔다. -->

## 흐름 2. 보내기 (지원자)

```
Flow: 보내기
Persona: 지원자
Trigger: 면접관에게 보낼 Catch를 다 썼다
Steps:
  1. 발행 -> 「발행할 자료 고르기」에서 「저장소마다 3~5개를 권합니다」와 항목마다 저장소 이름·「설명 안 씀」을 본다 -> 필요하면 [작성자 설명을 쓴 Catch만 보기]를 켜 서버에서 거른 목록을 본다 -> Catch를 고른다
  2. 순서·제목·비밀번호 -> 지금 그대로
  3. 발행 내용 확인 -> 설명 없는 Catch를 골랐으면 「작성자 설명이 없는 Catch가 N개 있습니다…」 안내를 본다 -> 그대로 발행하거나 돌아가 설명을 쓴다 -> 발행됨
  4. 발행됨 -> 링크를 면접관에게 보낸다
Success outcome: 발행 사본에 저장소 이름·작성 시점·작업 전체 한계가 담긴 발행본 링크가 생긴다(2단계 뒤)
Error paths:
  - 발행 실패 -> 지금 발행 화면의 실패 안내 그대로
  - 발행 뒤 작성자 설명을 고쳤다 -> 이미 보낸 링크에는 반영되지 않는다 -> 새로 발행해 새 링크를 보낸다
```
<!-- Text fallback: 지원자는 발행 화면에서 저장소마다 3~5개 권장 안내를 보며 Catch를 고르고, 나머지 발행 단계는 지금 그대로 진행해 링크를 면접관에게 보낸다. -->

## 흐름 3. 면접 전·면접 중 (면접관)

```
Flow: 면접 전·면접 중
Persona: 면접관(Catch를 받아 보는 사람)
Trigger: 지원자에게서 발행본 링크를 받았다
Steps:
  1. 발행본 링크 -> (비밀번호가 있으면 입력) -> 발행본 자료가 열린다
  2. Catch 항목 -> 제목과 저장소 이름, 「이 작업에서 정한 것」을 훑는다
  3. 작성자 설명 -> 「파일 이름 · 줄 · 판본」 이름의 짚어 볼 곳 링크를 연다 -> GitHub 커밋 판본 줄이 새 탭에서 열린다(주소 전체는 마우스를 올리면 보인다)
  4. 판본·커밋 이름 -> 「이 작업의 본인 커밋」 표지가 있으면 그 판본·커밋이 이 작업의 본인 커밋임을 안다(고른 줄을 본인이 썼다는 뜻은 아니다)
  5. 기록에서 확인한 내용 -> 작업 전체 한계를 읽는다 -> 물어볼 재료로 쓴다
  6. 면접 중 -> 짚어 볼 곳을 띄우고 지원자에게 설명을 청한다
Success outcome: 면접관이 지원자 말과 코드 자리를 함께 놓고 질문을 만든다
Error paths:
  - 짚어 볼 곳 링크가 열리지 않는다(저장소 비공개 전환·삭제·강제 푸시) -> GitHub 쪽 오류 화면 -> 사본에는 주소만 남는다는 한계로 둔다(입력 문서 §8-3)
  - 관련 커밋에 표지가 없다 -> 아무 표지도 붙지 않는다 -> 면접관이 원본에서 직접 확인한다
  - 작성자 설명이 없다 -> 지금처럼 「작성자 설명이 없습니다.」, 작성 시점도 없음 -> 기록에서 확인한 내용과 원본을 본다
  - 이 변경 전에 발행한 옛 발행본 -> 저장소 줄·작성 시점·작업 전체 한계 없이 지금 그대로 보인다
```
<!-- Text fallback: 면접관은 발행본 링크를 열어 Catch마다 제목·저장소 이름·이 작업에서 정한 것을 훑고, 짚어 볼 곳 링크로 GitHub 줄을 열며, 관련 커밋 표지와 작업 전체 한계를 물어볼 재료로 쓴다. 링크가 열리지 않거나 표지가 없거나 작성자 설명이 없는 경우를 예외 경로로 둔다. -->

| 작성자 설명 걸러 보기(목록·발행 화면), 8칸 편집, 발행하면 면접관에게 열릴 링크, 권장 안내, 발행 화면 항목의 저장소 이름·「설명 안 씀」, 확인 단계의 설명 없는 Catch 안내, 면접관 화면 칸 제목별 보기, 링크 이름 | 1단계 | 범위 문서 「범위 안」, 변경 요청 1·2, 2차 변경 요청 5, 3차 변경 요청 3·4 |
