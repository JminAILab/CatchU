# 새 Catch — 의도 설명

이 작업은 지원자가 고른 Catch에 자기 말로 쓴 판단과 짚어 볼 코드 자리를 붙이는 새 Catch다. [desc] 진행과 완료 증거는 이슈 #491에 남긴다. [Q8]

이 문서에서 「팀장」은 이 intent를 정하는 우리 팀장만 뜻하고, Catch를 받아 보는 쪽은 「면접관」이라 부른다. [Q12]

## Problem Statement

면접관은 면접에서 지원자가 무엇을 맡았고 무엇을 고르고 버렸는지, AI가 낸 것을 어떻게 확인했는지를 실제 코드 앞에서 묻고 싶어 한다. [Q1] [Q12]

지금 Catch에는 세 가지 문제가 있다. [Q1]

- **카드가 너무 많다:** 작업마다 만든 카드가 같은 무게로 늘어선다. TheMe 한 저장소에서 46장이 나온다. [Q1]
- **AI 설명이 판단을 담지 못한다:** AI 설명은 바뀐 줄만 보고 쓰여서 '무엇이 문제였나' 같은 한 단계 위의 말을 담지 못한다. [Q1]
- **판단을 쓸 자리가 없다:** 판단을 쓸 자리는 빈 자유 칸 하나다. [Q1]

판단은 GitHub 기록보다 지원자의 머릿속에 더 많이 있다. 그래서 기록에서 판단을 캐내지 않고 지원자에게 묻고, 면접관이 코드 자리와 원본에서 그 말을 시험하게 한다. Catch는 판단을 증명하거나 평가하지 않는다. [Q1]

### Catch의 정의

> Catch는 지원자가 분석된 작업 가운데 골라 면접관에게 보내는 한 장이다. 그 작업에서 내린 판단을 지원자가 자기 말로 적고, 면접관이 그 말을 시험해 볼 코드 자리와 GitHub 원본이 함께 붙는다. Catch는 판단을 증명하지 않는다. 판단은 면접에서 확인한다. [Q3]

고르지 않은 작업도 지원자 화면에는 Catch로 남는다. [Q3]

이미 있는 원칙 넷을 함께 지킨다. [Q3]

- CatchU는 판단을 증명하거나 평가하지 않는다. [Q3]
- 면접관에게 가는 글은 누가 썼는지 구분한다. [Q3]
- 면접관은 원본으로 한 번에 갈 수 있어야 한다. [Q3]
- 고르는 일은 지원자가 하고, CatchU는 순위나 추천을 내지 않는다. [Q3]
