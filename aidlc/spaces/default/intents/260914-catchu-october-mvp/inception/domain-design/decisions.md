## ADR-001: B 등록 정본과 F 처리 결과 책임의 분리

- **Context:** F 결과가 생긴 것과 서비스 자산으로 받아들여진 것, 사용자가 공개한 것은 서로 다른 사건이다. F가 저장/공개를 함께 수행하면 B의 기준·권한과 실패 복구가 분산된다. [Q1, AR, U]
- **Decision:** EvidenceAnalysis는 AnalysisResult/WorkCandidate/AnalysisEvidence/DraftOutcome의 생성·의미·한계를 책임진다. F의 서비스 DB 직접 접근은 허용하지 않는다. AnalysisCoordinator가 결과 반영을 연결하고 CatchRegistry가 등록 판정·CatchAsset/CatchEvidence 저장·본인 확인/공개를 소유한다. 서비스 조회의 정본은 B 등록 자료이며 F 임시 자료에 영구 의존하지 않는다.
- **Consequences:** 등록·공개 권한과 자료 수명이 일관된다. 대신 E/F/B가 출처 식별·최소 자료·등록 성공/실패·중복/유실·영속 처리를 계약으로 맞춰야 한다. F 출처 참조를 유지하되 원문 전체 복제·무기한 보관을 요구하지 않는다. 민감 원문·토큰을 서비스 자료/로그로 옮기는 허가는 아니다.
- **Alternatives Rejected:** 별도 결과 반영 구성요소는 복잡한 조정을 모을 장점이 있지만 담당·정본·실패 경계가 추가되어 Q1에서 채택하지 않았다. F 직접 저장은 전달 단계가 줄지만 B 등록/공개 규칙을 우회하므로 제외한다. 한 데이터의 공동 정본은 갱신 충돌·권한 추적을 어렵게 하므로 제외한다.

## ADR-002: 분석 요청 동의의 소유자는 E

- **Context:** 분석 동의는 로그인·GitHub 연동·자산 공개와 다르며 요청한 대상과 연결돼야 한다. [R FR1.1/11.2, Q8]
- **Decision:** AnalysisCoordinator가 AnalysisRequest와 해당 AnalysisConsent를 소유한다. IdentityProfile은 계정·연동 정보를 제공하고 EvidenceAnalysis는 요청의 허용 범위 안에서 처리한다. 상세 기록·검사·API는 A/E가 제안하고 F와 검토한다.
- **Consequences:** 동의와 요청의 추적 책임이 명확해진다. A 연동 상태와 E 동의 기록을 함께 검사하고 기록/접수 실패의 일관성을 설명해야 한다. 권한 확대나 동의 없는 처리를 막아야 하며 기록 필드·문구 판본·검사 시점은 후속이다. 과거 동의 재사용·재분석 허용·철회 효과는 결정하지 않는다.
- **Alternatives Rejected:** A가 모든 동의를 소유하는 안은 계정 관련 기록을 모을 수 있으나 대상/범위와 요청의 일치를 위한 A/E 계약이 더 필요하여 Q8에서 E를 선택했다. F가 동의를 추정하거나 연동을 동의로 대체하는 안은 제품 정책에 어긋나므로 제외한다.

## ADR-003: 등록 적합성·초안 생성·사용자 확인·공개를 구분

- **Context:** 처리 실패와 후보 품질을 혼동하면 유효한 근거가 사라지거나 오류가 정상 0건으로 보인다. 초안 생성 여부만으로 공개를 결정하면 사용자 선택 원칙을 위반한다. [Q2~Q6, U]
- **Decision:** 작업 사실·본인 기여와 다른 기준이 충족되면 초안 생성 실패에도 미공개 등록한다. 오류 없는 정상 0건과 부분 실패를 구분하고, 실패 영향과 분리해 적합성을 확인한 후보만 제공한다. 초안 없는 공개에도 다른 공개 조건, 사용자의 근거·본인 기여 확인 및 별도 개별 공개 선택이 모두 필요하다. 없는 동기·과정·성과를 채우지 않는다.
- **Consequences:** 유효한 근거 중심 자료를 제공할 수 있고 생성 실패를 정직하게 드러낸다. 대신 F/E/B/C가 근거 확인·초안 실패·사용자 확인·공개 상태를 구분해야 한다. 초안 생성 기능 요구는 여전히 충족해야 하며 부분 성공을 전체 품질 통과로 보지 않는다. 수신자 화면은 최소 공개 자료만 보여 주고 내부 오류/민감 로그를 노출하지 않는다.
- **Alternatives Rejected:** 초안 성공을 등록 필수 조건으로 두는 안은 상태 처리가 단순하지만 유효한 작업 사실까지 제공하지 못하여 Q4에서 제외했다. 초안 없는 Catch를 영구 미공개로 제한하는 안은 Q5에서 제외했다. 이유/성과까지 등록 필수로 두는 안은 Q6에서 제외했다. 자동 공개는 기존 원칙에 반하므로 대안으로 채택하지 않는다.

## ADR-004: 작업 단위의 후보와 근거 중첩의 구분

- **Context:** 작은 변경·단일 커밋 허용은 커밋마다 Catch 생성 규칙이 아니다. 근거 중첩만으로 중복을 판단하면 다른 작업을 놓치고, 문구 차이로 구별하면 같은 작업을 반복 제공한다. [Q6/Q7, R FR1.4/NFR4]
- **Decision:** 같은 분석에서 서로 다른 작업임을 근거로 확인하고 각각 기준을 충족하면 일부 근거가 겹쳐도 별도 등록할 수 있다. 같은 작업의 제목·표현만 바꾼 후보는 중복 등록하지 않는다. F가 묶음 판별/중복 방지 방식을 제안하고 B/E와 검토한다.
- **Consequences:** 근거 원본의 구성에 따라 유효한 작업을 잃지 않는다. 대신 작업을 구별한 근거와 추정 한계를 전달해야 하며 키·비교 단위·알고리즘·임계값은 미정이다. 타인의 작업을 본인의 다른 작업으로 분리해 만드는 것을 허용하지 않는다. 새 분석으로 기존 자산/링크를 병합·교체·삭제하는 정책은 보류한다.
- **Alternatives Rejected:** 근거가 겹치면 별도 등록을 제한하는 안은 단순하지만 서로 다른 작업도 누락할 수 있어 Q7에서 제외했다. 커밋마다 카드 생성이나 제목 유사도만으로 중복을 확정하는 안은 작업 의미를 보존하지 못하므로 채택하지 않는다.

## ADR-005: 링크 수명과 현재 자산 공개 권한의 분리

- **Context:** 링크 중단/만료와 자산 숨김은 서로 다른 행위다. 발행 때의 권한만 보거나 응답을 캐시하면 이후 숨김이 반영되지 않는다. [R FR3.2/3.4/4.1~4.5, NFR1, Q5]
- **Decision:** ShareAccess는 ShareLink와 접근 조건을 소유하고 요청마다 IdentityProfile의 현재 공개 프로필 및 CatchRegistry가 허용한 자산을 조합한다. RecipientExperience는 그 응답만 표시한다. 숨김·확인된 원본 비공개 보호를 적용하고 수신 응답을 캐시하지 않는다. 대표 없는 발급·현재 링크 규칙을 유지한다.
- **Consequences:** 자산 공개의 정본이 B에 남고 링크별 중단·만료가 무관한 자료를 바꾸지 않는다. A/B 조회가 실패하면 빈 정상 결과와 구분해야 한다. 비밀번호 보호·현재 권한 검사의 세부 계약과 성능은 후속이며, 아직 정하지 않은 Catch 구성/본문 변화의 기존 링크 반영은 결정하지 않는다.
- **Alternatives Rejected:** 링크 발행 시 공개 상태를 복제해 그대로 제공하는 안은 숨김 반영 요구를 위반하므로 제외한다. 링크 중단과 자산 전역 숨김을 합치는 안은 무관한 접근까지 바꾸므로 제외한다. 후속 대표 구성/스냅샷을 첫 MVP에 도입하지 않는다.

## ADR-006: 논리적 구성요소와 화면·배포 책임의 구분

- **Context:** 업무 데이터 소유와 사람별 화면 담당, 서버/DB 배치는 다른 축이다. 이를 하나로 고정하면 D에 모든 화면을 맡기거나 H/I에 미배정 기능이 넘어갈 수 있다. [P, H, Q 통합 요약]
- **Decision:** 업무 구성요소 5개와 회원/수신자 UI 구성요소 2개로 소유·호출을 표현한다. MemberExperience는 각 A/B/C/D 화면의 연결이며 D의 독점 영역이 아니다. UI는 서버 업무 정본을 소유하지 않는다. H는 환경/수동 배포·복구, I는 연결 조율·검증 취합으로 유지한다.
- **Consequences:** 데이터 생애와 담당별 설계·테스트 책임을 보존한다. UI 통합/진입·복귀 차이는 해당 담당이 맞춰야 한다. 전체 UI 코드의 단일 담당·별도 서버/DB·신규 Unit을 확정하지 않는다. 비로그인 화면은 ShareAccess의 허용 응답 밖으로 접근하지 않는다.
- **Alternatives Rejected:** 영역 문자마다 서버/DB를 분리하는 안은 현재 단계의 배포 설계 범위를 넘으므로 제외한다. 화면에 독립 작업/공개 상태 정본을 두는 안은 불일치와 권한 우회를 일으키므로 제외한다. 모든 연결 설계를 팀원 1에게 맡기는 안은 기존 책임 분담과 다르므로 제외한다.

## ADR-007: 분석 접수와 결과 반영을 분리한 호출 관계

- **Context:** 분석은 접수와 완료가 다르며 처리 결과 임시 보존만으로 사용자에게 자산 준비 완료를 표시할 수 없다. 정확한 상태·큐·재시도 계약은 아직 미결이다. [R FR1.4, AR §3/6, Q2/Q3]
- **Decision:** AnalysisCoordinator → EvidenceAnalysis는 async 논리 요청, E → B 등록 및 UI/권한 조회는 sync 논리 응답 의존으로 표현한다. 완료 결과는 원 분석 요청의 결과로 돌아오며 새 역방향 업무 호출을 가정하지 않는다. 선언된 12개 호출 관계는 DAG이고 실제 전송/알림/폴링·트랜잭션 경계는 후속이다.
- **Consequences:** 접수·처리·등록·열람 준비의 실패 경계를 설명할 수 있다. 실제 메시지 유실/중복·반영 실패·늦은 결과의 계약 검증이 필요하다. 사용자 재요청과 저장된 결과의 재전달을 구분하며 자동 분석/LLM 재호출을 허용하지 않는다. 요청 소유·허용 범위를 결과와 연결해야 한다.
- **Alternatives Rejected:** 접수 또는 임시 결과 저장을 전체 완료로 보는 안은 영속/열람 준비를 입증하지 못해 제외한다. 이 단계에서 큐 엔진·폴링 간격·자동 재시도 정책을 확정하는 안은 담당자 후속 계약과 미결 정책을 대신하므로 제외한다.

## 보류와 최종 승인 조건

- 실패 후 초안 보완, 동의 재사용·재분석 허용, 기존 Catch·링크의 변경 정책은 미결·보류다. ADR-003/004/007의 등록·중복/전달 규칙으로 이를 해결했다고 해석하지 않는다. 원본 재공개/연결 해제·자료 수명과 링크 변경 세부도 해당 계약 전에 사용자 정책 판단이 필요하다.
- 서비스 LLM은 미선정이며 Astra 개발용·Luna medium 실험용은 최종 모델이 아니다. 제공자 조건/약관·정량 목표·실제 호출/권한·비용·서비스 결과 품질을 확인했다고 주장하지 않는다.
- C01/C02는 9/22 최신 승인대로 적용한다. C01 기준 미달·R1 문맥 줄 오귀속을 유지하고 R1 한 건만 필수 추가 튜닝·재호출 선행 사유에서 제외한다.
