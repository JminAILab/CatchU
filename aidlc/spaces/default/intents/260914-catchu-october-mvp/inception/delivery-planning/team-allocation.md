## 담당 표

| 담당 | 기존 책임·공통 기반 | 첫 연결 검토 상대 |
|---|---|---|
| 팀원 1 | F 결과 생성/의미, H 환경·수동 배포/복구, I 연결 취합; #86 DB·마이그레이션 | A/E(2) 요청·허용 범위, B(4) 후보/근거·중복. F의 결과 책임은 서비스 DB 직접 저장이 아님 |
| 팀원 2 | A 계정·프로필·GitHub 연동, E 요청·동의/진행·반영; #87 인증 기반 | F(1) 요청/결과, B(4) 등록/열람 준비, D/C(3) 상태·권한 |
| 팀원 3 | C 링크·수신자와 해당 화면, D 본인 홈/진입; #88 공통 오류 | A/E(2) JWT·진행, B(4) 현재 공개 Catch·열람 준비 |
| 팀원 4 | B 등록·근거/초안/최소 질문 정본, 본인 확인·공개·해당 화면 | F(1) 후보/근거, E(2) 반영, C(3) 현재 허용 자료 |

각 영역의 설계·구현·테스트와 PR 설명은 해당 담당이 책임진다. D나 I가 모든 화면·업무 시험을 대신하지 않는다. 추가 인력/가용량/완료 날짜·지원 분담은 확정하지 않는다.

## 승인과 리뷰

- 첫 연결 M1은 담당별 결과를 모아 팀장이 한 번 승인하며 이후 코딩마다 반복하지 않는다. 통상 PR의 작성자 외 승인·merge commit 규칙은 별개로 유지한다.
- B의 C03 검토 이연에 따라 **팀원 4의 B 영역 확인은 PR #89 병합 전 필수**다. 도메인 경계 문제는 이슈 → AI-DLC 수정으로 처리한다.
- 이번 계획은 다른 담당의 작업 완료나 구현·외부 처리 허가를 대신하지 않는다. 코딩은 기존 이슈별 선행 조건을 따른다.
- PR #89 본문은 단계마다 갱신하지 않는다. API·ERD가 모두 준비되어 리뷰를 요청할 때 사용자가 별도로 전달할 작성 기준에 따라 한 번 정리한다(9/23 PR 운영 지시).
