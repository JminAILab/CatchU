# CatchU — 연결별 선행 조건

## 의존과 해소 기준

| 의존·담당 | 막는 범위·해소 시점 | 지연 시 진행 가능한 범위 |
|---|---|---|
| #83 api 뼈대, 각 이슈 담당 | #86~#88 api 공통 기반 전에 이슈의 실행 근거 확인. #88 web은 #82도 필요 | 문서·계약 검토. 관련 코드 완료를 추정하지 않음 |
| #77 E/F 전송 검증, 1·2 | 실제 worker 전송 연결 전에 결과와 방식 검토 | 제공자 비종속 스키마·가짜 생성기/합성 전달. BullMQ를 먼저 연결하지 않음 |
| OQ-A1 실제 인증, 2와 연결 담당 | 실제 로그인·GitHub 연동/재인증 전에 경로·보안/수명 확인 | Access JWT 소비·#87 개발용 로그인, 합성 계약 개발 |
| OQ-F1 자격정보·F 임시 보존, 1·2 | 실제 수집·결과 보존/전송 전에 경계와 수명 확인 | 합성 결과. F 엔티티는 서비스 DB 밖이며 보존 위치 미정 유지 |
| OQ-L 서비스 LLM, 팀장 | 개발 중후반 실제 제공자 연결 전에 선정 | SDK/API 키 없는 가짜 생성기 |
| OQ-F2·B1 작업 동일성·등록/반영, 1 제안·2/4 검토 | 실제 중복 판정·DB 반영/결과 진입 연결 전 검토. B 영역 확인은 PR #89 병합 전 필수 | 알려진 합성 작업 ID로 경계 검증; 실제 동일성 판별 완료로 표시하지 않음 |
| OQ-A2·B3·C1 공개 프로필/보호, 관련 A/B/C/F/H | 실제 공개 프로필·원본 관측·비밀번호 보호 연결 전 해당 담당 확인 | 합성 공개/거부 시나리오. 현재 권한·공통 거부/비밀번호 계약 유지 |
| 보류 정책 OQ-B2, 팀장·B/E/F/C | 해당 기능을 새로 추가하기 전에 제품 판단 | 승인된 Q1 실패 재요청과 현재 공개 기능; 보류 endpoint 추가 없음 |

승인 소요 시간·실제 완료 날짜는 미정이며 새 기한을 만들지 않는다. 지연 시 미결을 숨기거나 실제 연결 성공으로 표시하지 않는다.
