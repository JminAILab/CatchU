### 준비 상태와 후속 확인을 구분할 항목

현재 서비스 폴더에는 README·`.gitignore`가 있고, 확인한 제품 경로에 패키지 manifest·잠금 파일·lint/format 설정·스캐너 설정이 없다. `.github`에는 이슈/PR 양식만 확인했다. AI-DLC 자체 훅·센서·doctor 성공은 제품 보안 검사의 증거가 아니다.

| 검사 관행 | 확인 상태 | 기존 후속 준비에서 다룰 내용 |
|---|---|---|
| lint/format·타입 검사 | 도구 후보와 설정 우선 원칙만 있음. 제품 명령/실행 증거 없음 | 서비스 초기화에서 도구·범위·실제 명령을 제안하고 README에 확인 결과 기록. ESLint/Prettier/Black/Ruff 채택으로 단정하지 않음 |
| SAST/DAST | 제품 소스 정적 보안 검사 또는 실행 서비스 대상 동적 검사 구성·결과를 확인하지 못함 | 관련 보안 설계/검사 준비에서 적용 대상·필요성·허용 환경을 결정. 현 단계에서 새 스캐너·필수 통과 수치·실행을 요구하지 않음 |
| 비밀값 검사 | 비밀값을 기록하지 않는 원칙은 있으나 자동 탐지 활성화·이력 검사 증거 없음 | 환경 예시와 로그의 자료 보호를 유지하고 자동 검사 방식은 후속 준비에서 검토. 저장소 제공자의 비밀값 탐지 기능이 켜져 있다고 추정하지 않음 |
| 의존성·공급망 검사 | 서비스 의존성/잠금 관리와 취약점 검사·공급망 통제 구현 증거 없음 | 선택된 패키지/잠금 관리, 변경 검토·재현 방법과 검사 증거를 준비 작업에 연결. SBOM·서명·특정 취약점 도구가 이미 필수이거나 완료됐다고 쓰지 않음 |

이 표는 새 보안 기능 요구사항이나 현 단계 차단 목록이 아니라 관측 한계와 후속 준비의 위치다. 실제 도구 선정은 필요할 때 합의하며 이번 단계에서 무조건 추가 인터뷰로 확장할 이유는 없다.

### 자료·로그 보호에서 재사용할 정확한 경계

PR #72의 다음 제안을 Code Style의 설명 또는 evidence에 보존할 수 있다. 제안 채택 여부는 인터뷰의 공통 관행 확인에 묶고, 기존 명시적 호출/자료 보호 제한은 그대로 적용한다.

- 비밀값은 Git·환경변수 예시·화면·로그에 남기지 않는다. 오류 객체·URL·함수 인자/반환값 전체에도 인증정보나 원문이 섞일 수 있으므로 필요한 안전한 정보만 기록한다. AI·이슈·PR에 공유하는 로그에도 동일 경계를 적용한다.
- 일반 개발·검사는 합성·비식별 자료와 모의 응답을 우선한다. 실제 자료/호출 검사는 허용 대상·범위·비용·취급 조건을 별도로 충족해야 한다. 오류 해결 요청만으로 대화·실험 원문 복구나 외부 전송을 허용받았다고 추정하지 않는다.
- 요청 접수와 비동기 작업의 실제 완료/실패를 구분하고 예외를 삼키지 않는다. 식별자 전달은 관련 계약에 남긴다. 로그 플랫폼·모든 함수 데코레이터는 필수로 추가하지 않는다.
