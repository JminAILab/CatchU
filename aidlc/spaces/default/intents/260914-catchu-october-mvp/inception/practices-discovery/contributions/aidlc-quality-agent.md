### 검사와 완료 증거의 최소 구분

리드 초안은 PR #72의 품질 제안을 정확히 재사용한다. 최종 통합 시 다음을 간결하게 유지하면 된다.

1. 테스트의 기대 결과는 승인된 행동·합의 계약·이슈 완료 기준에서 가져온다. 정상·거부·실패와 필요한 상태 전환을 대조하고, AI가 만든 테스트 자체를 기대 결과의 근거로 삼지 않는다. 발행 후 Catch 구성/본문 변화의 링크 영향과 0건/부분 결과 등 미결의 기대 결과를 임의 확정하지 않는다.
2. 결과에 판본과 미커밋 포함 여부, 실행 위치·명령·환경, `통과 / 실패 / 실행하지 못함 / 해당 없음`, 실제/모의 대상, 확인자와 작성자 외 재현 여부를 남긴다. 하네스 진단·Markdown 검사는 제품 검사와 별도다.
3. 문서 변경의 제품 커버리지 `해당 없음`과 적용되지만 실행하지 못한 CI를 구분한다. 제품 검사 기반이 없으면 준비 상태는 미완료다. 측정 대상·제외·수집 도구·실행 명령·CI 조건이 정해지기 전 수치를 주장하지 않는다. 구체 측정 단위나 새 도구를 이번 검토에서 확정하지 않는다.
4. 새 코드·테스트·CI 구성 및 실행은 이번 관행 재개의 허가 범위 밖이다. 이후 허용된 작업에서 기준을 구체화하되 필수 기준 미충족은 해당 머지/완료 조건 미충족으로 보고한다. 모든 독립 설계를 일괄 차단하는 조건으로 확대하지 않는다.

### 최소 인터뷰와 후속 위치

새 품질 질문은 시험 작성 순서 하나다. 예: “테스트 코드는 기능 코드를 만든 뒤 작성할까요, 먼저 작성할까요, 아니면 업무 시나리오를 먼저 정하고 세부 테스트는 구현 후 작성할까요?” 기본 제안은 `test-after`; 먼저 쓰는 방식은 실제 선택에 맞춰 TDD/BDD/ATDD를 구분하고, 혼합이면 `custom`과 명확한 Ordering을 기록한다. 이 질문은 테스트 실행·구현 착수 허가가 아니다.

그 외에는 기존 답변을 재사용하고 서비스별 측정/검사 도구·명령·CI 실행 조건·공통 준비/독립 재현 담당을 후속 준비의 미정으로 인계한다. 담당 재배정·새 필수 일정표·이번 단계에서의 도구 설치를 요구하지 않는다.
