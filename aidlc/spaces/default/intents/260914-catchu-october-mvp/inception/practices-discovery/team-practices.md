## Testing Posture

- **Methodology**: custom
- **Ordering**: 각 담당자가 기존 요구사항과 화면 흐름을 바탕으로 주요 업무 시나리오·기대 결과·실패 조건을 먼저 정하고, 세부 테스트 코드는 구현 후 작성·실행한다.
- 우리는 위 혼합 순서를 Q2에서 선택했다. 공통 세션은 연결 구간·누락·충돌을 검토하며 담당자의 설계·구현·테스트 책임을 유지한다. 초기 초안의 `test-after`는 선택 전 기본 제안이며 현재 선택은 `custom`이다. [Q2]
- 현재 `feature`·Standard의 80% 라인 커버리지와 머지 전 CI 기준을 유지한다. 영향별 로컬 검사나 제품 CI 부재를 면제로 해석하지 않으며 테스트 전략 변경만으로 하한을 낮추지 않는다. [Q2, O]
- 기대 결과는 승인된 제품 행동·기존 요구사항·합의 계약·이슈 완료 기준에서 가져온다. AI가 작성한 코드나 테스트 자체를 기대 결과의 근거로 삼지 않는다. 보류 정책·미합의 결과 의미는 임의 확정하지 않는다. 정상·거부·실패와 필요한 상태 전환·연결 검사를 선택한다. [Q1, Q2, H]
- 검사 결과에는 판본과 미커밋 포함 여부, 실행 위치·명령·환경·확인자, `통과 / 실패 / 실행하지 못함 / 해당 없음`, 실제/모의 대상과 작성자 외 재현 여부를 남긴다. 실패는 근거와 실제 결과를 대조하고 관련 결함을 수정·재시험한다. 계약·기준을 임의 변경해 실패를 없애지 않는다. [Q1, P72]

- **적용 차이:** `org.md`의 기본은 staging에 merge 시 자동 배포지만, 이번 intent의 승인 계획과 사용자의 명시적 수동 배포 지시가 우선한다. 자동 CD를 다시 선택하도록 질문하거나 자동 배포를 착수 조건으로 추가하지 않는다. 이 통합본은 `org.md`를 직접 수정하거나 하위 규칙 추가로 원본 충돌이 해결됐다고 주장하지 않는다. 공식 통합·승격 절차가 적용 관계의 추가 정리를 요구하면 해당 문장과 최소 범위만 제시한다. [O, W, U]

## Code Style

- 우리는 Next.js·NestJS·FastAPI와 `web/api/worker` 배포 단위를 유지한다. API/스키마·큐·모듈/레이어 경계의 상세는 담당 설계·계약으로 결정하며 PR #70 초안을 공식 채택으로 높이지 않는다. [C, H]
- 실제 저장소 linter/formatter 설정을 우선하고 언어별 관용 표기를 따른다. ESLint/Prettier/Black/Ruff는 기본 후보 예시이며 채택 완료가 아니다. 구체 도구·버전·패키지/잠금 관리·타입 검사 범위는 후속 초기화에서 제안한다. [O, L, Q1]
- 우리는 서비스 README를 설치·환경·실행·검사·종료 안내의 정본으로 삼고 실제 확인한 명령과 준비 상태만 기록한다. 초기화 담당은 실행 기반·안내를 준비하고 기능 담당자는 필요한 환경의 재현·사용성 확인에 참여한다. 확인되지 않은 명령을 실행 가능한 안내나 팀 전체 준비 완료로 쓰지 않는다. [Q1, P72]
- 예외를 삼키지 않으며 비동기 요청 접수와 실제 완료·실패를 구분한다. 합의한 안전한 요청/작업 식별자, 처리 단계·성공/실패·필요한 소요 시간·오류 항목만 기록한다. 오류 응답 형식·HTTP 상태·Result/exception·재시도 분류·식별자 전달 방식은 관련 계약에서 정한다. [Q1, P72]
- 비밀값은 Git·환경변수 예시·화면·로그에 남기지 않는다. 원문·인자/반환값·오류 객체·URL 전체에 인증정보나 사용자 자료가 섞일 수 있으므로 통째로 기록하지 않는다. AI·이슈·PR에 공유하는 로그에도 같은 보호를 적용한다. Next.js 서버 오류와 브라우저 개발 로그를 구분하고 브라우저에 민감정보를 출력하지 않는다. [Q1, P72]
- 일반 개발·검사에는 합성·비식별 자료와 모의 외부 응답을 우선한다. 실제 자료·외부 호출은 별도로 허용된 대상·범위·비용·취급 조건에서만 다루며 오류 해결 요청만으로 실험 원문 복구·외부 전송이 허용된 것으로 추정하지 않는다. [Q1, H]
- 자료 사용은 세 구분으로 적용한다. 과거 실험 원문·발췌·생성 응답·저장 결과의 접근·복구·복사·전송·실행/시험 자료 사용은 허용하지 않는다. 승인 문서·비원문 검토 결론·합성 자료 기반의 과거 자료 비의존 새 코드·시험·모의 연결은 보조 7개 식별 미완료만으로 차단하지 않는다. 새 실제 자료 수집·생성·외부 전송·실자료 시험은 기존 동의·모델·계약·안전성 및 별도 실행 허용 조건을 따른다. 이 구분은 구현 착수 승인이나 다른 조건의 면제가 아니다. 기존 비식별 자료 우선 원칙은 과거 실험 자료의 비식별화·가공 허가가 아니며, PoC 소스의 함수별 채택은 C03 검토를 따른다. 과거 자료 로딩 의존을 그대로 옮길 수 있다는 뜻이 아니다. [H, U]
- 담당자는 기존 설계/계약 검토에 입력·fixture 출처와 과거 자료 의존 유무를 연결한다. 같은 식별 불확실성만으로 비의존 구현을 다시 보류하거나 구현 직전에 같은 위험 판단을 반복하지 않는다. 의존이 불명확한 경로만 보류하거나 합성/모의 경로로 분리한다. 실제 관련 사본 잔존·과거 자료 의존·조건 위반이라는 새 사실이 확인되면 해당 범위만 재검토한다. 전수 부재/무관함 증명·일반 가능성 위치 조사·A 삭제 경위·공급자 물리 삭제 증명을 새 조건으로 추가하지 않는다. 추가 사본 접근은 허용되지 않았다. [H, U]

- 별도 로그 플랫폼·모든 함수 데코레이터·전역 명명 변경을 새 필수 관행으로 만들지 않는다. 보안 검사 구성·자동 탐지·의존성/공급망 확인 상태와 후속 준비 위치는 저장소 루트 기준 `aidlc/spaces/default/intents/260914-catchu-october-mvp/inception/practices-discovery/evidence.md`에 구분한다([공유 판본의 검사 근거](https://github.com/JminAILab/CatchU/blob/08c428847c4084dac0dace3b1c0cf52d963378c9/aidlc/spaces/default/intents/260914-catchu-october-mvp/inception/practices-discovery/evidence.md#보안-검사-준비-상태와-후속-위치)).
