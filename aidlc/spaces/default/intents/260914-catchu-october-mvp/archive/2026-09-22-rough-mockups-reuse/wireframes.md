# 실제 MVP Rough Mockups — 기존 화면 통합 검토본

2026-09-21 · `260914-catchu-october-mvp` · **단계 승인 전**

## 목적·지위·읽는 방법

실제 MVP 평가에서 사용자 행동·정보·예외·담당 경계를 따라갈 수 있도록 기존 저해상도 화면을 통합한다. 화면 원본과 상세 설계의 정본은 각 담당 제출물이다. 이 문서는 그것을 복제한 새 디자인 시스템이 아니라 **사용할 화면 구조·첫 MVP 적용 차이·연결 미결의 공통 검토본**이다. 화면 식별자는 기존 초안의 참조이며 확정 라우트·공식 유닛 ID가 아니다.

- **기준:** 승인 범위와 사용자 후속 결정. 배치·버튼 문구까지 확정했다는 뜻은 아니다.
- **원안:** 담당자가 이미 제시한 화면 구조·이동·문구. 공통 세션의 채택 확정이나 당사자 합의로 높이지 않는다.
- **연결 미결:** 양측 담당이 보완할 화면/상태 차이. 해당 분기만 보류하고 다른 설계는 진행한다.
- **공통 검토 주석:** 접근성·작은 화면에서 확인할 항목. 구현 검증 완료 또는 새 제품 정책이 아니다.

[작성 전 요약](rough-mockups-questions.md)의 `Looks correct`를 공식 기록했다. 이어 받은 사용자 지시대로 A/E §5.5를 먼저 대조했다. 구판 질문 파일의 ‘E 내용 확인 불가·링크 요청’은 당시 댓글 HTTP 404 기록이다. **이번에 원문을 확인했으므로 E 상태표 전체/링크를 다시 요청하지 않는다.** 질문 파일의 확인 당시 내용은 보존한다. 이 자료 확인은 기존 통합 방향을 바꾸지 않으며, 새 제안은 미결로 남긴다.

## 접근성·작은 화면 검토 주석

NFR6의 기본 접근성을 화면별로 연결한 검토 항목이다. 기존 PC 저해상도 원안을 우선 사용하며 정확한 브레이크포인트·색상·컴포넌트 구현은 후속이다. WCAG 적합성 시험을 수행했다고 주장하지 않는다.

| 화면 | 제목·영역 / 키보드 첫 진입·초점 | 작은 화면에서 담당자가 확인할 차이 |

## 범위·조건·검증 한계

- M01~M06의 사용자 동작은 위 구조에 연결하고, M07/IB07의 NCP 수동 배포·보존·복구·통합 검증은 후속 검증 항목으로 유지한다. 운영 전용 G 화면을 다시 추가하지 않는다.
- C01 미달·R1 1건 예외의 공식 반영 대기, C02 제한적 수용 방향과 별도 미확인, C03~C12 및 자료 보호/사본 삭제 조건을 유지한다. [기존 변경안](../../../../../../../docs/ai-dlc-input-mvp/2026-09-17_C02-C01_수용검토_변경안.md)의 기한/승인 지점을 해제하지 않는다.
- 추가 수집·원문 복구·LLM 호출·튜닝·모델 교체·코드·CI·인프라 실행 없음. 화면의 설명용 상태는 실제 실행 결과가 아니다.
- 웹 모의 시연의 네 흐름·일정·모의 데이터 결정을 가져오지 않았다. 실제 MVP 평가용 설계와 제품 완료/실행 검증을 구분한다.
- 검증은 고정 문서의 의미·범위·참조 대조다. 당사자 합의, 실제 UI/키보드 시험, API/큐 호환성, C01/C02 수용 완료 및 서비스 품질을 입증하지 않는다.
