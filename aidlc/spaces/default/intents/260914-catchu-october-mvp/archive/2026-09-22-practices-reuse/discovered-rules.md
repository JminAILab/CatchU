# CatchU 실제 MVP — 제약 통합 검토본

## 지위와 근거

Practices Discovery Step 5 통합본. 아래 제약은 intent `260914-catchu-october-mvp`에 적용하는 기존 사용자 지시·승인 인계·레포 규칙과 [Q1~Q3 및 작성 전 확인](practices-discovery-questions.md)에 근거한다. 단계 최종 승인·memory 승격 전이며 PR #72 전체를 승인한 것은 아니다. 기한이 있는 조건과 미결 상태는 해당 증거·공식 후속 결정에 따라 갱신하며 영구 미해결 규칙으로 고정하지 않는다. 근거는 [evidence.md](evidence.md), [인계 결정](../../ideation/approval-handoff/decision-log.md), [기존 답변](../../ideation/approval-handoff/approval-handoff-questions.md), [승인 계획](../../workflow-plan.md)이다.

## Mandated

- ALWAYS 이번 실제 MVP에서 팀원 1 F/H/I, 팀원 2 A/E, 팀원 3 C/D, 팀원 4 B의 자기 설계·구현·시험 책임을 유지하고, 공통 세션은 제출물 통합·충돌 정리를 맡는다.
- ALWAYS 기존 제출물·PR #72를 출처와 지위를 붙여 재사용하고 미합의 연결·지원·가용량을 미확인으로 남긴다.
- ALWAYS 보호 브랜치 `dev`·`main`에는 PR·승인 1건·merge commit을 사용하고, 커밋은 영문 접두사 5종과 한국어 이유를 남긴다.
- ALWAYS 실제 MVP의 NCP 수동 배포·자료 영속/복구·정상/거부/실패 검증과 로컬/모의 시연의 증거를 구분한다.
- ALWAYS 이 intent의 C01/C02 관련 착수 전에는 해당 수용 기준·예외의 공식 적용·독립 대조·시간 상한 확인을 증거와 대조하고, 필요한 후속 결정 전에는 현재 미달·미확인을 해소로 간주하지 않는다.
- ALWAYS 이 intent의 발행 후 Catch 구성/본문 변화에 대한 기존 링크 영향은 후속 정책 결정 전까지 보류하고, 그와 무관한 설계를 계속할 수 있도록 경계를 구분한다.
- ALWAYS 이 intent의 해당 실험 사본은 기존 기한인 2026-09-23 23:59 KST 또는 domain-design 승인/관련 구현 착수 중 먼저 오는 시점 전에 삭제 조건을 이행하고, 대상 종류·세션 식별자·완료 시각·확인 방법·미확인 사본 여부의 증거로 완료 상태를 갱신한다. 로컬 삭제와 공급자 보관/삭제는 구분하며 증거 확보 전 완료로 간주하지 않는다.
- ALWAYS 담당자가 기존 요구사항·화면 흐름에서 주요 시나리오·기대 결과·실패 조건을 먼저 정하고 세부 테스트 코드는 구현 후 작성·실행하며, 공통 세션은 연결·누락·충돌을 검토한다.
- ALWAYS 각 담당자가 자기 영역의 최소 전체 연결 흐름을 먼저 확인하고 첫 결과의 별도 승인을 유지하며, 구체 범위·순서·연결 방식은 후속 설계·계약에서 정한다.
- ALWAYS 공통 파일·계약·의존성 변경은 영향받는 담당과 조율하고 검사 결과·실제/모의 연결·미실행을 구분하며 서비스 README에는 확인된 명령·준비 상태를 남긴다.

## Forbidden

- NEVER 이번 Practices Discovery 재개를 구현·CI·환경 구축·자동 CD·버전 변경 승인으로 확대한다.
- NEVER 기존 승인·감사 기록을 소급 수정하거나 복구 입력의 존재 차이에 따른 approval-handoff 안내를 없애려고 인계 재승인·초기화 재수행을 한다.
- NEVER 이번 관행 확인을 추가 LLM/PoC 호출·원문 복구·튜닝·모델 교체 허가로 사용하거나 세션 변경을 호출·시간 예산 초기화로 해석한다. 기존 금지는 별도 명시적 허용 전까지 유지한다.
- NEVER PR 병합·문서 재사용·관행 초안만으로 C01/C02 조건 해소, 상세 계약 합의, 실제 실행/CI 통과 또는 전체 MVP 완료를 선언한다.
- NEVER 미배정 공통 설계·구현·시험·지원·운영을 팀원 1이나 초기화 담당자에게 자동 배정한다.
- NEVER 보호 브랜치 반영에 squash·rebase 머지를 사용한다.
- NEVER 예외를 삼키거나 비동기 요청 접수를 실제 완료로 기록하고, 비밀값·원문·인자/반환값·오류 객체 전체를 로그·환경 예시·화면·AI/이슈/PR 공유에 노출한다.
- NEVER 최소 연결 성공을 첫 MVP 전체 완료로 처리한다.

## 제약으로 승격하지 않은 항목

PR #72의 브랜치 변경안은 Q1에 따라 후속 검토로 남기고 현행 규칙을 유지한다. 공통 작업·검사·오류/로그 절차와 Q2의 custom 순서·Q3의 최소 연결 방식을 반영했지만 구체 검사 도구·버전·계약은 미정이다. org의 80% 라인 커버리지·머지 전 CI를 유지한다. 수동 배포 지시와 org 자동 staging 배포 기본의 차이는 사용자 지시를 따르되 원본의 적용 관계가 수정됐다고 주장하지 않는다. 현재 C01 미달/R1 예외 적용 대기·C02 독립 대조/시간 상한 미확인·사본 삭제 완료 미확인은 evidence의 관측 상태이며 위 조건 이행 증거가 나오면 갱신한다.
