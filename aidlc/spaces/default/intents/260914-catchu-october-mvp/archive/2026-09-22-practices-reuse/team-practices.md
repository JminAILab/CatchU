# CatchU 실제 MVP 개발 관행 — 최종 통합 검토본

## 지위와 적용 범위

2026-09-22 KST · `260914-catchu-october-mvp` · Practices Discovery Step 5. 세 독립 검토와 Q1~Q3 답변, `Looks correct` 작성 전 확인을 반영했다. 아래는 팀이 선택한 관행의 통합 검토본이며 단계 최종 승인·팀 규칙 승격 전이다. 기존 승인과 제약을 보존하며 이번 확인은 구현·CI·환경 구축·외부 호출·배포·버전 변경 허가가 아니다. [Q]

## Way of Working

- **기존 확정:** 팀원 1 F/H/I, 팀원 2 A/E, 팀원 3 C/D, 팀원 4 B. 각 담당자가 자기 설계·구현·시험을 맡고 공통 세션은 제출물 통합·충돌 정리를 맡는다. 지원·독립 검토·가용량은 별도 미결이다. 초기화 담당과 서비스 폴더의 모든 기능 책임을 동일시하지 않는다. [H, U]
- **기존 확정:** `main`은 배포, `dev`는 통합, 작업 브랜치는 `영역/작업내용`. 보호 브랜치에는 PR·승인 1건·merge commit을 사용한다. 커밋은 영문 접두사 5종과 한국어 이유를 남긴다. [C]
- **현행 AI-DLC 기준:** Construction 작업은 intent 통합 브랜치를 기준·대상으로 삼고 merge commit으로 합친다. 부모 브랜치 갱신은 현행 규정대로 Bolt 경계에서 `git rebase dev`로 수행한다. 현재 복구 브랜치가 향후 Construction 통합 브랜치로 확정됐다고 추정하지 않는다. [O]
- PR #72의 필요한 연결 검증에만 임시 통합 브랜치를 두고 공유 브랜치를 merge로 갱신하는 변경안은 **후속 검토로 남긴다**. 현행 Construction의 필수 intent 브랜치·경계 시 rebase 규칙과 PR·승인·merge commit 기준을 유지한다. 향후 변경 채택 전 원본 규칙과 실제 도구 동작의 적용 관계를 정리한다. [Q1, O, P72]
- **기존 확정:** 기존 화면·설계 제출물을 다시 만들지 않는다. E 상태·복귀는 A/E v0.10 §5.1/§5.5를 재사용하고 연결 상대의 남은 차이만 다룬다. 발행 후 Catch 구성/본문 변화가 기존 링크에 미치는 정책은 보류하며 관련 없는 설계를 막지 않는다. [H, R, U]
- 우리는 PR #72의 공통 작업 절차를 반영한다. 합의가 필요한 연결은 보류하고 기존 착수 조건 안의 독립 작업을 진행한다. 수정 전 브랜치·HEAD·기존 변경·관련 계약과 기대 결과를 확인하며 타인의 변경을 보존한다. 공통 파일·계약·의존성·잠금 파일 변경은 영향받는 담당과 조율한다. 이미 확정된 행동을 다시 선택하게 하거나 초기화 담당에게 모든 기능을 배정하지 않는다. [Q1, P72]

## Walking Skeleton

- 우리는 각 담당자가 자기 영역을 맡아 최소 전체 연결 흐름을 먼저 확인하고, 첫 결과의 별도 승인을 유지한다. 이후 진행 방식은 해당 승인 경계에서 별도로 정한다. [Q3, O, F]
- 구체적인 범위·유닛·순서·선행 계약·실제/모의 연결 방식과 완료 증거는 후속 설계·계약·개발 계획에서 정한다. 공통 세션은 연결·누락·충돌을 검토하고 담당자의 설계·구현·시험을 대행하지 않는다. [Q2, Q3, W]
- 최소 연결 성공은 첫 MVP 완료가 아니다. 기존 승인 범위의 실제 분석·보호·NCP 배포/복구 검증을 별도로 충족해야 하며 모의 연결 성공을 실제 처리 성공으로 세지 않는다. 이번 선택은 구현·GitHub/LLM 호출 허가가 아니다. [Q3, H]

## Testing Posture

- **Methodology**: custom
- **Ordering**: 각 담당자가 기존 요구사항과 화면 흐름을 바탕으로 주요 업무 시나리오·기대 결과·실패 조건을 먼저 정하고, 세부 테스트 코드는 구현 후 작성·실행한다.
- 우리는 위 혼합 순서를 Q2에서 선택했다. 공통 세션은 연결 구간·누락·충돌을 검토하며 담당자의 설계·구현·테스트 책임을 유지한다. 초기 초안의 `test-after`는 선택 전 기본 제안이며 현재 선택은 `custom`이다. [Q2]
- 현재 `feature`·Standard의 80% 라인 커버리지와 머지 전 CI 기준을 유지한다. 영향별 로컬 검사나 제품 CI 부재를 면제로 해석하지 않으며 테스트 전략 변경만으로 하한을 낮추지 않는다. [Q2, O]
- 기대 결과는 승인된 제품 행동·기존 요구사항·합의 계약·이슈 완료 기준에서 가져온다. AI가 작성한 코드나 테스트 자체를 기대 결과의 근거로 삼지 않는다. 보류 정책·미합의 결과 의미는 임의 확정하지 않는다. 정상·거부·실패와 필요한 상태 전환·연결 검사를 선택한다. [Q1, Q2, H]
- 검사 결과에는 판본과 미커밋 포함 여부, 실행 위치·명령·환경·확인자, `통과 / 실패 / 실행하지 못함 / 해당 없음`, 실제/모의 대상과 작성자 외 재현 여부를 남긴다. 실패는 근거와 실제 결과를 대조하고 관련 결함을 수정·재시험한다. 계약·기준을 임의 변경해 실패를 없애지 않는다. [Q1, P72]
- 제품 실행·측정 설정·검사 명령·CI 통과 증거는 아직 없다. 이번 문서 변경의 제품 커버리지는 해당 없음이며, 적용되지만 실행하지 못한 검사·CI는 미실행으로 구분한다. 필수 기준이 미충족이면 해당 머지·완료 조건도 미충족으로 보고한다. 하네스 진단과 문서 검사는 제품 시험이 아니다. [L, Q1]
- 서비스별 측정 대상·제외 근거·도구·명령·CI 실행 조건·공통 준비/독립 재현 담당은 후속 초기화·테스트 전략·CI 준비에서 구체화한다. 이것을 모든 독립 설계의 새 차단 조건이나 이번 실행 허가로 만들지 않는다. [Q1, W]
- C01 미달과 R1 한 건 예외의 공식 적용 대기, C02 제한 수용 방향과 독립 대조·시간 상한·전체 품질 통과의 차이를 유지한다. 별도 정식 결정 전 관련 조건을 해소로 간주하지 않으며 추가 LLM/PoC 호출·원문 복구·튜닝·모델 교체를 실행하지 않는다. [H, U]

## Deployment

- **기존 확정·최신 사용자 경계:** 실제 MVP는 NCP 수동 배포·외부 URL·자료 영속/복구 검증을 포함하며 자동 CD는 제외한다. 로컬 시연이나 모의 연결을 NCP 전체 완료로 바꾸지 않는다. H는 팀원 1, 각 기능의 시험·결함 책임은 해당 담당에게 남는다. [H, S, W, U]
- **적용 차이:** `org.md`의 기본은 staging에 merge 시 자동 배포지만, 이번 intent의 승인 계획과 사용자의 명시적 수동 배포 지시가 우선한다. 자동 CD를 다시 선택하도록 질문하거나 자동 배포를 착수 조건으로 추가하지 않는다. 이 통합본은 `org.md`를 직접 수정하거나 하위 규칙 추가로 원본 충돌이 해결됐다고 주장하지 않는다. 공식 통합·승격 절차가 적용 관계의 추가 정리를 요구하면 해당 문장과 최소 범위만 제시한다. [O, W, U]
- **PR #72 후속 입력:** 기능 우선·상황에 따른 자동 배포 선택·지연 시 로컬 시연 검토는 미병합 제안에 남은 후속 방향이다. 현재 사용자의 자동 CD 제외 경계를 바꾸는 근거로 사용하지 않는다. [P72, U]
- **미정:** 고정 배포 버전·명령·설정·환경 목록·복원 절차·성공/실패 판단과 실제 검증. 기존 수동 릴리스·환경 준비·배포·복구 단계에서 작성/확인한다. 이번 단계에서 NCP 자원을 만들거나 배포하지 않는다. [W]

## Code Style

- 우리는 Next.js·NestJS·FastAPI와 `web/api/worker` 배포 단위를 유지한다. API/스키마·큐·모듈/레이어 경계의 상세는 담당 설계·계약으로 결정하며 PR #70 초안을 공식 채택으로 높이지 않는다. [C, H]
- 실제 저장소 linter/formatter 설정을 우선하고 언어별 관용 표기를 따른다. ESLint/Prettier/Black/Ruff는 기본 후보 예시이며 채택 완료가 아니다. 구체 도구·버전·패키지/잠금 관리·타입 검사 범위는 후속 초기화에서 제안한다. [O, L, Q1]
- 우리는 서비스 README를 설치·환경·실행·검사·종료 안내의 정본으로 삼고 실제 확인한 명령과 준비 상태만 기록한다. 초기화 담당은 실행 기반·안내를 준비하고 기능 담당자는 필요한 환경의 재현·사용성 확인에 참여한다. 확인되지 않은 명령을 실행 가능한 안내나 팀 전체 준비 완료로 쓰지 않는다. [Q1, P72]
- 예외를 삼키지 않으며 비동기 요청 접수와 실제 완료·실패를 구분한다. 합의한 안전한 요청/작업 식별자, 처리 단계·성공/실패·필요한 소요 시간·오류 항목만 기록한다. 오류 응답 형식·HTTP 상태·Result/exception·재시도 분류·식별자 전달 방식은 관련 계약에서 정한다. [Q1, P72]
- 비밀값은 Git·환경변수 예시·화면·로그에 남기지 않는다. 원문·인자/반환값·오류 객체·URL 전체에 인증정보나 사용자 자료가 섞일 수 있으므로 통째로 기록하지 않는다. AI·이슈·PR에 공유하는 로그에도 같은 보호를 적용한다. Next.js 서버 오류와 브라우저 개발 로그를 구분하고 브라우저에 민감정보를 출력하지 않는다. [Q1, P72]
- 일반 개발·검사에는 합성·비식별 자료와 모의 외부 응답을 우선한다. 실제 자료·외부 호출은 별도로 허용된 대상·범위·비용·취급 조건에서만 다루며 오류 해결 요청만으로 실험 원문 복구·외부 전송이 허용된 것으로 추정하지 않는다. [Q1, H]
- 별도 로그 플랫폼·모든 함수 데코레이터·전역 명명 변경을 새 필수 관행으로 만들지 않는다. 보안 검사 구성·자동 탐지·의존성/공급망 확인 상태와 후속 준비 위치는 [evidence.md](evidence.md)에 구분한다. [Q1]
