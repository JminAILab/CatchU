# CatchU 실제 MVP — 설계 인계 요약

## 목적과 인계 권고

구직자가 GitHub 기록에서 경험 후보·근거·짧은 Catch 초안을 확인하고 직접 공개를 선택해 링크로 전달하며, 비로그인 수신자가 현재 허용된 자료를 읽는 실제 MVP를 설계한다. **조건부로 후속 요구사항·설계 검토를 이어가는 것을 권고한다.** 실제 분석·통합·NCP 검증이 목표이며 모의 응답 연결로 완료를 대신하지 않는다. 현재 판단은 구현 준비 완료·일정 달성·생성 품질 확보의 보증이 아니다. [I, F, S, Q1~Q5]

## 화면 재사용·담당과 남은 차이

팀원 1은 F/H/I, 팀원 2는 A/E, 팀원 3은 C/D, **팀원 4는 B 확정**이다. 과거 B 조건부 배분은 현재 담당 기준이 아니다. 지원자·시간·독립 검토 배분과 일정 여유는 미확정이다. 각 담당자가 자기 설계를 맡고 공통 세션은 제출물 통합·충돌 정리를 맡는다. A~I는 공식 유닛과 일대일로 고정하지 않는다. [Q6]

- E 상태·복귀는 기존 A/E v0.10 §5.1/§5.5를 재사용한다. E/F/D는 반영 대기·복구 중 기존 작업 반환 제안과 실패 확정·새 요청 허용 시점의 차이만 대조하고, B는 결과 반영/열람 접점을 확인한다.
- F는 0건·부분·근거 부족 결과의 실제 의미를, B/D는 해당 표시·행동을 보완한다. D/B의 화면 배치·진입/복귀와 A/C/D/B의 남은 프로필·재인증 연결 차이는 담당자 판단으로 남긴다.
- 현재 공개 권한·기존 링크 숨김 반영·현재 공개 프로필·생성 본문 유지 기준을 사용한다. **발행 후 Catch 구성/본문 변화의 기존 링크 영향은 후속 논의로 보류**하며 해당 분기 밖 설계를 막지 않는다.
- PR #70은 기존 설계 입력으로 재사용한다. 화면 통합 승인이 상세 아키텍처·API/스키마·큐 호환성의 합의나 검증을 뜻하지 않는다. [R, Q4/Q6]

## 실행 가능성·자원·조건

원격 수집·근거 기반 생성의 제한적 가능성은 관찰됐으나 사실성·수집 안전성·통합/복구 증거는 부족하다. C01은 기준 미달이며 R1 문맥 줄 오귀속 한 건의 예외는 공식 영향 재검토/승인 전이다. C02 후보 확보의 제한적 수용 방향은 독립 대조·시간 상한 준수·전체 품질 통과가 아니다. 기존 domain-design 승인/관련 구현 착수 전 조건과 C03~C12의 각 기한·실패 대응을 유지한다. [F, C, Q2]

사본 삭제는 **9/23 23:59 KST 또는 domain-design 승인/관련 구현 착수 중 먼저 오는 시점 전**이며 완료 미확인이다. 추가 호출·원문 복구·튜닝·모델 교체는 허용되지 않았다. 이 인계로 예외를 발효하거나 조건을 해제하지 않는다. [C]

NCP 계정/Admin 사용자 확인은 실제 환경 검증과 다르다. 서비스 최종 LLM·이용 조건, 순수 가용량·지원·재시험 여유는 준비 완료로 선언하지 않는다. 기존 작업 시간·첫 통합 뒤 활동 비중 조정을 재사용하고 새 필수 시간표·일정 확약을 만들지 않는다. 시장 조사는 승인 계획상 생략됐으며 기존 인터뷰는 문제 배경이다. 시장 효과·투자수익 검증으로 확대하지 않는다. [Q3/Q5, P]
