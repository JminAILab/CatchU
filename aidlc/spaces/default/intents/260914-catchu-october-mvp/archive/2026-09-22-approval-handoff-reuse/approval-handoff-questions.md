## Q1. 목적·범위와 이해관계자 합의의 확인 범위

근거: I의 Q1~Q5·Q8, S의 Q7~Q8 및 공식 승인, U.

[Answer]: 구직자의 동의 기반 선정 공개 저장소 실제 분석 → 후보·근거·짧은 초안·최소 질문 확인 → 별도 공개 선택 → 대표 없는 링크 발급 → 비로그인 열람을 목표로 한다. 첫 MVP는 M01~M07·IB01~IB07 및 기본 보호·실제 NCP 수동 배포·영속/복구 검증을 포함한다. 대표 기능은 첫 MVP 후속 개발, 탐색/일괄 관리/장식은 재검토 후보, G는 10월 제외다. 범위·우선순위의 합의 주체는 기존 4인 팀이고 전달된 회의 결정과 공식 승인을 근거로 한다. 모든 담당자가 미결 상세까지 합의했다고 기록하지 않는다. 발표 준비·기존 발표일의 모든 기능 동시 완성 전제를 되살리지 않으며 실제 MVP 평가용 설계를 우선한다.

## Q2. 위험 인지와 완화·차단 조건

근거: F, S의 잔여 조건표, C, U.

[Answer]: 조건부로 요구사항·설계 검토를 지속한다. 생성 사실성·근거 범위·수집 안전성·자료 보호·통합/복구·가용량 위험은 남아 있다. C01은 기준 미달 유지, R1 문맥 줄 오귀속 한 건에 대한 제한적 예외는 공식 영향 재검토/승인 전이며 전체 착수 제한을 해제하지 않는다. C02는 제출 근거상 후보 확보의 제한적 수용 방향이고 독립 대조·시간 상한 준수·전체 품질 통과와 다르다. domain-design 승인/관련 구현 착수 중 먼저 오는 경계 등 기존 C01~C12 조건을 유지한다. 사본 삭제는 9/23 23:59 KST 또는 더 이른 관련 경계 전이며 완료 미확인 상태를 보존한다. 추가 호출·원문 복구·튜닝·모델 교체를 실행하지 않는다. 미달·기한 초과·가용량 수용 불가가 확인되면 영향과 일정을 재검토한다.

## Q3. 예산·자원·가용량의 확정 범위

## Q4. Rough Mockups와 실제 MVP 방향

근거: R, 현재 사용자 `Approve`, U의 E 대조 지시.

[Answer]: Rough Mockups는 공식 승인됐다. 기존 담당별 화면·사용자 흐름과 PR #70 초안을 입력으로 재사용하며 원안·연결 미결·검증 한계를 보존한다. E는 A/E v0.10 §5.5에서 확인한 상태 의미표를 재사용하고 팀원 2에게 전체 표나 이미 있는 복귀안을 재요청하지 않는다. 현재 공개 권한·숨김의 기존 링크 반영·현재 공개 프로필·생성 본문 유지를 사용한다. 발행 후 Catch 구성/본문 변화의 기존 링크 영향은 후속 논의로 보류하며 관계없는 설계를 막지 않는다. 웹 모의 시연의 흐름·모의 데이터·결정은 실제 MVP 근거에 혼합하지 않는다.

## Q5. 시장 근거와 투자 판단의 범위

[Answer]: 시장 조사는 승인 계획상 생략됐다. 기존 HR/HM 인터뷰는 문제 배경이며 일반적 제품 효과·시장 적합성·이번 사용자 조사 확보를 입증하지 않는다. 시장 검증 완료나 투자수익·일정 달성을 새로 주장하지 않고 실제 MVP의 평가 가능한 핵심 흐름 설계를 이어간다. 새 시장 조사나 웹 시연을 추가하지 않는다.
