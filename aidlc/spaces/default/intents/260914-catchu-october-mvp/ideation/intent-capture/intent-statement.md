# CatchU 10월 MVP 의도문

## Problem Statement

구직자가 GitHub 기록에서 자신의 경험을 설명할 후보와 근거를 찾고, 확인한 자료를 공개·전달할 수 있게 한다. 수신자는 전달받은 링크에서 허용된 자료를 확인한다. 이번 작업은 기존 제품 방향을 10월의 실제 분석·자료 준비·링크 열람 흐름으로 구현하고 검증하는 데 목적이 있다. [Q1] [Q2]

첫 intent의 HR·HM 인터뷰는 문제를 파악한 배경으로 재사용한다. 이를 모든 채용 담당자의 특성이나 CatchU의 검증된 효과로 일반화하지 않으며, 이번 조사 참여자 확보로도 계산하지 않는다. [Q1]

MVP 입력의 10월 기능 16개·공통 기능 2개와 적용 NFR 7개의 상세 추적은 후속 범위·요구사항 단계에서 연결한다. 첫 통합 흐름의 성공만으로 전체 필수 범위를 완료 처리하거나 미완료 기능을 임의 제외·12월 이관하지 않는다. 사용자 조사 실행과 12월 전체 품질 판정은 이번 성공 기준에 추가하지 않는다. [Q2] [Q3] [desc]

## Initiative Trigger

2026년 10월 1~2일 중간 발표를 위해 구직자와 수신자가 실제 서비스를 이용할 수 있는 MVP를 설계·분담 구현·검증하고 NCP에 수동 배포한다. 첫 intent의 승인 제품 행동과 요구사항 ID는 유지하며, 이번 실행의 준비 상태와 검증 결과를 새 기록에 남긴다. [Q2]

4인 팀의 담당자는 각자의 설계·코딩·테스트를 수행하고 AI의 지원과 사람의 실행 책임을 구분한다. 팀원 1의 조율·자문 여유와 팀원 4의 학습 부담을 반영하며, 계정·가용량·PoC 확인 전 일정 달성이나 재사용에 따른 단축을 보장하지 않는다. [Q4] [Q7] [desc]

## Initial Scope Signal

workflow-selected scope는 `feature`, 깊이는 Standard다. 실제 수행 순서는 이미 승인된 [workflow-plan.md](../../workflow-plan.md)를 유지하며 이번 목적 정리는 새 계획 구성 요청이 아니다. 제품 경계는 확인된 10월 범위이며 scope 이름이나 문서 재사용을 개별 단계의 승인으로 계산하지 않는다. [scope] [Q2] [Q8]

- 포함: 동의 기반 선정 공개 저장소 실제 분석부터 Catch 준비·공개 선택·링크 열람까지, 실패·중복·공개 권한·링크 수명·내부 품질·운영 통제 및 NCP 수동 배포·자료 유지·복구 검증. [Q2] [Q3]
- 제외: 12월 기능의 상세 설계·구현, 사용자 조사 실행, 12월 전체 품질 판정, 자동 배포 파이프라인. 수동 배포와 운영·복구 산출물은 유지한다. [Q2] [Q3] [Q8]
- 최신 인증·홈 결정: 기본 로그인은 Google OAuth이고 GitHub 연결 없이 홈에 들어갈 수 있다. 이것은 유일한 로그인 수단의 확정이나 분석 실행 허용을 뜻하지 않는다. [Q6]
- 분석 전 GitHub 연결 필요 여부, Google 계정과 선정 저장소의 소유·커밋 관계 확인 및 분석 동의 방식은 미결이다. 표시 이름 필수 등 회원 초안의 별도 제안도 확정하지 않는다. [Q6]
