판정은 **조건부 검토 지속**이다. 보조 7개의 식별·실험 관련성 미확인만 Domain Design 문서 승인 차단에서 제외하며, 같은 불확실성을 아래 비의존 새 구현의 차단 사유로 반복 적용하지 않는다. 미확인 위험을 남긴 한정 수용이지 삭제 완료·관련 없음·전체 자료 보호 통과가 아니다.

## 판단 요약

> GitHub 원격 자료 수집과 근거 기반 초안 생성의 가능성은 확인했다. 다만 수집 누락 처리, 수집 방식의 보안·운영 조건, 발췌 범위를 넘어선 서술 방지를 보완해야 한다. 생성의 사실성과 실제 운영의 안전성이 확보됐다고 판단하기에는 부족하다.

현재 권고는 **조건부로 범위·요구사항·설계 검토를 이어가는 것**이다. 서비스 전체의 실행 가능성·품질·안전성 확보, 구현 착수 또는 10월 일정 달성 확정이라는 판정이 아니다. 제한된 실패만으로 서비스 구현 불가능이라고 단정할 근거도 없다. 남은 조건은 [제약 등록부](constraint-register.md)의 담당·완료 시점·수용 기준으로 추적한다.

feasibility 결론에 필요한 것은 관찰 사실과 제품 주장에 대한 영향, 가능한 처리 경로, 잔여 검증의 책임·기한·실패 대응을 확인하는 일이다. 전량 diff 복구, 모든 보안 세부 설계 또는 서비스 인프라 구축을 지금 선행할 필요는 없다. 반대로 후속 검증 미달·기한 초과가 확인되면 결론을 그대로 유지하지 않고 즉시 실행 가능성과 일정을 재검토한다.

### 수집 누락이 경험 설명에 미치는 영향

누락 7건은 파일 7개가 아니라 **`Front/theme/package-lock.json` 한 경로의 서로 다른 커밋 파일 변경 7건**이다. API에 파일 정보와 증감 통계는 있었으나 patch가 없었다. 큰 변경량에 따른 생략 가능성은 있지만 정확한 원인은 미확정이다. 복구 출처는 사용자 PC의 기존 작업물이 아니라 GitHub에서 새로 복제한 동일 커밋 이력이다. 수집 후 별도 검사에서 복구했으므로 제품 자동 복구 구현으로 세지 않는다. [S4 §8~§9]

### LLM 사실성·활용성 평가와 최소 재검증안

실험은 OpenAI API 플랫폼 `gpt-5.6-luna`, `reasoning.effort=medium`, `store:false`로 총 6회(기본 3 + 합성 인젝션 1 + 보완 2)를 소진했다. 총 $3 제한 아래 기록된 최대 예상 비용은 6회 $0.0876, 사용량 기반 계산 비용은 $0.00521185이며 청구 확정액이 아니다. 과거 실험 기록으로 인용하며 현재 가격·서비스 비용 견적을 새로 보증하지 않는다. 추가 호출·자동 재시도·모델 변경은 실행하지 않는다. [S4]

- 충분근거 최초 초안의 새 UI 과장과 보완 초안의 사실성 판정을 분리한다. 보완 초안의 주요 변경 설명은 근거와 대체로 일치하나, ‘기록에 없다’는 전역 부재 단정과 업로드 완료 관련 서술은 관측 범위를 넘을 수 있다. 사용자는 **사실 정정 필요**로 판정했다.
- 필요한 사실 표현은 ‘이번에 제공된 발췌에서는 확인할 수 없다’, ‘제공된 발췌에서 업로드 호출 예시는 주석 처리되어 있으며, 실제 업로드 완료 여부는 이 발췌만으로 확인할 수 없다’이다. 사람이 고친 문장은 모델 원래 생성 성공으로 계산하지 않는다.
- 합성 인젝션 응답은 삽입 지시·단독 기여 요구를 따르지 않은 제한적 관찰과 별개로, 부재 단정의 사실성 미달을 유지한다. 충분근거 보완 실패와 별개 사례이며 일반 보안 통과가 아니다. 희박근거 보완의 자동 평가도 공식 사람 품질 판정이 아니다.
- LLM이 두 구획만 쓰는 방식은 PoC 보고서에 따른 **실험 가정**이다. 제품 구조 확정이 아니며 FR3.5의 직접 문구 수정 미제공을 사용자 수동 교정 기능으로 바꾸지 않는다.

| 오류 관점 | 현재 해석 | 후속 보완안 |
|---|---|---|
| 입력 | 발췌·마스킹·잘림으로 전체 이력이 보이지 않음. 코드 예시와 실제 실행 증거는 다름 | 리비전·파일·발췌 범위·누락/잘림 표식, 주장에 충분한 최소 근거 제공. 전체 부재나 실제 실행 여부를 입력 완전성으로 오인하지 않게 함 |
| 프롬프트 | ‘기록에 없는 것’ 구획과 표현이 전역 부재 단정을 유도할 여지 | 발췌에서 관찰한 사실 / 제한적 해석 / 확인 불가를 분리. 미관측은 ‘이번 발췌에서 확인 불가’로 제한하고 코드 존재를 실행·성과 증거로 바꾸지 않도록 요구 |

최소 재검증은 S4 §8.6의 제안을 유지한다. 먼저 원문 없는 합성 범위 단정 사례로 프롬프트를 점검하고, ljm0850가 별도 실행 허용을 받은 뒤 **기존 오류 회귀 1건 + 새 충분근거 1건 + 새 부분근거 1건**, 총 3회·모델 1개·보완 호출 0회를 제안한다. 기존 사례는 정답을 알고 교정하는 회귀, 새 사례는 사례별 정답을 프롬프트에 주지 않는 전이 평가로 분리한다. 최초 결과를 보존하며 보완 호출을 자동 추가하지 않는다. 새 동의 입력 확보·약관·접근·현재 가격·입출력/추론 토큰 한도·호출/누적 예산을 실행 전에 다시 확인해야 하며, 지금의 6회 한도를 다시 쓰는 승인이 아니다.
