# CatchU 10월 MVP — Scope Definition 질문·입력 검토

2026-09-16. intent `260914-catchu-october-mvp`. [#37](https://github.com/JminAILab/CatchU/issues/37) / [PR #58](https://github.com/JminAILab/CatchU/pull/58).

**Mode:** chat. 기존 사용자의 대화·한 번에 1~2개 질문 요청을 유지한다. 아래는 범위 확정을 준비하는 입력·질문 기록이며 scope-document / intent-backlog의 작성 전 확인이나 단계 승인이 아니다.

## 재사용하는 확정 입력

- [승인 요구사항](../../../260909-catchu-definition-review/inception/requirements-analysis/requirements.md)의 FR/NFR를 [현재 intent](../intent-capture/intent-statement.md), [MVP 입력](../../../../../../../docs/ai-dlc-input-mvp/CatchU_mvp_input.md) §1·§3, [후속 결정](../../../../../../../docs/ai-dlc-input-mvp/2026-09-14_followup.md)과 함께 적용한다. 과거 승인본은 수정하지 않는다.
- [feasibility 평가](../feasibility/feasibility-assessment.md)·[제약 등록부](../feasibility/constraint-register.md)·[RAID](../feasibility/raid-log.md)·[기존 답변](../feasibility/feasibility-questions.md)을 재사용한다. 공식 승인 지위는 현재 상태·감사 기록을 따르며, 승인 전 작성된 산출물의 당시 표기를 소급 수정하지 않는다.
- 사용자의 feasibility 승인은 관찰된 가능성과 잔여 위험을 바탕으로 후속 범위·요구사항 검토를 계속하는 판단이다. 생성 사실성·운영 안전성 확보나 10월 달성 승인이 아니다. C01~C12와 관련 구현 착수 제한은 유지한다.
- 사용자 최신 지시: 2.9.0 설치를 보류하고 검증된 2.8.1로 Scope Definition을 진행한다. 진행 중 workflow에 적용할 공식 지원 경로가 확인되거나 이번 workflow 종료 시 업데이트를 다시 검토한다. 재검증 완료 기한은 변경하지 않는다.
- 10월은 선정 공개 저장소의 동의 기반 실제 분석 → 경험 후보·근거·설명 초안 → Catch 확인과 별도 공개 선택 → 선택적 대표 구성 → 링크 발행·비로그인 열람을 완주한다. 대표 구성은 발행 필수 조건이 아니다. 실패·명시적 재요청·중복 방지·현재 권한·내부 품질·운영 중단/기록·NCP 수동 배포·영속/복구 검증을 임의 제외하지 않는다.
- Google 기본 로그인, GitHub 미연동 홈 진입 허용, 분석 요청 전 GitHub 연동 필요, 자산 GitHub 탭에서 저장소 선택·동의·분석 요청을 구분한다. 연동만으로 소유·커밋 관계 확인이나 분석 동의가 완료되지는 않는다. 탭 복귀는 조회이지 새 분석 요청이 아니다.
- 홈 분석 결과 상자·결과 단위 검토 집계는 제외하고 Catch별 상태를 유지한다. 링크 제목 필수·수신자 비표시, 공백 제거 후 유효 제목 중복 금지, 유효 링크 최대 5개, 사용자 단위 원자적 확인·생성, 요청마다 현재 권한 확인 및 수신 응답 캐시 금지 결정은 다시 묻지 않는다. 구현 방식은 미결이다.
- 이력서는 이 세션에서 확인한 **12월 PDF 업로드**를 유지한다. 12월 알림·DM·피드 등은 10월 구현 범위가 아니며 확장 제약만 후속 설계에 연결한다. 자동 CD는 제외하되 수동 배포 검증을 제외하지 않는다.
