# CatchU 10월 MVP — Scope Definition 질문·입력 검토

2026-09-16. intent `260914-catchu-october-mvp`. [#37](https://github.com/JminAILab/CatchU/issues/37) / [PR #58](https://github.com/JminAILab/CatchU/pull/58).

**Mode:** chat. 기존 사용자의 대화·한 번에 1~2개 질문 요청을 유지한다. 아래는 범위 확정을 준비하는 입력·질문 기록이며 scope-document / intent-backlog의 작성 전 확인이나 단계 승인이 아니다.

**최신 B 조건부 방안(2026-09-17): 담당 확정 대기, 수행 불가 시 대안 있음.** 팀원 4의 참여 일정·가용량이 미확인이라 현재 담당을 확정하지 않는다. 팀원 4가 수행하기 어렵다고 판단되는 경우 팀원 1(ljm0850)이 기존 F·H·I와 병행하여 B를 맡고 팀원 2·3이 상황에 따라 지원하는 조건부 방향이다. 조건 성립·대안 적용은 아직 확인되지 않았고 지원 세부 작업·시간도 미합의다. 기존 팀원 2 서버·팀원 3 화면 분담안은 확정 배정이 아니다. **이 상태에서 첫 MVP/후속 범위·완료 기준 초안과 독립 가능한 초안·계약 검토를 계속한다.** 아래의 ‘B 미정으로 범위 확정 대기’는 독립 검토 전체를 중단한다는 뜻이 아니다. 공식 작성 전 확인·단계 승인·구현 착수 조건은 유지한다.

**최신 입력(2026-09-17 KST):** 역할 선택 회의 결과를 수신했다. 팀원 1 F·H·I, 팀원 2 A·E, 팀원 3 C·D 확정, B 담당 미정, G는 10월 구현 제외, 팀원 4 참여 일정 불확실. 발표를 전제로 한 전체 기능 완성에서 **10월 초 핵심 흐름 우선·나머지 후속**으로 목표가 바뀌었다. 상세는 맨 아래 「9/17 회의 결과 수신·영향 검토」를 따른다. 이제 회의 결과 자체의 수신 대기가 아니라 **B 담당·첫 MVP 경계·G 제외 영향 확인 대기**다. 범위 산출물 작성 전 확인·Scope Definition 전체 승인·다음 단계 진행은 하지 않았다. 기존 A안은 미채택 예시로 보존한다. C01·C02는 별도 세션 진행 중이라는 사용자 보고만 받았으며 완료/통과로 처리하지 않는다.

**Q6·Q7 후속 확인(2026-09-17):** B 담당은 미정 유지, 팀원 2 서버·팀원 3 화면 분담은 제안만 유지한다. 사용자가 아래 최소 B 작업표로 추가 협의한다(협의 기한 미정). 기본 보호 경계 유지 방향은 확인됐고 아래 서비스 동작안으로 구체화했으나 상세 설계·수치·추가 담당 배정은 확정하지 않았다. G 제외는 유지한다. 범위 확정은 B 협의와 첫 MVP/후속 경계 검토가 남아 있으며 작성 전 확인·공식 승인은 별개다.

**품질 기준 구분 보완(2026-09-17):** 사용자는 최소 B 작업표로 팀원 2·3과 추가 협의하며 결과 전달 전 담당 미정을 유지한다고 재확인했다. C01/C02는 합의된 제한적 재검증 조건을 유지한다. **NFR3는 별개의 12월 품질 목표이며, 전체 목표·표본·판정을 첫 MVP 조건으로 앞당기지 않는다.** 승인 요구사항 NFR3의 적용 시점(12월), OQ12 및 제약 등록부 C12와 일치하며 반대 근거는 확인하지 못했다. 이번 답변은 Scope Definition 전체 승인이 아니다.

**최신 답변(2026-09-16):** Q3의 변경 적용 확인 완료. ‘사실 수정 없이 활용 가능’은 짧은 초안의 사실 주장·기여 귀속이 제공 근거와 일치한다는 의미이며 문장 완성도·풍부함·취향상 무수정을 요구하지 않는다. ljm0850이 9/17 C02 최대 2시간 → C01 최대 4시간, 총 최대 6시간을 우선 배정했다. 호출 구성은 알려진 실패 회귀 1건 + 새 충분근거 1건 + 새 부분근거 1건, 최대 3회다. **실제 호출은 자료 범위·모델·예산 확인 후 사용자의 별도 허용 대기**다. Q2의 팀 가용량·공통 책임은 미확정이고 Scope Definition 전체 승인·작성 전 확인은 하지 않았다. 아래 최초 계획 표의 ‘시간 미배정’은 답변 전 이력이며 과거 feasibility 승인본은 고치지 않는다.

## 재사용하는 확정 입력

아래는 회의 결과 수신 전 기준도 포함한 재사용 목록이다. 10월 전체 기능·내부 품질/운영·발표 전제·옛 담당은 맨 아래 후속 결정과 변경 영향표를 함께 읽는다. 과거 승인본을 소급 수정하거나 새 범위가 공식 승인됐다고 해석하지 않는다.

- [승인 요구사항](../../../260909-catchu-definition-review/inception/requirements-analysis/requirements.md)의 FR/NFR를 [현재 intent](../intent-capture/intent-statement.md), [MVP 입력](../../../../../../../docs/ai-dlc-input-mvp/CatchU_mvp_input.md) §1·§3, [후속 결정](../../../../../../../docs/ai-dlc-input-mvp/2026-09-14_followup.md)과 함께 적용한다. 과거 승인본은 수정하지 않는다.
- [feasibility 평가](../feasibility/feasibility-assessment.md)·[제약 등록부](../feasibility/constraint-register.md)·[RAID](../feasibility/raid-log.md)·[기존 답변](../feasibility/feasibility-questions.md)을 재사용한다. 공식 승인 지위는 현재 상태·감사 기록을 따르며, 승인 전 작성된 산출물의 당시 표기를 소급 수정하지 않는다.
- 사용자의 feasibility 승인은 관찰된 가능성과 잔여 위험을 바탕으로 후속 범위·요구사항 검토를 계속하는 판단이다. 생성 사실성·운영 안전성 확보나 10월 달성 승인이 아니다. C01~C12와 관련 구현 착수 제한은 유지한다.
- 사용자 최신 지시: 2.9.0 설치를 보류하고 검증된 2.8.1로 Scope Definition을 진행한다. 진행 중 workflow에 적용할 공식 지원 경로가 확인되거나 이번 workflow 종료 시 업데이트를 다시 검토한다. 재검증 완료 기한은 변경하지 않는다.
- 10월은 선정 공개 저장소의 동의 기반 실제 분석 → 경험 후보·근거·설명 초안 → Catch 확인과 별도 공개 선택 → 선택적 대표 구성 → 링크 발행·비로그인 열람을 완주한다. 대표 구성은 발행 필수 조건이 아니다. 실패·명시적 재요청·중복 방지·현재 권한·내부 품질·운영 중단/기록·NCP 수동 배포·영속/복구 검증을 임의 제외하지 않는다.
- Google 기본 로그인, GitHub 미연동 홈 진입 허용, 분석 요청 전 GitHub 연동 필요, 자산 GitHub 탭에서 저장소 선택·동의·분석 요청을 구분한다. 연동만으로 소유·커밋 관계 확인이나 분석 동의가 완료되지는 않는다. 탭 복귀는 조회이지 새 분석 요청이 아니다.
- 홈 분석 결과 상자·결과 단위 검토 집계는 제외하고 Catch별 상태를 유지한다. 링크 제목 필수·수신자 비표시, 공백 제거 후 유효 제목 중복 금지, 유효 링크 최대 5개, 사용자 단위 원자적 확인·생성, 요청마다 현재 권한 확인 및 수신 응답 캐시 금지 결정은 다시 묻지 않는다. 구현 방식은 미결이다.
- 이력서는 이 세션에서 확인한 **12월 PDF 업로드**를 유지한다. 12월 알림·DM·피드 등은 10월 구현 범위가 아니며 확장 제약만 후속 설계에 연결한다. 자동 CD는 제외하되 수동 배포 검증을 제외하지 않는다.

### C01/C02 제한적 재검증 — NFR3와 별도 기준

- **C02:** 후보 2~3건의 주장·근거·누락/잘림 대조, 최대 2시간. 신규 수집/복구 기능 개발 제외. 근거 부족 시 설명 제한/보류하며 사용할 후보가 확보되지 않으면 완료로 처리하지 않는다.

### 조건부 대안 적용 시 F·H·I·B 작업 순서·일정 영향

아래는 **정상 승인·관련 착수 조건 충족 후의 순서 제안**이다. 지금 인프라/서비스 구현을 시작하거나 다른 팀원에게 지원을 요청한 기록이 아니다. B가 팀원 1로 확정됐다는 뜻도 아니다.

1. **현재 검토 구간:** 각 영역이 자기 계약·상태·환경 요구 초안을 준비하고 연결 상대와 먼저 대조. ljm0850은 C01/C02 제출 결과 수용 검토와 F→E 입력/출력 경계를 우선 정리. H는 필요한 환경 요구/설정 목록만 준비하고 I는 쟁점·시험 목록을 취합. B 의존 부분은 가정/미결로 표시한다.
2. **대안 적용이 확인되면:** E/F/B 식별·결과 저장·공개 상태 계약을 먼저 합의. 팀원 1은 F의 실제 최소 결과 경로를 안정화한 뒤 **최소 B 서버·화면 연결을 순차 배치**하는 안을 기본 검토한다. F/B를 동시에 전담 구현하는 것으로 시간을 중복 계산하지 않는다. 지원이 확정되면 해당 조각만 분리할 수 있다.
3. **배포 준비를 마지막까지 미루지 않음:** H의 환경 요구·배포/복구 설계 검토는 앞에서 진행하되, 실제 자원 준비는 승인된 절차에 맞는 별도 작업 구간을 확보한다. F/B 작업 중 배포 장애가 발생하면 같은 사람의 일정에서 시간을 차감한다. 기존 단계 순서/승인 계획을 이 제안으로 바꾸지 않는다.
4. **연결·재시험:** B→C 연결과 NCP 전체 흐름을 검증하고 각 담당이 자기 결함을 수정한다. I는 취합·우선순위 조율이며 A/E/C/D의 구현·시험 대행이 아니다. H 복구 확인과 I 결함 재시험 시간을 기능 구현의 남는 시간으로만 취급하지 않는다.

**지원 필요 후보(미합의):** 팀원 2의 E↔B 저장/소유자 계약 대조는 본래 경계 검토이고 B 서버/시험 코드 작성은 추가 지원이다. 팀원 3의 D→B→C 이동 대조는 본래 경계 검토이고 B 화면 구현/상태 테스트는 추가 지원이다. 추가 지원을 받으려면 구체 결과물·시간·본래 A/E/C/D 지연 영향과 당사자 수용을 확인한다. 배포 재현·통합 재시험 보조도 필요할 수 있으나 담당/시간을 지정하지 않는다.

**일정 영향:** B를 맡을 사람이 있다는 조건부 대안은 실행 가능한 가용 시간이 확보됐다는 증거가 아니다. 지원 미확정 상태에서는 F→B→연결 검증이 팀원 1의 순차 경로가 되고 H/I 중단 대응·재시험이 더해져 10월 초 일정 위험이 증가한다. 현재 근거로 일수/시간을 확정하거나 4인 가용량·야근·연휴를 전제하지 않는다. 필요한 총량은 F 잔여 + 최소 B + H 실행/복구 + I 조율/재시험이며, 확인된 분담만 차감하고 학습·리뷰 시간을 중복 계산하지 않는다. 수용 불가하면 대표/부가 UI 후속화, 지원 재협의 또는 제공일 조정을 검토하되 핵심 흐름·보호/검증 조건을 자동 삭제하지 않는다.
