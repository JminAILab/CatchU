## 범위 구분

범위와 순서를 별도 축으로 관리한다. **첫 MVP 내 후행**은 완료 전 필수이고, **첫 MVP 완료 후 개발**은 첫 MVP 완료 조건에서 제외된 확정 후속 범위다. **후속 검토 후보**는 개발 약속이 아니다. 이후 개발일은 미정이며 ‘첫 MVP 이후’를 ‘반드시 10월 이후’로 바꾸지 않는다. [S4]

### 기본 링크의 열람·접근 기준

- **열람 대상:** 기본 프로필과 **사용자가 서비스에서 공개로 선택한 전역 공개 GitHub 자산·근거**. GitHub 저장소의 공개 상태는 분석 대상의 조건이지 자산 자동 공개 동의가 아니다. 링크별 전체 자산 선택 제한을 새로 도입하지 않는다. [FR3.1/3.2·FR4.1/4.2, S5]
- 생성·확인만으로 공개되지 않으며 미공개 자료는 본인만 확인한다. G 제외 상태에서 내부 선택 공유 예외 경로를 기본 허용하지 않는다. 숨긴 자산은 기존 링크에도 제외하며 요청마다 현재 권한을 검사하고 수신 응답을 캐시하지 않는다. [S3, S4]
- 제목은 필수·수신자에게 비표시, 공백 제거 후 유효 제목 중복 금지, 유효 링크 최대 5개. 사용자 단위 원자적 확인/생성으로 경합 시에도 제한을 지킨다. [S4]
- 사용자 링크 중단·발행 시점부터 **30일 고정 만료**·선택 비밀번호는 첫 MVP 필수다. 기본 발급 연결 다음에 구현할 수 있으나 완료 후로 미루지 않는다. 중단/만료 URL 재전달도 열람 거부, 비밀번호 설정 시 올바른 값 필요·미설정 시 요구하지 않음. 만료 검증은 시간을 제어한 시험으로 가능하다. [FR4.3~4.5]
- 링크 중단 자체는 자산 삭제/전역 숨김이 아니다. 원본 저장소 비공개 전환이 확인되면 관련 Catch에 비공개와 같은 보호를 적용하고 일시 장애·관계없는 자료 전체 중단과 구분한다. [FR1.5·FR4.3]

C01은 검사한 사례의 무근거 단정·오귀속·금지 누출 미발견, 충분근거에서 근거와 연결된 실제 변경/기여 설명이 있는 **사실 수정 없이 활용 가능한 짧은 초안**을 확인한다. 문장 취향/풍부함의 무수정을 요구하지 않으며 모든 내용을 확인 불가로 처리하면 성공이 아니다. 미관측 사실은 ‘제공된 발췌에서 확인할 수 없음’으로 제한한다. 사람 수정은 모델 원생성 성공이 아니며 회귀와 새 사례 전이를 구분한다. 제한 사례 결과를 서비스 전체 오류 0건으로 일반화하지 않는다. [S4]
