# #123 공개 선택·링크 수신자 열람 화면 통합 검사

본인 결과 진입 → 근거 확인 → 별도 공개 → 링크 수신자 열람이 화면 코드와 API·DB에서 함께 맞게 도는지 보는 검사의 실행 안내다. 실행 결과는 이 문서에 두지 않고 검증한 PR에 판본별로 기록한다. 이슈는 [#123](https://github.com/JminAILab/CatchU/issues/123), 기대 결과의 기준은 [통합 검증표 마~사](../../docs/CatchU_integration_rows_sharing.md)와 [가~라](../../docs/CatchU_integration_rows_intake.md)의 IV-21·IV-23·IV-24다.

## 무엇이 실제이고 무엇이 대역인가

| 부분 | 이 검사에서 |
|---|---|
| web 화면 코드 | 실제. 자동 검사는 화면이 쓰는 상태·호출 코드(저장소 연결 관리·내 자산·공유 링크·수신자)를 그대로 부른다. 화면 그리기는 수동 브라우저 확인에서 본다 |
| api·DB | 실제. Nest HTTP와 PostgreSQL 테스트 DB |
| 로그인 | 개발용 로그인. 실제 Google 로그인은 범위 밖(IV-37) |
| 분석 결과 | [#103 공용 합성 결과](../../worker/fixtures/m1-synthetic/README.md)를 실제 접수 요청에 개발 주입으로 넣는다. worker·큐·GitHub는 쓰지 않는다. 실제 분석은 범위 밖(IV-38) |
| 만료 | 30일을 기다리지 않고 링크의 발급·만료 시각을 DB에서 함께 과거로 옮긴다 |
| 조회 실패 | 시험이 응답을 500이나 통신 실패로 바꿔 만든다(**실패 대역**). 이 사례만으로는 실제 연결 통과로 세지 않는다 |

시험 앱 조립은 #114 연결 시험과 같은 [`test/helpers/intake-app.cjs`](../test/helpers/intake-app.cjs)를 쓴다. Catch가 두 개 필요한 사례는 #103 `two-candidates-same-work`의 둘째 후보 작업 식별만 시험 안에서 바꿔 만든다(공용 자료 파일은 고치지 않는다).

## 사례와 완료 기준

자동 검사 파일은 [`test/integration/sharing-screen-web.test.cjs`](../test/integration/sharing-screen-web.test.cjs)다. 시험 이름 앞의 [실제 HTTP·DB]·[실패 대역]이 구간이다.

| 자동 시험 | #123 완료 기준 | 검증표 행 |
|---|---|---|
| 상태 응답의 `ownerResultsReady`·등록 Catch로만 결과에 들어가고 처음 Catch는 비공개 | 본인 결과 진입, 최초 PRIVATE | IV-24·IV-25, IV-21의 정상 0건 |
| 확인·불일치 표시만으로는 공개되지 않고 별도 공개한 Catch만 보이며 숨기면 다음 요청부터 막힘 | 확인만으로 비공개, 별도 공개만 수신자에 보임, 숨김 뒤 차단, 본인용 질문·내부 식별자 미노출 | IV-26·IV-27·IV-28·IV-31·IV-32 |
| 타인·없는 Catch와 없음·중단·만료 링크는 각각 같은 공통 거부 | 타인/없는 자료와 링크 없음·중단·만료의 공통 거부 | IV-23(화면 몫)·IV-31·IV-33 |
| 비밀번호 미입력·잘못된 값·올바른 값, grant로 중단·만료·다른 링크를 넘지 못함 | 비밀번호 분기와 grant 우회 불가 | IV-34 |
| [실패 대역] 조회 실패가 0건·링크 불가·새 분석 요청으로 바뀌지 않음 | 정상 빈 자료와 조회 실패 구분 | IV-21(화면 몫)·IV-31 |

수동 브라우저 확인은 같은 흐름을 실제 화면으로 한 번 따라가 화면 문구와 이동을 본다(아래 「수동 브라우저 확인」).

## M1 최소 연결 증거와 전체 MVP 남은 항목

- **M1 최소 연결:** 결과 진입(IV-24), 최초 비공개·확인만으로 비공개·별도 공개·숨김(IV-25~28), 링크 발급(IV-29의 발급만), 수신자 목록·상세(IV-31), 수신자에게 나가지 않는 정보(IV-32). 위 표의 앞 두 자동 시험과 수동 확인의 1~5단계가 이 증거다.
- **이 검사에서 함께 보는 전체 MVP 항목:** 링크 없음·중단·만료(IV-33), 비밀번호와 grant(IV-34), 조회 실패 구분.
- **이 검사로 보지 않는 항목:** 발급 제한·제목 중복·재전송(IV-29 나머지·IV-30, [#149 검사](share-links-integration-149.md)), 링크 중단 요청의 답(IV-40), 숨기기 전에 받은 다음 페이지 커서(IV-28의 일부, 공개 Catch 21개 이상 필요), 원본 보호(IV-35·IV-36, 10월에는 만드는 경로 없음), 실제 로그인·실제 분석·배포 환경(IV-37~39).

## 자동 검사 실행

[api README 「DB 테스트」](../README.md#db-테스트)대로 테스트 DB를 띄운 뒤 `api` 폴더에서 실행한다. 일반 `npm test`도 이 파일을 찾는다.

```powershell
npm ci
npm test -- test/integration/sharing-screen-web.test.cjs
```

같은 테스트 DB에서 다른 `npm test`나 아래 수동 도구를 동시에 돌리지 않는다(시험마다 표를 비운다).

## 수동 브라우저 확인

자동 검사를 한 번 돌려 테스트 DB에 마이그레이션을 적용한 뒤, 창 두 개에서 실행한다. 도구는 테스트 DB의 표를 비우고 시작하며 api를 3432 포트에 연다.

```powershell
# 창 1: api 폴더
npm run build
node scripts/verify-sharing-screen-browser.cjs
```

```powershell
# 창 2: web 폴더
npm ci
$env:NEXT_PUBLIC_API_BASE_URL='http://127.0.0.1:3432'
$env:NEXT_PUBLIC_DEV_LOGIN_ENABLED='true'
npm run dev
```

창 1에 `{"kind":"ready",...,"ownerCatches":2,"emptyCatches":0}`이 나오면 `http://localhost:3000/login?next=%2Fassets`를 연다. 토큰은 메모리에만 있으므로 로그인 뒤에는 주소창 대신 화면의 버튼·메뉴로 이동한다.

| 단계 | 조작 | 기대 화면 |
|---|---|---|
| 1 | `verify-123-owner`로 개발용 로그인 → 표시 이름 저장 → 내 자산 → [연결 관리] → 연결된 저장소 줄 | ‘성공’, ‘Catch 2개가 준비되었습니다’, [이 저장소 Catch 보기] |
| 2 | [이 저장소 Catch 보기] | 저장소로 거른 목록에 Catch 2개, 둘 다 ‘확인 전’·‘미공개’ |
| 3 | 한 Catch 상세 → 두 확인 체크 → [확인 완료] | 근거·기여·본인용 질문이 보이고, 확인 뒤에도 ‘미공개’ |
| 4 | [지금 공개] → 공유 링크 → 비밀번호를 켜고 링크 발행 | 버튼이 [숨기기]로 바뀜, 발행 완료에 URL·‘비밀번호 설정됨’ |
| 5 | 다른 탭에서 링크 URL → 빈 값 → 틀린 값 → 맞는 값 | ‘비밀번호를 입력해 주세요’ → ‘비밀번호가 맞지 않습니다’ → 공개한 Catch 1개만 보이는 목록. 상세에 본인용 질문이 없음 |
| 6 | 회원 탭에서 그 Catch [숨기기] → 수신자 탭 상세 새로고침 → [공개 자료 목록으로] | ‘현재 열람할 수 없는 자료입니다’ → ‘현재 열람할 수 있는 공개 GitHub 자산이 없습니다’ |
| 7 | 공유 링크에서 [링크 중단] → 수신자 탭 새로고침, 없는 링크 주소 열기 | 둘 다 ‘이 링크는 열람할 수 없습니다’ |
| 8 | 새 탭에서 `verify-123-empty`로 로그인 → 내 자산 → [연결 관리] | ‘아직 표시할 Catch가 없습니다’, ‘검토할 Catch가 없습니다’, [Catch 보기] 없음 |
| 9 | 창 1을 끈 뒤 [상태 새로고침]·창 닫기, 수신자 탭 새로고침 | ‘저장소 상태를 불러오지 못했습니다. 분석이 실패한 것은 아닙니다’, ‘Catch 목록을 불러오지 못했습니다’, ‘자료를 불러오지 못했습니다’. 0건·링크 불가로 보이지 않음 |

9단계는 api를 끈 실제 통신 실패다. 만료(IV-33)는 화면에서 시각을 바꿀 수 없어 자동 검사로만 본다. 도구 출력에는 식별 문자열과 Catch 수만 나오며 토큰·비밀번호·내부 식별자는 나오지 않는다.

## 결과 기록 방법

PR(또는 검증만 한 경우 이슈 댓글)에 판본(커밋), 실행 환경(OS·Node·PostgreSQL), 자동 검사 통과 수, 수동 단계별 결과, 발견한 결함과 연결한 담당 이슈를 적는다. 대역 구간을 쓴 사례는 그 사실을 결과 옆에 적는다.
