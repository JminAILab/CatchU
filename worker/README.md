# worker — 수집·분석 처리

FastAPI 기반으로 GitHub 자료 수집·근거·경험 후보·짧은 설명 초안·최소 생각해볼 질문 생성을 맡는다. 시간이 걸리는 외부 호출과 분석 처리를 API의 사용자 요청 처리와 분리한다. 세부 범위는 [MVP 범위 문서](../aidlc/spaces/default/intents/260914-catchu-october-mvp/ideation/scope-definition/scope-document.md)와 해당 작업의 합의된 기준을 확인한다.

> **초기화 전 준비안:** 아래는 준비·검증할 항목이며, 실행 가능한 명령이나 검사 통과 기록이 아니다. 초기화 후 실제 설정과 확인 결과에 맞춰 이 README를 갱신한다.

## 작업 시작

- [공통 작업관리](../docs/CatchU_작업관리.md)를 읽고 해당 이슈의 범위·완료 기준·관련 계약을 확인한다.
- worker 초기화와 분석 기능 구현은 완료 기준을 구분한다. 연결하는 API 기능·공통 환경의 책임까지 초기화 담당자에게 자동 배정하지 않는다.
- 착수·브랜치·기술·검사 기준은 [코딩 운영](../docs/CatchU_작업관리.md#코딩-운영)을 따른다. [아키텍처 검토초안 PR #70](https://github.com/JminAILab/CatchU/pull/70)은 API↔worker 결과 전달의 설계 입력이다.

## 실행·검증 준비 항목

초기화 시 사용할 도구와 명령을 정하고, 작업 디렉터리·필요 환경·성공 확인 방법을 함께 기록한다. 기능 검사에는 이슈 완료 기준에서 확인한 기대 결과를 사용한다.

| 구분 | 준비하고 확인할 내용 |
|---|---|
| 설치 | Python·FastAPI 버전, 가상환경 생성·활성화·의존성 설치와 재현 방법. 가상환경·의존성 관리 도구는 미정 |
| 개발 실행 | 서버·작업 처리 경로의 시작·종료, 정상 시작 확인, 작업에 필요한 API·큐·외부 서비스 설정 |
| 정적·타입 검사 | 채택한 정적 검사와, 채택하는 경우 타입 검사. 도구·적용 범위·실제 명령은 초기화에서 확정 |
| 관련 단위 테스트 | 변경한 자료 파싱·근거 처리·결과 형식·실패 처리. 외부 응답은 필요한 범위에서 모의 처리 |
| 관련 통합 테스트 | API와 합의한 작업·결과 계약, 중복·실패 처리. 실제 큐·외부 호출과 모의 대체 대상을 구분 |
| 실행 가능성 확인 | 필요한 모듈 로드, 서버 시작, 합의한 작은 작업의 처리 경로 확인. JavaScript 서비스와 같은 빌드 방식을 강제하지 않음 |

가상환경 준비도 실행 안내에 포함한다. 실제 GitHub·LLM 호출 검증은 일반 로컬 검사와 구분하고, 해당 작업의 자료·계정·호출 허용 범위를 먼저 확인한다. 모의 응답으로 처리 경로를 확인한 것을 실제 분석 성공으로 기록하지 않는다.

## 아직 필요한 입력

| 필요한 입력 | 결정할 곳 | 결정 전 가능한 작업 |
|---|---|---|
| Python·FastAPI 버전, 가상환경·의존성 관리, 검사·테스트 도구 | worker 초기화 이슈·PR에서 제안, 공통 설정 영향은 공통 준비 담당과 조율 | 기존 파일과 제약 확인, 도구·설정 제안 |
| 큐 선정·버전, 작업 수신·상태 전달·결과 계약 | PR #70의 검증 과제와 후속 계약; 연결 쟁점은 [#23](https://github.com/JminAILab/CatchU/issues/23) | 요청·처리·완료·실패의 의미와 질문 정리 |
| 결과 보존·전달과 API의 결과 반영 경계 | E·B·F 연결 계약과 실제 기능 담당자 간 합의 | 결과 형식·중복·유실·실패 사례 초안. 저장·상태 반영 책임을 임의 배정하지 않음 |
| GitHub 수집 방식, 서비스 모델·외부 호출 환경, 토큰 전달 | 후속 설계와 관련 착수·자료 처리 조건 | 필요한 권한·설정·보호 항목 정리, 허용된 범위의 모의 자료 준비 |
| API·큐·결과 저장소 등 로컬·통합 환경 | 관련 계약과 공통 환경 준비 작업 | 접속·실행 조건과 환경 요구 정리 |

## 초기화 후 이 README에 채울 안내

- 가상환경 생성·활성화·의존성 설치·실행·검사 명령과 각각의 실행 위치, 필요한 버전.
- 환경변수 이름·용도·준비 경로와 비밀값 없는 `.env.example`, 필요한 공통 환경 안내 링크.
- 정상 시작·작업 처리 확인 방법, 종료 방법, 흔한 실패의 확인 위치.
- 모의 분석과 허용된 실제 분석을 구분하는 실행 조건과 확인 범위.
- 가상환경·임시 자료·결과를 지우는 명령이 있다면 삭제 대상과 다시 준비할 항목.

주요 작업 단계와 실제 완료·실패를 로그로 확인할 수 있게 준비한다. Python 데코레이터는 구현 선택지이며 모든 함수에 적용하지 않는다. 기록·공유 시 자료 보호와 예외 처리 원칙은 공통 작업관리를 따른다.

개발 준비 완료는 공통 작업관리의 확인 목록으로 판단한다. 확인한 사람·환경·기준 커밋, 작성자 외 재현 여부와 실제·모의 연결 범위는 초기화 이슈·PR에 남긴다. 로컬 실행 확인과 NCP 배포 검증은 각각 기록한다.
