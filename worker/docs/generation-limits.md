# 생성 호출 한도와 운영 로그 — #120

> [설명 초안·생각해볼 질문·Catch 제목 생성](generation.md)의 「호출 한도와 시간」·「운영 로그」 절을 문서 크기 상한(36 KB) 때문에 따로 옮겼다. 말뜻(생성 호출·고쳐 쓰기·재료 등)은 그 문서를 따른다. 코드는 `app/generation/limits.py`(상한)와 `app/generation/flow.py`(운영 로그)에 있다.

## 호출 한도와 시간

| 항목 | 값 |
|---|---|
| 생성 호출 | 후보당 1회, 요청당 200회(2026-10-17 팀장 결정, 아래 「요청당 200회의 근거」) |
| 고쳐 쓰기 호출 | 제목당 3회(팀장 결정, 설정으로 늘릴 수 없음), 요청당 20회. 생성 호출 상한과 따로 센다 |
| 호출마다 시간 제한 | 생성 45초, 고쳐 쓰기 20초. 마감까지 남은 시간이 이보다 적으면 새 호출을 시작하지 않는다(생성 호출은 크기 선별 전과 호출 직전에 두 번 본다) |
| 입력 | 자료(직렬화한 UTF-8) 24,000 B, 지시문 포함 32,000 B |
| 출력 | 4,000 B. 넘으면 해석하지 않는다 |
| 고쳐 쓰기 입력 | 첫 호출에서 보낸 고를 수 있는 줄 최대 20줄 |
| 설명 조각·질문 | 각 1~3개 |
| 제목·질문·코드 이름 | 40자·150자·64자 |
| 줄마다 싣는 고를 수 있는 이름(`names`) | 최대 12개, 나온 순서대로 |

제목당 고쳐 쓰기 3회와 요청당 생성 호출 200회 말고는 실측 전 제안값이다.

생성은 후보 근거에 든 본인 커밋의 가장 최근 작성 시각이 늦은 후보부터 하고, 같으면 그 커밋 SHA순, 그것도 같으면 결과 순서다(결정 9·14). 이 순서는 호출 우선순위에만 쓰고 결과의 후보·근거 순서는 바꾸지 않는다. 작성 시각은 커밋한 사람이 정할 수 있는 값이라 드물게 실제와 다를 수 있지만, 한도에 걸릴 때의 순서에만 쓰인다.

### 요청당 200회의 근거

- 2026-10-16 로컬 실제 연결 2건([#121](https://github.com/JminAILab/CatchU/issues/121) ③ 1단계, `claude-haiku-5-5`)에서 생성 호출은 평균 1.48초, 가장 길어도 2.42초였다. PR 없이 직접 올린 커밋만 있는 저장소는 후보 159건 가운데 처음 상한(40회)만큼만 생성해 119건이 설명·질문 없이 등록됐고 요청은 `PARTIAL_FAILED`였다. 후보가 있는 부분 실패는 다시 요청해 보완할 수 없다.
- 후보는 지금 변경 내용을 받은 본인 커밋에서 나온다(수집의 상세 조회 상한 200건, [수집](github-collection.md)). 커밋을 경로로 나누는 일은 아직 없어([한계 L8](candidate-checks.md#알려진-한계)) 200회면 대부분의 요청이 모든 후보를 생성한다. 넘으면 지금처럼 최근 후보부터 생성하고, 나머지는 미생성으로 두며 요청에 `ANALYSIS` 실패 1건을 더한다.
- 시간은 횟수와 따로 지킨다. 마감까지 호출 시간 제한만큼 남지 않으면 새 호출을 시작하지 않으므로 상한을 올려도 요청 마감을 넘기지 않는다. 실측 평균이면 159회가 약 4분이다.
- 비용: 호출마다 입력·출력 상한을 채우고 1바이트를 1토큰으로 본 최악 계산(미국 고정 1.1배)으로, 생성 호출이 Sonnet 5.5(아래 「모델」)이면 분석 1건 약 $23 이하다(생성 200회 약 $22.9 + Haiku 고쳐 쓰기 20회 약 $0.11). Haiku 5.5였다면 약 $1.26, 처음 상한 40회의 Haiku는 약 $0.34였다([#119 결정](https://github.com/JminAILab/CatchU/issues/119#issuecomment-6159097353)). 실측으로는 실제 팀 프로젝트(후보 46건)가 Sonnet으로 $0.73이다.
- 수집 단계의 GitHub 호출 상한(300회)·응답 크기 상한은 생성 상한의 근거가 아니다. 요청 전체 시간 상한은 #121이 정해 넘긴다.

## 모델

생성 호출은 `claude-sonnet-5-5`, 제목 고쳐 쓰기는 `claude-haiku-5-5`다(2026-10-18 팀장 결정, [생성의 실제 제공자](generation-provider.md)). [#119 결정](https://github.com/JminAILab/CatchU/issues/119#issuecomment-6159097353)의 「호출 종류별 모델」이 정한 대로 대표 사례를 두 모델로 한 번씩 돌려 비교했다(2026-10-16~18 로컬 시험대, 팀장 저장소, 같은 수집 결과·같은 입력, 2026-10-18 처방 전 판본).

| 저장소 | 후보 | 설명·질문 실패 Haiku | 설명·질문 실패 Sonnet | 호출 평균 Haiku·Sonnet | 분석 1건 비용 Haiku·Sonnet |
|---|---|---|---|---|---|
| 실제 팀 프로젝트(Java·Vue, 본인 커밋 124) | 46 | 30/92(32.6%) | 5/92(5.4%) | 1.6초·3.3초 | $0.04·$0.73 |
| 알고리즘 풀이(직접 push 커밋 602) | 159 | 27/318(8.5%) | 10/318(3.1%) | 1.6초·2.9초 | $0.06·$1.24 |
| 시험용 작은 저장소(PR·이슈) | 6 | 3/12 | 1/12 | 1.4초·2.4초 | $0.002·$0.035 |

- Sonnet은 실패율이 Haiku의 절반 이하이고 요청 마감(20분) 안에 끝나, #119의 "Sonnet이 분명히 나을 때만 바꾼다"를 채웠다. 알고리즘 풀이 저장소는 짧은 새 파일 추가가 대부분이라 실제 프로젝트보다 Haiku가 좋아 보였다.
- 처방 전 실패 원인은 Haiku가 이름 모양 위반·이름이 그 줄에 없음·조각 개수 위반·응답 읽기 실패, Sonnet이 이름이 그 줄에 없음뿐이었다. 그래서 줄마다 이름 목록을 함께 보낸다([생성 「응답과 판정」](generation.md#응답과-판정)).
- 판단 근거는 팀장 저장소 3개뿐이다. 실제 서비스 결과의 품질 판정은 [#122](https://github.com/JminAILab/CatchU/issues/122)다.

## 운영 로그

요청마다 한 줄(`app.generation.flow`, 「생성 종료」)에 건수만 남긴다: 후보·생성 호출·고쳐 쓰기 호출 수, 재료 없음·예산 부족·전체 실패 후보 수, 설명 생성·설명 실패·질문 실패 수, 설명이 생성됐는데 제목만 null인 후보 수(`titleOnlyNull`, #122 검수용), 고쳐 쓴 제목 수, 가린 값·비밀 파일 수(호출 여부와 관계없이 입력을 준비할 때 센 수), 가리기 뒤 재료가 0개가 된 후보 수, 크기·잘림 문구를 붙인 커밋 수, 응답의 모르는 최상위 키 수. SHA·경로·이름·제목·본문·응답 원문·가린 값은 남기지 않는다. 예산 부족 후보가 있으면 경고 수준이다.

같은 줄에 실패 원인별 건수를 `wholeReasons`·`draftReasons`·`reflectionReasons`로 남긴다(2026-10-17, 검증 실패의 원인을 나눠 보려고 더함). 값은 `원인 코드:건수`를 코드순으로 쉼표로 이은 것이고, 없으면 `-`다. 전체 호출 실패는 실패 코드(`GENERATION_TIMEOUT` 등)로, 설명·질문 실패는 그 부분이 실패한 첫 원인 하나로 센다. 그래서 설명 실패 수는 전체 호출 실패 수와 `draftReasons` 합을 더한 값이고, 질문도 같다. 원인 코드는 로그에만 쓰고 실패 코드·회원 문구는 그대로다. 제목 확인 실패(null)는 실패가 아니라 원인을 세지 않는다.

| 원인 코드 | 실패 코드 | 뜻 |
|---|---|---|
| `COUNT` | `GENERATION_RULE_VIOLATION` | 조각·질문이 목록이 아니거나 개수가 1~3개가 아님 |
| `ITEM_SHAPE` | `GENERATION_RULE_VIOLATION` | 항목 모양·종류 값·키 위반 |
| `NAME_SHAPE` | `GENERATION_RULE_VIOLATION` | 코드 이름이 식별자 하나의 모양이 아님 |
| `DUPLICATE_TYPE` | `GENERATION_RULE_VIOLATION` | 같은 종류 질문이 둘 이상 |
| `TOO_LONG` | `GENERATION_RULE_VIOLATION` | 파일 이름으로 줄여도 질문이 글자 상한을 넘음 |
| `UNKNOWN_LINE`·`UNKNOWN_FILE` | `GENERATION_UNVERIFIED` | 그 호출에서 보낸 자료에 없는 줄·파일 id |
| `MASKED_LINE` | `GENERATION_UNVERIFIED` | 가린 줄을 지목 |
| `NAME_MISSING` | `GENERATION_UNVERIFIED` | 이름이 그 줄에 없음 |
| `NAME_JOINED_ASCII` | `GENERATION_UNVERIFIED` | 이름이 그 줄에 영문자·숫자·밑줄·`$`와 붙어서만 있음(`loginRateLimit` 줄의 `limit`) |
| `NAME_JOINED_NON_ASCII` | `GENERATION_UNVERIFIED` | 이름이 한글 등 ASCII 밖 글자와 붙어서만 있음(「limit을」) |
| `KIND_MISMATCH` | `GENERATION_UNVERIFIED` | 추가 줄 조각으로 삭제 줄을 지목(또는 반대) |
| `NO_TEMPLATE` | `GENERATION_UNVERIFIED` | 지목한 파일 상태에 맞는 문장 틀이 없음 |
