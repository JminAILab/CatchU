# 후보 문장과 근거 — #118

> [후보 묶음과 작업 동일성](candidate-decision.md)의 「후보 내용」·「생성 단계(#120)가 이어 붙일 곳」 절을 문서 크기 상한(36 KB) 때문에 따로 옮겼다. 말뜻(연동 계정·본인 커밋·연결 PR 조회 등)은 그 문서를 따른다.

[#118](https://github.com/JminAILab/CatchU/issues/118)이 후보마다 만드는 작업 사실(`workFacts`), 나의 기여(`subjectContribution`), 묶음 설명(`groupingBasis`)과 한계(`groupingLimitations`), 근거(`evidence`)의 규칙이다. 숫자·근거 순서·제목은 2026-10-08 팀장 결정을 따른다([결정 문서](../../docs/ai-dlc-input-mvp/2026-10-08_catch-decisions.md)). 코드는 `app/candidates/build.py`에 있다.

## 후보 내용

- 문장에는 구조 값(번호·SHA 앞 12자·상태)만 쓴다. 제목·본문·커밋 메시지·브랜치 이름·파일 경로는 넣지 않는다. 연결 PR 조회·API 같은 조회 방식의 말도 쓰지 않는다. 본인 기여는 '작성한'이 아니라 '작성자로 기록된' 커밋으로 적는다([결정 문서 「본인 기여의 뜻」](../../docs/ai-dlc-input-mvp/2026-10-08_catch-decisions.md#본인-기여의-뜻)).
- **센 숫자를 쓰지 않는다**([결정 문서 「수신자에게 나가는 숫자와 근거 순서」](../../docs/ai-dlc-input-mvp/2026-10-08_catch-decisions.md#수신자에게-나가는-숫자와-근거-순서)). 작업 사실과 나의 기여에는 CatchU가 센 숫자(몇 건 중 몇 건, 줄 수 합계, 본인 커밋 수)를 넣지 않는다. 근거 한계에 든 본인 커밋 수도 센 수 대신 정해 둔 상한 값이나 '일부'로 쓴다. 그 커밋의 파일·줄 수, PR 커밋 수 같은 원본 숫자는 근거의 관측 사실(`representedFacts`)에 남는다. 링크를 열기 전에 작은 수정과 대량 생성을 가를 단서이기 때문이다. 묶음 설명은 이 결정의 범위(제목·작업 사실·나의 기여) 밖이라 「다른 PR에 배정한 변경 N건」 같은 판정 설명의 수가 남는다.
- **작업 사실 첫 항목은 단위 이름이다**: 「PR #7, 상태 병합됨」, 「PR 없이 병합한 병합 커밋 {SHA 앞 12자}」, 「PR·병합에 속하지 않은 본인 커밋 {SHA 앞 12자}」, 여러 커밋이면 「PR·병합에 속하지 않은 본인 커밋 묶음(가장 최근 커밋 {SHA 앞 12자})」이다. PR 조회가 허용되지 않은 요청에서는 「병합에 속하지 않은」이다. 나눈 부분은 「PR #7에서 나눈 부분(가리키는 이슈 #5)」이 맨 앞에 온다. 후보마다 다르므로 아래 「제목」의 임시 대체값이 겹치지 않는다.
- **다른 계정 커밋이 섞였는지**: PR·PR 없는 병합은 작업 사실 둘째 항목에 숫자 없이 적는다. 주어는 '연동 계정이 작성자로 기록되지 않은 커밋'이고 「있다」·「없다」·「있는지 알 수 없다」 가운데 하나다. 범위는 PR이면 그 PR 커밋 목록 전체(병합 커밋 포함), PR 없는 병합이면 그 병합이 들인 커밋 전체(흡수분을 빼고 경계 비교를 반영, 병합 커밋 자신은 뺌)다. GitHub가 작성자를 계정과 연결하지 못한 커밋도 기록되지 않은 쪽이다. '없다'는 목록을 끝까지 받았을 때만 쓴다. PR 커밋 목록을 받지 못했거나 덜 받았는데 다른 계정 커밋을 보지 못했으면 「있는지 알 수 없다(목록을 끝까지 확인하지 못함)」다. 나눈 부분도 단위 전체 값을 쓴다. 커밋 묶음에는 이 문장이 없다.
- **나의 기여**는 「연동 GitHub 계정이 작성자로 기록된 커밋」이다. PR이면 괄호에 PR을 연 계정의 문맥(「연동 계정이 연 PR」, 「다른 계정이 연 PR에 담긴 본인 커밋」, 「PR을 연 계정은 확인하지 못함」)을 적는다. 기여 커밋이 단위 안에 없고 같은 변경으로 다른 곳에서 배정됐으면, 또는 둘이 섞였으면 괄호에 그 사실을 숫자 없이 적는다(PR 없는 병합도 같다).
- **묶음 설명**은 판정에 실제로 쓴 근거만 적는다. PR은 소속을 확인한 근거(PR 커밋 목록, 병합된 PR이 기준 브랜치에 남긴 커밋, GitHub가 알려 준 커밋의 PR)를, 커밋 묶음은 부모·변경 파일 겹침으로 이었는지와 같은 변경(cherry-pick 표시와 같은 변경 내용)으로 이었는지를 쓴 것만 적는다. 커밋 묶음에는 작성 시각과 메시지는 보지 않았다고 적는다.
- **근거 순서**: PR·병합 단위는 그 단위 근거(PR, 또는 병합 커밋)가 먼저 오고, 그다음 본인 기여 커밋이 최근 것(작성 시각, 같으면 SHA순)부터 최대 20건 온다. 커밋 묶음은 본인 커밋이 최근 것부터 온다. 이슈 조회가 허용된 요청이면 그 뒤에, 본인 기여 커밋 메시지가 가리킨 이슈 가운데 이슈 목록으로 수집한 것의 근거가 번호순으로 온다. 같은 이슈를 가리킨 서로 다른 작업이면 후보마다 따로 들어간다(사례 C6). 결정이 정한 단위 근거·본인 커밋의 순서를 바꾸지 않으려고 맨 뒤에 둔다. B는 이 순서대로 보인다. 20건을 넘으면 「본인 커밋이 20건을 넘어 최근 20건만 근거로 담았다」를 단위 근거(커밋 묶음은 맨 앞 커밋 근거)에 붙인다. 커밋 묶음의 값은 SHA 전체로 만드므로 20건을 넘으면 값을 이루는 SHA가 근거에 다 나오지는 않는다. 계약(메시지 스키마 v1)에는 근거 개수 상한이 없고, 기준 문서 「#118이 지킬 것과 시험할 것」 9번이 대표 근거만 둘지를 #118에 맡겼다. 20건은 실측 전 제안값이다.
- **근거의 귀속 범위**(`contributionScope`): 본인 커밋은 「연동 계정이 작성자로 기록된 커밋」이고, 같은 변경으로 다른 곳에서 배정한 커밋이면 그 사실을 괄호로 덧붙인다. PR은 「연동 계정이 연 PR(본인 기여는 이 PR의 본인 커밋에 한정)」처럼 PR을 연 계정과 기여 범위를 적는다. 병합 커밋은 병합 커밋 자체를 변경으로 세지 않는다고 적는다. 이슈는 「이 작업에서 연동 계정이 작성자로 기록된 커밋이 가리킨 이슈(이슈를 쓰거나 논의한 것은 본인 기여로 보지 않음)」다.
- **값이 같은 후보**: 한 결과에 값이 같은 후보가 생기면(생기면 안 된다) 첫 후보에 합친다. B가 두 번째 후보의 내용을 저장하지 않기 때문이다. 작업 사실·묶음 한계는 순서를 지켜 합친다. 출처·판본이 같은 근거는 하나로 두되 관측 사실과 한계를 합치고, 귀속 범위가 다르면 첫 범위를 두고 「같은 근거를 다른 귀속 범위로도 담았다」를 한계로 남긴다. 합친 근거는 단위 근거 먼저, 본인 커밋 근거를 최근 것부터, 이슈 근거를 맨 뒤에 다시 놓는다. 경고 로그를 남긴다(`sameIdentityMerged`).
- **후보 순서**: PR 번호순, 그다음 병합 SHA순, 그다음 커밋 묶음의 첫 SHA순. 나눈 부분은 가장 작은 SHA순이다.

## 제목

#118은 제목을 만들지 않는다(후보의 `title`은 `None`). 제목은 [#120](https://github.com/JminAILab/CatchU/issues/120)이 설명 초안과 같은 생성에서 확인할 수 있는 조각(대상·종류·동작)으로만 만들고, 만들 수 없으면 null이다([결정 문서 「Catch 제목」](../../docs/ai-dlc-input-mvp/2026-10-08_catch-decisions.md#catch-제목)).

지금 계약과 B·C·E는 빈 제목을 받지 않는다. 그래서 결과 조합(`app/processing/result.py`)이 제목이 없는 후보에 작업 사실 첫 항목을 넣는다. 이것은 계약 정정과 B·C·E 수정이 병합된 뒤 빼는 임시 동작이다(결정 문서 「[담당과 순서](../../docs/ai-dlc-input-mvp/2026-10-08_catch-decisions.md#담당과-순서)」 ③).

## 생성 단계(#120)가 이어 붙일 곳

- 바꿀 칸: 각 `EligibleCandidate`의 `draft`(지금 `DraftOutcome.not_generated()`), `reflection`(지금 `ReflectionOutcome.not_generated()`), `title`(지금 `None`). `work_identity`·`work_facts`·`subject_contribution`·`grouping_basis`·`grouping_limitations`·`evidence`와 후보 순서는 바꾸지 않는다.
- 대조 기준: 제목과 설명 초안은 근거가 가리키는 연동 계정 커밋의 추가·삭제 줄과 변경 파일(경로·상태)로만 확인한다. 바뀌지 않은 문맥 줄, 다른 계정 커밋, PR 본문, 커밋 메시지는 쓰지 않는다. 변경 내용(`patch`)이 없거나 잘렸으면 제목은 null이다(결정 문서 「Catch 제목」의 확인 기준).
- 실패: 초안·질문 실패는 후보를 두고 `DraftOutcome.failed`·`ReflectionOutcome.failed`로 적는다. 결과 조합이 `failures`에 더한다. 초안이 나왔는데 제목만 null이면 실패가 아니다(결정 문서).
- 재료를 얻는 길(지금 제안): 후보에는 커밋 메시지·PR 제목·본문·변경 내용을 넣지 않았다. 같은 수집 결과로 `group(outcome)`을 다시 불러 `Grouping.units`·`commits`를 얻는다. 단위와 후보는 `work_identity(request.source_mode, request.repository_id, unit.unit, unit.parts)` 값으로 맞춘다(후보가 되지 않은 단위가 있어 순서로는 맞추지 않는다). 근거가 가리키는 본인 커밋은 근거의 판본(`source_revision`, 커밋은 SHA)으로 찾고, 그 커밋 기록의 `changes.files`에 경로·상태·`patch`가 있다. 후보에 내부 값을 더할지는 #120에서 정한다. 원문은 신뢰할 수 없는 자료로 다룬다([보안 점검](../../docs/CatchU_security_checks.md)).
