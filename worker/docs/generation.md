# 설명 초안·생각해볼 질문·Catch 제목 생성 — #120

> AI 쪽(CR3: Claude가 쓰는 제목 후보·설명 문장과 판정)이 켜졌을 때의 생성·판정·적용 규칙은 [판정](generation-judgement.md)에 있다. 이 문서는 AI 쪽이 꺼진 경로다.
>
> [#120](https://github.com/JminAILab/CatchU/issues/120)의 첫 범위(후보 입력 어댑터와 제공자 비종속 생성 모듈)를 합성 제공자로 구현한 내용이다. 실제 제공자 어댑터는 [생성의 실제 제공자](generation-provider.md)에 있다. 실제 호출 확인과 품질 확인, 처리 순서에 잇는 전체 조립, 결과의 제목 null 전달은 아직 아니다(맨 아래 「남은 연결」). 후보 문장·근거의 규칙은 [후보 문장과 근거](candidate-text.md)를 따른다.

후보 판정(#118)이 만든 후보마다, 그 후보 근거가 가리키는 본인 커밋의 바뀐 줄로 짧은 설명 초안·본인용 질문·Catch 제목을 만든다. 모델은 근거 조각과 질문 종류, 제목 대상을 **고르기만** 하고, 문장과 제목 글자는 코드가 확인한 경로·이름·파일 상태만 넣어 만든다. 바뀐 줄에 이름이 있다는 것만으로 자유 문장 전체가 사실이라고 볼 수 없기 때문이다. 코드는 `app/generation/`에 있다.

이 문서에서 쓰는 말:

- **재료**: 후보 근거가 가리키는 본인 커밋(연동 계정이 작성자로 기록된 커밋)에서 설명에 쓸 수 있는 추가·삭제 줄.
- **생성 호출**: 후보 하나에 대한 모델 호출 한 번. 분석 전체 실행(`app.processing.Generator`)과 다르다.
- **고쳐 쓰기**: 형식을 어긴 제목만 모델에 대상을 다시 고르게 하는 작은 호출. 한 분석 안에서 허용된 유일한 재호출이다.

## 결정과 근거

- 설명·질문·재료·실패·제목 동작·한계 문구는 2026-10-12 팀장 결정 1~17을 따른다: [설명 결정 1·2](https://github.com/JminAILab/CatchU/issues/120#issuecomment-6118569221), [생성 규칙 결정 3~16](https://github.com/JminAILab/CatchU/issues/120#issuecomment-6125259129), [결정 17과 커밋 순서·같은 문자열 보완](https://github.com/JminAILab/CatchU/issues/120#issuecomment-6125925482). 범위·완료 기준은 [#120 본문](https://github.com/JminAILab/CatchU/issues/120)이다. 확인할 수 없는 본인 커밋이 섞인 후보의 제목은 [2026-10-13 팀장 결정 18](https://github.com/JminAILab/CatchU/issues/120#issuecomment-6142728696)을 따른다.
- 제목의 조각 방식·확인 기준·40자·고쳐 쓰기 3회·제목만 null은 [결정 문서 「Catch 제목」](../../docs/ai-dlc-input-mvp/2026-10-08_catch-decisions.md#catch-제목), 허용하는 재호출이 제목 고쳐 쓰기뿐인 것은 같은 문서 「[한 분석 안의 LLM 재호출](../../docs/ai-dlc-input-mvp/2026-10-08_catch-decisions.md#한-분석-안의-llm-재호출)」이다.
- 설명·질문에서 틀린 항목만 버리고 맞는 항목을 쓰는 것, 상한 뒤 항목·같은 종류 질문·조각 종류의 처리는 2026-10-19 팀장 결정이다([#120 본문 「응답과 실패 판정」](https://github.com/JminAILab/CatchU/issues/120)). 모양 검사만 풀고 지목한 줄·이름의 대조는 그대로이며, 다시 부르지 않는다.
- 아래의 응답 모양·문장 틀·위치 분류·실패 코드는 이슈가 구현에 맡긴 부분에서 고른 것이다. 수치의 현행 결정과 기존 제안값은 [호출 한도](generation-limits.md#호출-한도와-시간)에서 구분한다.

## 경계

- 입구는 `run_generation(request, outcome, built, *, provider, clock, deadline, limits)`다. `built`는 같은 요청·수집 결과로 만든 `build_candidates(request, outcome)`의 결과다. 돌려주는 값은 생성 칸을 채운 `GenerationOutput`과 운영 로그 건수다.
- 바꾸는 것은 후보의 `title`·`draft`·`reflection`과, 본인 커밋 근거의 `coverageLimits` 끝 고정 문구(아래 「coverageLimits」)뿐이다. 후보 순서·작업 사실·기여·묶음 설명·근거와 그 순서·미제공 집계·기존 실패는 그대로다. 실패는 요청 단위 `ANALYSIS` 1건이 끝에 더해질 수 있다.
- 제공자는 `GenerationProvider` Protocol 하나다(`complete(ProviderRequest) -> str`). 요청에는 지시문·자료·시간 제한·최대 출력이 따로 들어간다. 제공자는 시간 제한 안에 끝내지 못하면 `TimeoutError`, 다른 실패는 `ProviderError`를 내고 스스로 다시 시도하지 않는다. 호출은 됐지만 거절·출력 상한으로 응답 전체를 쓸 수 없으면 하위 예외 `UnusableResponse`를 내고, 생성 흐름은 이를 읽을 수 없는 응답·크기 초과 응답으로 다룬다. 실제 제공자는 SDK 기본 재시도를 끈 Anthropic Claude API 어댑터(`claude.py`)이고, 시험은 합성 제공자로 한다.
- 처리 순서에 잇기와 큐·E 전달은 [#121](https://github.com/JminAILab/CatchU/issues/121)의 LIVE 조립(`app/processing/live.py`)이다. `deadline`은 생성 몫의 마감 시각으로, 큐 소비자는 꺼낸 시각 + 60분 − 60초(결과 조합·전송 여유)를 넘긴다([현행 상한](repository-analysis-u7.md)).

## 재료 찾기

재료 커밋은 후보 근거에 든 본인 커밋(최근 20건) 가운데 변경 내용을 받은(`FETCHED`) 커밋이다(`app/generation/material.py`). 다른 계정 커밋, PR·병합·이슈 근거는 재료가 아니다. 후보와 단위를 맞추는 법, 파일 종류와 담는 순서, 큰 후보의 변경 묶음과 한 파일 상한은 [재료 고르기](generation-material.md)에 있다.

## 보내기 전

**patch 확인**(`patch.py`). 파일마다 한 번 해석해 가리기·크기 선별·응답 확인·제목 판정이 함께 쓴다. 줄은 `split("\n")`로만 나누고(정상 줄에 든 `\x0c`·`\x85`를 깨지 않게), 끝 줄바꿈 하나만 버리며 줄 끝 `\r`은 남긴다. 다음을 모두 지켜야 온전하다: 모든 줄이 hunk 머리글 뒤에 오고, hunk마다 머리글의 줄 수와 내용이 맞고(`\ `로 시작하는 `\ No newline at end of file` 표시는 세지 않고, `\`로 시작하지만 `\ `가 아닌 줄은 온전하지 않다), 빈 hunk·겹친 hunk가 없고, 각 머리글의 이후 위치가 앞 hunk들이 늘리고 줄인 줄 수만큼만 밀려 있고(사이 hunk가 빠지면 어긋난다), 머리글 숫자가 9자리 이하이고 줄이 있는 쪽의 시작 위치가 1 이상이고(0은 새 파일·지운 파일의 빈 쪽에만), `+`·`-` 줄 수가 GitHub의 additions·deletions와 같고, patch와 경로·상태를 UTF-8로 인코딩할 수 있다. 하나라도 어기면 그 파일은 쓰지 않고 한계 문구를 붙인다(결정 6). patch가 없는 파일(이진·큰 파일 등)은 수집이 이미 한계로 적었으므로 그냥 쓰지 않는다. 줄은 모델이 지목하는 patch 안 순서와, 제목 전후 비교에 쓰는 이전·이후 줄 위치를 따로 가진다.

**가리기**(`app/redact.py`, 결정 7·16, 후보 판정의 기록의 글 검사와 함께 쓴다). 비밀값·개인정보를 자리표시 `[MASKED]`로 바꾸고 줄 구조는 남긴다. 가린 줄은 "고를 수 없음"으로 표시해 보내고, 설명·제목·질문 어디에 지목해도 받지 않는다. 대상: PEM 개인 키 블록(BEGIN·END가 문맥 줄이어도 그 사이 바뀐 줄), 대소문자·숫자가 섞인 40자 이상 base64 덩어리만으로 된 줄(키 블록 경계가 hunk 밖인 키 내용 줄), AWS 접근 키, GitHub 토큰(`ghp_` 등·`github_pat_`), Slack 토큰, Google API 키, JWT 꼴, 비밀 이름(secret·token·password·api key 등, camelCase·붙임표 포함)에 따옴표 값을 대입한 것, 대문자 환경 변수 꼴(`export`·Dockerfile `ENV`·compose 목록 `- `·`docker run -e`·명령 앞 대입, `:`로 대입한 것 포함, 값은 공백·`;`·`&`·`|`·`#` 앞에서 끝남), `Authorization` 머리글과 숫자가 든 `Bearer` 토큰 값, URL 안 사용자 정보, 이메일, 주민등록번호·휴대전화 꼴. 따옴표 값은 여는 따옴표와 같은 따옴표까지이고 이스케이프된 따옴표에서 끊지 않는다. 값의 앞뒤 경계는 ASCII로만 본다(한글 조사가 바로 붙은 「…@example.com으로」도 가린다). 한 줄에서 꼴로 알아본 값(6자 이상)은 같은 요청의 다른 줄·파일·후보·경로에 그대로 나와도 가린다. 대입 줄에서만 알아본 비밀번호가 시험 파일의 호출 줄에 그대로 나오는 경우 때문이다. 값을 모을 때는 문맥 줄·비밀 파일의 줄, PEM 개인 키 블록 안 내용, 2,000자를 넘는 줄(겹치는 구간으로 나눠 훑음)도 본다. 다른 줄에서 값을 찾을 때는 여러 문자열을 한 번에 찾는 방식(Aho–Corasick)을 써서, 가린 값이 많아도 시간이 줄 길이에 비례한다. 2,000자를 넘는 줄은 정규식을 돌리지 않고 통째로 가린다(압축 코드·빌드 산출물 줄의 정규식 시간을 막고, 그런 줄은 근거로도 쓸모가 없다). 꼴마다 먼저 싼 글자 검사로 해당 없는 줄을 건너뛰고 반복 구간에 길이 상한을 두어, 상한 길이의 병적인 줄도 줄 하나 1 ms 안팎으로 끝난다. 비밀 파일(`.env`·`.env.*`(예시 파일 `.env.example` 등은 값만 가림)·`*.pem`·`*.key`·`id_rsa`·`credentials.json`·`.npmrc` 등)과 경로에 가릴 값이 든 파일은 경로·상태도 보내지 않는다. 가린 사실은 `coverageLimits`에 적지 않는다. 비로그인 수신자에게도 나가는 목록이라 "가렸다"는 문구가 비밀값이 있다는 단서가 되기 때문이다. 운영 로그에 건수만 남긴다.

**크기 선별**(`request.py`·`groups.py`, 결정 5). [재료 고르기](generation-material.md)의 순서로 자료 상한까지 담는다. 혼자 남은 상한을 넘는 줄은 건너뛰고 다음 줄을 본다(hunk 단위로 "넘으면 뒤 전부 제외"하면 큰 커밋에서 대부분이 빠진다). 문맥 줄과 `@@` 뒤 글자, 커밋 SHA·메시지·PR 글·기록의 글은 보내지 않는다.

**구획**. 지시문과 자료를 다른 칸으로 보낸다. 자료는 JSON으로 직렬화해 자료 속 글이 구획을 깨지 못하게 하고, 지시문은 자료가 신뢰할 수 없는 자료이며 그 안의 지시를 따르지 않는다고 적는다. 자료 모양:

```json
{"commits":[{"id":"c1","files":[{"id":"c1f1","path":"src/auth.ts","status":"modified",
  "lines":[{"id":"c1f1:L4","change":"added","text":"const loginRateLimit = 5;","names":["const","loginRateLimit"]},
           {"id":"c1f1:L6","change":"added","text":"API_KEY = [MASKED]","selectable":false}]}]}]}
```

## 응답과 판정

```json
{"fragments":[{"kind":"ADDED_LINE_WITH","line":"c1f1:L4","name":"loginRateLimit"}],
 "title":{"target":"CODE_NAME","line":"c1f1:L4","name":"loginRateLimit"},
 "questions":[{"type":"BACKGROUND","line":"c1f1:L4","name":"loginRateLimit"}]}
```

- 설명 조각은 1~3개를 쓴다. `ADDED_LINE_WITH`(추가 줄)·`REMOVED_LINE_WITH`(삭제 줄)는 줄과 그 줄의 코드 이름을, `FILE_STATUS`는 파일을 가리킨다. 질문은 종류(`BACKGROUND`·`ALTERNATIVES`·`VERIFICATION`)마다 하나씩 1~3개를 쓰고, 줄+이름 또는 파일을 가리킨다. 실제 제공자는 이 모양을 구조화된 출력으로 보내 API가 지키게 하고([생성의 실제 제공자 「요청 설정」](generation-provider.md#요청-설정)), 개수·지목·이름은 여기서 확인한다. 질문이 조각 번호가 아니라 줄을 직접 가리키므로 설명 실패와 질문 실패는 서로를 지우지 않는다.
- 코드 이름은 영문자·숫자·밑줄·`$`로 된 식별자 하나(영문자 하나 이상, 64자 이하)이고, 지목한 줄에 **식별자 경계로** 있어야 한다. 부분 문자열로 보면 `limit`이 `loginRateLimit`에, `func_1`이 `func_10`에 묻어 확인된다. 경계는 유니코드로 본다. 이름 바로 앞뒤에 한글 등 다른 글자·숫자·밑줄·`$`·결합 문자가 붙어 있으면 다른 식별자의 일부일 수 있어 확인하지 않는다(`한글limit`의 `limit`, 한글 조사가 바로 붙은 「limit을」). 이 제한은 공백·백틱·주소·명령문이 이름으로 새는 통로를 막지만, 모든 프롬프트 주입을 막는다는 뜻은 아니다.
- 고를 수 있는 줄에는 이 규칙으로 확인되는 이름을 나온 순서대로 최대 12개 `names`에 실어 보내고, 지시문은 그 가운데서 고르게 한다(2026-10-18 팀장 결정: 로컬 실제 연결의 검증 실패 대부분이 '이름이 그 줄에 없음'·'이름 모양 위반'이었다, [생성 호출 한도와 운영 로그 「모델」](generation-limits.md#모델)). 이름이 없는 줄에는 칸을 두지 않는다. 목록은 안내일 뿐 판정은 위 규칙 그대로다(`app/generation/names.py`).
- 지목은 그 호출에서 **보낸** 줄·파일만 받는다. 문맥 줄, 보내지 않은 줄, 다른 후보·다른 계정 커밋·커밋 메시지·PR 글은 보낸 자료에 없으므로 지목할 수 없다.

| 응답 문제 | 처리 |
|---|---|
| 호출 오류(`ProviderError`), 시간 초과(`TimeoutError`, 또는 시간 제한을 넘겨 끝난 호출 — 쓸 수 없는 응답·호출 오류여도), 응답이 최대 출력을 넘음, JSON이 아님(NaN·Infinity 같은 표준 밖 값 포함)·최상위가 객체가 아님·최상위 객체에서 같은 키가 겹침 | 전체 호출 실패: 설명·질문 모두 `FAILED`, 제목 null |
| 조각·질문이 목록이 아니거나 비었음 | 그 부분(설명 또는 질문) 실패(형식 위반) |
| 항목의 모양 위반·모르는 키·항목 안에서 겹친 키·이름 모양 위반, 파일 이름으로 줄여도 150자를 넘는 질문 | 그 항목만 버린다(형식 위반). 남은 항목이 없으면 그 부분이 첫 원인으로 실패한다 |
| 지목한 줄·파일이 보낸 자료에 없음, 가린 줄, 이름이 그 줄에 없음, 문장 틀이 없는 파일 상태 | 그 항목만 버린다(확인 실패). 남은 항목이 없으면 그 부분이 첫 원인으로 실패한다 |
| 확인된 항목이 상한(3개)을 넘음, 앞과 같은 종류의 질문 | 앞에서부터 상한까지 쓰고, 같은 종류 질문은 처음 것만 쓴다. 문장을 만들 수 없는 항목은 이보다 먼저 버려 자리를 차지하지 않는다 |
| 조각 종류와 지목한 줄의 종류가 다름 | 버리지 않고 실제 줄 종류로 문장을 쓴다 |
| 최상위의 모르는 키 | 판정에서 무시하고 어느 글에도 쓰지 않는다. 건수만 로그에 남긴다. 모르는 키 하나로 설명·질문 전체를 실패로 넓히지 않는다(#120 본문 「응답과 실패 판정」의 확대 금지). 자료 속 지시를 따라 최상위에 자유 글 칸을 더한 응답도 이 행이며, 그 글은 결과에 들어갈 길이 없다 |
| 제목 칸 누락·모양 위반·이름 모양 위반·만든 제목이 40자 초과 | 제목 형식 위반: 생성 호출이 모두 끝난 뒤 고쳐 쓰기 |
| 제목 지목이 확인되지 않거나 종류·동작을 정할 수 없음 | 제목 null(고쳐 쓰지 않음) |

자료 속 지시를 따라 개수·종류·필드를 바꾼 항목은 위 규칙으로 버려지거나 상한에서 잘린다. 문장은 확인한 줄·이름으로만 만들므로 지시를 따른 응답에서도 자료 속 글이나 틀린 문장이 결과에 들어가지 않는다.

## 문장 틀

틀에는 숫자가 없어, 설명에 든 숫자는 확인한 경로·이름 안에만 있다(결정 1: CatchU가 센 활동량을 쓰지 않음). 틀은 이름이 줄에 "포함"됐다고만 말하고 함수 신설·호출·성능 개선 같은 효과·동기·행위, 다른 사람의 기여, 작업 범위 전체를 말하지 않는다. 조사가 받침에 따라 바뀌지 않게 「이름이」·「파일이」처럼 고정된 말 뒤에 조사를 붙이고, 화면에 글자 그대로 보이는 백틱은 쓰지 않는다.

| 조각·대상 | 설명 문장 | 질문의 대상 구(동사) |
|---|---|---|
| 추가 줄 | 「{경로}에서 {이름} 이름이 포함된 줄이 추가되었습니다.」 | 「{경로}에서 {이름} 이름이 포함된 줄을」(추가한·추가할) |
| 삭제 줄 | 「…줄이 삭제되었습니다.」 | 같은 구(삭제한·삭제할) |
| 파일 added·removed·modified | 「{경로} 파일이 추가되었습니다.」(삭제·수정) | 「{경로} 파일을」(추가한·삭제한·수정한) |
| 파일 renamed | 「{이전 경로} 파일의 이름이 바뀌어 {경로} 파일이 되었습니다.」 | 「{이전 경로} 파일의 이름을」(바꾼·바꿀) |

설명은 조각마다 한 문장이고 같은 문장은 한 번만 쓴다. 질문은 종류마다 「{대상 구} {동사} 배경은 무엇인가요?」(BACKGROUND), 「{대상 구} {동사} 때 다른 방법도 고려했다면 무엇이었나요?」(ALTERNATIVES), 「{대상 구} {동사} 뒤 의도대로 동작하는지 확인했다면 어떻게 확인했나요?」(VERIFICATION)다. 확인되지 않은 행동은 조건부로 묻는다. 질문이 150자를 넘으면 경로 대신 파일 이름을 쓰고, 그래도 넘으면 그 질문을 버린다(형식 위반). 질문은 후보의 `reflection.questions`에만 담기는 본인용 결과이고, 답변 저장·수신자 공개는 없다.

## 제목

쓸 만한 기록의 글이 있으면 그 글이 제목이고, 아래 조각 제목·40자·고쳐 쓰기를 쓰지 않는다(CR1 BR3, [후보 문장과 근거 「제목」](candidate-text.md#제목)). 아래는 조각 제목이다.

제목은 「{대상} {종류} {동작}」, 공백 포함 40자 이하다(예: 「loginRateLimit 코드 추가」, 「install.md 문서 수정」). 설명과 같은 생성 호출에서 모델이 대상과 근거 줄(또는 파일)을 지목하고, 종류·동작·글자는 코드가 정한다(`title.py`). 대상 이름 안의 낱말·기호는 거르지 않는다.

**종류**는 대상 파일 위치로 정하고, 여럿에 해당하면 앞이 이긴다. 목록 밖(이미지·잠금 파일·확장자 없는 파일 등)이면 null이다.

| 순서 | 종류 | 위치 규칙 |
|---|---|---|
| 1 | 시험 | 디렉터리 `test`·`tests`·`__tests__`·`spec`·`e2e`, 파일 `test_*.py`·`*_test.*`·`*.test.*`·`*.spec.*` |
| 2 | 문서 | `*.md`·`*.mdx`·`*.rst`·`*.adoc`, `docs/`·`doc/` 아래 `*.txt`, 점 앞 이름이 `README`·`CHANGELOG`인 파일(대소문자 무관) |
| 3 | 설정 | `*.toml`·`*.yaml`·`*.yml`·`*.ini`·`*.cfg`, 알려진 설정 json(`package.json`·`tsconfig*.json` 등), `Dockerfile`, `docker-compose*`, `.github/` 아래, `*.config.{js,ts,mjs,cjs}` |
| 4 | 코드 | 알려진 소스 확장자(`.py`·`.ts`·`.js`·`.java`·`.go`·`.rs`·`.html`·`.css` 등) |

CR1이 더한 꼴(`*Test.*`·`androidTest`·모바일 설정·`.ipynb`)은 [재료 고르기 「종류」](generation-material.md#종류)에 있다.

**동작**은 대상 파일을 건드린 후보 안 본인 재료 커밋마다 정한다. 파일 이름은 GitHub 상태 added·removed·modified·renamed를 추가·삭제·수정·이름 변경으로 옮기고, 그 밖의 상태는 null이다. 코드 이름은 그 파일에서 이름이 든 줄이 추가 줄에만 있으면 추가, 삭제 줄에만 있으면 삭제, 둘 다면 수정이다. 공백만 다른 줄 쌍은 정규화하지 않고 보통 변경(수정)으로 본다. 커밋마다 동작이 같으면 그 동작이다(결정 11: 동작이 하나로 일정하면 기존 규칙 그대로). 그래서 `limit = 5`→`limit = 10`→`limit = 5`처럼 매번 수정이면 시작 전·끝이 같아도 수정이다. 다만 후보의 본인 커밋 가운데 대상 파일을 함께 확인할 수 없는 커밋이 있으면 동작이 같아 보여도 null이다. 변경 내용을 받지 못했거나(응답 크기 상한 초과·상세 조회 범위 밖 등) 파일 목록이 잘렸는데 대상이 보이지 않아 대상 파일을 건드렸는지 모르는 커밋, 그리고 받은 파일 목록에 대상이 있는데 재료가 아닌 커밋(근거 20건 밖 등)이다. 받지 못한 변경을 없었던 것으로 보지 않기 위해서다([2026-10-13 팀장 결정 18](https://github.com/JminAILab/CatchU/issues/120#issuecomment-6142728696)). 이름 바꿈으로 이어진 이전·이후 경로는 같은 파일로 보며, 후보 안에서 그 파일을 여러 커밋이 건드렸으면 이름 바꿈이 낀 흐름이라 null이다.

**커밋마다 동작이 갈리면** 후보의 시작 전과 끝을 비교한다(결정 11·17). PR·PR 없는 병합·커밋 묶음 모두 같다. 커밋 순서는 확인된 부모·자식 관계로만 정하고, 생성 순서의 작성 시각·SHA나 근거 배열 순서는 쓰지 않는다. 대상 파일을 건드린 각 커밋에서 부모를 따라 올라가 그 파일을 건드린 가장 가까운 후보 커밋을 찾고, 그 결과가 한 줄로 이어질 때만 순서가 정해진다. 사이 커밋은 부모가 하나이고 변경 내용을 모두 받았고 그 파일을 건드리지 않아야 한다.

- 파일: 처음 커밋이 added면 시작 전에 없고, 마지막 커밋이 removed면 끝에 없다. 추가→수정은 추가, 추가→삭제는 null, 수정→삭제는 삭제다. 중간에 지웠다 다시 만들면 null이다.
- 코드 이름: 앞 커밋이 더한 줄을 뒤 커밋이 **같은 위치에서 같은 내용으로** 지울 때만 서로 지운다. 위치는 hunk의 이전·이후 줄 위치로 커밋마다 옮겨 보고, 내용이 어긋나면 이어 볼 수 없어 null이다. 끝에 남은 이름 든 추가 줄과 시작 전 줄을 지운 이름 든 삭제 줄로 정한다(둘 다 수정, 추가만 추가, 삭제만 삭제, 둘 다 없으면 null). `limit = 5`를 더한 뒤 `limit = 10`으로 바꾸면 추가이고, 더한 줄을 뒤에서 지우면 null이다. 같은 문자열이 다른 위치에서 더해지고 지워진 것은 상쇄하지 않는다(옮긴 줄은 수정). 시작 전 줄을 지운 자리도 커밋마다 옮겨 본다. 그 자리는 지운 위치부터 그 뒤에 처음 남은 줄까지이고, 뒤 커밋들이 그 자리에 더한 줄도 그 안에 든다. 뒤 커밋이 그 자리에 지운 줄과 같은 내용의 줄을 더하면 원래 줄을 되살린 것으로 보고 서로 지운다(되살린 줄은 시작 전부터 있던 줄로 본다).

**제목 null**: 지목한 줄·대상이 보낸 자료에 없음, 종류·동작을 정할 수 없음, 대상 파일을 건드린 재료 커밋 가운데 그 파일 patch가 없거나 온전하지 않음, 가린 줄에 대상 이름이 있음, 후보의 본인 커밋 가운데 대상 파일을 건드렸는지 모르는 커밋(변경 내용 미수신·파일 목록 잘림)이나 대상을 건드렸는데 재료가 아닌 커밋(근거 20건 밖 등)이 있음, 후보 안 이름 바꿈으로 이어진 파일을 여러 커밋이 건드림. 동작이 갈리는데 다음 가운데 하나면 null이다: 같은 단위에 연동 계정이 작성자로 기록되지 않은 커밋이 있거나 있는지 모름, 부모 관계로 순서를 잇지 못함(부모 둘 이상, 사이 커밋 기록 없음·변경 내용 미수신·후보 밖 커밋이 그 파일을 건드림, 부모 관계 없는 같은 변경 커밋). 같은 자리에 되살린 줄은 시작 전부터 있던 줄로 보아, 대상 이름이 든 줄이 시작 전·끝에 같으면 null이다. 후보의 다른 파일이 빠졌다는 이유로는 null로 두지 않는다. 판정을 위해 GitHub를 새로 조회하거나 checkout하지 않고, 받지 못한 변경을 없었던 것으로 보지 않는다. 제목 null은 결과에도 대체값 없이 `title: null`로 나간다([후보 문장과 근거 「제목」](candidate-text.md#제목)).

**고쳐 쓰기**(결정 15). 모든 후보의 생성·미생성 판정이 끝난 뒤, 생성 순서대로, 남은 시간 안에서 형식을 어긴 제목만 고친다. 어긴 규칙(고정 문장)과 첫 호출에서 보낸 고를 수 있는 줄 가운데 앞에서부터 최대 20줄·그 파일만 보내고, 응답은 `{"title": …}` 하나만 받는다. 고친 지목도 확인을 다시 통과해야 쓴다. 응답의 모양이 또 어긋나면 제목당 최대 3회까지 다시 고친다. 고쳐 쓰기 호출 실패·시간 초과·읽을 수 없는 응답·확인 실패, 요청당 고쳐 쓰기 상한, 남은 시간 부족이면 멈추고 제목을 null로 둔다. 이 경우에도 새 실패를 더하지 않는다. 고쳐 쓰기에 적게 보낸 줄은 크기 제외로 세지 않는다.

## 상태와 실패

| 상황 | 설명 | 질문 | 제목 | 새 failures |
|---|---|---|---|---|
| 고를 수 있는 줄이 없음(수집 오류·patch 없음·잘림·가리기·크기 선별 뒤 0개 등 원인 무관) | NOT_GENERATED(null) | NOT_GENERATED | null | 없음. 호출 0회 |
| 호출 수·남은 시간이 모자라 새 생성 호출을 시작하지 못함 | NOT_GENERATED | NOT_GENERATED | null | 그런 후보가 있으면 요청당 후보에 묶이지 않은 `ANALYSIS` 1건 |
| 전체 호출 실패 | FAILED | FAILED | null | `DRAFT`·`REFLECTION` 각 1건. 같은 호출의 `ANALYSIS`는 없음 |
| 설명만 실패 | FAILED | 확인되면 GENERATED | 확인되면 값 | `DRAFT` 1건 |
| 질문만 실패 | 확인되면 GENERATED | FAILED | 확인되면 값 | `REFLECTION` 1건 |
| 설명 생성, 제목만 null | GENERATED | 그대로 | null | 없음(failures·outcome 그대로, 로그 건수만) |

- 실패 코드는 원인별이다: `GENERATION_CALL_FAILED`, `GENERATION_TIMEOUT`, `GENERATION_RESPONSE_UNREADABLE`, `GENERATION_RESPONSE_TOO_LARGE`(전체), `GENERATION_RULE_VIOLATION`, `GENERATION_UNVERIFIED`(부분), `GENERATION_BUDGET_EXHAUSTED`(요청 단위). 계약에서 코드는 자유 문자열이고 E는 코드로 갈라 처리하지 않는다.
- message는 회원 화면에 「실패한 부분: {message}」로 그대로 나간다. 원인과 실패한 결과를 구분하는 고정 문장만 쓰고(예: 「생성 시간이 초과되어 설명 초안을 만들지 못했다」, 「생성 결과를 변경 내용과 대조해 확인하지 못해 생각해볼 질문을 만들지 못했다」), 제공자·모델 이름, 내부 용어, 경로, 원문, 비밀값, 내부 오류 문구는 넣지 않는다. 말투는 수집 실패 문구와 같은 평서문이다. 예산 부족은 「생성 횟수·시간 한도에 걸려 일부 후보의 설명 초안과 생각해볼 질문을 만들지 못했다」다.
- 실패 기록은 기존 결과 조합(`compose_result`)이 만든다. 후보의 설명·질문 실패가 그 후보의 `DRAFT`·`REFLECTION` 실패가 되고, 종결값도 기존 규칙(후보·실패 수)대로다. 후보가 있는 부분 실패는 다시 요청해 보완할 수 없다(계약의 추가 보완 보류).
- 생성 실패로 후보를 버리지 않는다. 실제 호출·응답 오류를 재료 부족으로 바꾸지 않는다.
- 후보별 시간 초과는 그 후보의 실패로 바꿔 처리 전체의 실행 여부 불명(`UNCERTAIN`)으로 새지 않게 한다. 제공자가 낸 그 밖의 예외(결함, 요청 전체의 실행 여부 불명)는 잡지 않고 올린다.

## 호출 한도와 시간

[생성 호출 한도와 운영 로그](generation-limits.md#호출-한도와-시간)로 옮겼다. 요청당 생성 호출 300회(#424 후속 결정)·고쳐 쓰기 20회(제목당 3회), 호출마다 생성 45초·고쳐 쓰기 20초, 입력 32,000 B, 출력 4,000 B다. 생성 순서와 과거 200회를 정한 당시의 실측 기록도 그 문서에 있다.

## coverageLimits

`coverageLimits`는 근거마다 그 근거로 알 수 없는 것을 적는 목록이고, 회원 화면과 비로그인 수신자 응답에 모두 나간다. #120은 아래 두 사유만 **본인 커밋 근거 목록의 끝**에 고정 문구로 더한다(결정 5·6·13). 같은 근거에 사유마다 한 번이고, 이미 같은 문구가 있으면 더하지 않는다. 기존 내용·순서는 그대로이고 숫자·경로·원문·새 필드는 넣지 않는다. PR·병합·이슈 근거에는 붙이지 않는다.

| 문구 | 붙는 때 |
|---|---|
| 「이 커밋의 변경 내용 일부는 생성 입력 크기 제한으로 생성 모델에 보내지 않았다」 | 크기 선별로 그 커밋의 줄을 일부 뺐고, 그 커밋 줄을 일부 보내 생성 호출을 했을 때 |
| 「이 커밋의 변경 내용은 생성 입력 크기 제한으로 생성 모델에 보내지 않았다」 | 크기 선별로 그 커밋의 줄을 뺐는데 그 커밋 줄을 하나도 보내지 않았거나, 선별 뒤 고를 수 있는 줄이 0개라 부르지 않았을 때 |
| 「이 커밋의 변경 파일 가운데 받은 변경 내용이 온전하지 않은 파일은 생성에 쓰지 않았다」 | 재료 커밋에 patch가 있는데 온전하지 않은 파일이 있을 때. 생성 여부와 관계없이(재료 0개·호출 한도로 미생성인 후보 포함) |

- 크기 문구는 선별을 실제로 거친 때만 붙는다. 호출 예산 부족으로 부르지 못한 후보, 선별 전에 재료가 0개인 후보, 제목 고쳐 쓰기의 작은 입력에는 붙이지 않는다.
- 가리기로 뺀 값·파일, patch가 없는 파일(수집 한계 「파일 N개는 GitHub 응답에 변경 내용이 없어 확인하지 못했다」가 이미 있음), 수집이 이미 적은 사유는 더하지 않는다.
- 확인에는 받은 전체 patch를 쓰므로 문구는 "생성 모델에 보내지 않았다"로 적는다. 문구가 없다고 해서 그 근거가 모델에 모두 전달되거나 생성에 쓰였다고 보장하지 않는다.

## 운영 로그

[생성 호출 한도와 운영 로그 「운영 로그」](generation-limits.md#운영-로그)로 옮겼다. 요청마다 한 줄에 건수와 실패·버린 항목의 원인별 건수만 남기고 SHA·경로·이름·원문은 남기지 않는다.

## 시험

`tests/generation_scenarios.py`의 합성 제공자는 받은 요청을 기록하고, 정해 둔 응답·예외·늦은 응답(합성 시계를 움직임)을 돌려준다. 시험은 합성 수집 결과 → `build_candidates` → 생성 → `compose_result` → 메시지 스키마 v1 검사까지 돌리고, 생성 전후 후보를 workIdentity로 짝지어 생성 칸과 끝 고정 문구 말고는 그대로인지 매번 본다. 기대값은 #120 완료 기준과 결정에서 가져온다. 합성 사례 통과는 그 사례에 대한 확인이며 실제 모델의 품질·안전성을 입증하지 않는다.

## 알려진 한계

- 실제 모델 결과는 2026-10-16~18 로컬 시험대에서 팀장 저장소 3개로만 봤다([생성 호출 한도와 운영 로그 「모델」](generation-limits.md#모델)). 생성 품질 제약 C01(문맥 줄을 이번 변경으로 잘못 귀속한 결함)에 대한 영향과 실제 서비스 결과의 품질 판정은 [#122](https://github.com/JminAILab/CatchU/issues/122)다.
- 문장 틀은 이름이 줄에 있다는 것만 말한다. 이름이 주석 안에 있어도 "포함된 줄"은 사실이지만, 그 줄이 무엇을 하는지는 말하지 않는다.
- 코드 이름은 ASCII 식별자만 받는다. 한글 변수 이름 등은 이름으로 고를 수 없어 파일 조각을 고르거나 실패한다. 한글 조사가 바로 붙은 이름(「limit을」)이 든 주석·문서 줄에서도 그 이름을 고를 수 없다.
- 가리기는 정규식이다. 따옴표 없는 소문자 대입(`password = hunter2`, YAML `password: …`·`secret_key_base: …`), 점 이름 설정(`spring.datasource.password=…`), `curl -u 사용자:비밀번호`, 띄어 쓰거나 국제 표기한 전화번호·하이픈 없는 주민번호는 놓친다. 같은 값을 다른 줄에서 가리는 것도 한 줄에서 꼴로 알아본 값에만 적용된다. `git@github.com`·`logo@2x.png`·`tokenizer = "bert"`·`MAX_TOKENS = 4096`·인증서·공개 키 내용 줄은 잘못 가린다. 잘못 가린 줄은 고를 수 없어 재료가 줄어들 뿐 값이 새지는 않는다. 알려진 경우는 시험으로 고정했다.
- 제목: 대상 파일을 건드렸는지 모르는 본인 커밋이 하나라도 있으면 제목을 두지 않으므로, 응답이 아주 큰 커밋이나 상세 조회 범위 밖 커밋이 섞인 후보는 제목이 빠진다(선택 상세 조회 범위는 요청당 1,500건).
- 제목 전후 비교는 이름 바꿈이 낀 흐름, 부모가 둘 이상인 사이 커밋, 같은 변경이지만 부모 관계가 없는 커밋을 모두 null로 둔다. 되살림은 지운 자리에 같은 내용을 다시 더한 경우만 알아보며, 그 밖의 위치에 더한 같은 내용은 옮긴 것으로 보아 수정이 될 수 있다.
