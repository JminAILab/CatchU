# 텍스트 자료 화면 (U4 W2)

12월 intent U4(발행·링크) 제출 1의 텍스트 자료 목록·편집 화면이다. 주소는 `/materials`이고 회원 헤더의 [텍스트 자료]로 들어간다. 회원 가드·API 호출·토큰은 공통 기반(`(member)` 레이아웃, `api.member`)을 쓰며 이 폴더가 따로 갖지 않는다. 기준: [U4 기능 명세](../../../../aidlc/spaces/default/intents/260925-intent-12/construction/u4-publication-link/functional-design/functional-spec.md) W2, [업무 규칙](../../../../aidlc/spaces/default/intents/260925-intent-12/construction/u4-publication-link/functional-design/rules.md) BR2·BR3, api 안내 [발행본·텍스트 자료·Catch 설명](../../../../api/docs/publications.md) 「텍스트 자료 API」.

## 파일

| 파일 | 역할 |
| --- | --- |
| `materials-api.ts` | API 호출(`createMaterialsApi(api.member)`), 응답 모양 확인, 보내기 전 길이 검사, 저장 결과 반영(`applyMaterialSave`)과 안내 문구. 화면과 분리해 시험한다 |
| `materials-view.tsx` | 목록(`MaterialsListView`)·편집(`MaterialEditorView`) 그리기만 한다 |
| `materials-screen.tsx` | 상태·요청·이탈 확인을 맡는 화면(`MaterialsPage`) |
| `materials.module.css` | 화면 모양 |
| `src/app/(member)/materials/page.tsx` | 주소 연결 |

저장 실패 구분과 공통 문구(“저장됨”·“저장되지 않았습니다”·로그인 만료 안내)는 `src/lib/save-outcome.ts`에 두고 Catch 작성자 설명 편집(`src/features/assets/author-description-*`)과 함께 쓴다.

## 동작

- 목록은 본인 자료를 최신순으로 20개씩 읽고 [더 보기]로 이어 읽는다. 조회 실패는 0건으로 보이지 않고 다시 불러오기를 보인다. 항목에는 제목과 마지막 저장 시각만 있다.
- 편집 화면에는 “주민등록번호 같은 민감한 정보는 지우고 올려 주세요”를 늘 보인다. 서비스가 내용을 찾아 가리지 않는다(BR3.3).
- 제목 1~100자(앞뒤 공백 제외)·본문 1~20,000자(코드 포인트)를 넘거나 비면 보내지 않고 안내한다. 서버 검증이 기준이며 화면 검사는 미리 알려 주는 것이다.
- 저장은 응답이 201(새 자료)·200(수정)이고 모양이 맞을 때만 “저장됨”이다. 실패(400·401·404·429·5xx·연결 끊김·성공 형식 오류)는 “저장되지 않았습니다”와 이유를 보이고 입력을 지우지 않는다(BR2.3, NFR6.1). 401은 로그인 만료 안내를 함께 보인다. 자동으로 다시 보내지 않는다.
- 저장 중에는 입력·버튼을 잠근다. 새 자료를 처음 저장하면 편집기를 다시 열지 않고 그 자리에서 수정으로 이어 간다.
- 저장·삭제를 기다리는 동안 미저장 확인을 거쳐 다른 자료로 옮겨도 보낸 요청은 취소하지 않는다. 늦게 온 성공은 목록에 반영하고(새 자료는 목록에 더함, 삭제는 목록에서 뺌), 지금 연 자료의 선택·입력은 바꾸지 않는다. 서버에 저장된 자료가 목록에서 빠져 같은 자료를 다시 만드는 일을 막기 위해서다. 불러오기 요청은 다른 자료를 열면 취소한다. 목록 조회 중에 저장·삭제가 끝나면 진행 중인 조회를 버리고 다시 읽어, 변경 전에 읽은 늦은 응답이 새 자료·제목·삭제를 덮지 않게 한다. 다시 읽은 목록이 실패하면 목록에만 실패와 다시 불러오기를 보이고 편집기의 “저장됨”·입력은 그대로 둔다. 목록을 다시 읽은 뒤 도착한 [더 보기] 응답은 새 목록에 붙이지 않는다.
- 저장하지 않은 입력이 있으면 새로고침·창 닫기·링크 이동(`useUnsavedGuard`), 로그아웃·다시 로그인(`useUnsavedChanges`), 다른 자료 열기·[새 자료]·[목록으로] 전에 묻는다(BR2.2).
- 삭제는 확인 창 뒤 204일 때만 목록에서 뺀다. 실패하면 “삭제되지 않았습니다”와 이유를 보이고 편집 화면에 남긴다. 이미 발행한 사본은 남는다고 확인 창에 적는다(BR3.5).
- 제목·본문은 React 텍스트로만 그린다(NFR1.10).
- 이 편집 화면은 입력창만 있어 주소를 링크로 그리지 않는다.
- 텍스트 자료 본문과 Catch 작성자 설명 안의 주소는 #416 팀장 결정(2026-10-29, Q1 B)과 NFR1.11에 따라 발행본을 보여 주는 화면(작성자 발행본 상세 W5, 받은 사람 화면 W4)에서 GitHub 주소만 새 탭 링크(`rel="noopener noreferrer"`)로 그리고, 그 밖의 주소는 글자로 둔다. 판정은 `isGithubSourceUrl`을 쓴다. 포트가 붙은 주소(OQ-U4-NFR-1)와 문장 안 주소의 끝 판정(OQ-U4-NFR-2)은 그 구현 전에 정한다.
- 조작 요소에는 `data-testid`(`materials-*`, `material-*`)를 단다.

## 한계

- 로그인 만료 때 입력 유지는 공통 인증 모드에 따라 다르다(2026-11-02 로컬 브라우저 확인: Access 토큰 수명 900초를 실제로 기다린 만료, 갱신 실패는 api 서명 키 교체와 세션 삭제로 만듦).
  - 통합 시험 전환을 끈 기존 모드(현재 기본값): 회원 API가 401을 받으면 공통 클라이언트가 토큰을 지우고 회원 가드가 로그인 화면으로 보낸다. 편집 화면이 사라져 입력이 남지 않는다.
  - 통합 시험 전환을 켠 모드(`NEXT_PUBLIC_AUTH_SESSION_INTEGRATION=true`): 갱신이 되면 "로그인이 연장되었습니다. 다시 눌러 주세요."와 함께 입력이 남고, 다시 누르면 저장된다. 갱신도 실패하면 재인증 안내와 [다시 로그인]이 뜨고 화면·입력이 남으며, [다시 로그인]은 미저장 확인을 거친다(이 화면이 `useUnsavedChanges`로 알린다).
  - 가드·인증 기본값은 공통 기반 범위라 이 화면에서 바꾸지 않았다.
- 화면 상태 전이는 `materials-screen.tsx`의 `createMaterialsScreenModel`·`createMaterialEditorModel`이 맡고, 시험(`test/materials-screen.test.mjs`)이 원본 파일을 변환해 직접 확인한다. 새 자료를 처음 저장해 ID가 생겨도 편집기를 다시 만들거나 다시 불러오지 않으며, 저장 중에 더 쓴 입력은 저장 성공 응답이 덮지 않는다. 삭제 성공은 목록에서 그 자료를 빼고, 편집기는 지금 그 자료를 열고 있을 때만 닫는다(삭제를 기다리는 동안 다른 자료를 열어 쓰던 입력은 남는다).
- `node --test` 시험은 합성 응답과 서버 렌더링으로 한 행동 시험이다. 화면 컴포넌트의 마운트 효과(열 때 불러오기)는 이 시험에서 돌지 않아 브라우저에서 따로 확인했다(2026-11-02 로컬, 실제 api·DB, 두 인증 모드). 지연·실패 응답은 브라우저 개발자 도구 프로토콜로 요청을 붙잡거나 끊어 만들었고, 확인 창은 대역 없이 실제 네이티브 창이 열리는 것을 확인했다.

## 시험

- `node --test test/materials.test.mjs`: API 경로·성공 판정, 실패 구분, 길이 검사, 저장 결과 반영(입력 유지·dirty), 편집 화면의 민감 정보 안내·`data-testid`·실패 안내, 목록의 실패·0건 구분. 합성 응답만 쓴다.
- `node --test test/materials-screen.test.mjs`: 화면 모델의 상태 전이. 첫 저장 회귀, 저장 중 추가 입력, 늦은 불러오기 응답, 저장 실패 입력 유지, 로그인 변경 뒤 응답 무시, 삭제 확인·실패, 목록·더 보기, 이탈 확인, 삭제·저장 경합(A 삭제 중 B 편집, 저장 중 다른 자료로 이동한 뒤 늦은 저장 성공, 목록 조회 중 끝난 저장·삭제, 자동 재조회 실패, [더 보기] 지연 중 변경·재조회). 합성 응답만 쓴다.
