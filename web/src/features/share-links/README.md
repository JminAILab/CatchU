# 공유 링크 관리 — W6 (#149)

로그인한 발행자가 `/links`에서 내 링크 목록을 보고, 새 링크를 발급하고, URL을 복사하고, 링크를 중단한다. 실제 회원 API(#147 발급, #148 목록·중단)에 연결한다. 수신자 화면(`/s/...`)은 #152 범위다.

## 동작

- **목록(L03):** 발행 시각 최신순(서버 순서)으로 20개씩 받고 [더 보기]로 이어 붙인다. 조회 중·정상 0건·조회 실패를 서로 다르게 표시한다. 이미 목록이 있을 때 다시 조회하면 그 목록을 유지한 채 갱신하고, 갱신 중이거나 갱신에 실패한 동안에는 복사·중단을 막는다(마지막 확인 기준 표시).
- **상태:** `ACTIVE`·`STOPPED`·`EXPIRED`를 ‘유효·중단됨·만료됨’ 글자로 표시한다. 시각은 `YYYY-MM-DD HH:mm:ss (KST)`, 남은 기간은 유효 링크에만 보조로 표시한다. 중단된 링크의 만료 시각도 지났으면 함께 알린다.
- **유효 링크 수:** 모든 페이지를 받았을 때만 ‘N/5개’를 보여 준다. 다 받지 못했으면 추정하지 않는다. 한도 판정은 서버가 발급과 함께 한다.
- **공개 프로필 요약(L01):** 발행 준비를 열 때마다 본인 `GET /v1/me`(A, #135)를 읽어 수신자에게 공개되는 필드만 보인다. 기준은 수신자 응답 `PublicProfile`(공통 스키마)과 api `OwnerProfileReader.readPublicProfile`이다.
  - 이름·한 줄 소개·희망 직무·기술(직접 입력값)은 그대로, GitHub 계정은 연결 상태가 `CONNECTED`일 때만 보인다. `/me`는 재연결 필요·미연결이어도 마지막 계정명을 주므로 화면에서 같은 규칙으로 거른다. `CONNECTED`인데 계정명이 빈 문자열이면 수신자 조회가 오류이므로 계정 줄만 숨기지 않고 조회 실패로 보이고, 계정명이 `null`이면 수신자 화면처럼 계정 줄만 보이지 않는다. 실제 GitHub 연결은 저장 전에 계정명 형식을 검사해 빈 문자열을 거부하므로, 저장 단계의 추가 차단은 이 기능에서 요구하지 않는다(A 확인, [PR #396 승인 리뷰](https://github.com/JminAILab/CatchU/pull/396#pullrequestreview-5661178328)). 회원 ID·연결 상태값은 보이지 않는다.
  - 빈 값은 수신자 화면처럼 ‘입력하지 않음’으로 보인다. 조회 중·조회 실패를 구분하고, 응답이 계약과 다르면 빈 프로필로 바꾸지 않고 조회 실패로 둔다. [다시 불러오기]는 `/me`만 다시 읽는다.
- **공개 Catch 요약(L01):** 발행 준비를 열 때마다 본인 `GET /v1/catches`(저장소 필터 없음, 20개씩)를 첫 페이지부터 마지막 페이지까지 읽고, `visibility=PUBLIC`·`restriction=NONE`인 Catch만 보여 준다. 수신자 조회와 같은 기준이다(B 확인, [#149 2026-10-26](https://github.com/JminAILab/CatchU/issues/149#issuecomment-6405409061)).
  - 각 항목은 `/assets?catchId=…`로 내 자산 상세를 연다(B 상세 진입 접점, #168 주소 유지 기준). 기존 [공개 자료 확인으로] → `/assets`는 그대로 둔다. 제목이 없으면 ‘제목 없는 Catch’와 첫 작업 사실만 보이고 다른 값으로 채우지 않는다.
  - 공개로 설정했어도 원본 저장소 보호(`SOURCE_PRIVATE`)인 Catch는 수신자에게 보이지 않으므로 목록에서 뺀다.
  - **확정 목록으로 안내하지 않는다.** 여러 페이지를 차례로 읽는 동안이나 읽은 뒤에 자료가 바뀔 수 있어, 조회에 성공하면(0건 포함) ‘이 요약은 조회하는 동안이나 조회 후에 달라질 수 있습니다. 수신자에게는 링크를 여는 시점에 공개 중인 자료가 보입니다.’를 함께 보인다.
  - 조회 중·정상 0건·조회 실패를 구분한다. 한 페이지라도 실패하거나 응답이 계약과 다르면 일부만 보여 주지 않고 조회 실패로 두며, [다시 불러오기]는 첫 페이지부터 다시 읽는다. 같은 cursor가 다시 오거나 50페이지를 넘으면 끝까지 읽었다고 볼 수 없어 조회 실패로 둔다. 읽는 동안 같은 Catch가 다시 나오면 한 번만 센다.
  - 발급은 두 요약의 결과와 무관하다. 근거가 둘로 나뉜다.
    - 공개 0건: 조회에 성공해 0건이면 발행을 허용한다는 결정이다(초안 §4.7 공개 자산 0개 — 발행 허용).
    - 조회 중·조회 실패: 조회 상태를 안내하고, 실패를 0건과 구분하며, 수동 재조회([다시 불러오기])를 제공하는 조건으로 발행을 허용한다. 링크는 사본을 만들지 않고 수신자가 열 때의 공개 자료를 보여 주므로, 요약은 확인용 안내일 뿐 발행 내용을 바꾸지 않는다. 초안 §4.8의 화면 제안(‘요약 확인 전 발행 버튼 잠시 차단’) 대신 이 조건을 A·B가 합의했다([A 승인 리뷰](https://github.com/JminAILab/CatchU/pull/396#pullrequestreview-5661178328), [B 댓글](https://github.com/JminAILab/CatchU/pull/396#issuecomment-6409389200)). 발행 사본을 고정하는 방식으로 바뀌면 확인 조건을 따로 정한다.
  - 발행 준비를 닫거나 화면을 떠나면 두 요약의 진행 중 조회를 취소하고 늦은 응답을 버린다.
- **발급(L01→L02):** 제목은 필수이며 앞뒤 공백을 뺀 값을 보낸다. 비밀번호는 선택이고 trim하지 않는다. [링크 발행]을 누르면 요청 전에 입력·버튼을 잠근다. 201·200(같은 키의 기존 결과) 모두 L02로 바꾸고 비밀번호 입력을 지운다.
- **재전송:** 키는 `createIdempotencyKeyHolder`로 붙잡는다. 응답 불명(조회 실패·5xx)이면 입력을 잠근 채 [다시 발행]으로 **같은 키·같은 본문**만 다시 보낸다. 새 키로 자동 재요청하지 않는다.
  - [목록에서 확인]으로 닫아도 키·본문을 버리지 않는다. 목록 조회까지 실패해도 [새 링크 발행]·[요청 다시 보기]로 다시 열면 같은 불명 상태로 이어진다.
  - **목록으로는 결과를 확정하지 않는다.** 같은 제목의 링크는 기존 링크나 다른 탭의 발급일 수 있으므로, 해당 행에 ‘제목이 같음 — 이 요청의 결과인지는 아직 모름’만 표시하고 요청은 계속 붙잡는다.
  - 결과는 같은 키·본문으로 다시 보낸 응답으로 확정한다. 서버는 이미 처리한 키면 그 링크를 현재 상태로 200 응답하고, 처리하지 않은 키면 새로 판정한다(같은 제목이 있으면 `LINK_TITLE_CONFLICT`). 돌려받은 링크가 그사이 중단·만료됐으면 발행 완료 화면에 현재 상태를 알리고 복사를 막는다.
  - 붙잡은 요청은 (1) 다시 보낸 요청이 확정되거나 (2) 사용자가 [새로 작성] → 안내 확인 → [새로 작성 계속]을 고를 때만 놓는다. 안내 문구: ‘이전 요청은 이미 발급됐을 수 있습니다. 목록을 확인한 뒤 새로 작성해 주세요. 새로 작성하면 새 요청으로 보내며, 이전 요청은 자동으로 다시 보내지 않습니다.’ 안내 단계에서 [취소]나 [목록에서 확인]을 누르면 같은 요청을 계속 붙잡는다.
  - [새로 작성 계속]은 이전 요청을 취소하지 않는다. 이전 요청을 자동으로 다시 보내지 않고, 다음 [링크 발행]은 새 키로 보낸다. 같은 제목을 보내면 이전 요청이 처리됐을 때 서버가 제목 중복으로 거부하므로 같은 제목의 링크가 두 번 생기지 않는다(다른 제목이면 두 링크가 모두 생길 수 있어 안내를 먼저 보인다).
  - 서버가 판정한 4xx 거부(401·429 제외)는 확정으로 보고 다음 발행은 새 키를 쓴다.
- **빈도 제한(429 `RATE_LIMITED`, #235):** 서버가 처리하지 않은 요청이며 앞선 같은 키 요청의 결과도 알려 주지 않는다. 확정으로 보지 않고 **키·본문을 그대로 붙잡는다**.
  - ‘요청이 많아 지금은 발행하지 못했습니다’를 안내하고 입력을 잠근다. 앞선 시도의 결과를 모르면(조회 실패·5xx 뒤) ‘앞선 요청의 발행 여부는 아직 모릅니다’를 함께 알린다.
  - `Retry-After`의 남은 초 동안은 [다시 발행]을 막고 남은 초를 보여 준다. 화면 상태 처리(`share-links-store.ts`)도 대기 중 재전송을 거부한다(버튼을 강제로 눌러도 보내지 않음). 시간이 지나면 버튼만 풀리고, **자동으로 다시 보내지 않는다.** 사용자가 누르면 같은 키·본문으로 보낸다. 다시 429면 새 남은 시간으로 기다린다.
  - `Retry-After`가 없거나 형식이 맞지 않으면 남은 시간을 추정하지 않고 [다시 발행]을 바로 허용한다(같은 키·본문).
  - **대기 시간은 요청 키·본문과 따로 관리한다.** 같은 화면에서 닫기·다시 열기·[새로 작성 계속]으로 요청을 놓아도 대기는 이어지며, 대기 중에는 새 요청도 보내지 않는다. [링크 발행]도 남은 초 동안 막고, 화면 상태 처리의 `submit`·`resend` 모두 대기 중 요청을 보내지 않는다. 화면을 떠나면(회원 전환 포함) 대기도 지운다.
  - 요청을 붙잡는 기준은 그대로다. 앞선 시도의 결과를 모르면 닫아도 요청을 붙잡고([새로 작성]은 위 안내를 거친다), 결과를 모르는 시도가 없었으면 처리된 요청이 없으므로 닫을 때 놓는다. 붙잡은 요청은 대기 뒤 같은 키·본문으로, 놓은 뒤 새로 작성한 요청은 대기 뒤 새 키로 보낸다.
  - 401은 기존과 같다. 결과를 모르는 시도가 있었으면 불명 상태와 키를 유지하고, 없었으면 새 요청으로 작성한다.
- **발급 거부 안내:** `LINK_TITLE_CONFLICT`는 앞선 요청이 성공했을 수 있어 ‘실패’라고 하지 않고 목록 확인을 안내한다. 이 안내(한도·멱등 충돌 포함)에서 [공유 링크로]를 누르면 목록을 다시 받는다(앞선 불명 요청이 만든 링크가 아직 목록에 없을 수 있다). `LINK_LIMIT_REACHED`는 중단 후 발행을 안내한다. `VALIDATION_FAILED`는 `field`·`reason`으로 필드별 안내를 한다. `RATE_LIMITED`는 위 「빈도 제한」을 따른다.
- **중단:** 유효 링크만 [링크 중단] → 확인 상자 → `PUT /v1/share-links/{linkId}/stop`을 **본문·쿼리 없이** 보낸다(`{}`도 400). 결과는 요청 중·성공·실패 확정·응답 불명으로 나눈다. 응답 불명이면 목록을 중단됨으로 바꾸지 않고, 목록을 다시 확인하기 전에는 같은 링크의 중단을 다시 보내지 않는다. [상태 다시 확인]은 조회만 한다.
- **복사:** 클립보드 쓰기에 성공했을 때만 ‘복사했습니다’를 표시한다. 실패하면 직접 복사할 수 있게 주소를 선택된 입력칸으로 보여 준다.
- **화면 이탈·회원 전환:** 화면을 떠나면 진행 중 조회를 취소하고, 조회·발급·중단의 늦은 응답을 버리며, 입력(비밀번호 포함)과 확인하지 못한 발급 요청을 지운다. 토큰이 바뀌면(401·로그아웃 뒤 재로그인, 다른 계정) 화면을 새로 만들어 이전 회원의 목록·요청·입력을 잇지 않는다. 화면을 떠난 뒤에는 이전 발급 요청의 키도 없으므로, 같은 제목으로 다시 보내면 서버가 결과(제목 중복)를 알려 준다.

## 경계와 남은 것

- **입력 길이:** 제목 1~50자, 비밀번호 8~64자 기준(#223 계약)은 이 화면에서 미리 막지 않고, 서버 검사(#221)의 `400 VALIDATION_FAILED`(`maxLength`·`minLength`)를 필드별로 안내한다. 서버 길이 검사와의 연결은 #149 통합 검사에서 web 상태 저장소·API 호출·응답 해석을 실제 HTTP·DB에 붙여 확인했다(제목 51→50자, 비밀번호 7→8자·65→64자). 검증 결과는 [PR #266](https://github.com/JminAILab/CatchU/pull/266), 실행 방법은 [#149 실행 안내](../../../../api/docs/share-links-integration-149.md)에 있다. React 화면의 필드 안내 표시는 이 자동 검사의 범위가 아니며 수동 브라우저 재현으로 따로 확인한다.
- **L01 공개 자료 요약:** 위 「공개 프로필 요약(L01)」·「공개 Catch 요약(L01)」으로 연결했다. 두 요약은 발행 준비를 연 시점에 따로 읽은 결과이며, 수신자가 링크를 열 때의 화면과 같은 시점의 확정 자료가 아니다. 발급은 공개 Catch 수와 무관하게 가능하다(계약).
- **로그인 만료:** 회원 API가 `AUTH_REQUIRED`·`AUTH_INVALID`를 돌려주면 공통 호출 함수가 토큰을 지우고 회원 가드가 로그인으로 보낸다. 로그인 뒤 같은 키를 이어 쓰는 기능은 없다(web README 「API 호출」).
- **중단 요청 식별·대기 시간:** 계약에 중단 요청 식별·결과 조회가 없어, 응답 불명은 목록 재조회로만 확인한다(초안 §4.3.2의 남은 합의).
