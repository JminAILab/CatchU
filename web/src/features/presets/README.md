# 프리셋 화면 (발행 프리셋 U2)

지원자가 발행에 쓸 자료 묶음(프리셋)을 만들고 고치는 화면이다. 주소는 `/presets`(목록)·`/presets/new`(새 프리셋)·`/presets/[presetId]`(고치기)이고 회원 헤더의 「프리셋」으로 들어간다. 발행 화면(`/publications/new`)은 여기서 만든 프리셋을 1~5개 골라 발행한다([발행·발행본](../publications/README.md)). 회원 가드·API 호출·토큰은 공통 기반(`(member)` 레이아웃, `api.member`)을 쓴다. 서버 검증과 글자 수·발행할 수 없는 이유 계산은 api(발행 프리셋 U1, [api/docs/presets.md](../../../../api/docs/presets.md))가 하고, 화면은 그 결과를 미리 보일 뿐이다.

기준: [U2 기능 설계](../../../../aidlc/spaces/default/intents/261118-publication-presets/construction/u2-applicant-screens/functional-design/functional-spec.md) 흐름 1·2, [규칙](../../../../aidlc/spaces/default/intents/261118-publication-presets/construction/u2-applicant-screens/functional-design/rules.md) BR1~BR3, [NFR 설계](../../../../aidlc/spaces/default/intents/261118-publication-presets/construction/u2-applicant-screens/nfr-design/), 다듬은 화면 [M1~M3](../../../../aidlc/spaces/default/intents/261118-publication-presets/inception/refined-mockups/mockups.md)·[interaction-spec](../../../../aidlc/spaces/default/intents/261118-publication-presets/inception/refined-mockups/interaction-spec.md).

## 동작

### 목록 (M2)

- 열면 「프리셋 목록을 불러오고 있습니다.」를 보이고 `GET /v1/presets`를 한 번 부른다(쪽 나눔 없음, 50개까지). 받은 순서(만든 순서)대로 이름, 「항목 N개 · M자」(천 단위 쉼표), 발행할 수 없는 자료가 있으면 「 · 발행할 수 없는 자료 N개」, 60,000자를 넘으면 「 · 상한을 넘었습니다」, <고치기>(읽히는 이름 「(이름) 고치기」)를 보인다.
- 0개면 「아직 만든 프리셋이 없습니다. [새 프리셋]으로 만들어 보세요.」, 실패면 「프리셋 목록을 불러오지 못했습니다.」와 [다시 불러오기]다. 실패를 0개로 보이지 않는다.
- [새 프리셋]은 단추다. 50개면 `disabled`로 막고 「프리셋은 50개까지 만들 수 있습니다.」를 보이며 그 글을 단추의 `aria-describedby`로 잇는다.

### 편집 (M3)

- 고치기 화면은 상세 1, 새 프리셋은 상세 없이 연다. 둘 다 저장소 목록 1(Catch 작은 줄의 저장소 이름, 실패하면 이름만 뺀다) + 고르기 목록 3(Catch·텍스트 자료·PDF 첫 쪽) + 세기 최대 3이다. 상세 404는 「프리셋을 찾을 수 없습니다.」와 <프리셋 목록으로>만, 그 밖의 실패는 「프리셋을 불러오지 못했습니다.」와 [다시 불러오기]다.
- 내 Catch 목록은 `GET /v1/catches?publishable=true`(공개·확인됨·보호 아님만)이고, 「작성자 설명을 쓴 Catch만 보기」를 켜면 `authorDescription=written`도 붙인다. 작은 줄은 「저장소 이름 · 설명 안 씀 · 불일치 표시됨」이다(공개 상태 글은 뺀다). 글 추출이 끝난 PDF만 고를 수 있다.
- 쪽을 하나 불러올 때마다 그 쪽의 고를 수 있는 자료(Catch 전부·텍스트 자료 전부·추출이 끝난 PDF)를 `POST /v1/presets/measure`로 한 번 센다. 고를 수 있는 자료가 없는 쪽은 부르지 않는다. 단추는 목록 응답이 오면 먼저 그리고, 글자 이유는 세기 응답 뒤에 붙는다. 세기가 실패한 쪽은 글자 수를 모르는 채로 두고 글자 이유로 막지 않는다(저장 때 서버가 검사한다).
- 걸러 보기를 바꾸거나 목록을 다시 부르면 앞 요청을 끊고 세대를 올려, 늦게 온 옛 목록·옛 세기 응답은 버린다. [더 보기]는 부르는 동안 다시 누를 수 없다.
- 고르기는 누르는 단추(`aria-pressed`)이고 다시 누르면 빠진다. 같은 자료는 한 번만 담긴다. 20개를 담으면 안 담긴 단추를 막고 단추 안에 「항목은 20개까지 담을 수 있습니다」, 담으면 60,000자를 넘는 자료는 「전체 글이 60,000자를 넘습니다」를 보인다. 담긴 단추는 막지 않는다.
- 「담긴 자료와 순서 (항목 N개 · M자)」는 글자 수를 모르는 자료가 하나라도 있으면 M 대신 「글자 수를 세지 못했습니다」다. 합이 60,000자를 넘으면 머리에 「전체 글이 60,000자를 넘어 발행할 수 없습니다.」를 보이고 [저장]은 막지 않는다. 상세의 이유(비공개·보호·확인 필요·추출 미완료)는 그 줄에 글자로 붙는다. 끝에 「프리셋을 고쳐도 이미 보낸 링크는 바뀌지 않습니다.」가 있다.
- [위로][아래로][빼기]로 순서를 바꾸고 뺀다. 첫 [위로]·끝 [아래로]는 막히고 옮긴 뒤 초점은 옮긴 항목의 같은 단추에 남는다(끝에 닿아 그 단추가 막히면 같은 항목의 다른 순서 단추).
- 이름 칸은 보이는 이름표 「이름」과 도움말(`aria-describedby`)이 있다. [저장]은 이름을 앞뒤 공백을 빼고 1~50자(코드 포인트)인지 먼저 보고, 아니면 요청하지 않고 칸 아래 「이름을 1~50자로 써 주세요.」(`role="alert"`, 칸에 `aria-invalid`)를 보인다.
- 저장 중에는 이름 칸·고르기·걸러 보기·순서·[저장]·[프리셋 지우기]를 모두 막고 「저장하고 있습니다.」를 보인다. 새 프리셋은 `POST`, 고치기는 `PUT`이다. 첫 저장(201) 뒤에는 「저장하지 않은 변경」을 끈 다음 라우터의 `replace`로 `/presets/{presetId}`에 옮긴다(뒤로 가기 기록을 더하지 않음, NFR 설계 Q1 B). 옮긴 화면은 상세를 불러 고치기 상태로 그린다: 다음 [저장]은 `PUT`, h1은 「프리셋 고치기」, [프리셋 지우기]가 보인다. 고르기 목록·저장소 목록·세기도 그 화면이 다시 부른다. 주소만 바꾸는 `history.replaceState`는 쓰지 않는다. 회원 가드가 주소마다 회원을 다시 확인하며 화면을 새로 만들어, 빈 「새 프리셋」이 다시 그려졌다(Build and Test 되돌아가기 1).
- 고치기 저장이 성공하면 늘 그려 둔 `role="status"` 칸에 「저장했습니다.」를 보이고 상세를 한 번 다시 불러 같은 자료의 글자 수·이유만 서버 값으로 맞춘다(담긴 목록은 바꾸지 않는다). 다시 불러오기가 실패하면 「저장했습니다. 내용을 다시 불러오지 못했습니다.」와 [다시 불러오기]다. 다음 변경이 생기면 「저장했습니다.」는 사라진다. 첫 저장의 「저장했습니다.」는 옮기기 전에 그 프리셋 ID와 함께 이 모듈 안 메모리에 남기고, 옮긴 화면이 열 때 같은 ID면 한 번 꺼내 보인 뒤 지운다(주소·브라우저 저장소에 두지 않음). 새로 고침·다시 열기·다른 프리셋 화면에서는 보이지 않는다.
- 편집 화면 모델은 정리(`dispose`) 뒤 다시 열면(`open`) 정리 표시를 되살린다. 개발 모드의 React Strict Mode가 효과를 마운트→정리→마운트로 두 번 돌려도 상세·저장 결과를 버리지 않는다. 마지막 정리 뒤 늦게 온 결과는 버린다.
- 저장 실패는 이유별 글(`role="alert"`)이고 입력·담은 자료·순서를 남기며 초점은 [저장]에 돌아온다: 409 「프리셋은 50개까지 만들 수 있습니다.」, 400 `maxTotalLength` 「전체 글이 60,000자를 넘어 저장할 수 없습니다. 자료를 빼 주세요.」, 404 「담은 자료나 프리셋을 찾을 수 없습니다. 목록을 다시 불러와 주세요.」와 <프리셋 목록으로>, 그 밖 「저장하지 못했습니다. 다시 시도해 주세요.」. 400 `name`은 이름 칸 아래에만 보인다.
- [프리셋 지우기](고치기 화면에만)는 「‘(이름)’ 프리셋을 지울까요? 이미 보낸 발행본은 그대로 남습니다.」 확인(`window.confirm`)을 거친다. 취소하면 그대로, 204·404면 경고 없이 `/presets`로, 그 밖은 「지우지 못했습니다. 다시 시도해 주세요.」와 함께 지우기 전 상태로 남는다.
- 이름·담기·순서를 바꾼 뒤 저장 전에 떠나면 텍스트 자료 화면과 같은 「저장하지 않은 입력이 있습니다. 이동하시겠습니까?」를 묻는다(`useUnsavedGuard`·`useUnsavedTraverseGuard`·`useUnsavedChanges`).
- 프리셋 이름과 자료 제목은 React 글자로만 그린다. 이름·제목·자료 ID를 `console`이나 오류 보고에 남기지 않는다.
- 조작 요소에는 `data-testid`(`presets-*`, `preset-*`)를 단다.

## 한계

- `node --test` 시험은 합성 응답과 서버 렌더링으로 한 행동 시험이다. 마운트 효과(열 때 불러오기, 첫 저장 뒤 주소 바꾸기, 지운 뒤 이동, 저장 실패 뒤 초점, 순서 단추 초점)는 이 시험에서 돌지 않아 브라우저에서 따로 확인한다. 320px 폭의 헤더·편집 화면도 브라우저에서 본다.
- 같은 프리셋을 두 창에서 동시에 저장하면 나중 저장이 이긴다(U1 R-08).

## 시험

- `node --test test/presets.test.mjs`: 프리셋 호출의 경로·몸통·응답 모양·실패 구분, 본인 Catch 호출의 `publishable` 쿼리, 메뉴 순서·현재 자리, 복귀 허용 목록, 목록 상태 넷·50개·글자 표시·`<b>` 이름, 편집 요청 수(상세·저장소 목록·고르기 목록·세기, [더 보기]·걸러 보기), 담기·빼기·20개·60,000자 막힘·세기 실패와 늦은 세기·늦은 목록 버림, 순서 단추, 이유 글, 상한 넘음, 이름 검사, 첫 저장 뒤 주소·두 번째 저장 `PUT`, 저장 중 막힘, 저장 뒤 글자 수·이유 맞춤, 저장 실패 표, 다시 불러오기 실패, 지우기 확인·취소·실패, 이탈 경고 대상, 접근성 속성, 옮겨 온 고르기 동작(PDF 상태·걸러 보기·목록 실패), `console` 없음. 합성 응답만 쓴다.
