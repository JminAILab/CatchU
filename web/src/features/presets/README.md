# 프리셋 화면 (발행 프리셋 U2)

지원자가 발행에 쓸 자료 묶음(프리셋)을 만들고 고치는 화면이다. 주소는 `/presets`(목록)·`/presets/new`(새 프리셋)·`/presets/[presetId]`(수정)이고 회원 헤더의 「프리셋」으로 들어간다. 발행 화면(`/publications/new`)은 여기서 만든 프리셋을 1~5개 골라 발행한다([발행·발행본](../publications/README.md)). 회원 가드·API 호출·토큰은 공통 기반(`(member)` 레이아웃, `api.member`)을 쓴다. 서버 검증과 글자 수·발행할 수 없는 이유 계산은 api(발행 프리셋 U1, [api/docs/presets.md](../../../../api/docs/presets.md))가 하고, 화면은 그 결과를 미리 보일 뿐이다.

기준: [U2 기능 설계](../../../../aidlc/spaces/default/intents/261118-publication-presets/construction/u2-applicant-screens/functional-design/functional-spec.md) 흐름 1·2, [규칙](../../../../aidlc/spaces/default/intents/261118-publication-presets/construction/u2-applicant-screens/functional-design/rules.md) BR1~BR3, [NFR 설계](../../../../aidlc/spaces/default/intents/261118-publication-presets/construction/u2-applicant-screens/nfr-design/), 다듬은 화면 [M1~M3](../../../../aidlc/spaces/default/intents/261118-publication-presets/inception/refined-mockups/mockups.md)·[interaction-spec](../../../../aidlc/spaces/default/intents/261118-publication-presets/inception/refined-mockups/interaction-spec.md).

## 동작

### 목록 (M2)

- 열면 「프리셋 목록을 불러오고 있습니다.」를 보이고 `GET /v1/presets`를 한 번 부른다(쪽 나눔 없음, 50개까지). 받은 순서(만든 순서)대로 이름, 「항목 N개 · M자」(천 단위 쉼표), 발행할 수 없는 자료가 있으면 「 · 발행할 수 없는 자료 N개」, 60,000자를 넘으면 「 · 상한을 넘었습니다」, <수정>(읽히는 이름 「(이름) 수정」)을 보인다. #632부터 발행할 수 없는 자료 수와 상한 넘음은 「항목 N개 · M자」 뒤의 주의 표시(글자 그대로)이고, 제목 아래에 「저장한 묶음을 확인하고 발행에 사용할 구성을 관리하세요.」가 있다. 펼침·더 보기 메뉴·돌아올 때 복원은 없다.
- 0개면 「아직 만든 프리셋이 없습니다. [새 프리셋]으로 만들어 보세요.」, 실패면 「프리셋 목록을 불러오지 못했습니다.」와 [다시 불러오기]다. 실패를 0개로 보이지 않는다.
- [새 프리셋]은 단추다. 50개면 `disabled`로 막고 「프리셋은 50개까지 만들 수 있습니다.」를 보이며 그 글을 단추의 `aria-describedby`로 잇는다.

### 편집 (M3)

- 수정 화면은 상세 1, 새 프리셋은 상세 없이 연다. 둘 다 저장소 목록 1(Catch 작은 줄의 저장소 이름, 실패하면 이름만 뺀다) + 고르기 목록 3(Catch·텍스트 자료·PDF 첫 쪽) + 세기 최대 3이다. 상세 404는 「프리셋을 찾을 수 없습니다.」와 <프리셋 목록으로>만, 그 밖의 실패는 「프리셋을 불러오지 못했습니다.」와 [다시 불러오기]다.
- 내 Catch 목록은 `GET /v1/catches?publishable=true`(공개·확인됨·보호 아님만)이고, 「작성자 설명을 쓴 Catch만 보기」를 켜면 `authorDescription=written`도 붙인다. 작은 줄은 「저장소 이름 · 설명 안 씀 · 불일치 표시됨」이다(공개 상태 글은 뺀다). 글 추출이 끝난 PDF만 고를 수 있다.
- 쪽을 하나 불러올 때마다 그 쪽의 고를 수 있는 자료(Catch 전부·텍스트 자료 전부·추출이 끝난 PDF)를 `POST /v1/presets/measure`로 한 번 센다. 고를 수 있는 자료가 없는 쪽은 부르지 않는다. 단추는 목록 응답이 오면 먼저 그리고, 글자 이유는 세기 응답 뒤에 붙는다. 세기가 실패한 쪽은 글자 수를 모르는 채로 두고 글자 이유로 막지 않는다(저장 때 서버가 검사한다).
- 걸러 보기를 바꾸거나 목록을 다시 부르면 앞 요청을 끊고 세대를 올려, 늦게 온 옛 목록·옛 세기 응답은 버린다. [더 보기]는 부르는 동안 다시 누를 수 없다.
- 고르기는 체크박스이고(#632) 다시 누르면 빠진다. 줄 전체가 이름표라 이름·작은 줄·막힌 이유가 함께 읽히고, Space로만 고른다(Enter로는 고르지 않는다. 승인된 조작 기준의 「Enter·Space」는 이 결정으로 바뀌었다). 같은 자료는 한 번만 담긴다. 20개를 담으면 안 담긴 체크박스를 막고 그 줄에 「항목은 20개까지 담을 수 있습니다」, 담으면 60,000자를 넘는 자료는 「전체 글이 60,000자를 넘습니다」를 보인다. 담긴 체크박스는 막지 않는다. 자료가 많아도 「담긴 자료와 순서」가 밀려나지 않게 고르기 목록만 스크롤한다(화면 높이 640px 이하에서는 페이지 스크롤).
- 「담긴 자료와 순서」 아래 줄은 상한을 함께 보인 「항목 N개 / 20개 · M자 / 60,000자」이고(#632), 글자 수를 모르는 자료가 하나라도 있으면 「M자 / 60,000자」 대신 「글자 수를 세지 못했습니다」다. 합이 60,000자를 넘으면 그 아래에 「전체 글이 60,000자를 넘어 발행할 수 없습니다.」를 보이고 [저장]은 막지 않는다. 상세의 이유(비공개·보호·확인 필요·추출 미완료)는 그 줄에 글자로 붙는다. 목록 아래에 「프리셋을 수정해도 이미 보낸 링크는 바뀌지 않습니다.」와 안내 두 줄(「손잡이를 드래그하거나 순서를 직접 지정할 수 있습니다.」, 「「빼기」로 빼면 왼쪽 선택도 해제됩니다. 원본은 남습니다.」)이 있다.
- 순서는 손잡이 드래그나 「순서 직접 지정」으로 바꾸고 [빼기]로 뺀다([위로][아래로]는 #632에서 없앴다). 동작은 아래 「순서 목록」에 있다.
- 「목록으로」(아래)와 「← 프리셋 목록」(위)은 둘 다 `/presets` 링크라 저장하지 않은 입력이 있으면 묻는다. 「목록으로」 · 저장 결과 칸 · [저장] · [프리셋 지우기] 순서라 첫 저장 뒤 Tab은 [프리셋 지우기]로 간다.
- 이름 칸은 보이는 이름표 「프리셋 이름」과 도움말 「1~50자 · 받은 사람 화면의 탭 이름입니다.」(`aria-describedby`)가 있다. [저장]은 이름을 앞뒤 공백을 빼고 1~50자(코드 포인트)인지 먼저 보고, 아니면 요청하지 않고 칸 아래 「이름을 1~50자로 써 주세요.」(`role="alert"`, 칸에 `aria-invalid`)를 보인다.
- 저장 중에는 이름 칸·고르기·걸러 보기·순서(손잡이·번호 칸·[빼기]·「순서 직접 지정」)·[저장]·[프리셋 지우기]를 모두 막고 「저장하고 있습니다.」를 보인다. 새 프리셋은 `POST`, 고치기는 `PUT`이다. 첫 저장(201) 뒤에는 「저장하지 않은 변경」을 끈 다음 라우터의 `replace`로 `/presets/{presetId}`에 옮긴다(뒤로 가기 기록을 더하지 않음, NFR 설계 Q1 B). 옮긴 화면은 상세를 불러 고치기 상태로 그린다: 다음 [저장]은 `PUT`, h1은 「프리셋 수정」, [프리셋 지우기]가 보인다. 고르기 목록·저장소 목록·세기도 그 화면이 다시 부른다. 주소만 바꾸는 `history.replaceState`는 쓰지 않는다. 회원 가드가 주소마다 회원을 다시 확인하며 화면을 새로 만들어, 빈 「새 프리셋」이 다시 그려졌다(Build and Test 되돌아가기 1).
- 수정 화면의 저장이 성공하면 늘 그려 둔 `role="status"` 칸에 「저장했습니다.」를 보이고 상세를 한 번 다시 불러 같은 자료의 글자 수·이유만 서버 값으로 맞춘다(담긴 목록은 바꾸지 않는다). 다시 불러오기가 실패하면 「저장했습니다. 내용을 다시 불러오지 못했습니다.」와 [다시 불러오기]다. 다음 변경이 생기면 「저장했습니다.」는 사라진다. 첫 저장의 「저장했습니다.」는 옮기기 전에 그 프리셋 ID와 함께 이 모듈 안 메모리에 남기고, 옮긴 화면이 열 때 같은 ID면 한 번 꺼내 쥐고, 상세가 준비된 렌더에서 빈 상태 칸이 그려진 뒤(효과) 글을 넣는다(주소·브라우저 저장소에 두지 않음). 글이 든 채 새로 생긴 칸은 화면 낭독기가 읽지 않을 수 있어서다(접근성 점검 A9). 글을 넣으면 초점을 [저장]에 둔다. 옮긴 화면은 새로 만들어져 초점이 사라지고, 그대로 두면 Tab이 머리글로 간다(#629 리뷰). 새로 고침·다시 열기·다른 프리셋 화면에서는 보이지 않는다.
- 편집 화면 모델은 정리(`dispose`) 뒤 다시 열면(`open`) 정리 표시를 되살린다. 개발 모드의 React Strict Mode가 효과를 마운트→정리→마운트로 두 번 돌려도 상세·저장 결과를 버리지 않는다. 마지막 정리 뒤 늦게 온 결과는 버린다.
- 저장 실패는 이유별 글(`role="alert"`)이고 입력·담은 자료·순서를 남기며 초점은 [저장]에 돌아온다: 409 「프리셋은 50개까지 만들 수 있습니다.」, 400 `maxTotalLength` 「전체 글이 60,000자를 넘어 저장할 수 없습니다. 자료를 빼 주세요.」, 404 「담은 자료나 프리셋을 찾을 수 없습니다. 목록을 다시 불러와 주세요.」와 <프리셋 목록으로>, 그 밖 「저장하지 못했습니다. 다시 시도해 주세요.」. 400 `name`은 이름 칸 아래에만 보인다.
- [프리셋 지우기](수정 화면에만)는 「‘(이름)’ 프리셋을 지울까요? 이미 보낸 발행본은 그대로 남습니다.」 확인(`window.confirm`)을 거친다. 취소하면 그대로, 204·404면 경고 없이 `/presets`로, 그 밖은 「지우지 못했습니다. 다시 시도해 주세요.」와 함께 지우기 전 상태로 남는다.
- 이름·담기·순서를 바꾼 뒤 저장 전에 떠나면 텍스트 자료 화면과 같은 「저장하지 않은 입력이 있습니다. 이동하시겠습니까?」를 묻는다(`useUnsavedGuard`·`useUnsavedTraverseGuard`·`useUnsavedChanges`).
- 프리셋 이름과 자료 제목은 React 글자로만 그린다. 이름·제목·자료 ID를 `console`이나 오류 보고에 남기지 않는다.
- 조작 요소에는 `data-testid`(`presets-*`, `preset-*`)를 단다.

### 순서 목록 (#632)

프리셋 편집의 「담긴 자료와 순서」와 발행의 「고른 프리셋과 순서」가 같은 부품(`../publications/pick-parts.tsx`의 `ReorderList`, 계산은 `reorder.ts`)을 쓴다. 기준: [#632 팀장 결정](https://github.com/JminAILab/CatchU/issues/632#issuecomment-7123841889). 새 라이브러리 없이 포인터 이벤트로 만들었다.
- **드래그:** 줄 왼쪽 손잡이에서만 끌기가 시작된다(터치도 같고, 손잡이 밖은 평소처럼 스크롤된다). 손잡이는 Tab 순서 밖이고 화면 낭독기에 숨긴다. 끄는 줄이 따라오고 놓을 자리에 선이 보인다. 목록이 상자 안에서 스크롤될 때 포인터가 상자 테두리를 넘어도(받아 주는 거리 안) 끄는 줄과 선은 상자의 보이는 범위 안에 남고, 놓으면 그 선이 가리키던 자리에 들어가며 놓은 줄이 가려 있으면 보이게 스크롤한다. 끝에 일부만 보이는 줄은 가운데가 보이는 범위 밖이면 그 줄 앞으로 센다. 목록 테두리에서 줄 하나 높이까지 벗어나 놓은 것은 받고, 그보다 멀리서 놓거나 Esc를 누르면 순서를 그대로 두고 「순서를 바꾸지 않았습니다.」를 알린다. 목록이 넘쳐 스크롤될 때는 위·아래 끝 줄 하나 높이의 띠에서 스스로 스크롤한다: 띠에 들어오면 초당 약 2줄에서 시작해 깊어질수록 빨라지고 테두리에서 최대 초당 약 6줄이다. 두 값은 줄 높이 기준의 시작 값이다(`reorder.ts`의 `DROP_SLACK_ROWS`·`SCROLL_ROWS_PER_SECOND`). 터치 기기(`pointer: coarse`)에서는 손잡이·번호 칸이 44px다. 끄는 동안에만 화면의 글자 선택을 막는다(iOS Safari가 손잡이를 길게 눌러 끌 때 둘레 글자를 선택하고 돋보기·복사 메뉴를 띄워서다). 놓거나 그만두면 되돌리므로 평소의 본문 선택은 그대로다.
- **순서 직접 지정:** 항목이 둘 이상이면 보이는 「순서 직접 지정」을 누르면 줄마다 번호 칸이 생긴다(읽히는 이름 「(이름) 순서, 1에서 N까지」, 안내는 `aria-describedby`). Enter로만 확정하고, 1~N의 정수가 아니면 고쳐 넣지 않고 이유를 알린다(`aria-invalid`). Enter 없이 칸을 벗어나면 값을 버리고 「Enter를 누르지 않아 순서를 바꾸지 않았습니다.」를 알린다. 옮기면 「‘(이름)’ 자리: N번째로 옮겼습니다.」를 알리고 초점은 옮긴 항목의 번호 칸에 둔다. 번호 칸에 새로 초점이 오면(켠 직후, 옮긴 직후, Tab, 마우스로 누름) 안의 숫자를 전체 선택해, 친 숫자가 원래 숫자 뒤에 붙지 않고 대신한다.
- **[빼기]:** 그대로다. 뺀 뒤 초점은 다음 줄(없으면 앞 줄)의 [빼기], 목록이 비면 그 자료·프리셋의 고르기 체크박스다.
- 알림(`role="status"`)과 오류(`role="alert"`) 칸은 늘 그려 둔다. 저장·발행 중에는 손잡이·번호 칸·[빼기]·「순서 직접 지정」을 막고, 끄는 도중 저장·발행이 시작되면 놓아도 순서를 바꾸지 않는다.
