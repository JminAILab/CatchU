# 로그인 후 홈 (D, #155)

`/home`의 연결 상태 안내와 다음 행동 이동이다. 근거는 [홈 흐름 초안](../../../../docs/ai-dlc-input-mvp/CatchU_서비스홈_흐름_와이어프레임_초안.md) §5.3·§5.4·§6.2·§7.1, #155 완료 기준과 [#155 합의](https://github.com/JminAILab/CatchU/issues/155#issuecomment-6488715811)이며, 초안의 문구·배치는 [제안] 지위 그대로다.

## 파일

| 파일 | 역할 |
|---|---|
| `home-readiness.ts` | 조회 결과 → 표시 상태 판정(순수 함수). 상태별 상태 이름·문구·단계·다음 행동 |
| `home-api.ts` | `GET /v1/me`(저장소 연결 관리 #153의 `githubState()`를 그대로 씀)와, 연결됨일 때만 `GET /v1/me/analysis-summary`(#432 계약·#434 구현, [api 안내](../../../../api/docs/analysis-history.md#홈용-본인-접수-이력-유무--428))를 읽는다. 조회 한 번의 시작·중단과 늦은 응답을 버리는 규칙(`startHomeLookup`·`currentHomeLookup`)도 둔다 |
| `use-home-readiness.ts` | 세션·재조회 번호마다 위 조회를 시작하고, 세션 변경·재조회·화면 이탈 때 중단한다 |
| `home-guide.tsx` | 연결 안내 표시 컴포넌트. 받은 내용만 그린다 |
| `home-member-page.tsx` | 조회 중·조회 실패·연결 안내와 다음 행동 버튼을 조립한다 |
| `home.module.css` | 홈 스타일. 전역 색·글꼴 변수만 쓴다 |

## 표시 규칙

| 조회 결과 | 상태 이름 | 표시 | 다음 행동 |
|---|---|---|---|
| 조회 중 | — | ‘홈 준비 상태를 확인하고 있습니다’ | 없음 |
| 조회 실패·계약과 다른 응답(연결됨에서 접수 이력 유무만 실패한 경우 포함) | — | ‘홈 준비 상태를 불러오지 못했습니다’ + ‘다시 불러와 주세요.’ + [다시 불러오기](문구는 제안) | 같은 조회만 다시 보낸다 |
| `DISCONNECTED` | GitHub 미연결 | 단계 표시(현재: GitHub 연결) + 연결 안내 | [프로필에서 GitHub 연결] → `/profile/github`. 전환 꺼짐: 비활성 + 이유 |
| `REAUTH_REQUIRED` | GitHub 재연결 필요 | 단계 표시(현재: GitHub 연결) + 재확인 안내 | [GitHub 다시 연결] → `/profile/github`. 전환 꺼짐: 비활성 + 이유 |
| `CONNECTED` + 이력 없음(`false`) | GitHub 연결됨 | 단계 표시(현재: 레포 연결) + 레포 연결 안내(초안 §5.4) | [내 자산에서 레포 연결] → `/assets` |
| `CONNECTED` + 이력 있음(`true`) | GitHub 연결됨 · 레포 연결됨 | 단계 표시 없이 ‘분석 요청 내역은 내 자산의 저장소 연결 관리에서 확인해 보세요’ 한 줄(준비 완료, 문구는 제안) | [내 자산으로 가기] → `/assets` |

- 조회 중·조회 실패는 미연동으로 표시하지 않는다(#155 완료 기준). 접수 이력 유무 조회 실패(500 등)도 이력 없음으로 바꾸지 않는다. 실패 문구는 GitHub 연결 실패로 읽히지 않게 ‘홈 준비 상태’라고 쓴다.
- 회원 전환·로그아웃·화면 이탈·재조회 뒤 늦게 온 응답은 반영하지 않고, 현재 세션·현재 재조회 번호의 결과만 그린다. 연결 상태를 읽는 사이 중단되면 접수 이력 조회를 보내지 않는다.
- 접수 이력 유무는 GitHub 연결됨일 때만 읽고 쓴다(#155 합의). 연결된 레포 = 분석 요청이 접수된 저장소 1개 이상이며 진행 중·실패와 무관하다(초안 §7.1). 이력 있음은 분석이 끝났거나 지금 분석할 수 있다는 뜻이 아니므로 그렇게 안내하지 않는다.
- 준비 완료 화면은 초안 §5.5의 두 상자 구성이 [제안·미채택]이라 같은 안내 틀에 내 자산 이동 하나만 둔다. 공유 링크 상자 등 구성은 #155 검토로 정한다.
- 미연동·재연동 필요의 목적지는 GitHub 연동 화면(`/profile/github`, [#253](../github-connection/README.md))이다. 공통 인증 통합 시험 전환(`NEXT_PUBLIC_AUTH_SESSION_INTEGRATION`)을 끈 제품 기본값에서는 GitHub에 다녀오면 로그인이 사라져 연결을 마칠 수 없으므로, 두 버튼을 비활성(`unavailable`)으로 두고 연동 화면과 같은 이유를 버튼 아래에 보인다(`aria-describedby`). 기준과 문구는 #253의 `githubStartBlockedReason`이며 `use-home-readiness.ts`가 `homeView()`에 넘긴다. 전환을 켜면 연동 화면으로 이동한다.
- 재연동 필요의 안내 방식은 초안 §6.2에서 [미정]이다. 지금은 미연동과 상태 이름·문구·버튼 이름을 구분하고 같은 연동 화면을 가리킨다.
- `/me` 조회는 회원 가드의 조회와 별도로 한 번 더 보낸다(`/assets`의 저장소 연결 관리와 같은 방식). 연결됨이면 이어서 `/me/analysis-summary`를 보낸다.

## 인증 연결 기준과 후속

- 현재 조회는 dev의 기존 회원 호출(`api.member`, 메모리 토큰)과 회원 가드 기준이다. 아래 검사와 브라우저 확인도 **공통 인증 통합 시험 전환(#308 `auth-integration`)을 끈 상태** 기준이다.
- **후속(#308 전환 시):** 홈의 `use-home-readiness.ts`는 메모리 토큰 저장소로 세션을 구분한다. 전환을 켜면 공통 인증의 세션 범위·`skipped`(보내지 않은 요청·이전 세션 응답) 처리에 맞춰 홈 조회를 연결하고, 조회 중·실패·재시도·세션 변경을 다시 검증해야 한다. #308이 자산·링크 화면에 한 연결과 같은 작업이며 이 PR에는 포함하지 않는다.

## 아직 하지 않는 것

- 분석 상태·결과·집계, 공유 링크 상자, 12월 피드(초안 §5.1·§5.5·§5.6). 홈은 분석 목록·상태를 조회하지 않는다.

## 외형 보완

- 바꿔도 되는 곳: `home-guide.tsx`의 마크업, `home.module.css`, `home-member-page.tsx`의 배치와 `HomeActionButton`의 모양.
- 바꾸지 않는 곳: `home-readiness.ts`의 상태 판정·상태 이름·이동 대상·비활성 이유, `home-api.ts`·`use-home-readiness.ts`의 조회·재조회, 비활성 버튼의 `disabled`·이유 연결. 바꿔야 하면 #155에서 먼저 조율한다.
- 조회 중·조회 실패가 연결 안내처럼 보이지 않게 하고, 단계 표시는 현재 단계를 시각만이 아니라 `aria-current`로도 구분한다.

```tsx
<HomeGuide status={view.status} step={view.step} title={view.title} description={view.description}
  action={<HomeActionButton action={view.action} />} />
```

## 검사

- `npm test`의 `test/home-readiness.test.mjs`: 조회 중, 세 연동 상태와 연결됨의 이력 없음·있음별 상태 이름·단계·다음 행동(이동 대상, 전환 꺼짐의 비활성과 이유), 미연동과 재연동 필요의 구분, 미연결·재연결 필요에서는 이력 유무를 읽지 않는지, 이력 있음을 분석 완료·분석 가능으로 안내하지 않는지, ‘연결 전’ 표기 미사용, 조회 실패·통신 오류·계약과 다른 응답(연동 필드 없음·알 수 없는 값, 이력 유무 500·통신 오류·boolean 아님)이 미연동·이력 없음이 아닌 조회 실패가 되는지, 회원 전환·로그아웃·화면 이탈·재조회 뒤 늦은 응답을 반영하지 않는지와 중단 뒤 이력 조회를 보내지 않는지(hook의 effect를 같은 함수로 재현). 합성 응답이며 실제 로그인·API 연결·React 렌더링은 검사하지 않는다.
- 브라우저 확인 기록은 #155 PR에 남긴다.
