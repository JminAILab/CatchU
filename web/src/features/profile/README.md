# 프로필 화면 — #137

회원의 최초 프로필 입력(/profile/setup), 상세 프로필(/profile), 기존 프로필 수정(/profile/edit)을
GET /v1/me·PUT /v1/me/profile([#135](../../../../api/docs/member-profile.md))에 연결한다.
세 화면 모두 회원 경로 가드(#106) 안에서 열리며 별도 토큰 처리를 하지 않는다. 인증 만료는 공통 API·회원 가드가 처리한다.
조회·저장·검증은 profile-api.ts의 함수 하나를 세 화면이 함께 쓴다.

표시 이름은 필수이며 trim 후 최대 50 코드 포인트, 소개 200, 직무 100,
기술 20개·각 50 코드 포인트를 검사한다. 선택 값은 trim·중복 제거하지 않는다.
NUL·고립 서로게이트를 거부한다. 입력은 브라우저 메모리에만 보관한다.

## 최초 입력 — /profile/setup

본인 프로필을 GET /v1/me로 조회해 네 필드를 편집한다. 이름이 빈 회원만 연다.
PUT /v1/me/profile 성공 후 GET /v1/me를 다시 조회하고 이름이 저장됐음을 확인하면 /home으로 이동한다.
저장 실패·결과 불명 시 입력을 유지한다. 처리되지 않은 저장(아래 「프로필 수정」의 통합 시험 전환 항목)도 같은 기준이다. 저장 성공 후 조회만 실패하면 입력을 잠그고
'회원 정보 다시 확인'으로 GET만 재시도한다. 자동 저장·자동 재전송은 하지 않는다.
최초 입력에는 취소 버튼이 없다. 미저장 입력의 링크 이동과 새로고침·창 닫기는 확인한다.

## 상세 프로필 — /profile

프로필 메뉴의 [프로필 보기]가 여는 화면이다. GET /v1/me의 `profile` 네 필드를 저장된 값 그대로 표시한다.
빈 소개·직무·기술은 '입력하지 않았습니다'로 표시하며 직접 입력한 정보임을 안내한다.
조회 중에는 불러오는 중, 실패·응답 형식 오류에는 '다시 불러오기'를 보이고 빈 프로필이나 이름 미저장으로 바꾸지 않는다.

- [프로필 수정] → /profile/edit.
- [GitHub 연결 상태] → /profile/github([GitHub 연동 화면](../github-connection/README.md), #253). 연결 상태 조회·표시는 그 화면이 한다.

## 프로필 수정 — /profile/edit

저장된 프로필을 GET /v1/me로 불러와 같은 네 필드를 편집한다. 조회 중에는 입력과 저장을 열지 않고,
조회 실패는 오류와 '다시 불러오기'·'돌아가기'(→ /profile)를 보인다. 빈 프로필이나 다른 값으로 대체하지 않는다.

- 저장은 PUT /v1/me/profile 한 번이다. 성공하면 /profile로 이동한다(`router.replace`). 상세가 다시 조회하므로 저장된 값이 보인다.
- 저장 실패·응답 유실·성공 형식 오류는 이 화면과 입력을 유지하고 성공 안내나 이동을 하지 않는다.
  '저장 결과를 확인하지 못했습니다. 입력을 유지했습니다. 다시 시도해 주세요.'를 보이며 자동 재전송은 하지 않는다.
  저장은 네 필드 전체 교체라 사용자가 다시 저장해도 중복되지 않는다.
- 통합 시험 전환을 켰을 때(#286) 로그인 연장 뒤 거부는 '로그인이 연장되었습니다. 다시 눌러 주세요.', 보내지 않은 저장은
  '지금은 요청을 보내지 않았습니다. 입력은 그대로 두었습니다.'로 안내하고 입력을 유지한다. 앞선 저장의 결과를 모르면 그 안내도 남긴다.
  갱신하지 못한 회원 인증 401(재인증 필요 등)도 서버가 인증 단계에서 거부해 저장되지 않은 것이라 결과 불명으로 두지 않고
  '로그인이 필요해 저장하지 않았습니다. 입력은 그대로 두었습니다.'로 안내한다(`reauth-rejected`, 문구는 제안, #286 10/29 검증 확인 필요 1).
  다시 로그인 안내는 재인증 안내가 맡는다. 세 경우 모두 자동으로 다시 보내지 않으며 최초 입력에도 같은 안내를 쓴다(`unprocessedSaveMessages`).
  보낸 뒤 로그인이 바뀌어 반영하지 않은 응답은 결과 불명으로 두며 새 회원 화면에 보이지 않는다([담당 합의](https://github.com/JminAILab/CatchU/issues/286#issuecomment-6209853081)).
- [취소]는 /profile로 돌아가며 저장된 프로필을 바꾸지 않는다. 미저장 변경이 있으면 먼저 확인하고,
  머무르기를 고르면 이동하지 않고 입력을 유지한다.
- 미저장 변경의 판정은 네 필드와 기술의 순서·빈 항목까지 저장본과 비교하고, 기술 입력칸의 미확정 변경(아래 「기술 입력」)도 넣는다. 링크 이동과 새로고침·창 닫기도 확인한다.
  같은 판정을 `useUnsavedChanges`에도 등록해 로그아웃·재인증 [다시 로그인] 전 확인(#287)이 쓴다.
- 처리 중·저장 성공 뒤에는 저장·취소를 막는다. 세션이 바뀌거나 화면을 떠나면 진행 중 요청의 취소를 시도하고, 해당 응답으로 화면 안내·이동을 처리하지 않는다. 이미 서버에 전달된 저장은 반영됐을 수 있다.
- 이름이 빈 회원은 회원 가드가 /profile/setup으로 보내므로 수정 화면에서 첫 이름을 저장할 수 없다.

## 기술 입력 — #469

최초 입력과 프로필 수정이 같은 `ProfileFields`를 쓴다. 입력칸 하나와 [추가]가 위, 안내 문구 '기술 칩을 클릭하면 수정할 수 있습니다.', 칩 상자 순서다. 상태 규칙은 `skill-editor.ts`에 있고, 입력칸·선택 상태는 두 화면이 가져 미저장 판정과 저장 전 확인에 쓴다.

- [추가]는 입력한 이름을 목록 끝에 붙이고 입력칸을 비운다. 칩 이름을 누르면 그 칩을 강조하고 이름을 입력칸에 채우며 버튼이 [수정]이 된다. [수정]은 그 칩에 반영하고 입력칸을 비운 추가 모드로 돌아간다.
- 고른 칩을 다시 누르면 미확정 수정을 버리고 선택을 푼다(칩 이름은 그대로). 칩의 ×는 그 기술만 지운다. 별도 [지우기]·[선택 취소]는 없다.
- 새 기술을 쓰던 중이거나 고른 칩을 고치던 중(아래 미확정 변경)에 다른 칩을 누르면, 그 변경을 버리고 누른 칩의 수정 모드로 바뀐다. 확인창이나 전환 차단은 두지 않는다(#469 확정 사항).
- 입력칸의 Enter는 [추가]·[수정]이며 폼 제출(전체 저장)로 이어지지 않는다. 한글 등 입력기 조합을 확정하는 Enter(`isComposing` 또는 keyCode 229)는 조합만 확정한다.
- 빈 값·앞뒤 공백·같은 이름은 기존처럼 막거나 다듬지 않는다. 비었거나 공백만 있는 칩은 '(빈 항목)'으로 보인다. 20개면 [추가]만 막히고 수정·삭제는 된다. 50 코드 포인트를 넘거나 NUL·고립 서로게이트가 든 이름은 [추가]·[수정] 때 반영하지 않고 입력칸 아래에 안내한다. 저장 전 검사(`profileErrors`)도 같은 제한(`PROFILE_SKILL_LIMITS`)을 쓴다.
- 서버 반영은 기존 전체 [저장]이다. 미확정 변경은 새 기술을 입력했거나 고른 칩의 이름을 바꾼 뒤 [추가]·[수정]하지 않은 상태다(칩을 고르기만 한 것은 아니다). 이때 [저장]은 요청을 보내지 않고 입력을 둔 채 [추가]·[수정]을 안내하며, 미저장 확인에도 이 변경이 들어간다.
- 칩을 지우면 초점을 같은 자리의 다음 칩(없으면 앞 칩, 칩이 없으면 입력칸)으로, 칩을 고르거나 [추가]·[수정]하면 입력칸으로 옮긴다.

## 이 범위에서 하지 않은 것

- 브라우저 뒤로/앞으로 이동의 미저장 확인은 연결하지 않았다. 버튼형 [로그아웃]·재인증 [다시 로그인]의 확인 흐름은 #287(2026-11-03 종료)로 연결됐다(이 화면은 판정 등록만). 공통 인증의 통합 모드(`NEXT_PUBLIC_AUTH_SESSION_INTEGRATION=true`)를 켰을 때만 연결되며, 제품 기본은 켜짐이다(2026-11-11 팀장 승인, #467. [로그인·인증 화면 「현재 상태」](../auth-screens/README.md#현재-상태-통합-시험-전환-아래-연결-제품-기본-켜짐)).
- 수정 화면의 '프로필 수정은 기존 공유 링크의 다음 조회에도 반영됩니다' 안내는 넣지 않았다. 팀장 결정은 있으나 수신자 화면이 현재 프로필을 읽는지 이 PR에서 확인하지 않았다.
- Google 이름을 미리 채우지 않는다. 저장된 표시 이름을 Google 이름으로 덮어쓰지 않는다.
- 상세의 [돌아가기]는 두지 않았다(헤더로 이동).

  기술 칩 입력은 상태 규칙(`test/profile-skill-editor.test.mjs`)과 `ProfileFields`의 정적 렌더링 구조(`test/profile-skill-fields.test.mjs`)를 검사한다.
  그 밖의 화면 컴포넌트를 직접 렌더링하는 자동 검사는 없고, 클릭·키보드·CSS 배치는 브라우저에서 확인한다.
- node test/profile-http.integration.mjs (web 폴더): 실제 web API 함수 → Nest HTTP → PostgreSQL.
  최초 입력과 수정 저장·재조회·잘못된 입력 거부 시 기존 값 보존·다른 회원 프로필 분리를 확인한다.
  api 의존성 설치·빌드가 필요하다. 127.0.0.1의 전용 catchu_issue137_test DB(기본 포트 55137, TEST_DB_PORT로 변경),
  catchu/catchu_local 합성 접속 설정만 사용한다. 마이그레이션과 합성 회원·프로필을 생성한다.
  다른 DB로 포워딩하지 말고 전용 postgres:16 컨테이너에서 실행한 후 해당 컨테이너를 정리한다.
- 직접 브라우저에서 최초 입력, 빈 이름 거부, 저장 후 홈 이동, 조회 실패·복구, 저장 실패 시 입력 유지·복구 후 재시도, 동일 회원 재로그인을 확인했다(최초 입력, 2026-10-09·10-14).
  상세·수정 화면의 실제 브라우저 조작은 이 문서의 기록 시점에 확인하지 않았다. PR 본문의 검증 범위를 따른다.
  이후 #137 [종료 정리](https://github.com/JminAILab/CatchU/issues/137#issuecomment-6257904659)(2026-10-19)에서 dev `ad4fa6b`로 실제 API·전용 시험 DB에 연결해 상세·수정 화면을 확인했다.
  web 개발 모드와 운영 빌드를 Windows 헤드리스 Chrome 155로 확인했고, 개발용 로그인·합성 회원을 썼으며 API는 `NODE_ENV=development`였다. 확인하지 않은 경로는 그 댓글에 있다.

## 2026-10-09 연결 검사

기준 dev 144815f 위의 미커밋 변경에서 실제 web API 함수·Nest HTTP·PostgreSQL로 초기 이름 판정, 네 필드 저장, 재조회, 홈 허용, 빈 이름 거부와 기존 값 보존을 확인했다.
저장 완료 함수는 PUT 실패, PUT 성공 뒤 GET 실패 및 GET만 재시도, 세션 변경 후 취소를 모의 응답으로 검사한다.
이후 사용자가 Windows Chrome과 실제 API·전용 PostgreSQL로 위 브라우저 흐름을 확인했다. 저장 성공 직후 조회만 실패하는 분기는 자동 검사로만 확인했으며, 뒤로/앞으로 이동 이탈 방지는 미구현이다. 최초 조회 복구 시 오류 화면이 한 차례 유지된 원인은 상세 기록 부족으로 확정하지 못했다. 이후 통제된 중단·복구 재검사에서는 정상 복구했다.
