# 발행·발행본 화면 (U4 W3·W5)

12월 intent U4(발행·링크) 제출 2의 발행 화면과 작성자 발행본 목록·상세·중지·삭제 화면이다. 주소는 `/publications`(목록)·`/publications/new`(발행)·`/publications/[publicationId]`(상세)이고 회원 헤더의 [발행본]으로 들어간다. 회원 가드·API 호출·토큰은 공통 기반(`(member)` 레이아웃, `api.member`)을 쓰며 이 폴더가 따로 갖지 않는다. 기준: [U4 기능 명세](../../../../aidlc/spaces/default/intents/260925-intent-12/construction/u4-publication-link/functional-design/functional-spec.md) W3·W5·「작성자 API」·「C-09 합의 전 임시 상태」, [업무 규칙](../../../../aidlc/spaces/default/intents/260925-intent-12/construction/u4-publication-link/functional-design/rules.md) BR4·BR5·BR7·BR8, [신뢰성 설계](../../../../aidlc/spaces/default/intents/260925-intent-12/construction/u4-publication-link/nfr-design/reliability-design.md) 「작성자 실패 안내」, [보안 설계](../../../../aidlc/spaces/default/intents/260925-intent-12/construction/u4-publication-link/nfr-design/security-design.md) 「web 화면 출력」, #416 팀장 결정(2026-10-29 Q1 B, 2026-11-02·11-03 [링크 열기]).

| 화면 | 주소 | API |
| --- | --- | --- |
| 발행 | `/publications/new` | `GET /v1/presets`(프리셋 목록, 열 때와 막힘·404·400 `presetIds` 뒤 한 번), `POST /v1/publications`(`{ title, password?, presetIds }`) |

## 동작

### 발행 (W3)

발행 프리셋 U2(다듬은 화면 M4, [기능 설계](../../../../aidlc/spaces/default/intents/261118-publication-presets/construction/u2-applicant-screens/functional-design/functional-spec.md) 흐름 3, [규칙](../../../../aidlc/spaces/default/intents/261118-publication-presets/construction/u2-applicant-screens/functional-design/rules.md) BR4.1~BR4.7)부터 발행 화면은 자료 대신 프리셋을 고른다. 자료 고르기(Catch·텍스트 자료·PDF, 걸러 보기, 저장소 이름)는 [프리셋 편집 화면](../presets/README.md)으로 옮겼다.

- 열 때 「프리셋 고르기」 자리에 「프리셋 목록을 불러오고 있습니다.」를 보이고 `GET /v1/presets`를 한 번 부른다(쪽 나눔 없음). 0개면 「아직 만든 프리셋이 없습니다.」와 <프리셋 만들러 가기>(`/presets`)만, 실패면 「프리셋 목록을 불러오지 못했습니다.」와 [다시 불러오기]다. 실패를 0개로 보이지 않는다(BR4.4).
- 프리셋마다 누르는 단추 하나: 이름, 「항목 N개 · M자」, 막혔으면 이유 하나. 이유는 항목 0개(「담긴 자료가 없어 고를 수 없습니다」) → 발행할 수 없는 자료(「발행할 수 없는 자료가 있습니다: (첫 자료 제목)」, 둘 이상이면 「 외 N개」) → 고른 프리셋들과 더한 항목 수 20개 넘음(「고르면 항목이 20개를 넘습니다」) → 더한 글자 수 60,000자 넘음(「고르면 전체 글이 60,000자를 넘습니다」, 혼자 넘는 프리셋도) 순서로 처음 맞는 것이다. 같은 자료가 두 프리셋에 있으면 두 번 센다. 이미 고른 프리셋은 막지 않는다(BR4.2).
- 고른 프리셋은 「고른 프리셋과 순서 (n/5)」 끝에 더해지고 다시 누르거나 [빼기]로 뺀다. [위로][아래로]로 순서를 정하고 읽히는 이름은 「(이름) 위로」 꼴이다(BR4.1). 다섯 개를 고르면 안 고른 단추를 모두 막고 「프리셋은 5개까지 고를 수 있습니다.」를 목록 위 `aria-live="polite"` 칸에 한 번만 보이며, 단추 안 이유는 항목 0개·발행할 수 없는 자료일 때만 보인다(BR4.3). 고르고 빼고 순서를 바꾸는 동안 서버에 아무것도 보내지 않는다.
- 비공개 Catch를 공개로 바꾼다는 안내(`PRIVATE_CATCH_NOTICE`)는 그리지 않는다. 프리셋에는 공개한 Catch만 담기고 서버도 공개로 바꾸지 않는다(BR4.7).
- 프리셋은 1~5개, 제목은 1~50자(앞뒤 공백 제외), 비밀번호는 쓸 때 8~64자(다듬지 않음)다. [다음]은 막지 않고, 눌렀을 때 넘거나 비면 보내지 않고 안내한다(0개는 「프리셋을 하나 이상 골라 주세요.」, 6개 이상은 「프리셋은 5개까지 고를 수 있습니다.」). 서버 검증이 기준이다.
- 확인 단계는 제목, 「고른 프리셋과 순서」(프리셋 이름을 고른 순서대로), 비밀번호 여부, "발행 시각부터 90일 뒤 만료, 연장 없음"을 보인 뒤 [발행]을 둔다(BR4.5). 고른 자료 목록과 「작성자 설명이 없는 Catch N개」 안내는 그리지 않는다(프리셋 목록 응답에 그 값이 없어 화면이 모름, 기능 설계 열린 질문). 발행 전 미리보기 사본은 만들지 않는다.
- 발행 요청은 `POST /v1/publications`에 `{ title, password?, presetIds }`(고른 순서)다. 옛 `items` 칸은 보내지 않는다.
- 비밀번호를 끄면 비밀번호 체크 아래와 확인 단계의 비밀번호 행(비밀번호 없음)에 "비밀번호 없는 링크는 받은 사람이 Claude 같은 외부 AI 도구로 읽을 수 있습니다."를 보인다(12월 intent U9 BR7.1). 문구는 [`../recipient-claude/recipient-claude-text.ts`](../recipient-claude/recipient-claude-text.ts)의 `AUTHOR_AI_NOTICE` 하나를 두 곳이 같이 쓰고, 확인 단계의 `publish-confirm-password` 칸 글(설정됨·없음)은 그대로이며 링크별 허용 설정은 두지 않는다(시험: `test/u9-recipient-claude.test.mjs` S22).
- [발행]은 응답까지 버튼을 막는다(BR4.9). 재전송 키는 보내지 않는다. 201과 응답 모양이 맞을 때만 완료 화면이며, 완료 화면은 실제 응답의 링크 주소·상태·발행·만료 시각·비밀번호 여부와 [URL 복사]·[링크 열기]·[발행본 상세 보기]를 보인다(BR5.6). 사본 자체는 상세에서 본다.
- 403 `AI_CONSENT_REQUIRED`는 U2 공용 동의 창(`components/ai-consent`, `useAiConsent().run`)이 열고 [동의] 뒤 같은 요청을 한 번 다시 보낸다. [닫기]면 보내지 않고 입력을 남긴다.
- 실패 안내(신뢰성 설계 「작성자 실패 안내」)는 `publishOutcome` → `publishFailureLines`가 맡는다. 어떤 경우든 고른 프리셋·순서·제목·비밀번호 입력은 그대로 두고 첫 줄은 "발행되지 않았습니다"다.
- **막힘 안내(BR4.6):** 막힘 응답의 `details.blockedSources`(줄마다 프리셋 ID·자료 종류·자료 ID, `src/lib/api-response.ts`가 세 칸만 옮김)를 받으면 코드별 첫 줄 아래에 줄마다 「‘(프리셋 이름)’ 프리셋의 ‘(자료 이름)’ 때문에 발행할 수 없습니다.」를 잇는다. 프리셋 목록을 한 번 다시 불러와 프리셋 이름은 프리셋 ID로, 자료 이름은 그 프리셋의 `unpublishableItems`에서 종류·자료 ID로 찾는다. 자료 이름을 못 찾으면 그 자리에 종류(Catch·텍스트 자료·PDF 자료)를, 프리셋 이름을 못 찾으면 「고른 프리셋」을 따옴표 없이 쓴다. 다시 불러오기가 실패하면 그 전 목록으로 찾는다. 새 목록으로 단추 막힘도 다시 정하고, 막힌 프리셋은 고른 목록에 남긴다(지원자가 직접 뺀다). 이름은 글자로만 잇는다.

| 응답 | 안내 | 화면 |
| --- | --- | --- |
| 409 `CONFIRMATION_REQUIRED` / `SOURCE_RESTRICTED` / `CATCH_PRIVATE` | 10월 Catch 문구("작업 사실과 나의 기여를 먼저 확인해 주세요." / "원본 저장소가 보호되어 지금은 공개할 수 없습니다.") / "비공개 Catch는 발행할 수 없습니다."(api 오류 문구와 같은 글) 아래에 `details.blockedSources`의 막힘 줄 | 프리셋 목록을 한 번 다시 불러오고 편집 단계로 돌아간다 |

| 403 `AI_CONSENT_REQUIRED` | 동의 창. 창을 거친 뒤에도 403이면 "외부 AI 전송에 먼저 동의해 주세요." | 확인 단계에 남는다 |

| 401 `AUTH_*` | 로그인 만료 안내 | 입력은 남지만 공통 인증 모드에 따라 화면이 바뀔 수 있다(텍스트 자료 README 「한계」와 같다) |

- 저장하지 않은 입력(고른 프리셋·제목·비밀번호)이 있으면 새로고침·창 닫기·링크 이동(`useUnsavedGuard`), 뒤로·앞으로 가기(`useUnsavedTraverseGuard`), 로그아웃·다시 로그인(`useUnsavedChanges`) 전에 묻는다. 완료 뒤에는 묻지 않는다.

### 발행본 목록·상세 (W5)

- 목록은 서버가 준 최신순 그대로 20개씩 읽고 [더 보기]로 이어 읽는다. 제목·상태(유효·중지됨·만료됨)·비밀번호 여부·발행·만료 시각·링크 주소를 보인다. 중지·만료된 발행본도 보인다(BR8.1).
- [URL 복사]는 상태와 관계없이 있고 실제 클립보드 쓰기에 성공했을 때만 "URL을 복사했습니다."를 보인다. 실패하면 주소를 직접 복사하게 보여 준다.
- [링크 열기](#416 2026-11-02·11-03)는 발행 완료·목록·상세 세 화면에 있고, [URL 복사]가 복사하는 것과 같은 서버 응답의 `url`을 `target="_blank"`·`rel="noopener noreferrer"`로 새 탭에서 연다. 서버가 돌려준 `state`가 `ACTIVE`일 때만 보인다. 새 API는 없고 작성자 로그인으로 받은 사람 접근 조건을 우회하지 않는다(새 탭의 받은 사람 화면이 비밀번호·중지·만료를 그대로 판정한다).
- **발행본 자료의 프리셋 탭(발행 프리셋 U3 M6, [기능 설계](../../../../aidlc/spaces/default/intents/261118-publication-presets/construction/u3-reader-views/functional-design/functional-spec.md) 흐름 1·3):** 상세의 「발행본 자료」는 받은 사람 화면과 같은 부품이라 같은 탭 줄(이름 「발행본 자료」, 고른 프리셋마다 탭 하나, 하나여도 있음, 개수 없음)·탭 아래 열린 탭의 프리셋 이름 전체·키보드(화살표 돎·Home·End)·모든 패널 그려 두고 `hidden`이다. 사본 항목의 `presetOrdinal`(1~5 정수)·`presetName`(앞뒤 공백 뺀 1자 이상)이 없거나 모양이 다르면 상세 응답 전체를 올바르지 않은 응답으로 본다(`isPublishedItem`, BR2.4). 요약의 출처 단추가 다른 탭 항목을 가리키면 그 탭과 대상을 한 번에 바꾸고 「(프리셋 이름) 탭을 열었습니다」를 알린다. [답으로 돌아가기]는 없다. 요약이 위·자료가 아래인 순서와 그 밖의 상세 구성은 그대로다. 자세한 동작은 [받은 사람 화면 README](../recipient/README.md) 「동작」.
- 상세는 `GET /publications/{id}`의 사본을 프리셋 탭마다 항목 순서대로 보인다. Catch는 「AI 설명 초안」·「작성자 설명」·「기록에서 확인한 내용」(작업 사실·본인 기여·근거)을 다른 표지로 나누고(AI 설명 초안이 없으면 그 칸을 그리지 않는다, Catch 개편 CR3 BR7.1) 불일치 표시를 단다(BR1.3·BR4.3·BR7.5). 순서와 근거 접기는 받은 사람 화면과 같은 부품이라 같다: 불일치 표지 → AI 설명 초안 → 작성자 설명 → 기록이고, 기록의 본인 기여·근거 목록은 「근거 자세히 보기」에 접혀 있다가 누르거나 요약 근거 단추가 그 안을 가리키면 펼친다(#488, [받은 사람 화면 README](../recipient/README.md) 「동작」). 텍스트 자료는 제목·본문이다. 빈 설명·초안은 다른 값으로 채우지 않는다.
- 발행본 상세의 PDF 항목(U8)은 [받은 사람 화면 README 「PDF 항목과 사본 열람 (U8)」](../recipient/README.md#pdf-항목과-사본-열람-u8)의 컴포넌트를 쓰고 작성자 사본 경로로 연다.
- 작성자 설명은 칸별로 보인다(새 Catch BR7.1~BR7.5). 저장된 글을 칸 제목 줄(`【칸 제목】`)로 나눠 글이 있는 칸만 h5 칸 제목과 그리고, 빈 칸은 h5째 그리지 않는다. 「더 쓰기」 하나뿐이면(칸 제목 줄이 없는 옛 글 포함) h5 없이 지금처럼 글만이고, 다른 칸과 함께면 h5는 「덧붙인 말」이다. 글이 없으면 「작성자 설명이 없습니다.」다. h5 칸 제목은 상수에서만 오고 h4보다 한 단계 작은 굵은 글이다.
- 작성자 설명 속 GitHub 링크는 주소 전체 대신 이름으로 보인다: 파일 줄은 「파일 이름 · L40–58 · 판본 ba6bba8」, 줄 없는 파일·폴더는 「경로 끝 · 판본」, 커밋은 「커밋 ba6bba8」, 커밋 화면에서 줄 번호를 눌러 얻은 바뀐 줄 주소(`#diff-…R16-R23`)는 「커밋 ba6bba8 · 바뀐 줄 16–23」(L 쪽은 「이전 줄」, 파일 이름은 주소에 없다, NC1 로컬 확인 중 팀장 발견 2026-11-10), PR은 「PR #12」, 판본이 커밋 식별값이 아니면 「브랜치 main」이고, 근거 저장소와 다른 저장소면 앞에 「소유자/저장소 · 」가 붙는다. 표에 맞지 않는 꼴(다른 조각·뒤 경로·포트가 든 주소 등)은 지금처럼 주소 전체다. 질의는 이름에서만 무시하고, 경로는 마디마다 풀어 이름에만 쓰며(풀리지 않으면 원문), 제어·서식 문자는 이름에서 지운다. `href`·`title`은 원래 주소이고 긴 이름은 자르지 않고 줄을 바꾼다. 텍스트 자료 본문 링크는 주소 전체 그대로다.
- AI 답의 근거 강조 범위는 저장된 글 전체의 UTF-16 위치로 오므로 칸마다 칸 안 위치로 바꿔 칸 글과 겹치는 부분만 강조한다. 칸 제목 줄·칸 사이 빈 줄에만 걸치면 강조하지 않고, 링크와 겹치면 지금처럼 링크 전체를 감싸며 위치는 원래 주소 길이로 센다. 같은 칸 제목 줄이 두 번 나와 이어 붙인 칸은 강조하지 않는다(FR1.6 한계).
- 긴 글 접기(#607, 2026-11-19 팀장 결정): AI 설명 초안·「기록에서 확인한 내용」의 작업 사실 목록·PDF 쪽 글은 12줄을 넘으면 6줄만, 지원자가 쓴 글(작성자 설명·텍스트 자료 본문)은 18줄을 넘으면 12줄만 보인다. 기준 이하면 그대로 보이고 단추가 없다. 글자는 자르지 않고 보이는 높이만 줄이므로 강조 위치(저장된 글의 글자 위치)는 바뀌지 않는다.
  - **줄 수:** 본문 글줄만 센다. 문단과 목록 항목마다 그려진 높이를 줄 높이로 나눠 더하고, 작성자 설명의 칸 제목(h5)과 칸·항목 사이 여백은 넣지 않는다. 화면 폭이 바뀌어 줄바꿈이 달라지면 다시 잰다. 접힌 높이는 보일 마지막 글줄의 아래 끝까지라서 칸 제목이 끼어 있어도 글줄은 정해진 수만큼 보인다. 「이 기록으로 알 수 없는 것」과 「근거 자세히 보기」는 접는 틀 밖이라 줄 수에 들지 않는다.
  - **단추:** 같은 자리에서 「전체 보기」와 「접기」로 바뀌고 `aria-expanded`·`aria-controls`로 상태와 대상을 알린다. 화면에 보이지 않는 이름(자료 제목과 칸 이름)을 함께 읽어 어느 글의 단추인지 구분한다. 「N줄」 같은 검토용 글은 없다.
  - **근거 연동:** 강조가 가리키는 글은 그리는 차례에 펼쳐지므로 화면이 강조로 옮길 때 이미 보인다. 규칙은 「근거 자세히 보기」(#488)와 같다: 사람이 다시 접은 뒤 같은 근거 단추를 누르면 다시 펼치고, 강조가 다른 곳으로 가면 자동으로 펼쳤던 글은 접힘으로 돌아가며, 사람이 펼쳐 둔 글은 그대로 둔다. AI 요약과 질의응답 답의 근거 단추가 같은 길(`showEvidence`)을 쓴다.
  - **펼친 뒤 단추 자리:** 펼친 글의 「접기」에 키보드 초점이 있는 동안에만 단추 줄이 화면 아래쪽에 붙고, 초점이 떠나거나 글 끝이 화면에 들어오면 제자리에 놓인다. 긴 글을 키보드로 펼쳐도 화면이 옮겨지지 않아 읽던 자리가 그대로이고 초점을 받은 단추가 보인다. 초점은 한 곳에만 있으므로 여러 글을 펼쳐도 붙는 단추 줄은 하나다. 붙어 있는 동안에는 밑으로 지나가는 글 한 줄 높이를 가리며(화면을 내리면 보인다), 마우스로 읽을 때는 붙지 않는다. `:has()`를 모르는 브라우저에서는 붙지 않고 글 끝에 놓인다.
  - **가려진 줄:** 접힌 글 안의 링크로 초점이 가거나 브라우저 찾기가 가려진 줄을 가리켜 상자 안쪽이 밀리면 그 글을 펼친다. 긴 글 아래쪽에서 접으면 접은 글이 보이는 자리로 필요한 만큼만 화면을 옮긴다.
  - **낭독 탐색으로 다시 펼쳐짐:** 접힌 글은 높이만 제한하므로 가려진 줄도 화면 낭독기에는 그대로 읽힌다. 접은 뒤 낭독기로 가려진 줄을 탐색하면 글이 다시 펼쳐지고 단추 상태가 「확장됨」으로 바뀔 수 있다(2026-11-20 NVDA 2026.2·Chrome에서 담당자가 관찰: 접은 직후에는 「축소됨」이 유지되고, 위쪽 화살표로 가려진 본문을 탐색하자 펼쳐짐). 원인은 낭독기가 읽는 줄을 보이게 하려고 상자 안쪽을 밀어 위 「가려진 줄」 규칙이 걸리는 것으로 보이며, 이는 코드와 관찰을 맞춘 추정이고 낭독기가 실제로 상자를 미는지는 확인하지 않았다. 이 동작은 #607 검토에서 유지하기로 했다.
  - **프리셋 탭(2026-11-23, #629가 dev에 먼저 들어가 #607이 맞춤):** 열리지 않은 탭의 패널은 `hidden`이라 그 안의 글은 높이가 0이고 줄 수를 셀 수 없다. `snapshot-view.tsx`가 패널마다 열림 여부(`FoldVisibleContext`)를 넘기고, `FoldText`는 탭이 열리는 그리기 차례에 화면에 칠하기 전에 다시 잰다. 숨긴 동안에는 재지 않고 앞서 잰 판정과 사람이 접고 편 상태를 그대로 둔다. 출처 단추가 다른 탭의 글을 가리키면 차례는 **탭 열기 → 대상 글 펼치기와 그 패널의 접기 판정 → 화면 옮기기**다: 대상 글은 강조를 받은 그리기 차례에 펼쳐지고, `snapshot-jump.ts`는 그 그리기 묶음이 끝난 직후에 옮긴다. 먼저 옮기면 위쪽 글들이 접히면서 강조 글의 자리가 어긋난다.
  - **단추가 없어질 때의 초점:** 화면 폭이 넓어져 글이 기준 이하가 되면 단추가 없어진다. 초점이 그 단추에 있었으면 단추가 빠지기 전에 그 단추가 다루던 글 상자(`tabIndex={-1}`, Tab 순서 밖)로 넘겨, 다음 Tab이 단추 다음 요소로 이어지게 한다. 넘기지 않으면 초점이 문서 맨 위로 떨어진다. 글 상자는 키보드로 쓰던 중이면 초점 테두리가 보인다. 넘겨받는 자리는 #607 결정·화면 명세에 정해진 것이 없어 담당이 고른 것이다.
  - **단추 아래 여백:** 단추 줄 아래 8px을 비운다. 화면 아래쪽에 붙는 동안에는 본문을 더 가리지 않게 뺀다.
  - **한계:** 줄 수는 브라우저에서 그린 뒤에 재므로 서버에서 그린 글과 `ResizeObserver`가 없는 환경에서는 접지 않는다.
- 새 Catch NC2 사본 칸 셋([기능 설계](../../../../aidlc/spaces/default/intents/261109-new-catch/construction/nc2-snapshot-fields/functional-design/rules.md) BR3.1~BR3.4): 사본에 `repositoryName`이 있으면 Catch 제목(h3) 바로 아래·불일치 표지 위에 작은 글자 한 줄로, `authorDescriptionEditedMonth`가 있으면 h4 「작성자 설명」 안 옆에 「2026년 11월에 마지막으로 고침」(달의 앞 0을 뺌, 사본의 달이 이미 한국 시간이라 다시 계산하지 않음)으로, `workLimits`가 있으면 「기록에서 확인한 내용」 안 작업 사실 바로 아래·「근거 자세히 보기」 앞에 굵은 「이 기록으로 알 수 없는 것」과 목록으로 펼친 채 보인다. 칸이 없으면(이 변경 전 사본) 그 칸만 그리지 않고 나머지는 지금 그대로다. 모두 React 텍스트로만 그리고 한계 속 PR 번호·식별값은 링크로 만들지 않는다. 사본 모양 검사(`isCatchSnapshot`)는 칸이 없으면 받고, 있으면 모양(비어 있지 않은 글, `YYYY-MM`, 1개 이상의 글 배열, 참·거짓 `ownCommit`)이 틀릴 때 사본 전체를 올바르지 않은 응답으로 본다.
- 「이 작업의 본인 커밋」 표지(NC2 BR4.1~BR4.7): 사본 근거 가운데 `ownCommit`이 참인 커밋 주소 근거로 본인 커밋 목록을 한 번 만들고, 작성자 설명 속 판본·커밋 꼴 링크(파일 줄·파일·폴더·커밋·커밋 화면 바뀐 줄, 판본이 16진수 7~40자)의 저장소(대소문자 무시)와 식별값 앞부분이 본인 커밋 하나와만 맞으면 링크 바로 뒤에 표지를 둔다. 맞지 않거나 둘 이상과 맞으면 아무것도 붙이지 않는다(부정 표지 없음). PR 링크·브랜치 판본·표 밖 꼴은 판정하지 않는다. 표지는 Catch 종류 표지(`kindBadge`)와 같은 모양의 글자 상자이고 새 색이 없다.
  - **뜻(FR10.5):** 표지는 그 판본·커밋이 이 작업의 본인 커밋이라는 뜻이다. 링크가 가리키는 줄을 본인이 썼다는 뜻이 아니다. 면접관 화면에는 뜻을 푸는 안내 문장을 두지 않는다.
  - **자리:** 표지는 늘 링크 요소 밖, 링크(이름 글자와 숨은 「(새 탭)」) 바로 뒤의 형제 글자 요소이고 `tabIndex`·`role`·`aria-hidden`이 없어 글자로 읽히고 초점을 받지 않는다. FR10.3은 「판본·커밋 이름 바로 뒤」라고 적었는데, 이 화면은 이를 「링크 바로 뒤」로 읽는다(NC2 기능 설계 Q3 B). 파일·폴더·커밋 링크는 이름 끝이 판본·커밋 이름이라 같은 자리이고, 커밋 화면 바뀐 줄 링크(「커밋 ba6bba8 · 바뀐 줄 16–23」)는 이름을 나누지 않고 링크 전체 뒤에 붙인다. 그 링크도 본인 커밋의 바뀐 줄을 가리켜 뜻이 같고, 표지를 링크 안에 넣으면 눌리는 것처럼 보여 interaction-spec 4절 「표지는 누르는 것이 아님」과 어긋나기 때문이다. AI 답 근거 강조가 링크와 겹치면 링크만 강조로 감싸고 표지는 감싸지 않으며, 표지는 저장된 글에 없는 글자라 강조 위치 세기에 들지 않는다.
  - **쓰는 곳:** 사본 보기(받은 사람 화면과 작성자 발행본 상세)의 작성자 설명에만 쓴다. 텍스트 자료 본문과 내 자산 편집 화면의 「발행하면 면접관에게 열릴 링크」에는 쓰지 않는다. 판정은 화면에서만 하고 저장된 글·사본·API 응답을 바꾸지 않는다.
  - **한계:** 화면 낭독기는 진짜 표지와 작성자가 쓴 「[이 작업의 본인 커밋]」을 같은 글자로 읽는다(화면에서는 흉내 글이 상자 없이 대괄호째 보여 모양이 다르다). 사본 근거는 본인 커밋 최근 20건까지라 그보다 오래된 본인 커밋 링크에는 표지가 없다. 소속 기록 마이그레이션(`1794054790720-CreateCommitAssignment`) 전에 등록된 Catch와, 이미 다른 Catch(다른 작업)에 배정된 커밋에는 `ownCommit`이 거짓이라 표지가 없다. 옛 사본(`ownCommit` 없음)은 거짓으로 읽는다.
- 본문·작성자 설명 안의 `https://github.com/…` 주소만 새 탭 링크이고 그 밖의 주소는 글자다(#416 Q1 B, NFR1.11). 판정은 받은 사람 화면과 같은 `isGithubSourceUrl`이다. 주소의 끝은 주소 글자(RFC 3986)가 끊기는 곳이며 끝에 붙은 문장 부호·닫는 괄호는 글자로 돌린다. AI 설명 초안·제목·근거의 GitHub가 아닌 주소에는 링크를 만들지 않는다(OQ-U4-NFR-3). 모든 글은 React 텍스트로만 그린다(NFR1.10).
- 고정 안내(BR7.2)는 항상, 저장소 비공개 전환 안내(BR7.3)는 사본에 Catch 항목이 하나라도 있을 때 보인다(사본에는 공개 전환 여부가 없어 Catch 유무로 정했다).
- 링크 중지는 확인 창(되살릴 수 없음 안내) 뒤 `PUT .../stop`을 보내고 응답의 `state`·`stoppedAt`을 그대로 반영한다. 이미 중지면 처음 시각, 만료면 `{EXPIRED, null}`이다(BR8.2). 실패하면 "링크가 중지되지 않았습니다"와 다시 시도이고 상태를 바꾸지 않는다.
- 삭제는 확인 창 뒤 `DELETE`를 보내고 204일 때만 목록으로 옮긴다. 실패(접두어 삭제 실패 500 포함)는 "삭제되지 않았습니다. 다시 시도해 주세요."와 함께 발행본을 그대로 둔다(BR8.4·NFR5.3). 접수만으로 중지·삭제를 표시하지 않는다.
- 조작 요소에는 `data-testid`(`publish-*`, `publications-*`, `publication-*`, `snapshot-*`)를 단다.

## 한계

- 상세의 요약 자리(`data-testid="publication-summary-slot"`)에는 U5 `BaseSummaryPanel` 작성자 모드를 단다(#441). 근거 단추는 받은 사람 화면과 같은 규칙(`resolveEvidenceTarget`)으로 사본의 그 위치를 강조하고 옮긴다. 중지·만료 뒤에도 보인다(계약 C-11 owner-summary).
- 색인 상태(`indexState`)와 [검색 다시 준비]는 C-09 합의 전이라 만들지 않았다(기능 명세 「C-09 합의 전 임시 상태」, OQ-U4-5). 이 상태는 미완성이며 U4 완료 전에 해소한다.
- 받은 사람 판정(비밀번호·중지·만료·삭제 뒤 404)의 브라우저 확인과 [링크 열기]로 연 새 탭의 받은 사람 화면 확인은 제출 3(W4)에서 한다. 제출 2에서는 세 화면의 버튼 주소·새 탭 속성(화면 시험)과 원래 탭의 작성자 화면·입력 유지(브라우저)만 확인한다.
- 링크 복사는 공용 `web/src/lib/copy-text.ts`의 `copyText`를 사용한다. `formatKst`와 상태 표기는 이 폴더에서 관리한다.
- 로그인 만료 때 입력 유지와 뒤로·앞으로 가기 보호의 한계는 [텍스트 자료 README](../materials/README.md) 「한계」와 같다.
- `node --test` 시험은 합성 응답과 서버 렌더링으로 한 행동 시험이다. 화면 컴포넌트의 마운트 효과(열 때 불러오기, 삭제 뒤 이동, 빈도 초과 1초 갱신, 동의 창 열기)는 이 시험에서 돌지 않아 브라우저에서 따로 확인한다.
