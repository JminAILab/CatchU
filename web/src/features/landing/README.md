# 비로그인 서비스 소개 (`/`)

비로그인 사용자가 처음 보는 소개 화면이다. 서비스 안내, 합성 시연, 가상 Catch 예시, 로그인 진입을 보여 준다.

## 근거

- 디자인과 동작은 2026-11-24에 확정한 디자인 검토본(60번)을 옮긴 것이다. 문구·배치·색·재생 규칙의 기준이 그 판본이고, 이 폴더의 코드가 서비스 쪽 정본이다.
- 단계 설명은 기능 흐름(기록 → Catch 확인 → 공개 선택 → 링크 공유)을 따른다.
- 기능 3과 대표 시연의 여섯째 장면은 확인을 따로 하는 단계를 그리지 않는다. 앱에서 내용 확인을 공개에 합쳐(#635, 2026-11-24·25 팀장 결정) 체크 상자·[확인 완료]·「확인 전/확인 완료」 표지가 없어졌다. Catch 내용을 읽고 「공개 선택」의 전환 단추 하나를 켜는 두 단계로 그린다. 문장은 앱의 공개 선택 안내와 #635 「소개 페이지 글」에서 가져왔다.
- 발행본은 발행할 때 고정한 사본이다. 소개 화면은 "숨기면 보낸 링크에서 빠진다"고 말하지 않고, 공유를 끝내려면 링크를 중지한다고 안내한다(#565, 12월 요구사항 FR4.3).
- 이전 외형(#384·#395·#457, 겹친 카드 3장과 한 번 조립되는 장면)은 이 구성으로 바뀌었다. 옛 코드는 git 이력에 있다.

## 구성

헤더 → 첫 화면(제목·대표 시연) → Catch 예시 카드 줄 → 기능 1~4 → 면접관 화면 → 마지막 안내 → 푸터 순서다.

| 영역 | 내용 | 파일 |
|---|---|---|
| 헤더 | 로고(누르면 맨 위로)와 [Google로 시작하기]. 페이지와 함께 올라가고 고정하지 않는다 | `sections/site-header.tsx` |
| 첫 화면 | 제목(「근거」를 포인터가 끌어 칠함), 한 줄 설명, Catch 정의(700px 이하는 짧은 문장), 대표 자동 시연 7장면. 3회 재생 뒤 세 화면 요약으로 바뀌어 남는다 | `sections/hero.tsx`, `demos/hero-demo.tsx` |
| Catch 예시 | 가상 예시 카드 4종이 한 줄로 흐른다. [일시정지]/[재생] | `sections/catch-gallery.tsx` |
| 기능 1~4 | 파란 영역 하나를 고정해 두고 스크롤로 13단계(4·3·2·4)를 고른다. 바로가기 버튼 4개 | `sections/story.tsx`, `demos/*-demo.tsx` |
| 면접관 화면 | 받은 사람의 화면 6단계를 같은 방식으로 고른다 | `sections/recipient.tsx`, `demos/recipient-demo.tsx` |
| 마지막 안내 | 원형 U 심벌, 문구, [Google로 시작하기], 가입 순서 한 줄 | `sections/ending.tsx` |
| 푸터 | 남색. 메뉴 네 묶음(700px 이하 2열), [개인정보 처리방침](→ `/privacy`, #496), 가상 예시 고지 | `sections/site-footer.tsx` |

- 소개의 헤더는 이 화면이 그린다. 공통 `GuestHeader`는 `/`에서만 생략하고 로그인·콜백 화면에서는 기존 헤더를 유지한다.
- 탈퇴 직후 안내(`?withdrawn=1`)는 `app/(guest)/page.tsx`가 이 화면 위에 그린다.
- 푸터의 팀 소개·이용 가이드·자주 묻는 질문·이용약관은 아직 페이지가 없어 누를 수 없는 글자다. 페이지가 생기면 그 자리를 링크로 바꾼다.

## 코드 구조

```
landing-page.tsx      구간을 차례로 놓는다(서버 컴포넌트)
landing-root.tsx      바깥 틀. 화면에 올라온 뒤 움직임을 켜고, 떠날 때 정리한다(클라이언트 컴포넌트)
landing.module.css    이 화면 전용 스타일. 모든 규칙이 .page 아래에만 걸린다
sections/             구간별 마크업
demos/                시연 화면 마크업(가상 예시)과 공통 부품(창 머리줄·포인터·아이콘)
playback/             움직임. React를 쓰지 않는 TypeScript 모듈
```

`playback/`은 구간마다 `mount…(page, scope, motion)` 함수 하나를 낸다. `mount.ts`가 순서대로 부르고, `scope`에 등록한 이벤트·관찰자·타이머·예약한 프레임을 화면을 떠날 때 모두 정리한다.

| 파일 | 맡는 것 |
|---|---|
| `demo-config.ts` | 장면 길이, 자막, 포인터 동작 시각 |
| `demo-clock.ts` | 대표 시연의 시계(보일 때만 흐름, 3회 뒤 요약) |
| `pointer-path.ts` | 어느 시각에 포인터가 어디에 있는지 |
| `scene-renderer.ts` | 시연 화면을 "어느 장면의 몇 ms" 하나로 그림(표시·타이핑·눌림·확대·내부 이동·포인터) |
| `hero-player.ts` | 대표 자동 시연과 등장 효과 |
| `title-highlight.ts` | 제목 등장과 「근거」 강조 |
| `gallery-marquee.ts` | 카드 줄 흐름·일시정지 |
| `story-controller.ts` | 기능 1~4의 고정·단계 선택·바로가기·가림 대기·안쪽 스크롤 안내 |
| `recipient-controller.ts` | 면접관 구간의 배치 선택과 단계 선택 |
| `ending-pin.ts` | 마지막 안내를 잠깐 고정할지 |
| `viewport-fit.ts` | 쓸 수 있는 화면 높이 읽기(세 구간 공통) |
| `reload-reset.ts` | 새로고침하면 맨 위에서 시작 |

클래스 이름 끝의 숫자(`demo16`, `feature-nav42` 등)는 디자인 검토본에서 쓰던 이름 그대로다. 스타일과 제어 코드가 같은 이름으로 요소를 찾으므로 한쪽만 바꾸지 않는다. CSS 모듈 안에서는 `.page :global(...)`로 써서 이름은 그대로 두고 범위만 이 화면으로 가둔다.

Next의 CSS 처리기는 선택자 목록(`A, B { }`)을 `:is(A, B)`로 묶어 목록에서 가장 센 선택자의 우선순위를 전부에 적용한다. 우선순위가 다른 선택자는 한 규칙에 쉼표로 묶지 말고 규칙을 나눠 쓴다.

## 재생 규칙

- 진행 시간은 어디에도 저장하지 않는다. 새로고침하면 맨 위에서 0부터 시작한다.
- 시계는 그 구간이 화면에 충분히 보이고 탭이 켜져 있을 때만 흐른다. 화면 밖이나 다른 탭에서는 포인터·타이핑·확대·내부 이동이 같이 멈추고, 돌아오면 멈춘 자리에서 이어진다. 끝난 것은 끝난 채로 남는다.
- 대표 시연은 7장면(1회 51.6초)을 3회 돈 뒤 세 화면 요약을 남긴다.
- 기능·면접관 구간에서 스크롤은 단계를 고를 뿐이다. 단계마다 진행 시간이 있고, 끝난 단계는 결과 화면을 유지한다. 경계에서는 28px을 더 넘고 120ms 머물러야 단계가 바뀐다.
- 포인터가 향하거나 글자를 넣는 자리가 가려져 있으면 그 단계는 시간을 쓰지 않고 기다린다.
- 영역이 화면 높이에 들어가지 않으면 영역 안쪽을 스크롤하게 하고 안내 문구를 보인다. 넓고 낮은 화면(높이 647px 이하)의 첫 화면에는 시연 대신 「대표 시연 보기」 링크가 보인다.
- 바로가기 버튼은 그 기능의 첫 단계로 페이지를 옮기고 그 기능을 처음부터 다시 보여 준다. 기능 하나를 가리키는 페이지 안 링크(푸터의 「Catch란?」 → `#evidence`)도 같은 방식으로 옮기고, 초점을 그 기능의 바로가기 버튼에 둔다. 고정 배치에서는 지금 기능이 아닌 것이 감춰져 있어 브라우저의 기본 이동으로는 갈 수 없기 때문이다(확정 디자인은 이 링크가 움직이지 않았다, #642 리뷰).
- 고정 배치에서 지금 기능이 아닌 것은 화면에서만 가린다. 제목과 설명은 보조기기에 남겨, 화면 낭독기로 위에서부터 읽으면 기능 1→2→3→4가 차례로 읽히고 면접관 구간으로 이어진다. 시연 그림과 단계 자막은 지금 기능 것만 읽힌다. 낭독이 앞서가도 보이는 단계는 스크롤 위치로만 바뀐다(#641, 넓은 화면·좁은 화면 공통).
- 카드 줄 [일시정지]의 초점 테두리는 파란 구역에서 기능 바로가기와 같은 색(`#FFD77E`)이다(#641).
- 카드 줄의 [일시정지]는 화면 밖이나 다른 탭에 다녀와도 유지되고, [재생]을 누르면 멈춘 자리에서 이어 흐른다.
- 운영체제의 「동작 줄이기」가 켜져 있으면 대표 시연은 처음부터 요약, 카드 줄은 정적 예시, 기능·면접관은 각 단계의 결과 화면이고 포인터는 보이지 않는다. 재생 도중에 켜도 지금 단계가 바로 결과 화면으로 바뀐다(확정 디자인은 기능 구간이 재생 중간 모습으로 멈췄다, #642 리뷰).
- JavaScript가 꺼져 있으면 첫 화면은 제목과 세 화면 요약으로, 카드 줄은 멈춘 카드로, 면접관 구간은 마지막 화면으로 읽힌다(서버가 그린 직후 감춰 둔 제목과 대표 시연은 2.5초 뒤 나타난다). 기능 1~4 구간은 이때 고정하지 않고, 기능 네 개의 설명과 결과 화면을 순서대로 세로로 놓는다(정적 배치). 바로가기·포인터·자막은 보이지 않는다. 확정 디자인(60번)은 이 경우 구간이 비어 있었고, 서비스에서 보이게 고쳤다(2026-11-25). 규칙은 `landing.module.css` 끝의 `@media (scripting: none)` 묶음이다. 제어 코드가 고정 구간을 켜다 실패했을 때(`data-layout="static"`)도 같은 배치로 물러난다. 스크립트가 켜진 화면에는 걸리지 않는다.

## 지키는 것

- [Google로 시작하기] 두 곳만 다른 화면으로 가는 버튼이고 `/login`으로만 간다. 로그인·분석·동의·공개·발행·질문·복사를 이 화면에서 실행하지 않는다.
- 시연 속 버튼·입력·탭은 그림(`span`)이다. 클릭 이벤트를 달지 않고 서버 호출·클립보드·새 탭 열기에 연결하지 않는다. 「자동 시연 · 가상 예시」「합성 시연」 같은 표시와 안내 문구를 지우지 않는다.
- 가상 예시는 고정 문구이며 실제 사용자·저장소·커밋 주소를 쓰지 않는다.
- 서버 조회·브라우저 저장·외부 서비스 자원을 쓰지 않는다. 글꼴과 로고는 `public/landing/`에서 같은 출처로 내려 준다(글꼴의 SIL OFL 라이선스는 `Pretendard-OFL.txt`).
- HTML 문자열을 주입하지 않는다(`dangerouslySetInnerHTML` 없음). 마크업은 JSX로 쓴다.
- 소개 전용 색·폭·글꼴은 `landing.module.css`의 `.page` 범위에 두고, 다른 화면의 `globals.css` 공통 테마는 바꾸지 않는다.
- 첫 제목의 `id="landing-title"`은 실행 확인과 운영 이미지 검사가 이 화면을 알아보는 표식이다. 지우지 않는다.

## 검사

- `npm test`의 `test/landing.test.mjs`가 연결(로그인·개인정보·페이지 안 이동), 검토용 요소가 없는 것, 시연 속 버튼이 링크·버튼이 아닌 것, 재생 계산(3회 완료·정지·단계 시간·화면 맞춤), 고정 배치의 낭독용 규칙과 [일시정지] 초점 테두리 규칙을 본다. 실제 낭독 순서와 테두리가 보이는지는 브라우저의 접근성 트리와 화면 낭독기로 확인한다.
- `npm run check`의 `check:run`이 `/` 본문의 `id="landing-title"`로 이 화면이 그려졌는지 확인한다.
- 운영 이미지는 `public` 폴더를 따로 싣는다(Next standalone 출력에는 들어가지 않는다). 이미지 검사(`deploy/scripts/check-images.mjs`)가 `web/public`의 파일이 이미지에 모두 있고 같은 주소로 열리는지 본다. 빠지면 화면은 200이어도 로고와 글꼴이 404가 된다(#560).
- 문구·배치·재생을 바꾸면 브라우저로 확인한다. 기준 크기는 1440×790, 1366×650, 1280×560, 390×700, 360×800, 390×500이다. 가로 넘침과 겹침, 기능 13단계와 면접관 6단계가 끝까지 가는지, 바로가기, 다른 탭에서 멈추는지, 동작 줄이기, 스크립트를 끈 화면에서 기능 네 개가 읽히는지, 키보드 Tab으로 [Google로 시작하기]에 닿고 Enter로 `/login`에 가는지를 본다.
