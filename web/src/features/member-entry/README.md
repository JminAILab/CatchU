# 회원 진입 연결 — #106

회원 가드와 로그인 진입에서 기존 API 호출 함수로 GET /v1/me를 조회한다.
조회 성공 후 profile.displayName이 빈 문자열일 때만 /profile/setup으로 이동한다.
소개·직무·기술 및 GitHub 연결 여부는 이동 조건이 아니다.
조회 중에는 회원 화면 표시를 보류하고, 실패·응답 형식 오류는 다시 불러오기로 처리한다.
AUTH_REQUIRED·AUTH_INVALID는 기존 API 함수가 토큰을 지우고 로그인 진입으로 연결한다.
이미 /profile/setup이면 다시 이동하지 않는다. 이름이 있으면 로그인 후 유효한 next 또는 /home으로 이동한다.
/profile/setup은 이름이 빈 회원만 연다. 이름이 저장된 회원이 직접 들어오면 최초 입력을 거친 뒤와 같은 /home으로 보낸다. 조회 중·실패에는 폼을 열지 않는다.
세션 변경·경로 변경·재조회 시 이전 응답을 사용하지 않고, 화면 종료 시 조회를 취소한다.
수신자 경로에는 회원 가드를 적용하지 않는다.

## 현재 범위와 남은 작업

/profile/setup의 최초 입력·저장은 [프로필 안내](../profile/README.md)를 따른다.
저장 후 회원 정보 재조회와 홈 복귀를 연결했다. 실제 브라우저에서 최초 입력 이동·조회 실패 후 복구·저장 후 회원 경로 진입을 확인했다. 검증 기록과 남은 범위는 프로필 안내 및 PR 본문을 따른다.

## 검사

npm run check로 lint·타입·모의 fetch 테스트·빌드·루트 HTTP smoke를 검사한다.
member-lookup.test.mjs와 member-navigation.test.mjs는 실제 API 클라이언트와 판정 함수를 사용하지만 응답은 합성이다.
실제 API·DB 및 브라우저 상호작용 통합 검증은 별도 단계이며 루트 smoke 통과로 대체하지 않는다.
