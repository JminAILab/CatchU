# 회원 진입 연결 — #106

회원 가드와 로그인 진입에서 기존 API 호출 함수로 GET /v1/me를 조회한다.
조회 성공 후 profile.displayName이 빈 문자열일 때만 /profile/setup으로 이동한다.
소개·직무·기술 및 GitHub 연결 여부는 이동 조건이 아니다.
조회 중에는 회원 화면 표시를 보류하고, 실패·응답 형식 오류는 다시 불러오기로 처리한다.
AUTH_REQUIRED·AUTH_INVALID는 제품 기본의 공통 인증이 갱신과 GET 한 번 재조회를 처리하고, 실패하면 가드가 인증 상태에 맞는 로그인 이동·재인증 안내를 정한다. 통합 시험 전환을 끈 빌드만 토큰을 지우는 기존 방식을 쓴다([공통 인증](../auth-session/README.md)).
이미 /profile/setup이면 다시 이동하지 않는다. 일반 로그인은 이름이 있으면 유효한 next 또는 /home으로 이동한다.
/profile/setup은 이름이 빈 회원만 연다. 이름이 저장된 회원이 직접 들어오면 기본은 /home으로 보낸다. 조회 중·실패에는 폼을 열지 않는다.
받은 링크에서 시작한 로그인(#638)은 `recipient-login-return.ts`가 분리한 이 탭 sessionStorage 값으로 같은 링크에 돌아간다.
이름이 없으면 최초 입력까지 보관하고, 저장·회원 재조회 뒤 돌아간다. 이미 이름이 있는 회원을 최초 입력에서 보내는 가드도 같은 복귀를 적용한다.
링크 token은 회원 `next`나 Google 로그인 시도 값에 넣지 않는다. 30분 만료·잘못된 token·일반 로그인 진입 때는 버리고 기존 목적지를 쓴다.
이름이 빈 회원이 /profile·/profile/edit에 들어오면 같은 판정으로 /profile/setup에 보낸다. 상세·수정 화면은 [프로필 안내](../profile/README.md)를 따른다.
세션 변경·경로 변경·재조회 시 이전 응답을 사용하지 않고, 화면 종료 시 조회를 취소한다.
수신자 경로에는 회원 가드를 적용하지 않는다.

## 최초 입력 연결

/profile/setup의 최초 입력·저장은 [프로필 안내](../profile/README.md)를 따른다.
저장 후 회원 정보 재조회와 일반 홈 복귀, 받은 링크에서 시작한 경우의 링크 복귀를 연결했다. 기존 최초 입력 이동·조회 실패 후 복구·저장 후 회원 경로 진입의 브라우저 검증 기록은 프로필 안내를, #638 변경의 검증 범위는 PR 본문을 따른다.

## 검사

npm run check로 lint·타입·모의 fetch 테스트·빌드·루트 HTTP smoke를 검사한다.
member-lookup.test.mjs와 member-navigation.test.mjs는 실제 API 클라이언트와 판정 함수를 사용하지만 응답은 합성이다.
실제 API·DB 및 브라우저 상호작용 통합 검증은 별도 단계이며 루트 smoke 통과로 대체하지 않는다.
