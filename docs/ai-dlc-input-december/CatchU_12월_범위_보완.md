# CatchU 12월 범위 보완 — 첫 intent 요구사항에서 누락된 기능의 팀장 결정

기록일: 2026-09-15
기준 커밋: `94362c4`
출처: PR #44 검토 대화에서 팀장이 확인한 결정. 별도 회의 기록은 없다.
지위: **팀장 결정 입력.** 승인 요구사항(2026-09-11)을 소급 수정하지 않는다. 12월 범위를 다룰 AI-DLC intent의 입력으로 쓰며, 항목별 세부 동작과 요구사항 ID는 그 intent의 요구사항 분석에서 정한다. 10월 MVP intent에는 §4의 설계 제약만 적용한다.

## 1. 누락 경위

첫 intent의 참고 원문인 [v10 기획 문서](../ai-dlc-input/CatchU_v10_reference.md) 4절 기능 목록에서 "포함"이던 기능 중 일부가 [승인 요구사항](../../aidlc/spaces/default/intents/260909-catchu-definition-review/inception/requirements-analysis/requirements.md)의 12월 항목에 오르지 않았다. 팀장은 이 기능들이 12월 목표였다고 확인했다.

- **팔로우·포스팅·피드·구직자 간 DM:** AI-DLC 시작 설명에 "링크드인이라는 비유만으로 소셜 기능 전체를 추가하지 않는다"는 기준이 들어갔다. 이 문장이 의도 정리와 범위 정의를 거쳐 요구사항의 "제품 범위 밖·자동 확대 금지"로 이어졌고, 네 기능을 12월 항목으로 따로 묻는 질문이 없어 제외처럼 굳었다.
- **알림·MCP·채용공고 등:** 입력 문서 [범위와 이용 흐름](../ai-dlc-input/CatchU_scope_and_journeys.md) 3절은 "과금·공고·MCP 등 기존 항목은 필요한 흐름에 연결해 우선순위를 검토한다. 생략만으로 폐기하지 않는다"고 넘겼다. 첫 intent의 범위·요구사항 기록에서는 이 항목들이 다뤄지지 않았다.

아래 판단 대상은 v10 4절에서 "포함"이면서 첫 intent 기록에 없던 항목이다. 키워드 대조로 찾았으므로 다른 표현으로 들어간 항목은 빠졌을 수 있다.

## 2. 12월 포함

|---|---|---|

**마일리지 조건**

- 현금으로 사거나 현금·재화로 바꾸는 기능을 두지 않는다.
- 직접 링크 열람은 차감 대상이 아니다. 요구사항은 직접 GitHub 근거 열람을 기업 구독으로 제한하지 않는다(FR4.2).
- 탐색 중 정보 열람에서 무엇을 무료로 둘지는, 비구독 기업도 기본 프로필·대표 주장·근거를 확인하고 그 밖의 정보에서 차등을 두는 첫 intent 범위 정의의 비교 방향(C02)과 함께 정한다.
- 확인 전 조사 메모: 온라인 결제 대행(PG) 가맹에는 사업자등록증이 기본 서류다. 운영진이 무상 지급하고 이 서비스 안에서만 쓰며 현금 구매·환전이 없는 마일리지는 결제가 없고, 단일 서비스에서만 쓰는 선불전자지급수단의 등록 예외 유형에 해당할 가능성이 있다. 법 해석이므로 12월 적용 전에 소속 기관이나 전문가에게 확인한다.

## 4. 10월 설계에 주는 제약

10월 MVP intent는 위 기능을 10월에 구현하지 않는다. 아래는 기존 제품 행동을 지키면서 후속 확장을 검토하기 위한 원칙이다. 물리적 배치·저장 구조·프레임워크는 해당 설계 단계에서 결정한다.

- **권한 판정 재사용:** 화면·링크·향후 MCP에서 일관된 권한 규칙을 재사용한다. API 한 곳이라는 물리적 위치를 미리 강제하지 않는다. MCP의 구체 허용 범위는 12월 요구사항 분석에서 정한다.
- **공개 상태 모델:** 10월 공개·숨김과 기업·링크 열람 규칙을 유지한다. 12월 구직자 간 전체·맞팔 공개를 추가할 때 기존 규칙과의 적용 대상·우선순위를 구분할 수 있도록 설계한다. 저장값의 개수나 같은 필드 사용 여부를 지금 지정하지 않는다.
- **분석 상태·기록:** 10월에 필요한 분석 식별자·상태와 완료·실패·운영 기록을 확보한다. 12월 알림에서 필요한 기록을 활용할 수 있도록 검토하되, 이를 이유로 10월에 알림 발송·이벤트 전달 시스템을 구축하지 않는다. 상세 기록·보관 기준은 OQ13에서 정한다.
- **계정 유형:** 구직자·기업 계정의 역할을 구분할 여지를 둔다. §2의 회사 프로필 구성 재사용과 동일 데이터 구조 강제는 구분한다. 회사와 로그인 계정의 관계, 프로필 소유·편집 권한은 12월 설계에서 정한다.
- **링크 발행:** 10월 발행은 무료다. 향후 마일리지 등 발행 조건을 추가할 경계를 검토하되, 10월에 잔액·차감 기능을 구현하지 않는다.
- **홈·헤더:** 10월 로그인 홈에는 분석 결과 상자를 두지 않는다. 12월에는 피드가 로그인 홈의 중심이 되고, 분석 완료·실패 안내는 헤더 알림으로 간다(#51). 10월 분석 진입·재방문 경로는 후속 입력의 GitHub 연동·자산 탭 결정을 따른다.

## 5. 다음 절차

- 12월 범위를 다룰 intent를 시작할 때 이 문서를 입력으로 넣고, 요구사항 분석에서 항목별 요구사항 ID와 세부 동작을 정한다.
- 보류 항목과 탈퇴 시점은 그 intent의 요구사항 분석 전에 다시 확인한다.
- 10월 MVP intent는 [후속 입력](../ai-dlc-input-mvp/2026-09-14_followup.md)을 통해 §4만 참조한다.
