# JD 적합도 수치 표시 기능

**국내·해외 유사 서비스 조사 결과**

- 작성일: 2026년 8월 31일
- 조사 범위: 국내 ATS·AI 서류평가 솔루션, 해외 ATS·채용 플랫폼

---

## 1. 핵심 요약

**결론:** JD 적합도를 수치로 표시하는 기능은 국내에 이미 상용화되어 있다. 본 문서는 국내·해외 서비스의 구현 현황과 인터뷰 내용을 정리한 조사 자료이며, 기획 방향에 대한 제언은 포함하지 않는다.

- 국내: 그리팅(ATS 내장형), 무하유 프리즘(외부 솔루션형) 2개 축으로 상용화 완료
- 해외: Manatal은 퍼센트, Skima·Zoho는 100점 척도로 직접 노출
- 대형 플랫폼(LinkedIn, ZipRecruiter)과 엔터프라이즈 ATS(Greenhouse, Workday)는 의도적으로 숫자 대신 등급·순위 사용
- 전 사례 공통: 자동 합불 처리 기능은 제공하지 않으며, 점수에는 반드시 근거가 동반됨

**인터뷰 결과와의 대조:** 인터뷰이는 "JD를 봐도 이해하지 못하니 적합 여부를 알려달라"는 의도를 밝혔다. 반면 국내 대표 제품인 그리팅은 담당자가 평가 조건을 직접 작성하는 것을 전제로 설계되어 있어(3.1), 조건 입력 단계에서 사용에 제약이 발생한다. 조사 대상 제품 대부분은 담당자가 직무 요건을 판단할 수 있다는 전제 위에 설계되어 있다.

---

## 2. 조사 배경 — 사용자 인터뷰 피드백

> "합불 결정 자체를 AI에 맡기는 것에는 부담을 표시하였다. 정말 괜찮은 지원자를 탈락시킬 수 있기 때문이다. 대신 JD 적합도를 퍼센테이지로 표시해주는 기능은 유용하다고 평가하였다(지원자 30명 중 80% 일치, 10% 일치 식으로 표시되면 도움이 됨)."

후속 확인 결과 인터뷰이가 밝힌 의도는 다음과 같다.

> "HR은 JD를 봐도 이해하지 못하니, 이 사람이 적합한지 아닌지를 알려달라."

## 3. 국내 서비스 조사

### 3.1 그리팅 AI 서류평가 (두들린) — ATS 내장형

2026년 6월 오픈베타 전환. 비즈니스 플랜 대상. 국내 채용관리 솔루션 중 유일하게 내장형 AI 서류평가와 MCP 연동을 동시 지원한다고 밝히고 있다.

#### 노출 형태

- 100점 만점 정수 점수 (소수점은 반올림 처리, 예: 56.25점 → 56점)
- 지원자 칸반뷰에 예상 점수 표시 → 상세 페이지에서 상세 내용 확인 → 면접관 뷰에서도 조회 가능
- 점수 기준 필터링 및 정렬 지원

#### 점수 산출 공식 (공식 문서 공개)

```
(선호 조건 일치 + 비선호 조건 일치) ÷ 사용된 조건 수
```

- 선호 조건: 0점에서 시작, 가중치만큼 가산
- 비선호 조건: 100점에서 시작, 가중치만큼 감산
- 둘 다 사용 시 ÷2, 하나만 사용 시 ÷1
- 일치 판정은 "완전 일치 / 부분 일치" 2단계. 부분 일치는 배점의 절반 부여 (가중치 25% 조건 → 완전 25점, 부분 12.5점)

#### 설정 방식

- 공고별로 선호/비선호 조건을 담당자가 직접 입력. 최소 4개, 최대 20개, 각 항목 5자 이상
- 가중치는 숫자 직접 입력 또는 슬라이더. [비율] 버튼은 총합 100% 자동 조정, [균등] 버튼은 동일 배분
- 역할별 권한 분리: "평가 조건 관리 권한"과 "평가 결과 조회 권한"이 별도 설정됨

#### 근거 제시 방식

- **"선호·비선호 조건에 일치해요":** 완전 일치/완전 불일치 항목을 긍정·부정 아이콘으로 표시, 가중치 높은 순 정렬
- **"면접에서 확인해보세요":** 부분 일치 항목을 가중치 높은 순으로 표시 → 애매한 항목을 버리지 않고 면접 질문으로 전환하는 설계

#### 안전장치

- 자동 합불 처리 없음을 공식 문서에 명시
- 합격·불합격 상태 지원자는 아예 평가 대상에서 제외 (평가 대기 상태에만 점수 부여)
- AI가 완료한 평가 내용은 사용자가 수정 불가
- 지원자 개인정보는 AI 학습 데이터로 미사용
- 한계 명시: 이력서 내 객관적 정보만 기반하므로 인성·커뮤니케이션 등 비정형 요소는 미반영

#### 주목할 설계 변경 — JD 미참조

2026년 5월 13일 Ver.2 업데이트 이후 **AI 서류평가는 JD를 참고하지 않는다.** 담당자가 입력한 선호/비선호 조건만 기준으로 평가한다. Ver.1은 JD를 함께 참조했으나 공고 내용이 부실할 경우 오류가 발생했기 때문이다.

**시사점:** "JD 적합도"라 부르더라도 실제 산출 기준은 JD가 아니라 명시적 조건으로 가는 것이 정확도 면에서 안정적이다. JD는 애초에 정제된 평가 기준이 아니다. 다만 이 선택은 **조건 작성 부담을 전적으로 담당자에게 전가하는 대가**를 수반했다. 정확도는 확보했으나 사용자층은 좁아진 셈이며, 본 프로젝트에서는 이 상충 관계를 어떻게 다룰지에 대한 검토가 필요하다.

#### 효과 검증 데이터

- 바이오 기업(파마리서치) 사례: 이력서 약 100건 접수 공고에서 사람 면접관이 고른 면접 대상자 8명 중 6명(75%)이 AI 점수 상위 10위 내 포함
- 공고당 서류평가 기간 평균 1주일 → 2~3일로 단축
- ※ 검증 지표가 "평균 매칭률"이 아니라 "상위권 포함 여부"라는 점에 주목 — 순위 기반 검증

### 3.2 무하유 프리즘 — 외부 솔루션 연동형

- 도입 규모: 프리즘·몬스터 합산 약 700개 기업. 프리즘 단독 연간 120만 건 이상 자소서 분석
- 서류 검토 시간 기존 10분 → 약 4초
- **수치화 방식:** BP(Best Person) 평가에서 직무 적합도, 조직 적합도, 지원 동기 등 항목별로 역량을 수치화. 이전 버전 기준 답변 적합도·내용의 구체성·문법 적합도·조직 적합도·직무 적합도로 분해
- **근거 제시:** 유의미한 구절을 하이라이팅하여 제공하고, 해당 문장을 기반으로 면접 질문 자동 생성
- **방향성:** 2025년 10월 전면 개편 시 "설명 가능한 AI 채용"을 명시적 목표로 제시
- **그리팅과의 차이:** 그리팅은 단일 총점 + 조건별 아이콘, 프리즘은 평가 축 자체를 다중으로 분해

### 3.3 사람인 — 자체 개발 대신 외부 연동 선택

- 자사 채용 시스템 "등용문S"에 무하유 프리즘 연동
- 도입 사유로 "설명 가능한 AI 평가의 필요성 증가"를 명시
- 기업용 자체 기능은 "사람인 AI매치" 형태의 인재 추천으로, 점수 노출형이 아님
- 참고: 사람인 개발 조직은 "합격률"은 상대적 값이라 산출 불가하여 절대값인 "적합도"라는 표현으로 대체했다고 밝힌 바 있음 — 네이밍 참고 사례

## 4. 해외 서비스 조사

### 4.1 수치를 직접 노출하는 유형

| 서비스 | 표시 형태 | 근거 제시 | 특징 |
|---|---|---|---|
| Manatal | 퍼센트(%) | 조건 기반 | JD에서 요구사항 자동 추출, 리크루터가 스코어링 가중치 직접 통제 |
| Skima AI | 0~100점 | Match Reasons | 점수 근거가 된 이력서 부분을 직접 인용 — 설명 가능성 최고 수준 |
| Zoho Recruit | 숫자 점수 | 스킬 분해 | Zia Match. 로직 공개형 |
| Workable | Fit score | 제한적 | Screening Assistant 형태 |
| Phenom | Fit Score 랭킹 | 요건별 | 2026년 독립 감사로 유효성·공정성 검증, adverse impact 없음 판정 및 리포트 공개 |
| Eightfold | Match Score | 스킬 기반 | 매칭 점수와 입사 후 재직 유지율의 상관관계를 실증 연구로 발표 |

#### Zoho Recruit — 참고할 만한 산출 로직

- 스킬을 필수(primary)와 우대로 구분. 필수 스킬 미보유 시 매칭에서 제외
- 희소 스킬 가중: 50명 중 5명만 보유한 스킬은 "희귀"로 분류해 가산점 부여
- 숙련도, 경력 기간, 최근 사용 시점을 반영해 최대 20명을 순위대로 노출
- 노출 지점 3분할: 공고→후보자 매칭 / 후보자→적합 공고 매칭 / 지원서→매칭 스코어

### 4.2 의도적으로 숫자를 노출하지 않는 유형

#### ZipRecruiter — 4단계 등급 + 실측 효과 데이터

- Great Match / Good Match / Fair Match / Not a Match 4단계만 표시. 수십억 건의 상호작용 데이터로 학습했음에도 등급으로 출력
- 모바일 앱 실측: 매치되지 않는 공고 지원 평균 **47% 감소**, Great Match 공고 지원 26% 증가, Good Match 14% 증가
- ※ 하위권 차단 효과(47%)가 상위권 유인 효과(26%)보다 약 2배 큼

#### LinkedIn — 대상별 차등 노출

- 동일 모델을 3개 제품에 배포하되 표현을 다르게 설계
  - 구직자: 적합 시 검색 결과 강조 표시만 (Quality Match), 점수 없음
  - Premium 구직자: high/medium/low 3단계 + Top Applicant 배지 + 상위 50%·25%·10% 백분위
  - Recruiter(기업): 지원자 랭킹 정렬 + 매우 높은 점수 후보 지원 시 알림 발송
- 기업용에서 숫자를 뿌리지 않고 **"정렬 + 이상치 알림"** 으로 처리한 점이 핵심. 담당자는 숫자를 읽는 것이 아니라 "이 사람은 봐야 한다"는 신호를 받는다.
- 강점과 함께 갭(부족한 부분)을 명시 (예: "디지털 캠페인 경험은 강점이나 ESG 리포팅 경험 부재")

#### 엔터프라이즈 ATS

| 서비스 | 방식 | 단일 점수 | 비고 |
|---|---|---|---|
| Greenhouse | 불리언 조건 필드별 필터링 | 노출 안 함 | 스코어카드·구조화 인터뷰 킷으로 대체 |
| Workday | OCR + ML 관련도 모델 | 내부용 | JD 대비 절대평가가 아닌 지원자 풀 내 상대 비교 |

## 5. 시장 패턴 분석

### 5.1 제품군에 따라 노출 방식이 갈린다

| 구분 | % / 점수 노출 | 대표 사례 | 배경 |
|---|---|---|---|
| SMB 대상 ATS | 노출함 | Manatal, Zoho, Skima | 사용자가 숫자를 최종 근거로 쓰지 않는 환경 |
| B2C 구직자 도구 | 노출함 | 합격닷컴, 각종 스캐너 | 오류 시 책임 소재가 크지 않음 |
| 국내 ATS | 점수형 노출 | 그리팅, 프리즘 | 근거 동반을 전제로 노출 |
| 대형 플랫폼 | 등급·순위 | ZipRecruiter, LinkedIn | 대규모 노출에 따른 신뢰도 리스크 관리 |
| 엔터프라이즈 ATS | 노출 안 함 | Greenhouse, Workday | "왜 탈락시켰나"에 대한 설명 의무 |

### 5.2 전 사례 공통 원칙

1. **점수는 정렬·참고용, 결정은 사람이 한다**
2. **숫자 옆에는 반드시 근거가 붙는다**
3. **자동 컷오프·일괄 탈락 기능은 제공하지 않는다**

### 5.3 점수 신뢰도에 관한 실증 데이터

무하유가 2025년 1~12월 프리즘×몬스터 교차검증 도입 기업 데이터를 분석한 결과, 지원자가 자소서에서 강조한 역량과 역량검사 결과가 **일치하지 않은 비율이 52.2%** 로 나타났다. 자소서에서 특정 역량이 높게 평가된 지원자가 역량검사에서도 같은 항목에서 높은 평가를 받은 비율은 47.8%였다.

**해석:** 벤더는 교차검증 필요성을 강조하기 위해 낸 수치이나, 뒤집어 보면 서류만으로 산출한 적합도 점수의 절반가량이 다른 검증 방식과 어긋난다는 의미이기도 하다. 인터뷰이가 우려한 "괜찮은 지원자를 탈락시킬 위험"이 데이터로 확인된 셈이며, **점수를 컷오프 기준으로 사용해서는 안 되는 근거 자료**로 활용 가능하다.

### 5.4 규제 환경
