## 새 규칙 한계와 관찰(팀장 결정)

- **D1 — `.DS_Store`로 이어진 커밋 묶음(규칙 한계)**: algo-problem의 커밋 묶음 15개가 서로 다른 문제 풀이를 한 작업으로 이었다. 묶음 안 연결 27곳 중 25곳이 macOS가 자동으로 만드는 `.DS_Store` 파일의 겹침뿐이었다. 방법 B 규칙(부모 하나·변경 파일 겹침)대로라 결함은 아니고, [후보 판정의 한계](../worker/docs/candidate-checks.md)·[작업 동일성 사례](CatchU_work_identity_cases.md)의 알려진 한계에 없는 새 한계다. #122 범위에 예외로 적어 규칙 한계로 두고 후속 작업은 등록하지 않는다. 이 묶음 후보 15개의 경험 후보 적합성(FR2.1의 경험 선택 활용)은 수용 근거로 세지 않는다.
- **D2 — 커밋 하나짜리 후보의 묶음 설명**: 여러 커밋을 이은 묶음에는 「작성 시각 차이와 메시지 비슷함은 보지 않았다」가 있고, 하나짜리 후보에는 없다. 하나짜리는 이을지 판단할 일이 없어 필요 없는 문장이므로 결함이 아니다. [후보 문장과 근거](../worker/docs/candidate-text.md)의 「커밋 묶음에는 적는다」는 그대로 둔다.
- **D3 — 수집이 멈췄을 때의 경고 문구**: 비교를 끝내지 못한 같은 변경 쌍의 경고가 「공백을 무시한 변경 비교로 같은 변경을 확정하지 못함」이라고 적혀, 멈춤 때문이라는 사유가 드러나지 않는다. 규칙대로이므로 맞음으로 두고 관찰로만 남긴다.
- 그 밖의 관찰: 임시 제목(제목을 확인하지 못해 작업 사실 첫 항목을 넣은 값)이 15건이다. BEASTA-ZOO가 10건이다. 같은 제목이 여러 후보에 붙는 경우가 있다.

## 미실행과 관측 한계

- 실제 저장소에서 생기지 않아 미실행: 전체 실패(S7), 설명·질문 생성 실패(S15), 호출 한도로 미생성(S16), 목록을 다 받지 못한 PR의 squash(S4), 본인 커밋 없는 본인 PR(S8), 근거 20건 초과 문구(S5), 이슈 조회가 없는 요청의 번호 처리(S20). 이 경로들은 worker 합성 시험으로만 확인돼 있다.
- 실제 저장소는 팀장 계정의 공개 저장소 5곳뿐이다. 다른 회원 저장소, 비공개 저장소, 실제 접수 경로(#323)는 보지 않았다. H 배포 환경 검증과 #37 C05 실제 환경 통제 검사도 아니다.
- 사람의 독립 검토는 두지 않았다. 규칙대로 묶였지만 작업 의미가 다른지는 F를 만든 팀장이 결과를 본 뒤 판단했다. F 작성·검수·통합 수용을 같은 사람이 맡는다.
- 쓸모(설명이 읽을 만한지)는 판정하지 않았다. Catch 완성본 방향은 개발 서버에서 실제 화면을 본 뒤 정한다(10/18 팀장 결정).
- 검수 중 대조 스크립트 쪽 결함 3건을 고치고 다시 대조했다(PR 단위 다른 계정 커밋 문장의 앞부분, PR 없는 병합 대조 추가, GitHub 비교 API의 250건 상한). worker 결과를 바꾼 것은 없다.

## C11 수용 판단과 I 전달(2026-10-19 팀장 확정)

- 제약 C11(실제 서비스 결과 판본의 근거·귀속·공개·활용성 확인)은 네 부분으로 나눠 본다.
  - **근거·귀속**: 커밋 단위의 근거(판본·문장이 원본과 일치)와 본인 귀속을 이 기록으로 수용한다(10월 MVP 기준, 위 「미실행과 관측 한계」 안에서). D1의 묶음 15개는 서로 다른 작업이 한 후보로 합쳐진 것이라, 그 후보들의 묶음 적합성은 수용 범위에서 빼고 예외로 I에 전달한다.
  - **공개**: B·C 몫이라 [#124](https://github.com/JminAILab/CatchU/issues/124) 통합 검증에서 본다.
  - **활용성**: 개발 서버 화면을 본 뒤 정한다.
- I([#124](https://github.com/JminAILab/CatchU/issues/124))에 전달하는 것은 다음과 같다.
  - F 결과의 수용 근거와 그 범위(이 기록. 근거·귀속은 커밋 단위로 수용, D1 묶음의 적합성은 제외)
  - 실행 판본(dev `e4401dcd`·`claude-haiku-5-5`)
  - 알려진 한계: D1(수용 범위에서 뺀 묶음 15개. 이 합침을 알리는 문구는 결과에 없다), 미실행 경로, 로컬 대역 접수
  - E 수신 확인이 8건 모두 ACCEPTED였다는 사실(E/B 반영 정합성 자체는 [#121](https://github.com/JminAILab/CatchU/issues/121)·#124 몫)
