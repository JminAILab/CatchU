이 문서에서 「프리셋」은 지원자가 미리 만들어 두는 자료 묶음이다. 발행본을 받아 읽는 사람은 「면접관」으로 부르고, 그 사람이 여는 화면의 이름은 코드와 같이 「받은 사람 화면」으로 쓴다.

## 2. 왜 바꾸는가

2026-11-16과 11-17 회의에서 발행·받은 사람 화면 담당(팀원 3)이 지금 발행 흐름의 문제 넷을 정리했다.

| 항목 | 지금 문제 |
|---|---|
| 발행 자료 선택 | 발행할 자료를 고르기 어렵다 |
| 작성자 설명 필터 | 원하는 Catch를 찾을 때까지 「더 보기」를 반복해야 한다 |
| 발행 순서 편집 | 순서 조절 단추의 배치와 쓰는 법이 눈에 잘 들어오지 않는다 |
| 발행본 화면 | 자료가 길게 나열되고 요약은 맨 아래에 있다. 박스 크기가 제각각이고 안내가 펼쳐져 있어 복잡하다 |

2026-11-18 팀장은 이 문제를 따로따로 고치지 않고 발행 방식을 바꾸기로 했다.

- 지원자: 발행할 때마다 Catch와 자료를 하나씩 고르지 않는다. 묶음을 미리 만들어 두고 발행할 때는 묶음을 고른다.
- 면접관: 발행본이 한 줄로 길게 이어지지 않는다. 묶음이 탭으로 나뉘어 무엇이 어떤 자리인지 구분된다.

예: 「자기소개서」 프리셋(자기소개서 텍스트 자료 + Catch 몇 개), 「포트폴리오」 프리셋(포트폴리오 PDF + Catch 몇 개).

## 3. 정한 것 (팀장 결정, 2026-11-18)

### 3-1. 프리셋과 발행

1. 지원자는 프리셋을 미리 만든다. 프리셋에는 이름을 붙이고 Catch·텍스트 자료·PDF를 담는다.
2. 발행할 때는 자료를 하나씩 고르지 않고 프리셋을 고른다. 한 발행본에 프리셋을 여러 개 넣을 수 있고 최대 5개다.
3. 발행 화면 안에서 프리셋을 만들지 않는다. 프리셋은 한 번 만들어 두면 자주 바꾸지 않고, 발행 화면이 복잡해지기 때문이다. 프리셋이 하나도 없으면 프리셋을 만들러 가는 링크만 보인다.
4. 순서를 정하는 자리는 둘이다. 프리셋 안 자료의 순서, 발행할 때 프리셋의 순서. 지금처럼 「위로」「아래로」 단추로 만든다. 드래그는 뒤에 화면을 다듬을 때 더하고, 그때도 단추는 남긴다.
5. 비공개 Catch를 고르는 목록에서 빼지 않는다. 빼면 지원자가 Catch를 하나씩 공개로 바꿔야 발행할 수 있어 불편하다. 비공개 Catch도 담을 수 있고 발행할 때 공개로 바뀌는 지금 동작을 그대로 둔다.
6. 지금 발행 화면의 자료 고르기와 「작성자 설명을 쓴 Catch만 보기」는 프리셋을 만드는 화면으로 옮긴다.

### 3-2. 받은 사람 화면

1. 프리셋은 받은 사람 화면에서도 묶음으로 나뉘어 탭으로 보인다. 작성자 발행본 화면도 같게 보인다.
2. 탭 줄은 프리셋이 하나여도 보인다. 발행본마다 모양이 같아야 서비스의 통일감이 유지된다.
3. 탭 이름은 프리셋 이름이다. 길면 뒤를 줄여 보이고, 탭을 누르면 그 아래에 프리셋 이름 전체가 보인다. 안에 무엇이 있는지 알리는 것은 이름을 짓는 지원자의 몫이라 탭 이름 옆에 자료 개수를 붙이지 않는다.
4. AI 요약과 질의응답은 탭 안에 넣지 않고 탭 밖에 둔다. 질의응답이 탭 하나면 면접관이 열지 않고 지나칠 수 있고, AI 요약은 발행본 전체를 다뤄 어느 한 탭에 속하지 않는다. 탭이 자료만 바꾸므로 탭을 바꿔도 질의응답 대화가 남는다.
5. 답·요약의 출처 단추가 다른 탭의 글을 가리키면 그 탭으로 바꿔 그 글로 이동한다. 답으로 돌아가는 단추를 둔다.

### 3-3. 지원자에게 알리는 것

1. 프리셋에 담을 때 확인이 필요한 Catch와 비공개 Catch를 표시한다.
2. 프리셋마다 지금 항목 수와 글자 수를 보인다.
3. 발행이 막히면 어느 프리셋의 어느 자료 때문인지 보인다.
4. 프리셋을 고쳐도 이미 보낸 링크는 바뀌지 않는다는 것을 프리셋을 고치는 화면에 적는다.

이유: 지금은 발행할 수 없는 Catch를 고르는 자리에서 바로 알 수 있다. 프리셋은 담는 때와 발행하는 때가 떨어져 있어, 막히는 이유와 상한 초과가 발행할 때에야 드러난다.

### 3-4. 하지 않는 것

1. 대표 Catch 표시를 만들지 않는다([#571](https://github.com/JminAILab/CatchU/issues/571)은 하지 않기로 하고 닫았다). 지원자가 대표 작업을 앞에 두고 싶으면 대표 Catch만 담은 프리셋을 따로 만들어 넣으면 된다.
2. Catch 검색과 JD 연계는 이 작업에 넣지 않는다.

### 3-5. 일정과 우선순위

11월 안에 dev에 넣는다. 우선순위는 P1이다. 화면을 다듬는 작업이 이 작업을 기다린다(§5).

## 4. 지금 코드: 바뀌는 자리

기준 커밋 `61b03716`에서 확인했다.

### 4-1. 발행 요청과 사본

- 발행 요청은 제목, 비밀번호, 항목 목록 하나다. 항목은 종류(`CATCH`·`TEXT_MATERIAL`·`PDF_MATERIAL`)와 원본 ID뿐이다(`api/src/publications/publish-input.ts`).
- 항목은 1개부터 20개까지, 같은 원본은 한 번만 받는다. 배열 순서가 보이는 순서다. 전체 글은 60,000자까지다(`api/src/publications/publications-config.ts`).
- 발행할 때 고른 비공개 Catch를 공개로 바꾼다. 확인하지 않은 Catch가 있으면 발행을 거부하고 어느 Catch인지 돌려준다(`api/src/publications/publish.service.ts`).
- 사본은 항목마다 순서 번호 하나로 저장한다. 묶음이라는 개념이 없다.

### 4-2. 순서 번호를 쓰는 곳

- AI 요약의 근거 목록(`api/src/rag-answer/summary-sources.ts`)
- 질의응답의 항목 머리글(`api/src/rag-answer/qna-sources.ts`)
- 검색 조각 나누기(`api/src/published-index/chunker.ts`)

### 4-3. 화면

- 발행 화면(`web/src/features/publications/publish-screen.tsx`·`publish-view.tsx`): 자료 고르기, 「작성자 설명을 쓴 Catch만 보기」, 「위로」「아래로」 단추, 확인 단계의 안내가 있다. 걸러 보기는 켜면 서버가 전체 Catch에서 설명이 있는 것만 골라 20개씩 돌려준다.
- 사본 표시(`web/src/features/publications/snapshot-view.tsx`): 받은 사람 화면과 작성자 발행본 화면이 함께 쓴다. 항목을 순서대로 한 줄에 모두 펼쳐 그린다.
- 받은 사람 화면의 순서(`web/src/features/recipient/recipient-view.tsx`): 제목 → 「이 링크에서 할 수 있는 것」 안내 → Claude 연결 → 발행 시각 → 발행본 자료 → AI 요약 → 질의응답 → JD 요약.
- 출처 단추(`web/src/features/recipient/recipient-screen.tsx`): 가리키는 항목 자리로 화면을 옮기고 그 글을 강조한다. 답으로 돌아오는 단추는 없다.
- 질의응답 대화(`web/src/features/rag-answer/qna-panel.tsx`): 서버에 저장하지 않고 화면 부품 안에만 기억한다. 부품을 내렸다 올리면 사라진다.
- 탭 부품은 자료 화면(`web/src/features/materials/materials-view.tsx`)에 이미 있다. web에 드래그용 도구는 없다.

### 4-4. 발행본을 읽는 다른 기능

- Claude 연결의 받은 링크 읽기(`api/src/claude-mcp/`)
- JD 요약(`api/src/jd-summary/`)

## 6. 바뀌는 기준과 그대로인 기준

[12월 요구사항](../../aidlc/spaces/default/intents/260925-intent-12/inception/requirements-analysis/requirements.md) 기준이다.

| 기준 | 내용 | 이 작업에서 |
|---|---|---|
| FR4.1 | 작성자는 자료를 직접 고르고 순서를 정해 발행한다. 비공개 Catch도 고를 수 있다 | 「직접 고르고」가 「프리셋을 고르고」로 바뀐다. 비공개 Catch를 고를 수 있다는 것은 그대로다 |
| FR4.6 | 발행 전에는 고른 자료·순서와 접근 조건을 안내한다 | 안내할 것이 프리셋과 그 순서로 바뀐다 |
| FR1.5 | 비공개 Catch도 발행에 고를 수 있고 발행할 때 공개로 바뀐다 | 그대로 |
| FR4.3 | 발행본은 발행 당시 자료를 고정한 것이다 | 그대로. 프리셋을 고치거나 지워도 발행본은 바뀌지 않는다 |
| FR4.4 | 발행본에 넣지 않은 자료는 얻을 수 없다 | 그대로 |
| FR4.7 | 발행할 때 권한·선택·크기를 다시 확인한다 | 그대로 |
| FR2.7·FR6.2 | AI 요약과 질의응답은 발행본을 근거로 쓴다 | 그대로. 등록한 프리셋 전체가 근거다 |

[새 Catch](../../aidlc/spaces/default/intents/261109-new-catch/inception/requirements-analysis/requirements.md) 작업에서 발행 화면에 넣은 것(작성자 설명 걸러 보기, 「설명 안 씀」 표시, 확인 단계의 안내)은 자리만 프리셋 화면과 새 발행 화면으로 옮기는 것을 기본값으로 한다.

## 7. 정하지 않은 것과 기본값

intent의 요구사항 단계에서 확정한다.

| 정할 것 | 지금 사실 | 기본값 |
|---|---|---|
| 같은 Catch를 여러 프리셋에 담을 수 있는지 | 발행본은 같은 원본을 한 번만 받는다 | 없음. 질문으로 올린다 |
| 항목 20개와 전체 글 60,000자 상한을 어떻게 셀지 | 발행본 전체 기준이다 | 발행본 전체 기준 그대로 |
| 프리셋 이름의 길이 상한 | 발행본 제목은 50자까지다 | 없음. 질문으로 올린다 |
| 이 변경 전에 발행한 발행본의 탭 이름 | 프리셋 이름이 없다 | 탭 하나에 지금 화면 제목인 「발행본 자료」 |
| 받은 링크 읽기에 프리셋 구분을 실을지 | 항목을 순서대로 읽는다 | 없음. 질문으로 올린다 |
| 작성자 설명 걸러 보기를 그대로 옮길지 | 서버가 전체에서 고른다. 담당이 겪은 불편이 어느 화면의 것인지는 확인 중이다 | 그대로 옮긴다 |

## 8. 채택하지 않은 안

다시 꺼내지 않는다.

| 안 | 채택하지 않은 이유 |
|---|---|
| 비공개 Catch를 고르는 목록에서 빼기 | 지원자가 Catch를 하나씩 공개로 바꿔야 한다 |
| 대표 Catch를 고르고 나머지를 접기(#571) | 대표만 담은 프리셋으로 풀린다. 발행 요청과 사본에 표시를 더하지 않아도 된다 |
| 질의응답을 별도 탭으로 두기 | 면접관이 열지 않고 지나칠 수 있고, 출처를 보러 다녀오면 대화를 지켜야 한다 |
| 프리셋이 하나면 탭 줄 숨기기 | 발행본마다 모양이 달라져 통일감이 사라진다 |
| 발행 화면 안에서 프리셋 만들기 | 발행 화면이 복잡해진다 |
| 탭 이름 옆에 자료 개수 붙이기 | 이름으로 알리는 것은 지원자의 몫이다 |
| 탭 대신 한 화면에 구역으로 쌓고 바로가기 두기 | 화면이 여전히 길다 |
| 답 아래에 원문 조각을 펼쳐 보이기 | 탭을 바꿔 이동하는 방식 위에 나중에 얹을 수 있어 지금은 넣지 않는다 |
| 넓은 화면에서 자료와 질의응답을 좌우로 나란히 두기 | 화면 틀을 새로 짜야 한다 |

## 9. 받아들인 약점

- 브라우저의 찾기는 열려 있지 않은 탭의 글을 찾지 못한다. 질의응답이 그 역할을 대신한다.
- 처음 쓰는 지원자는 프리셋 화면을 먼저 거쳐야 해서 첫 발행까지 걸음이 하나 늘어난다.
