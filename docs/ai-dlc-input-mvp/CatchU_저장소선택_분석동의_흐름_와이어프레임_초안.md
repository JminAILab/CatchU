# CatchU 10월 MVP — 저장소 선택·분석 동의 화면 흐름·와이어프레임 초안

> 지위: 팀 검토용 초안 v0.5 (2026-09-22). 이슈 #30의 산출물이며 팀원 1이 조율하는 AI-DLC에 전달할 참고 입력이다. 공식 요구사항·설계·승인 기록이 아니다.
> 대상: PC 웹의 로그인한 구직자. 담당 범위는 서비스 홈·분석 화면 프론트엔드이며, 이번 상세 범위는 서비스 홈 초안의 A-01(저장소 선택·분석 동의)이다.
> 표현: 상자·텍스트·버튼만 사용한다. 아래 화면과 예시는 실제 선정 저장소·분석 결과가 아니며, 제품 코드·API 연결·완성 시각 디자인은 포함하지 않는다.

## 0. 10월 공통 헤더 적용

**[팀원 2·3 합의 — 2026-09-22 기록]** [10월 헤더 합의 #55](https://github.com/JminAILab/CatchU/issues/55)·[사용자 메뉴 동작 합의 #51](https://github.com/JminAILab/CatchU/issues/51)를 적용한다. 팀원 3이 두 사람의 안건 A~H 답변이 동일함을 확인해 기록한 범위다. API·시각 디자인·구현 승인과 구분한다.

| 화면·상태 | 10월 헤더 구성·동작 |
|---|---|
| 로그인 일반 서비스·발행자 | 왼쪽 로고 → 내 자산 → 공유 링크, 오른쪽 프로필. 로고는 로그인 홈, 내 자산은 자산 영역, 공유 링크는 L03으로 이동 |
| 비로그인 일반 홈 | 왼쪽 로고, 오른쪽 Google로 시작하기. 로고는 비로그인 홈, 헤더·본문 시작 버튼은 같은 로그인 흐름으로 연결 |
| 수신자 V01~V03, 로그인·비로그인 공통 | 이동 없는 브랜드만 표시. 로그인·프로필·관리 메뉴 없음. V03 본문의 같은 링크 V02 목록 복귀 버튼 유지 |

10월에는 채용공고·알림 및 대표 구성 진입점(내 자산 내부 포함)을 숨긴다. 최초 프로필 입력의 저장 조건을 우회하는 메뉴 진입을 새로 허용하지 않는다. 12월 수신자 회원 연결·알림 설정은 후속 논의다.

로그인 일반 서비스의 프로필 버튼 근처에 **모달**을 열고 **프로필 보기 / 로그아웃**을 둔다. 프로필 보기 → 상세 프로필 → 수정 → 저장 성공·취소 후 상세 프로필로 돌아온다. 변경이 있는 취소·이동·로그아웃은 이탈 확인을 거치며, 머무르기를 선택하면 화면과 입력을 유지한다. 로그아웃은 최초 입력 W02를 포함해 성공 시 **비로그인 홈(H-01)**으로 이동하고, 실패 시 현재 화면·입력을 유지하며 완료로 표시하지 않는다. 모달 닫기 조작의 조합과 로그아웃 실패 안내의 구체 문구는 후속 검토다.

이 반영은 공통 헤더·프로필 연결만 다룬다. 분석 요청·동의·접수 불명·재요청 및 #64의 화면 단위 경계는 기존 기준을 유지한다. 화면 이동·로그아웃을 분석 취소·완료로 해석하지 않는다.

## 2. 관련 요구사항과 화면 표현

| 근거 | 지켜야 할 행동 | 이 화면의 표현 |
|---|---|---|
| FR1.1, C4 | **[요구]** 팀이 사전 선정한 공개 저장소를 분석한다. 구직자의 해당 저장소 분석 동의가 선행 조건이며, **동의가 없으면 분석하지 않는다.** 동의를 받는 구체 방식은 OQ11에서 정한다 | **[제안]** 선정 목록에서 저장소를 고르면 그 아래에 동의 안내를 펼치고, 체크박스로 동의하기 전에는 [분석 요청]을 비활성으로 둔다. 화면 비활성화는 표현 방식이며 서버가 동의 없는 요청을 실행하지 않는 것이 요구 충족의 기준이다 |
| FR1.4, NFR4 | **[요구]** 같은 저장소의 **진행 중 중복 실행을 막는다.** 판정 단위는 OQ1 | **[제안]** 이 사용자의 분석이 진행 중인 저장소는 목록에 ‘분석 진행 중’을 표시하고 [진행 상태 보기]로 연결한다. 요청 중 반복 제출도 화면에서 막는다. 화면 처리는 보조이며 중복 실행 방지의 기준은 서버 판정이다 |
| FR10.4 | **[요구]** 운영자가 신규 분석을 중단하면 새 분석이 시작되지 않고 기존 자료 열람은 유지된다 | **[제안]** 중단 중에는 요청할 수 없다는 사유를 안내하고 상단 메뉴의 기존 자료 경로는 그대로 둔다 |

| MVP 입력 OQ11 | **[제안]** 분석 동의는 저장소 선택 화면에서 저장소별로 받는다. 문구에 분석 범위(공개 저장소의 커밋·PR·diff), 외부 AI 전송 사실, 공동 기여자 가명 처리, 결과의 공개 선택 분리를 적는다. 동의 시각과 동의한 저장소를 기록한다 | **[제안]** 이 초안의 와이어프레임은 이 제안안을 따른다. 동의 수집 방식·기록 시점·보관은 확정하지 않는다(§6) |

## 3. 진입 경로와 사용자 흐름 [제안]

진입은 서비스 홈(H-01)의 [저장소 선택]이다. 첫 방문에서는 주 행동, 재방문에서는 최근 분석 상자 아래 보조 버튼이다(홈 초안 v0.3).

```text
[H-01 홈] → [저장소 선택]
    → [A-01 저장소 선택·분석 동의]
         ├─ 선정 목록 조회
         │    ├─ 성공·1건 이상 → 목록 표시
         │    ├─ 성공·0건 → ‘지금 분석할 수 있는 저장소가 없습니다’
         │    └─ 실패 → 조회 실패 안내 + [목록 다시 불러오기]
         │
         ├─ 이 사용자의 분석이 진행 중인 저장소
         │    └─ [진행 상태 보기] → A-02 (새 요청을 만들지 않음)
         │
         ├─ 저장소 하나 선택 → 그 저장소 아래에 동의 안내 펼침
         │    ├─ 동의 체크 전 → [분석 요청] 비활성
         │    ├─ 동의 체크 → [분석 요청] 활성
         │    └─ 다른 저장소로 변경 → 이전 펼침 닫힘, 동의 체크 해제
         │
         ├─ [분석 요청] 전송
         │    ├─ 접수 확인 → A-02 진행 상태
         │    ├─ 같은 저장소가 이미 진행 중 → 기존 A-02로 연결
         │    ├─ 신규 분석 중단·선정 조건 변경 등으로 거절 → 사유 안내, A-01 유지
         │    └─ 접수 여부 불명 → 상태 확인 안내 (자동 재제출 없음)
         │
         └─ 요청 전 [취소] → 분석을 시작하지 않고 H-01로 이동
              (동의 기록 시점·보관은 미정)
```

- **[요구]** 동의가 없으면 분석하지 않는다(FR1.1). **[제안]** 위 흐름의 비활성·활성 전환은 그 요구를 화면에서 표현하는 방식이다.
- **[제안]** 동의 체크는 선택한 저장소 하나에만 적용한다. 다른 저장소를 고르면 체크를 해제하고 새 저장소의 동의를 다시 받는다.
- **[제안]** 요청 전 [취소]는 분석을 시작하지 않고 홈으로 돌아가는 동작이다. **[미정]** 동의를 언제 기록하는지(체크 시점·요청 전송 시점·접수 시점), 요청 전에 떠난 경우 기록이 남는지, 기록 보관 기간은 정하지 않았다(§6).
- **[제안]** 요청을 전송한 뒤에는 [취소]를 두지 않는다. 화면을 떠나거나 뒤로 가도 분석 요청이 취소되거나 동의·요청 기록이 삭제된다고 안내하지 않는다. 분석 요청 취소 기능은 이 초안에서 다루지 않는다.

## 4. PC 와이어프레임 [제안]

표기는 홈 초안과 같다. 굵은 선 상자(┏ ┃ ┗)는 강조 영역, `[[버튼]]`은 주 버튼, `[버튼]`은 보조 버튼, `( )`·`(●)`는 단일 선택, `[ ]`·`[✓]`는 체크 항목이다. `[예시]`는 임시 표시값이며 실제 선정 저장소가 아니다. 화면의 배치·문구·버튼은 모두 제안이다.

**설계 주석 — 저장소 표시 정보 [미정]:** 와이어프레임에는 저장소 이름만 그렸다. 이름 외에 목록 항목에 보여 줄 정보(설명·분석 기간·규모 등)와 정렬은 정해지지 않았으며, 정해지면 각 저장소 이름 아래에 추가한다(OQ1, §6 ‘선정 목록’).

### 4.1 저장소를 고르기 전

```text
┌─ A-01 저장소 선택·분석 동의 · 선택 전 ─────────────────────────
│ [CatchU 로고] [내 자산] [공유 링크]                  [프로필]
├────────────────────────────────────────────────────────────────
│ 분석할 저장소 선택
│ 팀이 선정한 공개 저장소 중 하나를 고르세요.
│ 선택한 저장소에 분석 동의를 한 경우에만 분석합니다.
│
│ ┌ 선정 저장소
│ │ ( ) [예시] example-org/demo-repo-a
│ │
│ │ ( ) [예시] example-org/demo-repo-b
│ │
│ │ · [예시] example-org/demo-repo-c   분석 진행 중
│ │     [진행 상태 보기]
│ └
│
│ 저장소를 고르면 그 아래에 분석 동의 안내가 펼쳐집니다.
│
│ [취소]
└────────────────────────────────────────────────────────────────
```

- **[제안]** 진행 중인 저장소는 선택 버튼 대신 ‘분석 진행 중’과 [진행 상태 보기]를 보여 준다. 이는 FR1.4 **[요구]**(진행 중 중복 실행 방지)를 돕는 화면 표현이다.
- **[미정]** 완료·실패 이력이 있는 저장소를 다시 고를 때의 표시와 동작(§6).

### 4.2 저장소를 고른 뒤, 동의하기 전

```text
┌─ A-01 저장소 선택·분석 동의 · 동의 전 ─────────────────────────
│ [CatchU 로고] [내 자산] [공유 링크]                  [프로필]
├────────────────────────────────────────────────────────────────
```

## 5. 버튼 동작과 상태

### 5.1 버튼 [제안]

표의 동작·조건은 모두 제안이다. 괄호 안의 [요구]는 그 동작이 돕는 요구사항이다.

| 버튼 | 동작·이동 | 조건·주의 |
|---|---|---|
| 저장소 선택(단일 선택) | 선택한 저장소 아래에 동의 안내와 [분석 요청] 펼침 | 다른 저장소로 바꾸면 이전 펼침을 닫고 체크 해제. 선택만으로 분석을 요청하지 않음 |
| 동의 체크 | [분석 요청] 활성 | 선택한 저장소 하나에만 적용. 체크를 기록하는지·기록 시점은 미정 |
| 분석 요청 | 선택 저장소와 동의 여부를 담아 요청 전송 → 접수 확인 후 A-02 | 체크 전 비활성([요구] FR1.1). 신규 분석 중단 중 요청 불가([요구] FR10.4). 전송 후 반복 제출 막음([요구] FR1.4). 자동 재제출 없음([결정] OQ1) |
| 진행 상태 보기 | 이 사용자의 해당 저장소 진행 중 분석 A-02 | 새 요청을 만들지 않음([요구] FR1.4) |
| 취소 | 요청 전: 분석을 시작하지 않고 H-01로 이동 | 요청 전송 후에는 표시하지 않음. 동의 기록 처리는 미정 |
| 목록 다시 불러오기 | 선정 목록 조회만 재실행 | 분석 요청과 구분 |
| 요청 상태 확인 | A-01에 머문 채 해당 요청의 접수·처리 상태를 다시 조회. 접수가 확인되면 A-02로 이동, 거절이 확인되면 해당 거절 안내 표시 | 접수가 확인되지 않으면 A-01의 접수 불명 안내를 유지. 분석을 다시 요청하거나 자동 재제출하지 않음([결정] OQ1). 실제 조회 방법(요청 식별·조회 경로)은 연결 계약 미정(§6) |
| 로그인으로 이동 | 인증 영역(기본 로그인은 Google OAuth — [팀 합의]) | 세션 만료 시. 로그인 후 복귀 위치와 세션 만료 처리는 회원 담당과 연결 확인(§6) |

## 6. 미정 사항과 연결 확인

아래는 이 초안이 확정하지 않은 항목이다. 한꺼번에 답을 요구하는 질문지가 아니며, 관련 담당과 순서대로 확인한다.

**정하는 곳 (PR #31 리뷰 답변·후속 입력):** 동의 방식·동의 기록은 **#24 공통 준비**에서 정한다(후속 입력은 동의 방식의 조율을 팀원 1에게 연결한다). GitHub 연결·선정 목록·요청 처리(다시 고르기·동시 요청·요청 후 취소·응답 확인 불가 판정·요청 상태 조회 포함)는 **팀원 1의 후속 답변**으로 정한다. 이 초안은 그 결과를 받기 전까지 해당 항목을 제안·미정으로 유지한다. 기본 로그인 방식과 홈 진입 조건은 후속 입력의 **팀장 확인(팀 합의)**을 따른다.

| 구분 | 미정·확인 사항 | 확인 상대 |
|---|---|---|

## 7. 검토 기준

- 동의 없이는 분석하지 않는다는 요구가 화면 흐름에서 드러나고, 버튼 비활성화는 그 표현 방식으로 구분된다.
- 진행 중 중복 실행 방지 요구와 [진행 상태 보기] 연결·반복 제출 차단이라는 화면 표현이 구분된다.
- 목록 밖 저장소 선택(FR1.2)과 미지원 사유 안내(FR1.3)가 10월 화면에 없다.
- 저장소를 바꾸면 동의가 새 저장소로 옮겨 가지 않는다.
- 요청 전 취소와 요청 전송 후 상태가 구분되고, 전송 후 취소·기록 삭제를 안내하지 않는다.
- 목록 조회 실패·목록 없음·신규 분석 중단·접수 불명이 구분된다.
- 기본 Google OAuth 로그인과 GitHub 연결 없는 홈 진입은 팀 합의로 표시되고, 분석 요청 전 GitHub 연결 필요 여부·저장소 관계 확인·동의 방식·동의 기록은 확정처럼 표현되지 않는다.
- GitHub 연결 없는 홈 진입이 분석 동의나 분석 요청 허용으로 표현되지 않는다.

이 기준은 팀 검토용 체크 항목이며 제품 동작의 테스트 통과나 팀 승인 완료를 뜻하지 않는다. 원본 요구사항·AI-DLC 공식 기록은 이 초안에 맞춰 변경하지 않는다.
