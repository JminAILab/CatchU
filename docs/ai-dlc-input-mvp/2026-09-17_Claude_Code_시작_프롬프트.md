## 1. 별도 브랜치·worktree

실험 작업의 시작 커밋은 **`c0e9327ac3331dfcaccc951a621bbdd978789784`**이다. 기존 답변 기준 `0eebd671df1ae1878f9ba28ad6254f8bfd5093db`에 인계서·결과 양식·문서 목록만 더한 판본이다. 움직이는 dev/PR 브랜치 HEAD로 대체하지 않는다. 해당 커밋에는 아래 인계서와 양식이 들어 있으며 이 시작 안내는 그 뒤 별도 커밋에서 제공한다.

현재 Codex 작업 폴더를 건드리지 않도록 별도 터미널에서 아래를 순서대로 확인한다. 경로/브랜치가 이미 있으면 강제 덮어쓰거나 지우지 말고 상태를 먼저 확인한다. 아래는 **안내 명령이며 인계 준비 세션에서 실행하지 않았다**.

```sh
cd /Users/ljm/Desktop/github/CatchU-feasibility
git status --short
git worktree list
git show --no-patch --format=fuller c0e9327ac3331dfcaccc951a621bbdd978789784
git worktree add -b docs/c02-c01-revalidation-0917 /Users/ljm/Desktop/github/CatchU-revalidation-0917 c0e9327ac3331dfcaccc951a621bbdd978789784
cd /Users/ljm/Desktop/github/CatchU-revalidation-0917
git rev-parse HEAD
git status --short
```

기존 worktree의 미커밋 변경은 유지한다. 새 worktree에서 Claude Code를 시작하고 아래 프롬프트를 넣는다. 새 worktree가 없거나 올바른 커밋이 아니면 원본 작업 폴더에서 실험을 대신 시작하지 않는다. API 키는 사용자가 해당 터미널 환경으로 제공하며 키를 명령 인수/프롬프트/문서에 적지 않는다. 이 문서는 키 설정 명령을 만들거나 현재 키를 검사하지 않았다.
