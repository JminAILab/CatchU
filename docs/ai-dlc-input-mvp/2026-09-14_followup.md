## 회의에서 확인한 내용

사용자가 전달한 회의 결과: “§2.5 중 팀원 2·3·4의 담당 작업은 회의에서 변경 없이 진행하기로 했다.”

| 담당 | 회의에서 진행하기로 한 작업 | 첫 결과물 기준 |
|---|---|---|
| 팀원 2 | 회원·기본 프로필, 내 자산·대표 프리셋 | 로그인·프로필, Catch 확인·공개·숨김·불일치 표시, 대표 주장·Catch 선택 흐름과 와이어프레임 |
| 팀원 3 | 공유 링크 발행·관리, 수신자 열람 | 발행자·수신자 흐름, 비밀번호·중단·만료·자료 열람 와이어프레임 |
| 팀원 4 | 서비스 홈, 저장소 선택·분석 진행·실패·재시도 화면 프론트엔드 | 먼저 홈 와이어프레임, 이후 분석 화면으로 확장 |

팀원 1은 공통 조율, PoC 분석, GitHub 분석 서버 처리를 맡으려는 의사를 밝혔다. 첫 결과물은 PoC 분석 요약, 분석 입력·상태·결과 데이터 초안, 전체 기능 담당표다. 실제 GitHub 계정과 팀원 번호의 대응, 작업량·날짜는 이 입력으로 확정하지 않는다.

첫 화면 결과물은 MVP 입력 §2.5에 따라 목적·진입·정보·버튼·이동과 관련 빈 상태·로딩·실패·미정 질문을 설명한다. 완성 디자인이나 실제 API 연결은 첫 제출의 필수 조건이 아니다. 담당자는 자신의 영역을 설계·코딩·테스트하며, 사람의 책임 배분과 AI 에이전트 역할은 별도로 기록한다.

## 팀장 확인 (2026-09-14): 인증·홈 진입

지위: 팀 합의. 별도 회의 기록은 없으며 PR #29 검토 과정에서 팀장이 확인했다. 승인 요구사항·MVP 입력을 소급 수정하지 않고 새 intent가 이 확인을 함께 참조한다.

- 기본 로그인은 Google OAuth다. 다른 로그인 수단의 추가·배제, 계정 연결 상세는 미정이다.
- GitHub 연결 없이 홈 진입을 허용한다. 홈 진입을 저장소 분석 동의나 분석 실행 허용으로 보지 않는다.
- 파생 미결: Google 계정과 사전 선정 저장소의 소유·커밋 관계 확인 방법(OQ1)과 분석 동의 방식(OQ11)은 팀원 1이 조율한다. 10월 분석 요청 전에 GitHub 연결이 필요한지도 이 조율에 포함한다. 확인 규칙은 #23의 연결 기준에, 결정·구현 책임과 OAuth 준비는 #24의 담당 배분에 연결한다. GitHub OAuth 준비는 12월 FR1.2와 분석 연결용으로 남는다.

## 팀장 확인 (2026-09-14): 링크 용어·수신자 접근 불가 안내

지위: 팀 합의. 별도 회의 기록은 없으며 PR #33(공유 링크 흐름·와이어프레임 초안)과 PR #38(관리·예외 동작 v0.7) 검토 과정에서 팀장이 확인했다. 승인 요구사항을 소급 수정하지 않고 링크 초안과 새 intent가 이 확인을 함께 참조한다.

- 링크 관련 용어는 승인 요구사항과 같이 **‘발행’**으로 통일한다. 이슈 #21 제목·본문, 이 문서의 표와 MVP 입력 §2.5 담당표는 ‘발행’으로 갱신했다. 홈 초안에 남은 ‘발급’은 홈 담당의 다음 판에서 맞춘다. 이전 판·이슈의 ‘발급’은 같은 뜻이다.
- 수신자 화면은 **중단·만료·없는 URL의 사유를 구분하지 않고 같은 접근 불가 문구 하나**를 표시한다. 비밀번호가 설정된 링크라도 비밀번호 입력보다 이 안내를 먼저 표시하며, 문구가 하나이므로 링크 상태는 노출되지 않는다. 중단·만료 구분은 발행자의 링크 관리 화면에만 둔다. 이유: FR4.3·FR4.5는 열람 불가만 요구하고 NFR6의 안내 일치는 발행자 측 상태 전환 화면 기준이며, 사유를 구분하면 수신자가 비밀번호 없이 구직자의 중단 사실과 URL 존재 여부를 알게 된다. 구체 문구는 링크 담당의 화면 제안이다(현재 “이 링크는 열람할 수 없습니다.”).
- 유효한 링크 안에서 **숨긴 Catch와 없는 Catch를 직접 열었을 때도 같은 문구 하나**를 표시한다(PR #38 검토에서 확인). 링크 단위와 같은 원칙으로, Catch의 존재·숨김 여부를 추론할 단서를 주지 않는다. 비밀번호 조건을 아직 충족하지 않았으면 Catch 구분 없이 비밀번호 입력부터 적용하고, 링크 자체가 접근 불가면 링크 공통 문구를 우선한다. 구체 문구는 링크 담당의 화면 제안이다(현재 “현재 열람할 수 없는 자료입니다.”). 응답 코드·응답 시간 등 화면 밖 단서의 통제는 권한 계약·검증에서 확인한다.
- **공개 GitHub 자산이 0개로 확인돼도 링크 발행을 허용**한다(PR #38 검토에서 확인, 링크 초안 §4.7의 A안). 이유: 승인 요구사항(FR3.1·FR4.2)에 최소 자산 조건이 없고, 발행 후 자산을 모두 숨기면 프로필만 보이는 링크가 어차피 생기므로 발행 시점 조건을 추가해도 보장되는 것이 없다. 발행 준비 화면은 공개 자산이 없음을 안내하고, 수신자는 공개 허용 프로필과 자료 없음 안내를 본다. 조회 실패는 0개로 취급하지 않는다. 프로필 공개 항목은 OQ3에 남는다.

## 여전히 검토·결정할 내용

- 화면 연결 지점·API 계약·공통 및 미배정 작업은 이번 회의에서 논의하지 않았다. §2.5의 담당 경계 설명은 관련 작업의 설계 시점에 확인할 제안으로 유지한다. 인증 방식과 홈 진입 조건은 위 팀장 확인을 따른다.
- 내부 선택 공유·품질 신호·검토 권한, 운영 기록·신규 처리 중단·재개, 환경 준비·수동 배포·복구, 통합 검증의 구현·검토·운영 책임을 팀에서 배분한다. 선택 공유 내용의 검토자가 팀원 1이라는 사실로 구현·운영까지 배정하지 않는다.
- 독립 화면 초안은 병행할 수 있다. 실제 API·저장·권한 연결 전에는 해당 공통 설계와 계약을 확인한다. 초안이 제출되지 않았다면 존재한다고 가정하지 않는다.
- 각 화면 초안의 작성 주체·정본·리비전을 확인하고 관련 AI-DLC 단계에서 검토·보완해 재사용한다. 팀장 세션에서 같은 결과물을 중복 작성하지 않는다.

## 공식 계획 제안에 반영할 요청

- 첫 intent의 승인된 제품 행동·FR/NFR ID를 재사용하고, 10월 적용과 후속 결정만 구체화한다. 첫 intent를 다시 열거나 승인 이력을 소급 수정하지 않는다. 재사용은 새 단계 완료나 승인과 다르다.
- PoC 분석은 코드·의존성·입출력·흐름, 확인 가능한 실행 결과·한계, 유지·수정·제외 근거, 서비스 요구사항과의 차이, 재사용·재설계·추가 검증을 다룬다. 분석 전 코드 복사나 재사용을 근거로 한 일정 단축 확약은 하지 않는다. 규칙 기반 결과는 LLM 초안 생성 검증과 구분한다.
- 공통 데이터·권한·상태 모델을 확인하고 구현·검토 가능한 유닛으로 분할한 뒤 API 계약과 의존성을 정한다. 사람별 큰 담당 영역을 유닛 하나로 고정하지 않는다.
- 각 담당자가 연결 구현을 시작할 때 필요한 설계·계약·검증 기준, 첫 통합 흐름과 전체 기능 검증, NCP 수동 배포·외부 URL·자료 유지·복구 확인의 검토 지점을 제안한다. 자동 배포 파이프라인은 제외한다.
- 10월 필수 범위는 MVP 입력 §1·§3을 유지한다. 대표 구성은 링크 발행 필수 조건이 아니다. 미완료 기능을 임의 제외하거나 12월로 넘기지 않는다.
- NCP 계정 수령·권한, 서비스 LLM API 제공자·모델·등급, GitHub OAuth 준비는 실제 확인한다. GitHub OAuth의 용도는 12월 FR1.2와 분석 연결이며, 10월 분석에 GitHub 연결이 필요한지는 OQ1에서 정한다. 예정일이 지났다는 사실은 준비 완료가 아니다. 팀원 1의 조율·자문과 팀원 4의 학습 부담을 가용량에 반영한다.

## 입력의 효력과 실행 기록

원래 §2.5 전체가 제안이라고 적힌 부분 중 **팀원 2·3·4의 담당 작업 진행 여부**에 이번 회의 결과를, **인증·홈 진입**과 **링크 용어·수신자 접근 불가 안내**에 위 팀장 확인을 후속 입력으로 적용한다. GitHub 연결 없이 홈에 들어가는 것과 분석을 요청할 수 있는 것은 별개이며, Google OAuth는 기본 로그인 방식이지 유일한 방식으로 확정한 것이 아니다. 연결 계약과 공식 단계 승인은 그대로 미결이다. 기존 입력·승인본을 소급 변경하지 않고 새 intent가 이 후속 입력을 함께 참조하도록 한다.

실행 상태·막힘·담당은 [공용 Project](https://github.com/orgs/JminAILab/projects/2)와 기존 이슈 [#19](https://github.com/JminAILab/CatchU/issues/19)·[#20](https://github.com/JminAILab/CatchU/issues/20)·[#21](https://github.com/JminAILab/CatchU/issues/21)·[#22](https://github.com/JminAILab/CatchU/issues/22)·[#23](https://github.com/JminAILab/CatchU/issues/23)·[#24](https://github.com/JminAILab/CatchU/issues/24)에 남긴다. 이 파일을 진행 현황판으로 사용하지 않는다. 요구사항·설계·승인은 새 intent의 AI-DLC 산출물에, 변경·검증·리뷰 증거는 PR에 남긴다.
