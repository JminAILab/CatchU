# CatchU 10월 MVP — 서비스 홈 흐름·와이어프레임 초안

> 지위: 팀 검토용 초안 v0.7 (2026-09-15). 팀원 1이 조율하는 AI-DLC에 전달할 참고 입력이며 공식 요구사항·설계·승인 기록이 아니다. 팀 결정·작성자 요청·화면 제안·미정을 구분한다.
> 대상: PC 웹의 비로그인 방문자와 로그인한 구직자. 작성자(팀원 4)의 담당 범위는 서비스 홈·분석 화면 프론트엔드이며, 이번 상세 범위는 로그인 여부와 초기 설정 상태(GitHub 연결·저장소 설정)에 따른 홈이다.
> 표현: 상자·텍스트·버튼만 사용한다. 가상 Catch는 설명용 예시이며 실제 분석 결과가 아니다. 제품 코드·API 연결·완성 시각 디자인은 포함하지 않는다.

**[요구]**는 승인 요구사항의 행동, **[결정]**은 MVP 입력의 명시된 결정, **[팀 합의]**는 병합된 후속 입력의 팀장 확인, **[팀장 결정]**은 PR #44 댓글에서 팀장이 정하고 PR #53(미병합)에 기록 중인 결정, **[회의 결정]**은 #55에 기록한 2026-09-15 팀 회의 결정이다. 여기까지가 팀 결정이다. **[작성자 요청]**은 작성자(팀원 4)가 v0.7에서 요청한 홈 방향이며 팀 합의 전이다. **[제안]**은 화면 배치·문구·동작, **[연결 제안]**은 다른 담당과 맞출 연결, **[미정]**은 남은 정책·계약이다. 화면 ID는 초안 안의 식별자이며 URL·API 계약을 확정하지 않는다.

**대체 범위:** v0.7은 v0.6의 ‘로그인 홈 공통 구성([저장소 선택] → A-01 직행)’을 초기 설정 상태별 세 표현으로, 상단 메뉴 [홈]·[대표 구성]을 #55의 내비게이션으로 대체한다. PR #44 팀장 결정은 PR #46의 ‘홈 최근 분석 한 건’ 항목과 v0.4·v0.5의 홈 검토 현황 제안을 대체한다. PR #46의 ‘내 자산 GitHub 관련 탭에서 이전 분석을 찾는다’는 경로는 유지한다. 과거 판의 화면·표는 현행 본문에서 제거하고 §9의 이력과 git 판본으로 남긴다. 승인 요구사항·후속 입력 원본·AI-DLC 상태·승인 기록을 이 초안에서 수정하지 않는다.

다른 담당 영역은 MVP 입력 §2.5의 담당 제안을 기준으로 연결 상대를 표시한다. 작성자(팀원 4)의 화면 밖 상세 설계·전체 배정의 확정을 뜻하지 않는다.

## 5. PC 홈 와이어프레임 [제안]

### 5.1 v0.7 공통 구성

- 비로그인 홈은 v0.6 구성(서비스 소개·가상 Catch·[Google로 시작하기])을 유지한다.
- **[팀장 결정]** 로그인 홈은 **GitHub 연결 전 / repo 연결 전 / repo 연결 후** 세 표현으로 나눈다. GitHub 연결만으로 repo 연결 후 홈을 보여 주지 않고 연결된 repo(분석 요청이 접수된 저장소 1개 이상)까지 확인한다. 분석 완료는 조건이 아니다. 작성자 요청의 ‘저장소 설정 완료’는 이 ‘연결된 repo 있음’으로 읽는다.
- 홈에는 최근 분석 상자, 진행·완료·실패 상태, 결과 단위 검토 현황, 분석 조회 로딩·실패 표시를 두지 않는다. 로그인 여부·초기 설정 상태 확인의 로딩·실패와는 구분한다.
- **[회의 결정 #55]** 로그인 내비게이션은 `[CatchU 로고] [내 자산] [공유 링크] [채용공고] [알림] [프로필]`이다. 그림의 간격·표현은 제안이며, 로그인 여부별 노출과 프로필·로그아웃 연결은 [#55](https://github.com/JminAILab/CatchU/issues/55)·[#51](https://github.com/JminAILab/CatchU/issues/51)에서 정리한다. [채용공고]·[알림]이 여는 화면과 10월 제공 시점은 미정이다(§7.2).
- `[[버튼]]`은 주 버튼, `[버튼]`은 보조 버튼이다. 상자·문구·강조 순서는 화면 제안이다.

### 5.3 로그인 홈 — GitHub 연결 전

```text
+- H-01 서비스 홈 · 로그인 · GitHub 연결 전 ---------------------
| [CatchU 로고] [내 자산] [공유 링크] [채용공고] [알림] [프로필]
+----------------------------------------------------------------
| GitHub 기록을 나의 경험으로 정리해 보세요.
|
| + GitHub 연결 -----------------------------------------------
| | 분석을 요청하려면 먼저 프로필에서 GitHub를 연결하세요.
| | 연결한 뒤 내 자산의 GitHub 탭에서 저장소를 연결합니다.
| | [[프로필에서 GitHub 연결]]
| +------------------------------------------------------------
|
| 결과 확인과 공개 선택은 별도입니다.
+----------------------------------------------------------------
```

- **[팀장 결정]** 10월 분석 요청 전에는 GitHub 연동이 필요하고, 미연동 사용자는 홈 → 프로필의 GitHub 연동 → 자산 GitHub 탭 → 저장소 선택·동의 순서로 진행한다(PR #53 `25f94b0`). **[제안]** 이 순서를 한 줄씩 안내하고 주 버튼은 [프로필에서 GitHub 연결] 하나만 둔다.
- **[제안]** GitHub 연결 상태를 정상 조회해 ‘미연결’로 확인한 경우에만 이 화면을 보여 준다. 확인 중·조회 실패는 §6.2를 따른다.
- **[연결 제안]** 연결 화면의 위치·연결 취소·실패·만료 안내, 연결 성공 후 자산 GitHub 탭으로 돌아오는 방식은 회원·자산 담당(팀원 2)이 정한다. GitHub 연결만으로 저장소 소유·커밋 관계 검증이나 분석 동의가 완료되지 않는다.

### 5.4 로그인 홈 — GitHub 연결 후, repo 연결 전

```text
+- H-01 서비스 홈 · 로그인 · repo 연결 전 -----------------------
| [CatchU 로고] [내 자산] [공유 링크] [채용공고] [알림] [프로필]
+----------------------------------------------------------------
| GitHub 기록을 나의 경험으로 정리해 보세요.
|
| + 분석할 저장소 연결 ----------------------------------------
| | 분석할 저장소는 내 자산의 GitHub 탭에서 연결합니다.
| | 저장소 선택·동의·분석 요청을 그곳에서 한 번에 진행합니다.
| | [[내 자산에서 repo 연결]]
| +------------------------------------------------------------
|
| + 요청한 분석 확인
| | 분석 상태와 결과는 내 자산의 GitHub 탭에서 확인하세요.
| | [내 자산에서 분석 보기]
| +
|
| 결과 확인과 공개 선택은 별도입니다.
+----------------------------------------------------------------
```

- **[팀장 결정]** GitHub는 연결했지만 연결된 repo(분석 요청이 접수된 저장소)가 없으면 자산 GitHub 탭으로 보낸다. repo 연결은 자산 GitHub 탭에서 저장소 선택·분석 동의·분석 요청을 버튼 하나로 처리하며, 홈에서 저장소 선택으로 바로 가지 않는다(PR #53 `25f94b0`).
- **[제안]** 주 버튼은 [내 자산에서 repo 연결] 하나이며 이동만 한다. 홈에서 저장소를 고르거나 동의·요청을 받지 않는다. 버튼 이름에 동의를 담는 규칙은 자산 탭의 repo 연결 버튼에 적용된다.
- **[작성자 요청]** 자산에서 분석을 확인하는 경로인 [내 자산에서 분석 보기]를 보조 버튼으로 함께 둔다. 팀장 결정은 이 상태의 CTA를 자산 GitHub 탭 하나로 적었고, 연결된 repo 기준상 이 상태의 회원에게는 접수된 분석이 없을 수 있다. 보조 버튼을 유지할지 문구로 줄일지는 §7.1의 질문이다.
- **[연결 제안]** 두 버튼 모두 자산 GitHub 탭으로 간다. 탭 안의 repo 연결 버튼·빈 상태·미연결 안내는 자산 담당 화면이다(PR #54 팀장 요청). repo 연결 버튼이 여는 선택·동의 화면 내부는 작성자(팀원 4) 영역이며 병합된 A-01 정리와 함께 다음 작업으로 남긴다.
- **[제안]** 저장소를 잠깐 클릭하거나 동의를 체크만 한 화면 상태는 연결된 repo로 보지 않는다. 분석 요청 접수가 확인된 저장소만 센다.

### 5.5 로그인 홈 — repo 연결 후

```text
+- H-01 서비스 홈 · 로그인 · repo 연결 후 · 12월 기준 -----------
| [CatchU 로고] [내 자산] [공유 링크] [채용공고] [알림] [프로필]
+----------------------------------------------------------------
|
| + 피드 ------------------------------------------------------
| | 피드 영역
| +------------------------------------------------------------
|
+----------------------------------------------------------------
```

- **[팀장 결정]** GitHub 연결과 연결된 repo가 모두 확인된 회원의 12월 홈에는 팔로우한 사람의 포스팅 피드를 두고, 팔로우한 사람이 없으면 팔로우가 많은 사람의 공개 포스팅을 보여 준다(12월 범위 보완 §2, PR #53 `25f94b0`). 위 그림은 이 12월 기준의 자리만 나타내며 게시물·팔로우·글쓰기·반응은 설계하지 않는다.
- **[작성자 요청]** 이 상태의 회원에게는 GitHub 연결·repo 연결 같은 초기 시작 안내를 반복하지 않는다. 자산·공유 링크 등은 공통 내비게이션으로 이동한다.
- **[제안]** 분석이 진행 중이거나 실패했다는 이유로 이 상태를 미루지 않는다. 분석 상태 상자·결과 요약도 두지 않는다.
- **설계 주석 [미정]:** 피드를 10월로 앞당긴 결정은 없다. 팀장은 10월의 이 상태 홈을 홈 담당이 제안하도록 요청했지만, 이번 판은 작성자 요청에 따라 10월 구성을 확정하지 않고 §7.2의 질문으로 남긴다. 10월 화면에 ‘피드 준비 중’ 문구나 빈 피드 상자를 둘지도 정하지 않는다.

### 5.6 피드·알림·채용공고의 적용 경계

**[팀장 결정]** 12월 범위 보완 §2(PR #53 `25f94b0`)에 따라 12월에는 로그인한 구직자의 홈에 팔로우 기반 포스팅 피드(팔로우한 사람이 없으면 팔로우가 많은 사람의 공개 포스팅)를 두고, 분석 완료·실패 안내는 헤더 알림에서 다룬다. **[회의 결정 #55]** 내비게이션에 [채용공고]·[알림]·[프로필] 진입점을 포함한다. **[작성자 요청]** repo 연결 후 회원의 홈은 피드 중심으로 둔다(§5.5).

이 문단은 화면 밖 설계 주석이다. **[미정]** 피드·알림·채용공고가 10월에 실제로 무엇을 여는지와 제공 시점은 범위 문서·#55와 맞춘다(§7.2). 홈 그림에는 피드 게시물·팔로우·글쓰기·반응, 알림 배지·목록, 채용공고 목록을 그리지 않는다. 시작 안내 영역(§5.3·§5.4)은 분석 상태·집계와 결합하지 않아 repo 연결 후 홈과 섞이지 않게 한다. 헤더 사용자 메뉴·로그아웃은 #51·#55, 피드 상세는 12월 요구사항 분석에서 정한다.

## 7. 다른 영역과 연결할 데이터·조건

다음은 정보의 의미이며 API 필드·엔드포인트·상태 enum이 아니다. **홈 최소 데이터 제안은 로그인 여부 조회 결과, 초기 설정 상태(GitHub 연결 여부·연결된 repo 유무와 각각의 조회 성공 여부), 각 화면으로의 진입 대상, 고정 소개·가상 예시 콘텐츠**다. 홈용 분석 목록·최근 요청·결과 참조·검토 수·불일치 수·공개 상태·원문·링크 비밀번호는 요청하지 않는다. 연결된 repo 유무는 분석 요청이 접수된 저장소가 있는지로 판단하지만, 홈은 분석 목록·상태를 받지 않는다(§7.1).

| 연결 상대 | 홈에 필요한 입력 | 전달·이동·경계 | 남은 질문 |
|---|---|---|---|
| 회원·프로필 (#20) | 로그인 유효 여부·조회 성공 여부, GitHub 연결 여부·조회 성공 여부, 프로필 GitHub 연결 진입 대상 | 비로그인 Google 시작 → 회원 흐름. [팀 합의] GitHub 연결 없이 로그인 홈 진입. [팀장 결정] 분석 요청 전 GitHub 연결, 연결 후 자산 GitHub 탭. [연결 제안] 표시 이름 저장 전이면 회원 입력을 거친 뒤 홈 | 실제 로그인·GitHub 연결 방식, 연결 취소·실패·만료와 복귀, 세션 만료 후 복귀. 회원 화면 상세는 해당 담당이 정함 |

## 8. v0.7 검토 순서와 AI-DLC 전달 시 확인점

이번 판은 §5.3~§5.5의 초기 설정 상태별 로그인 홈과 §7.1·§7.2의 질문을 검토한다. 비로그인 홈(§5.2)은 v0.6 구성을 유지한다. 작성자(팀원 4)는 화면 제안을 전달하고, 팀원 1과 연결 담당은 아래 항목을 확인한다. #22의 완료 판단·이슈 종료는 이 체크와 구분한다.

- 비로그인 방문자가 서비스 소개·가상 Catch·[Google로 시작하기]를 보고 시작할 수 있다. 가상 내용이 실제 처리 결과로 오해되지 않는다.
- 로그인 홈이 가입 시점이 아니라 GitHub 연결 여부와 연결된 repo 유무로 나뉘고, GitHub 연결만으로 repo 연결 후 홈을 보여 주지 않는다.
- 연결 전 홈은 프로필 GitHub 연결 → 자산 GitHub 탭 순서를, repo 연결 전 홈은 자산 GitHub 탭의 repo 연결과 분석 확인 경로를 안내하며, 홈에서 A-01로 직행하지 않는다.
- 연결된 repo가 분석 요청 접수 저장소 1개 이상(진행 중·실패 무관)으로 적용되고, 저장소 클릭·동의 체크만으로 세지 않으며 분석 완료가 조건으로 추가되지 않는다.
- 설정 상태 확인 중·조회 실패를 GitHub 미연결·repo 미연결로 단정하지 않는다.
- 피드는 12월로 표시되고, 10월 repo 연결 후 홈 구성은 확정처럼 표현되지 않고 §7.2의 질문으로 남는다.
- 홈에 분석 상태·최근 결과·결과 단위 검토 현황이 없고, 10월 상태·결과 확인은 A-02와 내 자산 GitHub 관련 탭에서 한다.
- 로그인 홈 내비게이션이 #55 구성과 맞고, 로그인 여부별 노출·로그아웃·[채용공고]·[알림]의 이동 대상은 #55·#51로 남는다.
- 홈 담당이 집계를 사용하지 않는다는 답변과 자산 담당의 Catch별 확인·공개 정책이 구분된다.
- Google 로그인·GitHub 연결·분석 동의는 별개이며 홈 이동만으로 분석·재요청·공개가 실행되지 않는다.
- 대표 없는 링크 진입, L03 → L01, 로고로 홈 복귀와 링크 목록·비밀번호를 홈에 보내지 않는 경계가 유지된다.
- 회원·자산·공유 링크·병합된 A-01의 상세 설계를 이 초안에서 바꾸지 않고, 필요한 연결 조건과 질문만 남긴다.

이 체크 항목은 문서 검토용이며 제품 실행·API 연결·접근성 테스트 통과를 뜻하지 않는다. AI-DLC 입력으로 재사용할 때는 채택한 배치, 근거 ID, 이번 결정이 대체한 범위와 남은 연결 조건을 함께 전달한다.
