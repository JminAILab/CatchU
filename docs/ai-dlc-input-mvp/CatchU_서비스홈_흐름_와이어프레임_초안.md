# CatchU 10월 MVP — 서비스 홈 흐름·와이어프레임 초안

> 지위: 팀 검토용 초안 v0.9 (2026-09-20). 팀원 1이 조율하는 AI-DLC에 전달할 참고 입력이며 공식 요구사항·설계·승인 기록이 아니다. 팀 결정·작성자 요청·화면 제안·미정을 구분한다.
> 대상: PC 웹의 비로그인 방문자와 로그인한 구직자. 이번 상세 범위는 로그인 여부와 GitHub·레포 연결 상태에 따른 홈이다.
> 표현: 상자·텍스트·버튼만 사용한다. 가상 Catch는 설명용 예시이며 실제 분석 결과가 아니다. 제품 코드·API 연결·완성 시각 디자인은 포함하지 않는다.

> 원작성자: leechaeah(팀원 4). 인계·후속 보완: csyg0616(팀원 3). 상태·인증 연결은 팀원 2, 결과 의미는 팀원 1과 대조한다. B 목록·결과·공개 계약은 담당 확정 전 최종 합의하지 않는다.
> 화면 단위: A-01·A-02·A-03의 탭 안 표현/별도 화면과 진입·복귀는 [#64](https://github.com/JminAILab/CatchU/issues/64) 미결이다. 기존 독립 화면 그림은 비교용 제안이며 별도 페이지·URL 확정으로 읽지 않는다.

PR #44 팀장 결정은 PR #46의 ‘홈 최근 분석 한 건’ 항목과 v0.4·v0.5의 홈 검토 현황 제안을 대체한다. PR #46의 ‘내 자산 GitHub 관련 탭에서 이전 분석을 찾는다’는 경로는 유지한다. 과거 판의 화면·표는 현행 본문에서 제거하고 §9의 이력과 git 판본으로 남긴다. 승인 요구사항·후속 입력 원본·AI-DLC 상태·승인 기록을 이 초안에서 수정하지 않는다.

다른 담당 영역의 연결 상대는 팀별 첫 작업 안내 §4를 따른다. 팀원 3의 후속 수정이 B 담당 확정이나 다른 영역의 상세 설계 승인을 뜻하지 않는다.

## 5. PC 홈 와이어프레임 [제안]

### 5.1 v0.9 공통 구성

- 비로그인 홈은 v0.6 구성(서비스 소개·가상 Catch·[Google로 시작하기])을 유지한다.
- **[팀 합의·회의 결정]** 로그인 홈은 **GitHub 연결 전 / 레포 연결 전 / 레포 연결 후** 세 표현으로 나눈다(후속 입력 「GitHub 연동·자산 탭 분석 경로」 병합, 9/16 오전 회의 #22). GitHub 연결만으로 레포 연결 후 홈을 보여 주지 않고 연결된 repo(분석 요청이 접수된 저장소 1개 이상, 진행 중·실패 무관)까지 확인한다. 분석 완료는 조건이 아니다.
- **[회의 결정]** 두 미연결 상태에서는 연결 안내 영역에 ‘GitHub 연결 — 레포 연결’ 두 단계를 함께 표시하고 현재 단계만 진하게 보여 준다. 안내는 텍스트 설명과 버튼으로 구성한다. 12월에는 안내 아래에 피드 영역이 함께 표시되며(§5.6), 10월 화면에는 피드를 두지 않는다.
- 홈에는 최근 분석 상자, 진행·완료·실패 상태, 결과 단위 검토 현황, 분석 조회 로딩·실패 표시를 두지 않는다. 로그인 여부·연결 상태 확인의 로딩·실패와는 구분한다.
- **[회의 결정 #55]** 로그인 내비게이션은 `[CatchU 로고] [내 자산] [공유 링크] [채용공고] [알림] [프로필]`이다. 전체 구성은 12월 기준이며 메뉴 나열 순서와 10월 표시 방식은 확정이 아니다. 로그인 여부별 노출·프로필·로그아웃 연결은 [#55](https://github.com/JminAILab/CatchU/issues/55)·[#51](https://github.com/JminAILab/CatchU/issues/51), 새 알림 숫자·DM 위치는 [#59](https://github.com/JminAILab/CatchU/issues/59)에서 정한다.
- `[[버튼]]`은 주 버튼, `[버튼]`은 보조 버튼, `**단계**`는 연결 안내에서 진하게 표시하는 현재 단계다. 상자·문구·강조 순서는 화면 제안이다.

가상 예시는 고정 설명 콘텐츠로 두며 실제 사용자·저장소·커밋 URL을 쓰지 않는다. 실제 Catch 4구획의 최종 레이아웃을 정하는 안이 아니며, 클릭·상세·저장·분석 실행 버튼은 없다. 비로그인 상태의 내비게이션 노출과 헤더 최종 구성은 #55·#51에서 맞춘다. [Google로 시작하기]는 회원 담당의 로그인 흐름으로 연결하며, OAuth를 홈에서 별도로 구현하는 안이 아니다.

### 5.3 로그인 홈 — GitHub 연결 전 (10월)

- **[회의 결정]** 연결 안내 영역에 **GitHub 연결 — 레포 연결** 두 단계를 함께 표시하고, 현재 단계만 진하게·나머지는 연하게 보여 준다. 안내는 텍스트 설명과 버튼으로 구성한다(9/16 오전 회의, #22). 그림에서 `**단계**`는 진한 표시를 뜻한다.
- **[팀 합의]** 10월 분석 요청 전에는 GitHub 연동이 필요하고, 미연동 사용자는 홈 → 프로필의 GitHub 연동 → 자산 GitHub 탭 → 레포 연결 순서로 진행한다(후속 입력 「GitHub 연동·자산 탭 분석 경로」, PR #53 병합).
- **[제안]** 주 버튼은 목적지를 드러내는 [프로필에서 GitHub 연결] 하나만 둔다. 회의에서 예로 든 ‘연결하러 가기’를 포함해 최종 문구는 미정이다.
- **[제안]** GitHub 연결 상태를 정상 조회해 ‘미연결’로 확인한 경우에만 이 화면을 보여 준다. 확인 중·조회 실패는 §6.2를 따른다.
- **[회의 결정·12월]** 12월에는 이 안내 아래에 피드 영역이 함께 표시된다(§5.6). 10월 화면에는 피드를 두지 않는다.
- **[연결 제안]** 연결 화면의 위치, 연결 취소·실패·만료 안내, 연결 성공 후 자산 GitHub 탭으로 돌아오는 방식은 회원·자산 담당(팀원 2)이 정한다. GitHub 연결만으로 저장소 소유·커밋 관계 검증이나 분석 동의가 완료되지 않는다.

### 5.4 로그인 홈 — GitHub 연결 후, 레포 연결 전 (10월)

```text
+- H-01 서비스 홈 · 로그인 · 레포 연결 전 (10월) ----------------
| [CatchU 로고] [내 자산] [공유 링크] [채용공고] [알림] [프로필]
+----------------------------------------------------------------
| GitHub 기록을 나의 경험으로 정리해 보세요.
|
| + 연결 안내 -------------------------------------------------
| | GitHub 연결 ─ **레포 연결**
| | 분석할 레포는 내 자산의 GitHub 탭에서 연결합니다.
| | 저장소 선택·동의·분석 요청을 그곳에서 한 번에 진행합니다.
| | [[내 자산에서 repo 연결]]
| +------------------------------------------------------------
|
| 결과 확인과 공개 선택은 별도입니다.
+----------------------------------------------------------------
```

- **[회의 결정]** 같은 두 단계 표시를 쓰되 현재 단계는 레포 연결이다(9/16 오전 회의, #22).
- **[팀 합의]** GitHub는 연결했지만 연결된 repo(분석 요청이 접수된 저장소)가 없으면 자산 GitHub 탭으로 보낸다. repo 연결은 자산 GitHub 탭에서 저장소 선택·분석 동의·분석 요청을 버튼 하나로 처리하며, 홈에서 저장소 선택으로 바로 가지 않는다(후속 입력 「GitHub 연동·자산 탭 분석 경로」, PR #53 병합).
- **[제안]** 주 버튼은 [내 자산에서 repo 연결] 하나이며 이동만 한다. 홈에서 저장소를 고르거나 동의·요청을 받지 않는다. 버튼 이름에 동의를 담는 규칙은 자산 탭의 repo 연결 버튼에 적용된다.
- **[제안]** v0.7에 두었던 보조 버튼 [내 자산에서 분석 보기]는 뺐다. 같은 자산 GitHub 탭으로 가는 중복 경로였고, 연결된 repo 기준상 이 상태에는 접수된 분석이 없기 때문이다. 분석 확인 경로는 내비게이션의 [내 자산]과 레포 연결 후 홈(§5.5)에 둔다.
- **[회의 결정·12월]** 12월에는 이 안내 아래에도 피드 영역이 함께 표시된다(§5.6). 10월 화면에는 피드를 두지 않는다.
- **[연결 제안]** 탭 안의 repo 연결 버튼·빈 상태·미연결 안내는 자산 담당 화면이다(PR #54 팀장 요청). repo 연결 버튼이 여는 선택·동의 화면 내부는 인계 담당 팀원 3의 D 영역이며 병합된 A-01 정리와 함께 다음 작업으로 남긴다.
- **[제안]** 저장소를 잠깐 클릭하거나 동의를 체크만 한 화면 상태는 연결된 repo로 보지 않는다. 분석 요청 접수가 확인된 저장소만 센다.

아래는 v0.8의 두 상자 비교안이다. 원작성자는 제외 의견을 남겼으나 팀의 삭제·대체 결정은 없다([#22 의견](https://github.com/JminAILab/CatchU/issues/22#issuecomment-5729552628)). 현재 그림을 확정 화면으로 채택하지 않으며 대체 구성은 §7.2에서 검토한다. 이번에는 첫 MVP 이후인 대표 구성 문구만 제거한다.

### 5.6 12월 기준 로그인 홈과 피드 방향 [12월]

아래는 **12월 기준 참고 그림**이며 10월 구현 범위가 아니다. 10월 화면은 §5.3~§5.5를 따른다.

```text
+- H-01 로그인 홈 · 12월 기준 (참고) ----------------------------
| [CatchU 로고] [내 자산] [공유 링크] [채용공고] [알림] [프로필]
+----------------------------------------------------------------
| + 연결 안내 (미연결 상태에서만) -----------------------------
| | GitHub 연결 ─ 레포 연결        [[연결하러 가기]]
| +------------------------------------------------------------
|
| + 피드 ------------------------------------------------------
| | 팔로우 기반 공개 포스팅이 이어집니다(선정 기준은 아래 참조).
| | (무한 스크롤. 최상단 이동 버튼은 두지 않음)
| +------------------------------------------------------------
+----------------------------------------------------------------
```

- **[회의 결정]** GitHub 미연결·레포 미연결 화면에도 안내 아래에 피드 영역을 함께 표시한다. 피드는 무한 스크롤을 전제로 하며 별도의 최상단 이동 버튼을 두지 않는다. 홈 이동은 #55의 로고 클릭으로 하고 상단 홈 메뉴를 되살리지 않는다(9/16 오전 회의, #22).
- **[팀 합의]** 12월에는 로그인한 구직자의 홈에 팔로우 기반 포스팅 피드를 두고, 팔로우한 사람이 없으면 팔로우가 많은 사람의 공개 포스팅을 보여 준다([12월 범위 보완](https://github.com/JminAILab/CatchU/blob/d70d33a8da916a12611ccf659d07812c2f2a8913/docs/ai-dlc-input-december/CatchU_12월_범위_보완.md) §2, PR #53 병합).

**[작성자 제안·미채택] 기존 피드 의견 — 위 팀 합의의 대체 기준이 아님:**

```text
팔로우한 사람이 있음
→ 팔로우한 사람들의 글을 보여줌

팔로우한 사람이 없음
→ 유명한 사람들의 글이나 인기 있는 글을 보여줌
```

- 유명한‘유명한 사람’·‘인기 있는 글’의 선정 기준과 정렬 기준은 정하지 않는다. 팔로우한 사람은 있지만 그 사람들의 게시물이 없는 경우에 무엇을 보여 줄지도 별도 질문으로 남긴다(§7.2).
- 유명한피드 상단 필터는 미정이다. 필터를 도입해 스크롤 중 사라지는 구조가 되면 최상단 이동 버튼을 다시 검토할 수 있다(9/16 오전 회의).
- 이 절은 12월 설계 설명이다. 10월 화면에는 피드 영역·게시물·팔로우·글쓰기·반응을 그리지 않는다.

### 5.7 알림·채용공고의 적용 경계

**[회의 결정 #55]** 내비게이션에 [채용공고]·[알림]·[프로필] 진입점을 포함한다. 전체 구성은 12월 기준이며 10월에 채용공고·알림을 어떻게 표시할지는 미결이고 메뉴 나열 순서도 확정이 아니다(9/16 오전 회의). **[팀 합의]** 분석 완료·실패 안내는 12월 헤더 알림에서 다룬다(12월 범위 보완 §2, PR #53 병합).

이 문단은 화면 밖 설계 주석이다. 유명한채용공고·알림이 10월에 무엇을 여는지와 표시 방식은 #55·범위 문서와 맞춘다(§7.2). 홈 그림에는 알림 배지·목록과 채용공고 목록을 그리지 않는다. 새 알림 숫자 표시·DM 위치 등 세부는 #59, 프로필 모달과 알림 설정 진입은 #51에서 정하며 홈 초안은 연결만 남긴다.

## 7. 다른 영역과 연결할 데이터·조건

### 7.1 연결된 repo 판단 — 확인 결과와 질문 링크

**확인한 기준:**

- **[팀 합의]** [후속 입력 «GitHub 연동·자산 탭 분석 경로»](https://github.com/JminAILab/CatchU/blob/d70d33a8da916a12611ccf659d07812c2f2a8913/docs/ai-dlc-input-mvp/2026-09-14_followup.md)(PR #53 병합): 연결된 repo는 분석 요청이 접수된 저장소가 1개 이상인 경우이며 진행 중·실패 여부와 무관하다. 홈은 GitHub 연결 여부와 연결된 repo 유무만 확인하고 분석 상태·결과를 조회하지 않는다. 9/16 오전 회의도 이 기준을 유지했다(#22).
- 병합된 A-01 초안 §5: 저장소 선택만으로 분석을 요청하지 않고, 동의 체크를 기록하는지와 기록 시점은 미정이다(OQ11, #24). 선택·체크만으로는 연결된 repo가 생기지 않는다.
- 회원·자산 초안 v0.9 W03에는 별도의 ‘저장소 설정’ 저장 항목이 없다.

**적용:** 작성자 요청의 ‘저장소 설정 완료’는 팀 합의의 ‘연결된 repo 있음’으로 읽는다. 잠깐 저장소를 클릭하거나 동의를 체크만 한 상태, 요청 전송 후 접수가 확인되지 않은 상태는 포함하지 않는다. 분석 완료나 결과 존재는 조건이 아니다. 조회 중·조회 실패는 ‘연결된 repo 없음’으로 보지 않는다(§6.2).

## 8. v0.9 검토 순서와 AI-DLC 전달 시 확인점

이번 판은 §5.3~§5.6의 상태별 홈과 §7.2의 질문을 검토한다. 비로그인 홈(§5.2)은 v0.6 구성을 유지한다. 인계 담당 팀원 3은 수정안을 작성하고 팀원 2(A/E)와 먼저 연결을 확인한다. 결과 의미는 팀원 1(F)과 대조하고 B 최종 계약은 담당 확정 전 보류한다. #22의 완료 판단·이슈 종료는 이 체크와 구분한다.

- 비로그인 방문자가 서비스 소개·가상 Catch·[Google로 시작하기]를 보고 시작할 수 있다. 가상 내용이 실제 처리 결과로 오해되지 않는다.
- 로그인 홈이 GitHub 연결 여부와 연결된 repo 유무로 나뉘고, 연결 안내에 ‘GitHub 연결 — 레포 연결’ 두 단계가 함께 보이며 현재 단계만 진하다.
- 연결 전 홈은 프로필의 GitHub 연결로, 레포 연결 전 홈은 자산 GitHub 탭의 repo 연결로 보낸다. 홈에서 A-01로 직행하지 않고 같은 탭으로 가는 중복 버튼도 없다.
- 레포 연결 후 홈(§5.5)이 초기 설정 안내를 반복하지 않고 자산 확인·관리로 이어지며, 분석 상태·결과 상자와 검토 현황 집계, 빈 피드 상자가 없다.
- 피드는 12월 기준으로만 그려지고(§5.6) 10월 화면에 추가되지 않는다. 피드 표시 방향은 작성자 제안이며 선정·정렬 기준과 게시물 없는 경우는 미정으로 남는다.
- 연결 상태 확인 중·조회 실패를 GitHub 미연결·레포 미연결로 단정하지 않는다.
- 연결된 repo가 분석 요청 접수 저장소 1개 이상(진행 중·실패 무관)으로 적용되고, 저장소 클릭·동의 체크만으로 세지 않으며 분석 완료가 조건으로 추가되지 않는다.
- 내비게이션이 #55 구성과 맞고, 10월 채용공고·알림 표시와 메뉴 순서·로그인 여부별 노출·알림 숫자·DM 위치는 #55·#51·#59로 남는다.
- Google 로그인·GitHub 연결·레포 연결·분석 동의가 구분되고, 홈 이동만으로 분석·재요청·공개가 실행되지 않는다.

- 회원·자산·링크·병합된 A-01의 상세 설계를 이 초안에서 바꾸지 않고, 필요한 연결 조건과 질문만 남긴다.

이 체크 항목은 문서 검토용이며 제품 실행·API 연결·접근성 테스트 통과를 뜻하지 않는다. AI-DLC 입력으로 재사용할 때는 채택한 배치, 근거 ID, 이번 결정이 대체한 범위와 남은 연결 조건을 함께 전달한다.
