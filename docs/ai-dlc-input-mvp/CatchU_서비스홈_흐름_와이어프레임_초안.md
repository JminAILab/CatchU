# CatchU 10월 MVP — 로그인 후 서비스 홈 흐름·와이어프레임 초안

> 지위: 팀 검토용 초안 v0.4 (2026-09-15). 팀원 1이 조율하는 AI-DLC에 전달할 참고 입력이며 공식 요구사항·설계·승인 기록이 아니다. 배치 선택은 비교·검토용 한 벌이며 최종 정책 확정이 아니다(§9).
> 대상: PC 웹의 로그인한 구직자. 담당 범위는 사용자가 밝힌 서비스 홈·분석 화면 프론트엔드이며, 이번 상세 범위는 로그인 후 홈이다.
> 표현: 상자·텍스트·버튼만 사용한다. 아래 화면과 예시는 실제 분석 결과가 아니며, 제품 코드·API 연결·완성 시각 디자인은 포함하지 않는다.

다른 팀원 영역은 MVP 입력 §2.5의 **담당 제안**을 기준으로 연결 상대를 표시한다. 사용자의 담당 영역 외에 팀 전체 배정이 확정됐다는 뜻은 아니다.

**이미 정해진 10월 정책:** 실패 후 사용자가 재요청할 때만 재시도하며 자동 재시도는 하지 않는다(MVP 입력 OQ1). 링크 비밀번호는 발행 시에만 설정하고, 중단·만료 URL은 재활성화하지 않으며 필요하면 새 URL을 발행한다(OQ4). 이 정책들은 이번 화면 검토에서 다시 선택할 항목이 아니다.

**미정 정책 요약:** 선정 저장소와 한도·중복 판정·부분 성공 처리(OQ1), 원본 상태 확인과 본인 자료 보관·복구(OQ2), 결과·본문·프로필 버전과 표시 상세(OQ3), 동의 수집 방식·외부 처리 안내(OQ11), 운영 중단이 진행 중 작업에 미치는 영향(OQ13), 대기·실패 판정 시간과 접근성 기준(OQ14). 동의를 저장소 선택에서 받는 안은 입력 문서에서도 아직 제안이다.

목록 밖 저장소 입력·미지원 분류 UI, JD, 기업 검색·제안·DM, 자기소개서·포트폴리오, 복수 프리셋, 서술 오류 재생성은 10월 홈에 추가하지 않는다.

## 4. 첫 사용자 흐름 제안

```text
[회원 영역: 로그인 성공]
    → [H-01 홈]                       로그인 후 도착 위치는 제안
        ├─ [저장소 선택]
        │    → [A-01 선정 저장소 확인 + 분석 동의]   배치는 제안
        │         ├─ 미동의 → 분석 실행 안 함
        │         └─ 동의·허용 조건 충족 → [분석 요청]
        │              ├─ 접수 확인 → [A-02 진행 상태]
        │              ├─ 같은 요청이 이미 진행 중 → 기존 상태 연결 [제안]
        │              └─ 접수 여부 불명 → 상태 확인 안내 [제안]
        │                   (분석 실패로 단정하거나 자동 재요청하지 않음)
        │
        │    [A-02 진행 상태]
        │         ├─ 완료·확인 가능한 결과 있음 → [결과 확인]
        │         │    → [내 자산: 경험 후보·근거·질문·Catch 초안 확인]
        │         │         ├─ 확인만 완료 → 자동 공개 안 함
        │         │         └─ 별도 공개 선택 (‘지금 공개’ 기본 제안)
        │         └─ 실패 → [A-03 실패 안내]
        │              └─ [다시 분석 요청] → 허용 조건 확인 → 접수 후 A-02
        │                   (사용자 실행만 허용, 기존 자료·링크 보존)
        │
        ├─ 재방문: 완료된 결과의 검토 현황 [연결 제안]
        │    ├─ 검토 전·일부 검토 → [결과 확인] → 같은 결과
        │    └─ 전체 검토 → [결과 다시 보기] → 같은 결과
        │         (이동만으로 검토·공개 상태를 바꾸지 않음)
        │
        └─ 상단 메뉴 [제안]
             ├─ [내 자산] → 본인 자산 확인·공개·숨김·불일치 표시 영역
             ├─ [대표 구성] → 대표 주장 1개 + Catch 2~3장 구성 영역
             └─ [공유 링크] → 링크 관리 → 발행 준비 [연결 제안] → 전달한 URL → 비로그인 수신자 열람
                  ↑ 대표 구성을 먼저 완료해야만 진입하는 순서로 묶지 않음
```

완료 결과 0건·부분 성공은 아래 상태 표의 정책 확인 대상으로 남긴다. 다른 영역에서 홈으로 돌아오는 공통 이동은 제안이며, 실제 경로와 돌아올 때 상태 갱신 방식은 함께 맞춘다. 홈을 다시 열어도 분석 요청 자체가 재실행되는 동작은 넣지 않는다.

## 5. PC 홈 와이어프레임 — 첫 방문과 재방문 비교 [제안]

### 5.1 공통 구성

v0.3은 v0.2의 **위쪽 메뉴만 + 최근 분석 한 건** 안을 유지하면서, 팀원 1의 PR #28 리뷰 의견에 따라 **분석 이력이 있는 재방문 화면의 강조 순서**를 바꾼다.

- **상단 메뉴:** [홈]·[내 자산]·[대표 구성]·[공유 링크]. 모든 상태에서 같은 위치·항목으로 둔다. 자산 수·대표 완성도·분석 상태로 메뉴를 숨기거나 막지 않는다(FR3.1·FR3.2).
- **첫 방문(분석 이력 0건):** v0.2 배치를 유지한다. 분석 안내 + [저장소 선택]이 주 영역이고, 최근 분석 상자는 빈 상태로 아래에 둔다.
- **재방문(분석 이력 1건 이상):** **최근 분석 상자를 메뉴 바로 아래 맨 위**에 두고 그 상태의 행동을 주 버튼으로 둔다. 새 분석 시작 영역과 [저장소 선택]은 상자 아래 **보조 버튼**으로 낮춘다.
- [저장소 선택]은 어느 위치에서든 A-01로 이동만 하며 분석을 실행하지 않는다(FR1.1).
- **검토 현황 (v0.4, [연결 제안]):** 분석이 완료된 최근 분석 상자에는 결과별 검토 현황(검토 전·일부 검토·전체 검토)을 보여 준다. 세는 규칙과 숫자 표시는 자산 담당과 맞출 연결 제안이다(§5.5).

표기: 굵은 선 상자(┏ ┃ ┗)는 강조 영역, `[[버튼]]`은 주 버튼, `[버튼]`은 보조 버튼이다. 실제 시각 표현은 정하지 않는다.

아래 화면은 서로 다른 상태의 예시이며 한 분석이 동시에 여러 상태라는 뜻이 아니다. `[예시] example-user/demo-repo`는 임시 표시값이며 실제 선정 저장소·처리 결과가 아니다. 표시 이름 저장 후 홈에 도착하는 분기 등 회원 영역의 진입 조건은 회원·자산 초안의 연결 제안이며 연결 확인이 필요하다(§7).

### 5.5 재방문 — 완료, 검토 현황 [연결 제안]

**홈 담당 선호안 — 자산 담당과 맞출 연결 제안.** 회원·자산 초안 §5.2가 다음 판 기본 검토안으로 둔 ‘검토 처리됨’ 집계를 홈 담당이 선호안으로 택했다. 자산 담당(#20)과 합의하기 전까지 확정이 아니며, 세는 규칙과 숫자 표시는 모두 연결 제안이다.

- **세는 규칙:** 한 결과 범위 안의 Catch마다 ‘확인 완료’ 또는 ‘불일치 표시’ 기록이 **정상 저장**됐으면 검토한 Catch로 센다. 두 기록이 모두 있어도 **한 번만** 센다. 저장 중·저장 실패, 화면을 열거나 스크롤한 것만으로는 세지 않는다. 공개·숨김 여부는 세는 수에 영향을 주지 않는다.
- **판정 조건:** 같은 결과 범위의 대상 수(N)와 검토 기록을 **정상적으로 확인한 경우에만** 판정한다. 검토 전은 N ≥ 1이고 검토한 수(K) = 0, 일부 검토는 0 < K < N, 전체 검토는 N ≥ 1이고 K = N이다.
- **불일치 표시 수:** 정상 조회된 불일치 표시 수가 **1장 이상일 때만** 따로 보여 준다. 조회 실패·집계 대기를 0장으로 처리하지 않는다.
- **표현:** 홈에서는 ‘확인 완료’ 대신 ‘검토 현황’으로 표현한다. ‘검토’는 사용자가 확인 완료 또는 불일치 표시를 한 상태를 뜻하며, 불일치를 표시한 Catch도 검토한 Catch에 포함된다. **전체 검토는 내용의 정확성·오류 해결·공개 완료를 뜻하지 않는다.**
- **분석 완료와 구분:** A-02의 ‘분석 완료’는 분석 처리가 끝났다는 상태이고, 검토 현황은 완료된 결과에 대한 사용자 행동의 집계다. 홈은 분석이 완료된 결과에만 검토 현황을 보여 준다.

- **[제안]** 일부 검토에서도 주 버튼은 [결과 확인]을 유지하고, 전체 검토에서는 [결과 다시 보기]를 둔다. 두 버튼 모두 이 분석의 같은 결과로 연결하며, 이동만으로 검토·공개 상태를 바꾸지 않는다.
- **[제안]** 불일치 표시가 정상 조회로 0장이면 ‘불일치 표시’ 줄을 보여 주지 않는다. 위 예시의 수는 모두 임시 값이다.
- 검토할 Catch 없음(정상 조회로 대상 0장)·검토 현황 조회 실패·집계 대기는 §6.2에서 다루며, 어떤 경우도 전체 검토로 표시하지 않는다.
- **검토 현황과 공개 여부는 구분한다.** 홈은 이 상태에서 공개 여부를 표시하거나 추정하지 않는다. 공개 선택·숨김은 자산 영역에서 다룬다(FR4.1).
- **[연결 제안·질문]** 회원·자산 초안은 결과의 Catch 식별 정보를 넘겨 Catch 상세(W04)로 여는 안을 두었다. 결과에 Catch가 여러 장일 때 [결과 확인]·[결과 다시 보기]가 여는 화면은 질문으로 남긴다(§7).
- **[미정]** 표시 취소 시 집계, 재분석·Catch 추가·내용 변경 시 집계 범위와 기존 기록을 이어갈지, 결과 범위·판본, 집계 주체·홈 갱신 시점, 중복·열람 제한 Catch 처리(§5.8).

### 5.7 상태 비교

| 상태 | 맨 위 영역 | 최근 분석 상자 문구 [제안] | 주 버튼 → 이동 | [저장소 선택] |
|---|---|---|---|---|
| 첫 방문 | 분석 안내 | 아직 요청한 분석이 없습니다 | [저장소 선택] → A-01 | 주 행동 (v0.2 유지) |

| 재방문·완료(검토 전) | 〃 | 저장소명 + 완료 안내 + 확인·공개 분리 안내 | [결과 확인] → 해당 결과 | 〃 |

첫 방문은 조회에 성공해 이력 0건이 확인된 경우만 해당한다. 조회 중·조회 실패, 검토할 Catch 없음, 검토 현황 조회 실패·집계 대기는 §6.2 상태 표에서 다루며 전체 검토로 표시하지 않는다.

### 5.8 미정 사항

- **[미정] 최근 한 건의 선정 기준:** 가장 마지막에 요청한 분석인지, 진행 중 분석을 우선 표시하는지 등. 분석 처리 조율(팀원 1)과 맞춘다(§7).
- **[미정] 이전 작업을 다시 찾는 경로:** 최근 한 건에 가려진 이전의 진행 중·실패 작업을 사용자가 어디서 다시 확인할지. 여러 건 이력을 보여주는 것과 여러 분석을 동시에 실행하는 것은 별개의 문제로 다룬다. 홈에 이력 목록을 추가하는 안도 이번 비교에서 확정하지 않는다.
- **[연결 제안] 검토 현황의 세는 규칙과 숫자 표시:** §5.5의 홈 담당 선호안(확인 완료 또는 불일치 표시가 정상 저장된 Catch를 한 번씩 세는 ‘검토’ 집계, 같은 결과 범위를 정상 조회한 경우에만 판정). 회원·자산 초안 §5.2와 맞춰 자산 담당(#20)과 합의한다(§7).
- **[미정] 표시 취소·재분석·집계 범위:** 확인 완료나 불일치 표시를 취소했을 때의 집계, 재분석·Catch 추가·내용 변경 시 집계 범위와 기존 기록을 이어갈지, 결과 범위·판본, 누가 집계하고 언제 홈에 갱신할지, 중복 Catch·열람 제한 Catch의 처리.
- **[미정] 결과 목적지:** 결과에 Catch가 여러 장일 때 [결과 확인]·[결과 다시 보기]가 여는 화면(§7).

## 6. 버튼 동작과 빈 상태·로딩·실패

### 6.1 홈 버튼 명세 [제안]

| 버튼 | 동작·이동 대상 | 조건·주의 |
|---|---|---|
| 홈 | H-01로 이동하고 허용된 최신 상태 조회 | 조회가 분석 요청을 발생시키지 않음 |
| 저장소 선택 | A-01로 이동 | 첫 방문은 주 행동, 재방문은 최근 분석 상자 아래 보조 버튼. 분석 실행 버튼과 구분. 신규 분석 중단 확인 시 비활성·사유 안내 제안. 다른 저장소 분석 가능 여부는 동시 요청 정책에 따름 |
| 진행 상태 보기 | 해당 분석의 A-02 | 분석 식별자를 전달. 같은 저장소의 새 분석을 생성하지 않음 |
| 결과 확인 | 해당 결과에 연결된 자산 영역 화면 | 검토 전·일부 검토 결과에 표시. 결과 식별자·본인 권한 필요. 이동만으로 확인 완료·불일치 표시·공개 처리하지 않음. 여는 화면은 연결 질문(§7) |
| 결과 다시 보기 | 전체 검토한 같은 결과에 연결된 자산 영역 화면 | 전체 검토 결과에 표시. 결과 식별자·본인 권한 필요. 이동만으로 검토·공개 상태를 바꾸지 않음. 여는 화면은 연결 질문(§7) |
| 실패 내용 보기 | 해당 실패 분석의 A-03 | 재요청은 A-03의 명시적 버튼에서 실행. 자동 재시도 없음 |
| 내 자산 (상단 메뉴) | 본인 자산 확인·관리 영역 | 신규 분석 실패·중단 중에도 접근 가능한 기존 자료 유지 |
| 대표 구성 (상단 메뉴) | 대표 주장·Catch 구성 영역 | 이동만으로 기존 링크의 대표 문구·구성이 바뀌지 않음 |
| 공유 링크 (상단 메뉴) | 링크 관리 화면 → 발행 준비([연결 제안], 공유 링크 초안 §6.3 수용안) | 대표 완성 여부로 진입을 막지 않음. 버튼 클릭 자체는 링크 발행이 아님. ‘대표 없이도 발행 가능’ 안내는 홈에 두지 않고 링크 영역에 두는 안을 팀원 3에게 전달(§7) |
| 상태 다시 불러오기 | 최근 분석 상자의 실패한 상태 조회만 재실행 | 분석 재요청·새 AI 호출 버튼과 구분. 반복 클릭 시 분석 요청이 생기지 않음 |
| 로그인으로 이동 | 인증 영역으로 이동(기본 로그인은 Google OAuth — [팀 합의]) | 세션 만료 안내용 제안. 회원·자산 초안은 홈에서 만료되면 재인증·표시 이름 조회 후 홈으로 돌아오는 안을 [연결 제안]으로 두었다. 복귀 위치·계약은 회원 담당과 확인 |
| 관련 자산 안내 보기 | 원본 비공개 확인의 영향·대응 안내 영역 | 구체 목적지·본인 열람 정책은 OQ2 및 자산 담당과 확인 |

### 6.2 상태별 표시와 행동

표의 문구·배치·버튼은 제안이며, ‘유지할 규칙’은 근거 ID를 따른다.

| 상황 | 표시·행동 제안 | 유지할 규칙·미정 |
|---|---|---|
| 분석 이력 없음 | 첫 방문 배치. ‘아직 요청한 분석이 없습니다’ + [저장소 선택] | 조회가 성공해 0건임이 확인된 경우만 빈 상태로 표현 |
| 상태 조회 중 | 최근 분석 상자 위치에 ‘분석 상태를 불러오는 중입니다’, [저장소 선택]은 상자 아래 | ‘분석 중’과 구분. 이력 유무를 모르므로 첫 방문 배치로 단정하지 않는 안. 확인 전 새 요청 가능 여부를 추정하지 않음 |
| 상태 조회 실패 | 최근 분석 상자 위치에 ‘분석 상태를 불러오지 못했습니다. 잠시 후 다시 불러와 주세요.’ + [상태 다시 불러오기]. 상단 메뉴와 [저장소 선택]은 그대로 표시 | 분석 작업 자체가 실패했다고 표시하지 않고 첫 방문 빈 상태로도 대체하지 않음. 완료·결과 존재를 알 수 없으므로 [결과 확인]·[결과 다시 보기]·[결과 보기]를 표시하지 않음. [상태 다시 불러오기]는 조회만 재실행하며 분석을 재요청하지 않음. 홈 전체를 실패 화면으로 대체하지 않는 안. 자동 재조회 여부·간격은 미정(OQ14) |
| 최근 한 건 밖의 진행 중·실패 작업 | 이번 비교안에서는 홈에 표시하지 않음 | 선정 기준과 다시 찾는 경로 미정(§5.8). 표시하지 않는다고 해당 작업이 사라지거나 중단된 것으로 안내하지 않음 |
| 접수 응답 불명 | ‘요청 접수 여부를 확인하고 있습니다’ + 상태 조회 경로 | 자동 제출 반복 금지. 요청 식별·중복 처리 계약 필요(OQ1) |
| 분석 진행 중 | 재방문 배치. 저장소·‘분석 진행 중’ + [진행 상태 보기] | 같은 진행 중 요청 중복 금지. UI 비활성만으로 서버 중복 방지 완료로 간주하지 않음(FR1.4) |
| 완료·검토 전 | 재방문 배치. 완료 안내 + [결과 확인] | 자동 공개 금지(FR2.2·FR4.1). **[연결 제안]** 같은 결과 범위의 대상 수(1장 이상)와 검토 기록을 정상 조회해 검토한 Catch가 0장일 때만 |
| 완료·일부 검토 | 재방문 배치. ‘검토 현황: 일부 검토 · N장 중 K장’ + 불일치 표시 수(정상 조회 값이 1장 이상일 때) + [결과 확인] | **[연결 제안]** 대상 수·검토 기록을 정상 조회했고 0 < K < N일 때만. 세는 규칙은 §5.5 |
| 완료·전체 검토 | 재방문 배치. ‘검토 현황: 전체 검토 · N장 모두’ + 불일치 표시 수(1장 이상일 때) + ‘전체 검토는 내용 확정·오류 해결·공개를 뜻하지 않습니다’ + [결과 다시 보기] | **[연결 제안]** 대상 수·검토 기록을 정상 조회했고 N ≥ 1, K = N일 때만. 내용의 정확성·오류 해결·공개 완료가 아님. 홈에서 공개 여부를 추정하지 않음(FR4.1) |
| 완료·검토할 Catch 없음 | 재방문 배치. ‘이번 분석에서 검토할 Catch가 없습니다’ 제안 | 정상 조회로 대상이 0장일 때. **전체 검토로 표시하지 않음.** 0건이 정상 완료가 될 수 있는지부터 확인(OQ1·OQ3). A-02의 ‘완료·결과 0건’과 같은 경우인지 연결 질문. 사용자 역량 부족으로 판정하거나 무조건 재요청을 권하지 않음 |
| 완료·검토 현황 조회 실패 | 재방문 배치. ‘검토 현황을 불러오지 못했습니다’ + [결과 보기] | **적용 조건:** 분석 완료와 볼 수 있는 결과의 존재가 조회로 확인되고 대상 수·검토 기록만 불러오지 못한 경우. 분석 상태 자체를 불러오지 못하면 ‘상태 조회 실패’ 행을 따른다. 검토 전·일부·전체로 단정하지 않고 불일치 표시를 0장으로 보여 주지 않음 |
| 완료·검토 현황 집계 대기 | 재방문 배치. ‘검토 현황을 준비하고 있습니다’ + [결과 보기] | 조회 실패와 구분. 검토 전·일부·전체로 단정하지 않고 불일치 표시를 0장으로 보여 주지 않음. 대기 판정 방식은 미정 |
| 분석 실패 | 재방문 배치. 실패 안내 + [실패 내용 보기], 기존 자료 경로 유지 | 실패 유형별 안내·허용 재요청 조건 미정. 기존 자료·링크 보존, 사용자 재요청 지원(FR1.4, 입력 OQ1) |
| 일부 결과 후 실패 | 실패 안내, 기존 자료·링크 유지 | 새 부분 결과를 완료 결과로 노출할지·재사용할지는 미정(OQ1). 임의로 완료 건수·결과 확인 버튼을 붙이지 않음 |
| 신규 처리 중단 | ‘현재 새 분석을 시작할 수 없습니다’ + 사유, 기존 자산·링크 경로 유지 | 실제 중단 범위에 맞춰 표시(FR10.4). 신규 AI 호출만 중단된 경우의 분석 접수 여부·진행 중 작업 처리는 OQ13 |
| 선정 목록 없음·접근 조건 변경 | A-01에서 제공 불가·확인 필요 사유 안내. 홈에도 표시할지는 제안 | 목록 밖 URL 입력으로 우회하지 않음. 선정 후 삭제·권한 변경 등의 안내 계약 필요(OQ1·OQ2) |
| 원본 비공개 전환 확인 | 관련 Catch 열람 제한의 원인과 [관련 자산 안내 보기] | 관계없는 링크 전체를 중단하지 않음. 일시적 조회 실패를 비공개로 단정하지 않음(FR1.5). 복구 행동·본인 열람은 OQ2 |
| 로그인 세션 만료 | 본인 자료 표시 중지·로그인 안내 + [로그인으로 이동] | 인증·복귀 방식 제안. 홈에서 만료 시 재인증·표시 이름 조회 후 홈 복귀는 회원·자산 초안의 [연결 제안]. 비로그인 수신자 링크 경로와 구분(NFR1) |

빈 상태와 조회 오류를 서로 대체하지 않고, 분석 실패와 운영 중단이 함께 있으면 재요청 제한의 사유도 함께 표시한다. 구체 상태 우선순위·동시 작업 표시 기준은 서버 상태 계약과 함께 정한다.

## 7. 다른 영역과 연결할 데이터·조건

다음은 화면에 필요한 **정보의 의미**이며 승인된 API 필드·엔드포인트·상태 enum이 아니다. 홈에 필요한 요약만 받고 상세 내용은 대상 영역에서 다루는 안이다.

| 연결 상대 | 홈·분석 프론트엔드에 필요한 입력 | 전달하거나 보장할 출력·경계 | 합의할 내용 |
|---|---|---|---|

홈 최소 데이터 제안은 로그인 상태, 분석 이력 유무, 최근 분석의 식별자·저장소명·처리 상태·결과 참조·실패 안내, 결과별 검토 현황(대상 수·검토 수·불일치 수·조회 성공·집계 대기 여부, [연결 제안]), 신규 처리 허용 상태, 영역별 이동 대상이다. 공개 여부는 홈 표시 데이터로 요구하지 않는다. Catch 본문·GitHub 원문·공유 링크 비밀번호·LLM 비용·호출 토큰은 이 홈 초안의 표시 데이터에 포함하지 않는다.

## 8. 검토 순서와 AI-DLC 전달 시 확인점

v0.4에서는 §5의 첫 방문·재방문 비교안과 완료된 결과의 검토 현황(§5.5, 자산 담당과 맞출 연결 제안)을 검토한다. 검토 결과에 따라 H-01의 상태별 문구·버튼을 다듬고, A-01 → A-02 → A-03 순으로 담당 화면의 와이어프레임을 확장하는 안이다. §5.8의 미정 중 최근 한 건·이전 작업 경로는 팀원 1에게, 검토 현황의 세는 규칙·숫자 표시와 결과 목적지는 자산 담당(팀원 2)에게, 링크 안내 위치 제안은 팀원 3에게 전달한다. §7의 정책·데이터 합의는 구현 연결 전에 팀원 1과 관련 담당에게 전달한다. 이 문서의 미정 목록은 이번에 사용자에게 한꺼번에 답변을 요구하는 질문지가 아니다.

초안 검토 기준:

- 첫 방문자가 저장소 선택 위치와 동의 후 분석이라는 순서를 이해할 수 있다.
- 재방문자가 새 분석 시작보다 현재 분석의 상태와 해당 행동을 먼저 볼 수 있다.
- 재방문자가 진행 중·완료(검토 전·일부 검토·전체 검토)·실패·조회 오류를 구분하고 다음 화면으로 갈 수 있다.
- 전체 검토가 내용의 정확성·오류 해결·공개 완료로 읽히지 않고, 검토 현황과 공개 여부가 섞이지 않는다.
- 검토할 Catch 없음·검토 현황 조회 실패·집계 대기가 전체 검토나 불일치 0장으로 표시되지 않는다.
- 기본 Google OAuth 로그인·GitHub 연결 없는 홈 진입·‘발행’ 용어는 팀 합의로, 프로필 수정·복귀·결과 목적지·검토 현황 집계는 연결 제안이나 질문으로 구분된다.
- 분석 실패가 기존 자료·링크 손실이나 자동 재시도로 이어지지 않는다.
- 결과 확인과 공개 선택이 분리되고, 대표 없이 링크 발행으로 이동할 수 있다.
- 빈 상태·로딩·실패·운영 중단·원본 비공개의 의미가 구분된다.
- 다른 담당자의 화면은 입력·출력·연결 질문으로 남으며 상세 설계를 대체하지 않는다.
- 모든 화면 배치·미확정 동작·예시는 제안 또는 가상 예시로 구분된다.

이 기준은 팀 검토에 사용할 체크 항목이며, 제품 동작의 테스트 통과나 팀 승인 완료를 뜻하지 않는다. 팀원 1이 공식 입력으로 재사용할 때 근거 ID, 채택한 화면 제안, 남은 정책·연결 조건을 함께 옮긴다. 원본 요구사항·공식 단계 상태·승인 기록을 이 초안에 맞춰 소급 변경하지 않는다.

- v0.2 (2026-09-14) — 작성자 검토에서 비교용 배치로 **위쪽 메뉴만 + 최근 분석 한 건**을 선택. 하단 바로가기 제거, 첫 방문·분석 중·완료·실패 네 상태를 전체 화면으로 비교(§5). 최근 한 건 선정 기준과 이전 작업 재확인 경로를 미정으로 추가(v0.2 §5.7, 현재 §5.8·§7). ‘대표 없이도 링크 발행 가능’ 안내 위치를 팀원 3 전달 제안으로 이동(§6.1·§7). 상태 조회 실패의 안내·다시 불러오기 동작을 상태 표에 구체화(§6.2). 팀 검토용 선택이며 정책 확정이 아니다.
- v0.3 (2026-09-14) — PR #28 팀원 1 리뷰 의견 반영. 첫 방문 배치는 유지하고, 재방문 화면은 **최근 분석 상자와 해당 행동을 맨 위**에 두고 [저장소 선택]을 보조 버튼으로 낮춤(§5.1·§5.3~5.6). 완료 상태를 **확인 전·확인 후**로 나누고 확인 후에는 ‘확인한 분석 결과를 다시 볼 수 있습니다’ + [결과 다시 보기]로 같은 결과에 연결, 확인 여부와 공개 여부를 구분(§5.5·§6). ‘확인 완료’ 판단 기준과 결과별 확인 상태 데이터를 자산 담당과 맞출 미정으로 추가(§5.8·§7). 상태 표에 조회 중 배치, 완료·결과 존재가 확인되고 확인 여부만 모를 때의 중립 [결과 보기] 안내를 제안으로 추가하고 상태 조회 실패와 구분(§6.2). 팀 검토용 비교안이며 정책 확정이 아니다.
- v0.4 (2026-09-15) — PR #40에 연결된 회원·자산 초안 §5.1·§5.2와 공유 링크 초안 §6.3 대조 반영. 완료 상태를 **검토 전·일부 검토·전체 검토**의 검토 현황으로 바꾸고, 확인 완료 또는 불일치 표시가 정상 저장된 Catch를 한 번씩 세는 홈 담당 선호안과 판정 조건·불일치 표시 수(정상 조회 1장 이상일 때만)를 자산 담당과 맞출 연결 제안으로 추가(§5.4·§5.5·§5.7·§6). 전체 검토가 내용의 정확성·오류 해결·공개 완료가 아님을 명시하고, 검토할 Catch 없음·검토 현황 조회 실패·집계 대기를 전체 검토와 구분(§5.5·§6.2). 이전의 ‘확인 후’·‘확인 여부만 모름’ 행을 대체한다. 후속 입력의 팀장 확인에 따라 기본 Google OAuth 로그인·GitHub 연결 없는 홈 진입·‘발행’ 용어를 팀 합의로 표시하고 ‘발급’ 표기를 정리(§1·§2·§3·§4·§6·§7). 표시 이름 저장 후 홈 도착·프로필 수정·세션 만료 복귀·공유 링크 관리/발행 준비 진입·결과 목적지는 연결 제안이나 질문으로 추가(§3·§6·§7). 표시 취소·재분석·집계 범위는 미정 유지(§5.8). §3 화면 목록의 A-02 설명을 별도 초안(#41)의 ‘완료·실패 후 화면에 머물며 버튼으로 이동하는 안’ 제안으로 맞춤(확정 정책 아님). 팀 검토용 비교안이며 정책 확정이 아니다.
