# CatchU 10월 MVP — 서비스 홈 흐름·와이어프레임 초안

> 지위: 팀 검토용 초안 v0.6 (2026-09-15). 팀원 1이 조율하는 AI-DLC에 전달할 참고 입력이며 공식 요구사항·설계·승인 기록이 아니다. 팀장 결정과 화면 제안을 구분한다.
> 대상: PC 웹의 비로그인 방문자와 로그인한 구직자. 작성자(팀원 4)의 담당 범위는 서비스 홈·분석 화면 프론트엔드이며, 이번 상세 범위는 로그인 여부에 따른 홈이다.
> 표현: 상자·텍스트·버튼만 사용한다. 가상 Catch는 설명용 예시이며 실제 분석 결과가 아니다. 제품 코드·API 연결·완성 시각 디자인은 포함하지 않는다.

**[요구]**는 승인 요구사항의 행동, **[결정]**은 MVP 입력의 명시된 결정, **[팀 합의]**는 병합된 후속 입력의 팀장 확인, **[팀장 결정]**은 PR #44에서 확인하고 PR #53에 기록 중인 이번 결정, **[제안]**은 화면 배치·문구·동작, **[연결 제안]**은 다른 담당과 맞출 연결, **[미정]**은 남은 정책·계약이다. 화면 ID는 초안 안의 식별자이며 URL·API 계약을 확정하지 않는다.

**대체 범위:** 이번 팀장 결정은 PR #46의 ‘홈 최근 분석 한 건’ 항목과 v0.4·v0.5의 홈 검토 현황 제안을 대체한다. PR #46의 ‘내 자산 GitHub 관련 탭에서 이전 분석을 찾는다’는 경로는 유지한다. 과거 판의 화면·표는 현행 본문에서 제거하고 §9의 이력과 git 판본으로 남긴다. 승인 요구사항·후속 입력 원본·AI-DLC 상태·승인 기록을 이 초안에서 수정하지 않는다.

다른 담당 영역은 MVP 입력 §2.5의 담당 제안을 기준으로 연결 상대를 표시한다. 작성자(팀원 4)의 화면 밖 상세 설계·전체 배정의 확정을 뜻하지 않는다.

## 4. 사용자 흐름 제안

```text
[홈 진입 → 로그인 상태 확인]
    ├─ 확인 중·조회 실패 → 로딩·다시 확인 안내 (§6.2)
    ├─ 비로그인 → [H-01 비로그인 홈]
    │    └─ [Google로 시작하기] → 회원 영역
    │         ├─ 인증 취소·실패 → 회원 화면에서 안내
    │         └─ 로그인·홈 진입 조건 충족 → [H-01 로그인 홈]
    └─ 로그인 → [H-01 로그인 홈]
         ├─ [저장소 선택] → [A-01 선정 저장소·분석 동의]
         │    ├─ 미동의 → 분석 실행 안 함
         │    └─ 동의·허용 조건 충족 → [분석 요청]
         │         ├─ 접수 확인 → [A-02 현재 상태]
         │         └─ 접수 불명 → A-01에서 요청 상태 확인
         │              (자동으로 다시 제출하지 않음)
         │
         ├─ [내 자산에서 분석 보기] → 내 자산 GitHub 관련 탭
         │    └─ 분석 항목 선택 → A-02 / A-03 / 해당 결과
         │         (항목별 연결과 표시 방식은 자산 담당)
         │
         └─ 상단 [내 자산] / [대표 구성] / [공유 링크]
              └─ 각 담당 화면으로 이동

[A-02 현재 상태]
    ├─ 완료·결과 있음 → [결과 확인] 클릭 → 자산 영역
    │    (열람·분석 완료만으로 확인 완료·공개 처리하지 않음)
    └─ 실패 → [실패 내용 보기] 클릭 → [A-03 별도 화면]
         └─ 명시적 재요청 → 접수 확인 알림창 [제안]
              ├─ [진행 상태 보기] 클릭 → 재요청한 분석의 A-02
              └─ [닫기] → A-03 접수 안내 유지 (취소·재요청 아님)
```

회원 영역의 표시 이름 저장 전·후 분기는 회원·자산 초안 §5.1의 연결 제안이다. 인증 취소·실패 처리와 재인증 후 복귀 계약은 회원 담당이 정한다. 홈이나 내 자산 메뉴를 열었다고 분석을 실행하거나 다시 요청하지 않는다. 알림창은 재요청 행동에 대한 접수 안내이며, 12월의 헤더 알림 목록을 구현하는 것이 아니다.

## 5. PC 홈 와이어프레임 [제안]

### 5.1 v0.6 공통 구성

- 비로그인 홈은 서비스의 목적과 가상 Catch를 설명하고 Google 시작 경로를 제공한다.
- 로그인 홈은 첫 방문·기존 이용자 모두에게 **새 분석 시작 / 요청한 분석 확인** 두 경로를 보여 준다. 이전처럼 분석 이력에 따라 배치를 바꾸지 않는다.
- 홈에는 최근 분석 상자, 진행·완료·실패 상태, 결과 단위 검토 현황, 분석 조회 로딩·실패 표시를 두지 않는다. 로그인 여부 확인 로딩과는 구분한다.
- 로그인 상단 [홈]·[내 자산]·[대표 구성]·[공유 링크]는 기존 연결안을 유지한다. 사용자 메뉴·프로필·로그아웃 배치와 12월 알림 위치는 [#51](https://github.com/JminAILab/CatchU/issues/51) 합의에 연결만 남기며 이 그림에서 정하지 않는다.
- `[[버튼]]`은 주 버튼, `[버튼]`은 보조 버튼이다. 상자·문구·강조 순서는 화면 제안이다.

### 5.2 비로그인 홈 — 소개·가상 예시·Google 시작

```text
+- H-01 서비스 홈 · 비로그인 ------------------------------------
| CatchU
+----------------------------------------------------------------
| GitHub 기록을 나의 경험으로 정리해 보세요.
| 선정된 공개 저장소를 분석해 경험 후보와 근거,
| 생각해볼 질문과 Catch 설명 초안을 제공합니다.
|
| + 가상 예시 Catch -------------------------------------------
| | 제목: 중복 요청을 줄인 경험
| | 설명 초안: 요청 중 버튼을 잠가 반복 클릭을 줄였습니다.
| | 근거 예시: 버튼 처리 변경 커밋·PR
| | 생각해볼 질문: 서버에서도 중복 요청을 막았나요?
| | 설명용으로 만든 가상 내용이며 실제 분석 결과가 아닙니다.
| +------------------------------------------------------------
|
| [[Google로 시작하기]]
| 분석은 저장소 선택과 동의 후 시작합니다.
| 결과 확인과 공개 선택은 별도입니다.
+----------------------------------------------------------------
```

가상 예시는 고정 설명 콘텐츠로 두며 실제 사용자·저장소·커밋 URL을 쓰지 않는다. 실제 Catch 4구획의 최종 레이아웃을 정하는 안이 아니며, 클릭·상세·저장·분석 실행 버튼은 없다. 비로그인 상태의 개인 메뉴·헤더 최종 구성은 #51에서 맞춘다. [Google로 시작하기]는 회원 담당의 로그인 흐름으로 연결하며, OAuth를 홈에서 별도로 구현하는 안이 아니다.

### 5.3 로그인 홈 — 첫 방문·기존 이용자 공통

```text
+- H-01 서비스 홈 · 로그인 --------------------------------------
| CatchU      [홈]   [내 자산]   [대표 구성]   [공유 링크]
+----------------------------------------------------------------
| GitHub 기록을 나의 경험으로 정리해 보세요.
|
| + 새 분석 시작 ----------------------------------------------
| | 팀이 선정한 공개 저장소를 고르고 동의 후 분석합니다.
| | [[저장소 선택]]
| +------------------------------------------------------------
|
| + 요청한 분석 확인
| | 분석 상태와 결과는 내 자산의 GitHub 탭에서 확인하세요.
| | [내 자산에서 분석 보기]
| +
|
| 결과 확인과 공개 선택은 별도입니다.
+----------------------------------------------------------------
```

- 첫 방문자는 [저장소 선택]으로 시작하고, 기존 이용자는 [내 자산에서 분석 보기]로 이전 작업을 찾을 수 있다. 두 버튼은 분석 유무에 상관없이 동일하게 표시하는 제안이다.
- 본문 [내 자산에서 분석 보기]는 GitHub 관련 탭을 여는 연결 제안이다. 상단 [내 자산]은 일반 자산 진입으로 유지한다. 탭을 직접 여는 방법과 실제 탭 이름은 자산 담당과 맞춘다. 개인 분석·결과 참조를 홈에 먼저 가져올 필요는 없다.
- 본문 안내는 ‘분석이 있다’거나 ‘완료됐다’는 개인 상태를 단정하지 않는다. 분석이 없는 사람이 자산으로 이동하면 그 영역에서 빈 상태를 안내한다.

### 5.4 12월 피드·알림을 위한 설계 경계

**[팀장 결정]** 12월에는 로그인 홈의 중심이 팔로우 피드이며 분석 완료·실패 안내는 헤더 알림에서 다룬다. **[제안]** 지금 본문의 시작 안내 두 영역은 10월용 진입 안내로 두고, 향후 중앙 본문을 피드로 바꿀 수 있도록 분석 상태·집계와 결합하지 않는다. 시작 경로의 12월 위치는 그때 별도로 검토한다.

이 문단은 화면 밖 설계 주석이다. 10월 화면에는 ‘피드 준비 중’, 빈 피드 상자, 팔로우·글쓰기 버튼, 알림 아이콘·배지·목록을 추가하지 않는다. 헤더의 향후 자리와 사용자 메뉴는 #51, 피드 상세는 12월 작업에서 정한다.

## 7. 다른 영역과 연결할 데이터·조건

다음은 정보의 의미이며 API 필드·엔드포인트·상태 enum이 아니다. **홈 최소 데이터 제안은 로그인 여부의 조회 결과와 각 화면으로의 진입 대상, 고정 소개·가상 예시 콘텐츠**다. 홈용 분석 목록·최근 요청·결과 참조·검토 수·불일치 수·공개 상태·원문·링크 비밀번호는 요청하지 않는다.

| 연결 상대 | 홈에 필요한 입력 | 전달·이동·경계 | 남은 질문 |
|---|---|---|---|
| 회원·프로필 (#20) | 로그인 유효 여부·조회 성공 여부, 회원 진입 대상 | 비로그인 Google 시작 → 회원 흐름. [팀 합의] GitHub 연결 없이 로그인 홈 진입. [연결 제안] 표시 이름 저장 전이면 회원 입력을 거친 뒤 홈 | 실제 로그인 연결 방식, 인증 취소·실패·세션 만료 후 복귀. 회원 화면 상세는 해당 담당이 정함 |
| 자산·분석 이력 (#20·#23) | 자산 진입 대상과 GitHub 관련 탭 선택 방법 | 본문 버튼 → GitHub 관련 탭. 이전 분석에서 A-02·A-03·결과로 이동하는 경로 유지. **홈은 결과 단위 집계를 쓰지 않는다**(아래 답변) | 탭 실제 이름·직접 진입 조건·빈 상태의 다음 화면. 결과·Catch별 확인·공개·불일치는 자산 영역에서 다룸 |
| 분석 처리 (#23, 팀원 1 조율) | A-01 진입 대상 | 홈은 저장소 선택으로 이동만 함. 상태와 결과는 A-02·자산 탭에서 조회. A-03은 별도 화면 | GitHub 연결·저장소 관계·동시 요청·재요청·부분 성공·조회 계약은 해당 분석 초안에 남김 |
| 대표 구성 (#20) | 대표 구성 진입 대상 | 대표 유무로 공유 링크 메뉴를 막지 않음 | 대표 영역 내부의 빈 상태·저장·복귀는 자산 담당 |
| 공유 링크 (#21) | L03 진입 대상·접근 조건 | L03 → 발행 준비 버튼 → L01. 대표 없는 발행 안내는 L01. 상단 [홈] → H-01. 홈에 링크 목록·비밀번호 전달 없음 | 링크 담당이 수용한 화면 연결을 유지. 실제 URL·API 계약은 별도 |

**회원·자산 초안 §5.2에 대한 홈 담당 답변:** “홈은 결과 단위 집계를 쓰지 않는다.” PR #44 팀장 결정에 따라 v0.4·v0.5의 집계 선호안과 홈에 전달할 집계 데이터 요청을 철회한다. Catch별 확인 완료·불일치 기록과 공개 선택은 자산 영역에 남는다. 자산 영역 자체에서 집계가 필요한지는 해당 담당이 검토하며, 이 답변으로 그 정책·API 계약을 확정하거나 삭제하지 않는다.

## 8. v0.6 검토 순서와 AI-DLC 전달 시 확인점

이번 판은 §5.2 비로그인 소개와 §5.3 로그인 공통 구성을 검토한다. 작성자(팀원 4)는 화면 제안을 전달하고, 팀원 1과 연결 담당은 아래 항목을 확인한다. #22의 비로그인 진입 범위는 이번 판에 작성했으며 최종 검토·이슈 종료와는 구분한다.

- 비로그인 방문자가 서비스 소개·가상 Catch·[Google로 시작하기]를 보고 시작할 수 있다. 가상 내용이 실제 처리 결과로 오해되지 않는다.
- 로그인한 첫 방문자와 기존 이용자가 각각 분석 시작·기존 분석 확인 위치를 찾을 수 있다. 홈은 분석 이력 유무로 분기하지 않는다.
- 홈에 분석 상태·최근 결과·결과 단위 검토 현황이 없고, 10월 상태·결과 확인은 A-02와 내 자산 GitHub 관련 탭에서 한다.
- 12월 피드·헤더 알림은 확장 조건으로만 기록돼 있고 10월 화면에 추가되지 않는다. 사용자 메뉴는 #51 협의로 남는다.
- A-02의 홈 최근 분석 진입이 제거되고, A-03은 별도 화면으로 연결된다. 재요청 접수 알림 뒤 버튼으로 A-02에 가는 것은 PR #52의 제안으로 구분된다.
- 홈 담당이 집계를 사용하지 않는다는 답변과 자산 담당의 Catch별 확인·공개 정책이 구분된다.
- Google 로그인·GitHub 연결·분석 동의는 별개이며 홈 이동만으로 분석·재요청·공개가 실행되지 않는다.
- 대표 없는 링크 진입, L03 → L01, [홈] 복귀와 링크 목록·비밀번호를 홈에 보내지 않는 경계가 유지된다.
- 로그인 조회 실패와 비로그인·분석 실패를 구분하고, 실제 URL·API·헤더 배치의 미정을 임의 확정하지 않는다.

이 체크 항목은 문서 검토용이며 제품 실행·API 연결·접근성 테스트 통과를 뜻하지 않는다. AI-DLC 입력으로 재사용할 때는 채택한 배치, 근거 ID, 이번 결정이 대체한 범위와 남은 연결 조건을 함께 전달한다.
