```text

│ 유효기간: 발행 시점부터 30일 — 고정                      │

```

- [임시 예시] A·B는 대표 Catch, C·D는 대표 밖 공개 Catch다. 팀원 2 W03의 미공개·숨김 예시 상태를 공개로 바꾼 결과가 아니라 독립적인 화면 예시다.
- [연결 제안] [공개 자료 확인으로] → W03. [돌아가기] → 진입한 W03·W06·L03, 직접 진입 시 L03을 복귀 기본값으로 제안한다. 다른 화면의 편집·저장 상세는 해당 담당에게 남긴다.
- [화면 제안] [링크 발행] → 발행을 확인한 뒤 L02. 대표 없음은 ‘대표 구성 없음’과 현재 공개 자산으로 표시하며 대표 미구성만으로 버튼을 막지 않는다(FR3.1).
- [미정] 공개 자산이 0개면 ‘현재 공개된 GitHub 자산이 없습니다’라는 안내안을 제시하되, 발행 허용·제한을 확정하지 않는다. 공개 프로필 항목도 OQ3의 합의 대상이다.

### 4.2 L02 — 발행 완료

```text
┌─ L02 링크 발행 완료 ─────────────────────────────────────┐
│ 링크가 발행되었습니다.                    [임시 예시]   │
│ URL: https://example.invalid/share/demo   [URL 복사]     │
│ 발행 시각: <실제 발행 시각>                              │
│ 만료 시각: <발행 시점 + 30일>                            │
│ 비밀번호: 설정됨 / 없음 — 해당 상태 하나만 표시          │
│ URL을 수신자에게 전달하세요.                            │
│ 비밀번호를 설정했다면 비밀번호도 전달해야 합니다.       │
│                                        [공유 링크로]    │
└─────────────────────────────────────────────────────────┘
```

- [화면 제안] [URL 복사]는 URL을 복사하고 확인 문구를 표시한다. [공유 링크로] → L03. 이 예시 URL은 실제 서비스 주소가 아니다.
- [요구] 실제 발행·만료 시각을 기준으로 안내하며 기간 선택·연장 기능을 두지 않는다(FR4.5). [화면 제안] 비밀번호 원문 재조회 기능은 추가하지 않는다.

### 4.3 L03 — 공유 링크 최소 관리

```text
┌─ L03 공유 링크 ─────────────────────────────────────────┐
│ CatchU   [홈]  [내 자산]  [대표 구성]  [공유 링크]        │
│                                        [새 링크 발행]   │
├─────────────────────────────────────────────────────────┤
│ [임시 예시] 링크: …/demo                                 │
│ 상태: 유효 / 중단 / 만료 — 해당 상태 하나만 표시         │
│ 만료 시각: <시각>           비밀번호: 있음 / 없음        │
│ [링크 중단] ← 유효한 링크에 표시                         │
│ 중단하면 이 URL은 열람할 수 없고 다시 활성화할 수 없습니다.│
│ 자료 삭제·전역 숨김은 실행하지 않습니다.                 │
└─────────────────────────────────────────────────────────┘
```

- [화면 제안] [새 링크 발행] → L01. [링크 중단]은 해당 링크 중단을 요청하고 완료를 확인하면 ‘중단’으로 표시한다. 확인 상자·실패 복구 등 상세 동작은 §8의 다음 작업이다.
- [요구] 중단 후 같은 URL의 재접근도 열람되지 않으며 자산은 삭제·숨김 처리되지 않는다(FR4.3). [결정] 중단·만료 URL 복구 및 발행 후 비밀번호 변경·해제 기능은 두지 않는다(M OQ4).
- [화면 제안] 링크가 없으면 ‘발행한 링크가 없습니다’와 [새 링크 발행]만 표시한다. 목록 정렬·검색·페이지 구성 등은 이번 제출에서 정하지 않는다.

### 4.4 V01 — 비밀번호 입력

```text
┌─ V01 비밀번호 입력 ─────────────────────────────────────┐
│ 비밀번호가 필요한 링크입니다.                          │
│ 전달받은 비밀번호를 입력하세요.                        │
│ 비밀번호 [                                           ] │
│                                           [열람하기]   │
│ 안내 영역: 입력 필요 / 비밀번호가 맞지 않습니다         │
└─────────────────────────────────────────────────────────┘
```

- [요구] 유효하고 비밀번호가 설정된 링크는 올바른 조건을 충족해야 V02를 열람한다. 미설정 링크는 V01을 건너뛴다(FR4.2·FR4.4).
- [화면 제안] 빈 입력·오입력은 V01에서 안내하고 본문은 표시하지 않는다. [열람하기]는 현재 링크 조건과 비밀번호를 확인해 V02로 연결한다.
- [미정] 세션 유지 기간·재인증·오입력 제한 상세는 OQ4·OQ14 연결 설계에서 정한다. 인증 성공을 만료·중단 이후 열람 권한으로 사용하지 않는다(NFR1).

### 4.5 V02 — 공개 자료 열람·접근 불가 상태

```text
┌─ V02 공개 자료 ─────────────────────────────────────────┐
│ CatchU                                    [임시 예시]   │
├─────────────────────────────────────────────────────────┤
│ 기본 프로필: <공개 허용 항목>                            │
│ 직무·기술 스택을 표시하면 ‘직접 입력한 정보’ 구분        │
├─────────────────────────────────────────────────────────┤
│ 대표 — 있는 경우                                        │
│ <발행 당시 대표 주장 문구>                               │
│ [Catch A 상세 보기]             [Catch B 상세 보기]      │
├─────────────────────────────────────────────────────────┤
│ 그 밖의 공개 GitHub 자산                                 │
│ [Catch C 상세 보기]             [Catch D 상세 보기]      │
└─────────────────────────────────────────────────────────┘

┌─ V02 접근 불가 상태 — 자료 대신 표시 ────────────────────┐
│ 중단: 이 링크는 중단되어 열람할 수 없습니다.             │
│ 만료: 이 링크는 만료되어 열람할 수 없습니다.             │
│ 없는 URL: 유효하지 않은 링크입니다.                     │
│ ※ 해당 상태의 문구 하나만 표시, 프로필·Catch 본문 없음   │
└─────────────────────────────────────────────────────────┘
```

- [화면 제안] [상세 보기] → 해당 Catch의 V03. 대표가 없으면 대표 영역을 생략하고 공개 GitHub 자산 목록을 표시한다.
- [요구] 대표 밖 공개 자산도 열람하며 현재 숨긴 Catch는 제외한다. 기존 대표에 숨긴 카드가 생겨도 다른 카드로 자동 보충하지 않는다(FR3.2·FR3.4).
- [화면 제안] 열람 가능한 자산이 0개면 허용된 프로필과 ‘현재 열람할 수 있는 공개 GitHub 자산이 없습니다’를 표시한다. 숨긴 카드의 제목·개수·내용은 공개하지 않는다. 이 빈 상태는 L01의 최초 발행 허용 정책을 확정하지 않는다.
- [미정] 프로필·Catch 본문 버전은 OQ3이므로 화면 전체가 발행 당시 그대로라는 문구를 사용하지 않는다.

```text
┌─ V03 Catch·근거 ─────────────────────────────────────────┐
│ [공개 자료 목록으로]                      [임시 예시]   │

├─────────────────────────────────────────────────────────┤

│ 근거: <PR 또는 커밋>                [GitHub 근거 열기]   │
└─────────────────────────────────────────────────────────┘
```

- [화면 제안] 4구획의 세부 표시는 M OQ3의 제안을 사용한다. 수신자용 읽기 화면이며 팀원 2의 본인 확인·공개·불일치 조작을 복제하지 않는다. [연결 제안] 설명·근거의 표시 내용은 자산 담당이 제공하는 결과와 맞춘다.
- [화면 제안] [공개 자료 목록으로] → 현재 조건을 적용한 V02. [GitHub 근거 열기] → 연결된 외부 원문을 새 탭으로 연다.
- [요구] 선택한 Catch가 숨김·원본 비공개 확인으로 제한되면 내용 열람을 허용하지 않는다. [화면 제안] ‘현재 열람할 수 없는 자료입니다’와 목록 복귀를 표시한다. 일시적 원문 접근 실패만으로 비공개라고 판단하지 않는다(FR1.5).

## 5. 접근 상태별 수신자 화면

[요구] 링크 조건과 현재 Catch 공개 상태를 함께 적용한다(FR4.2~FR4.5·FR3.4·NFR1). [화면 제안] 중단·만료·없는 URL은 비밀번호 입력보다 접근 불가 안내를 먼저 표시한다. ‘숨김 있음’은 요청 대상 또는 구성 중 일부 Catch가 현재 비공개라는 뜻이며 관계없는 공개 자료는 유지한다. 최초 미공개 및 확인된 원본 비공개 Catch에도 같은 열람 제외 원칙을 적용한다.

| 비밀번호 | 링크 상태 | Catch 숨김 | 수신자가 보는 화면·내용 |
|---|---|---|---|
| 없음 | 유효 | 없음 | [화면 제안] V02 → 선택한 공개 Catch V03 |
| 없음 | 유효 | 있음 | [화면 제안] V02에서 숨긴 Catch 제외. 그 Catch 직접 진입은 V03 내용 대신 열람 불가·목록 복귀 |
| 있음 | 유효 | 없음 | [화면 제안] 조건 미충족 시 V01. 올바른 비밀번호 조건 충족 후 V02·V03 |
| 있음 | 유효 | 있음 | [화면 제안] 조건 미충족 시 V01. 충족 후에도 숨긴 Catch 제외, 직접 진입은 내용 미제공 |
| 없음 | 중단 | 없음 | [화면 제안] V02 중단 안내. 프로필·Catch 열람 불가 |

| 있음 | 중단 | 없음 | [화면 제안] V01 없이 V02 중단 안내. 올바른 비밀번호·기존 인증으로도 우회 불가 |
| 있음 | 중단 | 있음 | [화면 제안] V01 없이 V02 중단 안내. 전체 링크 열람 불가 |

| 있음 | 만료 | 없음 | [화면 제안] V01 없이 V02 만료 안내. 올바른 비밀번호·기존 인증으로도 우회 불가 |

[미정] 중단과 만료가 동시에 성립할 때의 상세 표시 우선순위, 이미 열린 화면의 재검증 시점·갱신 방식은 다음 작업에서 정한다. 열람 제한 원칙은 유지하며 즉시 회수 시간이나 이미 열람한 자료의 소급 삭제를 약속하지 않는다.

| 필요한 정보 | 제안하는 전달·사용 방식 |
|---|---|
| 본인 식별·권한과 복귀 지점 | [연결 제안] 현재 본인 권한으로 저장 자료 조회. 진입 출처 W03/W06/L03을 복귀에 사용. 출처나 클라이언트 값 자체를 접근 권한으로 신뢰하지 않음 |
| 기본 프로필 | [연결 제안] 공개 가능한 프로필의 참조·요약을 조회. 항목·기존 링크 반영 정책은 OQ3로 남김 |
| 대표 유무 | [연결 제안] 저장된 대표 없음과 조회 실패를 구분. 대표 없음은 허용 경로이며 임의 주장·Catch를 채우지 않음 |
| 저장된 구성 식별·버전 | [연결 제안] W06 저장 성공으로 식별되는 구성 참조와 해당 저장본을 구별할 버전 표식을 전달. 변경 가능한 구성 ID만으로 저장본을 동일시하지 않음 |
| 저장된 주장·선택 Catch | [연결 제안] 그 저장본에 대응하는 주장 문구와 연결 Catch 식별 목록을 L01에서 조회·요약. 미저장 입력을 발행 재료로 쓰지 않음 |
| 현재 공개 자산 | [연결 제안] 대표 밖 공개 자산까지 포함한 현재 목록·열람 가능 상태를 조회. 구성 버전은 현재 공개 권한을 고정하지 않음 |

- [연결 제안] W06은 저장 성공·편집 내용 일치 조건에서 해당 저장본 참조를 L01로 넘긴다. W03·L03 경로는 진입 시 저장된 대표 유무와 참조를 조회한다. 없는 대표를 만들도록 강제하지 않는다.
- [연결 제안] L01에서 요약한 구성과 발행 직전 저장본이 달라졌으면 임의로 새 구성으로 바꿔 발행하지 않고, 현재 구성을 다시 확인하도록 한다. 충돌 안내·재확인 조작의 구체화는 다음 작업이다.
- [요구] 실제 발행 시 대표 문구·연결 구성은 해당 링크의 발행 당시 상태로 보존하고, 이후 열람에는 현재 비공개 제외를 적용한다(FR3.4). [미정] 이를 저장할 방법·버전 표식의 형식·동시 변경 판정은 팀원 1·2·3이 구현 연결 전에 합의한다.
- [미정] 팀원 2에게 확인할 핵심은 **저장 성공 결과에서 구성 참조·저장본 버전 표식을 제공할 수 있는지**, **W06의 저장본과 편집 내용 일치 조건을 위 이동 조건으로 맞출지** 두 가지다. 이 문서의 답안을 합의 완료로 기록하지 않는다.
