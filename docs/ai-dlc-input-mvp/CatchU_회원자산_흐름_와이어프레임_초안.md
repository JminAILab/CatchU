### 1.1 기본 로그인·GitHub 미연결 홈 진입 — 팀장 확인

**팀 합의(팀장 확인 2026-09-14, 후속 입력 문서).** 기본 로그인은 Google OAuth(U1)이며, GitHub 연결 없이 홈 진입을 허용한다(U4). 별도 회의 기록은 없고 팀장이 PR #29 리뷰에서 확인한 뒤 후속 입력 문서에 기록했다. v0.5의 ‘회의 결정 근거 확인 필요’는 이 후속 확인으로 해소됐다. 확인일을 과거 회의 개최일로 해석하지 않는다.

**[팀장 결정 — 2026-09-15]** GitHub 미연결 홈 진입은 허용하지만 **10월 분석 요청 전 GitHub 연동은 필요**하다. 프로필에서 연결 성공 후 내 자산 GitHub 탭으로 이동하며, repo 연결은 그 탭에서 저장소 선택·동의 내용을 확인하고 동의를 담은 버튼으로 요청하는 행동이다. 홈에서 저장소 선택으로 바로 가지 않는다. 근거: [#23 결정](https://github.com/JminAILab/CatchU/issues/23#issuecomment-5677465925), [후속 입력](2026-09-14_followup.md)의 「GitHub 연동·자산 탭 분석 경로」.

**남은 조율:** Google 계정과 선정 저장소의 소유·커밋 관계 확인(OQ1), 동의 기록·유효 범위·재요청 시 재동의(OQ11), 실제 API 계약은 #23·#24에서 연결 당사자와 팀원 1이 조율한다. 연결만으로 관계 확인·분석 동의가 완료되지 않는다. 이미 결정된 연동 필요 여부·동의 버튼 방향을 미정으로 되돌리지 않는다.

### 1.2 분석 이력 위치·홈 연결 — 최신 팀장 결정과 이번 제안

**[팀 합의 — 팀장 확인 2026-09-15]** 진행 중·완료·실패한 분석을 다시 찾는 곳은 **내 자산의 GitHub 관련 탭**이다. 10월 분석 상태·결과는 A-02와 이 탭에서 확인한다. 홈에는 분석 상태·결과 상자를 두지 않는다. 기존 ‘홈은 가장 최근에 요청한 분석 한 건을 보여 준다’는 결정은 최신 결정으로 **대체됐다**. 홈 → [내 자산] 진입은 유지하지만 홈에서 W03-R로 직접 들어가거나 W03-R에서 홈으로 복귀하는 연결은 두지 않는다.

근거: [PR #54 팀장 리뷰](https://github.com/JminAILab/CatchU/pull/54#pullrequestreview-5206413716), [PR #53으로 dev에 반영된 최신 후속 입력](https://github.com/JminAILab/CatchU/blob/25f94b0b9ea9efcee9a8269cc4482942e2974dcb/docs/ai-dlc-input-mvp/2026-09-14_followup.md)의 「팀장 확인 (2026-09-15): 홈 분석 결과 안내를 알림으로 이동」. 이전 [#20 분석 이력 위치 확인](https://github.com/JminAILab/CatchU/issues/20#issuecomment-5673652691)은 유지한다. 최신 결정은 홈과 내 자산 모두에서 결과 단위 검토 집계를 제외하고 Catch별 상태를 유지한다(§5.2). 탭 이름·배치·내부 동작은 화면 제안이며 데이터 계약·공식 AI-DLC 승인을 뜻하지 않는다.

**헤더 합의 반영 — W02-P 참조:** [#55의 9/22 정정](https://github.com/JminAILab/CatchU/issues/55#issuecomment-5773134158)과 [9/23 제안](https://github.com/JminAILab/CatchU/issues/55#issuecomment-5788084856)·[합의](https://github.com/JminAILab/CatchU/issues/55#issuecomment-5788108788)에 따라 10월 채용공고·알림은 모두 **비활성 표시(클릭 시 안내창)**로 표기한다. 두 메뉴를 클릭하면 현재 화면 위 작은 안내창에 ‘개발 중인 기능입니다’와 [확인]을 표시하며, [확인]은 안내창만 닫고 기존 화면을 유지한다. 별도 페이지 이동은 없다. 비활성은 기능 미제공을 뜻하며 클릭 불가를 뜻하지 않는다. 10월에는 알림 목록·배지·설정 기능을 제공하지 않는다. 대표 진입점 숨김과는 구분하며 로그인 일반 서비스·비로그인 일반 홈·수신자 헤더의 구성은 W02-P를 따른다. B 과거 화면의 전체 헤더 교체는 인계 후 작업이다.

**[회원·자산 측 화면·연결 제안]** A-02와 분석 이력 탭의 [결과 확인]을 같은 W03-R 결과 목록으로 연결한다. Catch가 한 장이어도 목록을 거쳐 W04로 이동하고 같은 결과 목록으로 돌아온다. 완료 결과의 Catch가 정상 조회로 0장이면 [결과 확인] 없이 ‘이번 분석에서 검토할 Catch가 없습니다’만 표시한다. 버튼·문구는 [머지된 A-02 문서 v0.5 §5.1·§5.2](https://github.com/JminAILab/CatchU/blob/b827fe0c2a461280334036828e3473faa2ff2723/docs/ai-dlc-input-mvp/CatchU_분석진행_흐름_와이어프레임_초안.md)와 맞춘다. 해당 A-02 판본의 과거 홈 연결·집계 언급은 현행 근거로 채택하지 않고 최신 후속 입력을 따른다. **실제 라우트·API 계약이나 담당 간 연결 합의 완료가 아니다.** A-02·A-03 문서는 읽기만 한다.

**[원문 확인 필요]** 기존 ‘팀원 1이 분석 입력·상태·결과를 모두 작성’ 전제는 최신 #23의 **E 상태 의미는 팀원 2, F 결과 의미는 팀원 1** 분담으로 갱신한다. 이번 E 입력은 §5.5이며 F 결과 의미표의 제출 원문은 확인되지 않았다. [#23 기존 입력 등록](https://github.com/JminAILab/CatchU/issues/23#issuecomment-5675898043)과 [연결 충돌표](https://github.com/JminAILab/CatchU/issues/23#issuecomment-5733334145)를 재사용한다. PR #70 아키텍처 입력과 PoC 보고서는 F 결과 의미표·실제 API 계약의 대체물이 아니다.

## 4. PC 웹 와이어프레임

### W01 — 로그인

```text
┌──────────────────────────────────────────────────────────────┐
│ CatchU                                                       │
├──────────────────────────────────────────────────────────────┤
│                      CatchU 시작하기                         │
│               내 경험과 근거를 정리해 전달합니다.             │
│                                                              │
│                  [Google로 계속하기]                         │
│                                                              │
│ 안내 영역: 로그인 취소 / 로그인 실패 시 문구                  │
│                  [다시 시도]  ← 실패 상태                     │
└──────────────────────────────────────────────────────────────┘
```

- **[팀 합의 U1]** 기본 로그인은 Google OAuth다(팀장 확인 2026-09-14, 후속 입력 문서, 이 문서 §1.1). 버튼 문구는 ‘Google로 계속하기’라는 화면 제안이다. Google 인증 화면은 외부 연결로 표시하고 이 문서에서 상세 설계하지 않는다.
- **[화면 제안]** 인증 성공 후 서비스에 저장된 표시 이름 유무로 분기한다. 첫 로그인뿐 아니라 저장 전 이탈한 재방문자도 W02 최초 입력으로 연결한다. 이름을 이미 저장했다면 기본 진입은 홈, 세션 만료 재인증은 §5.1의 복귀안을 따른다. 조회 실패는 W01-R로 구분하며, Google 인증 취소·실패는 W01에서 다시 시도한다.
- **[요구 경계]** 로그인 성공을 GitHub 연결·저장소 분석 동의·Catch 공개로 취급하지 않는다(FR1.1·FR4.1). G 내부 선택 공유는 10월 제외다.
- **[화면 제안]** 취소는 ‘로그인을 취소했습니다’, 실패는 ‘로그인하지 못했습니다’로 W01에서 구분한다. 다시 시도는 사용자가 선택할 때만 인증을 시작한다. 기본 진입과 재인증 진입을 구분하며 세션 만료 후 복귀는 §5.1을 따른다. 인증 응답 확인 불가를 가입 실패·계정 없음으로 단정하지 않는다.
- **[미정]** 계정 생성 방식·약관 안내·세션 갱신 상세는 인증 계약에서 정한다. Google 계정·선정 저장소 관계와 동의 기록은 OQ1·OQ11에 남는다. 로그아웃 성공 후 비로그인 홈 H-01 이동은 #51 합의를 따른다. 재시도 안내·재인증 복귀 상세는 화면 제안이다. 기본 로그인 결정만으로 다른 로그인 수단이나 이메일·비밀번호 가입/재설정 기능을 추가하지 않는다.

### W01-R — 로그인 직후 표시 이름 조회 대기·실패

**[화면 제안]** 인증 성공 후 표시 이름을 조회하는 동안 회원 영역의 이 상태에 머문다. W01-R은 설명용 화면 ID이며 별도 URL·페이지 생성은 확정하지 않는다. 실패 시 빈 W02나 홈으로 이동하지 않는다.

```text
┌──────────────────────────────────────────────────────────────┐
│ CatchU                                          [로그아웃]   │
│ 로그인은 완료됐지만 프로필을 불러오지 못했습니다.            │
│ 표시 이름 저장 여부를 확인한 뒤 계속할 수 있습니다.           │
│                                         [다시 불러오기]     │
│ 재조회 중: 프로필을 불러오는 중입니다.                        │
└──────────────────────────────────────────────────────────────┘
```

- 최초 조회·재조회 중에는 로딩 안내를 표시하고 ‘다시 불러오기’를 비활성화해 중복 요청을 막는 안이다. 실패하면 위 안내와 활성 버튼을 표시한다. 상자는 서로 다른 상태의 문구 예시이며 실제 로그인·조회 결과가 아니다.
- ‘다시 불러오기’는 현재 로그인 세션으로 표시 이름 저장 여부만 다시 조회한다. 유효한 세션에서 Google 인증을 반복하지 않는다. 성공하면 이름 미저장자는 W02, 저장자는 기본 진입 시 H01로 이동하며 세션 만료 재인증은 §5.1의 복귀안을 적용한다. 재실패하면 같은 화면에서 다시 시도할 수 있고 자동 재시도하지 않는다.
- 세션 만료가 확인되면 W01로 이동해 ‘로그인이 만료되었습니다. 다시 로그인해 주세요’라고 안내한다. 재인증 후 표시 이름을 다시 조회한다. 홈·다른 작업 중 만료 후 원래 위치 복귀는 §5.1 협의 사항이다.
- **[#51 합의 반영]** ‘로그아웃’은 CatchU 세션 종료 성공 후 비로그인 홈 H-01로 이동한다. 실패하면 W01-R에 머물고 완료로 표시하지 않는다. 실패 안내와 재시도 버튼의 구체 문구는 **화면 제안**이다. Google 계정 전체 로그아웃·연결 해제는 의미하지 않는다. 조회 실패를 이름 없음으로 간주하거나 Google 이름으로 대체 저장하지 않는다. 세션 만료가 확인된 경우에는 기존 W01 재로그인 흐름을 따른다.

### W02 — 기본 프로필

**검토용 제안 U2:** 표시 이름만 필수로 두고, 나머지 항목은 비워 둔 채 홈에 들어갈 수 있게 한다. 필수·선택 구분은 팀 확정 정책이 아니다. **상자의 GitHub 미연결 홈 진입 안내는 팀 합의 U4를 반영한 안내**로, 필수·선택 항목에 관한 검토용 제안 U2와 지위가 다르다. 배치와 나머지 조작은 화면 제안이다.

아래 상자는 **최초 입력 상태**다. 저장 전 이탈한 재방문자도 이 상태로 연결한다. 최초 입력과 이후 수정은 같은 W02의 표시 상태 구분이며 별도 페이지·API를 확정하는 것이 아니다.

```text
┌──────────────────────────────────────────────────────────────┐
│ CatchU                     기본 프로필          [로그아웃]   │
├──────────────────────────────────────────────────────────────┤
│ 사용할 표시 이름을 확인해 주세요.                            │
│                                                              │
│ 표시 이름 (필수) [한지우                                 ]    │
│ Google에서 받은 이름을 미리 채웠습니다. 수정할 수 있습니다.  │
│                                                              │
│ 선택 정보 — 지금 비워 두고 나중에 프로필에서 작성해도 됩니다.│
│ 한 줄 소개 (선택) [                                     ]    │
│ 직무 (선택)      [                                     ]    │
│ 기술 스택 (선택) [기술 추가]                                 │
│                직무·기술 스택은 직접 입력한 정보입니다.        │
│ GitHub 계정을 연결하지 않아도 홈에 들어갈 수 있습니다.        │
│                                                              │
│ 입력 오류 / 저장 실패 안내 영역                               │
│                                       [저장하고 홈으로]      │
└──────────────────────────────────────────────────────────────┘
```

- ‘한지우’와 Google 이름 수신 안내는 **[임시 예시]**다. 실제 인증 결과가 아니다. 직무·기술 스택의 입력 방식과 기술 추가 조작은 **[화면 제안]**으로 유지한다.
- **[검토용 제안 U2]** 이름은 서비스에서 사용할 **표시 이름**이며 유일한 필수 프로필 항목이다. Google 이름을 받으면 입력란에 미리 채우되 사용자가 자유롭게 수정할 수 있게 한다. 실명 인증·이름의 유일성을 보장한다는 의미가 아니다.
- **[화면 제안]** Google 이름을 받지 못하면 표시 이름 입력란을 비워 두고 직접 입력하게 한다. 빈 상태로 저장을 시도하면 ‘표시 이름을 입력해 주세요’라고 안내하며 홈 이동을 완료하지 않는다. 미리 채운 이름도 사용자가 ‘저장하고 홈으로’를 선택해 저장한다.
- **[검토용 제안 U2]** 한 줄 소개·직무·기술 스택은 선택이다. 모두 비워 두어도 표시 이름을 저장하면 홈으로 이동할 수 있고, 나중에 프로필 수정에서 작성할 수 있다. 선택 항목의 미입력을 ‘프로필 미완료’로 표시하거나 홈 진입을 막는 조건으로 사용하지 않는다.
- **[팀 합의 U4 / 연결 경계]** GitHub 연결 없이 홈 진입을 허용하지만 분석 요청 전에는 연결이 필요하다(§1.1). 최초 이름 입력의 홈 진입 조건으로 GitHub 연결을 추가하지 않는다. 이후 프로필 연결은 W02-P/W02-G이며 소유·커밋 관계 확인과 동의 기록은 미정이다.
- **[팀장 결정 — 9/20]** 공개 프로필 항목은 표시 이름·한 줄 소개·직무·기술 스택·GitHub 계정이며 현재 공개 허용 내용을 제공한다. 수정은 기존 링크의 다음 조회에도 반영한다(§1.3). **[화면 제안]** 수정 화면에 ‘프로필 수정은 기존 공유 링크의 다음 조회에도 반영됩니다’라고 안내한다. 직무·기술 스택은 직접 입력한 정보로 표시한다. 이메일 공개·링크별 사본을 추가하지 않는다.
- **[미정]** 이름 길이·허용 문자·중복 규칙, 선택 항목 길이·개수·목록과 공개 허용 판정의 전달 계약. 입력 필수·선택 U2는 제안이며 공개 항목 결정으로 필수 입력을 늘리지 않는다.
- **[화면 제안]** 최초 입력은 저장 성공 시에만 홈으로 이동하고, 실패 시 입력을 유지하며 같은 자리에서 안내한다. 응답 유실은 저장 여부 확인 불가로 구분해 저장된 이름을 재조회하고 자동 재제출하지 않는다. 저장 성공·실패는 설명용 분기이며 실제 처리 결과가 아니다. 이후 수정은 아래 상태에 따른다.
- **[화면 제안]** 선택 항목마다 별도 건너뛰기 버튼을 두지 않고 ‘나중에 프로필에서 작성할 수 있습니다’ 안내와 ‘저장하고 홈으로’ 버튼으로 진행한다. **[#51 합의 반영]** 이후 수정은 W02-P의 상세 프로필에서 ‘프로필 수정’으로 진입하며 저장 성공·취소 후 상세 프로필로 복귀한다(§5.1).

**최초 입력의 취소·로그아웃·이탈 — 기존 화면 제안과 #51 합의 반영:**

- **취소 없음, 이탈 시 재방문 규칙 적용.** 최초 입력에는 ‘취소’나 이름 저장을 생략하는 홈 이동 버튼을 두지 않는다. 이후 수정 화면의 ‘취소’와 구분한다.
- ‘로그아웃’을 제공하며 **미저장 변경이 있으면 먼저 확인**한다. 머무르기를 선택하면 이동·로그아웃 없이 W02와 입력을 유지한다. 변경이 없거나 확인에 동의한 경우에만 CatchU 세션 종료를 요청하고, 동의 직후에는 입력을 버리지 않는다. **성공 후 비로그인 홈 H-01로 이동하며 미저장 입력을 폐기**한다(#51 합의). Google 계정 전체 로그아웃이나 계정 삭제가 아니다. 처리 중 저장·로그아웃 버튼을 비활성화하는 방식은 화면 제안이다.
- **[#51 합의 반영]** 로그아웃 실패 시 W02와 입력을 유지하며 로그아웃 완료로 표시하지 않는다. **[화면 제안]** ‘로그아웃하지 못했습니다. 다시 시도해 주세요’ 안내와 재시도 버튼을 제공한다. 저장 중에는 완료·실패 응답 전 로그아웃을 중복 요청하지 않는 안이다. 실패 안내의 구체 문구·버튼은 합의된 동작과 별개로 검토한다.
- 탭 닫기·뒤로 가기 등으로 저장 전 이탈하면 자동 저장하거나 홈 진입 완료로 처리하지 않는다. 재방문 시 세션이 유효하면 이름 조회부터, 만료됐다면 W01 로그인부터 다시 진행한다. 서버에 저장된 이름이 없으면 최초 입력으로 돌아오며 미저장 입력 복원을 약속하지 않는다. 저장 요청 후 응답을 받기 전에 이탈했다면 실제 저장 여부를 재조회한 결과로 분기한다.
- 입력 중 세션 만료가 확인되면 본인 정보 표시를 중지하고 자동 제출 없이 W01에서 재로그인을 안내한다. 미저장 입력 복원을 약속하지 않고 다시 작성을 안내하는 제안이다. 재인증 뒤 저장 여부부터 확인한다(§5.1).

**이후 수정 상태 — #51 합의 동작과 화면 제안:**

```text
┌──────────────────────────────────────────────────────────────┐
│ 프로필 수정                                                  │
│ 서비스에 저장된 프로필을 불러왔습니다.                        │
│ 표시 이름 (필수) [내가 저장한 이름                       ]    │
│ 한 줄 소개·직무·기술 스택 (선택): 저장된 값 또는 빈 입력란    │
│ 조회 실패 / 저장 실패 / 저장 성공 안내 영역                    │
│                                           [취소] [저장]     │
└──────────────────────────────────────────────────────────────┘
```

- Google에서 다시 받은 이름으로 저장된 표시 이름을 덮어쓰지 않는다. ‘Google 이름을 미리 채웠습니다’ 안내도 최초 입력에만 표시한다. 위 값은 임시 예시다.
- **[#51 합의 반영]** 이후 수정에서는 ‘저장’을 사용한다. 저장 성공·취소 후에는 상세 프로필로 복귀한다. 취소는 미저장 변경이 있으면 확인 후 편집만 폐기하며 저장된 프로필을 삭제하지 않는다. 저장 실패 시에는 수정 화면과 입력을 유지한다. 이전 ‘진입 화면 복귀·출처 불명 시 홈’ 제안은 이 복귀 규칙으로 대체한다. 최초 입력 저장 후 홈, GitHub 연결 성공 후 자산 GitHub 탭, 분석 재인증 복귀에는 이 규칙을 확대하지 않는다.
- 조회 중에는 저장을 막고, 조회 실패는 오류·[다시 불러오기]·[돌아가기]를 제공한다. 빈 프로필이나 Google 이름으로 대체하지 않는다. 저장 중 중복 저장을 막으며 실패하면 입력을 유지한다. **응답 유실은 저장 실패 확정과 구분**해 ‘저장 여부를 확인하지 못했습니다’와 [저장된 프로필 확인]을 제안한다. 확인 전 자동 재저장·화면 이탈을 하지 않으며 입력과 저장본이 다르면 비교 후 재편집을 안내한다. 동시 변경 처리는 미정이다.
- **[#51 합의 반영]** 미저장 변경이 있으면 취소·화면 이동·로그아웃 전에 확인한다(최초 입력에는 취소 없음). 머무르기를 선택하면 이동·로그아웃을 실행하지 않고 현재 입력을 유지한다. 취소·이동에 동의하면 편집만 폐기하고 해당 목적지로 이동한다. **로그아웃은 확인 동의 후에도 입력을 유지하고 성공한 뒤에만 폐기**하며, 실패하면 현재 화면·입력을 유지하고 완료로 표시하지 않는다. 근거는 [#51 로그아웃 폐기 시점 확인](https://github.com/JminAILab/CatchU/issues/51#issuecomment-5770539360)이다. 세션 만료 확인 시에는 W01 재로그인 흐름을 따르며 세션 만료·브라우저 종료에서 확인 안내나 입력 복원을 보장하지 않는다.
- **[화면 제안]** 미저장 확인 문구는 ‘작성한 내용을 저장하지 않고 나갈까요?’, 선택은 [계속 작성]/[나가기]로 표현한다. 버튼명·배치·실패 안내 형식은 검토 대상이며, [나가기]가 로그아웃 동의인 경우에도 입력 폐기는 성공 이후라는 위 조건을 따른다.

### W02-P — 프로필 모달·상세 보기와 회원 동작 연결

**[#51 합의 반영]** 일반 서비스 [프로필] → 버튼 근처의 모달 → [프로필 보기] → 상세 프로필이다. 모달 메뉴는 **프로필 보기 / 로그아웃**이며, **프로필 수정·GitHub 연결은 상세 프로필에서 진입**한다. 근거는 [#51 합의 기록](https://github.com/JminAILab/CatchU/issues/51#issuecomment-5770449582)과 [PR #79 리뷰](https://github.com/JminAILab/CatchU/pull/79#issuecomment-5778362287)다. 아래 배치·버튼 표현은 화면 제안이며 보기와 W02 수정은 별개다.

```text
┌─ 프로필 모달 ─────────────────────────┐
│ 내 표시 이름                         │
│ [프로필 보기]                        │
│ [로그아웃]                           │
└──────────────────────────────────────┘
프로필 보기 → 상세(저장된 본인 정보 / 자가 입력 출처)
              [프로필 수정] [GitHub 연결 상태] [돌아가기]
                 ↓ W02              ↓ W02-G
              저장 성공/취소       연결 성공
                 ↓                   ↓
              상세 프로필         자산 GitHub 탭
```

- **[합의 반영]** 수정 저장 성공·취소는 상세 프로필로 복귀하고 저장 실패는 수정 화면·입력을 유지한다. GitHub 연결의 **성공은 출처와 무관하게 자산 GitHub 탭**으로 이동한다. 세션 만료는 §5.1을 따른다. **[미결]** 모달 닫기 조작(X·Esc·바깥 클릭 등)의 조합은 정하지 않았다. **[화면 제안]** 모달을 닫으면 연 화면을 유지하고 호출 버튼으로 초점을 돌리며, 상세의 [돌아가기]는 상세를 연 화면으로 복귀한다. 미저장 변경이 있으면 아래 확인을 먼저 적용한다.
- **[합의 반영]** 로그아웃 성공은 비로그인 홈 H-01, 실패는 현재 화면·입력 유지이며 완료로 표시하지 않는다. Google/GitHub 계정 전체 로그아웃·연결 해제가 아니다. 미저장 취소·이동·로그아웃에는 W02의 확인 규칙을 적용한다. 머무르기는 이동·로그아웃 없이 입력 유지, 로그아웃에 동의해도 입력 폐기는 성공 후다. **[화면 제안]** 상세 조회 중 로딩, 조회 실패 [다시 불러오기]/[돌아가기], 로그아웃 실패 안내·재시도 버튼을 둔다. 실패를 빈 프로필로 표시하지 않는다. 구체 문구·버튼은 미확정이다.

**[#55 최신 합의 반영 — 10월 헤더]** [9/22 정정](https://github.com/JminAILab/CatchU/issues/55#issuecomment-5773134158)과 [후속 전달](https://github.com/JminAILab/CatchU/issues/55#issuecomment-5773298665)의 적용 경계를 유지하며, 안내 형태·알림 클릭 동작은 [9/23 제안](https://github.com/JminAILab/CatchU/issues/55#issuecomment-5788084856)과 [팀원 3의 합의 답변](https://github.com/JminAILab/CatchU/issues/55#issuecomment-5788108788)을 반영한다. 과거 표시 제안·숨김 선후 확인과 안내 형태·알림 클릭의 미결 표기는 이 후속 합의로 대체됐다. 담당자의 이번 반영본 확인·실제 구현 완료를 뜻하지 않는다.

| 적용 화면 | 헤더 구성·동작 | 적용 경계 |

| 로그인한 일반 서비스·발행자 화면 | 왼쪽: [CatchU 로고] → [내 자산] → [공유 링크] → [채용공고: 비활성 표시(클릭 시 안내창)]. 오른쪽: [알림: 비활성 표시(클릭 시 안내창)] → [프로필]. 로고 클릭 → 로그인 홈 H01 | 두 메뉴 클릭 → 현재 화면 위 작은 안내창, [확인] → 닫고 기존 화면 유지. 최초 입력 W02의 이름 저장 조건을 헤더 이동으로 우회하지 않음. 프로필은 위 모달을 거침 |

- **[#55 9/23 합의 반영]** 10월 채용공고·알림은 모두 **비활성 표시(클릭 시 안내창)**로 표기한다. 비활성은 기능 미제공을 뜻하며 클릭 불가를 뜻하지 않는다. 두 메뉴를 클릭하면 **현재 화면 위 작은 안내창에 ‘개발 중인 기능입니다’와 [확인]**을 표시한다. **[확인]을 누르면 안내창을 닫고 기존 화면을 유지**하며 별도 페이지로 이동하지 않는다. 10월에는 **알림 목록·배지·설정 기능을 제공하지 않는다.** 대표 진입점 숨김과는 별개다.
- **[합의 범위·미결]** 마우스 올림 툴팁 방식은 이번 합의에 포함되지 않는다. 안내창의 X·Esc·바깥 클릭 동작 등 추가 닫기 조작은 미결이며, [확인]으로 닫는 동작만 합의에 반영한다. 프로필 모달 닫기 조합·로그아웃 실패 안내의 구체 문구/버튼과는 별도 미결이다.
- **대표 진입점의 뜻:** 대표 주장과 Catch를 구성하는 W06으로 들어가는 메뉴·버튼이다. 이 진입점을 숨기는 것은 Catch 자체를 비공개로 바꾸거나 공유 링크를 숨기거나 중단하는 동작이 아니다. 대표 없이도 공유 링크를 발행할 수 있는 기존 조건은 유지된다.
- **[기존 결정 / #55 합의 기록 반영]** 상단 별도 [홈]/[대표 구성] 메뉴 제거와 **10월 내 자산 내부의 W06 진입 버튼 숨김**은 구분한다. 전체 제품에서는 대표 구성 진입을 내 자산 안으로 옮기되, 10월에는 내부 버튼도 숨기는 범위다. 근거는 [#55 본문 「10월 헤더 합의」](https://github.com/JminAILab/CatchU/issues/55), [팀원 2의 수용 댓글](https://github.com/JminAILab/CatchU/issues/55#issuecomment-5755284514), [9/22 반영본 확인 요청](https://github.com/JminAILab/CatchU/issues/55#issuecomment-5770533271)이다. 이전 [#55 제안](https://github.com/JminAILab/CatchU/issues/55#issuecomment-5749176277)과 달리 이 숨김 범위에는 합의 기록이 있으며, 담당자의 반영본 확인·실제 구현 완료와는 별개다. 대표 기능은 첫 MVP 이후·날짜 미정이고 내부의 구체적 위치·표현은 B 담당 검토다.
- 과거 W03~W06의 상단 [홈]/[대표 구성]과 내부 대표 버튼은 B 인계 원문이며 현행 10월 헤더·진입 표시안이 아니다(§1.3). 이 합의 반영은 담당자의 이번 반영본 확인이나 구현 완료를 뜻하지 않는다.

- **접근성 제안:** 모달 제목을 읽고 키보드 초점을 내부에 유지, 닫은 뒤 호출 버튼으로 돌린다. 닫기 조작의 조합은 위 미결과 별개로 확정하지 않는다. 상세는 main 제목으로 초점을 옮긴다. 작은 화면은 한 열로 쌓으며 모달 폭·스크롤 상세는 후속 검토다.

### W02-G — 프로필 GitHub 연결

**[팀장 결정]** Google 로그인과 GitHub 연동은 별개이며 분석 전 연동이 필요하다. **연결 성공 → 내 자산 GitHub 탭**을 적용한다. 아래 상태·재시도·취소 복귀는 **A 측 화면 제안**이다. 외부 GitHub 인증 화면의 상세·앱 종류·권한 범위·API를 정하지 않는다.

```text
┌─ 프로필 · GitHub 연결 ───────────────────────────────────┐
│ 분석을 요청하려면 GitHub 계정을 연결해 주세요.           │
│ 연결만으로 저장소 분석이 시작되지 않습니다.              │
│ 상태: GitHub 미연결                     [GitHub 연결]   │
│ 오류/확인 불가 안내                     [상태 다시 확인]│
│                                        [돌아가기]      │
└─────────────────────────────────────────────────────────┘
```

서로 다른 상태의 문구·버튼 예시이며 실제 연결 결과가 아니다. 상자의 오류/재조회 영역은 해당 상태에서만 표시한다.

| 진입·상태 | 표시·행동 [화면 제안] | 다음 화면·복귀 / 확인할 경계 |
|---|---|---|
| 홈의 미연결 CTA / 자산 GitHub 탭 직접 진입 / W02-P 상세 프로필 | 연결 상태부터 조회. 조회 중 연결 성공·미연결로 단정하지 않음 | 정상 미연결이면 [GitHub 연결], 연결됨이면 계정 표시와 [자산 GitHub 탭으로] |
| 연결 시작·외부 인증 대기 | ‘GitHub 연결을 진행하고 있습니다’. 반복 연결 요청 막음 | 외부 인증 응답 후 CatchU 연결 저장 상태 확인. 외부 인증 성공만으로 저장 완료 처리하지 않음 |
| 연결 성공 확인 | ‘GitHub 계정이 연결되었습니다’ | 내 자산 GitHub 탭 → repo 연결(A-01). 저장소 선택·동의·분석 요청은 D 담당 흐름. 자동 요청 없음 |
| 외부 인증 취소 확인 | ‘GitHub 연결을 취소했습니다’ + [다시 연결]/[돌아가기] | W02-G 유지, 돌아가기는 진입한 홈/프로필/자산 탭. 출처 불명은 홈. 기존 연결 삭제로 해석하지 않음 |
| 연결 실패 확인 | ‘GitHub 계정을 연결하지 못했습니다’ + [다시 연결]/[돌아가기] | W02-G 유지. 재시도는 사용자 선택 시만. 기존 연결이 있던 경우 상태 재조회 전 해제됐다고 단정하지 않음 |
| 응답 유실·연결 상태 조회 실패 | ‘연결 상태를 확인하지 못했습니다’ + [상태 다시 확인]/[돌아가기] | 연결 저장 여부 조회만 수행. 자동 재연결·분석 요청 없음. 확인 불가를 미연결로 표시하지 않음 |
| GitHub 권한/연결 만료가 확인됨, CatchU 세션 유효 | ‘GitHub 연결을 다시 확인해 주세요’ + [다시 연결] | 성공 시 자산 GitHub 탭. 일시 조회 실패와 구분. 기존 Catch 열람 제한·삭제/복구는 임의 결정하지 않음 |
| CatchU 세션 만료 확인 | 본인 정보 표시 중지·W01 재로그인 | 같은 계정과 이름 확인 후 W02-G 상태 재조회, 연결됨이면 자산 GitHub 탭. 다른 계정이면 이전 출처·요청 참조를 버리고 기본 로그인 흐름. 자동 분석 없음 |

미저장 W02에서 연동 진입 시 먼저 W02의 이탈 안내를 거친다. 연결 취소와 CatchU 로그아웃, GitHub 연결 해제는 다른 행동이다. **연결 해제 기능·다른 GitHub 계정으로 교체·기존 자산 영향은 이번 판에서 추가하지 않고 #67 §4-4·#23 Q3로 남긴다.**

**접근성 제안:** main 제목→연결 안내→행동 버튼 순서, 오류는 텍스트와 함께 알리고 재조회 후 상태 영역으로 초점 이동. 외부 인증 복귀 초점·팝업/전체 이동 방식은 D와 협의한다. 작은 화면에서는 상태와 버튼을 한 열로 쌓는다.

### H01 — 홈 연결 범위

```text
┌──────────────────────────────────────────────────────────────┐
│ 홈 담당 화면                                                 │
│                                                              │
│ [프로필] → W02-P 모달: [프로필 보기] / [로그아웃]             │
│ [프로필 보기] → 상세 프로필 → 수정 / GitHub 연결               │
│ 그 밖의 연결할 행동: [내 자산] [공유 링크]                     │
│ 미연결 CTA → W02-G / 연동됨·repo 없음 → 자산 GitHub 탭        │
│ 홈에는 분석 상태·결과를 표시하지 않습니다.                    │
│ 분석 상태·결과는 A-02와 내 자산의 GitHub 탭에서 확인합니다.    │
└──────────────────────────────────────────────────────────────┘
```

이 상자는 로그인 홈 H01의 **D 전달용 연결 목록**이다. 비로그인 홈은 D의 H-01로 구분하며 로그아웃 성공 시 이곳으로 이동한다. 로그인·비로그인 헤더는 W02-P의 #55 합의를 따른다. 비로그인 홈의 Google 시작은 W01 로그인으로 연결하고, 최초 이름 저장 조건을 헤더로 우회하지 않는다. 기본 로그인은 이름 미저장자 W02→홈, 저장자→홈이며 선택 정보 미입력·GitHub 미연결은 홈을 막지 않는다. **repo 있음은 접수된 저장소가 하나 이상이라는 사실**로 판단하며 진행·실패와 무관하다. 접수 불명인 요청만 있고 다른 접수 저장소도 없으면 있음으로 확정하지 않는다. 연결 조회 중·실패는 미연결과 구분한다. 홈은 분석 상태·결과를 조회하지 않으며 세션 만료 복귀 예외는 §5.1을 따른다. 상세 배치와 두 연결이 모두 있는 경우의 홈 구성은 팀원 3 D가 정한다.

**A 접근성·작은 화면 메모 [제안]:** W01은 main 제목 후 Google 버튼, W01-R은 로딩/실패 텍스트 알림 후 재조회, W02는 label이 있는 입력 순서와 오류 요약→해당 입력 초점으로 연결한다. 저장/조회 중 여부를 색만으로 전달하지 않는다. W01/W01-R/W02는 작은 화면에서 한 열, 버튼 줄바꿈을 허용하는 안이며 실제 반응형·키보드 실행 시험은 미수행이다. H01의 header/nav/main 상세는 D 담당과 맞춘다.

### W03 — 내 자산: 내 Catch·GitHub 분석 이력

**[회원·자산 측 화면 제안]** 기본 진입은 기존 ‘내 Catch’ 목록을 유지한다. 같은 W03 안에 ‘GitHub 분석 이력’ 탭을 나란히 둔다. 이력의 위치는 §1.2의 팀장 확인이며, 탭 이름·배치·표시 정보는 제안이다.

```text
┌──────────────────────────────────────────────────────────────┐
│ CatchU     [홈]     내 자산                      [대표 구성]  │
├──────────────────────────────────────────────────────────────┤
│ 내 Catch                                  [링크 발행으로]    │
│ [내 Catch — 선택됨]    [GitHub 분석 이력]                     │
│ 공개·숨김은 모든 링크에 적용됩니다.                            │
│                                                              │
│ C-A  API 오류 응답 정리                                       │
│      확인 전 · 미공개                           [상세 확인]   │
│ ──────────────────────────────────────────────────────────── │
│ C-B  중복 요청 방지                                           │
│      확인 완료 · 공개                          [상세 확인]   │
│ ──────────────────────────────────────────────────────────── │
│ C-C  테스트 보강                                              │
│      불일치 표시 있음 · 미공개                  [상세 확인]   │
│ ──────────────────────────────────────────────────────────── │
│ C-D  요청 기록 정리                                           │
│      확인 완료 · 숨김                          [상세 확인]   │
└──────────────────────────────────────────────────────────────┘
```

- C-A~C-D는 각각 독립적인 **[임시 예시]**다. 실제 카드 ID·제목·분석 건수가 아니다.
- **[화면 제안]** 확인 여부, 공개 여부, 불일치 여부를 구분해 표시한다. 불일치 표시를 사람이 검토 중·해결 완료 같은 처리 상태로 바꾸지 않는다.
- **[화면 제안]** 최초 미공개와 공개 후 숨김을 구분해 보여주되 둘 다 외부 열람 불가다. 내부 저장 상태값을 이 표기로 확정하지 않는다.
- **[화면 제안]** 카드가 없으면 ‘아직 확인할 Catch가 없습니다’와 [홈으로]를 제공해 홈의 기존 분석 시작 안내로 연결한다. 홈·분석 담당 합의 전이며 새 분석·재분석을 직접 실행하지 않는다. 로딩은 ‘Catch를 불러오는 중입니다’, 조회 실패는 ‘Catch를 불러오지 못했습니다’와 [다시 불러오기]로 구분한다. 실패를 ‘Catch 없음’으로 표시하지 않는다.
- **[요구]** 대표가 없어도 링크 발행 화면 진입을 허용한다(FR3.1). 발행 화면 내부와 수신자 화면 상세는 제외한다.

**GitHub 분석 이력 탭 — [회원·자산 측 화면 제안 / 임시 예시]**

```text
┌──────────────────────────────────────────────────────────────┐
│ 내 자산                                                      │
│ [내 Catch]    [GitHub 분석 이력 — 선택됨]                     │
├──────────────────────────────────────────────────────────────┤
│ GitHub 분석 이력                           [다시 불러오기]    │
│ 저장소별로 요청한 분석의 상태를 확인합니다.                   │
│                                                              │
│ 저장소 A · 분석 예시 1                                       │
│ 분석 상태: 진행 중                        [진행 상태 보기]    │
│ ──────────────────────────────────────────────────────────── │
│ 저장소 B · 분석 예시 2                                       │
│ 분석 상태: 완료                               [결과 확인]    │
│ (Catch가 있는 것으로 정상 조회된 예시)                       │
│ ──────────────────────────────────────────────────────────── │
│ 저장소 C · 분석 예시 3                                       │
│ 분석 상태: 실패                           [실패 내용 보기]   │
│ ──────────────────────────────────────────────────────────── │
│ 저장소 D · 분석 예시 4 · 분석 상태: 완료                     │
│ 이번 분석에서 검토할 Catch가 없습니다                        │
│ (정상 조회로 0장 확인. 결과 이동 버튼 없음)                   │
│ ※ 임시 데이터 예시이며 실제 처리 결과가 아닙니다.            │
└──────────────────────────────────────────────────────────────┘
```

- **[화면 제안]** 한 행은 한 분석 요청을 식별하는 항목으로 둔다. 같은 저장소의 여러 요청을 구별하는 표시·정렬·보관 범위는 데이터 담당과 협의한다. ‘분석 예시 1’ 등은 임시 구분이며 실제 식별자·요청 시각 필드를 확정하지 않는다.
- 진행 중은 A-02, 실패는 A-03으로 연결한다. 완료이고 Catch가 있는 것으로 확인된 경우에만 [결과 확인] → W03-R로 연결한다. **정상 조회로 0장이면 [결과 확인] 없이 ‘이번 분석에서 검토할 Catch가 없습니다’만 표시**한다. 결과 수를 조회하지 못하면 0장으로 간주하지 않고 조회 실패 안내와 다시 불러오기를 제공하며 결과 버튼은 표시하지 않는 안이다. 조회 중에도 0장·완료 결과를 추정하지 않는다. 완료 결과의 참조·접근 가능 여부는 §5.4에서 맞춘다.
- **[경계]** ‘분석 완료’는 Catch별 확인·공개 완료가 아니다. 결과 단위 검토 집계는 두지 않고 Catch별 확인·불일치·공개 상태만 유지한다. [다시 불러오기]는 상태 목록만 조회하며 분석 재요청을 발생시키지 않는다.
- A-02·A-03 내부의 상태 변화·실패·재요청 동작은 해당 담당 범위다. 동시 분석 수·완료 또는 실패 이력의 재분석 진입 경로는 #23의 별도 결정 사항으로 유지한다.

```text
┌──────────────────────────────────────────────────────────────┐
│ [돌아가기]                                 분석 결과        │
├──────────────────────────────────────────────────────────────┤
│ 저장소 B · 선택한 분석 결과                                  │

│                                                              │

│ 확인 전 · 미공개                              [상세 확인]    │

│                                                              │
│ 목록·상세를 여는 것만으로 확인·공개되지 않습니다.            │
│ ※ 임시 데이터 예시이며 실제 조회·저장 결과가 아닙니다.       │
└──────────────────────────────────────────────────────────────┘
```

- 해당 분석 결과에 속한 Catch만 나열한다. 전체 내 Catch 목록이나 같은 저장소의 다른 분석 결과와 섞지 않는다. 결과 범위·판본을 특정하는 실제 방법은 미정이다.
- Catch가 **한 장이어도 목록을 거쳐** [상세 확인]으로 W04를 연다. W04의 복귀 표기는 이 진입에 한해 [결과 목록으로]를 제안하며 **같은 결과 목록**으로 돌아온다. 다른 분석 결과나 전체 내 Catch로 자동 전환하지 않는다. 기존 내 Catch → W04의 [내 자산으로] 복귀는 유지한다.
- W03-R의 [돌아가기]는 진입 출처인 **A-02 또는 W03 분석 이력**으로 복귀하는 안이다. 홈은 복귀 대상에 넣지 않는다. 결과·진입 출처를 유지할 방법은 §5.4의 연결 협의다. 같은 목록 유지가 Catch 내용·공개 상태를 과거 값으로 고정한다는 뜻은 아니며, 변경된 Catch별 상태를 반영할 시점·방법은 미정이다.
- **[팀장 결정 반영]** §5.2에 따라 결과 전체의 검토 현황·검토 수를 표시하지 않는다. Catch별 확인·불일치·공개 상태는 기존 W03·W04와 같은 의미로 유지한다.

- **[연결 상태]** 원본 비공개가 확인되면 관련 Catch의 외부 열람 중단 이유를 알린다. 본인 화면에서 설명을 계속 볼 수 있는지는 OQ2가 결정하므로 이 초안으로 보관·복구를 약속하지 않는다. 일시적 근거 접근 실패는 별도의 접근 실패 안내로 둔다.

- **[요구]** 대표 주장 직접 작성과 Catch 2~3장 한 벌을 제공한다. 대표 주장 자동 작성·첨삭, 복수 프리셋, 검색 대표 지정 기능은 넣지 않는다(FR3.1·FR3.3·FR3.5).
- **[화면 제안]** 선택 후보는 확인을 마친 현재 공개 Catch 중심으로 보여준다. 미공개·불일치·숨김 카드는 ‘내 자산에서 상태 확인’으로 연결한다. 후보 자격·편집 중 상태 변화의 세부 판정은 합의가 필요하다. 대표 선택 자체가 Catch를 공개하지 않는다.
- **[화면 제안]** 완성된 구성 저장은 주장 1개와 Catch 2~3장일 때 제공한다. 0~1장이면 부족 안내, 4번째 선택 시 ‘최대 3장’ 안내를 둔다. 불완전한 구성의 임시 저장·자동 저장 정책은 추가하지 않는다.
- **[회원·자산 측 수용 답변 — §5.3]** 대표 구성 저장 성공 결과에서 ‘구성 참조 + 해당 저장본을 구별하는 버전 표식’을 제공하는 안을 수용한다. 수정 가능한 구성 ID만으로 저장본을 특정하지 않는다. 필드명·버전 형식·저장 방식·API 계약은 미정이며 실제 구현 완료를 뜻하지 않는다.
- **[회원·자산 측 수용 답변 — §5.3]** 저장된 대표를 가지고 W06에서 L01로 이동할 때는 **‘편집 내용 = 저장본’이고 저장 중·실패 상태가 아닐 때만 [링크 발행으로]를 표시**한다. 저장 성공 후 W06에 머무는 경우와 기존 저장 구성을 불러온 경우에 같은 조건을 적용한다. 재편집하면 버튼을 숨기고 ‘변경한 구성을 먼저 저장해 주세요’라고 안내하는 안이다. 저장 중·실패에도 버튼을 숨기며, 저장 자체가 L01 이동이나 링크 발행을 실행하지 않는다. 이 조건은 대표 없는 발행이나 W03·L03 진입으로 확대하지 않는다.
- **[요구]** 구성 완료를 링크 발행의 필수 조건으로 만들지 않는다. 위 우회 버튼은 대표 미구성 상태의 경로다. 기존 대표가 있을 때 특정 링크에서 대표를 제외하는 옵션은 이 문서로 새로 채택하지 않는다.
- **[미정]** 주장 길이, Catch 순서 편집, 대표 제거, 편집 중 공개 상태가 바뀐 경우의 저장. **과거 인계 기준:** 당시의 ‘기본 프로필·Catch 본문 버전 미정’ 표현은 §1.3의 9/20 리뷰에서 각각 구체화됐다. 프로필 제공·수정 반영은 W02, Catch 본문의 생성 결과 유지·직접 편집/재생성/링크별 사본 미도입은 §5.3의 별도 근거를 따른다. 저장·조회 계약과 재분석 결과 반영은 미결이다. Catch를 숨긴 기존 링크에 다른 카드를 자동 보충하지 않는다(FR3.4).

### 5.2 10월 결과 단위 검토 집계 제외·Catch별 상태 유지

**[팀장 결정] 10월에는 결과 단위 검토 집계를 두지 않는다.** 홈뿐 아니라 내 자산의 분석 결과 목록에도 적용한다. 결과 전체의 검토 현황·검토 수·불일치 수, 집계 실패·대기 표시와 관련 데이터 요구를 두지 않는다.

근거는 [PR #54 팀장 리뷰](https://github.com/JminAILab/CatchU/pull/54#pullrequestreview-5206413716)와 [머지된 PR #53 최신 후속 입력](https://github.com/JminAILab/CatchU/blob/25f94b0b9ea9efcee9a8269cc4482942e2974dcb/docs/ai-dlc-input-mvp/2026-09-14_followup.md)의 「홈 분석 결과 안내를 알림으로 이동」 절이다. 승인 요구사항에 근거가 없고 12월 알림의 완료·실패 안내에도 필요하지 않아 제외하며, 분석 데이터 초안에서도 다루지 않는다고 명시돼 있다.

- **Catch별 확인·불일치·공개 상태는 유지한다.** W03·W03-R은 각 Catch의 상태를 보여 주고 W04·W05의 확인·공개 선택을 구분한다. 불일치를 확인 완료·사실 검증·공개 동의로 바꾸지 않는다.
- **[화면 제안]** Catch의 확인 완료는 명시적인 확인 행동 후 기록 저장이 성공했을 때 표시한다. 열람·스크롤·분석 완료만으로 확인 완료로 처리하지 않으며 저장 중·실패도 성공으로 표시하지 않는다.
- 결과에 속한 Catch 목록과 0장 여부를 정상 조회하는 것은 화면 연결에 필요한 정보다. 이를 결과 단위 검토 집계와 혼동하지 않는다. 정상 0건·부분 실패 처리 기준은 §5.5의 사용자 결정을 따른다. 표시 취소·재분석 시 기존 Catch 기록 처리와 실제 판별·전달 계약은 미결이다.

### 5.3 공유 링크 초안 §6.2에 대한 회원·자산 측 수용 답변

근거: [이슈 #20 팀장 코멘트](https://github.com/JminAILab/CatchU/issues/20#issuecomment-5660716151), [공유 링크 초안](CatchU_공유링크_흐름_와이어프레임_초안.md) §6.2. 아래는 2026-09-15 작성자(팀원 2)의 **회원·자산 측 수용 답변**이다. 두 초안의 연결 규칙을 맞추는 기록이며 실제 구현 완료, 공식 API 계약 또는 AI-DLC 승인이 아니다.

| 팀원 3의 질문 | 회원·자산 측 수용 답변 | 적용 범위·미정 사항 |
|---|---|---|
| 저장 성공 결과에서 구성 참조·저장본 버전 표식을 제공할 수 있는지 | 대표 구성 저장 성공 결과에서 **구성 참조 + 해당 저장본을 구별하는 버전 표식**을 제공하는 안을 수용한다. L01이 그 저장본에 대응하는 주장 문구·연결 Catch를 식별할 수 있도록 하며, 수정 가능한 구성 ID만으로 저장본을 특정하지 않는다. | 의미상의 전달 정보에 대한 수용이다. 필드명·버전 형식·저장 방식·API 계약은 미정이며, 현재 제공 기능이 구현됐다고 주장하지 않는다. |
| W06의 저장본과 편집 내용 일치 조건을 이동 조건으로 맞출지 | **저장된 대표를 가진 W06 → L01**에서 ‘편집 내용 = 저장본’이고 저장 중·실패 상태가 아닐 때만 [링크 발행으로]를 표시하는 규칙을 수용한다. 재편집하면 버튼을 숨기고 저장을 먼저 안내한다. 저장 중·실패에도 버튼을 숨긴다. | 대표 없는 발행이나 W03·L03 진입에 이 조건을 확대하지 않는다. 저장과 화면 이동·실제 발행은 별도 행동이며 저장만으로 이동·발행하지 않는다. |

**[요구 / 유지할 경계]** 저장본 버전은 현재 공개 권한을 고정하지 않는다. 발행 당시 대표 문구·연결 구성은 보존하되, 현재 숨김 Catch는 기존 링크에서도 열람 대상에서 제외한다(FR3.4). 대표 밖 공개 자산의 열람과 대표 없는 발행을 유지하며(FR3.1·FR3.2), 저장본 버전을 근거로 숨긴 Catch를 다시 공개하거나 다른 카드로 자동 보충하지 않는다.

**링크 측 일치 확인됨 (2026-09-15):** 팀원 3의 [PR #45 확인 댓글](https://github.com/JminAILab/CatchU/pull/45#issuecomment-5673683686)에서 ‘저장 성공 결과의 구성 참조·저장본 버전 표식 제공안’과 ‘저장된 대표를 가진 W06 → L01 버튼 조건’이 공유 링크 초안과 일치함을 확인했다. 댓글은 공유 링크 v0.8과 대조한 기록이며, [공유 링크 문서 v0.9 §6.2](https://github.com/JminAILab/CatchU/blob/176dc54a84df0b2f88f6adb8aa62eeb3639233fe/docs/ai-dlc-input-mvp/CatchU_공유링크_흐름_와이어프레임_초안.md)에도 이 확인이 반영됐다. 두 조건의 내용과 적용 경계는 위 표를 따른다. 이 기록은 두 담당 문서의 일치 확인이며 실제 구현 완료·공식 API 계약·AI-DLC 승인을 뜻하지 않는다. PR #38의 v0.9를 현재 체크아웃의 공유 링크 문서와 동일시하지 않는다.

**남은 협의:** 필드명·버전 형식·저장 방식·API 계약, 동시 변경 판정과 발행 직전 재확인·복귀 조작의 세부는 후속 협의 대상으로 유지한다. **과거 인계 기준과 현재 결정:** ‘기본 프로필·Catch 본문 버전 정책 미정’은 9/15 당시 표현이다. §1.3에 연결한 PR #67 팀장 9/20 리뷰는 두 항목을 별도로 정했다. 기본 프로필은 열람 시점의 현재 공개 허용 내용을 제공하며 수정은 기존 링크의 다음 조회에도 반영한다(W02). Catch 본문은 해당 Catch의 생성 결과를 유지하고 직접 문구 편집·재생성·링크별 본문 사본은 도입하지 않는다. 공개 권한은 요청 시점에 확인하며 숨긴 Catch는 기존 링크에서도 제외한다. Catch 본문 기준은 프로필 결정에서 추론한 것이 아니라 같은 리뷰의 별도 「Catch 본문」 항목에 근거한다. 저장·조회 계약, 완료 분석의 재분석 정책과 재분석 결과·새 공개 자산의 기존 링크 반영은 계속 미결이다. W06 변경 취소·이탈 안내는 다음 작업으로 남긴다. W03 분석 이력과 결과 목록의 연결은 W03·W03-R·§5.4의 현재 제안을 따르며 실제 연결 합의 전이다. 링크 측 두 조건의 일치 확인을 W03~W06 전체의 검토 완료로 확대하지 않는다.

### 5.4 W03 분석 이력·W03-R 결과 목록 — 홈·분석 연결 조건

**[팀장 확인과 제안 구분]** 분석 상태·결과는 A-02와 내 자산의 GitHub 관련 탭에서 확인하며 홈에는 분석 결과 연결을 두지 않는다(§1.2). 홈 → 내 자산 진입은 유지한다. 아래 탭 표시·결과 목록·복귀 동작과 데이터 항목은 **회원·자산 측 화면·연결 제안**이며 실제 API·담당 간 연결 합의 완료가 아니다.

**[원문 확인 필요 / 계약 미정]** 최신 #23의 역할은 E 상태 의미표=팀원 2(§5.5), F 결과 의미표=팀원 1이다. F 의미표 제출 원문은 확인되지 않았다. [기존 입력 등록](https://github.com/JminAILab/CatchU/issues/23#issuecomment-5675898043) 항목 5~8과 Q2/Q6에 이미 분석 식별·이력·결과 참조·조회 구분이 연결돼 있으므로 중복 등록하지 않는다. 아래는 B 인계용 데이터 요구이며 필드명·상태 enum·API·저장 방식은 확정하지 않는다.

| 연결 주제 | 회원·자산 측 제안 | 데이터·화면 담당에게 확인할 사항 |
|---|---|---|
| 분석 화면과 이력의 공통 분석 상태 | A-02·A-03과 W03 이력이 같은 분석 식별자·저장소명·처리 상태·결과 참조를 사용. 홈용 최근 분석 조회는 요구하지 않음 | E(팀원 2)의 상태 의미와 F(팀원 1)의 결과 원문, 공통 식별·조회·갱신 방식. #23 기존 등록 항목 4~6·Q2/Q4/Q6 참조 |
| 저장소별 이력 | 한 행은 한 분석 요청. 같은 저장소의 여러 요청도 구별 가능하게 표시 | 저장소 식별·표시명, 요청별 구별 정보, 목록 정렬·보관 범위·페이지 구분. 요청 시각 등 필수 표시 항목은 미확정 |
| 상태별 이동 | 진행 중 → A-02, 실패 → A-03, 완료·Catch 있음 → W03-R. 정상 조회로 0장이면 결과 버튼 없이 안내만 표시 | 동일 분석을 여는 참조·실패 안내 연결, 완료 결과 참조·Catch 목록 조회 결과와 준비 여부. 목록 열람 후 상태가 바뀐 경우의 처리 |
| 여러 Catch 결과 목적지 | A-02·이력 [결과 확인] → 같은 W03-R. 한 장이어도 목록을 거쳐 W04 | 분석 담당의 연결안 검토. 분석과 결과의 관계, 결과 범위·판본과 Catch 목록 참조. 결과 없음·조회 실패·접근 불가 구분 |
| 결과 목록 복귀 | W04에서 같은 W03-R로 복귀. W03-R [돌아가기]는 A-02 또는 분석 이력의 진입 출처로 복귀 | 선택한 결과와 진입 출처를 유지할 방법, 현재 본인 권한·대상 존재 확인, 복귀 불가 시 안내. Catch별 상태 갱신 시점·방법 |
| 빈 목록·실패 | 정상 조회로 0장인 결과와 결과 수·목록의 로딩·조회 실패를 구분 | 권한·대상 없음과 통신 실패의 구분, 재조회 응답 의미. 0장 여부가 불명확하면 없음으로 표시하지 않으며 조회를 새 분석·재요청으로 실행하지 않음 |

**결정과 미결 분리:** 실패 이력→실패 안내→명시적 사용자 재요청→접수 후 진행 확인은 후속 입력의 결정이다. PR #70의 기존 진행 작업 반환·명시 재요청 새 작업·전체 동시 실행 1개 방향은 §5.5에서 대조한다. 정상 0건·부분 실패·초안 없는 등록/공개의 제품 기준은 §5.5에 반영했다. 완료 건 재분석 진입·사용자별/다른 저장소 접수 한도·재동의와 후보 판별·실제 노출/전달 계약은 #23 Q5/Q6 미결이다. 목록 제공이 재분석 버튼·동시 요청 허용을 확정하지 않는다. F 원문 확인과 B 담당 검토 전 데이터·API를 확정하지 않으며 W06 변경 취소·이탈은 이번 범위 밖이다.

### 5.5 E 후속 설계 입력 — 분석 요청·상태의 의미

**[후속 설계 입력 / 반영된 방향·화면 제안·미결 구분]** D가 사용자에게 보여 줄 의미와 E/F의 사실 출처를 나눈다. 아래 용어는 화면·설계 검토용이며 API 필드·상태 enum·DB·큐 계약이 아니다. E 상태 의미표는 이 절에서 관리하며 §6은 기존 #23 Q1~Q6의 문서 반영 현황을 정리한다. 이번 보완분은 로컬 문서에 반영된 상태이고 #23에는 제출되지 않았다.

**근거와 적용 수준:** 승인 범위 M01/M05/M06·FR1.4의 동의/권한·중복 방지·기존 자료 보존, 후속 입력의 명시적 사용자 재요청을 유지한다. A-01 v0.3·A-02 v0.6·A-03 v0.5의 접수 불명·재조회 표현을 재사용한다. [PR #70 보완본 `d399553b7e441d23d7ca35ad63816b9402928033` §3/§6](https://github.com/JminAILab/CatchU/blob/d399553b7e441d23d7ca35ad63816b9402928033/docs/ai-dlc-input-mvp/CatchU_공통_아키텍처_검토초안.md)과 [2026-09-22 답변](https://github.com/JminAILab/CatchU/pull/70#issuecomment-5769968672), 최신 PR 본문의 리뷰 반영 설명을 대조했다. 아래 반영된 방향은 공식 API 계약·AI-DLC 승인·구현 완료를 뜻하지 않는다. F 결과 의미표 원문은 미확인 상태다.

**공통 규칙 [PR #70 답변·보완본에 반영된 방향]:** [2026-09-21 작성자 리뷰의 수정 제안 1](https://github.com/JminAILab/CatchU/pull/70#pullrequestreview-5262286913)에 대한 [9/22 답변](https://github.com/JminAILab/CatchU/pull/70#issuecomment-5769968672)과 보완본 §6에 반영된 방향은 다음과 같다.

- 같은 사용자·같은 저장소의 진행 중 재요청에는 새 분석 없이 기존 작업을 반환한다. **서비스 DB 반영 대기·반영 실패 복구 중도 이 진행 중 구간에 포함된다.**
- 서비스 DB 반영까지 끝나야 사용자 완료다. F 생성 종료·업로드·큐 알림만으로는 완료가 아니다.

**공통 미결 — #23 Q4·Q5:** 반영 실패의 확정 조건·시점과 이후 새 분석 요청 허용 시점은 E/F/D 조율 대상으로 남아 있다. worker의 수신·실행 중·실패 알림 방식과 실행 불확실 상태의 판단 기준도 미결이며, F 담당(팀원 1)이 큐 기술 검증(BullMQ 호환성·중복 전달·worker 중단 시 자동 분석 재실행 방지)과 함께 확인해 #23 Q4·Q5에 답변할 예정이다. F 결과 의미표 원문·공식 계약은 별도의 미확인·미결 항목이다. 아래 표의 사용자 안내·버튼·화면 이동은 화면 제안이며 공통 규칙의 지위와 구분된다.

**Q6 결과 판단 기준 — 기록된 사용자 결정:** [PR #79 리뷰](https://github.com/JminAILab/CatchU/pull/79#issuecomment-5772998087)가 연결한 [PR #68 사용자 답변 Q2~Q5 (`08c4288`)](https://github.com/JminAILab/CatchU/blob/08c428847c4084dac0dace3b1c0cf52d963378c9/aidlc/spaces/default/intents/260914-catchu-october-mvp/inception/domain-design/domain-design-questions.md)를 적용한다. 여기의 Q2~Q5는 도메인 질문 번호이며 §6의 #23 Q번호와 구분한다. 제품 결정의 반영이며 도메인 산출물 최종 승인·기술 검증·공식 API 계약 완료를 뜻하지 않는다.

- **정상 0건(Q2):** 오류 없이 분석했지만 등록 조건에 맞는 후보가 없으면 ‘정상 완료·새 Catch 없음’으로 표시한다. 근거 부족·기준 미달과 수집·생성·반영 오류를 구분하며 오류나 조회 실패를 정상 0건으로 바꾸지 않는다.
- **부분 실패(Q3):** 실패 영향과 분리해 등록 조건 충족을 확인한 후보만 미공개 Catch로 제공하고 일부 실패도 알린다. 조건 충족 여부를 판단할 수 없는 후보는 제공하지 않으며 이를 후보 부재로 단정하지 않는다. 일부 실패를 전체 성공으로 표시하지 않는다. 아직 처리 중인 결과의 점진적 노출을 결정한 것은 아니다.
- **초안 없는 등록(Q4):** 설명 초안은 등록 필수 조건이 아니다. 근거·본인 기여와 다른 등록 조건을 충족하면 초안 생성 실패와 별개로 미공개 Catch로 등록한다. 근거·기여 확인 결과와 초안 실패/없음 상태를 구분한다.
- **초안 없는 공개(Q5):** 다른 공개 조건을 충족하고 사용자가 근거·본인 기여를 확인한 뒤 별도로 공개를 선택하면 가능하다. 없는 설명을 생성된 초안처럼 표시하지 않으며 수신자는 근거·기여 중심으로 열람한다. 등록만으로 사용자 확인·공개가 완료되지 않는다.

**처리·반영·열람 경계 유지:** 접수 확인, F 처리 결과, 서비스 DB 반영, 본인 열람 준비를 각각 확인한다. 정상 0건의 완료 의미와 부분 후보 제공을 근거로 F 생성·업로드만으로 사용자 완료/열람 가능을 표시하지 않는다. 제공 후보의 등록·조회 가능 여부와 일부 실패 상태를 함께 전달해야 한다. 실패 범위 판별·후보 적합성·초안 상태·등록 결과의 계약은 E/F/B, 본인 화면 표현은 B/D, 공개 화면은 B/C 검토가 남아 있다. 재분석·동의 재사용·실패 후 보완·기존 Catch와 링크 변경 정책은 미결이다. 기존 초안 생성 기능 요구는 유지하며 자동 재호출·추가 호출을 허용하지 않는다.

**화면에 필요한 공통 정보 [제안]:** 현재 사용자/접근 판정, GitHub 연결 확인 결과, 요청 시도와 접수 작업을 구별할 참조, 대상 저장소, 접수 판단과 현재 업무 상태, 조회 성공 여부·마지막 확인 시점, 사용자용 거절/실패 사유, 실패 영향 범위와 후보별 등록 조건 판단 가능/충족 여부·근거/본인 기여 확인 결과·초안 생성 성공/실패/없음, 현재 상태를 다시 읽을 참조, 결과 반영/본인 열람 가능 여부·결과 참조·결과 수 확인 여부. ‘요청 시도/작업/결과’가 같은 ID라고 가정하지 않는다. 원본 토큰·비밀값·worker 내부 오류·저장 위치를 사용자 화면에 제공하자는 요구가 아니다.

**E/F/B 분담:** E는 접수·상태·중복·재요청을 맡고 F에 작업 시작/실패/생성 결과 사실을 확인한다. F 결과 전달만으로 자동 공개하지 않는다. PR #70의 E 결과 검사/반영 방향을 B의 자산 저장·소유권·공개 CRUD 전체 담당 배정으로 해석하지 않는다. B 담당 확정 전 최종 결과 저장·조회 계약은 보류한다. 메시지 재전달/결과 재반영이 추가 LLM 호출로 이어지지 않도록 검토하며 운영자 전체 중단 스위치(G)를 새로 추가하지 않는다.

**처리량 구분:** PR #70의 ‘전체 분석 동시 실행 1개’는 팀장 채택 방향이다. 이는 사용자당 접수 가능 수, 다른 저장소의 대기 요청 허용 여부·한도, 같은 저장소의 중복 판정 구간과 별개다. 이 세부와 완료 건 재분석 진입은 #23 Q5/Q6에 남긴다.

**가상 예시 — 실제 실행 결과 아님:** 예시 저장소 `sample/repo`의 시도 가에서 응답이 끊김 → ‘접수 불명’ → 사용자가 [요청 상태 확인] → 작업 나의 접수가 확인됨 → 현재 상태 조회. F 생성 종료만 확인되면 결과 준비 중이며, 서비스 반영·본인 열람 준비 확인 후 결과로 이동한다. 같은 결과 전달이 두 번 와도 새 Catch를 중복 생성해서는 안 된다. **[PR #70 답변·보완본 반영 방향] 작업 나의 서비스 DB 반영 대기·복구 중도 진행 중으로 판단하며 같은 사용자·같은 저장소 재요청에는 작업 나를 반환한다.** 실패가 확정되고 새 요청이 허용된 뒤 사용자가 재요청하면 새 작업 다로 연결하는 방향을 검토한다. **반영 실패의 확정 조건·시점과 이후 새 요청 허용 시점은 #23 Q4·Q5에서 F/D와 조율할 [미결]**이다. 가/나/다는 설명용 표식이며 실제 식별자 형식이 아니다.

## 7. 팀 검토·AI-DLC 입력 재사용 기준

이 초안의 작성 목적은 첫 행동·예외·다른 담당 화면으로의 이동을 검토할 수 있게 하는 것이다. 아래 기존 B/대표/내부 검토 기준은 인계용이며 §1.3의 범위 구분을 적용한다. 이번 A/E 시나리오 점검은 §7.2이며 제품 실행 시험이 아니다.

- 로그인 성공·취소·실패와 프로필 입력·저장·홈 이동을 설명할 수 있다.
- U2가 팀 확정 정책이 아닌 검토용 제안으로 표시돼 있으며, Google 이름 수신·미수신·수정과 표시 이름만 저장한 홈 진입을 설명할 수 있다.
- 선택 항목 미입력·GitHub 미연결이 홈 진입을 막지 않고, 선택 정보를 나중에 프로필에서 작성하는 경로가 있다.
- U3의 첫 이용자/기존 이용자 분기와 W02-P 상세에서의 수정·연동 진입, §5.1의 접수 전/후/불명 세션 복귀안을 D 담당에게 설명할 수 있다.
- 이름 저장 전 이탈한 재방문·조회 실패, 최초 Google 이름 채움과 이후 저장된 값 수정의 차이를 설명할 수 있다.
- W01-R 재조회·세션 만료와 W02 최초 입력의 취소 없음·저장 후 홈·이탈 재방문 제안을 설명할 수 있다. #51 합의인 미저장 확인·로그아웃 성공 후 H-01 이동 및 입력 폐기·실패 시 화면/입력 유지와 안내 문구 제안을 구분한다.
- 프로필 자가 입력값을 GitHub 검증 사실로 표시하지 않는다.
- Catch 설명·근거·질문 확인과 공개 선택이 분리돼 있다.
- 공개 Catch 재열람이 미공개 전환을 일으키지 않으며, 상태별 행동과 미정인 숨김·불일치 복구를 구분한다.
- 불일치 표시·미공개 유지·숨김과 내부 선택 공유의 차이를 설명할 수 있다.
- 대표 주장 1개·Catch 2~3장과 대표 없는 발행 경로가 모두 있다.
- W06 구성 저장과 L01 이동 버튼을 구분하고, 저장 실패·재편집 상태에서 저장 성공으로 표시하지 않는다.
- §5.3의 저장본 식별 정보와 W06 버튼 조건을 회원·자산 측 수용 답변으로 구분하며, 대표 없는 발행·W03·L03 진입에 조건을 확대하지 않는다. 실제 구현·API 계약 확정으로 표시하지 않는다.
- 대표 밖 공개 자산, 기존 링크의 대표 보존, 현재 숨김 제외가 함께 유지된다.
- 홈·분석·링크·내부 검토의 연결 조건과 미정 사항이 드러나 있다.
