# CatchU 10월 MVP — 회원·자산·대표 사용자 흐름과 와이어프레임

작성일: 2026-09-14 · 수정일: 2026-09-16 · 판본: v0.9 · 지위: **공동 검토용 화면 초안 / 미승인 AI-DLC 입력 후보**

이 문서는 작성자(팀원 2) 담당 영역의 첫 검토 자료다. 팀 합의 사항은 출처와 함께 반영하며, 이 초안 작성 자체는 별도 intent 생성이나 공식 단계 진행·승인, 새로운 제품 정책 확정을 의미하지 않는다. PC 웹의 상자·텍스트·버튼 배치만 표현하며 실제 코드·API·저장·분석 결과는 포함하지 않는다. 이후 검토에서 화면별로 구체화한다.

최초 초안의 저장소 기준 커밋: `622416602cedbaaefec8a3becd19c7adefd0517a`. v0.6은 PR #29의 v0.5 커밋 `4b037a0d234486d6f6623f515bc1a2a8ebd3845e`에 대한 리뷰를 반영한다. M이 발췌한 승인본 기준은 `3cd01aa`다. 원문과 과거 승인 기록은 수정하지 않는다.

- **[요구]**: 승인 문서가 정한 행동. 화면 배치나 버튼 형태까지 승인됐다는 뜻은 아니다.
- **[입력 제안]**: M에서 제안으로 제시한 내용. 아직 정책 확정이 아니다.
- **[팀 합의]**: 팀장 확인과 후속 입력 문서로 확인한 제품 행동. 과거 승인 원문은 소급 수정하지 않는다. 작성자(팀원 2)의 초안 요청과 구분한다.
- **[화면 제안]**: 이번 초안에서 제시하는 배치·이동·문구·조작 방식.
- **[회원·자산 측 수용 답변]**: 상대 초안의 연결 제안을 작성자(팀원 2)가 수용한 기록. 실제 구현 완료·공식 API 계약·AI-DLC 승인을 뜻하지 않는다.
- **[미정]**: 후속 합의가 필요한 사항. 구현 계약이나 저장 상태값으로 사용하지 않는다.
- **[임시 예시]**: 이해를 위한 가상 데이터. 실제 GitHub 기록·분석 결과·처리 성공 증거가 아니다.

모든 와이어프레임의 배치·버튼 배치는 [화면 제안]이다. 기능의 근거는 각 화면 설명으로 구분한다. 홈과 분석, 링크 발행·수신자 화면은 연결 조건만 남긴다. 팀 조율 상대는 이번 요청에 따라 팀원 2로 두되 M §2.5의 담당 제안표 자체를 변경하지 않는다. 작성자(팀원 2)의 GitHub 계정이나 다른 팀원의 실제 배정을 추정하지 않는다.

### 1.1 기본 로그인·GitHub 미연결 홈 진입 — 팀장 확인

**팀 합의(팀장 확인 2026-09-14, 후속 입력 문서).** 기본 로그인은 Google OAuth(U1)이며, GitHub 연결 없이 홈 진입을 허용한다(U4). 별도 회의 기록은 없고 팀장이 PR #29 리뷰에서 확인한 뒤 후속 입력 문서에 기록했다. v0.5의 ‘회의 결정 근거 확인 필요’는 이 후속 확인으로 해소됐다. 확인일을 과거 회의 개최일로 해석하지 않는다.

| 확인한 기록 | 날짜·해당 내용 | 효력과 경계 |
|---|---|---|
| [PR #29 팀장 리뷰](https://github.com/JminAILab/CatchU/pull/29#issuecomment-5659394192) | 2026-09-14, 팀장 `ljm0850`이 Google OAuth 기본 로그인과 GitHub 미연결 홈 진입 허용 모두 팀 합의라고 확인 | W02의 GitHub 안내도 팀 합의로 표기. 표시 이름 필수·선택 항목과 화면 연결 제안까지 승인한 것은 아님 |
| [PR #27 후속 입력 문서](https://github.com/JminAILab/CatchU/blob/6acab4acdd2b309b424eb8f36501689163181528/docs/ai-dlc-input-mvp/2026-09-14_followup.md)의 「팀장 확인 (2026-09-14): 인증·홈 진입」 | 2026-09-14 확인한 PR #27 커밋 `6acab4acdd2b309b424eb8f36501689163181528`에 반영돼 있음. 기본 로그인은 Google OAuth, GitHub 연결 없이 홈 진입 허용, 홈 진입은 분석 동의·실행 허용과 별개라고 명시 | dev에 반영된 후속 입력이며 공식 단계 승인이 아님. 다른 로그인 수단의 추가·배제와 계정 연결 상세는 미정 |

**남은 조율:** Google 계정과 사전 선정 저장소의 소유·커밋 관계 확인 방법(OQ1), 분석 동의 방식(OQ11), 분석 요청 전 GitHub 연결 필요 여부는 **팀원 1이 조율**한다. 이 초안에서 확정하지 않는다. 위 표에 결정 내용을 풀어 적어 외부 기록을 열지 않아도 팀 합의와 미결 경계를 읽을 수 있게 했다.

### 1.2 분석 이력 위치·홈 연결 — 최신 팀장 결정과 이번 제안

**[팀 합의 — 팀장 확인 2026-09-15]** 진행 중·완료·실패한 분석을 다시 찾는 곳은 **내 자산의 GitHub 관련 탭**이다. 10월 분석 상태·결과는 A-02와 이 탭에서 확인한다. 홈에는 분석 상태·결과 상자를 두지 않는다. 기존 ‘홈은 가장 최근에 요청한 분석 한 건을 보여 준다’는 결정은 최신 결정으로 **대체됐다**. 홈 → [내 자산] 진입은 유지하지만 홈에서 W03-R로 직접 들어가거나 W03-R에서 홈으로 복귀하는 연결은 두지 않는다.

근거: [PR #54 팀장 리뷰](https://github.com/JminAILab/CatchU/pull/54#pullrequestreview-5206413716), [PR #53으로 dev에 반영된 최신 후속 입력](https://github.com/JminAILab/CatchU/blob/25f94b0b9ea9efcee9a8269cc4482942e2974dcb/docs/ai-dlc-input-mvp/2026-09-14_followup.md)의 「팀장 확인 (2026-09-15): 홈 분석 결과 안내를 알림으로 이동」. 이전 [#20 분석 이력 위치 확인](https://github.com/JminAILab/CatchU/issues/20#issuecomment-5673652691)은 유지한다. 최신 결정은 홈과 내 자산 모두에서 결과 단위 검토 집계를 제외하고 Catch별 상태를 유지한다(§5.2). 알림은 12월 범위이며 이번에 헤더를 설계하지 않는다. 탭 이름·배치·내부 동작은 화면 제안이며 데이터 계약·공식 AI-DLC 승인으로 확대하지 않는다.

**[회원·자산 측 화면·연결 제안]** A-02와 분석 이력 탭의 [결과 확인]을 같은 W03-R 결과 목록으로 연결한다. Catch가 한 장이어도 목록을 거쳐 W04로 이동하고 같은 결과 목록으로 돌아온다. 완료 결과의 Catch가 정상 조회로 0장이면 [결과 확인] 없이 ‘이번 분석에서 검토할 Catch가 없습니다’만 표시한다. 버튼·문구는 [머지된 A-02 문서 v0.5 §5.1·§5.2](https://github.com/JminAILab/CatchU/blob/b827fe0c2a461280334036828e3473faa2ff2723/docs/ai-dlc-input-mvp/CatchU_분석진행_흐름_와이어프레임_초안.md)와 맞춘다. 해당 A-02 판본의 과거 홈 연결·집계 언급은 현행 근거로 채택하지 않고 최신 후속 입력을 따른다. **실제 라우트·API 계약이나 담당 간 연결 합의 완료가 아니다.** A-02·A-03 문서는 읽기만 한다.

**[원문 확인 필요]** 팀원 1의 분석 입력·상태·결과 데이터 초안은 **아직 작성 전이며 #23에서 작성한다**. [#23의 기존 입력 등록](https://github.com/JminAILab/CatchU/issues/23#issuecomment-5675898043)에 이 문서의 확인 항목이 이미 연결돼 있다. §5.4는 그 등록을 참조하며 중복 등록하지 않는다. 원문·실제 데이터 구조·API 계약을 확인하거나 확정한 것으로 보지 않는다.

## 3. 화면 목록과 사용자 흐름

| ID | 화면·상태 | 주요 행동 | 연결 |

## 4. PC 웹 와이어프레임

### W01 — 로그인

```text
┌──────────────────────────────────────────────────────────────┐
│ CatchU                                                       │
├──────────────────────────────────────────────────────────────┤
│                      CatchU 시작하기                         │
│               내 경험과 근거를 정리해 전달합니다.             │
│                                                              │
│                  [Google로 계속하기]                         │
│                                                              │
│ 안내 영역: 로그인 취소 / 로그인 실패 시 문구                  │
│                  [다시 시도]  ← 실패 상태                     │
└──────────────────────────────────────────────────────────────┘
```

- **[팀 합의 U1]** 기본 로그인은 Google OAuth다(팀장 확인 2026-09-14, 후속 입력 문서, 이 문서 §1.1). 버튼 문구는 ‘Google로 계속하기’라는 화면 제안이다. Google 인증 화면은 외부 연결로 표시하고 이 문서에서 상세 설계하지 않는다.
- **[화면 제안]** 인증 성공 후 서비스에 저장된 표시 이름 유무로 분기한다. 첫 로그인뿐 아니라 저장 전 이탈한 재방문자도 W02 최초 입력으로 연결한다. 이름을 이미 저장했다면 홈으로 이동한다. 조회 실패는 W01-R로 구분하며, Google 인증 취소·실패는 W01에서 다시 시도한다.
- **[요구 경계]** 로그인 성공을 저장소 분석 동의, Catch 공개, 내부 품질 검토 공유로 취급하지 않는다(FR1.1·FR4.1·FR10.2).
- **[미정]** 최초 Google 로그인 시 계정 생성 방식, 약관·동의 안내 내용과 위치, 세션 만료 후 복귀 정책. Google 계정·선정 저장소 관계 확인과 분석 동의는 팀원 1이 조율한다(OQ1·OQ11). 아래 로그아웃·재시도는 화면 제안이며 인증 계약 확정이 아니다. 기본 로그인 결정만으로 다른 로그인 수단이나 이메일·비밀번호 가입/재설정 기능을 추가하지 않는다.

### W01-R — 로그인 직후 표시 이름 조회 대기·실패

**[화면 제안]** 인증 성공 후 표시 이름을 조회하는 동안 회원 영역의 이 상태에 머문다. W01-R은 설명용 화면 ID이며 별도 URL·페이지 생성은 확정하지 않는다. 실패 시 빈 W02나 홈으로 이동하지 않는다.

```text
┌──────────────────────────────────────────────────────────────┐
│ CatchU                                          [로그아웃]   │
│ 로그인은 완료됐지만 프로필을 불러오지 못했습니다.            │
│ 표시 이름 저장 여부를 확인한 뒤 계속할 수 있습니다.           │
│                                         [다시 불러오기]     │
│ 재조회 중: 프로필을 불러오는 중입니다.                        │
└──────────────────────────────────────────────────────────────┘
```

- 최초 조회·재조회 중에는 로딩 안내를 표시하고 ‘다시 불러오기’를 비활성화해 중복 요청을 막는 안이다. 실패하면 위 안내와 활성 버튼을 표시한다. 상자는 서로 다른 상태의 문구 예시이며 실제 로그인·조회 결과가 아니다.
- ‘다시 불러오기’는 현재 로그인 세션으로 표시 이름 저장 여부만 다시 조회한다. 유효한 세션에서 Google 인증을 반복하지 않는다. 성공하면 이름 미저장자는 W02, 저장자는 H01로 이동한다. 재실패하면 같은 화면에서 다시 시도할 수 있고 자동 재시도하지 않는다.
- 세션 만료가 확인되면 W01로 이동해 ‘로그인이 만료되었습니다. 다시 로그인해 주세요’라고 안내한다. 재인증 후 표시 이름을 다시 조회한다. 홈·다른 작업 중 만료 후 원래 위치 복귀는 §5.1 협의 사항이다.
- ‘로그아웃’은 CatchU 세션 종료 성공 후 W01로 이동한다. 실패하면 이 상태에서 실패 안내와 재시도를 제공한다. Google 계정 전체 로그아웃·연결 해제는 의미하지 않는다. 조회 실패를 이름 없음으로 간주하거나 Google 이름으로 대체 저장하지 않는다.

### W02 — 기본 프로필

**검토용 제안 U2:** 표시 이름만 필수로 두고, 나머지 항목은 비워 둔 채 홈에 들어갈 수 있게 한다. 필수·선택 구분은 팀 확정 정책이 아니다. **상자의 GitHub 미연결 홈 진입 안내는 팀 합의 U4를 반영한 안내**이며 검토용 정책 표기를 해제한다. 배치와 나머지 조작은 화면 제안이다.

아래 상자는 **최초 입력 상태**다. 저장 전 이탈한 재방문자도 이 상태로 연결한다. 최초 입력과 이후 수정은 같은 W02의 표시 상태 구분이며 별도 페이지·API를 확정하는 것이 아니다.

```text
┌──────────────────────────────────────────────────────────────┐
│ CatchU                     기본 프로필          [로그아웃]   │
├──────────────────────────────────────────────────────────────┤
│ 사용할 표시 이름을 확인해 주세요.                            │
│                                                              │
│ 표시 이름 (필수) [한지우                                 ]    │
│ Google에서 받은 이름을 미리 채웠습니다. 수정할 수 있습니다.  │
│                                                              │
│ 선택 정보 — 지금 비워 두고 나중에 프로필에서 작성해도 됩니다.│
│ 한 줄 소개 (선택) [                                     ]    │
│ 직무 (선택)      [                                     ]    │
│ 기술 스택 (선택) [기술 추가]                                 │
│                직무·기술 스택은 직접 입력한 정보입니다.        │
│ GitHub 계정을 연결하지 않아도 홈에 들어갈 수 있습니다.        │
│                                                              │
│ 입력 오류 / 저장 실패 안내 영역                               │
│                                       [저장하고 홈으로]      │
└──────────────────────────────────────────────────────────────┘
```

- ‘한지우’와 Google 이름 수신 안내는 **[임시 예시]**다. 실제 인증 결과가 아니다. 직무·기술 스택의 입력 방식과 기술 추가 조작은 **[화면 제안]**으로 유지한다.
- **[검토용 제안 U2]** 이름은 서비스에서 사용할 **표시 이름**이며 유일한 필수 프로필 항목이다. Google 이름을 받으면 입력란에 미리 채우되 사용자가 자유롭게 수정할 수 있게 한다. 실명 인증·이름의 유일성을 보장한다는 의미가 아니다.
- **[화면 제안]** Google 이름을 받지 못하면 표시 이름 입력란을 비워 두고 직접 입력하게 한다. 빈 상태로 저장을 시도하면 ‘표시 이름을 입력해 주세요’라고 안내하며 홈 이동을 완료하지 않는다. 미리 채운 이름도 사용자가 ‘저장하고 홈으로’를 선택해 저장한다.
- **[검토용 제안 U2]** 한 줄 소개·직무·기술 스택은 선택이다. 모두 비워 두어도 표시 이름을 저장하면 홈으로 이동할 수 있고, 나중에 프로필 수정에서 작성할 수 있다. 선택 항목의 미입력을 ‘프로필 미완료’로 표시하거나 홈 진입을 막는 조건으로 사용하지 않는다.
- **[팀 합의 U4 / 연결 경계]** GitHub 연결 없이 홈 진입을 허용한다(팀장 확인 2026-09-14, 후속 입력 문서, 이 문서 §1.1). 상자의 GitHub 안내는 이 합의를 반영한다. Google 로그인·GitHub 연결·저장소 분석 동의는 구분하며, Google 계정과 선정 저장소의 관계 확인·분석 동의 방식은 팀원 1 조율에 남긴다. 이 화면에 GitHub 연결 강제 단계를 넣지 않는다.
- **[미정]** 표시 이름 길이·허용 문자·중복 규칙, 선택 항목의 길이·개수·목록, 프로필 공개 범위와 기존 링크 반영. Google 이름의 미리 채움을 프로필 자동 공개나 이메일 수집·공개로 확대하지 않는다. U2의 필수·선택 구분은 팀 검토 전 제안 상태다.
- **[화면 제안]** 최초 입력은 저장 성공 시에만 홈으로 이동하고, 실패 시 입력을 유지하며 같은 자리에서 안내한다. 저장 성공·실패는 설명용 분기이며 실제 처리 결과가 아니다. 이후 수정은 아래 상태에 따른다.
- **[화면 제안]** 선택 항목마다 별도 건너뛰기 버튼을 두지 않고 ‘나중에 프로필에서 작성할 수 있습니다’ 안내와 ‘저장하고 홈으로’ 버튼으로 진행한다. **연결 제안 U3:** 이후 수정은 홈 사용자 메뉴의 ‘프로필 수정’에서 진입한다. 메뉴의 위치·표현과 수정 후 복귀 경로는 홈 담당과 협의한다(§5.1).

**최초 입력의 취소·로그아웃·이탈 [화면 제안]:**

- **취소 없음, 이탈 시 재방문 규칙 적용.** 최초 입력에는 ‘취소’나 이름 저장을 생략하는 홈 이동 버튼을 두지 않는다. 이후 수정 화면의 ‘취소’와 구분한다.
- 대신 ‘로그아웃’을 제공한다. 선택하면 미저장 입력은 저장하지 않고 CatchU 세션 종료를 요청한다. 처리 중에는 저장·로그아웃 버튼을 비활성화하는 안이다. 성공하면 W01로 이동하고 미저장 입력은 폐기한다. Google 계정 전체 로그아웃이나 계정 삭제가 아니다.
- 로그아웃 실패 시 W02와 입력을 유지하며 ‘로그아웃하지 못했습니다. 다시 시도해 주세요’라고 안내하고 버튼을 다시 사용할 수 있게 한다. 저장 중에는 완료·실패 응답 전 로그아웃을 중복 요청하지 않는 안이다.
- 탭 닫기·뒤로 가기 등으로 저장 전 이탈하면 자동 저장하거나 홈 진입 완료로 처리하지 않는다. 재방문 시 세션이 유효하면 이름 조회부터, 만료됐다면 W01 로그인부터 다시 진행한다. 서버에 저장된 이름이 없으면 최초 입력으로 돌아오며 미저장 입력 복원을 약속하지 않는다. 저장 요청 후 응답을 받기 전에 이탈했다면 실제 저장 여부를 재조회한 결과로 분기한다.
- 입력 중 세션 만료가 확인되면 자동 제출 없이 W01로 이동해 재로그인을 안내하는 안이다. 미저장 값 보존·복원 여부와 원래 위치 복귀는 §5.1에서 협의한다.

**이후 수정 상태 [화면·연결 제안]:**

```text
┌──────────────────────────────────────────────────────────────┐
│ 프로필 수정                                                  │
│ 서비스에 저장된 프로필을 불러왔습니다.                        │
│ 표시 이름 (필수) [내가 저장한 이름                       ]    │
│ 한 줄 소개·직무·기술 스택 (선택): 저장된 값 또는 빈 입력란    │
│ 조회 실패 / 저장 실패 / 저장 성공 안내 영역                    │
│                                           [취소] [저장]     │
└──────────────────────────────────────────────────────────────┘
```

- Google에서 다시 받은 이름으로 저장된 표시 이름을 덮어쓰지 않는다. ‘Google 이름을 미리 채웠습니다’ 안내도 최초 입력에만 표시한다. 위 값은 임시 예시다.
- 이후 수정에서는 ‘저장하고 홈으로’ 대신 ‘저장’을 사용하고 저장 결과를 알린다. 취소는 수정 내용을 저장하지 않는 안이다. 저장·취소 후 홈 복귀 또는 화면 유지 여부는 §5.1에서 협의하며 자동 이동으로 확정하지 않는다.
- 조회 실패를 빈 프로필로 바꾸거나 Google 이름으로 대체해 저장하지 않는 안을 제안한다. 조회 실패 안내·재시도와 수정 중 이탈 안내의 세부 조작은 연결 검토에 남긴다.

### W03 — 내 자산: 내 Catch·GitHub 분석 이력

**[회원·자산 측 화면 제안]** 기본 진입은 기존 ‘내 Catch’ 목록을 유지한다. 같은 W03 안에 ‘GitHub 분석 이력’ 탭을 나란히 둔다. 이력의 위치는 §1.2의 팀장 확인이며, 탭 이름·배치·표시 정보는 제안이다.

```text
┌──────────────────────────────────────────────────────────────┐
│ CatchU     [홈]     내 자산                      [대표 구성]  │
├──────────────────────────────────────────────────────────────┤
│ 내 Catch                                  [링크 발행으로]    │
│ [내 Catch — 선택됨]    [GitHub 분석 이력]                     │
│ 공개·숨김은 모든 링크에 적용됩니다.                            │
│                                                              │
│ C-A  API 오류 응답 정리                                       │
│      확인 전 · 미공개                           [상세 확인]   │
│ ──────────────────────────────────────────────────────────── │
│ C-B  중복 요청 방지                                           │
│      확인 완료 · 공개                          [상세 확인]   │
│ ──────────────────────────────────────────────────────────── │
│ C-C  테스트 보강                                              │
```

- C-A~C-D는 각각 독립적인 **[임시 예시]**다. 실제 카드 ID·제목·분석 건수가 아니다.
- **[화면 제안]** 확인 여부, 공개 여부, 불일치 여부를 구분해 표시한다. 불일치 표시를 사람이 검토 중·해결 완료 같은 처리 상태로 바꾸지 않는다.
- **[화면 제안]** 최초 미공개와 공개 후 숨김을 구분해 보여주되 둘 다 외부 열람 불가다. 내부 저장 상태값을 이 표기로 확정하지 않는다.
- **[화면 제안]** 카드가 없으면 ‘아직 확인할 Catch가 없습니다’와 [홈으로]를 제공해 홈의 기존 분석 시작 안내로 연결한다. 홈·분석 담당 합의 전이며 새 분석·재분석을 직접 실행하지 않는다. 로딩은 ‘Catch를 불러오는 중입니다’, 조회 실패는 ‘Catch를 불러오지 못했습니다’와 [다시 불러오기]로 구분한다. 실패를 ‘Catch 없음’으로 표시하지 않는다.
- **[요구]** 대표가 없어도 링크 발행 화면 진입을 허용한다(FR3.1). 발행 화면 내부와 수신자 화면 상세는 제외한다.

**GitHub 분석 이력 탭 — [회원·자산 측 화면 제안 / 임시 예시]**

```text
┌──────────────────────────────────────────────────────────────┐
│ 내 자산                                                      │
│ [내 Catch]    [GitHub 분석 이력 — 선택됨]                     │
├──────────────────────────────────────────────────────────────┤
│ GitHub 분석 이력                           [다시 불러오기]    │
│ 저장소별로 요청한 분석의 상태를 확인합니다.                   │
│                                                              │
│ 저장소 A · 분석 예시 1                                       │
│ 분석 상태: 진행 중                        [진행 상태 보기]    │
│ ──────────────────────────────────────────────────────────── │
│ 저장소 B · 분석 예시 2                                       │
│ 분석 상태: 완료                               [결과 확인]    │
│ (Catch가 있는 것으로 정상 조회된 예시)                       │
│ ──────────────────────────────────────────────────────────── │
│ 저장소 C · 분석 예시 3                                       │
│ 분석 상태: 실패                           [실패 내용 보기]   │
│ ──────────────────────────────────────────────────────────── │
│ 저장소 D · 분석 예시 4 · 분석 상태: 완료                     │
│ 이번 분석에서 검토할 Catch가 없습니다                        │
│ (정상 조회로 0장 확인. 결과 이동 버튼 없음)                   │
│ ※ 임시 데이터 예시이며 실제 처리 결과가 아닙니다.            │
└──────────────────────────────────────────────────────────────┘
```

- **[화면 제안]** 한 행은 한 분석 요청을 식별하는 항목으로 둔다. 같은 저장소의 여러 요청을 구별하는 표시·정렬·보관 범위는 데이터 담당과 협의한다. ‘분석 예시 1’ 등은 임시 구분이며 실제 식별자·요청 시각 필드를 확정하지 않는다.
- 진행 중은 A-02, 실패는 A-03으로 연결한다. 완료이고 Catch가 있는 것으로 확인된 경우에만 [결과 확인] → W03-R로 연결한다. **정상 조회로 0장이면 [결과 확인] 없이 ‘이번 분석에서 검토할 Catch가 없습니다’만 표시**한다. 결과 수를 조회하지 못하면 0장으로 간주하지 않고 조회 실패 안내와 다시 불러오기를 제공하며 결과 버튼은 표시하지 않는 안이다. 조회 중에도 0장·완료 결과를 추정하지 않는다. 완료 결과의 참조·접근 가능 여부는 §5.4에서 맞춘다.
- **[경계]** ‘분석 완료’는 Catch별 확인·공개 완료가 아니다. 결과 단위 검토 집계는 두지 않고 Catch별 확인·불일치·공개 상태만 유지한다. [다시 불러오기]는 상태 목록만 조회하며 분석 재요청을 발생시키지 않는다.
- A-02·A-03 내부의 상태 변화·실패·재요청 동작은 해당 담당 범위다. 동시 분석 수·완료 또는 실패 이력의 재분석 진입 경로는 #23의 별도 결정 사항으로 유지한다.

### W03-R — 해당 분석의 Catch 결과 목록

**[회원·자산 측 화면·연결 제안 / 임시 화면 ID]** A-02와 W03 분석 이력의 [결과 확인]만 W03-R 진입점으로 둔다. 완료·Catch 있음이 확인된 경우의 연결이며 실제 라우트·담당 간 연결 합의 완료가 아니다. 홈에서는 내 자산으로 진입해 분석 이력을 확인한다.

```text
┌──────────────────────────────────────────────────────────────┐
│ [돌아가기]                                 분석 결과        │
├──────────────────────────────────────────────────────────────┤
│ 저장소 B · 선택한 분석 결과                                  │
│ 분석 상태: 완료                                              │
│                                                              │
│ API 오류 응답 정리                                           │
│ 확인 전 · 미공개                              [상세 확인]    │
│ 중복 요청 방지                                               │
│ 확인 완료 · 공개                              [상세 확인]    │
│ 테스트 보강                                                  │
│ 확인 전 · 미공개                              [상세 확인]    │
│                                                              │
│ 목록·상세를 여는 것만으로 확인·공개되지 않습니다.            │
│ ※ 임시 데이터 예시이며 실제 조회·저장 결과가 아닙니다.       │
└──────────────────────────────────────────────────────────────┘
```

- 해당 분석 결과에 속한 Catch만 나열한다. 전체 내 Catch 목록이나 같은 저장소의 다른 분석 결과와 섞지 않는다. 결과 범위·판본을 특정하는 실제 방법은 미정이다.
- Catch가 **한 장이어도 목록을 거쳐** [상세 확인]으로 W04를 연다. W04의 복귀 표기는 이 진입에 한해 [결과 목록으로]를 제안하며 **같은 결과 목록**으로 돌아온다. 다른 분석 결과나 전체 내 Catch로 자동 전환하지 않는다. 기존 내 Catch → W04의 [내 자산으로] 복귀는 유지한다.
- W03-R의 [돌아가기]는 진입 출처인 **A-02 또는 W03 분석 이력**으로 복귀하는 안이다. 홈은 복귀 대상에 넣지 않는다. 결과·진입 출처를 유지할 방법은 §5.4의 연결 협의다. 같은 목록 유지가 Catch 내용·공개 상태를 과거 값으로 고정한다는 뜻은 아니며, 변경된 Catch별 상태를 반영할 시점·방법은 미정이다.
- **[팀장 결정 반영]** §5.2에 따라 결과 전체의 검토 현황·검토 수를 표시하지 않는다. Catch별 확인·불일치·공개 상태는 기존 W03·W04와 같은 의미로 유지한다.

| 분석 이력 로딩 | ‘분석 이력을 불러오는 중입니다’ | 빈 이력·실패로 표시하지 않음 |
| 분석 이력 조회 실패 | ‘분석 이력을 불러오지 못했습니다’ + [다시 불러오기] | 분석 처리 실패와 구분 |
| 분석 이력의 완료 항목에서 Catch 정상 조회, 0장 | [결과 확인] 없이 ‘이번 분석에서 검토할 Catch가 없습니다’만 표시 | 머지된 A-02의 문구·결과 버튼 없음과 일치. 홈으로 결과를 연결하지 않음 |
| 완료 항목의 결과 수 조회 중 / 실패 | ‘분석 결과를 불러오는 중입니다’ / ‘분석 결과를 불러오지 못했습니다’ + [다시 불러오기] | 0장으로 취급하지 않으며 [결과 확인]은 표시하지 않는 안 |
| 이미 연 W03-R을 정상 조회한 결과가 0장 | ‘이번 분석에서 검토할 Catch가 없습니다’. 상세 확인 버튼 없음 | [돌아가기]는 A-02 또는 분석 이력으로 유지. 빈 결과의 정상 완료 정책을 확정하지 않음 |
| 결과 목록 로딩 | ‘분석 결과를 불러오는 중입니다’ | 결과 없음으로 단정하지 않음 |
| 결과 목록 조회 실패 | ‘분석 결과를 불러오지 못했습니다’ + [다시 불러오기] | 0장·분석 실패로 표시하지 않음 |

**[미정 유지]** 결과 0건의 정상 완료 여부와 부분 성공 정책·노출 시점은 OQ1·OQ3의 후속 결정이다. 위 0장 안내는 정상 조회로 대상 수가 0임을 확인한 경우의 조건부 화면 제안이며, 0건을 정상 완료로 정책 확정하거나 사용자 역량 부족으로 판단하지 않는다.

### W04 — Catch 상세·불일치·숨김

```text
┌──────────────────────────────────────────────────────────────┐
│ [내 자산으로]                Catch 상세                       │
│ API 오류 응답 정리       확인 전 · 미공개                     │
├──────────────────────────────────┬───────────────────────────┤
│ 자동 생성 설명 초안              │ 근거                      │
│                                  │ [PR 예시 A]               │
│ 무엇을 했나                      │ [커밋 예시 B]             │
│ 오류 응답 형식을 정리했다.       │ 원문 연결 위치            │
│ [근거 예시 A]                    │                           │
│                                  │ 생각해볼 질문             │
│ 판단의 흐름                      │ 어떤 사용 상황 때문에     │
│ 기록에서 확인 가능한 내용 자리   │ 변경이 필요했나요?        │
│                                  │                           │
│ 궤적 및 기록                     │                           │
│ 변경 순서와 연결 근거 자리       │                           │
│                                  │                           │
│ 기록에 없는 것                   │                           │
│ 판단 이유를 확인할 기록이 없음   │                           │
├──────────────────────────────────┴───────────────────────────┤
│ 설명 문구는 직접 수정할 수 없습니다.                          │
│ 나의 해석·보완은 대표 주장에 작성할 수 있습니다.              │
│                                                              │
│ [불일치 표시]                             [확인 완료]        │
└──────────────────────────────────────────────────────────────┘
```

- 설명·PR·커밋·질문은 전부 **[임시 예시]**이며 실제 원문 URL을 꾸며 넣지 않는다. 실제 데이터에서는 근거와 생성 설명을 연결해야 한다(FR2.1·FR2.2).
- 4구획 방향은 R의 의도 분석에 있고, 위 제목·문장별 근거 배치는 M OQ3의 **[입력 제안]**을 따른다. 근거에 없는 이유나 성과 수치를 사실로 채우지 않는다.
- **[요구]** 확인과 공개는 별개다. 위 상자의 확인 전·미공개 Catch는 ‘확인 완료’ 후에도 미공개를 유지하고 W05에서 별도 공개 선택을 받는다. 이미 공개된 Catch를 다시 보는 행동으로 미공개로 바꾸지 않는다(FR4.1). Catch 설명 수정·오류 문구 재생성 버튼은 10월에 제공하지 않는다(FR3.5·FR3.6).

**상태별 행동 표시 [화면 제안]:** 위 상자는 확인 전·미공개 상태에만 해당한다. 다음 표는 화면 행동의 구분이며 내부 상태값이나 복구 정책의 확정이 아니다.

| 현재 상태 | 보여줄 행동 | 행동 결과·경계 |
|---|---|---|
| 확인 전 · 미공개 · 불일치 없음 | ‘확인 완료’, ‘불일치 표시’ | 확인 완료 → 미공개 유지 + W05. 불일치는 아래 별도 조작 영역 |
| 확인 완료 · 미공개 · 불일치 없음 | ‘공개 선택’, ‘불일치 표시’ | 공개 선택 → W05의 별도 공개 선택. ‘확인 완료’를 다시 요구하지 않음 |
| 확인 완료 · 공개 · 불일치 없음 | ‘숨기기’, ‘불일치 표시’ | 상세 재열람만으로 상태 변경 없음. ‘확인 완료’·W05로 되돌리지 않음. 숨김 선택 시 기존 링크 열람 제외를 안내 |
| 숨김 또는 불일치 표시 있음 | 현재 상태·사유 안내 | 일반 ‘확인 완료’로 복구하지 않음. 표시 취소·재공개 조건과 버튼은 미정 |

불일치 조작 영역 **[화면 제안]**:

```text
┌──────────────────────────────────────────────────────────────┐
│ 불일치 표시                                                  │
│ 어떤 부분이 기록과 맞지 않나요?                               │
│ ( ) 설명 내용   ( ) 경험 묶음   ( ) 기여한 사람                │
│     위 유형 명칭·단일/복수 선택은 제안                        │
│                                                              │
│ 유형·건수는 내부 품질 확인에 사용됩니다.                      │
│ 이 행동만으로 설명·근거 전체를 팀에 공유하지 않습니다.        │
│                                                              │
│ [취소] [불일치 표시하고 미공개 유지]                          │
│ 공개 상태였다면 버튼: [불일치 표시하고 숨기기]                │
│                                                              │
│ [이 Catch의 설명·근거를 내부 검토에 별도 공유하기]             │
│ → 별도 선택·안내 화면으로 연결. 자동 동의하지 않음             │
└──────────────────────────────────────────────────────────────┘
```

- **[요구]** 불일치 신호는 FR10.1에, 선택된 설명·근거 공유는 FR10.2·NFR7에 따른다. 별도 공유는 기업 공개를 뜻하지 않는다. 공유 권한·철회·보관은 M OQ10과 연결해 후속 구체화한다.
- **[화면 제안]** 한 버튼의 명칭에 불일치 표시와 미공개/숨김 효과를 모두 적어 사용자가 선택하게 한다. 불일치 표시를 했다는 사실만으로 모든 경우에 자동 숨김이 실행된다고 정책을 확정하지 않는다.
- **[요구/안내 제안]** 숨김 전 ‘이 Catch는 기존 링크에서도 보이지 않게 됩니다. 다른 공개 자산과 링크 자체는 유지됩니다’라고 알린다(FR3.2·FR3.4·FR4.1). 저장 실패 시 완료로 표시하지 않는 안내는 화면 제안이다.
- **[미정]** 표시 취소, 재공개 조건, 대표에 포함된 카드 숨김 후 편집 화면의 경고·수량 판정. 기존 링크의 다른 카드로 자동 대체하지 않는다.
- **[연결 상태]** 원본 비공개가 확인되면 관련 Catch의 외부 열람 중단 이유를 알린다. 본인 화면에서 설명을 계속 볼 수 있는지는 OQ2가 결정하므로 이 초안으로 보관·복구를 약속하지 않는다. 일시적 근거 접근 실패는 별도의 접근 실패 안내로 둔다.

### W05 — 확인 완료 후 공개 선택

```text
┌──────────────────────────────────────────────────────────────┐
│ Catch 확인을 완료했습니다.                                   │
│ 현재는 미공개이며, 확인만으로 공개되지 않습니다.              │
│                                                              │
│ 공개하면 유효한 전달 링크에서 열람할 수 있습니다.              │
│ 대표로 선택하지 않아도 공개 자산에 포함됩니다.                │
│                                                              │
│ [지금 공개]                              [미공개 유지]        │
└──────────────────────────────────────────────────────────────┘
```

- **[요구]** ‘지금 공개’를 기본 행동으로 제안하되 자동 실행·사전 동의로 처리하지 않는다(FR4.1). 기업 검색 참여 같은 12월 동작을 묶지 않는다.
- **[화면 제안]** 공개 선택의 저장 성공을 확인한 뒤 공개 상태로 보여주고, 실패 시 완료 안내 대신 재시도 안내를 둔다. 이는 API 계약 확정이 아니다.
- 이 패널은 확인 완료·미공개·불일치 없음 상태의 공개 선택이다. 이미 공개된 Catch의 재열람에는 띄우지 않는다. 숨김·불일치 표시된 카드의 해제·재공개 흐름은 미정으로 분리한다.

### W06 — 대표 주장 작성·Catch 선택

```text
┌──────────────────────────────────────────────────────────────┐
│ [내 자산으로]                 대표 구성                       │
│ 대표 주장 1개와 Catch 2~3장을 한 벌로 구성합니다.              │
├─────────────────────────────┬────────────────────────────────┤
│ 대표 주장 직접 작성         │ 연결할 Catch 선택              │
│ ┌─────────────────────────┐ │ 선택: 2장 / 2~3장              │
│ │예외 상황을 고려해 API의 │ │                                │
│ │안정성을 개선했습니다.  │ │ [✓] API 오류 응답 정리         │
│ └─────────────────────────┘ │     공개 · 확인 완료 [근거 보기]│
│ 자신의 해석·보완을 작성    │ [✓] 중복 요청 방지              │
│                            │     공개 · 확인 완료 [근거 보기]│
│                            │ [ ] 요청 기록 정리              │
│                            │     공개 · 확인 완료 [근거 보기]│
├─────────────────────────────┴────────────────────────────────┤
│ 구성 미리보기: 위 주장 + 선택한 Catch 2장                      │
│ 대표 밖의 공개 Catch도 링크에서 열람할 수 있습니다.           │
│ 기존 링크의 대표 문구·연결 구성은 발행 당시 상태를 유지합니다.│
│                                                              │
│ [대표 구성 없이 링크 발행으로]               [구성 저장]     │
│ 저장 성공 상태: 구성을 저장했습니다.        [링크 발행으로] │
└──────────────────────────────────────────────────────────────┘
```

- 이 화면의 값은 W03과 다른 **[임시 예시 상태]**다. 실제 확인·공개·저장 실행을 보여주는 것이 아니다. 대표 주장은 사용자 작성 예문이며 AI가 검증한 사실이 아니다.
- 상자의 ‘저장 성공 상태’ 행은 조건부 표시 예시다. 저장 전 화면에 성공 문구와 이동 버튼이 함께 노출된다는 뜻이 아니다. ‘대표 구성 없이 링크 발행으로’는 대표가 아직 저장되지 않은 경우에만 제공하는 제안이다.
- **[요구]** 대표 주장 직접 작성과 Catch 2~3장 한 벌을 제공한다. 대표 주장 자동 작성·첨삭, 복수 프리셋, 검색 대표 지정 기능은 넣지 않는다(FR3.1·FR3.3·FR3.5).
- **[화면 제안]** 선택 후보는 확인을 마친 현재 공개 Catch 중심으로 보여준다. 미공개·불일치·숨김 카드는 ‘내 자산에서 상태 확인’으로 연결한다. 후보 자격·편집 중 상태 변화의 세부 판정은 합의가 필요하다. 대표 선택 자체가 Catch를 공개하지 않는다.
- **[화면 제안]** 완성된 구성 저장은 주장 1개와 Catch 2~3장일 때 제공한다. 0~1장이면 부족 안내, 4번째 선택 시 ‘최대 3장’ 안내를 둔다. 불완전한 구성의 임시 저장·자동 저장 정책은 추가하지 않는다.
- **[회원·자산 측 수용 답변 — §5.3]** 대표 구성 저장 성공 결과에서 ‘구성 참조 + 해당 저장본을 구별하는 버전 표식’을 제공하는 안을 수용한다. 수정 가능한 구성 ID만으로 저장본을 특정하지 않는다. 필드명·버전 형식·저장 방식·API 계약은 미정이며 실제 구현 완료를 뜻하지 않는다.
- **[회원·자산 측 수용 답변 — §5.3]** 저장된 대표를 가지고 W06에서 L01로 이동할 때는 **‘편집 내용 = 저장본’이고 저장 중·실패 상태가 아닐 때만 [링크 발행으로]를 표시**한다. 저장 성공 후 W06에 머무는 경우와 기존 저장 구성을 불러온 경우에 같은 조건을 적용한다. 재편집하면 버튼을 숨기고 ‘변경한 구성을 먼저 저장해 주세요’라고 안내하는 안이다. 저장 중·실패에도 버튼을 숨기며, 저장 자체가 L01 이동이나 링크 발행을 실행하지 않는다. 이 조건은 대표 없는 발행이나 W03·L03 진입으로 확대하지 않는다.
- **[요구]** 구성 완료를 링크 발행의 필수 조건으로 만들지 않는다. 위 우회 버튼은 대표 미구성 상태의 경로다. 기존 대표가 있을 때 특정 링크에서 대표를 제외하는 옵션은 이 문서로 새로 채택하지 않는다.
- **[미정]** 주장 길이, Catch 순서 편집, 대표 제거, 편집 중 공개 상태가 바뀐 경우의 저장, 기본 프로필·Catch 본문 버전. Catch를 숨긴 기존 링크에 다른 카드를 자동 보충하지 않는다(FR3.4).

## 5. 다른 영역과 연결할 조건

아래는 필요한 의미상의 입력·출력이며 API 경로·스키마·권한 계약 승인본이 아니다. 실제 담당자 배정과 이슈 번호는 추정하지 않는다.

| 연결 상대 | 받을 정보 | 전달할 정보 / 확인할 조건 |

### 5.1 홈 PR #28 검토 시 전달할 연결 조건

전달 대상: [홈 흐름·와이어프레임 PR #28](https://github.com/JminAILab/CatchU/pull/28). 관련 작업: [회원·자산 #20](https://github.com/JminAILab/CatchU/issues/20), [홈 #22](https://github.com/JminAILab/CatchU/issues/22), [연결 기준 #23](https://github.com/JminAILab/CatchU/issues/23).

**아래의 Google OAuth 기본 로그인·GitHub 미연결 홈 진입은 팀 합의 U1·U4이며, 나머지는 작성자(팀원 2) 요청 U3와 리뷰에 따른 검토용 연결 제안이다.** 세부 화면·홈 담당 합의·API 계약까지 확정한 것은 아니다. 이 절의 보완은 PR 댓글 게시나 홈 문서 반영 완료를 뜻하지 않는다.

| 경우 | 회원 영역에서 제안하는 연결 조건 | 홈 담당과 맞출 내용 |
|---|---|---|
| 첫 이용자 | Google 로그인 → W02 최초 입력: 표시 이름 확인·수정 → 저장 성공 → 홈 | 홈 도착 전 표시 이름 저장 단계를 포함하는 분기. Google에서 받은 이름의 미리 채움만으로 저장 완료로 취급하지 않음 |
| 표시 이름 저장 전 이탈한 재방문자 | Google 로그인 → 서비스에 저장된 표시 이름 없음 확인 → W02 최초 입력 → 저장 성공 → 홈 | 첫 로그인 여부 대신 저장된 이름 유무를 분기 기준으로 쓰는 안. 조회 실패를 ‘미저장’으로 단정하지 않음 |
| 표시 이름을 이미 저장한 기존 이용자 | Google 로그인 → 홈. 최초 입력 화면을 다시 거치지 않음 | 현재 사용자와 표시 이름 저장 여부를 확인하는 방법. Google 이름 수신 여부와 서비스에 저장된 표시 이름 존재 여부를 구분 |
| 선택 정보 미입력 | 표시 이름 저장 후 홈 진입 허용. 한 줄 소개·직무·기술 스택은 추가 필수 단계로 만들지 않는 제안 | 기존 홈 메뉴·안내와 충돌하지 않게 연결 |

| 프로필을 나중에 작성·수정 | 홈 → 사용자 메뉴 → ‘프로필 수정’ → W02 이후 수정: 서비스에 저장된 값 표시 | 사용자 메뉴의 위치·버튼 및 메뉴 항목 표현·조작 방식, 수정 화면에서 ‘저장’·‘취소’한 뒤 복귀 경로는 홈 담당과 협의. Google 이름으로 기존 값을 덮어쓰지 않는 안 |

홈 PR에서 확인할 지점은 ‘로그인 성공 → 홈’ 설명의 첫 이용자/기존 이용자 분기와 사용자 메뉴의 프로필 수정 진입점이다. 홈·상단 메뉴 배치 등 다른 담당 화면 상세를 이 초안에서 다시 설계하지 않는다. 홈의 분석 결과 연결은 §1.2의 최신 결정을 따른다.

표시 이름 조회 실패는 W01-R에 착지해 ‘다시 불러오기’로 조회를 재시도하고, 최초 입력 저장 실패는 W02에서 입력을 유지하며 저장을 재시도하는 안이다. 조회 실패를 ‘표시 이름 없음’으로 단정하거나 저장 성공으로 간주하지 않는다. 비로그인 사용자의 홈 진입 범위는 이 제안에 포함하지 않는다.

**홈 담당과 별도로 협의할 사항:**

- 로그인 성공 후 이름 저장 유무를 확인할 주체와 시점, 저장 전 이탈한 재방문자 경로, W01-R 조회 실패 안내·재시도 제안의 연결 방식을 맞춘다.
- 홈 사용자 메뉴의 위치와 ‘프로필 수정’ 표현, 회원 화면으로의 진입 방식, 수정 저장·취소 후 돌아갈 위치와 홈 표시 이름 갱신 시점을 맞춘다.
- **세션 만료 → W01 로그인 → 복귀 위치:** 홈에서 만료됐으면 재인증·표시 이름 조회 후 홈으로 돌아가는 안을 제안한다. 프로필 수정·Catch 상세 등에서 만료된 경우 원래 작업 위치와 홈 중 어디로 복귀할지, 복귀 대상의 접근 권한·존재 여부 확인과 접근 불가 시 대체 위치, 미저장 입력 보존·복원을 인증·홈 담당과 협의한다. 이름 미저장자는 우선 W02 최초 입력으로 보내는 안이며 그 저장 후 원래 위치 복귀 여부도 미정이다. 자동 저장·자동 공개·분석 재요청으로 이어지지 않게 한다.
- GitHub 미연결 홈 허용은 팀 합의로 적용한다. 홈의 연결 안내와 분석 시작 전 필요한 권한·동의는 구분하며, Google 계정·선정 저장소 관계 확인과 분석 동의 방식은 팀원 1 조율에 남긴다.
- 홈 → 내 자산 진입은 유지한다. 홈은 분석 상태·결과를 조회하지 않으며, 결과 단위 검토 집계도 제공하지 않는다(§1.2·§5.2).

Catch 상태별 버튼과 W06의 저장·발행 화면 이동 분리는 회원·자산 초안의 제안이다. W06 → L01의 두 연결 조건은 §5.3에 회원·자산 측 수용 답변으로 기록하고, 남은 세부는 링크 담당과 협의하며 홈 PR #28 담당에게 결정 책임을 넘기지 않는다. H01·W01~W06·L01은 이 문서의 연결 표기이며 실제 경로 확정을 뜻하지 않는다. 링크 측 화면 ID는 공유 링크 초안과 대조한다.

### 5.2 10월 결과 단위 검토 집계 제외·Catch별 상태 유지

**[팀장 결정] 10월에는 결과 단위 검토 집계를 두지 않는다.** 홈뿐 아니라 내 자산의 분석 결과 목록에도 적용한다. 결과 전체의 검토 현황·검토 수·불일치 수, 집계 실패·대기 표시와 관련 데이터 요구를 두지 않는다.

근거는 [PR #54 팀장 리뷰](https://github.com/JminAILab/CatchU/pull/54#pullrequestreview-5206413716)와 [머지된 PR #53 최신 후속 입력](https://github.com/JminAILab/CatchU/blob/25f94b0b9ea9efcee9a8269cc4482942e2974dcb/docs/ai-dlc-input-mvp/2026-09-14_followup.md)의 「홈 분석 결과 안내를 알림으로 이동」 절이다. 승인 요구사항에 근거가 없고 12월 알림의 완료·실패 안내에도 필요하지 않아 제외하며, 분석 데이터 초안에서도 다루지 않는다고 명시돼 있다.

- **Catch별 확인·불일치·공개 상태는 유지한다.** W03·W03-R은 각 Catch의 상태를 보여 주고 W04·W05의 확인·공개 선택을 구분한다. 불일치를 확인 완료·사실 검증·공개 동의로 바꾸지 않는다.
- **[화면 제안]** Catch의 확인 완료는 명시적인 확인 행동 후 기록 저장이 성공했을 때 표시한다. 열람·스크롤·분석 완료만으로 확인 완료로 처리하지 않으며 저장 중·실패도 성공으로 표시하지 않는다.
- 결과에 속한 Catch 목록과 0장 여부를 정상 조회하는 것은 화면 연결에 필요한 정보다. 이를 결과 단위 검토 집계와 혼동하지 않는다. 결과 0건의 정상 완료 여부·부분 성공(OQ1·OQ3), 표시 취소·재분석 시 기존 Catch 기록 처리는 별도 미정이다.

### 5.3 공유 링크 초안 §6.2에 대한 회원·자산 측 수용 답변

근거: [이슈 #20 팀장 코멘트](https://github.com/JminAILab/CatchU/issues/20#issuecomment-5660716151), [공유 링크 초안](CatchU_공유링크_흐름_와이어프레임_초안.md) §6.2. 아래는 2026-09-15 작성자(팀원 2)의 **회원·자산 측 수용 답변**이다. 두 초안의 연결 규칙을 맞추는 기록이며 실제 구현 완료, 공식 API 계약 또는 AI-DLC 승인이 아니다.

| 팀원 3의 질문 | 회원·자산 측 수용 답변 | 적용 범위·미정 사항 |
|---|---|---|
| 저장 성공 결과에서 구성 참조·저장본 버전 표식을 제공할 수 있는지 | 대표 구성 저장 성공 결과에서 **구성 참조 + 해당 저장본을 구별하는 버전 표식**을 제공하는 안을 수용한다. L01이 그 저장본에 대응하는 주장 문구·연결 Catch를 식별할 수 있도록 하며, 수정 가능한 구성 ID만으로 저장본을 특정하지 않는다. | 의미상의 전달 정보에 대한 수용이다. 필드명·버전 형식·저장 방식·API 계약은 미정이며, 현재 제공 기능이 구현됐다고 주장하지 않는다. |
| W06의 저장본과 편집 내용 일치 조건을 이동 조건으로 맞출지 | **저장된 대표를 가진 W06 → L01**에서 ‘편집 내용 = 저장본’이고 저장 중·실패 상태가 아닐 때만 [링크 발행으로]를 표시하는 규칙을 수용한다. 재편집하면 버튼을 숨기고 저장을 먼저 안내한다. 저장 중·실패에도 버튼을 숨긴다. | 대표 없는 발행이나 W03·L03 진입에 이 조건을 확대하지 않는다. 저장과 화면 이동·실제 발행은 별도 행동이며 저장만으로 이동·발행하지 않는다. |

**[요구 / 유지할 경계]** 저장본 버전은 현재 공개 권한을 고정하지 않는다. 발행 당시 대표 문구·연결 구성은 보존하되, 현재 숨김 Catch는 기존 링크에서도 열람 대상에서 제외한다(FR3.4). 대표 밖 공개 자산의 열람과 대표 없는 발행을 유지하며(FR3.1·FR3.2), 저장본 버전을 근거로 숨긴 Catch를 다시 공개하거나 다른 카드로 자동 보충하지 않는다.

**링크 측 일치 확인됨 (2026-09-15):** 팀원 3의 [PR #45 확인 댓글](https://github.com/JminAILab/CatchU/pull/45#issuecomment-5673683686)에서 ‘저장 성공 결과의 구성 참조·저장본 버전 표식 제공안’과 ‘저장된 대표를 가진 W06 → L01 버튼 조건’이 공유 링크 초안과 일치함을 확인했다. 댓글은 공유 링크 v0.8과 대조한 기록이며, [공유 링크 문서 v0.9 §6.2](https://github.com/JminAILab/CatchU/blob/176dc54a84df0b2f88f6adb8aa62eeb3639233fe/docs/ai-dlc-input-mvp/CatchU_공유링크_흐름_와이어프레임_초안.md)에도 이 확인이 반영됐다. 두 조건의 내용과 적용 경계는 위 표를 따른다. 이 기록은 두 담당 문서의 일치 확인이며 실제 구현 완료·공식 API 계약·AI-DLC 승인을 뜻하지 않는다. PR #38의 v0.9를 현재 체크아웃의 공유 링크 문서와 동일시하지 않는다.

**남은 협의:** 필드명·버전 형식·저장 방식·API 계약, 동시 변경 판정과 발행 직전 재확인·복귀 조작의 세부는 후속 협의 대상으로 유지한다. 기본 프로필·Catch 본문 버전 정책까지 확정하지 않는다. W06 변경 취소·이탈 안내는 다음 작업으로 남긴다. W03 분석 이력과 결과 목록의 연결은 W03·W03-R·§5.4의 현재 제안을 따르며 실제 연결 합의 전이다. 링크 측 두 조건의 일치 확인을 W03~W06 전체의 검토 완료로 확대하지 않는다.

### 5.4 W03 분석 이력·W03-R 결과 목록 — 홈·분석 연결 조건

**[팀장 확인과 제안 구분]** 분석 상태·결과는 A-02와 내 자산의 GitHub 관련 탭에서 확인하며 홈에는 분석 결과 연결을 두지 않는다(§1.2). 홈 → 내 자산 진입은 유지한다. 아래 탭 표시·결과 목록·복귀 동작과 데이터 항목은 **회원·자산 측 화면·연결 제안**이며 실제 API·담당 간 연결 합의 완료가 아니다.

**[원문 확인 필요 / 계약 미정]** 팀원 1 데이터 초안은 **아직 작성 전이며 #23에서 작성한다**([PR #54 팀장 리뷰](https://github.com/JminAILab/CatchU/pull/54#pullrequestreview-5206413716)). [#23 데이터 초안 입력 등록](https://github.com/JminAILab/CatchU/issues/23#issuecomment-5675898043)의 항목 5~8에 이 문서의 분석 식별·이력 목록·화면 참조·결과 범위·조회 구분이 이미 등록됐다. 동일 항목을 다시 등록하지 않고 이 근거를 연결한다. 후속 입력이 명시한 분석 식별자·저장소명·상태·결과 참조를 공통 정보로 삼되 아래 항목을 실제 데이터 구조·필드명·상태 enum·API·저장 방식으로 확정하지 않는다.

| 연결 주제 | 회원·자산 측 제안 | 데이터·화면 담당에게 확인할 사항 |

## 6. 다음 검토에서 먼저 다룰 질문

기본 로그인 Google OAuth(U1)와 GitHub 미연결 홈 진입 허용(U4)은 **팀 합의(팀장 확인 2026-09-14, 후속 입력 문서, 이 문서 §1.1)**다. U2의 표시 이름만 필수, Google 이름의 수정 가능한 미리 채움, 선택 정보의 나중 작성은 **검토용 제안**으로 유지한다. W01-R·W02 예외는 화면 제안으로 유지한다. §5.2는 최신 팀장 결정에 따라 10월 결과 단위 검토 집계를 제외하며, Catch별 확인·불일치·공개 상태는 유지한다.

U3의 첫 이용자/기존 이용자 분기와 홈 사용자 메뉴 → 프로필 수정은 §5.1의 연결 제안으로 유지한다. 홈 담당과 위치·표현·복귀 방식을 협의하기 전 최종 배치로 표시하지 않는다.

1. Google 계정·선정 저장소 관계 확인(OQ1), 분석 동의(OQ11)와 분석 요청 전 GitHub 연결 필요 여부는 팀원 1이 조율한다. 홈 진입 허용 합의와 구분해 연결 안내 위치·시점을 맞춘다.
2. 표시 이름·선택 정보가 외부 프로필에 어떻게 공개되는지와 수정 시 기존 링크 반영은 OQ3에서 검토한다. 입력 필수 여부와 외부 공개 여부를 합치지 않는다.

필요한 화면을 구체화할 때 관련 쟁점만 1~2개씩 묻는다. 나머지 OQ를 한꺼번에 답하도록 요구하지 않는다.

## 7. 팀 검토·AI-DLC 입력 재사용 기준

이 초안의 작성 목적은 첫 행동·예외·다른 담당 화면으로의 이동을 함께 검토할 수 있게 하는 것이다. 아래는 검토 기준이며 제품 구현 테스트의 통과 기록이 아니다.

- 로그인 성공·취소·실패와 프로필 입력·저장·홈 이동을 설명할 수 있다.
- U2가 팀 확정 정책이 아닌 검토용 제안으로 표시돼 있으며, Google 이름 수신·미수신·수정과 표시 이름만 저장한 홈 진입을 설명할 수 있다.
- 선택 항목 미입력·GitHub 미연결이 홈 진입을 막지 않고, 선택 정보를 나중에 프로필에서 작성하는 경로가 있다.
- U3의 첫 이용자/기존 이용자 분기와 홈 사용자 메뉴의 프로필 수정 진입안, 홈 담당 협의 사항을 PR #28 전달 조건으로 설명할 수 있다.
- 이름 저장 전 이탈한 재방문·조회 실패, 최초 Google 이름 채움과 이후 저장된 값 수정의 차이를 설명할 수 있다.
- W01-R 재조회 성공·반복 실패·세션 만료와 W02 최초 입력의 취소 없음·로그아웃 성공/실패·이탈 후 재방문을 화면 제안으로 설명할 수 있다.
- 프로필 자가 입력값을 GitHub 검증 사실로 표시하지 않는다.
- Catch 설명·근거·질문 확인과 공개 선택이 분리돼 있다.
- 공개 Catch 재열람이 미공개 전환을 일으키지 않으며, 상태별 행동과 미정인 숨김·불일치 복구를 구분한다.
- 불일치 표시·미공개 유지·숨김과 내부 선택 공유의 차이를 설명할 수 있다.
- 대표 주장 1개·Catch 2~3장과 대표 없는 발행 경로가 모두 있다.
- W06 구성 저장과 L01 이동 버튼을 구분하고, 저장 실패·재편집 상태에서 저장 성공으로 표시하지 않는다.
- §5.3의 저장본 식별 정보와 W06 버튼 조건을 회원·자산 측 수용 답변으로 구분하며, 대표 없는 발행·W03·L03 진입에 조건을 확대하지 않는다. 실제 구현·API 계약 확정으로 표시하지 않는다.
- 대표 밖 공개 자산, 기존 링크의 대표 보존, 현재 숨김 제외가 함께 유지된다.
- 홈·분석·링크·내부 검토의 연결 조건과 미정 사항이 드러나 있다.
- 문서 근거·입력 제안·화면 제안·임시 예시가 구분돼 있다.
- 팀 합의 U1·U4와 제안 U2·U3를 구분한다. §5.2에 따라 결과 단위 검토 집계를 두지 않으며, Catch별 확인·불일치·공개 상태와 분석 상태를 구분한다.
- 홈 → 내 자산 진입은 유지하고, W03-R 진입·복귀 출처는 A-02와 분석 이력 탭만 둔다. Catch가 한 장이어도 W03-R을 거쳐 W04로 이동하고 같은 목록으로 복귀한다.
- 완료 결과가 정상 조회로 0장이면 [결과 확인] 없이 정해진 안내를 표시한다. 결과 수 조회 실패·로딩을 0장으로 취급하지 않는다.
- 팀원 1 데이터 초안은 #23에서 작성 전이며 원문 확인 필요로 표시한다. 기존 등록 항목을 참조하고 데이터·API 계약으로 확정하지 않는다.

## 8. 초안 변경 이력

아래 변경 이력은 당시 기록이다. 현재 U1·U4 지위는 v0.6과 §1.1의 팀장 확인을 따른다. 과거 결과 단위 검토 집계 제안·비교안과 v0.8의 홈 최근 분석 한 건·홈 ↔ W03-R 연결은 v0.9에서 대체됐으며 현재 적용안이 아니다.

- v0.1 (2026-09-14): 첫 사용자 흐름·와이어프레임과 요구사항·미결·연결 조건 작성.
- v0.2 (2026-09-14): 작성자(팀원 2)의 당시 확인 U1에 따라 기본 로그인과 W01 버튼을 Google OAuth로 반영. GitHub 연결·분석 동의 및 프로필 자동 채움·공개와 구분하고 로그인 방식 미정 문구와 후속 질문을 갱신. 승인 요구사항·공식 상태·승인 기록은 이 변경 대상에 포함하지 않음.
- v0.3 (2026-09-14): 작성자(팀원 2)의 초안 요청 U2에 따라 표시 이름만 필수, Google 이름 수신 시 수정 가능한 미리 채움, 한 줄 소개·직무·기술 스택의 선택·나중 작성, GitHub 미연결 홈 진입을 반영. 요구사항 요약·분기·W02·홈 연결·검토 기준을 함께 갱신했으며 모두 팀 확정 정책이 아닌 검토용 제안으로 명시.
- v0.4 (2026-09-14): U2의 필수·선택 제안을 유지하면서 U3의 첫 이용자/기존 이용자 홈 진입 분기와 홈 사용자 메뉴의 프로필 수정 진입안을 정리. §5.1에 홈 PR #28 검토 시 전달할 연결 조건과 위치·표현·복귀 협의 사항을 추가. 다른 담당 화면 수정·PR 댓글 게시·팀 정책 확정은 포함하지 않음.
- v0.5 (2026-09-14): #20 범위에서 이름 미저장 재방문 분기, W02 최초 입력·이후 수정, W04 상태별 행동, W06 저장과 링크 발행 화면 이동을 **화면·연결 제안**으로 보완. §5.1에 홈 PR #28 협의 목록, §7.1에 완료 기준별 검증·미검토 범위를 정리. U4의 GitHub 미연결 홈 진입은 허용 안을 유지하되, 확인한 기록의 날짜·문서·해당 내용과 한계를 §1.1에 남기고 **회의 결정 근거 확인 필요**로 구분. v0.3·v0.4는 당시 요청 이력이며 현재 지위는 U4·§1.1을 따름.
- v0.6 (2026-09-14): PR #29 팀장 리뷰와 PR #27 후속 입력의 팀장 확인을 근거로 U1·U4·§1.1·W02 GitHub 안내를 팀 합의로 갱신. 표시 이름 조회 실패 착지·재시도(W01-R), 최초 프로필 입력의 취소 없음·로그아웃·이탈 처리를 화면 제안으로 구체화. §5.1에 세션 만료 후 로그인·복귀 협의, §5.2에 Catch 확인 기준과 결과 단위 전체·일부 확인 집계 제안을 추가. 작성자 지칭을 ‘작성자(팀원 2)’로 통일. W03~W06 상세 검토는 다음 작업에 남기고 계정·저장소 연결은 팀원 1, W06 → 링크 발행 조건은 링크 담당과 협의. AI-DLC 상태·승인 기록은 갱신하지 않음.
- v0.7 (2026-09-15): 이슈 #20 팀장 코멘트와 공유 링크 초안 §6.2에 따라 W06·§5.3에 구성 참조·저장본 버전 표식 제공안과 저장된 대표를 가진 W06 → L01 버튼 조건의 회원·자산 측 수용 답변을 기록. 대표 없는 발행·W03·L03 진입으로 조건을 확대하지 않고 현재 숨김 제외·발행 당시 대표 보존을 유지. API·저장 방식·동시 변경 등은 미정이며 실제 구현 완료·공식 승인을 뜻하지 않음.
- v0.8 (2026-09-15): 이슈 #20 팀장 댓글·PR #46 후속 입력을 근거로 내 자산의 GitHub 관련 분석 이력과 홈 최근 요청 한 건을 팀장 확인으로 구분. 작성자(팀원 2) 검토에 따라 W03의 기존 Catch 목록을 유지하고 이력 탭·W03-R 결과 목록·빈 목록·로딩·조회 실패를 추가. 홈·A-02·이력의 결과 버튼 → 같은 W03-R → W04 → 같은 결과 목록 복귀를 한 장인 경우에도 적용하는 회원·자산 측 화면·연결 제안으로 기록. 화면 목록·사용자 흐름·§5 연결 조건·검토 범위를 함께 맞춤. 홈·분석 담당 합의 완료가 아니며 팀원 1 데이터 초안은 원문 확인 필요. 결과 0건·부분 성공·동시 분석 수·재분석 경로와 데이터·API는 미정, W06 변경 취소·이탈은 범위 밖으로 유지. 로컬 문서만 수정하며 공식 AI-DLC 상태·승인 기록은 변경하지 않음.
- v0.9 (2026-09-16): PR #54 팀장 리뷰와 PR #53으로 dev에 반영된 최신 후속 입력에 맞춰 홈 최근 분석 한 건·홈 ↔ W03-R 연결을 제거하고 홈 → 내 자산은 유지. W03-R은 A-02·분석 이력에서만 진입·복귀하도록 화면 목록·흐름·연결 조건·검토 기준을 갱신. 10월 결과 단위 검토 집계 제외 결정에 따라 기존 집계 제안·비교표·현황·실패·대기 표시와 데이터 요구를 제거하고 Catch별 상태는 유지. 완료·Catch 0장이 정상 조회로 확인되면 결과 버튼 없이 ‘이번 분석에서 검토할 Catch가 없습니다’를 표시하도록 머지된 A-02 문서와 맞추고 조회 실패와 구분. 팀원 1 데이터 초안은 #23에서 작성 전·원문 확인 필요로 기록하고 기존 등록 근거를 연결. 데이터·API, 결과 0건의 정상 완료 여부·부분 성공·동시 분석 수·재분석 경로는 미정 유지. W06 변경 취소·이탈 및 #55 헤더 개편은 포함하지 않음. 로컬 문서만 수정하며 커밋·푸시·원격 갱신·공식 AI-DLC 기록 변경은 하지 않음.
