# CatchU 10월 MVP — 회원·자산·대표 사용자 흐름과 와이어프레임

작성일: 2026-09-14 · 판본: v0.6 · 지위: **공동 검토용 화면 초안 / 미승인 AI-DLC 입력 후보**

이 문서는 작성자(팀원 2) 담당 영역의 첫 검토 자료다. 팀 합의 사항은 출처와 함께 반영하며, 이 초안 작성 자체는 별도 intent 생성이나 공식 단계 진행·승인, 새로운 제품 정책 확정을 의미하지 않는다. PC 웹의 상자·텍스트·버튼 배치만 표현하며 실제 코드·API·저장·분석 결과는 포함하지 않는다. 이후 검토에서 화면별로 구체화한다.

최초 초안의 저장소 기준 커밋: `622416602cedbaaefec8a3becd19c7adefd0517a`. v0.6은 PR #29의 v0.5 커밋 `4b037a0d234486d6f6623f515bc1a2a8ebd3845e`에 대한 리뷰를 반영한다. M이 발췌한 승인본 기준은 `3cd01aa`다. 원문과 과거 승인 기록은 수정하지 않는다.

- **[요구]**: 승인 문서가 정한 행동. 화면 배치나 버튼 형태까지 승인됐다는 뜻은 아니다.
- **[입력 제안]**: M에서 제안으로 제시한 내용. 아직 정책 확정이 아니다.
- **[팀 합의]**: 팀장 확인과 후속 입력 문서로 확인한 제품 행동. 과거 승인 원문은 소급 수정하지 않는다. 작성자(팀원 2)의 초안 요청과 구분한다.
- **[화면 제안]**: 이번 초안에서 제시하는 배치·이동·문구·조작 방식.
- **[미정]**: 후속 합의가 필요한 사항. 구현 계약이나 저장 상태값으로 사용하지 않는다.
- **[임시 예시]**: 이해를 위한 가상 데이터. 실제 GitHub 기록·분석 결과·처리 성공 증거가 아니다.

모든 와이어프레임의 배치·버튼 배치는 [화면 제안]이다. 기능의 근거는 각 화면 설명으로 구분한다. 홈과 분석, 링크 발행·수신자 화면은 연결 조건만 남긴다. 팀 조율 상대는 이번 요청에 따라 팀원 2로 두되 M §2.5의 담당 제안표 자체를 변경하지 않는다. 작성자(팀원 2)의 GitHub 계정이나 다른 팀원의 실제 배정을 추정하지 않는다.

### 1.1 기본 로그인·GitHub 미연결 홈 진입 — 팀장 확인

**팀 합의(팀장 확인 2026-09-14, 후속 입력 문서).** 기본 로그인은 Google OAuth(U1)이며, GitHub 연결 없이 홈 진입을 허용한다(U4). 별도 회의 기록은 없고 팀장이 PR #29 리뷰에서 확인한 뒤 후속 입력 문서에 기록했다. v0.5의 ‘회의 결정 근거 확인 필요’는 이 후속 확인으로 해소됐다. 확인일을 과거 회의 개최일로 해석하지 않는다.

| 확인한 기록 | 날짜·해당 내용 | 효력과 경계 |
|---|---|---|
| [PR #29 팀장 리뷰](https://github.com/JminAILab/CatchU/pull/29#issuecomment-5659394192) | 2026-09-14, 팀장 `ljm0850`이 Google OAuth 기본 로그인과 GitHub 미연결 홈 진입 허용 모두 팀 합의라고 확인 | W02의 GitHub 안내도 팀 합의로 표기. 표시 이름 필수·선택 항목과 화면 연결 제안까지 승인한 것은 아님 |
| [PR #27 후속 입력 문서](https://github.com/JminAILab/CatchU/blob/6acab4acdd2b309b424eb8f36501689163181528/docs/ai-dlc-input-mvp/2026-09-14_followup.md)의 「팀장 확인 (2026-09-14): 인증·홈 진입」 | 2026-09-14 확인한 PR #27 커밋 `6acab4acdd2b309b424eb8f36501689163181528`에 반영돼 있음. 기본 로그인은 Google OAuth, GitHub 연결 없이 홈 진입 허용, 홈 진입은 분석 동의·실행 허용과 별개라고 명시 | PR 브랜치의 후속 입력이며 공식 단계 승인이 아님. 다른 로그인 수단의 추가·배제와 계정 연결 상세는 미정 |

**남은 조율:** Google 계정과 사전 선정 저장소의 소유·커밋 관계 확인 방법(OQ1), 분석 동의 방식(OQ11), 분석 요청 전 GitHub 연결 필요 여부는 **팀원 1이 조율**한다. 이 초안에서 확정하지 않는다. 위 표에 결정 내용을 풀어 적어 외부 기록을 열지 않아도 팀 합의와 미결 경계를 읽을 수 있게 했다.

## 3. 화면 목록과 사용자 흐름

| ID | 화면·상태 | 주요 행동 | 연결 |
|---|---|---|---|
| W01 | Google 로그인 | Google로 계속하기, 취소·실패 후 재시도 | W02 또는 홈 연결 H01 |
| W01-R | 로그인 후 표시 이름 조회 대기·실패 상태 | 다시 불러오기, 로그아웃 [화면 제안] | 조회 성공 → W02 또는 H01. 세션 만료 → W01 |
| W02 | 기본 프로필 최초 입력 / 이후 수정 | 표시 이름 확인·수정, 선택 항목 입력 또는 나중 작성, 저장 [검토용 제안 U2] | 최초 입력 저장 → H01. 수정 후 복귀는 홈 담당 협의 |
| H01 | 홈 진입 연결 지점 | 프로필·내 자산·대표 구성 진입점을 전달 | 홈 담당 화면. 내부 배치 상세 제외 |
| W03 | 내 자산 목록 | Catch 상태 확인, 상세 열기 | W04, W06 |
| W04 | Catch 상세 | 초안·근거·질문 확인, 확인 완료, 불일치 표시, 공개 자산 숨김 | 상태별 행동표에 따라 W05 또는 상세 유지 |
| W05 | 확인 완료·공개 선택 | 지금 공개 / 미공개 유지 | W03·W04 |
| W06 | 대표 구성 | 주장 직접 작성, Catch 2~3장 선택, 구성 저장 | 저장 후 W06 유지 → 별도 ‘링크 발행으로’ → L01 [화면 제안] |

W05는 W04 안의 완료 패널로 표현한다. 별도 페이지 여부는 제안 단계다. W06의 Catch 선택도 한 화면 안에 두어 첫 검토에서는 별도 모달을 늘리지 않는다.

**이번 보완 범위는 W01·W01-R·W02·홈 연결이다.** W03~W06의 기존 초안은 다음 작업에서 팀원 3 의견과 함께 상세 검토한다. 이번에는 §5.2의 Catch 확인 집계 연결 제안만 추가하며 W06 → 링크 발행 조건은 링크 담당과 합의한다.

```text
로그인 후 홈 진입 [연결 제안 U3 — 팀 확정 정책이 아님]
W01 [Google로 계속하기] → Google 인증 → CatchU 복귀
  ├─ 취소·실패 → W01 안내 → 다시 시도
  └─ 성공 → 서비스에 저장된 표시 이름 유무 확인 [연결 제안]
      ├─ 저장된 표시 이름 없음 → W02 최초 입력: 표시 이름 확인・수정
      │   (첫 이용자 + 이전 로그인 후 저장 전 이탈한 재방문자)
      │   (Google 이름을 받으면 미리 채움, 없으면 직접 입력)
      │       → 표시 이름 저장 성공 → H01 홈
      ├─ 표시 이름을 이미 저장한 기존 이용자 → H01 홈
      └─ 조회 실패 → W01-R 안내 → [다시 불러오기] → 표시 이름 유무 재조회
          ├─ 다시 실패 → W01-R 유지
          └─ 세션 만료 확인 → W01 재로그인 안내
         ※ U2 제안: 표시 이름만 필수, 선택 항목은 홈 진입을 막지 않음
         ※ 팀 합의 U4: GitHub 미연결도 홈 진입 허용(§1.1)
W02 최초 입력 → [로그아웃] → 로그아웃 성공 → W01 [화면 제안]
         ※ 취소 없음. 저장 전 이탈 시 재방문 규칙 적용. 상세는 W02 설명
```

## 4. PC 웹 와이어프레임

### W01 — 로그인

```text
┌──────────────────────────────────────────────────────────────┐
│ CatchU                                                       │
├──────────────────────────────────────────────────────────────┤
│                      CatchU 시작하기                         │
│               내 경험과 근거를 정리해 전달합니다.             │
│                                                              │
│                  [Google로 계속하기]                         │
│                                                              │
│ 안내 영역: 로그인 취소 / 로그인 실패 시 문구                  │
│                  [다시 시도]  ← 실패 상태                     │
└──────────────────────────────────────────────────────────────┘
```

- **[팀 합의 U1]** 기본 로그인은 Google OAuth다(팀장 확인 2026-09-14, 후속 입력 문서 §1.1). 버튼 문구는 ‘Google로 계속하기’라는 화면 제안이다. Google 인증 화면은 외부 연결로 표시하고 이 문서에서 상세 설계하지 않는다.
- **[화면 제안]** 인증 성공 후 서비스에 저장된 표시 이름 유무로 분기한다. 첫 로그인뿐 아니라 저장 전 이탈한 재방문자도 W02 최초 입력으로 연결한다. 이름을 이미 저장했다면 홈으로 이동한다. 조회 실패는 W01-R로 구분하며, Google 인증 취소·실패는 W01에서 다시 시도한다.
- **[요구 경계]** 로그인 성공을 저장소 분석 동의, Catch 공개, 내부 품질 검토 공유로 취급하지 않는다(FR1.1·FR4.1·FR10.2).
- **[미정]** 최초 Google 로그인 시 계정 생성 방식, 약관·동의 안내 내용과 위치, 세션 만료 후 복귀 정책. Google 계정·선정 저장소 관계 확인과 분석 동의는 팀원 1이 조율한다(OQ1·OQ11). 아래 로그아웃·재시도는 화면 제안이며 인증 계약 확정이 아니다. 기본 로그인 결정만으로 다른 로그인 수단이나 이메일·비밀번호 가입/재설정 기능을 추가하지 않는다.

### W01-R — 로그인 직후 표시 이름 조회 대기·실패

**[화면 제안]** 인증 성공 후 표시 이름을 조회하는 동안 회원 영역의 이 상태에 머문다. W01-R은 설명용 화면 ID이며 별도 URL·페이지 생성은 확정하지 않는다. 실패 시 빈 W02나 홈으로 이동하지 않는다.

```text
┌──────────────────────────────────────────────────────────────┐
│ CatchU                                          [로그아웃]   │
│ 로그인은 완료됐지만 프로필을 불러오지 못했습니다.            │
│ 표시 이름 저장 여부를 확인한 뒤 계속할 수 있습니다.           │
│                                         [다시 불러오기]     │
│ 재조회 중: 프로필을 불러오는 중입니다.                        │
└──────────────────────────────────────────────────────────────┘
```

- 최초 조회·재조회 중에는 로딩 안내를 표시하고 ‘다시 불러오기’를 비활성화해 중복 요청을 막는 안이다. 실패하면 위 안내와 활성 버튼을 표시한다. 상자는 서로 다른 상태의 문구 예시이며 실제 로그인·조회 결과가 아니다.
- ‘다시 불러오기’는 현재 로그인 세션으로 표시 이름 저장 여부만 다시 조회한다. 유효한 세션에서 Google 인증을 반복하지 않는다. 성공하면 이름 미저장자는 W02, 저장자는 H01로 이동한다. 재실패하면 같은 화면에서 다시 시도할 수 있고 자동 재시도하지 않는다.
- 세션 만료가 확인되면 W01로 이동해 ‘로그인이 만료되었습니다. 다시 로그인해 주세요’라고 안내한다. 재인증 후 표시 이름을 다시 조회한다. 홈·다른 작업 중 만료 후 원래 위치 복귀는 §5.1 협의 사항이다.
- ‘로그아웃’은 CatchU 세션 종료 성공 후 W01로 이동한다. 실패하면 이 상태에서 실패 안내와 재시도를 제공한다. Google 계정 전체 로그아웃·연결 해제는 의미하지 않는다. 조회 실패를 이름 없음으로 간주하거나 Google 이름으로 대체 저장하지 않는다.

### W02 — 기본 프로필

**검토용 제안 U2:** 표시 이름만 필수로 두고, 나머지 항목은 비워 둔 채 홈에 들어갈 수 있게 한다. 필수·선택 구분은 팀 확정 정책이 아니다. **상자의 GitHub 미연결 홈 진입 안내는 팀 합의 U4를 반영한 안내**이며 검토용 정책 표기를 해제한다. 배치와 나머지 조작은 화면 제안이다.

아래 상자는 **최초 입력 상태**다. 저장 전 이탈한 재방문자도 이 상태로 연결한다. 최초 입력과 이후 수정은 같은 W02의 표시 상태 구분이며 별도 페이지·API를 확정하는 것이 아니다.

```text
┌──────────────────────────────────────────────────────────────┐
│ CatchU                     기본 프로필          [로그아웃]   │
├──────────────────────────────────────────────────────────────┤
│ 사용할 표시 이름을 확인해 주세요.                            │
│                                                              │
│ 표시 이름 (필수) [한지우                                 ]    │
│ Google에서 받은 이름을 미리 채웠습니다. 수정할 수 있습니다.  │
│                                                              │
│ 선택 정보 — 지금 비워 두고 나중에 프로필에서 작성해도 됩니다.│
│ 한 줄 소개 (선택) [                                     ]    │
│ 직무 (선택)      [                                     ]    │
│ 기술 스택 (선택) [기술 추가]                                 │
│                직무·기술 스택은 직접 입력한 정보입니다.        │
│ GitHub 계정을 연결하지 않아도 홈에 들어갈 수 있습니다.        │
│                                                              │
│ 입력 오류 / 저장 실패 안내 영역                               │
│                                       [저장하고 홈으로]      │
└──────────────────────────────────────────────────────────────┘
```

- ‘한지우’와 Google 이름 수신 안내는 **[임시 예시]**다. 실제 인증 결과가 아니다. 직무·기술 스택의 입력 방식과 기술 추가 조작은 **[화면 제안]**으로 유지한다.
- **[검토용 제안 U2]** 이름은 서비스에서 사용할 **표시 이름**이며 유일한 필수 프로필 항목이다. Google 이름을 받으면 입력란에 미리 채우되 사용자가 자유롭게 수정할 수 있게 한다. 실명 인증·이름의 유일성을 보장한다는 의미가 아니다.
- **[화면 제안]** Google 이름을 받지 못하면 표시 이름 입력란을 비워 두고 직접 입력하게 한다. 빈 상태로 저장을 시도하면 ‘표시 이름을 입력해 주세요’라고 안내하며 홈 이동을 완료하지 않는다. 미리 채운 이름도 사용자가 ‘저장하고 홈으로’를 선택해 저장한다.
- **[검토용 제안 U2]** 한 줄 소개·직무·기술 스택은 선택이다. 모두 비워 두어도 표시 이름을 저장하면 홈으로 이동할 수 있고, 나중에 프로필 수정에서 작성할 수 있다. 선택 항목의 미입력을 ‘프로필 미완료’로 표시하거나 홈 진입을 막는 조건으로 사용하지 않는다.
- **[팀 합의 U4 / 연결 경계]** GitHub 연결 없이 홈 진입을 허용한다(팀장 확인 2026-09-14, 후속 입력 문서 §1.1). 상자의 GitHub 안내는 이 합의를 반영한다. Google 로그인·GitHub 연결·저장소 분석 동의는 구분하며, Google 계정과 선정 저장소의 관계 확인·분석 동의 방식은 팀원 1 조율에 남긴다. 이 화면에 GitHub 연결 강제 단계를 넣지 않는다.
- **[미정]** 표시 이름 길이·허용 문자·중복 규칙, 선택 항목의 길이·개수·목록, 프로필 공개 범위와 기존 링크 반영. Google 이름의 미리 채움을 프로필 자동 공개나 이메일 수집·공개로 확대하지 않는다. U2의 필수·선택 구분은 팀 검토 전 제안 상태다.
- **[화면 제안]** 최초 입력은 저장 성공 시에만 홈으로 이동하고, 실패 시 입력을 유지하며 같은 자리에서 안내한다. 저장 성공·실패는 설명용 분기이며 실제 처리 결과가 아니다. 이후 수정은 아래 상태에 따른다.
- **[화면 제안]** 선택 항목마다 별도 건너뛰기 버튼을 두지 않고 ‘나중에 프로필에서 작성할 수 있습니다’ 안내와 ‘저장하고 홈으로’ 버튼으로 진행한다. **연결 제안 U3:** 이후 수정은 홈 사용자 메뉴의 ‘프로필 수정’에서 진입한다. 메뉴의 위치·표현과 수정 후 복귀 경로는 홈 담당과 협의한다(§5.1).

**최초 입력의 취소·로그아웃·이탈 [화면 제안]:**

- **취소 없음, 이탈 시 재방문 규칙 적용.** 최초 입력에는 ‘취소’나 이름 저장을 생략하는 홈 이동 버튼을 두지 않는다. 이후 수정 화면의 ‘취소’와 구분한다.
- 대신 ‘로그아웃’을 제공한다. 선택하면 미저장 입력은 저장하지 않고 CatchU 세션 종료를 요청한다. 처리 중에는 저장·로그아웃 버튼을 비활성화하는 안이다. 성공하면 W01로 이동하고 미저장 입력은 폐기한다. Google 계정 전체 로그아웃이나 계정 삭제가 아니다.
- 로그아웃 실패 시 W02와 입력을 유지하며 ‘로그아웃하지 못했습니다. 다시 시도해 주세요’라고 안내하고 버튼을 다시 사용할 수 있게 한다. 저장 중에는 완료·실패 응답 전 로그아웃을 중복 요청하지 않는 안이다.
- 탭 닫기·뒤로 가기 등으로 저장 전 이탈하면 자동 저장하거나 홈 진입 완료로 처리하지 않는다. 재방문 시 세션이 유효하면 이름 조회부터, 만료됐다면 W01 로그인부터 다시 진행한다. 서버에 저장된 이름이 없으면 최초 입력으로 돌아오며 미저장 입력 복원을 약속하지 않는다. 저장 요청 후 응답을 받기 전에 이탈했다면 실제 저장 여부를 재조회한 결과로 분기한다.
- 입력 중 세션 만료가 확인되면 자동 제출 없이 W01로 이동해 재로그인을 안내하는 안이다. 미저장 값 보존·복원 여부와 원래 위치 복귀는 §5.1에서 협의한다.

**이후 수정 상태 [화면·연결 제안]:**

```text
┌──────────────────────────────────────────────────────────────┐
│ 프로필 수정                                                  │
│ 서비스에 저장된 프로필을 불러왔습니다.                        │
│ 표시 이름 (필수) [내가 저장한 이름                       ]    │
│ 한 줄 소개·직무·기술 스택 (선택): 저장된 값 또는 빈 입력란    │
│ 조회 실패 / 저장 실패 / 저장 성공 안내 영역                    │
│                                           [취소] [저장]     │
└──────────────────────────────────────────────────────────────┘
```

- Google에서 다시 받은 이름으로 저장된 표시 이름을 덮어쓰지 않는다. ‘Google 이름을 미리 채웠습니다’ 안내도 최초 입력에만 표시한다. 위 값은 임시 예시다.
- 이후 수정에서는 ‘저장하고 홈으로’ 대신 ‘저장’을 사용하고 저장 결과를 알린다. 취소는 수정 내용을 저장하지 않는 안이다. 저장·취소 후 홈 복귀 또는 화면 유지 여부는 §5.1에서 협의하며 자동 이동으로 확정하지 않는다.
- 조회 실패를 빈 프로필로 바꾸거나 Google 이름으로 대체해 저장하지 않는 안을 제안한다. 조회 실패 안내·재시도와 수정 중 이탈 안내의 세부 조작은 연결 검토에 남긴다.

### H01 — 홈 연결 범위

```text
┌──────────────────────────────────────────────────────────────┐
│ 홈 담당 화면                                                 │
│                                                              │
│ 사용자 메뉴 → [프로필 수정] → 회원 영역 W02  (연결 제안)      │
│ 그 밖의 연결할 행동: [내 자산] [대표 구성]                     │
│ 사용자 메뉴의 위치·표현은 홈 담당과 협의                       │
│ 분석 시작·진행 상태·다음 행동의 실제 배치는 홈 담당과 협의      │
└──────────────────────────────────────────────────────────────┘
```

이 상자는 홈 와이어프레임 완성안이 아니라 **연결할 행동 목록**이다. **연결 제안 U3:** 표시 이름 미저장자는 첫 이용·재방문 여부와 관계없이 확인·저장 후, 저장한 기존 이용자는 로그인 후 홈에 진입한다. **검토용 제안 U2:** 선택 정보가 비어 있어도 홈 진입을 막지 않는다. **팀 합의 U4:** GitHub 미연결 홈 진입을 허용한다(§1.1). 선택 정보는 홈 사용자 메뉴의 ‘프로필 수정’에서 나중에 작성하는 안이다. 홈 PR #28의 화면·메뉴는 직접 변경하지 않으며 위치·표현은 담당자 협의 사항으로 남긴다.

### W03 — 내 자산 목록

```text
┌──────────────────────────────────────────────────────────────┐
│ CatchU     [홈]     내 자산                      [대표 구성]  │
├──────────────────────────────────────────────────────────────┤
│ 내 Catch                                  [링크 발행으로]    │
│ 공개·숨김은 모든 링크에 적용됩니다.                            │
│                                                              │
│ C-A  API 오류 응답 정리                                       │
│      확인 전 · 미공개                           [상세 확인]   │
│ ──────────────────────────────────────────────────────────── │
│ C-B  중복 요청 방지                                           │
│      확인 완료 · 공개                          [상세 확인]   │
│ ──────────────────────────────────────────────────────────── │
│ C-C  테스트 보강                                              │
│      불일치 표시 있음 · 미공개                  [상세 확인]   │
│ ──────────────────────────────────────────────────────────── │
│ C-D  요청 기록 정리                                           │
│      확인 완료 · 숨김                          [상세 확인]   │
└──────────────────────────────────────────────────────────────┘
```

- C-A~C-D는 각각 독립적인 **[임시 예시]**다. 실제 카드 ID·제목·분석 건수가 아니다.
- **[화면 제안]** 확인 여부, 공개 여부, 불일치 여부를 구분해 표시한다. 불일치 표시를 사람이 검토 중·해결 완료 같은 처리 상태로 바꾸지 않는다.
- **[화면 제안]** 최초 미공개와 공개 후 숨김을 구분해 보여주되 둘 다 외부 열람 불가다. 내부 저장 상태값을 이 표기로 확정하지 않는다.
- **[화면 제안]** 카드가 없으면 ‘아직 확인할 Catch가 없습니다’와 분석 담당 화면 이동을 제공한다. 조회 실패는 ‘Catch 없음’으로 표시하지 않고 별도 실패 안내와 다시 불러오기를 둔다.
- **[요구]** 대표가 없어도 링크 발행 화면 진입을 허용한다(FR3.1). 발행 화면 내부와 수신자 화면 상세는 제외한다.

### W04 — Catch 상세·불일치·숨김

```text
┌──────────────────────────────────────────────────────────────┐
│ [내 자산으로]                Catch 상세                       │
│ API 오류 응답 정리       확인 전 · 미공개                     │
├──────────────────────────────────┬───────────────────────────┤
│ 자동 생성 설명 초안              │ 근거                      │
│                                  │ [PR 예시 A]               │
│ 무엇을 했나                      │ [커밋 예시 B]             │
│ 오류 응답 형식을 정리했다.       │ 원문 연결 위치            │
│ [근거 예시 A]                    │                           │
│                                  │ 생각해볼 질문             │
│ 판단의 흐름                      │ 어떤 사용 상황 때문에     │
│ 기록에서 확인 가능한 내용 자리   │ 변경이 필요했나요?        │
│                                  │                           │
│ 궤적 및 기록                     │                           │
│ 변경 순서와 연결 근거 자리       │                           │
│                                  │                           │
│ 기록에 없는 것                   │                           │
│ 판단 이유를 확인할 기록이 없음   │                           │
├──────────────────────────────────┴───────────────────────────┤
│ 설명 문구는 직접 수정할 수 없습니다.                          │
│ 나의 해석·보완은 대표 주장에 작성할 수 있습니다.              │
│                                                              │
│ [불일치 표시]                             [확인 완료]        │

```

- 설명·PR·커밋·질문은 전부 **[임시 예시]**이며 실제 원문 URL을 꾸며 넣지 않는다. 실제 데이터에서는 근거와 생성 설명을 연결해야 한다(FR2.1·FR2.2).
- 4구획 방향은 R의 의도 분석에 있고, 위 제목·문장별 근거 배치는 M OQ3의 **[입력 제안]**을 따른다. 근거에 없는 이유나 성과 수치를 사실로 채우지 않는다.
- **[요구]** 확인과 공개는 별개다. 위 상자의 확인 전·미공개 Catch는 ‘확인 완료’ 후에도 미공개를 유지하고 W05에서 별도 공개 선택을 받는다. 이미 공개된 Catch를 다시 보는 행동으로 미공개로 바꾸지 않는다(FR4.1). Catch 설명 수정·오류 문구 재생성 버튼은 10월에 제공하지 않는다(FR3.5·FR3.6).

**상태별 행동 표시 [화면 제안]:** 위 상자는 확인 전·미공개 상태에만 해당한다. 다음 표는 화면 행동의 구분이며 내부 상태값이나 복구 정책의 확정이 아니다.

| 현재 상태 | 보여줄 행동 | 행동 결과·경계 |
|---|---|---|
| 확인 전 · 미공개 · 불일치 없음 | ‘확인 완료’, ‘불일치 표시’ | 확인 완료 → 미공개 유지 + W05. 불일치는 아래 별도 조작 영역 |
| 확인 완료 · 미공개 · 불일치 없음 | ‘공개 선택’, ‘불일치 표시’ | 공개 선택 → W05의 별도 공개 선택. ‘확인 완료’를 다시 요구하지 않음 |
| 확인 완료 · 공개 · 불일치 없음 | ‘숨기기’, ‘불일치 표시’ | 상세 재열람만으로 상태 변경 없음. ‘확인 완료’·W05로 되돌리지 않음. 숨김 선택 시 기존 링크 열람 제외를 안내 |
| 숨김 또는 불일치 표시 있음 | 현재 상태·사유 안내 | 일반 ‘확인 완료’로 복구하지 않음. 표시 취소·재공개 조건과 버튼은 미정 |

불일치 조작 영역 **[화면 제안]**:

```text
┌──────────────────────────────────────────────────────────────┐
│ 불일치 표시                                                  │
│ 어떤 부분이 기록과 맞지 않나요?                               │
│ ( ) 설명 내용   ( ) 경험 묶음   ( ) 기여한 사람                │
│     위 유형 명칭·단일/복수 선택은 제안                        │
│                                                              │
│ 유형·건수는 내부 품질 확인에 사용됩니다.                      │
│ 이 행동만으로 설명·근거 전체를 팀에 공유하지 않습니다.        │
│                                                              │
│ [취소] [불일치 표시하고 미공개 유지]                          │
│ 공개 상태였다면 버튼: [불일치 표시하고 숨기기]                │
│                                                              │
│ [이 Catch의 설명·근거를 내부 검토에 별도 공유하기]             │
│ → 별도 선택·안내 화면으로 연결. 자동 동의하지 않음             │
└──────────────────────────────────────────────────────────────┘
```

- **[요구]** 불일치 신호는 FR10.1에, 선택된 설명·근거 공유는 FR10.2·NFR7에 따른다. 별도 공유는 기업 공개를 뜻하지 않는다. 공유 권한·철회·보관은 M OQ10과 연결해 후속 구체화한다.
- **[화면 제안]** 한 버튼의 명칭에 불일치 표시와 미공개/숨김 효과를 모두 적어 사용자가 선택하게 한다. 불일치 표시를 했다는 사실만으로 모든 경우에 자동 숨김이 실행된다고 정책을 확정하지 않는다.
- **[요구/안내 제안]** 숨김 전 ‘이 Catch는 기존 링크에서도 보이지 않게 됩니다. 다른 공개 자산과 링크 자체는 유지됩니다’라고 알린다(FR3.2·FR3.4·FR4.1). 저장 실패 시 완료로 표시하지 않는 안내는 화면 제안이다.
- **[미정]** 표시 취소, 재공개 조건, 대표에 포함된 카드 숨김 후 편집 화면의 경고·수량 판정. 기존 링크의 다른 카드로 자동 대체하지 않는다.
- **[연결 상태]** 원본 비공개가 확인되면 관련 Catch의 외부 열람 중단 이유를 알린다. 본인 화면에서 설명을 계속 볼 수 있는지는 OQ2가 결정하므로 이 초안으로 보관·복구를 약속하지 않는다. 일시적 근거 접근 실패는 별도의 접근 실패 안내로 둔다.

### W05 — 확인 완료 후 공개 선택

```text
┌──────────────────────────────────────────────────────────────┐
│ Catch 확인을 완료했습니다.                                   │
│ 현재는 미공개이며, 확인만으로 공개되지 않습니다.              │
│                                                              │
│ 공개하면 유효한 전달 링크에서 열람할 수 있습니다.              │
│ 대표로 선택하지 않아도 공개 자산에 포함됩니다.                │
│                                                              │
│ [지금 공개]                              [미공개 유지]        │
└──────────────────────────────────────────────────────────────┘
```

- **[요구]** ‘지금 공개’를 기본 행동으로 제안하되 자동 실행·사전 동의로 처리하지 않는다(FR4.1). 기업 검색 참여 같은 12월 동작을 묶지 않는다.
- **[화면 제안]** 공개 선택의 저장 성공을 확인한 뒤 공개 상태로 보여주고, 실패 시 완료 안내 대신 재시도 안내를 둔다. 이는 API 계약 확정이 아니다.
- 이 패널은 확인 완료·미공개·불일치 없음 상태의 공개 선택이다. 이미 공개된 Catch의 재열람에는 띄우지 않는다. 숨김·불일치 표시된 카드의 해제·재공개 흐름은 미정으로 분리한다.

### W06 — 대표 주장 작성·Catch 선택

```text
┌──────────────────────────────────────────────────────────────┐
│ [내 자산으로]                 대표 구성                       │
│ 대표 주장 1개와 Catch 2~3장을 한 벌로 구성합니다.              │
├─────────────────────────────┬────────────────────────────────┤
│ 대표 주장 직접 작성         │ 연결할 Catch 선택              │
│ ┌─────────────────────────┐ │ 선택: 2장 / 2~3장              │
│ │예외 상황을 고려해 API의 │ │                                │
│ │안정성을 개선했습니다.  │ │ [✓] API 오류 응답 정리         │
│ └─────────────────────────┘ │     공개 · 확인 완료 [근거 보기]│
│ 자신의 해석·보완을 작성    │ [✓] 중복 요청 방지              │
│                            │     공개 · 확인 완료 [근거 보기]│
│                            │ [ ] 요청 기록 정리              │
│                            │     공개 · 확인 완료 [근거 보기]│
├─────────────────────────────┴────────────────────────────────┤
│ 구성 미리보기: 위 주장 + 선택한 Catch 2장                      │
│ 대표 밖의 공개 Catch도 링크에서 열람할 수 있습니다.           │
│ 기존 링크의 대표 문구·연결 구성은 발행 당시 상태를 유지합니다.│
│                                                              │
│ [대표 구성 없이 링크 발행으로]               [구성 저장]     │
│ 저장 성공 상태: 구성을 저장했습니다.        [링크 발행으로] │
└──────────────────────────────────────────────────────────────┘
```

- 이 화면의 값은 W03과 다른 **[임시 예시 상태]**다. 실제 확인·공개·저장 실행을 보여주는 것이 아니다. 대표 주장은 사용자 작성 예문이며 AI가 검증한 사실이 아니다.
- 상자의 ‘저장 성공 상태’ 행은 조건부 표시 예시다. 저장 전 화면에 성공 문구와 이동 버튼이 함께 노출된다는 뜻이 아니다. ‘대표 구성 없이 링크 발행으로’는 대표가 아직 저장되지 않은 경우에만 제공하는 제안이다.
- **[요구]** 대표 주장 직접 작성과 Catch 2~3장 한 벌을 제공한다. 대표 주장 자동 작성·첨삭, 복수 프리셋, 검색 대표 지정 기능은 넣지 않는다(FR3.1·FR3.3·FR3.5).
- **[화면 제안]** 선택 후보는 확인을 마친 현재 공개 Catch 중심으로 보여준다. 미공개·불일치·숨김 카드는 ‘내 자산에서 상태 확인’으로 연결한다. 후보 자격·편집 중 상태 변화의 세부 판정은 합의가 필요하다. 대표 선택 자체가 Catch를 공개하지 않는다.
- **[화면 제안]** 완성된 구성 저장은 주장 1개와 Catch 2~3장일 때 제공한다. 0~1장이면 부족 안내, 4번째 선택 시 ‘최대 3장’ 안내를 둔다. 불완전한 구성의 임시 저장·자동 저장 정책은 추가하지 않는다.
- **[화면·연결 제안]** ‘구성 저장’ 성공 후에는 W06에 머물며 성공 안내와 별도 ‘링크 발행으로’ 버튼을 제공한다. 기존 저장 구성을 불러온 경우도 편집 내용과 저장된 구성이 같을 때 이동 버튼을 제공하는 안이다. 저장 후 다시 편집했거나 저장 실패·저장 중이면 변경한 구성으로 이동 가능한 상태로 표시하지 않고 저장을 먼저 안내한다. 저장 자체가 L01 이동이나 링크 발행을 실행하지 않는다. L01에 전달할 저장된 구성 식별·버전과 이동 조건은 링크 담당과 합의한다.
- **[요구]** 구성 완료를 링크 발행의 필수 조건으로 만들지 않는다. 위 우회 버튼은 대표 미구성 상태의 경로다. 기존 대표가 있을 때 특정 링크에서 대표를 제외하는 옵션은 이 문서로 새로 채택하지 않는다.
- **[미정]** 주장 길이, Catch 순서 편집, 대표 제거, 편집 중 공개 상태가 바뀐 경우의 저장, 기본 프로필·Catch 본문 버전. Catch를 숨긴 기존 링크에 다른 카드를 자동 보충하지 않는다(FR3.4).

## 5. 다른 영역과 연결할 조건

아래는 필요한 의미상의 입력·출력이며 API 경로·스키마·권한 계약 승인본이 아니다. 실제 담당자 배정과 이슈 번호는 추정하지 않는다.

| 연결 상대 | 받을 정보 | 전달할 정보 / 확인할 조건 |
|---|---|---|
| 인증·공통 권한 | Google 로그인 결과, 현재 사용자 식별, 서비스에 저장된 표시 이름 유무와 조회 결과 | Google 로그인·GitHub 연결·저장소 분석 동의를 구분. 개인별 자료 접근 확인, 이름 미저장/저장 분기·조회 실패 처리와 계정 연결 정책 합의 |

### 5.1 홈 PR #28 검토 시 전달할 연결 조건

전달 대상: [홈 흐름·와이어프레임 PR #28](https://github.com/JminAILab/CatchU/pull/28). 관련 작업: [회원·자산 #20](https://github.com/JminAILab/CatchU/issues/20), [홈 #22](https://github.com/JminAILab/CatchU/issues/22), [연결 기준 #23](https://github.com/JminAILab/CatchU/issues/23).

**아래의 Google OAuth 기본 로그인·GitHub 미연결 홈 진입은 팀 합의 U1·U4이며, 나머지는 작성자(팀원 2) 요청 U3와 리뷰에 따른 검토용 연결 제안이다.** 세부 화면·홈 담당 합의·API 계약까지 확정한 것은 아니다. 이 절의 보완은 PR 댓글 게시나 홈 문서 반영 완료를 뜻하지 않는다.

| 경우 | 회원 영역에서 제안하는 연결 조건 | 홈 담당과 맞출 내용 |
|---|---|---|

홈 PR에서 확인할 지점은 ‘로그인 성공 → 홈’ 설명의 첫 이용자/기존 이용자 분기와 사용자 메뉴의 프로필 수정 진입점이다. 홈의 분석 상태 상자·상단 메뉴 배치 등 다른 담당 화면 상세를 이 초안에서 다시 설계하지 않는다.

표시 이름 조회 실패는 W01-R에 착지해 ‘다시 불러오기’로 조회를 재시도하고, 최초 입력 저장 실패는 W02에서 입력을 유지하며 저장을 재시도하는 안이다. 조회 실패를 ‘표시 이름 없음’으로 단정하거나 저장 성공으로 간주하지 않는다. 비로그인 사용자의 홈 진입 범위는 이 제안에 포함하지 않는다.

**홈 담당과 별도로 협의할 사항:**

- 로그인 성공 후 이름 저장 유무를 확인할 주체와 시점, 저장 전 이탈한 재방문자 경로, W01-R 조회 실패 안내·재시도 제안의 연결 방식을 맞춘다.
- 홈 사용자 메뉴의 위치와 ‘프로필 수정’ 표현, 회원 화면으로의 진입 방식, 수정 저장·취소 후 돌아갈 위치와 홈 표시 이름 갱신 시점을 맞춘다.
- **세션 만료 → W01 로그인 → 복귀 위치:** 홈에서 만료됐으면 재인증·표시 이름 조회 후 홈으로 돌아가는 안을 제안한다. 프로필 수정·Catch 상세 등에서 만료된 경우 원래 작업 위치와 홈 중 어디로 복귀할지, 복귀 대상의 접근 권한·존재 여부 확인과 접근 불가 시 대체 위치, 미저장 입력 보존·복원을 인증·홈 담당과 협의한다. 이름 미저장자는 우선 W02 최초 입력으로 보내는 안이며 그 저장 후 원래 위치 복귀 여부도 미정이다. 자동 저장·자동 공개·분석 재요청으로 이어지지 않게 한다.
- GitHub 미연결 홈 허용은 팀 합의로 적용한다. 홈의 연결 안내와 분석 시작 전 필요한 권한·동의는 구분하며, Google 계정·선정 저장소 관계 확인과 분석 동의 방식은 팀원 1 조율에 남긴다.
- 홈의 결과 단위 전체·일부 확인 표시는 §5.2의 Catch 단위 집계 제안으로 검토한다. 표시 문구·데이터 전달 시점·불일치 처리 포함 여부는 홈·분석·회원 담당이 맞춘다.

Catch 상태별 버튼과 W06의 저장·발행 화면 이동 분리는 회원·자산 초안의 제안이다. W06 → L01 전달 조건은 링크 담당과 협의하며 홈 PR #28 담당에게 결정 책임을 넘기지 않는다. H01·W01~W06·L01은 이 문서의 연결 표기이며 상대 문서의 화면 ID·경로와 동일하다고 가정하지 않는다.

### 5.2 Catch 단위 확인과 결과 단위 전체·일부 확인 연결 제안

**[연결 제안 / 미확정]** W04의 확인은 Catch 한 장 단위로 유지한다. 홈의 결과 단위 표시는 해당 분석 결과에 속한 Catch의 확인 상태를 집계하는 안이다. 화면을 열거나 분석이 끝난 것만으로 확인 완료로 처리하지 않는다. 공개 여부·분석 성공 여부와도 구분한다(FR4.1).

- **Catch 확인 완료 기준 제안:** 구직자가 초안·근거·질문을 검토한 뒤 ‘확인 완료’를 명시적으로 선택하고 그 확인 기록의 저장이 성공했을 때 완료로 센다. 열람·스크롤만으로 추정하지 않는다. 저장 중·실패는 완료로 세지 않으며, 완료는 사실 검증·공개 동의를 뜻하지 않는다.
- **필요한 의미상의 정보:** 분석 결과 식별과 결과 범위·판본, 그 결과에 속한 Catch 식별 목록, 각 Catch의 확인 기록 유무·저장 결과, 불일치 여부, 목록·확인 상태 조회 성공 여부. 전체 대상 수와 확인 완료 수를 함께 전달하는 안이며 API 필드명·저장 스키마는 미정이다.

| 같은 결과 범위 안의 상태 | 홈에 전달할 요약 제안 | 판단 조건 |
|---|---|---|
| 확인 대상 Catch가 있고 완료 기록이 없음 | 미확인 | 대상 수 N > 0, 확인 완료 수 K = 0 |
| 대상 중 일부에 완료 기록이 있음 | 일부 확인 | 0 < K < N. 예: 3장 중 1장 확인 [임시 예시] |
| 모든 대상에 완료 기록이 있음 | 전체 확인 | N > 0, K = N. 결과 범위와 확인 기록을 정상 조회한 경우에만 판정 |
| 생성된 Catch가 없음 | 확인할 Catch 없음 | 정상 조회된 N = 0. 전체 확인으로 표시하지 않음 |
| 대상 목록·확인 기록을 조회하지 못했거나 범위가 아직 정해지지 않음 | 확인 상태를 불러오지 못함 / 집계 대기 | 실패와 대기를 구분. 미확인·0장·전체 확인으로 단정하지 않음 |

공개·숨김 여부만으로 확인 완료 수를 늘리거나 줄이지 않는 안이다. 불일치 표시는 별도 신호로 전달하고, ‘불일치 표시’만으로 확인 완료 기록을 만들지 않는 안을 제안한다. 기존 완료 후 불일치를 표시한 경우 완료 기록을 유지할지, 검토를 마친 불일치 카드도 홈에서 별도 처리 완료로 볼지는 다음 검토에서 합의한다. 합의 전에는 불일치를 집계에서 숨겨 ‘전체 확인’으로 해석하게 하지 않는다.

결과에 Catch가 추가되거나 재분석·내용 변경이 발생했을 때 집계 범위와 기존 확인 기록을 어떻게 이어갈지, 일부 생성 성공 결과의 노출 시점(OQ1), 중복 Catch·열람 제한된 Catch 처리, 누가 집계하고 언제 홈에 갱신할지는 홈·분석·회원 담당과 협의한다. **W03~W06 상세 화면은 이번에 확장하지 않고 다음 작업에서 팀원 3 의견과 함께 검토한다. W06 → 링크 발행 조건은 링크 담당과 합의한다.**

## 6. 다음 검토에서 먼저 다룰 질문

기본 로그인 Google OAuth(U1)와 GitHub 미연결 홈 진입 허용(U4)은 **팀 합의(팀장 확인 2026-09-14, 후속 입력 문서 §1.1)**다. U2의 표시 이름만 필수, Google 이름의 수정 가능한 미리 채움, 선택 정보의 나중 작성은 **검토용 제안**으로 유지한다. 새로 구체화한 W01-R·W02 예외와 §5.2의 확인 집계도 제안이며 팀장 확인 범위를 확대하지 않는다.

U3의 첫 이용자/기존 이용자 분기와 홈 사용자 메뉴 → 프로필 수정은 §5.1의 연결 제안으로 유지한다. 홈 담당과 위치·표현·복귀 방식을 협의하기 전 최종 배치로 표시하지 않는다.

1. Google 계정·선정 저장소 관계 확인(OQ1), 분석 동의(OQ11)와 분석 요청 전 GitHub 연결 필요 여부는 팀원 1이 조율한다. 홈 진입 허용 합의와 구분해 연결 안내 위치·시점을 맞춘다.
2. 표시 이름·선택 정보가 외부 프로필에 어떻게 공개되는지와 수정 시 기존 링크 반영은 OQ3에서 검토한다. 입력 필수 여부와 외부 공개 여부를 합치지 않는다.

필요한 화면을 구체화할 때 관련 쟁점만 1~2개씩 묻는다. 나머지 OQ를 한꺼번에 답하도록 요구하지 않는다.

## 7. 팀 검토·AI-DLC 입력 재사용 기준

이 초안의 작성 목적은 첫 행동·예외·다른 담당 화면으로의 이동을 함께 검토할 수 있게 하는 것이다. 아래는 검토 기준이며 제품 구현 테스트의 통과 기록이 아니다.

- 로그인 성공·취소·실패와 프로필 입력·저장·홈 이동을 설명할 수 있다.
- U2가 팀 확정 정책이 아닌 검토용 제안으로 표시돼 있으며, Google 이름 수신·미수신·수정과 표시 이름만 저장한 홈 진입을 설명할 수 있다.
- 선택 항목 미입력·GitHub 미연결이 홈 진입을 막지 않고, 선택 정보를 나중에 프로필에서 작성하는 경로가 있다.
- U3의 첫 이용자/기존 이용자 분기와 홈 사용자 메뉴의 프로필 수정 진입안, 홈 담당 협의 사항을 PR #28 전달 조건으로 설명할 수 있다.
- 이름 저장 전 이탈한 재방문·조회 실패, 최초 Google 이름 채움과 이후 저장된 값 수정의 차이를 설명할 수 있다.
- W01-R 재조회 성공·반복 실패·세션 만료와 W02 최초 입력의 취소 없음·로그아웃 성공/실패·이탈 후 재방문을 화면 제안으로 설명할 수 있다.
- 프로필 자가 입력값을 GitHub 검증 사실로 표시하지 않는다.
- Catch 설명·근거·질문 확인과 공개 선택이 분리돼 있다.
- 공개 Catch 재열람이 미공개 전환을 일으키지 않으며, 상태별 행동과 미정인 숨김·불일치 복구를 구분한다.
- 불일치 표시·미공개 유지·숨김과 내부 선택 공유의 차이를 설명할 수 있다.
- 대표 주장 1개·Catch 2~3장과 대표 없는 발행 경로가 모두 있다.
- W06 구성 저장과 L01 이동 버튼을 구분하고, 저장 실패·재편집 상태에서 저장 성공으로 표시하지 않는다.
- 대표 밖 공개 자산, 기존 링크의 대표 보존, 현재 숨김 제외가 함께 유지된다.
- 홈·분석·링크·내부 검토의 연결 조건과 미정 사항이 드러나 있다.
- 문서 근거·입력 제안·화면 제안·임시 예시가 구분돼 있다.
- 팀 합의 U1·U4와 제안 U2·U3를 구분하고, §5.2 결과 단위 전체·일부 확인을 Catch 공개·분석 성공과 혼동하지 않는다.

## 8. 초안 변경 이력

아래 v0.1~v0.5의 제안·확인 필요 표기는 당시 기록이며, 현재 U1·U4 지위는 v0.6과 §1.1의 팀장 확인을 따른다.

- v0.1 (2026-09-14): 첫 사용자 흐름·와이어프레임과 요구사항·미결·연결 조건 작성.
- v0.2 (2026-09-14): 작성자(팀원 2)의 당시 확인 U1에 따라 기본 로그인과 W01 버튼을 Google OAuth로 반영. GitHub 연결·분석 동의 및 프로필 자동 채움·공개와 구분하고 로그인 방식 미정 문구와 후속 질문을 갱신. 승인 요구사항·공식 상태·승인 기록은 이 변경 대상에 포함하지 않음.
- v0.3 (2026-09-14): 작성자(팀원 2)의 초안 요청 U2에 따라 표시 이름만 필수, Google 이름 수신 시 수정 가능한 미리 채움, 한 줄 소개·직무·기술 스택의 선택·나중 작성, GitHub 미연결 홈 진입을 반영. 요구사항 요약·분기·W02·홈 연결·검토 기준을 함께 갱신했으며 모두 팀 확정 정책이 아닌 검토용 제안으로 명시.
- v0.4 (2026-09-14): U2의 필수·선택 제안을 유지하면서 U3의 첫 이용자/기존 이용자 홈 진입 분기와 홈 사용자 메뉴의 프로필 수정 진입안을 정리. §5.1에 홈 PR #28 검토 시 전달할 연결 조건과 위치·표현·복귀 협의 사항을 추가. 다른 담당 화면 수정·PR 댓글 게시·팀 정책 확정은 포함하지 않음.
- v0.5 (2026-09-14): #20 범위에서 이름 미저장 재방문 분기, W02 최초 입력·이후 수정, W04 상태별 행동, W06 저장과 링크 발행 화면 이동을 **화면·연결 제안**으로 보완. §5.1에 홈 PR #28 협의 목록, §7.1에 완료 기준별 검증·미검토 범위를 정리. U4의 GitHub 미연결 홈 진입은 허용 안을 유지하되, 확인한 기록의 날짜·문서·해당 내용과 한계를 §1.1에 남기고 **회의 결정 근거 확인 필요**로 구분. v0.3·v0.4는 당시 요청 이력이며 현재 지위는 U4·§1.1을 따름.
- v0.6 (2026-09-14): PR #29 팀장 리뷰와 PR #27 후속 입력의 팀장 확인을 근거로 U1·U4·§1.1·W02 GitHub 안내를 팀 합의로 갱신. 표시 이름 조회 실패 착지·재시도(W01-R), 최초 프로필 입력의 취소 없음·로그아웃·이탈 처리를 화면 제안으로 구체화. §5.1에 세션 만료 후 로그인·복귀 협의, §5.2에 Catch 확인 기준과 결과 단위 전체·일부 확인 집계 제안을 추가. 작성자 지칭을 ‘작성자(팀원 2)’로 통일. W03~W06 상세 검토는 다음 작업에 남기고 계정·저장소 연결은 팀원 1, W06 → 링크 발행 조건은 링크 담당과 협의. 이번 수정은 로컬 초안만 대상으로 하며 커밋·푸시·PR·이슈·Projects·AI-DLC 상태·승인 기록 갱신을 포함하지 않음.
