## 프로필 — 이도현 (가명, 29세)

- Landit 운영팀(=우리 팀)의 백엔드 개발자. **운영 전담이 아니라 겸임** [설정]
- 본업은 요청사항 반영·기능 개선 개발. 운영은 하루 중 짧은 시간(목표: 15분)만 [설정]
- 운영 경험 없음 — 배포·모니터링은 알지만 CS·심사 업무는 처음 [설정]
- 혼자다. 사전조사 문서의 역할 분리(일반 운영/CS/AI 운영/최고 관리자)는 **미래의 조직도**이고, 초기의 이도현은 그 네 역할을 혼자 겸한다 — 그래서 역할별 권한 분리 설계가 "지금 나눠 구현"이 아니라 "나중에 나눌 수 있게 설계"로 필요하다 [설정]

## 목표

1. **운영이 개발 시간을 잡아먹지 않을 것** — 자동 처리가 기본, 예외만 내게 올 것
2. **"켜져 있는데 안 돌아가는 상황"을 빨리 알아차릴 것** — 서버 생존이 아니라 핵심 기능(분석·연동·알림)의 성공률을 볼 것
3. **서비스의 약속(동의·삭제·투명성)이 실제로 동작함을 보증할 것**
4. **판단에 고민이 없을 것** — 무엇을 봐도 되는지가 미리 정해져 있고, 예외 열람은 기록이 남아 나를 보호할 것

## 핵심 고통

- **시간 경쟁** — 운영에 쓰는 모든 시간은 개발에서 빼오는 시간 [설정]
- **판단 부담** — "이 문의를 처리하려면 내가 뭘 열어봐야 하나"를 매번 스스로 정해야 하는 상황이 가장 무섭다. 사전조사 문서의 표현으로: 필요한 건 자기소개서 전체가 아니라 "파싱 성공 → 수집 성공 → 분석 실패 → 오류코드"라는 **상태 정보**인데, 시스템이 상태를 안 보여주면 결국 원본을 열게 된다 — 설계 실패가 곧 권한 남용을 강제하는 구조 [설정]
- **조용한 장애 불안** — 서비스는 떠 있는데 분석 실패율이 치솟고 있는 걸 모르고 지나가는 것. 개별 문의로야 알게 되면 이미 늦다 [설정]
- **혼자라는 부담** — 사고(개인정보 노출, 대규모 장애)가 나면 일반 큐로는 처리 못 하는데, 대응 절차가 없으면 그 순간 즉흥 판단을 해야 한다 [설정]

## 하루 업무 흐름 (평범한 화요일, 15분)

1. **기능 건강 지표** 확인 — 오늘 분석 요청 대비 실패율, GitHub 연동 실패, 파일 파싱 실패, 알림 발송 실패. "평소보다 높음" 경보가 없으면 통과 [설정 — 팀 의견 반영]
2. **4개 큐** 확인 — 기업 인증 대기 / 신고·문의 / 인젝션 탐지 / 삭제 파이프라인
3. **품질 이상징후** 훑기 — 집계 수준의 변화만: 배포 후 실패 증가, 오탐 문의 급증 등. 개별 분석 결과의 판단·수정은 하지 않는다 [설정 — 팀 의견 반영]
4. 개발 복귀

## 처리 흐름 (팀 의견 반영해 구체화)

- **신고**: 접수 → 확인 → 처리 → 결과 기록 → 반복 패턴 확인. 각 단계가 상태값으로 남는다 [가결정]
- **기업 인증**: 심사는 시작일 뿐 — 인증 후 관리(사업자 정보 변경, 탈퇴, 계정 탈취 의심, 반복 신고 기업)가 별도 흐름으로 존재한다 [가결정]
- **긴급 상황** (개인정보 노출·대규모 분석 장애·악성 기업 계정): 일반 큐가 아니라 별도 원칙 — 탐지 → 해당 기능 일시 제한 → 영향 범위 확인 → 복구 → 기록 [설정 — 팀 의견 반영]
- **정책 변경**: 인증·신고 처리 기준이 바뀌면 언제·무엇이·왜 바뀌었는지 기록 — "왜 이땐 승인했고 지금은 반려했지"를 막는 장치이자, 혼자 운영하는 사람의 선례 관리 [설정 — 팀 의견 반영]

## 정보 접근 (가결정 — STEP 1~5에서 확정)

사전조사 문서의 5분류·신호등 체계를 그대로 따른다. 아래는 페르소나용 임시 가정:

| 분류 | 임시 가정 |
|---|---|
| ① 운영 상태 정보 (연동·분석 상태, 실패 원인, 큐) | 🟢 기본 조회 |
| ② 개인정보 (이름·연락처) | 🔴 기본 비노출, 가명화(사용자 #10352) — CS 필요 시 🟡 |
| ③ 지원자 원본 자료 (자소서·이력서·레포) | 🔴 기본 조회 금지 — 문의·조사 등 사유 있을 때만 🟡 + 감사로그 |
| ④ AI 분석 정보 | 상태·실패 원인은 🟢, 결과 내용은 🟡 [미결 — "결과를 봐야 오류를 아는가"는 STEP 3에서] |
| ⑤ 시스템 로그 | 🟢 단, 개인정보 포함 여부 점검 후 |

**원칙: "운영자니까 볼 수 있음"이 아니라 "이 업무 때문에 볼 수 있음". ①(상태)로 해결 가능한 문제에 ③(원본)을 열지 않는다.**

## 관리자 자신의 보안 (팀 의견 반영)

- 관리자 로그인 2단계 인증 [가결정]
- 중요 작업(예외 열람, 인증 승인·반려, 기능 제한)은 작업 로그 기록 [설정]
- 운영자가 늘어나면 최고 관리자/일반 운영자 구분 — 지금은 구현하지 않되, 권한을 코드에 하드코딩하지 않는 수준의 대비만 [미결]

## 이 페르소나가 아닌 사람
