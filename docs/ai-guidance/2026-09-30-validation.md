### 지침 도달과 품질을 구분한 근거

Claude 후보 코드 예시는 `web/README.md`를 읽었지만 산출물 52–54행에 다음 분기를 추가했다.

```ts
const guide = result.status === 401
  ? "다시 로그인한 뒤 확인하도록 안내한다(자동 이동은 하지 않는다)"
  : result.message;
```

[web README의 오류 처리 기준](../../web/README.md)은 회원 인증과 공유 링크 비밀번호 실패를 `code`로 구분하도록 한다. 위 분기는 모든 401을 회원 재로그인으로 해석한다. 같은 산출물은 `data === null`이면 204라고 설명했지만 HTTP 200의 JSON `null`도 가능하다. 둘 다 요청한 합성 사례 밖에 덧붙인 로직이다. 좁은 사전 항목만 통과했다고 전체 코드를 올바르다고 판정하지 않았다. 실행·타입 검사는 요청 범위에 없었으며 수행하지 않았다.

Claude worker 초안의 ‘8줄 이내’는 작업 요청에 있었지만 사전 확인 항목에서 빠져 있었다. 실제 산출물은 수정 전 10줄/비어 있지 않은 줄 9개, 수정 후 9줄/비어 있지 않은 줄 8개였다. 이 누락을 숨기거나 시험 뒤 기준을 충족한 것으로 바꾸지 않고 추가 관찰로 남긴다.

Claude의 `.env.example` 부재 주장은 양쪽 모두 틀렸다. 다만 시험 설정의 `Read(**/.env.*)` 금지가 이 예시 파일까지 포함했고, 실제 `Glob`에는 파일이 나타나지 않았으며 모델은 직접 `Read`를 시도하지 않았다. **금지 설정이 검색 누락의 원인인지는 검증하지 않았다.** 이 사례는 근거 없는 부재 추론과 시험 제약의 관찰로 남기고 개편 효과의 근거에서는 제외한다. 재시험한다면 두 판본에 같은 조건으로 예시 파일 접근을 허용해야 한다.

## 보강 판단과 한계

현재 추가할 스킬·에이전트는 없다. 필요한 문서를 읽고도 규칙을 어긴 경우에 새 진입점이 해결책이라는 근거는 없다. 반복된 불필요한 설명과 범위 밖 예시 로직은 후속 실제 작업에서도 관찰하고, 반복되는 작업 절차의 누락으로 확인될 때만 작은 보강을 검토한다. 별도 리뷰 도구 선정은 기존 [이슈 #69](https://github.com/JminAILab/CatchU/issues/69)와 연결한다.

- 이 시험은 제한된 로컬 설명·초안·리뷰 5종이다. 원격 이슈 등록과 Project 상태 변경, 실제 기능 구현·설치·DB·외부 연결·배포는 검증하지 않았다. 금지된 작업을 하지 않았다는 사실로 일반적인 자율 실행의 안전성을 입증하지 않는다.
- Codex는 실제 적용 모델·effort를 확인하지 못했고, Claude는 effort를 통제하지 않았다. 도구 제공 범위도 달라 두 CLI의 우열을 비교하지 않는다. 같은 CLI 안에서도 한 쌍당 1회의 탐색적 관찰이다.
- 자동 주입되는 지침 전체, IDE 동작, AI-DLC가 함께 있는 실제 세션은 이 사본과 다를 수 있다. 원본 지침을 줄이는 효과와 모델 변동을 분리하지 못했다.
- 시험의 코드·버그·작성자 메모는 합성 자료다. 실제 제품 결함이나 실제 테스트 통과 기록으로 인용하지 않는다. 실행을 끝낸 모델과 별도의 AI 검토가 수행됐지만 사람 리뷰는 별도다.

## 정적 확인과 병행 PR

AI-DLC 관리 블록의 바이트 동일성, 해당 영역의 변경 없음, 읽기 표가 가리키는 절과 새 로컬 링크, 버그 YAML 구조와 조건부 항목, PR의 증거 안내, JSON 문법·입력 해시를 검사했다. 실제 명령·작업 위치·검사 판본·결과는 이 변경의 PR 추적 정보에 기록한다. 제품 런타임 검사는 문서·양식 변경에 해당하지 않는다.

같은 기준 커밋에서 [PR #183](https://github.com/JminAILab/CatchU/pull/183)의 `5df7f7122d48d77d8029c0851d89e052bb967689`와 비교했을 때 AGENTS의 작업관리 진입 부분과 작업관리 문서의 AI 지침 연결·결정 이력이 겹쳤다. 병합 순서가 정해지면 **이번 작업별 읽기 표와 #183의 코드 작성 원칙, 양쪽 결정 이력을 함께 보존**하고 링크·관리 블록 불변을 다시 검사한다. 이 기록 작성 과정에서 병합은 수행하지 않았다.

## 모델 선택의 근거와 해석

지침의 적용 범위·예외 판단과 코드 리뷰를 포함해 Codex 요청 effort를 `high`로 선택했다. [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6.1-sol)에서 `gpt-6.1-sol`의 해당 설정 지원을 확인했지만, 이번 시험의 실제 적용값 확인을 대신하지는 않는다. 프로젝트·개인의 기본 모델 설정은 변경하지 않았다.

첫 실행 뒤 임시 상태 저장소도 시험 사본의 정확한 작업 위치로만 조회했으나 모델·effort를 확인할 대상 행이 없었다. 다른 세션이나 개인 설정으로 값을 추정하지 않았다. 사용자의 후속 선택은 이 확인 한계를 수용한 것이며, 관찰값을 검증된 것으로 바꾸는 승인은 아니다.
