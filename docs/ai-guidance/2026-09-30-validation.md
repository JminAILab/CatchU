### 지침 도달과 품질을 구분한 근거

후보 코드 예시는 `web/README.md`를 읽었지만 산출물 52–54행에 다음 분기를 추가했다.

```ts
const guide = result.status === 401
  ? "다시 로그인한 뒤 확인하도록 안내한다(자동 이동은 하지 않는다)"
  : result.message;
```

[web README의 오류 처리 기준](../../web/README.md)은 회원 인증과 공유 링크 비밀번호 실패를 `code`로 구분하도록 한다. 위 분기는 모든 401을 회원 재로그인으로 해석한다. 같은 산출물은 `data === null`이면 204라고 설명했지만 HTTP 200의 JSON `null`도 가능하다. 둘 다 요청한 합성 사례 밖에 덧붙인 로직이다. 좁은 사전 항목만 통과했다고 전체 코드를 올바르다고 판정하지 않았다. 실행·타입 검사는 요청 범위에 없었으며 수행하지 않았다.

worker 초안의 ‘8줄 이내’는 작업 요청에 있었지만 사전 확인 항목에서 빠져 있었다. 실제 산출물은 수정 전 10줄/비어 있지 않은 줄 9개, 수정 후 9줄/비어 있지 않은 줄 8개였다. 이 누락을 숨기거나 시험 뒤 기준을 충족한 것으로 바꾸지 않고 추가 관찰로 남긴다.

`.env.example` 부재 주장은 양쪽 모두 틀렸다. 다만 시험 설정의 `Read(**/.env.*)` 금지가 이 예시 파일까지 포함했고, 실제 `Glob`에는 파일이 나타나지 않았으며 모델은 직접 `Read`를 시도하지 않았다. **금지 설정이 검색 누락의 원인인지는 검증하지 않았다.** 이 사례는 근거 없는 부재 추론과 시험 제약의 관찰로 남기고 개편 효과의 근거에서는 제외한다. 재시험한다면 두 판본에 같은 조건으로 예시 파일 접근을 허용해야 한다.

## 보강 판단과 한계

현재 추가할 스킬·에이전트는 없다. 필요한 문서를 읽고도 규칙을 어긴 경우에 새 진입점이 해결책이라는 근거는 없다. 반복된 불필요한 설명과 범위 밖 예시 로직은 후속 실제 작업에서도 관찰하고, 반복되는 작업 절차의 누락으로 확인될 때만 작은 보강을 검토한다. 별도 리뷰 도구 선정은 기존 [이슈 #69](https://github.com/JminAILab/CatchU/issues/69)와 연결한다.

- 이 시험은 제한된 로컬 설명·초안·리뷰 5종이다. 원격 이슈 등록과 Project 상태 변경, 실제 기능 구현·설치·DB·외부 연결·배포는 검증하지 않았다. 금지된 작업을 하지 않았다는 사실로 일반적인 자율 실행의 안전성을 입증하지 않는다.
- Codex의 읽기·행동은 미검증이다. Claude 안에서도 한 쌍당 1회뿐이므로 도구 간 우열, 품질 향상률, 시간·토큰 절감을 주장하지 않는다.
- 자동 주입되는 지침 전체, IDE 동작, AI-DLC가 함께 있는 실제 세션은 이 사본과 다를 수 있다. 원본 지침을 줄이는 효과와 모델 변동을 분리하지 못했다.
- 시험의 코드·버그·작성자 메모는 합성 자료다. 실제 제품 결함이나 실제 테스트 통과 기록으로 인용하지 않는다. 실행을 끝낸 모델과 별도의 AI 검토가 수행됐지만 사람 리뷰는 별도다.

## 정적 확인과 병행 PR

같은 기준 커밋에서 [PR #183](https://github.com/JminAILab/CatchU/pull/183)의 `5df7f7122d48d77d8029c0851d89e052bb967689`와 비교했을 때 AGENTS의 작업관리 진입 부분과 작업관리 문서의 AI 지침 연결·결정 이력이 겹쳤다. 병합 순서가 정해지면 **이번 작업별 읽기 표와 #183의 코드 작성 원칙, 양쪽 결정 이력을 함께 보존**하고 링크·관리 블록 불변을 다시 검사한다. 이 기록 작성 과정에서 병합은 수행하지 않았다.

## 후속 확인: 모델과 effort

사용자가 시험 모델·effort를 확인하는 과정에서 앞선 Claude 10회의 effort를 명시하지 않았고 실효값도 기록하지 않았음을 확인했다. 모델명은 실행 메타데이터에서 확인했지만, 동일한 effort가 적용됐다는 증거는 없다. 기존 실행·발췌는 보존하며 **effort가 통제되지 않은 예비 관찰**로 해석한다.

후속 Codex 시험은 사용자 선택에 따라 `gpt-6.1-sol`, 추천 effort `high`를 명시적으로 고정한다. 지침의 적용 범위·예외 판단과 코드 리뷰를 포함하므로 충분한 검토를 위해 `high`를 선택했다. 이는 이 시험의 설정이며 프로젝트·개인의 기본 모델을 바꾸는 결정이 아니다. 공식 모델 문서에서 해당 조합의 지원을 확인했지만, 현재 로그인 계정의 실제 사용 가능 여부는 아직 검증하지 않았다.

후속 실행은 기존 기록과 분리하고, 수정 전·후에 같은 요청·판본·모델·effort를 적용한다. CLI에 요청한 값과 실행 메타데이터의 관찰값을 구분한다. 첫 실행에서 모델·effort를 확인하지 못하거나 값이 다르면 후속 실행을 멈추고, 다른 모델로 자동 대체하지 않는다. 초기화 실패·구성 미확인을 지침 품질 실패로 세지 않는다. 현재는 설정·구문·입력 해시의 로컬 준비 검사만 수행했으며, 권한 상승 실행과 사본 자료 전송의 명시적 승인이 남아 있다.
