## 목표

**표면적인 목표**

- 서류 준비를 잘하고, 면접을 잘 보는 것

**실질적인 목표**

1. 자소서·포트폴리오에 **어떤 내용을 담을지** — 하나뿐인 프로젝트에서 무엇을 골라 보여줄지
2. 면접에서 **어떤 대답을 준비할지** — 근거 있는 답변
3. 프로젝트 경험을 **데이터·근거로 증명**하고, 그 안에서 자신의 강점을 파악
4. **나를 제대로 어필하는 것** — 면접에서는 긴장해서 말로 역량을 다 설명하지 못한다. **말이 아니라 자료로 나를 보여주고 싶다**
5. **한 번 정리해둔 것이 계속 쓰이는 것** — 기업마다 처음부터 다시 만들지 않아도 되는 상태
6. **자기 힘으로 지원하는 것 말고도 기회가 오는 것** — 내가 못 찾은 회사가 나를 찾아오는 경로

## 핵심 고통

### ① 있는데 꺼내지 못한다

쓸 재료가 없는 게 아니다. **분명 내가 했던 일인데, 그때 왜 그렇게 결정했는지가 기억나지 않는다.**

판단의 흔적은 **코드와 커밋과 PR에 흩어져 있다.** 커밋 자체는 구체적으로 남겨 뒀지만, 수십 개를 다시 훑어 "이게 내가 어필할 만한 경험이다"로 묶어본 적이 없다. 그래서 자소서를 쓰려고 앉으면 **"쓸 게 없다"**고 느낀다.

> 재료가 없어서가 아니라, **재료가 어디에 있는지 몰라서** 못 쓴다.

### ② 말로는 다 설명하지 못한다

면접에서는 긴장한다. 준비한 내용도 입 밖으로 나오면 절반이 된다. **"왜 그렇게 했냐"**는 질문이 들어오면 특히 그렇다.

자료로 미리 보여줄 수 있으면 좋겠는데, 지금 가진 건 이력서와 포트폴리오뿐이고 그것만으로는 **내가 실제로 무엇을 했는지가 전달되지 않는다.**

### ③ 시간이 부족하다

공고 탐색·자소서·포트폴리오·면접 준비가 동시에 돌아간다. 프로젝트 경험을 기업별로 다시 꺼내 정리하는 작업은 **항상 뒤로 밀린다.** 그 결과 모든 기업에 같은 포트폴리오를 내게 되고, 본인은 그걸 문제로 인식하지 못한다.

> **다만 시간이 없다고 안 하는 것은 아니다.** 취업이 절박하기 때문에, 나를 어필할 수 있는 일이라면 시간이 걸려도 한다. 문제는 **들인 시간이 그 기업 하나로 끝난다는 것**이다.

## 필요한 것 (사용자의 언어로)

- 흩어져 있는 판단의 흔적을 **대신 끄집어내 주는 것**
- 꺼낸 재료 중 **이 공고에 뭘 보여줄지 골라주는** 선택지
- **말로 하지 않아도 내가 한 일이 전달되는 형태**
- 한 번 만든 것이 **다음 지원에도 그대로 쓰이는 것** — 들인 시간이 한 곳에서 끝나지 않게
- 내가 어디까지 보여줄지 **내가 정할 수 있는 것**
- **다른 사람들은 어떻게 정리했는지 볼 수 있는 것** — 팔로우로 남의 프로필을 보며 얻는 인사이트 *(고민을 나눌 커뮤니티는 2순위 기능)*

## POV — 관점 진술

> 형식: **[사용자]는 [필요/욕구]가 필요하다. 왜냐하면 [인사이트/이유]이기 때문이다.**

### 메인 POV

> **취준생·신입 개발자 한지우는 자신의 프로젝트 경험을 기업이 이해하고 신뢰할 수 있는 근거와 함께 재사용 가능한 형태로 보여줄 방법이 필요하다.**
> **왜냐하면 실제 개발 경험은 GitHub에 남아 있어도 이를 자신의 역량으로 정리하고 증명하기 어렵고, 취업 준비를 병행하면서 기업마다 반복해서 정리할 시간도 부족하기 때문이다.**

> **"지속적으로"가 아니라 "재사용 가능한 형태로"인 이유:** 기업은 필요할 때 한 번씩 열어본다. 우리가 만들어야 하는 것은 상시 노출이 아니라, **한 번 만들면 여러 곳에 다시 쓰이는 자산**이다.

### 보조 POV — 고통별 분해

| # | POV |
| --- | --- |
| **POV-A**<br>(인출) | 한지우는 **흩어진 개발 판단의 흔적을 대신 꺼내주는 도구**가 필요하다. 왜냐하면 쓸 재료가 없는 게 아니라 코드·커밋·PR에 흩어져 있어 다시 회수하기 어렵고, 그래서 "쓸 게 없다"고 느끼기 때문이다. |
| **POV-B**<br>(전달) | 한지우는 **말에 기대지 않고 자신을 설명할 수단**이 필요하다. 왜냐하면 면접에서는 긴장해서 준비한 내용도 절반밖에 전달하지 못하고, 이력서와 포트폴리오만으로는 실제로 무엇을 했는지가 드러나지 않기 때문이다. |
| **POV-C**<br>(노출) | 한지우는 **자신이 찾아내지 못한 기업에게도 발견될 경로**가 필요하다. 왜냐하면 혼자 탐색할 수 있는 공고의 수가 제한적이고, 지원한 곳에서만 기회가 생기는 구조에서는 병행하는 시간이 곧 기회의 상한이 되기 때문이다. |

## HMW — 우리가 어떻게 하면

### 메인 HMW

> **우리가 어떻게 하면, 프로젝트 경험이 있는 취준생·신입 개발자가 반복적인 정리 부담 없이 자신의 개발 경험을 근거와 함께 보여주고, 기업에게 발견될 수 있게 할 수 있을까?**

### 하위 HMW

| # | 대응 POV | 질문 |
| --- | --- | --- |
| HMW-1 | A | 우리가 어떻게 하면, 흩어진 커밋·PR에서 **본인이 잊어버린 개발 판단**을 꺼내줄 수 있을까? |
| HMW-2 | A·B | 우리가 어떻게 하면, **평가하지 않으면서** 무엇을 보여줄지 고를 수 있게 도울 수 있을까? |
| HMW-3 | B | 우리가 어떻게 하면, **말로 설명하지 않아도** 그 사람이 한 일이 전달되게 할 수 있을까? |
| HMW-4 | C | 우리가 어떻게 하면, 구직자가 **프로젝트에 집중하는 동안에도** 기업에게 발견될 수 있을까? |
| HMW-5 | A·C | 우리가 어떻게 하면, **보여주고 싶지 않은 부분은 감추면서도** 보여줄 만한 것은 드러내게 할 수 있을까? |

> **HMW-4의 표현에 주의한다.** "아무것도 하지 않는 동안에도"가 아니다. 이 사람은 GitHub에서 계속 역량을 키우는 중이고, 우리는 바로 그 활동을 분석한다. **프로젝트에 집중하는 시간이 곧 발견될 재료가 쌓이는 시간**이라는 것이 이 서비스의 구조다.

## 서비스 접점 시나리오

### ① 시작 국면 — 프로필을 만든다

수료 기수 단톡방에서 서비스를 알게 됨 → GitHub 연결(동의 기반) → 파이널 프로젝트 레포 분석 → 판단 흔적이 **증거 카드**로 추출됨 → **"어? 내가 이런 걸 했었네"** → 마크다운으로 자기소개 작성(README 쓰듯이, "풀스택 최적화를 고민하는 개발자입니다") → 관심사·소속(인공지능사관학교)·거주 지역 등록 → 공개 범위 설정

### ② 지원 준비 국면 — 공고를 보고 자소서를 쓴다

마감이 다가온 공고를 확인 → 공고의 필수·우대 항목에 대응하는 내 카드를 추천받음 → 카드의 근거를 재료 삼아 자소서 작성 → 면접 답변 준비에도 같은 카드 활용 → **지원 자체는 기업 채용 페이지로 이동해서 진행**

### ③ 발견 국면 — 기업의 연락을 받는다

프로필을 올려둔 채 다음 프로젝트를 하고 있음 → 기업 HR이 조건 검색·추천으로 발견 → **DM 수신** → 회사 정보·근무 조건이 포함된 제안을 확인 → 팔로우 관계에 따라 상대가 내 상세 정보를 어디까지 봤는지 인지 → 관심 있으면 응답, 아니면 무시하거나 차단

### ④ 재사용 국면 — 다음 지원

새 공고를 발견 → 이미 만들어둔 카드에서 다시 고름 → 처음부터 정리하지 않아도 됨 → 새 프로젝트를 하면 레포를 추가 연결해 카드가 늘어남

## 이 페르소나가 아닌 사람

- **공개 코드 흔적이 없는 구직자** — 프로필의 핵심 자산이 GitHub 카드이므로, 연결할 레포가 없으면 서비스가 성립하지 않는다
- 이력서-공고 텍스트 매칭만 원하는 재학생·코드 흔적 희박형 — 요약형 경쟁 서비스의 고객
- 회사 코드 비공개로 이력 증명이 막힌 경력 이직자 — 별도 페르소나 후보이나 우선순위 낮음 (8/31 결정)
