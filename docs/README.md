## 문서의 무게

우선순위: **확정 > 검증된 서술 > 초안·추론.**

- 위 표의 지위가 **확정**인 문서(그라운드룰·레포 컨벤션)는 팀이 따르는 기준이다. 바꾸려면 논의해서 문서를 고친다.
- 페르소나 P1~P4는 문장마다 근거를 태그로 밝힌다. **[인터뷰]**·**[조사]**·**[결정]**은 확인된 것이고, **[추론]**은 아직 검증 전의 가설이다. `[추론]`만 근거로 결정을 굳히지 않는다.
- 지위가 **초안**인 문서는 아직 확정되지 않았다. 본문의 🔲가 미확정 지점이고, 확정 전에는 그 문서를 인용해 다른 산출물을 쓰지 않는다.
- 지위가 **기록**인 문서(실측·PoC 산출물·이상형 정의)는 그때 관찰하거나 정의한 것을 남긴 것이다. 소급 수정하지 않는다. 결론을 가져다 쓸 때는 문서 안의 단서(표본 수·조건)를 함께 읽는다.
- 지위가 **회의용**인 문서는 그 회의에서 무엇을 정해야 하는지를 적은 것이다. 결정이 나면 대상 문서 쪽이 정본이 되고, 이 문서는 그때 무엇을 왜 정했는지를 되짚는 기록으로만 남는다.
- 두 문서의 서술이 어긋나면 확정 쪽이 이긴다. 어긋난 것을 발견하면 덮어두지 말고 Slack에 올린다.

폐기된 문서는 지운다. 기각 사유는 각 문서의 「결정 이력」 절과
PR 본문에, 판본은 git 이력에 남는다.

## 규칙

- 문서도 코드와 같은 규칙 — 브랜치 → PR → dev 머지 (브랜치 이름 `docs/파일명`)
- 현행 규칙 문서(그라운드룰·레포 컨벤션·시스템흐름): 본문은 현행 한 벌. 제자리 수정하고 말미 「결정 이력」 절에 항목을 추가한다. 흔적은 커밋 이력·PR 본문·이력 절이 함께 진다
- 설계 기록 문서(카드생성논리·페르소나): 소급 수정하지 않는다
- 현행 규칙 문서에는 말미에 「결정 이력」 절을 둔다. 없으면 수정할 때 신설한다
- 기각된 안도 사유와 함께 남긴다

## 문서 작성 규칙

이 디렉터리의 문서는 `docs/` 안의 것만으로 읽혀야 한다.
레포 밖 문서(개인 노트, 회의록, 지침 등)를 근거로 쓸 때는
조항 번호나 문서명만 남기지 말고 그 내용을 문장 안에 풀어 쓴다.
판정 기준: **이 레포만 클론한 팀원이 이 문장에서 막히는가.**

프로젝트의 현재 진행 상태(주차별 상황, 미결 항목, 일정)는 이 레포에서 관리하지 않는다.
필요하면 팀장에게 요청한다.
