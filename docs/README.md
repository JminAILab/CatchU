## 문서의 무게

우선순위: **확정 > 검증된 서술 > 초안·추론.**

- 위 표의 지위가 **확정**인 문서(그라운드룰·레포 컨벤션)는 팀이 따르는 기준이다. 바꾸려면 논의해서 문서를 고친다.
- 페르소나 P1~P4는 문장마다 근거를 태그로 밝힌다. **[인터뷰]**·**[조사]**·**[결정]**은 확인된 것이고, **[추론]**은 아직 검증 전의 가설이다. `[추론]`만 근거로 결정을 굳히지 않는다.
- 지위가 **초안**인 문서는 아직 확정되지 않았다. 본문의 🔲가 미확정 지점이고, 확정 전에는 그 문서를 확정·승인된 기준으로 인용하지 않는다. 검토 입력으로 사용할 때는 지위·미결 사항·출처를 함께 밝힌다.
- 지위가 **기록**인 문서(실측·PoC 산출물·이상형 정의)는 그때 관찰하거나 정의한 것을 남긴 것이다. 소급 수정하지 않는다. 결론을 가져다 쓸 때는 문서 안의 단서(표본 수·조건)를 함께 읽는다.
- 지위가 **회의용**인 문서는 그 회의에서 무엇을 정해야 하는지를 적은 것이다. 결정이 나면 대상 문서 쪽이 정본이 되고, 이 문서는 그때 무엇을 왜 정했는지를 되짚는 기록으로만 남는다.
- 두 문서의 서술이 어긋나면 확정 쪽이 이긴다. 어긋난 것을 발견하면 덮어두지 말고 Slack에 올린다.

폐기된 문서는 지운다. 기각 사유는 각 문서의 「결정 이력」 절과
PR 본문에, 판본은 git 이력에 남는다.

## AI-DLC 산출물과의 관계

- `docs/`는 팀의 현행 기준과 문서 안내를 관리한다. AI-DLC 산출물의 원본과 승인 이력은 `aidlc/`에서 관리한다(`aidlc/spaces/default/intents/<intent>/`의 단계별 폴더와 `audit/`). 원본을 두 곳에 복제해 수정하지 않는다.
- 현재 승인된 요구사항: `aidlc/spaces/default/intents/260909-catchu-definition-review/inception/requirements-analysis/requirements.md` (2026-09-11 승인 · 기능 요구사항 45 · 비기능 8 · 후속 결정 16). 질문·답변 기록은 같은 폴더의 `requirements-analysis-questions.md`.
- 10월 MVP에 적용하는 범위·순서·착수 조건은 후속 intent의 [scope-document.md](../aidlc/spaces/default/intents/260914-catchu-october-mvp/ideation/scope-definition/scope-document.md)·[intent-backlog.md](../aidlc/spaces/default/intents/260914-catchu-october-mvp/ideation/scope-definition/intent-backlog.md)와 연결된 후속 결정을 확인한다. 산출물에 남은 작성 당시 지위와 현재 승인 여부를 구분하고, 승인 여부는 해당 intent의 `aidlc-state.md`·`audit/` 기록에서 확인한다.
- 승인된 AI-DLC 산출물이 `docs/`의 기존 기준을 대체하는 경우, 대체 대상·범위·적용 시점·승인 근거를 해당 `docs/` 문서의 본문이나 「결정 이력」에 명시한다. 명시되지 않은 충돌에는 자동 우선순위를 적용하지 않고 미결로 표시해 Slack에 올린다.
- 현재 명시된 항목: 레포 컨벤션 §1의 Next.js·NestJS·FastAPI와 배포 대상 NCP는 2026-09-13 확정이다(해당 문서 결정 이력 및 [MVP 입력](ai-dlc-input-mvp/CatchU_mvp_input.md) 참조). KPI v4.1의 초안 지위는 그대로다. AI-DLC의 후속 intent에서 검토 자료로 쓰려면 입력 문서에 필요한 내용·지위·출처·기준 커밋을 옮겨 적는다. 링크만으로는 AI-DLC가 원문을 읽지 않는다.

## 규칙

- 문서도 코드와 같은 규칙 — 브랜치 → PR → dev 머지 (브랜치 이름 `docs/파일명`)
- 현행 규칙 문서(그라운드룰·레포 컨벤션): 본문은 현행 한 벌. 제자리 수정하고 말미 「결정 이력」 절에 항목을 추가한다. 흔적은 커밋 이력·PR 본문·이력 절이 함께 진다
- 설계 기록 문서(카드생성논리·페르소나): 소급 수정하지 않는다
- 현행 규칙 문서에는 말미에 「결정 이력」 절을 둔다. 없으면 수정할 때 신설한다
- 기각된 안도 사유와 함께 남긴다

## 문서 작성 규칙

이 디렉터리의 문서는 이 저장소 안의 것(`docs/`와 `aidlc/`의 승인 산출물)만으로 읽혀야 한다.
레포 밖 문서(개인 노트, 회의록, 지침 등)를 근거로 쓸 때는
조항 번호나 문서명만 남기지 말고 그 내용을 문장 안에 풀어 쓴다.
판정 기준: **이 레포만 클론한 팀원이 이 문장에서 막히는가.**

프로젝트의 실행 상태·담당·막힘·일정은 GitHub Issue·Projects에서 확인하며 문서에 중복 관리하지 않는다([작업관리](CatchU_작업관리.md)). 설계의 미결과 결정 근거는 해당 원본에 남긴다.
AI-DLC 워크플로우의 현재 단계·승인 기록은 `aidlc/`의 `aidlc-state.md`와 `audit/`에서 확인한다. 실행 보드의 완료와 공식 단계 승인은 구분한다.
