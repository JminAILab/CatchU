# CatchU 프로젝트: 채용 데이터 기반 의사결정 발표

**CatchU(JAEMIN_AI 팀)는 개발자의 깃허브 기록에서 객관적 증거 카드를 추출해 구직자와 기업 모두에게 제공하는 채용 프로필 플랫폼 기획을 발표하고, 수익 모델·학습 데이터 등에 대한 피드백을 수렴했다.**

---

## 1. 회의 요약

**발표 배경 및 문제 정의**

현행 채용 프로세스에서 기업(HR·HM)은 자기소개서·포트폴리오 위주로 지원자를 검토하며, 깃허브 데이터는 README 수준에서만 참고된다. 제출 서류에는 지원자의 주장만 담겨 있고 객관적 근거가 없어, 검증은 전적으로 면접에 의존한다. 구직자 역시 잡 디스크립션과 깃허브만으로는 "어떤 내용을 써야 할지" 판단하기 어렵다.

**서비스 개요: CatchU**

모토는 **"점수 대신 근거"**. 깃허브 커밋·레포지토리 기록에서 판단의 흔적을 **증거 카드** 형태로 추출하여, 구직자에게는 면접 준비 자산으로, 기업에게는 열람 가능한 근거로 제공하는 **프로필 플랫폼**이다. 기존 채용 프로세스(기업 ATS)를 대체하지 않고 링크드인 포지션으로 보완하는 구조를 지향한다.

**경쟁 서비스 분석 및 차별화**

- **점수형 분석 서비스**(예: Gilroy 계열): 기술 팀장급 인터뷰에서 "판단은 내가 하고 싶다, AI 판정을 믿을 수 없다"는 강한 반발 확인.
- **채용 공고 플랫폼**(사람인 등): 현장에서는 사실상 홍보용이며, 기업은 자체 ATS로 이동 중.
- CatchU는 두 시장 모두 깃허브 데이터의 핵심 가치가 희석된다고 판단, **링크드인형 증거 제공 플랫폼**으로 포지셔닝.

**인터뷰 인사이트**

- HR 담당자: 필터링용 추천 근거 및 기술 매칭 요청.
- HM(기술 팀장): "근거를 가져와라, 판단은 내가 한다"는 스탠스 → 시스템은 증거 서빙만 수행, 판단은 사람이 담당.

**기능 범위 및 기술 스택**

- 구직자: 깃허브 연결 → 레포지토리 선택 → 증거 카드 생성 → 어필 프리셋 구성 → **링크 발행**(자기소개서·포트폴리오·카드 세트 일괄 제공).
- 기업: 발행된 링크로 지원자 정보 열람 및 증거 카드 기반 검색.
- 기술 스택: 프론트엔드 **Next.js**, 백엔드 **Next.js 또는 FastAPI**, 분석 **상용 LLM API**.

**Q&A 주요 내용**

- *AI 신뢰 문제*: AI는 판정이 아닌 증거 서빙 역할에 한정; HM은 최대한 많은 정보를 직접 판단하길 원함.
- *시장 규모*: 2026년 공채 예정 기업 약 54%, 나머지는 수시 채용 → 수시 채용 중심 서비스로 시장 충분히 크다고 판단.
- *타겟 확장*: 초기 개발자 중심이나, AI 보편화로 일반인의 깃허브 활용 증가 시 확장 가능.
- *수익 모델*: 구직자가 **링크 발행 시 과금**; 기업은 헤드헌팅(비연결 지원자 정보 열람) 시 과금. 링크드인 모델 참조.
- *학습 데이터·과적합*: POC는 발표자 본인 레포지토리로 진행 → 편중 분석 경향 인지; 향후 동기 프로젝트 데이터 수집 및 표본 확대로 해결 예정.

## 2. 핵심 액션 아이템

1. **와이어프레임 및 ERD 완성** — 현재 착수 중이며, 7주 차 이전 기획·설계 단계를 마무리하기 위해 조속히 확정 필요.
2. **증거 카드 생성 알고리즘 고도화** — POC에서 발표자 레포지토리 편중 문제가 확인되었으므로, 다양한 표본으로 LLM 분석 기준을 재정립.
3. **학습·검증 데이터 확보** — 동기 프로젝트 데이터 수집 협의 및 더미 데이터 병행 구성으로 과적합 리스크 완화.
4. **수익 모델 세부 설계** — 링크 발행 과금 구조(구직자)와 헤드헌팅 열람 과금(기업)의 가격 정책 및 무료/유료 경계 구체화.
5. **성공 지표 정의** — 증거 카드 동의율, "이런 것도 했었지" 회상률 등 정성 지표를 수치화 가능한 형태로 설계.
6. **MVP 개발 착수 및 완료** — 7주 차 이후 개발 시작, 12주 차(2주 차 MVP 기준)까지 핵심 기능 완성.
7. **Q&A 피드백 반영** — 시장 규모 데이터 보완, 타겟 확장 로드맵, AI 신뢰 문제 대응 방안을 최종 발표 전 기획서에 반영.

- **~7주 차**: 와이어프레임·ERD 확정, 기획·설계 완료. 데이터 수집 협의 병행.
