**A02-03 — 공개 범위 2단 (09-01 확정)**
목록의 "등급"은 A09의 촌수와 같은 축이다. 촌수 체계는 **맞팔 1단**으로 확정됐다.
→ **전체 공개 / 맞팔 공개** 2단. 이 축은 숨김과 층이 다르다 —
숨김은 "어디에도 없음"이고, 공개 범위는 공개된 것 안에서 누가 보느냐다.

**A02-01 기술 스택 (⚑1 확정 09-01)**
- **지원자가 자가 입력한다.** 카드에서 자동 추출하지 않는다
- 각 항목에서 **관련 레포로 가는 링크**를 건다. 판정 기준은 **의존성 파일**
  (`package.json`·`requirements.txt`·`build.gradle`·`go.mod` 등)에 그 기술이 있는지
- **배지·체크마크·개수 표시 없음.** 링크가 걸리느냐 아니냐로만 드러난다.
  안 걸려도 부족하다는 표시를 하지 않는다
- 근거: 우리가 문제 삼은 것은 선언 자체가 아니라 **근거 없는 선언**이다.
  링크가 그 근거이고 판정은 열람자가 한다. 개편 전 "자가 입력 배제"는
  자가 입력만 있던 상태의 판정이라 사유가 성립하지 않는다
- 미결: 의존성 파일이 없는 레포(순수 C·스크립트 모음)는 링크가 안 걸린다.
  GitHub 언어 감지를 보조로 쓸지 미정 / 화면 문구 — "확인됨"은 우리가 인증한 것처럼
  읽힌다. 2단계에서 정할 것

기술 스택·연차는 검색 필터의 1차 키다(팀 조사). B04와 대응하는 필드가 있어야 한다.

**A05-02 제약**
- **시스템이 주장을 생성·추천하지 않는다** (기각 확정)

- **카드 탐색 동선**: 페이지를 벗어나지 않고 A04를 훑을 수 있어야 한다.
  구체적 형태(모달·패널·인라인)는 프론트 판단

**어필 프리셋 구조 (⚑2 확정 09-01)**

**프리셋 = 주장 + 붙은 카드 한 벌.** 여러 벌 만들 수 있고 그중 하나가 **디폴트**다.

| 쓰이는 곳 | 어느 프리셋 |
|---|---|
| A02 프로필 | **디폴트** |
| A07 링크 발행 | 발행할 때 고른다. 지원처마다 다르게 |

→ "대표 카드 선택"이라는 별도 화면은 없다. 프리셋을 만드는 것이 A05이고,
그중 무엇을 디폴트로 할지 지정하는 것뿐이다. A06(서류)의 프리셋과 같은 축이다.

**디폴트가 없을 때** — A02의 어필 영역이 빈다. **계정 주인에게만** 프리셋 생성 CTA가
보이고 타인에게는 그냥 없는 것으로 보인다. `아직 없습니다`까지만 쓰고 부족하다는
표현은 쓰지 않는다.

**프리셋 안의 카드를 숨겼을 때** — 타인에게는 존재하지 않는 것으로 보이고,
**계정 주인에게는 프리셋 안에서 숨김 상태가 시각적으로 표시된다.**
발행된 링크에도 즉시 반영된다. 가시성이 큐레이션보다 상위라는 구조를 화면으로 옮긴 것.
주인만 보는 표시이므로 열람자에게 빈칸이 신호가 되는 문제는 생기지 않는다.

**A09-01 팔로우 체계 (09-01 확정)**
- **팔로우는 일방. 맞팔이 되면 관계 성립** — 확장 공개 범위가 열린다
- **1단만 쓴다.** 2단(맞팔의 맞팔)은 계산이 커지고 본인이 관여하지 않는 사이에
  노출이 넓어진다
- **승인 화면 없음.** 팔로우당하면 알림이 가고, 그걸 보고 맞팔할지 정한다
- 근거: 일방 팔로우 기준으로 공개 범위를 열면 **거리를 상대가 정하게 된다.**
  맞팔은 본인 동의가 들어가므로 통제된다

**A09-02·03은 와이어프레임 그리지 말 것.** 추천 알고리즘(단체·위치·관심사·유명인사)과
DM은 **"개발자끼리 연결이 이 서비스에서만 되는 것이 무엇인가"**가 안 닫혔다.
딸려오는 부담: DM 필터링·신고·차단·탐지 로그.

## B04 구직자 검색

| ID | 화면 | 상세 | 순위 |
|---|---|---|---|
| B04-01 | 검색 입력 | **기술 스택 + 연차 중심** + 희망 조건 필터(지역·연봉·기업 규모·근무 형태) | 1 |

  디폴트 프리셋까지만 보인다

## B05 열람 화면 (A07의 결과물)

| ID | 화면 | 상세 | 순위 |
|---|---|---|---|
| B05-01 | 링크 진입 | 비회원. 비밀번호 인증. 만료 시 **중립 안내(사유 노출 금지)** | 1 |
| B05-02 | 탭 프레임 | 이력서 / 자소서 / 포트폴리오 / 카드 / RAG | 1 |
| B05-03 | 서류 탭 | 이력서·자소서 텍스트, 포트폴리오 뷰어 | 1 |
| B05-04 | 카드 탭 | 주장 + 붙은 카드 + 근거 링크 + 경계 등급 | 1 |
| B05-05 | RAG 검색 탭 | 자연어 질의 → **카드 목록 + 링크만.** 대상은 **숨김을 제외한 전체 카드** | 1 |
| B05-06 | 렌즈 전환 | 지원자 JD / 공고 JD / 내부 조건 프리셋 | 2 |
| B05-07 | 내부 조건 프리셋 관리 | 저장·재사용. **회원 전용** | 2 |

**공통 제약**
- **기업은 지원자 JD를 수정하지 않는다.** 자기 JD를 추가로 건다
- **내부 조건 프리셋은 지원자에게 안 보인다**
- 비회원에게 프리셋은 **회색 표시(선택 불가)** — 회원 전환 유도
- 숨긴 카드의 존재·개수 노출 금지 — 가시성은 전역 축이라 어느 탭에서도 안 보인다
- 편집 횟수·기본값 사용 여부·발행까지 걸린 시간 노출 금지

**B05-04(카드 탭) 제약**
- **세트 밖 카드 노출 금지.** 이 탭이 보여주는 것은 지원자가 이 링크에 담은
  어필 프리셋 한 벌이다

**B05-05(RAG 검색 탭) 제약**
- **검색 대상 = 숨김을 제외한 전체 카드.** 제출 세트에 한정되지 않는다.
  세트 탭과 다른 물건이다 — 세트는 지원자의 주장이고, RAG는 주장 층을 걷어낸
  원자료 탐색이다. 기업은 제출된 주장을 보고 같은 화면에서 주장 밖을 검색한다.
  둘 다 있어야 대조가 성립한다
- **걸리는 기준은 숨김 하나뿐이다.** A04-05의 공개 범위(전체·맞팔)는 구직자끼리
  누가 보느냐의 축이라 기업 열람 경로에 적용되지 않는다. 어느 프리셋에 담겼는지도
  조건이 아니다 — 프리셋은 세트 탭이 쓰는 축이고 이 탭은 쓰지 않는다
- **출력은 카드 목록과 링크뿐.** 요약·총평·순위·점수 금지
- 지원자가 A07-02에서 검색 허용을 끄면 이 탭이 비활성화된다
