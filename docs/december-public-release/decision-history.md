# 12월 공개판 범위 확인과 결정 이력

지위: **후속 계획의 결정 기록**. 10월 9~12일 논의에서 선택한 범위를 10월 12일 항목별로 재확인·정리했다. 아래 날짜는 각 확인·정리 시점을 나타내며 모든 방향을 그날 처음 선택했다는 뜻은 아니다. [범위 변경표](scope-changes.md)와 함께 읽으며 AI-DLC 승인·구현·배포 완료 기록을 대신하지 않는다.

## 결정 이력

- **2026-10-12** — 10월 9~12일 팀장 선택을 승인 원본 FR·US와 대조한 팀 검토용 초안을 작성했다. 기존 승인 원본·추적표·10월 구현 계약을 변경하지 않았다. 담당 배정·공식 설계 재개·구현·배포·원격 등록을 수행한 기록이 아니다.

- **2026-10-12 — FR11 범위 확인:** 팀장은 특정 발송자 계정의 새 안내만 차단·해제하고 기존 안내와 검색·자료 열람은 각 조건을 유지하는 범위를 확인했다. 소속·역할 변경이나 구직 의사 ON으로 차단을 해제하지 않고, 해제 후에도 현재 발송 조건을 확인하며 거부했던 안내를 자동 전달하지 않는다. 기업 전체 차단과 운영자의 계정 발송 중단은 구분한다.

- **2026-10-19 — 실패 안내와 사용량:** 분석·JD·AI의 실패 실행을 자동 재호출하지 않고 기존 자료를 보존하며 사용자가 직접 재요청하도록 정했다. 사용 기록은 영속 보관하고 시작 후 실패도 집계하되 실행 전 거부는 제외하고 같은 실행의 중복 전달은 한 번만 센다. 회원의 여러 MCP 연결·같은 링크의 웹/MCP CatchU AI 호출은 합산하며 다른 허용 열람은 유지한다. 채용 안내 계정 쌍 반복 제한의 실제 전달 집계는 바꾸지 않고, 정상 실행 안의 기존 생성 단계·제목 형식 보정과 실패 실행 재시작을 구분한다. 실제 상한·기간은 후속 설계에 남긴다.
- **2026-10-19 — 수동 운영 방식 선택:** 삭제 실패를 기록하고 운영자가 수동 재처리해 실제 정리 결과를 확인하도록 정했다. 이는 10월 12일의 수동·자동 처리 방식 미결을 구체화한 결정이다. 문의는 외부 연락 채널 하나의 수동 확인·회신으로 받고, 사용자 차단과 제보에 따른 운영자의 계정별 새 안내 수동 발송 제한·해제를 유지한다. 자동 재시도·자동 제재·별도 고객센터·신고함·관리자 화면은 추가하지 않으며 주소·담당·수동 실행 수단·기록 기간은 설계에 남긴다. 상세는 [운영 최소화 기준](operations.md)을 따른다.
- **2026-10-19 — 반자동 복원과 확정 EKS 연결:** 운영자가 스크립트로 복원을 실행하고 최종 확인과 실제 서비스 반영은 수동으로 수행한다. 12월 시험은 별도 이름 DB 복원·원본 대조·시험 자원 정리로 한정하며 운영 DB 전환 시험은 추가하지 않는다. 구성 정본은 [#276 본문](https://github.com/JminAILab/CatchU/issues/276)·[10월 19일 결정 댓글](https://github.com/JminAILab/CatchU/issues/276#issuecomment-6260130109)과 [#342 자동 배포 전환](https://github.com/JminAILab/CatchU/issues/342)이다. 제품의 자동 재호출 제한과 인프라 장애 조치·노드 복구·재연결·자동 배포를 구분한다.
- **2026-10-19 — 일정 고정점의 후속 구체화:** 날짜별 자원 생성·기능 착수 배치는 고정하지 않고 단계별 시작 조건을 따른다. EKS 생성은 11월 9일보다 앞당기지 않으며 11월 30일 핵심 흐름 외부 확인, 12월 9일 00:00 동결, 12월 10일 제출과 제출 확인 후 지원 계정 기한 전 정리를 고정점으로 둔다. 팀장이 전달한 실행 조건에 따라 두 API·복원 검증은 12월 8일까지 진행하고, 12월 1일까지 미전환이면 남은 검증 일정을 재판단한다. 10월 12일의 참고 일정 기록은 보존하되 현재 적용 조건은 [실행 계획](delivery-plan.md#확정된-eks-전제와-12월-검증)을 따른다. 예산은 100만 원이며 약 91만 원 추정은 11월 12일 생성 가정임을 함께 명시한다.
