# 12월 공개판 범위와 승인 원본의 변경 관계

작성일: 2026-10-12. 최근 결정 반영: 2026-10-19. 지위: **팀 검토용 초안**. 2026-10-09~12와 10-19 팀장이 선택한 제품·운영 방향을 정리한 후속 문서이며, AI-DLC 단계 승인·구현·배포 완료 기록이 아니다.

## 적용 범위와 읽는 법

목표는 불특정 사용자가 이용할 수 있는 12월 공개판이다. 작성 회원은 취준생, 링크 수신자와 기업 회원은 HR·기술 면접관의 이용 경로를 나타낸다. 작성·공유, 기업의 발견·채용 안내, JD·근거 검토, 제품 MCP 세 흐름을 완성한다. 기능별 중간 배치는 조정 가능한 참고안이다. 2026-10-19 후속 결정으로 11월 30일 핵심 흐름 외부 확인·12월 9일 00:00 변경 동결·12월 10일 제출과 제출 확인 후 자원 정리를 고정점으로 적용한다. EKS 전환과 검증의 시작 조건·예산은 [실행 계획](delivery-plan.md#확정된-eks-전제와-12월-검증)을 따른다. 실제 진행과 구현 가능성은 팀 회의·담당 배정·작업량 산정으로 확인하며 승인 원본의 과거 날짜 기록은 보존한다.

이 문서의 FR·US 번호는 모두 `260925-intent-12`의 [승인 요구사항](../../aidlc/spaces/default/intents/260925-intent-12/inception/requirements-analysis/requirements.md), [사용자 스토리](../../aidlc/spaces/default/intents/260925-intent-12/inception/user-stories/stories.md), [추적표](../../aidlc/spaces/default/intents/260925-intent-12/inception/user-stories/traceability.json)를 가리킨다. 승인 지위와 후속 설계 경계는 [12월 승인 문서 안내](../CatchU_12월_승인문서_안내.md)를 따른다.

- **유지**는 승인 원본의 동작을 이어 적용한다는 뜻이다.
- **변경·이연**은 이번 공개판에 적용할 후속 선택이다. 승인 원본의 과거 문장·승인·추적표는 수정하지 않고, 해당 기능의 설계 입력에 아래 차이를 함께 옮긴다.
- **팀 논의 보류**는 제외 확정이 아니다. 결정 전 특정 화면이나 구현 방식을 채택하지 않는다.
- 이번 범위 확인과 사전 설계는 공개판 구현 대상에 한정한다. 이연·비필수 항목은 범위 경계만 남기고 상세 동작·설계·완료 기준을 추가로 구체화하지 않는다. 개발 여력이 생겨 실제로 추가 개발하기로 하면 해당 기능 개발 단계에서 담당자가 설계한다.
- 이는 9월 28일 승인·정지 기록의 비필수·후순위 상세화 인계를 공개판 구현 대상 중심의 기능별 설계 참여로 조정한 후속 방침이다. 기존 인계·정지 기록은 보존한다.
- 이 초안의 검토·반영만으로 10월 구현 계약을 바꾸거나, 정지된 기존 12월 intent를 재개하지 않는다. 관련 12월 설계·계약과 완료 기준에 변경 관계를 연결한 뒤 구현에 적용한다.

담당 배정은 추후 팀 회의에서 정한다. 설계 방식·공통 경계·일정은 [실행 계획](delivery-plan.md), 완료 판단은 [완료 기준](acceptance.md), 팀원의 작업 선택과 포트폴리오 관점은 [작업 설명](work-guide.md)에 정리한다.

## 운영 최소화

2026-10-19 팀장은 GitHub·등록 자료의 지속 추적을 줄이고, 실패 안내·기존 자료 보존·사용자 직접 재요청, 삭제 실패 기록과 운영자 수동 재처리, 외부 문의 채널 하나와 수동 발송 제한, 스크립트 기반 반자동 복원을 선택했다. 실행량은 시작 후 실패도 집계하되 실행 전 거부와 같은 실행의 중복 전달을 구분한다. 상세 동작·원본 변경 경계·남은 값은 [운영 최소화 기준](operations.md)을 따른다.

이 선택은 FR1·3·4.5·6·13~15·19와 OQ4·8·11·13의 관련 동작에 한정한다. 서비스가 관리하는 현재 접근 조건과 자료 파기는 유지하고, 기존 승인 원본과 10월 실행 계약은 소급 수정하지 않는다.

## 작성 자료와 발행 고정본

### 수동 재분석과 주장 보존

2026-10-11~12 선택은 FR1.3·US1.3의 **정상 완료 재분석 미추가** 조건을 바꾼다. 새 커밋 이후에도 자동 분석하지 않으며 사용자가 수동 요청한다. 진행 중·실패 시 기존 결과와 주장 연결을 유지하고, 성공했을 때만 재분석한 저장소의 Catch 전체를 교체한다. 다른 저장소 결과는 교체하지 않는다.

기존 주장에 연결된 Catch도 교체 대상이다. 등록된 주장의 제목·본문은 서버에 남기고 작성자가 수정 화면에서 새 Catch를 선택한다. 자동 연결 대응 기능은 추가하지 않는다. FR2.3·2.6과 US2.1~2.2는 다음처럼 연결한다.

- 새로 작성 중인 미등록 글만 클라이언트 임시 저장한다. 저장 기술은 미정이며 서버 초안 저장·기기 간 동기화를 요구하지 않는다.
- 재분석 후 사용 가능한 Catch 연결이 없어진 등록 주장은 서버에 제목·본문을 보존하되 새 Catch를 연결하기 전까지 현재 공개·검색·AI 참고·새 발행에 사용하지 않는다. 새 Catch를 연결한 뒤에도 Catch 숨김·주장 공개 등 현재 이용 조건을 적용한다. 다른 저장소의 사용 가능한 Catch가 남은 경우와 구분한다.
- 이미 발행한 공유본은 FR4·US4.3의 고정 내용을 유지하고 자기 링크의 접근·수명 조건을 적용한다.

Catch 개별 원본 삭제 없이 숨김으로 관리하는 FR1.5는 유지한다. 재분석으로 생성한 새 Catch도 기존처럼 초기 상태를 숨김으로 한다. 재분석의 저장·전환 방법과 횟수·비용 한도 등 나머지 사항은 후속 설계에서 정한다. 이 확장분의 개발량은 아직 산정하지 않았다.

### 서류·공유·보관

자기소개서는 텍스트 입력·붙여넣기, 이력서는 PDF, 포트폴리오는 PDF 또는 외부 URL로 여러 벌 등록한다(FR3.1). 종류별 한 벌 제한은 채택하지 않았다. URL은 외부 이동용이며 본문 수집·고정·AI 참고를 하지 않는다. 열람 가능한 PDF가 AI 읽기에 실패해도 등록·공유할 수 있고 미참고 범위를 알린다.

공유본은 FR2.4·US2.3대로 대표 주장 하나와 선택적인 추가 주장·서류를 고른 뒤 선택된 주장·Catch·텍스트/PDF 내용과 URL 주소를 고정한다. 프로필 대표 지정과 공유본별 대표 선택을 혼동하지 않으며 선택하지 않은 자료를 함께 제공하지 않는다. 비로그인 웹 열람·JD 검토는 기존 링크 조건 안에서 유지한다.

작성자는 아직 유효하고 중단·삭제되지 않은 링크의 기간을 만료 전에 연장할 수 있다. 연장은 같은 주소와 고정 내용을 유지한 채 만료 시점만 바꾸며, 변경된 만료 시점을 확인할 수 있어야 한다. 만료·중단된 링크는 연장으로 되살리지 않고 다시 전달하려면 새로 발행한다. 기존 FR5.4·FR17.11·US17.15의 비필수 편의 중 이 연장 기능만 이번 구현 범위로 채택한다. 발행 시 만료일 직접 선택·발행 후 비밀번호 변경까지 필수로 올리지 않으며, 연장 횟수·최대 기간·조작 방식은 후속 설계에서 정한다.

작성자는 종료 후 정한 기간 발행 내용을 확인하거나 직접 삭제할 수 있다. 그 기간 뒤 자동 파기하며 기간값은 OQ3에서 정한다. 일반 링크 보관 기간을 탈퇴 후 보관 근거로 쓰지 않는다.

10월의 현재 권한을 반영하는 링크와 12월의 고정 공유본은 정책이 다르다. 구형 링크 자동 이관을 추가하지 않으며, 실제 개발·시험 데이터 초기화 대상은 배포 준비 시 확인한다. 이번 문서 작성으로 데이터를 삭제하지 않는다.

## 기업 자격·공개·검색

### 두 역할과 공개 범위

2026-10-11 결정으로 기업 직접 등록과 소속 신청·관리자 승인은 유지하고, 역할은 관리자와 기업 일반 회원 두 가지로 둔다. 기업 일반 회원은 **소속 승인을 받은 회원**이다. 기업 소속이 없는 구직 회원끼리 후보를 검색하는 기능을 뜻하지 않는다. 등록·승인만으로 실제 기업·재직 인증을 보장하지 않는다.

관리자와 기업 일반 회원 모두 자료 검토·기업 검색·채용 안내를 이용하고, 관리자에게만 다른 회원의 소속·역할 관리 권한을 둔다. 본인의 소속 해제·마지막 관리자 조건·탈퇴는 별도로 유지한다. 세부 역할·사용자 정의 권한은 향후 확장 대상으로 둔다. FR13.4·US13.4의 기존 검토자 검색 금지는 두 역할 구조에 맞춰 바꾼다.

| 자료·행동 | 이번 공개판의 접근 기준 |
|---|---|
| 프로필 대표 | 공개한 주장 중 하나를 대표로 선택. 제목·본문·허용 Catch를 전체 공개하며 기존 주장 사용 조건을 적용한다. |
| 대표 외 공개 주장 | 승인 기업 회원이 구직 의사·자료 조건을 충족할 때 무료 열람. 일반 방문자에게 전체 공개하지 않는다. 별도 주장별 기업 열람 스위치는 두지 않는다. |
| 검색·새 안내 수신 | 기본 OFF인 구직 의사 하나로 함께 제어. ON이면 허용 공개 주장·Catch를 검색 근거로 사용하고 채용 안내를 받을 수 있음을 알린다. |
| 구직 의사 OFF | 새 검색 발견·안내 수신과 기업의 추가 주장 새 조회를 중단. 과거 열람 기업도 예외 없이 적용하며 대표와 기존 공유본은 각자의 접근 기준을 유지한다. |
| 계정은 유지하고 OFF로 전환한 경우 | 이미 받은 안내는 계속 읽는다. 주장 공개 상태·자료 내용·기존 안내를 그 이유만으로 삭제하지 않는다. |

기업 열람을 무료로 제공하는 것은 결제·마일리지·구독 개발을 포함하지 않는다. 향후 정보 열람 비용을 받는 BM은 구상이다. FR8.4의 추가 자료 열람 전 제목·무료 안내, 열람 후 본문·허용 Catch 제공은 유지한다. 단계 통합을 채택해 이 조건을 없앤 결정은 없으며 별도 페이지·팝업 등 구체 화면은 설계에서 정한다.

새 주장 공개 기본값, 검색에 대표 지정이 필요한지, 비공개 주장을 공유본·본인 MCP에 사용할 수 있는지는 관련 설계 전에 확인한다. 원본 FR8.2의 검색 대표 조건과 FR8.3의 기본 기업 열람 미허용을 이미 삭제한 것으로 해석하지 않는다. 공개 주장들을 검색 근거로 삼는다는 선택만으로 이 세부 조건을 확정하지 않으며, 숨김·Catch 사용 조건은 유지한다.

### 자연어 벡터 검색

2026-10-11 결정으로 FR9.1의 구조화 필터·FR9.4의 필터용 기술 표기 대응을 이연하고, FR9.2의 모든 단어 문자열 일치를 자연어 관련성 검색으로 바꾼다. FR9.3의 유사도 순위 미추가와 FR9.4·AC9.1.4의 의미 검색 미추가 조건은 자연어 벡터 검색을 허용하는 범위에서 대체한다. US9.1의 필터 흐름, US9.2의 검색 판정과 US9.3의 유사도 제외 문구도 이에 맞춘다. 관련 근거·출처·한계는 유지하며 후보 평가·자동 조건 완화까지 허용하지 않는다.

기업 회원이 자연어로 경험을 입력하면 현재 허용된 공개 주장·Catch에서 관련 내용을 찾고 후보별로 묶어 원문 근거를 보여준다. 기술·직무 필터, 검색어 조건 자동 추출, 필터용 기술 추출·정규화·분류를 필수로 만들지 않는다. 서류 전체·고정 공유본을 검색 대상으로 추가하거나 후보 평가문·매칭 퍼센트·대화형 추천을 제공하지 않는다.

2026-10-12 결정으로 검색 품질은 시험 자료와 소수 검색어의 관련 후보·실제 근거 연결을 직접 확인한다. 별도 평가셋·정량 합격점·모델 비교·반복 순위 최적화는 이연한다. 자료 변경·숨김·비공개·구직 의사 OFF·탈퇴의 반영과 웹/MCP의 동일 권한은 계속 확인한다. 결과 없음·실패·준비 중을 구분하며 관련성을 기술 사용 확정이나 역량 점수로 표현하지 않는다.

벡터 저장소·임베딩 모델·정렬 방식은 미정이다. 임베딩 생성·갱신·삭제 반영과 비용·한도는 남는 작업이다. NFR4·OQ5의 기존 짧은 문자열·다중 기술 조건 측정은 새 검색 방식에 맞게 후속 설계에서 정합화하며 특정 기술 도입이나 일정 절감을 확정하지 않는다.

## 채용 안내·차단·연락처

2026-10-09 방향 선택과 10-11 후속 확인에 따라 기업 검색 이후를 **안내 전달과 외부 이동**으로 완성한다.

1. 기업 관리자 또는 승인 기업 일반 회원이 검색에서 후보와 근거를 확인한다.
2. 제목(포지션)·본문(업무·요구사항·안내 사유)·기업 측 외부 지원/연락 경로의 단순한 작성 폼을 기본안으로 안내를 작성해 보낸다. 실제 발송 때 현재 기업 자격·구직 의사·계정 차단·운영 발송 중단·반복 한도를 다시 확인한다.
3. 구직자는 받은 안내 목록·상세를 읽고 외부 경로로 이동할지 선택한다. 발송자는 본인의 간단한 발송 목록·상세를 확인한다.
4. 수신자는 특정 발송자 계정의 새 안내를 차단·해제할 수 있다. 같은 기업의 다른 계정으로 차단을 확대하지 않으며, 차단 해제·구직 의사 ON으로 거부된 안내를 자동 전달하지 않는다.

작성 폼은 고정된 입력칸 명세가 아니다. 담당자의 개선 의견을 적극 반영해 입력항목의 묶음·표현·배치와 조작 흐름을 설계에서 수정할 수 있다. 안내 전달·읽기·외부 이동의 목적과 발송·열람 조건을 유지하며, 별도 공고/JD 관리 기능을 선행으로 만들지 않는다.

FR10.2~3·US10.2의 발송 자격·계정 쌍 반복 제한은 실제 전달만 집계하고 실패·미전달은 제외하는 기존 기준을 유지한다. 이는 분석·AI 실행량의 실패 집계와 구분한다. 이어서 FR10.4·US10.3의 **열람은 남기고 수락·거절은 이연**한다. FR10.5~6·US10.4~10.5의 수락 취소·미응답 철회, 전달 후 수정, 읽음 추적·별도 도착 알림·기업 공동 관리함·채용 진행 관리는 이번 필수 범위에 넣지 않는다. 발송 전에는 전달 후 수정·회수가 불가능함을 알린다.

FR11·US11.1은 특정 발송자 안내 차단에 맞춘다. 기존 안내는 차단만으로 삭제하지 않고, 차단을 검색·자료 열람·MCP 제한으로 확대하지 않는다. 차단한 계정의 소속·역할 변경만으로 차단을 해제하지 않는다. 수락·연락처 분기는 이연하고 DM을 이 기능의 선행으로 만들지 않는다.

차단자가 구직자이면서 기업 회원이기도 한 경우 상대에게 보내는 역방향 안내의 처리까지 확정한 것은 아니다. FR11.2·AC11.1.1~2의 양쪽 연락 제한과 달라질 경계를 묶음 6의 설계 전에 확인하며, 이번 표현만으로 역방향 허용·차단을 새로 결정하지 않는다.

FR12 전체와 US12.1~12.2는 이연한다. 로그인 연락처 자동 공개나 서류에 직접 적힌 연락처 자동 제거를 제공하지 않는다. 외부 경로에 후보 자료·연락처를 자동 첨부하지 않으며, 외부 이동을 지원 완료·연락 성공으로 표시하지 않는다. 공고 관리·ATS 연동·DM·이메일/SMS 발송을 선행 기능으로 추가하지 않는다.

구직자 탈퇴 후에는 기업 발송자가 해당 안내 원문·구직자 자료를 새로 조회하지 못한다. 기존 주소·열어둔 화면의 새 조회에도 적용한다. FR14.7·US14.1의 과거 제안 열람 방향을 이 범위에서 바꾸며, 이름만 ‘탈퇴한 회원’으로 바꾸고 본문을 남기지 않는다. 목록 제거/내용 없는 상태 표시·최소 보관 항목과 발신자 탈퇴 시 수신자 표시의 세부는 OQ11에서 확인한다.

## JD·AI 검토와 제품 MCP

### 현재 자료의 검토 유지

JD 직접 입력·요약·현재 자료 관련 패널·질의응답과 AI가 제안하는 관련 Catch 근거 후보는 FR6·US6.1~6.4대로 유지한다. 작성자의 명시 연결과 AI 후보를 구분하고 저장된 연결을 자동 변경하지 않는다. 서류별 AI 참고 제외는 유지하며 미공유·읽기 불가 자료와 외부 URL 본문을 참고하지 않는다.

공유 링크 외에 기업 경로로 허용된 추가 주장도 검토할 수 있다. 이 경로에는 현재 기업 자격·구직 의사·주장 공개·Catch 이용 조건을 함께 적용하며, 공유본 접근이나 과거 열람으로 현재 제한을 우회하지 않는다.

2026-10-12 결정으로 근거 있는 질문·근거 없는 질문·제외 서류가 있는 경우를 소수 사례로 직접 확인한다. 별도 평가셋·점수 평가·답변 문장의 반복 개선은 이연한다. 권한·출처·확인 한계·호출 한도·유효 원문 열람은 유지한다. NFR3·OQ6의 JD 평가 작업량을 조정하는 것이며 Catch 생성의 기존 근거 링크·기여 귀속 기준까지 낮추지 않는다.

재방문용 JD·질문·AI 답변 이력 저장과 이어보기는 제공하지 않는다. 이는 FR6.6·US6.4에서 이미 자동 추가하지 않던 범위를 재확인한 것이므로 신규 필수 작업 절감으로 세지 않는다. 현재 검토·요약 재사용을 위한 최소 저장 여부와 수명은 OQ9·OQ11, 외부 AI의 처리 조건은 OQ12에서 정한다. 서비스·외부 도구의 무저장을 확정한 결정이 아니다.

### 외부 도구 한 종류에서 세 흐름

2026-10-12 결정으로 외부 도구 **한 종류**를 선정해 세 흐름을 모두 지원·검증한다. 한 명·한 연결만 허용한다는 뜻이 아니며 같은 회원의 여러 연결 요청 합산은 유지한다.

| 받은 공유본 검토 | 관리자·승인 기업 일반 회원. 기업 자격과 해당 링크의 비밀번호·만료·중단·삭제 조건을 함께 적용 | FR13.3·US13.3 |
| 후보 검색 | 관리자·승인 기업 일반 회원. 웹과 같은 구직 의사·주장 공개·허용 Catch 및 현재 접근 조건 | FR13.4·US13.4 |

FR13.1·13.5~7·US13.1의 연결 명시 승인·해제·현재 권한·요청 한도·읽기 전용 경계를 유지한다. 외부 도구의 LLM 이용과 CatchU의 새 AI 호출은 구분하고, 같은 링크의 CatchU AI 호출은 경로와 무관하게 합산한다. 한도 소진을 다른 허용 열람까지 막는 조건으로 확대하지 않는다.

실제 도구·판본·지원 환경·인증·외부 처리 조건은 관련 구현 전에 확인한다. 다른 도구 지원·호환성 검증은 후속 확대이며 한 도구 성공을 전체 호환으로 표현하지 않는다. 브라우저 MCP를 통한 웹 흐름 검사와 제품 MCP 직접 호출 검사는 기능 준비에 맞춰 병행한다. 개발 전용 MCP는 여유가 있을 때 반복 시험의 준비·실행·결과 확인을 묶는 선택 작업으로 둔다. 실제 착수 시 필요·구현/유지 비용을 확인하고 설계하며, 공개판 완료의 선행 조건이나 제품 MCP 쓰기 추가 근거로 삼지 않는다.

| 삭제 실패 | 10-19 선택: 실패 대상·처리 상태를 기록하고 운영자가 수동 재처리. 필요한 접근 중단을 유지하고 실제 정리 확인 뒤 완료 안내. 자동 재시도·별도 관리자 화면은 추가하지 않음 | FR5.2~3·14.5, US5.2~5.3·14.2, OQ11·13 |

운영 발송 제한은 전면 계정 정지가 아니다. 개인 자료·독립 공유 링크·검색·검토·MCP는 각자의 기존 조건을 따른다. 해제 뒤에도 현재 발송 자격·구직 의사·수신자 차단·한도를 확인하고, 거부한 안내 자동 전달이나 탈퇴 계정·종료 기업 복원을 하지 않는다. 별도 신고함·고객센터·자동 제재·관리자 화면은 추가하지 않는다. 외부 문의 주소·담당과 수동 조치 실행 수단은 후속 설계에서 정한다.

개인정보 처리에 관한 위 항목은 합의한 제품 행동과 후속 확인의 경계다. 실제 법적 적용·예외 보관·운영 주체·담당자 확정은 완료되지 않았다. OQ11·OQ12의 자료별 처리 목록·근거·기간·접근·캐시·백업·외부 AI/MCP 조건을 관련 개발·실제 처리 전에 확인한다. 해석이 필요한 예외는 전문가 또는 공식 상담으로 확인한다.

AWS는 [현행 문서 기준](../README.md)의 2026-10-06 결정이며 승인 원본의 NCP 문구는 보존한다. 구성은 [#276의 10-19 결정](https://github.com/JminAILab/CatchU/issues/276#issuecomment-6260130109), 자동 배포 전환은 [#342](https://github.com/JminAILab/CatchU/issues/342)를 따른다. 12월 8일까지 두 API 운영 검증과 이월 백업 복원 시험을 진행한다. 운영자가 스크립트로 다른 이름의 DB를 복원하고 대조·시험 자원 정리를 수동 확인하며, 이번 시험에서 운영 DB 전환은 하지 않는다. 세부 대조 항목·담당·성공 판단은 후속 설계에서 정한다. 미실행이면 미완료로 구분하고 고정 복구 시간이나 앱 자동 장애 복구를 추가하지 않는다. 자세한 전제·일정·예산은 [실행 계획](delivery-plan.md#확정된-eks-전제와-12월-검증)을 따른다. 원본 Q118·FR19.1·OQ14·AC19.2.2의 팀장 배포 담당 기록은 보존한다. 이후 담당 배정을 팀 회의에 남긴 방침에 따라 기존 담당의 유지·변경을 포함한 실제 배정을 확인하며, 이번 문서 작성으로 배포 담당 해제·재배정을 완료하지 않는다.

서류 종류별 한 벌 제한, 수신자의 서류별 AI 참고 선택 제거, JD 패널·AI 근거 후보 이연, 기업 등록 수동화, 공유본 주장 한 개 제한, PDF AI 참고 이연은 채택하지 않았다. 화면 단계·수량만 줄여도 남는 저장·권한·수명 처리가 있으므로 실제 작업량을 확인하지 않고 큰 절감으로 계산하지 않는다. 실패 실행은 자동 재호출 없이 사용자가 다시 요청하고, 삭제 실패는 기록과 운영자 수동 재처리로 마무리한다. 실행 수단의 세부는 이 경계 안에서 설계한다.
