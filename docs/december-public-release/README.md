# CatchU 12월 공개판 계획

작성일: 2026-10-12. 지위: 팀 검토용 계획 초안.

취준생·HR·기술 면접관이 실제로 사용할 12월 공개판의 기능 범위, 작업 순서, 완료 기준과 설계 참여 방식을 정리한다. 10월 MVP 기반을 이어 사용하며, 네 명이 평일 하루 8시간씩 참여하는 조건이다. 기존의 11월 30일 기능 완료·12월 10일 제출은 **조정 가능한 참고 목표**로 남기고 이번 계획에서 일정을 확정하지 않는다. 실제 일정은 팀 회의·담당 배정·작업량 산정과 진행 상황에 따라 조정한다.

## 공개판의 중심 흐름

- **작성과 공유:** 공개 저장소 분석·수동 재분석 → Catch를 연결한 주장과 서류 작성 → 선택 자료의 고정 공유본 발행 → 수신자 열람.
- **발견과 연결:** 기업 소속 확보 → 자연어로 후보와 근거 검색 → 채용 안내 전달 → 구직자가 외부 지원·연락 경로로 이동.
- **자료 검토:** 허용된 자료와 JD를 함께 확인 → 질문 → 관련 Catch 근거 후보·출처·확인 공백 확인.
- **외부 도구 활용:** 명시적으로 연결 승인 → 본인 자료·받은 공유본·후보 검색의 세 MCP 흐름 이용 → 연결 해제. 12월 지원·검증 대상은 외부 도구 한 종류다.

포스팅·팔로우·홈 피드는 이번 공개판에서 제외하고, 서비스 안의 제안 수락·거절·별도 연락처 전달 등은 이연한다. 검색과 JD 답변 품질 확인은 소수 사례로 최소화하면서 자료 접근·권한 회수·비용 통제 조건은 유지한다. 세부 범위와 미결은 범위 변경표를 따른다.

## 결정과 실행안의 지위

이 문서는 팀장과의 2026-10-09~12 논의에서 선택한 제품 행동과 실행 제안을 팀이 검토할 수 있도록 정리한 것이다. 결정의 의미는 각 문서에 풀어 적었으며, 별도의 대화 기록을 열지 않아도 범위와 남은 판단을 알 수 있어야 한다.

| 구분 | 이 문서에서의 의미 |
|---|---|
| 팀장 선택·확인 | 기능 범위·완료 수준·설계 참여 방향에 관해 대화에서 확인한 후속 결정. 승인 원본과 연결할 변경 대상은 범위 변경표에 명시 |
| 실행 초안·제안 | 여덟 작업 묶음, 주차별 배치, 시간 예산, AI-DLC 설정 제안. 팀 검토와 작업량 산정으로 구체화 |
| 후속 결정 | 담당자·실제 일정, 지원 도구·기술·한도·보관 기간·실제 운영 조건 등. 필요한 결정 시점과 판단 역할은 실행 계획에 기록 |

기존 [12월 승인 문서 안내](../CatchU_12월_승인문서_안내.md)는 2026-09-28 승인된 요구사항·스토리와 당시 정지 기록을 안내한다. 이번 문서군은 그 원본을 소급 수정하지 않는 후속 계획이다. 기존 기준과 다른 제품 행동은 범위 변경표의 대상·내용·적용 시점에 맞춰 후속 설계·계약·검증에 반영하고, 담당 기능의 착수 입력에 이전 기준과 달라지는 내용을 포함한다. 이 문서의 추가만으로 기존 승인·정지 기록이나 10월 구현 계약을 바꾸지 않는다.

AI-DLC 2.11.0 채택과 희망자의 기능별 별도 intent 설계 참여는 선택한 방향이다. 실제 환경 전환·intent 생성·구현·배포·사용자 검증은 각각 실행과 결과 확인이 필요하다. 현재 문서는 그 작업의 완료 보고가 아니다.

## 담당 배정과 설계 참여

누가 어떤 기능을 맡을지는 추후 팀 회의에서 정한다. 공통 작업도 같은 회의에서 책임을 배정한다. 담당 미정은 계획 문서 검토를 중단하는 조건이 아니며, 회의 날짜나 개인별 착수일을 임의로 확정하지 않는다.

기능마다 주담당이 설계·구현·검증을 이끌고 구현 협업자와 연결 검토자를 붙이는 방식을 제안한다. 한 사람이 모든 계층을 혼자 구현하거나 사람마다 intent 하나를 만들도록 강제하지 않는다. 설계·학습·검토 시간은 개발 시간에 포함하고, 공통 작업과 같은 시간을 중복 계산하지 않는다.

포트폴리오에서는 실제로 맡은 문제·선택 이유·구현·검증 결과를 설명한다. 기존 기반과 본인의 변경, 팀 공동 결정과 본인 판단을 구분한다. 포트폴리오를 위한 추가 기능이나 별도 평가 체계를 필수로 만들지 않는다.

## 이번 문서 검토에서 확인할 것

1. 범위 변경표가 합의한 기능과 이연·보류 사항을 정확히 담는가.
2. 작업 묶음이 연결 책임을 빠뜨리지 않고 병행할 수 있는 부분을 구분하는가.
3. 완료 기준이 선택한 최소 수준과 공개 서비스의 접근·자료 수명 조건을 함께 지키는가.
4. 남은 결정에 필요한 판단 역할과 시점이 있으며, 팀원의 설계 선택을 미리 확정하지 않았는가.

검토 후에는 팀 회의의 담당 배정과 작업량 산정, AI-DLC 환경 확인, 기능별 설계·구현으로 이어간다. 실제 담당·진행·막힘·검증 결과는 [작업관리](../CatchU_작업관리.md)에 따라 이슈·Projects·PR에서 관리한다. 이 문서에는 실행 상태를 중복 기록하지 않는다.
