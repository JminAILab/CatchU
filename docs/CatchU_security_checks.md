# CatchU 보안 점검 — 코드를 고칠 때 지킬 것

> 지위: 적용(2026-10-03 팀장 결정). [코딩 절차](CatchU_coding_procedures.md)를 보충한다. 승인된 API 명세·ERD와 서비스 README 규약이 이 문서와 어긋나면 그쪽이 이긴다. AI가 한 번에 읽을 수 있게 짧게 유지한다.

권한·입력·화면 출력·인증·설정·외부 호출·의존성·LLM을 건드리는 코드를 고칠 때 읽고, 해당하는 행만 적용한다. 기준 목록은 OWASP Top 10:2025(웹)와 OWASP GenAI LLM Top 10 2026이며, 그중 CatchU 코드에 실제로 해당하는 것만 옮겼다. 괄호 안은 그 목록의 항목 번호다.

## 바꾸는 것별로 지킬 것

| 바꾸는 것 | 지킬 것 |
|---|---|
| API 경로·권한 (A01) | 전역 인증 Guard를 유지한다. 인증 없이 여는 경로는 메서드에만 `@Public()`을 붙이고 클래스에는 붙이지 않는다. 회원이 요청으로 고른 자원은 조회 조건에 소유자를 넣고, 남의 자원과 없는 자원에 같은 404를 준다. 회원 두 명이 서로의 ID로 접근하는 거부 테스트를 둔다. 내부 참조(멱등 기록이 가리키는 링크 등)는 승인된 앞선 소유자 검사·복합 외래 키로 지키고, 불일치를 404로 숨기지 않는다. worker가 부르는 내부 경로는 회원 토큰과 다른 서비스 인증을 쓰고 `@Public()`으로 열지 않는다. |
| 요청·메시지 입력 (A05) | 정의하지 않은 필드는 거부한다. SQL은 `$1` 같은 매개변수로만 넘기고 문자열로 잇지 않는다. URL 경로에 넣는 ID는 형식을 먼저 확인한다. 셸 실행과 `eval`을 쓰지 않는다. |
| 화면 출력 (A05·LLM10) | 서버·분석 문구는 React 텍스트로만 그린다. `dangerouslySetInnerHTML`과 HTML을 만드는 마크다운 렌더링은 쓰지 않으며, 필요하면 이슈로 먼저 합의한다. 외부 링크는 http(s)와 허용한 호스트만 링크로 만들고 `rel="noopener noreferrer"`를 붙인다. |
| 인증·비밀번호·토큰 (A04·A07) | 링크 토큰과 서명 키는 `crypto` 같은 안전한 난수 생성기로 만든다. 회원 JWT·링크 grant 같은 서명 토큰의 형식·수명은 승인된 계약과 [#87](https://github.com/JminAILab/CatchU/issues/87)·[#150](https://github.com/JminAILab/CatchU/issues/150#issuecomment-5883572995) 결정을 따른다. 비밀번호는 salt를 붙인 느린 해시(scrypt 등)로 저장하고 상수 시간으로 비교한다. 시도 제한은 비밀번호를 맞혀 볼 수 있는 경로(수신자 unlock)에 두고 비싼 해시보다 먼저 판정한다. grant로 조회하는 GET에는 두지 않는다(API 명세). web은 회원 토큰을 메모리에만 둔다. |
| 설정·개발용 기능 (A02·A10) | 개발용 기능은 켤 환경을 정해서만 켠다(`NODE_ENV`가 `development`·`test`일 때). "production이 아니면 허용"처럼 막을 값만 정하지 않는다. 필수 비밀값이 없거나 형식이 틀리면 기동을 멈춘다. 판정할 수 없으면 허용하지 않는 쪽으로 처리한다. |
| 외부 호출 (A01 SSRF) | 서버가 외부를 부를 때 적용한다. 호스트는 코드에 고정하고 사용자 값·응답 속 주소로 바꾸지 못하게 한다. 경로에는 형식을 검사한 값만 넣는다(예: worker가 검사한 저장소 좌표). redirect를 따라가지 않고 응답 크기·시간에 상한을 둔다. |
| 로그·오류 응답 (A09·A10) | [자료와 실행 로그](CatchU_coding_procedures.md#자료와-실행-로그)를 따른다. 오류 응답에 입력 원문·SQL·stack·토큰을 넣지 않는다(API 명세 「공통 오류·요청 안전성」). 예외를 삼키거나 원인이 다른 실패를 한 코드로 묶지 않는다(계약이 정한 응답 코드는 그대로 따른다). |
| 의존성 추가·갱신 (A03) | 정확한 버전과 잠금 파일을 함께 바꾼다. 개발용까지 포함한 알려진 취약점은 CI `deps-audit`가 검사한다. 고친 판본이 없어 [예외 목록](../.github/deps-audit-exceptions.txt)에 더할 때는 그 이유를 PR 「리뷰 요청」에 적는다. |
| LLM·검색 기능 (LLM01~LLM10) | 저장소 글·서류·질의는 "신뢰할 수 없는 자료"로 표시해 지시문과 섞지 않고, 그 안의 명령을 따르지 않는다. 보내기 전에 비밀값과 개인정보를 가린다. 다만 구직자가 직접 올린 자기 자료(텍스트·PDF)는 첫 이용 동의 아래 그대로 보내고, 올리는 화면에서 민감한 정보를 지우도록 안내한다([11월 개발 범위 결정](CatchU_11월_범위_결정.md)). 프롬프트에 다른 회원 자료·비밀값·민감한 내부 정보를 넣지 않는다. 생성 문장의 사실·기여가 근거 자료에 있는지 대조하고, 근거에 없는 사실은 확정하지 않는다([worker 업무 규칙](../aidlc/spaces/default/intents/260914-catchu-october-mvp/construction/u3-worker/functional-design/rules.md)의 후보 제공 규칙·[#120](https://github.com/JminAILab/CatchU/issues/120) 완료 기준). 입력·출력 크기와 호출 횟수·비용에 상한을 둔다. LLM이 부르는 도구는 읽기 전용 허용 목록으로 둔다. 검색 색인도 화면과 같은 권한·숨김·삭제를 따른다. |

## 검사와 보고

- 위 행에 해당하면 거부 사례(남의 자원, 잘못된 입력, 틀린 비밀번호, 꺼진 개발용 기능)도 검사하고, 결과는 [검사 선택과 결과 보고](CatchU_coding_procedures.md#검사-선택과-결과-보고)대로 PR에 쓴다.
- 지킬 수 없거나 계약과 부딪치면 우회하지 말고 PR 「리뷰 요청」에 쟁점으로 적는다.

## 결정 이력

- 2026-10-03 신설. 팀 지침에 앱 보안 기준이 없어 OWASP 웹·LLM Top 10 중 CatchU 코드에 해당하는 것만 옮겼다. 출발점은 9/9 입력 스냅샷의 팀 결정(OWASP를 기획 문서에 넣는다, `docs/ai-dlc-input/CatchU_v10_reference.md` 2-8절)이고, 행 구성은 같은 날 dev(0ff414b) 코드 점검 결과를 따랐고, 점검에서 나온 배포 전 보강 항목은 [#212](https://github.com/JminAILab/CatchU/issues/212)에 있다.
- 2026-10-04 교차 검토 반영(팀장 결정). 소유자·토큰·시도 제한·외부 호출 규칙을 승인된 설계에 맞게 좁히고, 로그 행에 코딩 절차 원문의 계약 응답 코드 예외를 되살렸으며, 개발용 의존성 검사와 LLM 근거 대조를 더했다.
- 2026-10-05 의존성 행을 CI 검사에 맞췄다(팀장 결정, [#215](https://github.com/JminAILab/CatchU/issues/215)). 새 의존성의 알려진 취약점은 CI `deps-audit`가 개발용까지 검사하므로 PR에 결과를 따로 적지 않고, 고친 판본이 없어 예외 목록에 더할 때만 그 이유를 적는다.
- 2026-10-24 LLM 행에 구직자가 직접 올린 자기 자료의 예외를 더했다(팀장 결정, PR #367 자동 리뷰 지적). 본인 자료는 첫 이용 동의로 보내고 서비스가 개인정보를 찾아 가리지 않으며, 업로드 화면 안내로 민감한 정보를 지우게 한다.
