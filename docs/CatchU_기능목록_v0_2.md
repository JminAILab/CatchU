## 두 개의 축

**우선순위**와 **9/30 시연 범위**는 다른 축이다. 섞지 말 것.

| 순위 | 뜻 |
|---|---|
| **1** | 이게 없으면 서비스가 성립하지 않음 |
| **2** | 완결에 필요 |
| **3** | 있으면 좋음 |
| **보류** | 결정 대기 — **와이어프레임 그리지 말 것** |

기준 시점은 전부 12/18(최종)이다.

**◆ = 9/30 중간 발표 시연 범위.** 중간 발표는 "이런 걸 만들고 있습니다"를 보이는
자리이므로, 화면 수가 아니라 **하나의 동선이 끝까지 이어지는 것**이 목표다.

```
GitHub 연결 → 카드 생성 → 카드 확인 → 링크 발행 → 열어서 확인
```

우선순위 1인데 시연에 안 들어가는 것이 있고(회원 관리), 그 반대도 있다.

## 전제

**채용 공고는 정상적으로 확보된다고 가정하고 설계한다.** 수집 경로가 확정되지
않았다는 이유로 공고 기반 기능(검색·필터·프리셋·추천)을 설계에서 빼지 않는다.
MVP 단계에서 무엇으로 대체할지는 구현 시점의 문제이며, 화면 설계와 분리한다.

**F06 — 4분면 폐쇄 (결정)**

주장×흔적 4분면은 만들지 않는다. 두 칸이 **시점이 다른 기능**이었기 때문이다.

| 칸 | 언제 쓸모 있나 | 처리 |
|---|---|---|
| 근거 있는데 안 씀 | 작성 **전** — 재료 발굴 | **F06-03이 이미 함** |
| 주장했는데 근거 없음 | 작성 **후** — 이미 늦음 | **폐쇄** |

자소서를 다 쓴 사람 옆에 "이 주장엔 근거가 없습니다"를 띄우는 것은 도움이 아니라
사후 지적이고, 사용자가 할 수 있는 일이 없다. 원칙 면에서도 시스템이 지원자의 글에
판정을 내리는 것에 해당한다. 우리가 문제 삼은 것은 근거 없는 주장이지,
그것을 우리가 지적하겠다는 뜻이 아니었다.

**우리 서비스의 취준생 측 위치는 "자소서·포트폴리오 작성 전 단계의 재료 제공"이다.**
쓴 것을 검사하는 도구가 아니다. 기업 측은 다르며, 거기서도 시스템이 대조하지 않는다(F09-04).

**F06-06 — 에이전트 (보류 · 실측 조건)**

주기적 반복 검색은 에이전트 도입 여부와 묶여 있다. 에이전트 루프 방식은 비판정 원칙과의
충돌을 이유로 이미 한 번 기각하고 대안(자연어 → 구조화 쿼리 → 결정론적 실행)을 채택했다.
재개봉하려면 그 기각 근거가 무효화되었음을 보여야 하며, 현재는 그 재료가 없다.

**재개봉 조건**: 결정론적 쿼리로 풀리지 않는 실제 요청을 3~5개 문장으로 수집할 것.
예 — "협업 경험 어때요?"는 유형 필터로 풀린다. "레거시 리팩터링 해본 적 있나?"는?
안 풀리는 사례가 실제로 나오면 그것이 근거다. 팀 합의가 필요 없는 실측이다.

**도입하더라도 유지되는 선**: 루프를 몇 번 돌든 **출력은 카드 목록과 근거 링크뿐이다.**
평가 문장을 생성하지 않는다. 프롬프트는 뚫릴 수 있지만 출력 스키마는 구조다 —
평가 문장이 나올 자리가 없으면 나오지 않는다. 이 선이 검토되기 전에 트레이드오프를
논하는 것은 이르다.

> 로그인 없이 열리고, 열람자는 우리 회원이 아니다. **별도 명세 필요** — 아래는 골격.

| ID | 기능명 | 상세 | 순위 | 9/30 | 제약 |
|---|---|---|---|---|---|
| F09-01 | 링크 진입 | 비밀번호 인증 → 탭 화면 | 1 | ◆ | 만료 시 **중립 안내.** 사유 노출 금지 |
| F09-02 | 탭 프레임 | 이력서 / 자소서 / 포트폴리오 / GitHub / RAG | 1 | ◆ | **"밖으로 안 나가게"가 이 화면의 목적** |
| F09-03 | 이력서 탭 | text 표시 | 1 | | |
| F09-04 | 자기소개서 탭 | text 표시 | 1 | | **시스템이 "근거 없음"을 표시하지 않는다.** 나란히 놓기까지가 우리 몫 |
| F09-05 | 포트폴리오 탭 | canvas 뷰어 | 2 | | |

| F09-07 | GitHub 탭 — 카드 | 프리셋 카드 / **근거 등급** / 근거 링크 | 1 | ◆ | 세트 밖 카드 노출 금지 |
| F09-08 | RAG 탭 — 검색 | 자연어 질의 + **레포 필터(선택)** | 1 | ○ | **출력은 카드 목록 + 링크만.** 요약·총평·순위·점수 금지 |
| F09-09 | RAG 탭 — 조건 입력 | **구조화 필드**: 기술 / 작업 유형 / 직무 | 1 | | **자유 텍스트 프롬프트 금지** — 인젝션 표면 + 적합도 판정 경로 |
| F09-10 | 조건 프리셋(내부 기업) | 저장·재사용 | 3 | | 기업 측 명세 |
| F09-11 | 폴더 구조 탐색 | root → 폴더 → 파일 → 관련 카드 | 3 | | **작업 영역 색칠 O (이진).** 커밋 수 농도 그라데이션 X — 진한/연한 사이에 순위가 생김 |
| F09-12 | 파일 경로 표시·필터 | 카드에 경로 표시 + 경로 필터 | 2 | | F09-11의 데이터 기반 |
| F09-13 | 다운로드 | 허용 시 | 2 | | 기본 꺼짐 |

○ = 시연에 넣으면 가장 인상적이나 필수는 아님. 9/30까지 안 되면 12/18로.

**F09 전역 금지** (프론트가 화면에 넣지 말 것)
- 점수·등급·적합도·순위·합격 가능성
- 숨긴 카드의 존재·개수 / 프리셋에 안 담긴 공개 카드
- 커버리지 비율
- 편집 횟수, 기본값 사용 여부, 발행까지 걸린 시간
