## 자동 검사

실행 위치는 임시 사본의 `/workspace/api`, `/workspace/web`이다.

API 영향 검사 파일:

```sh
npm run lint
npm run typecheck
npm test -- test/integration/result-application-b.test.cjs test/rag-answer/rag-answer-app.test.cjs test/jd/jd-management.test.cjs test/jd/jd-summary.test.cjs test/jd/jd-integration.test.cjs test/jd/jd-acceptance-race.test.cjs test/jd/jd-publication-access.test.cjs test/u2/ai-run.test.cjs test/u2/ai-gate-jd.test.cjs test/db/member-cascade-delete.test.cjs
```

첫 API 실행은 lint·typecheck·build 뒤, 이미지에서 물려받은 SSL 설정과 TLS 없는 시험 DB의 불일치로 시험 전 중단됐다. 같은 빌드를 재사용하고 `PGSSLMODE=disable`을 전용 시험 프로세스에 지정해 `node scripts/test-with-db.cjs <위 10개 파일>`로 실행했다. 기존 개발·운영 DB 설정은 바꾸지 않았다.

이 영향 검사에서는 **79개 중 78개 통과·1개 실패·skip 0**이었다. 실패는 migration 정합성 검사에서 JSONB 기본값 재설정 SQL 3개가 검출된 건이다. 별도 진단 DB의 같은 파일에서도 18/19 통과·같은 1건 실패를 재현했다. 타인 수정·삭제 거부 직후 원본 보존, 실제 앱 JD 처리기 등록·중복 거부, 실제 C-10 경계, 합성 생성 응답의 DB 저장은 통과했다. 전용 Valkey의 실제 큐 전달·중복 억제도 통과했으며 외부 생성자는 합성이다.

JSONB 기본값 표현 수정 후 최종 API 소스를 임시 사본에 반영하고 다음을 재실행했다(`PGSSLMODE=disable` 유지).

```sh
node node_modules/eslint/bin/eslint.js src/app.module.ts src/jd-summary/jd-summary-result.entity.ts --max-warnings=0
npm test -- test/integration/result-application-b.test.cjs test/jd/jd-integration.test.cjs
```

최종 lint·재빌드와 **25/25 통과, 실패·skip 0, 종료 코드 0**을 확인했다. 여기에는 전체 migration down/up·스키마 차이 없음과 JD 실제 DB 저장·경합·로컬 큐가 포함된다. 앞서 통과한 영향 검사 79개 중 나머지 54개는 결과를 재사용했고, 최종 소스로 79개 전체를 다시 실행했다고 보고하지 않는다. 검사 중 `pg`의 동시 `client.query()` 사용에 관한 향후 pg@9.0 비권장 경고가 있었으나 실패는 없었다.

web은 `npm run check`를 실행했다. 첫 실행에 브라우저용 `NEXT_PUBLIC_AUTH_SESSION_INTEGRATION=true`가 섞여 881/889 통과·8 실패가 발생했다. 전환을 제거한 기본 검사 환경에서 다시 실행해 **889/889 통과, 실패·skip 0**, lint·typecheck·프로덕션 빌드·`check:run`(기본 화면 HTTP 200·보안 헤더)까지 종료 코드 0을 확인했다. 제품 코드나 테스트 기대값을 환경 문제에 맞춰 바꾸지 않았다.
