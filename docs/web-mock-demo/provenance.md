# 출처와 공유용 사본 관리

2026-09-21 · `260920-catchu-web-mock`

이 폴더는 같은 intent에서 승인된 구현 계획·테스트 지침을 팀에 전달하는 **공유용 사본**이다. 공식 AI-DLC 원본·승인 이력은 원본 관리 환경의 해당 intent 기록이 정본이다. 원본은 현재 이 저장소의 팀 공유 경로에 게시돼 있지 않으므로 깨지는 상대 링크나 개인 파일 경로를 제공하지 않는다. 팀의 첫 작업 판단에 필요한 범위·행동·명령은 이 폴더에 담았다.

## 원본 보관과 공유 방침

팀원 1 `ljm0850`이 별도 AI-DLC 원본 관리 환경의 `aidlc/spaces/default/intents/260920-catchu-web-mock/`에 요구사항·계획·검사 지침과 승인 이력을 보관한다. `docs/`를 또 하나의 승인 원본으로 만들지 않는다. 원본의 저장소 반영 범위·브랜치·시점은 아직 미정이며 팀원 1이 정리해 PR #74 또는 후속 기록에 남긴다. 현재 이 저장소에 원본 이력이 게시됐다고 해석하지 않는다.

이번에 팀에 공유하는 것은 첫 작업에 필요한 행동·파일 경계·명령과 판본 식별이다. 원본을 확인해야 하는 리뷰는 팀원 1이 대조 결과를 남긴다. 팀원은 이 공유본으로 착수 안내를 검토할 수 있으며 원본 전체 공개를 골격 착수 조건으로 추가하지 않는다. 후속 승인 판본이 바뀌면 관련 기능 구현 전에 공유본·원본 식별 해시·검토 PR을 함께 갱신한다. 개인 경로·실행 정보·비밀값은 공유하지 않는다.

## 9/21 리뷰 보완의 지위

PR #74 후속 보완은 착수 준비 책임, 기존 B 담당 합의, 용어·출처·원본 공유 방침과 브랜치 예외 안내를 명확히 한다. 수신자 갱신 충돌은 [9/15 기준 유지 결정](https://github.com/JminAILab/CatchU/pull/74#issuecomment-5758191355)에 따라 원본에서 보정·재승인됐고, 이 공유본의 OQ2·관련 검사·M3와 위 해시를 해당 판본에 맞췄다. 원본 머리말의 ‘재승인 검토본/재승인 미완료’는 작성 당시 문구이며 공유본의 지위는 원본 관리 세션이 보고한 후속 재승인을 기준으로 표시한다. 헤더·자산 탭·분석→Catch 접점과 브랜치 운영 구체안 리뷰는 별도로 남는다. 원본 승인 이력을 공유본에 복사하거나 앱 검사 성공으로 확대하지 않는다.

## 기존 실제 MVP 조건의 뜻

여기서 C01/C02는 intent `260914-catchu-october-mvp`의 [제약 등록부 「잔여 실행·검증 항목」](../../aidlc/spaces/default/intents/260914-catchu-october-mvp/ideation/feasibility/constraint-register.md#잔여-실행검증-항목)의 추적 ID다. 과거 다른 intent의 같은 표기와 구분한다.

- **C01:** LLM 입력·프롬프트 보완 및 최소 재검증. 담당은 `ljm0850`이며 원문의 domain-design 승인 / 관련 생성 구현 착수 전 조건과 수용 기준을 따른다.
- **C02:** 실제 사용 후보의 핵심 근거 충분성과 필요한 누락 처리 판단. 담당은 `ljm0850`이며 원문의 domain-design 승인 / 관련 분석·생성 구현 착수 전 조건과 수용 기준을 따른다.

이번 합성 시연의 성공으로 이 항목을 완료 처리하지 않는다. 자료 삭제 조건·기한은 두 검증 항목의 완료 시점과 별개다. 공유한 원본 계획에 기록된 **9/23 23:59 KST 또는 관련 설계·구현 경계 중 이른 시점**의 자료 삭제 조건을 연장·해소하지 않는다. 제한적 수용과 예외 변경에 관한 [PR #68](https://github.com/JminAILab/CatchU/pull/68)의 논의 상태를 이번 PR로 승인·완료 처리하지 않는다.

## 변경과 충돌 처리

- 오탈자·링크·팀 안내 수정은 문서 PR로 처리한다. 기능·담당·선행 관계·검사 기준을 바꾸는 수정은 원본 관리자가 같은 intent/단계의 공식 변경·필요한 재승인을 먼저 처리한 뒤 이 사본과 원본 식별 해시를 함께 갱신한다.
- PR 제출/병합은 원본 Plan Approval을 대신하지 않는다. 사본을 읽거나 clone했다고 팀원 환경에 공식 승인 영수증이 생기지 않는다. 새 intent 생성·요구사항 재작성을 기본 준비 절차로 요구하지 않는다.
- 원본과 사본의 내용이 다르면 기능 변경을 임의 적용하지 않고 차이와 영향을 PR에 남긴다. 기존 팀 규칙과의 관계는 [docs 안내](../README.md)의 AI-DLC 산출물 원칙을 따른다.
- 적용 범위는 **9/30 합성 web 모의 시연**이다. 기존 실제 MVP의 담당·기능·잔여 검증 조건·기한을 대체하거나 해결했다고 간주하지 않는다. 과거 PR/화면 초안은 검토 입력 지위를 유지한다.
