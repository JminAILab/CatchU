    git이 생겨도 **추록 누적 관행은 폐기 불가.**
  - → 08-19 추록의 "커밋 이력이 미러 역할을 대체" 는 *유실 복구* 한정. Claude 문맥은 대체 못 함.
- **자동 동기화 없음.** Sync 버튼 수동.
  → 회의록의 "AI 연동 자동 최신"은 **사실이 아니며 정정 대상.**
- **동기화 브랜치를 확인할 것** — 연동 설정 시 지정한 브랜치의 파일만 온다.
  main으로 잡혀 있으면 dev에 머지된 문서는 안 보인다.
- 모바일에는 Sync UI가 마땅치 않다 — 노트북 커밋 → 모바일 대화 패턴에서 누락 위험.

#### 5. `_notes/` — 개인 문서 레포

- 팀 레포 폴더 안에 개인 private 레포를 클론. 파일은 한 벌, 원격만 둘.
  Claude Code는 `~/CatchU/` 하나만 열면 둘 다 읽는다.
- **무시 규칙은 팀 `.gitignore`에 둔다** (08-20 결정). `.git/info/exclude` 안은 기각 —
  클론에 따라오지 않아 재클론·기기 변경 시 규칙이 소실된다.
  `_notes/`의 존재는 팀에 비밀이 아니라는 재민 판단이 전제.
- **gitignore를 먼저 커밋하고 클론할 것.** 순서가 반대면 `git status`에 `_notes/`가 통째로 뜬다.
  커밋 위치 주의 — `_notes/` 안 파일은 `cd _notes && git commit`으로만 잡힌다.
- **등기부는 레포별 1벌씩, 상호 참조 있음.** 팀 등기부가 `_notes/`를 참조하면
  팀 레포만 연결된 세션이 "존재하지만 못 읽는 문서"를 인지해 추측 대신 요청하게 된다.
- **`CLAUDE.md`에 4번째 게이트 추가**: `_notes/` 내용을 `docs/` 산출물에 인용 금지.
  `아카이브_전략_v0_8`은 팀 미공개가 전제인 문서이므로(지침 §2), 경계를 넘으면 전제가
  조용히 깨진다. 필요 시 재민 확인 후.
- 과거 문서 폴더는 `현행/`·`보관/`으로 분리. 통째 이관 금지 —
  v0.7의 D-21(외부 공고)처럼 현행과 모순되는 판본이 섞여 있다.

#### 5-1. 지침 1층의 분할 — 신규 과제 (08-20 제기)

이 상태 파일을 포함해 프로젝트 문서 상당수가 **1층 지침을 전제로 쓰여 있는데,
지침은 재민 개인 AI 도구 설정에만 있고 레포 어디에도 없다.** 팀원·멘토·심사위원,
그리고 나중에 이 문서를 읽을 누구도 전제를 못 읽는다.

기존 결정("지침은 `docs/`에 넣지 않음")의 근거는 *저장 위치*였을 뿐 *내용의 성격*이
아니었다 — 근거가 결론을 떠받치지 못함이 확인되어 재검토한다.

**분할 방침 (방향 확정, 실행 미착수)**
- **A. 팀 공유** → `docs/CatchU_설계원칙.md` 신설. 헌법 5원칙 / 반복 재발 논점 /
  프로젝트 정의·이름 결정 기록 / 핵심 설계 요점 / 페르소나 명부
- **B. 재민 개인 운영** → `_notes/현행/`. 세션 시작 규칙, 협업 스타일
- **C. 팀 비공개** → `_notes/현행/`. 지침 §2의 "강요하지 않는다" 서술, §7의 v0.8 미공개 전제.
  **통째 공유 시 이 부분이 노출되는 것이 분할의 핵심 이유**

**A는 복사가 아니라 재작성이다.** 지침의 서술은 재민이 AI에게 주는 지시문 형태라,
그대로 옮기면 "재민이 다 정해놨네"로 읽힌다. 팀 대면 문서 원칙(질문 먼저 → 팀 도달) 적용 대상.

**전달 방식 주의**: 팀이 흔들린 원인은 기둥의 부재가 아니라 기둥이 팀에게 안 보였던 것이다
(헌법은 06-23부터 존재, 팀 미공개). 문서를 만드는 것만으로는 반복을 못 막는다.
각 원칙에 **판별 도구 형태**를 병기할 것 — "점수를 매기지 않는다"(결론)가 아니라
"GitRoll이 이 문장을 쓸 수 있는가"(팀이 스스로 적용 가능한 기준).

**후속 위임 방식 (08-20 결정)**
설계원칙 문서 확립 후, 레포 전체 문서(README 포함)의 정합성을 Claude Code로 점검한다.
단 제약을 둔다:
- **이전(순서 1~3) 완료 후 착수.** 지금은 레포에 정본이 없어 점검 기준이 존재하지 않는다
- **1차는 읽기 전용 — 불일치 목록만 출력.** 판정은 재민, 수정은 2차 세션.
  "원칙에 맞게 고쳐줘"는 설계 판단을 위임하는 형태이므로 쓰지 않는다
- **세션 분리**: ① 팀 레포만 ② `_notes/`만. 두 레포를 걸치는 세션은 열지 않는다
- **`CatchU_설계원칙.md` 초안은 Code에 맡기지 않는다** — 설계 채팅에서 작성

구분되기를 원한다.

**다음 회의 전 선행 확인 (재민)**: 회의록의 저 문장이 ① 우리 팀이 커밋을 잘 쓰자는

①이면 D-02와 충돌하지 않는다. 이걸 안 가르고 헌법을 꺼내면 원칙으로 찍어누르는 모양이 된다.

**재프레이밍 방향은 별도 세션에서 다룬다.** 현 시점에서 확정된 것은 없으며 구체안을 여기
적지 않는다 — 적는 순간 기정사실이 된다. 시간이 갈수록 팀의 기정사실이 되므로 우선순위 최상.
