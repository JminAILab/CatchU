## 1. 문제 — v1.4로 표면이 셋이 되었다

KPI v4.0은 **"카드" 하나**를 전제로 썼다. 9/2 v1.4에서 근거 링크를 단 표면이 셋이 됐다.

```
기술 스택 배지 ──┐
프리셋 문장   ──┼──▶ 카드 ──▶ 커밋 · PR
                 └── (v4.0이 아는 유일한 경로)
```

| v1.4가 정한 것 | KPI에 생긴 구멍 |
|---|---|
| 기술 스택 **자가 입력 금지**, 전부 카드에서 도출 (§5.2). 이 배지가 **검색 필터의 입력** (§5.1) | 카드가 다 맞아도 **집계 규칙**이 틀리면 프로필이 틀린다. 백업이 없다 |
| 프리셋 = 주장 + 근거 카드, **주장은 사용자가 작성** (§6.2) | KPI는 *AI가 만든* 주장만 잰다. *사용자의* 주장은 안 잰다 |
| 디폴트 프리셋 = **전체 공개 · 프로필 첫 화면 · 랜딩 예시** (§5.4) | 가장 많이 읽히는 표면을 한 번도 재지 않는다 |
| 카드 **47장** 규모 (§6.2.2) | GT 주요 경험이 10건이면 1:4.7. 커버리지의 분모·분자가 다른 단위 |

## 2. 🔲 안건 1 — 정확도를 어느 표면까지 잴 것인가

| 층 | 주장을 만든 주체 | 현재 |
|---|---|---|
| 증거 카드 | **AI** | ✅ 재는 중 |
| 기술 스택 배지 | **AI(집계 규칙)** | ❌ |
| 프리셋 문장 | **사용자** | ❌ |
| 경험 요약(HR용) | AI(파생) | ❌ |

| # | 질문 | 선택지 |
|---|---|---|
| **A** | 기본 판정 대상 | 증거 카드만 / 카드 + 경험 요약 각각 (**GT 2벌 = 공수 두 배**) |
| **B** | **프리셋 문장–카드 연결 타당성**을 잴 것인가 | 안 잰다("사용자 주장은 책임 범위 밖" 명시) / **○× 판정만** / 전면 측정 |
| **C** | **기술 스택 도출 정확도**를 잴 것인가 | 안 잰다 / 잰다 → **안건 2-A①과 한 몸** |
| **D** | MCP 경로(v1.4 §6.2.3 유형 ②)를 포함할 것인가 | 포함 / 구현 후로 |

> **B가 왜 안건인가** — v1.4 §6.2.3이 *"이 검증이 없으면 근거 원칙이 MCP 경로로 뚫린다"*고 스스로 적었다. 그런데 거기서 막는 건 **카드가 붙어 있는가**뿐이다. **아무 카드나 붙여도 통과한다.**

**못 정하면:** GT를 시작할 수 없다.

## 3. 🔲 안건 2 — Ground Truth ⚠️ 되돌리기 어려움

### 2-A. GT에 항목 두 개를 추가할 것인가

| 추가 후보 | 안 넣으면 |
|---|---|
| **① 이 레포에서 도출되어야 할 기술 스택 목록** | 스택 도출 정확도를 영영 못 잰다. *"카드는 100%인데 프로필이 틀림"*을 설명할 수 없다 |
| **② "주요 개발 경험"의 입도 기준** | 2인 독립 판정에서 한 명은 커밋 단위, 한 명은 기능 단위로 세어 **일치율이 무너진다** |

> ①은 **v1.4 §5.2에 "기술 스택 도출 규칙"(어느 정도 변경을 그 스택 사용으로 볼 것인가)이 먼저 있어야** 정답을 쓸 수 있다. 지금 v1.4에 없다.

### 2-B. 담당과 명단

| # | 정할 것 |
|---|---|
| 1 | **GT 작성자 2명** (독립 판정) |
| 2 | **평가 레포 3~5개** — 어느 레포, 동의는 누가 받나 (**팀 프로젝트 필수 포함**) |
| 3 | **분리 규칙** — GT 쓴 사람은 그 레포의 피험자가 될 수 없다. 이 제약에서 5명이 되는가 |

> 3번 때문에 **담당을 정하는 순간 피험자 후보가 줄어든다.** 두 명단을 같이 놓고 정한다.

**못 정하면:** GT도 P1 세션도 못 한다. 나중에 넣으면 정답지를 처음부터 다시 훑어야 한다.

## 4. 🔲 안건 3 — 근거 링크 3층을 어떻게 다룰 것인가

**(1) 유효율 100% 기준을 어디까지?** — 이 기준은 링크가 한 종류일 때 세운 것이다.

| 층 | 링크 수 | 100% 적용? |
|---|---|---|
| 카드 → 커밋·PR | 카드 수 | ✅ 유지 |
| 프리셋 문장 → 카드 | 문장 수 | 🔲 |
| **배지 → 근거 카드** | **배지 × N — 가장 많다** | 🔲 |

**(2) 근거 확인 과제를 어느 층에서 시작할 것인가?**

| | 과제 문구 | 통과 층 |
|---|---|---|
| A | *"이 **카드**의 근거 원본을 찾아보세요"* | 1층 — 현재안, **실제 사용자 경로와 다름** |
| B | *"이 **프리셋 문장**의 근거 커밋까지 가보세요"* | **3층 전부** — P3가 요구한 "한 뎁스 내 근거 링크"가 성립하는지 여기서 드러남 |
| C | 층별 개별 과제 | 세션 시간 증가 |

**못 정하면:** P1 세션 과제지를 못 만든다. **세션은 한 번뿐이라 문구를 바꿔 다시 할 수 없다.**

## 5. 🔲 안건 4 — 확정정의서의 시장 수치 인용 문장

| 문서 | 문장 |
|---|---|
| **확정정의서**(레포 밖)의 시장 배경 절 | *"10분 이내 검토 57.8%와 GitHub 확인 50%의 조합이 우리 서비스의 존재 이유"* |
| **KPI v4.1**의 발표 연결 절 | *"두 수치는 모집단이 달라 이 문장은 쓰지 않는다"* |

57.8%는 **HR 담당자** 조사, 50%는 **채용 과정 일반** 조사다. 모집단이 다른 둘을 이어 인과를 주장하면 발표에서 지적당했을 때 **문제 제기 전체가 흔들린다.** 그런데 **확정정의서가 상위 문서**라, 지금은 발표 자료를 누가 만드느냐에 따라 두 문장 중 하나가 나온다.

| | 내용 |
|---|---|
| **A** | 정의서의 해당 절 수정 — 문제 제기는 **8/27 인터뷰 발언**으로, 시장 수치는 배경으로만 |
| **B** | 인용 유지하되 두 수치를 **잇지 않고 각각** 제시 |

> **파급:** P2 v2.0 · P3 v3.0도 57.8%를 인용 중이다.
